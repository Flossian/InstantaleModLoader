# `407_npc_starting_equipment`: パーティーに加わった NPC に初期装備を一度だけ持たせる

素のゲームの NPC は装備を持っていない（生成された世界の NPC の `equipments` は全て空。GAME.md §2.31）。
この MOD は、NPC がパーティーに加わったとき、人物に見合う武器と防具を1つずつ作って持たせる。
品は NPC の持ち物（`inventory`）に入り、`333_equipment_slots` を入れていればその装備欄へ入る。

### 装備させる

装備させるのは装備欄の MOD（`333_`）の仕事で、この MOD はローダの窓口 `equipment.equip` に頼むだけ（TECH.md §3.3.6）。
333 は窓を開くときと同じ道で控えに位置を書くので、ロードしても装備は外れない。
333 を入れていなければ、品は持ち物に渡すだけで装備はしない。

この MOD が `equipments` を自分で書かないのは、本体が仲間の `equipments` を保存しないため（GAME.md §2.13.3）。
書いても、その起動の間だけ効いてロードで外れる。
素のゲームは NPC の装備を読まない。
配った装備が戦闘の数と審判への文に効くのは、仲間の装備を読む MOD（`333_` と `319_` / `401_`）が居るときだけ。

## 流れ

1. `InstantaleApp.add_party_member` は本体へそのまま通す。加入できた NPC だけを対象にする
2. 人物の6項目（名前・種族・職業・プロフィール・性格・外見）を写し、背景のワーカーで LLM に頼む
3. 返答が来たらメインスレッドで、ゲーム本来の `generate_item_from_item_data` に1品ずつ渡して作る
4. 作れた品を窓口 `equipment.equip` に渡し（333 が装備欄へ入れる）、ゲームの `save_game` を呼ぶ
5. `save_game` が通った後で、`state\` に「この NPC にどの種類を渡したか」の印を書く

LLM を待つ間もゲームは止めない。待機表示も出さない。

### 加入は止めない

本体の呼び出し側は、`add_party_member` が戻った直後にパーティーが変わった前提で先へ進み、そのまま保存する。
加入を装備の完成まで遅らせると、その間の保存に新しい仲間が入らない。
雇った代金だけ払って仲間が居ない形が、保存の前に落ちたときに残る。
だから加入は本体のまま通し、装備は後から持たせる。

### 印は保存が通った後に確定する

印は `save_game` の包みの中で、本体の保存が通った後に書く。
保存が落ちたら書かず、次の保存でまとめて書く。
ロードと新規開始（`World.__init__`）では、保存されなかった印と LLM 待ちの仕事を捨てる。
品がセーブに無いのに印だけが残り、以後その NPC に装備が配られない、という形を作らないため。

## LLM に頼むもの

| 要素 | 使い方 |
| --- | --- |
| `item_type` | `weapon` / `wearable`。頼んだ種類だけを受ける |
| `item_name` | 日本語の品名 |
| `description` | 日本語の説明。ゲームの説明欄にそのまま出る |
| `item_sub_type` | 細分。頼み文に一覧を見せて選ばせる |
| `rarity` | `common` 〜 `mythic`。外れたら `common` |
| `item_appearance` | 英語の短い1文。ゲームが画像を選ぶ手掛かり |

細分の語彙は、ゲーム自身の品揃え生成のスキーマと同じ組（`312_` と同じ）。

- 武器: `small` / `medium` / `long` / `large` / `throwable`
- 防具: `headgear` / `body_armor` / `legwear` / `gauntlets` / `shield` / `accessory` / `clothing`

武器は、ゲームが細分に `_weapon` を足して品の種類（`item_detail`）にする。
`medium_weapon` を渡すと `medium_weapon_weapon` になり、画像の埋め込みが見つからずに生成が落ちる（VERIFICATION.md §3.76）。
LLM が `medium_weapon` の綴りで返しても、`_weapon` を外して受ける。
語彙の外の細分は、武器は `medium`、防具は `body_armor` に寄せる。
選んだ細分で生成が落ちたときも、同じ既定の細分で一度だけ作り直す。

価値段階（`value`）は LLM に決めさせない。
NPC の `difficulty_level` と `experience_level` から `max(難易度, レベル - 5)` を 1〜70 に収めて使う。
武器の攻撃力はこの段階から決まる（GAME.md §2.13.2）。

## 済んだとみなす条件

- 武器と防具の両方を渡したら済んだとする。以後、離脱して再加入しても、渡した品を手放していても作らない
- 装備欄が断った（空いている部位が無い）品も、持ち物に渡したので渡したことにする
- 片方しか作れなかったときは、欠けた種類だけを最大2回まで LLM に聞き直す
- それでも欠けたら、渡した種類だけを印に残す。再加入したときに欠けた種類だけを作る
- 加入の時点でもう身に着けている種類は作らない。装備欄の MOD が答えればそちら、居なければ `equipments` を見る
- LLM を待つ間に離脱した NPC には渡さない

## 対象にしない場面

- セーブのロード中に本体が名簿を組み直すときの加入。既存の仲間を加入し直したとは扱わない
- 世界がまだ読めない場面（新規ワールドの生成の途中）
- パーティー名簿へ直接書き込み、`add_party_member` を通らない経路

## state

フォルダは `state\npc_starting_equipment\`。周回（世界×主人公）ごとに1ファイルで、中身は印だけ。
`given` は渡した種類、`generated` は両方渡したか。

```json
{
 "npcs": {
  "<npc_id>": {"generated": true, "given": ["weapon", "wearable"]}
 }
}
```

`given` の無い `{"generated": true}` は前の版の印で、両方渡したものとして読む。

## ログ

`out\npc_starting_equipment.log` に、頼んだ・渡した・保存の後に印を書いた、を1件ずつ残す。
渡した行の `-> equipped` は装備欄へ入った、`-> inventory` は装備欄の MOD が居ない、それ以外は装備欄が断った理由。
生成の失敗は `out\modloader.log` に `generate_item_from_item_data failed (<種類> / <細分>)` で出る。

## 検査

`python tools\tests\test_npc_starting_equipment.py`。
偽の app と LLM と装備欄で、加入から保存・印の確定まで、ロード・離脱・不足・身に着けている場面を通す。
333 の側の `equip` の答えは `tools\tests\test_equipment_slots.py` の段5。
実機では、加入・LLM の返答・品の画像・持ち物のセーブまで見た（装備欄を通す前の版）。
装備欄を通す形は実機で測っていない。
