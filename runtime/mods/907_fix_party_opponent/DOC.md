## 1. 遊び方（`docs\MODS.md` 相当）

### `130_fix_party_opponent`: 仲間が敵として選ばれるのを直す

会話や自由入力から戦闘に入ると、パーティの仲間が敵側に出てくることがある。

クエスト外の入力を処理するマスターAI（GAME.md §2.26）は、
戦闘を起こすときに敵を **NPC の名前**で選ぶ。
候補の名簿にはその場に居る全員が入っていて、同行中の仲間も含まれる。
LLM が敵の欄に仲間の名前を書けば、そのまま仲間が敵として戦闘に出る。

この MOD は応答が返った直後に敵の欄を見て、パーティ名簿に居る名前を外す。

- 外しても相手が残るなら、残った相手だけで戦闘が始まる
- 誰も残らない（敵が仲間だけだった）なら、その戦闘は起こさない。
  地の文が戦いを語ったのに戦闘へ入らない回はこれ

どちらもゲームから見れば「LLM が最初からそう答えた」のと同じ形に収まる。
「行動」メニューの「戦闘を仕掛ける」で自分から仲間に仕掛けた戦闘には触らない。
仲間との手合わせ（模擬戦）も LLM 発では起こせなくなる。

#### 困ったとき

| 症状 | やること |
|---|---|
| それでも仲間が敵に出る | `out\party_opponent.log` を見る。行が1つも無ければ経路を通っていない（フックが効いていない）。`素通し` の行に仲間の名前があれば、名簿の名前と敵の欄の名前がずれている |
| 戦いを語ったのに戦闘にならない | `戦闘を起こさない` の行が出ているはず。敵が仲間だけだった回で、意図どおり |

## 3. 未確認項目と確認手順（`docs\VERIFICATION.md` §3 相当）

**実機では一度も通していない。** 分かっているのはここまで:

| 分かっていること | 根拠 |
| --- | --- |
| `start_battle` は `player_opponents`（最大3）/ `player_allies`（最大2）に NPC 名を入れる形 | `output_data\` の `master_ai_facilitator_from_conversation` の実記録（スキーマと応答の両方） |
| 名前の候補は Literal で、元は同じ呼び出しに渡る `npc_list` | 同上（候補1人の世界では `const` がその1人の名前だけになっている） |
| 4関数のどれも同じ形の応答を返す | GAME.md §2.26（`313_` と同じ前提） |
| パーティ名簿とキャラクタ名の取り方 | ローダの `ui.party_member_ids` / `ui.character_of`（`302_` / `306_` の実績） |

**推定のまま残っているもの:**

- 同行中の仲間が実機でも Literal の候補に入ること
  （選出された実例の報告はあるが、ログはまだ取っていない）
- 名簿から引いた `Character.name` と敵の欄の名前が実機で一致すること
- 応答の `process` が実行時に list であること・`player_opponents` への代入が
  pydantic の検証を通ること（通らなければ素通しして記録に残る作り）
- 敵を外した後の戦闘と、`start_battle` を抜いた後の会話が普通に続くこと

#### 確認手順

1. デバッグモードは要らない。注入して、仲間を1人以上連れて施設の NPC と会話する
2. 会話か自由入力で戦闘になるよう仕向ける（相手を挑発する・仲間との手合わせを挑む、の2通り）
3. `out\party_opponent.log` を読む

| 出た行 | 意味 |
| --- | --- |
| `敵から仲間を外した [...] -> [...]` | 決着。残った敵だけで戦闘が始まり、普通に終われば経路全体が成立 |
| `敵が仲間だけ [...] だったので戦闘を起こさない` | 手合わせの回はこれで決着（戦闘に入らず会話が続くこと） |
| `敵=[...] に仲間は居ない。素通し` | 仕組みは効いている。仲間が選ばれる回をまだ引いていないだけ |
| `素通し（同行者なし）` | 名簿が読めていない。仲間を連れているのにこれが出たら `ui.party_member_ids` の読みが外れている |
| `player_opponents を書き換えられなかった` | 代入が pydantic の検証に落ちている。型の読みから見直す |
| 行が1つも無い | フックが4関数に当たっていない（`llm_manager` の遅延 import。TECH.md §3.4） |
