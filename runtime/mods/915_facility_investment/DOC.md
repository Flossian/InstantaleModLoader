## 1. 遊び方（`docs\MODS.md` 相当）

### `915_facility_investment`: 街に施設を建てる（出資する）

素のゲームの街は生成された時点で固まっていて、遊んでいる側が何かを足す手段が無い。
この MOD は役場（役場の選択肢）に出資の窓口を1つ足す。

```text
[役場]  労働の募集をみる / 市民権の発行 / 施設の建設（出資） / 出る
                                ↓
        宿屋を建てる / 闘技場を建てる / 持っている施設 / やめる
                                ↓
        並(12,000G) / 上等(21,600G) / 最上(38,400G) / やめる
                                ↓
        入口の下の区画の1つに建物が1軒増え、主人が1人立つ

[入口]  中央居住区 / 外縁スラム / 街を出る
[区画]  雑貨店 / 鍛冶屋 / 灯火亭 ←これ / 入口へ戻る
                                ↓
[宿屋]  宿泊する(4ヵ月) / 会話する / 無料で泊まる / 売上を受け取る(1,800G) / 出る
[闘技場] 試合に出る / 会話する / 売上を受け取る(9,000G) / 出る
```

宿屋の `宿泊する` と `会話する` はゲーム自身が出すもの（`inn` 型の施設として扱う）。
この MOD が足すのは `無料で泊まる` と `売上を受け取る` と `出る`。
`無料で泊まる` は設定の部屋（既定 個室）で宿代なしに泊まる。ゲームの `宿泊する` は自分の宿屋でも普通に宿代を取る
（版33 までは同じ `宿泊する` で払って後から返していたが、見えないので別のボタンにした。版34）。
`会話する` の一覧には主人が並ぶ。

建物は入口の下の区画（`ward`）の1つに繋ぐ。どの区画かは建物ごとに決まり、建て直しても変わらない。
入口に置く `914_real_estate` の家とは場所が違う（入口に置くと街に着いた瞬間に店が見え、区画を回っても見つからない。実機 2026-09-13 の指摘）。

### 建てられるものは街の規模で決まる

街には規模がある（村・町・都市。ゲームが世界を作るときに決めていて、以後変わらない）。
規模が決めるのは2つ。

**1. その街に建てられる合計の軒数**（種類は問わない）。

| 村 | 町 | 都市 |
| --- | --- | --- |
| 1軒 | 2軒 | 3軒 |

数えるのは**この MOD で建てた分だけ**で、ゲームが最初から置いた施設は数えない。

**2. 種類ごとの最低の規模。**

| 種類 | 建つ規模 | 中でできること |
| --- | --- | --- |
| 宿屋 | 村から | `無料で泊まる`（設定の部屋、宿代なし）。ゲームの `宿泊する` は宿代を取る。主人と話せる |
| 雑貨店 | 村から | ゲームの売買 |
| 鍛冶屋 | 村から | ゲームの売買 |
| 専門店 | 村から | ゲームの売買 |
| 道場 | 町から | ゲームの訓練 |
| 闘技場 | 町から | ゲームの試合 |

**中身はどれもゲーム自身のもの。** 中の選択肢は施設の種類から本体が出すので、
この MOD が足すのは `売上を受け取る` と出口だけになる（§3.2 の11回目・18回目）。
枠が埋まった街では窓口に何も並ばないが、**条件は窓口の本文に必ず出る**（版15）。

```text
雲上神殿（村）にいま建てられるものは無い。条件はこうだ。
この街に建てられるのは合計1軒まで（いま1軒。空きが無い）
道場: 町から（村には建たない）
闘技場: 町から（村には建たない）
```

建てられるときは合計の行だけが出る（`この街に建てられるのは合計3軒まで（いま1軒）`）。

村に道場と闘技場が建たないのは実セーブの数え方から決めた（56街の村19に1軒も無かった。§3.1）。

### 費用と売上

```text
費用      = 種類の基礎額 × 等級 × 街の規模
1日の売上 = 種類の基礎売上 × 等級 × 街の規模
```

| | 並 | 上等 | 最上 |
| --- | --- | --- | --- |
| 費用の倍率 | ×1.0 | ×1.8 | ×3.2 |
| 売上の倍率 | ×1.0 | ×1.5 | ×2.2 |

| | 村 | 町 | 都市 |
| --- | --- | --- | --- |
| 費用の倍率 | ×0.6 | ×1.0 | ×1.8 |
| 売上の倍率 | ×0.5 | ×1.0 | ×2.0 |

都市は高いが儲かり、村は安いが細い。
上の等級ほど費用の伸びが売上の伸びより大きいので、回収は遅くなる（見栄の値段）。

```text
宿屋・並・町       20,000G で建ち、1日 60G   → 約 330 日で回収
雑貨店・並・町     25,000G で建ち、1日 70G   → 約 360 日で回収
道場・上等・都市  113,400G で建ち、1日 240G  → 約 470 日で回収
闘技場・最上・都市 691,200G で建ち、1日 1,320G → 約 520 日で回収
```

### 主人

建物を建てると、主人が1人一緒に生まれてその施設の主になる。
雇っているのではない（どこかで雇ってくるわけではなく、施設と一緒に生まれて、施設と一緒に居る）。
**主人はゲームと同じ生成 AI が1人ずつ作る**（版26）。建てるときに1回だけ聞き、
名前・老若男女・話し方・人柄・素性がその世界とその街に合わせて返る。
答えは帳簿に控えるので、建て直しでもロードでも同じ人が戻る（二度と聞かない）。

生成 AI が答えない・読めない・その版に載っていないときは、用意した12人から選ぶ。
設定（`KEEPER_SOURCE`）を `table` にすると最初から12人から選ぶ（待ち時間ゼロ）。
どちらでも、同じ世界に同じ名前の主人は出ない。

主人が居るので、宿屋では本体の宿泊がそのまま動く（宿泊は施設の主を名簿から引く。主が居ないと落ちる）。
「会話する」の一覧にも並ぶ（実機 2026-09-13）。
**主人はプレイヤーを出資者だと知っている**（版13）。
素性（`profile`）に出資者の名が入り、好感度は「多少の好意がある」から始まり、
会話のたびに「いま話している相手はこの施設を建てた出資者で、雇い主にあたる」という一文が頼み文に足される（`modnpc` の `notes`）。
版12 までに生まれた主人にも、次に建物へ入ったときに好感度と一文が効く。

### 店と道場

店は3種類ある（雑貨店・鍛冶屋・専門店。ゲームの `general_store` / `blacksmith` / `specialty_shop`）。
中では本体の売買がそのまま開き、品はゲームが主人の持ち物として作る。
道場は本体の訓練（費用と3年で経験値・能力値・スキル）がそのまま動く。

どちらも**素データを施設 id で引く**経路なので、中に立っている間だけ写しを置いている（§3.2 の11回目と同じ仕掛け）。
写しが間に合わないうちに押されたときのために網も張ってあり、落ちても「…」で止まらず選択肢に戻る。

### 闘技場の相手

試合の相手はゲーム自身が作る（`colosseum_enemy_generator`）。
ゲームの頼み文は世界観・エリア・施設名と概要・強さのランクだけで、前に出た相手を載せないので、
同じ施設では毎回ほぼ同じ人物に収束することがある（実機で4試合とも「黄金の…アウレリウス」。§3.2 の14回目）。
自分の闘技場では、既に出た闘士の名前を概要の末尾に足して「これらとは別の闘士を」と頼む（版13）。
本物の闘技場には触らない。

### 売上は訪ねて受け取る

日数が進んでも勝手には入らない。
建物へ行って「売上を受け取る」を押すと、**前回受け取った日からの日数 × 1日の売上**が入る。
溜まるのは設定の日数（既定 360 日）ぶんまでで、それ以上は放置しても増えない。

窓口の「持っている施設」で、全部の建物の溜まりが一度に見える。

### セーブには残らない

建物も主人もセーブには書かない。
控えは3つに分かれる。

| ファイル | 中身 |
| --- | --- |
| `state\facility_investment\<世界名×主人公名>.json` | 出資の帳簿（どの土地に何を建てたか、いつ受け取ったか） |
| `state\modfacility\<世界名×主人公名>.json` | 建物そのもの（ローダが持つ） |
| `state\modnpc\<世界名×主人公名>.json` | 主人（ローダが持つ） |

MOD を外せば街は素のまま。建物も主人も、そこへ繋がる道も残らない。

**控えは世界×主人公で1つ**（版27）。主人公が死んで同じ世界で新しい主人公を作ると、
ゲームは世界を初期化して組み直す。前の主人公の建物も主人も、新しい主人公には現れない。
前の主人公のセーブをバックアップから戻せば、建物も主人も戻る（控えは消していない）。
同じ名前で作り直したときだけ、前の主人公の建物を引き継ぐ。

設定はローダの設定画面の「設定…」から開く**同梱の画面**（`tool.py`）で編集する。
種類を行、建設費・1日の売上・最低の規模を列にした表で、隣に都市・最上での値札が出る。
共通の5項目も同じ画面。どの世界でも効く（ワールド個別はまだ無い）。

| 設定 | 意味 |
| --- | --- |
| 種類ごとの建設費（6件） | 既定は表と同じ。**並・町で建てるときの額**で、等級と街の規模と下の倍率がこの上に掛かる |
| 種類ごとの1日の売上（6件） | 既定は表と同じ。同じく並・町のときの額 |
| 種類ごとの最低の規模（6件） | 既定は表と同じ（村／町）。下げれば村にも闘技場が建つ |
| 建設費の倍率（%） | 既定 100。上の額にそのまま掛ける |
| 売上の倍率（%） | 既定 100 |
| 売上を溜めておける日数 | 既定 360。この日数ぶんで頭打ち |
| 「無料で泊まる」の部屋 | 既定 個室。ゲームの宿屋と同じ語彙。ゲームの `宿泊する` は宿代を取る |

### 困ったとき

| 症状 | 見るところ |
| --- | --- |
| 役場に「施設の建設（出資）」が出ない | 会話・戦闘・買い物の最中は出さない。それ以外で出ないときは `out\facility_investment.log` に `office:` の行があるか |
| 窓口に何も並ばない | 本文に「いま建てられるものは無い」と出ていれば規模か軒数の上限。「出資を受け付けていない」なら、その土地の規模が読めていない（ダンジョンは街ではない） |
| 建てたのに建物が見当たらない | ログの `built:` と `modfacility: built` の行。無ければ `WARN` を見る |
| 建物に入っても選択肢が出ない | ログの `modfacility: where:` の行（`914_real_estate` と同じ見方） |
| 主人が居ない | ログの `modnpc:` の行。`did not spawn` が出ていれば `modnpc` の関所が立っていない世代（`out\status.json`） |
| 売上が増えない | 日数が進んでいない（移動も宿泊もしていない）か、溜まりの上限に達している |
| 「無料で泊まる」で宿代が引かれた | ログの `stay: refunded` が無ければ返せていない（ゲームの `宿泊する` は引かれるのが正しい） |
| 帳簿をやり直したい | `state\facility_investment\<世界名×主人公名>.json` を消す。建物と主人はロードし直すと消える（ローダの控えは `unregister` を通らないので `state\modfacility\` と `state\modnpc\` の同名ファイルも消す） |

## 3. 検証の記録（`docs\VERIFICATION.md` §3 相当）

### 3.1 設計の根拠（実セーブ6世界、2026-09-13）

**語彙はゲームのもの。** 種類は `facility_type`、等級は `tier`、規模は `area["size"]`。
実セーブ6世界の施設を全部数えた。

| `facility_type` | 件数 | `tier` |
| --- | --- | --- |
| `inn` | 52 | `basic` / `standard` / `advanced` |
| `colosseum` | 6 | 同じ |
| `training_facility` | 4 | 同じ |

`tier` は全312件がこの3語だけ。`config` は `{"level_of_detail": 0}` だけで、`owner` は主の id。
**主の `job` は `facility_type` と同じ語**（GAME.md §2.13.1 の 67件中66件）なので、主人の `job` にはそれを入れる。

**種類ごとの最低の規模は街を数えて決めた。** 56の街（村19・町25・都市12）で、

| | 村 | 町 | 都市 |
| --- | --- | --- | --- |
| `inn` の実数 | 0〜1 | 1〜2 | 0〜2 |
| `colosseum` の実数 | 0 | 0〜1 | 0〜1 |
| `training_facility` の実数 | 0 | 0〜1 | 0〜2 |

闘技場は町にも2つあった（村には無い）ので、最低の規模は「町」にした。
本人の指定は「辺鄙な田舎に闘技場ができるのはおかしい」で、村を外せば足りる。

**軒数のほうは種類ごとではない**（本人の指定、2026-09-14。§3.2 の19回目）。
その街に建てられる合計（村1・町2・都市3）で、数えるのはこの MOD で建てた分だけ。

**`area["size"]` は実行時の `Area.size` からは読めない**（`324_` の実機 38/38 で取れず。GAME.md §2.7）。
`save_data_dict["areas"][id]["size"]` から取る。`dungeon` は街ではないので窓口を出さない。

**中身はゲーム自身の経路。こちらは選択肢を組まない。**
版1は「実行時に足した施設で本体の売買を起こすと `world_dict` を引いて `KeyError` で落ちる」（GAME.md §2.28）を理由に
店を外し、道場は `DisplayTrainingChoice(app, training_type)` の語彙が読めないので伏せ、宿屋と闘技場だけで始めた。
その後の実機で前提が2つ変わった。

- **中の選択肢は本体が `facility_type` から出す**（`inn` の `宿泊する`、`colosseum` の `試合に出る` / `観戦する`。§3.2 の3回目と12回目）。
  こちらが `VacationStartManager` や `DisplayTrainingChoice` を組む場面は無いので、`training_type` の語彙も要らない
- **素データを施設 id で引く経路は `plain=True` で通る**（闘技場の試合。§3.2 の11〜12回目）。売買の `KeyError` も同じ穴

版16 はこの2つを踏まえて、店3種（`general_store` / `blacksmith` / `specialty_shop`）と道場を足した。
写しを置くのは素データを引く種類だけで、宿屋は要らない（`VacationStartManager` は実体で足りた）。
店と道場の中身は**まだ実機で通していない**（§3.3 の 15〜16）。

**主人は施設と一緒に生まれる**（本人の指定：雇用ではなく、生成時に同時に生成して配置するだけ）。
`modnpc.register` → `spawn` → `place(owner=True)`。
素データは**建てるときに1回だけ生成 AI に作らせ**（版26。`llm.ask` + `create_structure`）、
答えを帳簿（`keeper_fields`）に控えて建て直しに使う。
作らせるのは4つ（名前・`category`・`speech_style`・`personality`）と素性の文だけで、
職・好感度・レベルはこちらが決める（ゲームの語彙と、出資者への態度を外さないため）。
能力値・見た目・技はゲームの詳細生成が会話の直前に埋める。
答えが読めないときは12人の表から選び、**その世界で使っている名前は飛ばす**（版25）。
`category` は実セーブの NPC 541 人が使う10語（`young woman` / `middle-aged man` …）から取った。

**主人を置くのはこの MOD。** `modnpc` の自動の置き直しは、施設が先に建っている保証を持たない
（フレームワークどうしは順序を約束しない。TECH.md §5.8）。
`apply_holdings` が建物を建てた後に `modnpc.place` を呼ぶ。
`modnpc` 側が先に控えから置こうとして `facility not found` を1行出すことはある（害は無い。次の塗り直しで置く）。

#### 5回目（同日 → 版6）: 主人が居ない

建物の並びは直った。今度は `会話する` の一覧に主人が出ない。
名簿には居る（保存のたびに `2 instance(s) hidden from the roster`）が、
ロード以降 `modnpc: ... is at ... as the owner` の行が1つも無い。

**`modnpc.place` が、読み直しの最中に前の世界の施設へ置いていた。**
`World.__init__` を包んでいる間は `app.world` がまだ前の世界を指していて、
`place` はそこから施設を引く。前の世界のノードには前の建物が残っている（`forget` は街から消さない）ので、
**引けてしまい、成功して記録（`placed`）まで立つ**。
実体の `.location` は古いオブジェクトになり、会話の一覧（`world.characters` を舐めて
各人物の `.location` を今の施設と突き合わせる）はその人物を出さない。
`modnpc.place` / `unplace` / `facility_of` に `world` を足し、`restore_world` から渡すようにした。

**この MOD 側の判定も記録では足りなかった。**
`keeper_placed`（`placed` があるか）は、上の形では真になってしまう。
実体の `.location` が**今の建物か**で見る（`keeper_at`）。世界を読み直せば施設は別のオブジェクトになる。

**関所の順序は環境で変わる。** 実機では `229_probe_mod_npc` が先に `modnpc.install` を呼ぶので
`World.__init__` の後処理は `modnpc` → `modfacility` の順（内側から走る）。
この MOD だけの検査では逆（`modfacility` が先）で、**建物が先に建つので問題が出ない**。
検査の側を実機と同じ順に揃えた（`setup` が `modnpc.install` を先に呼ぶ）。
どちらの順でも成り立つように、主人を置くのは実体を見てからにしてある。

#### 6回目（同日 → 版7）: それでも主人が出ない

版6でも `会話する` の一覧に主人が出ない。今度は `229_` の記録で差が取れた。
20:28（出た）と 21:36（出ない）の `talk list` を並べると、読みの並びが1点だけ違う。

```text
20:28  … 'visitor .name', "world.characters ['keeper']", "world.characters 'keeper' in"
21:36  … 'visitor .name',                                "world.characters 'keeper' in"
```

ゲームは `world.characters.items()` を舐めて各人物の `.location` と `.config` で候補を絞り、
候補だけ `world.characters[id]` で引き直す。21:36 は主人が**候補から落ちている**。

原因の候補として確かめられたのは1つ。
`229_` は施設に着くたびに主の id（＝この MOD の主人）へ被せの層を `modnpc.register` で積み直す。
`modnpc.register` は「同じ持ち主の登録し直し」で実体の参照を捨てる作りだったので、
**別の持ち主（229）の積み直しで、この MOD の主人の参照が捨てられていた**。
参照が無いと `place` / `unplace` / `snapshot_all` は実体に触れず、
保存のたびの `unplace` → `place` で `.location` が据わらないまま残る。

直したのは `modnpc` 側が3つ、この MOD 側が2つ。

| どこ | 何 |
| --- | --- |
| `modnpc.register` | 実体を捨てるのは**その id の持ち主**が登録し直したときだけ（`owner == owner_of_id(id)`）。次の `spawn` は組み直す（`rebuild` の印） |
| `modnpc.spawn` | 参照だけ落ちて実体が名簿に居れば、組み直さずそれを採る（記憶や HP を巻き戻さない） |
| `modnpc.place` / `unplace` / `snapshot_all` | 参照が無ければ名簿の実体を引く |
| `keeper_at` | 中に立っているときは、プレイヤーが立っている実体とも同じかを見る |
| `note_keeper` | 建物に立つたびに主人の姿を1行書く（`keeper: … location_is_building= … config= …`）。一覧に出ないときはこの行が手掛かり |

`.location` が本当に古かったかは実機で確かめていない（記録に主人側の読みが残らないため）。
次に出なければ `keeper:` の行で、`location_is_player_location` と `config` のどちらが外れているかが分かる。

#### 7回目（同日 → 版8）: `keeper:` の行で決着

```text
keeper: … in_roster=True record_has_instance=True same_instance=False
        location_is_building=False location_is_player_location=False location_id='0'
        config={'level_of_detail': 1, …, 'difficulty_level': 4} level=5 in_facility_characters=True
```

名簿に居る主人は、こちらが置いた実体と**別のオブジェクト**（`same_instance=False`）。
`difficulty_level` が 2 → 4 に変わっているので、詳細生成（会話の直前にゲームが埋める処理）が走り、
**ゲームが `Character` を作り直して名簿を差し替えた**。
`modnpc` の記録は古い実体を掴んだままなので、`.location` を据えても新しい実体には届かず、
`.location` はゲームが素データから解いた別の施設（id `0`）のまま。会話の一覧はそれを見て落とす。
`229_` の来訪者で気付かなかったのは、229 が施設に着くたびに置き直していたから。

`modnpc` を**名簿の実体が真実**に寄せた。
`_character_at` は名簿に居ればそれを返して記録も合わせ、差し替わっていれば印を立てる。
`place` / `unplace` / `snapshot_all` / 取っ手はそこを通る。
詳細生成の後は `replace_if_stale` が控えの置き場所へ新しい実体を据え直す。

**売上のボタンが2つ**は別の原因。建物の中に立ったまま保存すると、印の無い自前のボタンが

復元されたときの文言と今の文言が違い、前方一致の掃除に掛からなかった。
`modfacility.our_labels` が、関数で宣言した選択肢もいま組んで文言を集め、括弧の前までを鍵に足すようにした。

**版8 で通った**（同日 22:02）。`keeper:` の行が `same_instance=True location_is_player_location=True` になり、
オズワルドが `会話する` の一覧に並んで会話できた（`save: entering (in_conversation=mod:915_…:keeper-5-1)`）。

#### 8回目（同日 → 版9）: ロードで背景が2回読み込まれる

建物の中でロードすると部屋の絵が2回読み込まれる。
こちらの「立っているのに描いていなければ描く」予約（`ensure_background`）が先に走り、
その後にゲームの経路（`change_background_image_to_current_location`）が来て、

同じ滞在で既に描いてあれば描き直す理由が無い。
ゲームが**よその絵**を描いたとき（本体が走った後）に描いた覚えを消す形にして、

#### 9回目（同日 → 版10）: 闘技場に背景が出ない。出ても元の絵が出ない

**背景は施設の名前で保存されている。** `worlds\<世界>\backgrounds\<施設名>\image.png` で、
この世界には `金羊亭 - room(private_room)`（宿の部屋。こちらが借りた絵）も `祝祭の円形闘技場`（本物）も在った。
本体の `change_background_image_to_current_location` は `player.location` の**名前**で絵を引き、
無ければ生成して保存する。実行時の施設でもこの経路は通る。
914 が「ゲームは背景を施設 id から引くので自作の施設には描けない」と読んだのは
`change_background_image_from_location_id`（`self.app` で必ず落ちる本体の不具合）の側だけの話だった。

こちらの包みは「MOD の施設なら本体を呼ばない」にしていたので、
部屋の絵を借りない闘技場では**ゲームが絵を生成する機会まで奪っていた**。
出た後に元の絵が出ないのも同じ穴（立っている間に来た本体の描画を止めていた）。
層が描かなかったときは本体を通す形に直した（`modfacility`）。
闘技場は最初に入ったとき、ほかの新しい施設と同じように絵が生成される（数秒かかる）。
名前で引かれるので、**同じ名前の建物を2つの街に建てると絵を共有する**（`catalog` の候補名は街の名を含むものが多い）。

#### 10回目（同日 → 版11）: 闘技場の試合に出るとエラー

都市の闘技場（`mod:915_facility_investment:8-1`）で「試合に出る」→「申し込む」を押すと、

#### 11回目（同日 → 版12）: 「試合に出られない」

**1. 焼かれる選択肢はその瞬間の画面。**
セーブの `game_variables["buttons"]` はそのとき画面に出ていた選択肢で、
ロードはそれをそのまま出す（画面を組み直さない。GAME.md §2.3）。
会話の画面を焼くと、ロード後に並ぶのは相手の居ない会話の残骸で、
建物の入口（`会話する` / `売買する`）はどこにも無い ― NPC が消えたように見える。
実際、ロード後のセーブの `buttons` は `売買する` / `売上を受け取る` / `出る` で、`会話する` が落ちていた。

版21 は**会話・戦闘・自由入力の最中は中のまま保存しない**（`keep_inside` が偽を返す）。
入口へ移して入口の選択肢を焼くので、ロード後は普通の入口の画面になる。
建物へ入り直せば、ゲームが施設の画面を組み直す。

**2. 持ち物は品ごと辞書に均さないと控えに入らない。**
`Character.inventory` は入れ物のオブジェクト、その中の品も `Item` のオブジェクトで、
どちらも JSON に落ちない。版18 で入れ物は剥がしたが、中身が `Item` のままだったので
控えの `inventory` は**空のまま**だった（実測：店の主人の控えは 0 件、`index.item` は 7 つ進んでいた）。

版21 は品を1件ずつセーブと同じ形の辞書に均して控え、戻すときはゲーム自身に作り直させる
（`InstantaleApp.generate_item_from_dict`。`914_` の保管庫が実機で通した経路）。
この知識はローダの `instantale_modloader.items` に1か所だけ置き、`914_` の保管庫もそこを呼ぶ形にした
（同じ知識を2か所に置くと、片方だけ直して取りこぼす）。

### 3.4 オフラインで確かめたこと（`tools\tests\test_wip_facility_investment.py`、210件）

偽の `Facility` / `VacationStartManager` / `EntryColosseumMatchManager` / `ColosseumMatchStart` / `Character` / `Clock` を差し込んで、
表・種類ごとの設定・窓口・出資・上限・建物の中・売上・宿泊・闘技場・保存・ロード・別の世界・新しい主人公・設定画面・例外の15場面を通している。

- 規模ごとの可否と合計の軒数（村1・町2・都市3。種類ごとの `cap` は表に無い）、値段が 100G 単位、名前が鍵で決まる、6種類が窓口に出る、写しが要るのは売買と試合の種類だけ
- 役場でだけ「出資する」が出て、塗り直しても増えない。村では宿屋だけ、町では闘技場も並ぶ（道場は窓口に出ない）
- 建てられても建てられなくても、全部の種類の条件が本文に並ぶ（規模で建たない／軒数／空きが無い。ゲームの施設も数に入る）
- 等級を選ぶと所持金が減り、入口の下の区画に繋がって建ち（入口には繋がない）、id はローダの名前空間（ゲームの台帳は進まない）、種類と等級が施設に載る
- 主人が名簿に居て、施設の主で、職は施設の種類で、施設に立っている。帳簿に出資者と主人の名が残り、`profile` に入り、会話の `notes` に「出資者本人」の一文が組まれる。
- 同じ世界の主人は名前が重ならない（使っている名前は飛ばす。控えが無い持ち株は当て直しで埋め、重なっていれば後の方を寄せる）
- 別の世界を読むと建物も主人も道も無く、窓口は0軒から始まる。そこで保存しても前の世界の建物は別の世界の控えへ漏れず、前の世界の帳簿も減らない。元の世界に戻れば建ち直る
- 同じ世界で新しい主人公を作る（別の名のセーブを読む）と、前の主人公の建物も主人も道も無く、ログに周回の鍵が出る。前の帳簿はそのまま残り、新しい主人公が建てれば別のファイルにでき、建物は帳簿の名前で建ち（前の周回の写しではない）、その主人は新しい主人公を出資者と知っている。元の主人公に戻せば建物も主人も戻り、二代目の建物は持ち込まれず、主人は元の主人公を出資者と言う
- 建てるときに生成 AI へ1回だけ聞き（頼み文に世界・土地・施設・出資者が入り、待つ秒数を必ず渡す）、答えの名前と人柄で主人が立つ。
  職と好感度は表のまま。答えは帳簿に控えて塗り直しでも聞き直さない。読めない・落ちた・載っていない・設定が `table` なら表から建つ
  版12 までの主人（警戒心がある）は当て直しで好感度が 40 に上がり、育った値は下げない
- 村は1軒建てたら打ち止め（種類を問わない）。ゲームが最初から置いた宿屋は数に入れない
- 中では「泊まる」「売上を受け取る」と出口が出る。自前のボタンの spec は無害なクラス、印は `mod_` で始まる
- 絵は MOD が描かない。建物に立つとゲームに名前で1度だけ描かせ、部屋の絵は借りない（宿屋も闘技場も）
- 30日ぶんの売上が入り、受け取った日が帳簿に残り、溜まりは `HOLD_DAYS` で頭打ち
- 自分の宿屋の宿代は返り、暦は進み、宿泊中は自前の選択肢を混ぜない。よその宿屋には触らない
- 町の闘技場は1軒で打ち止め。建てただけでは素データに写らず、中に立つと `save_data_dict` と `world_dict` の両方に8項目の写しが置かれ（`config` は実体と同じ辞書、主は主人）、
  素データを施設 id で引くゲームの試合が通って `current_phase` が実体に載る。写しが無いまま試合まで進んでも落ちずに操作が戻り、よその闘技場には触らない。外に出ると写しが外れる
- 保存の間は写しが外れ、後で戻り、試合の進みが控えに写る（対戦相手の int の鍵は str に寄る）。ロードで試合の進みも戻る
- 既に出た闘士を `config` から鍵の順に拾い、1人ずつ `「」` で括って `location` の身代わり（辞書でも実体でも）の概要に足す。本物の概要は変わらず、既出が無ければそのまま
- 店と道場も窓口に並び、建つと主人の職が施設の種類になり、中に立つと写しが置かれ、ゲームの売買・訓練が通る。
  会話の最中も、会話相手の一覧にも混ぜず、終われば戻る
  写しが無いまま押されても握って操作が戻り（建物の名が本文に出る）、よその施設には触らない
- 主人の層はこの世代で1つだけ（注入し直せば積み直る）
- 保存で主人が名簿と素データの反復から隠れ、建物の中のまま保存し、保存の後は主のまま
- ロードで建物が建ち直り、名前も等級も戻り、主人が主として戻り、入口に道が出て、押すとゲームの移動が起きる
