## 1. 遊び方（`docs\MODS.md` 相当）

### `915_facility_investment`: 役場に出資して街に施設を建て、売上を受け取る

素のゲームの街は生成された時点で固まっていて、遊んでいる側が何かを足す手段が無い。
この MOD は役場（役場の選択肢）に出資の窓口を1つ足す。

```text
[役場]  労働の募集をみる / 市民権の発行 / 出資する / 出る
                                ↓
        宿屋を建てる / 闘技場を建てる / 持っている施設 / やめる
                                ↓
        並(12,000G) / 上等(21,600G) / 最上(38,400G) / やめる
                                ↓
        街の入口に建物が1軒増え、主人が1人立つ

[入口]  中央居住区 / 外縁スラム / 灯火亭 ←これ / 街を出る
                                ↓
[宿屋]  泊まる / 売上を受け取る(1,800G) / 出る
[闘技場] 試合に出る / 売上を受け取る(9,000G) / 出る
```

建物はその土地の入口に繋ぐ（`914_real_estate` の家と同じ場所）。

### 建てられるものは街の規模で決まる

街には規模がある（村・町・都市。ゲームが世界を作るときに決めていて、以後変わらない）。
種類ごとに「最低の規模」と「軒数の上限」があり、上限には**ゲームが最初から置いた施設も数える**。

| 種類 | 村 | 町 | 都市 | 中でできること |
| --- | --- | --- | --- | --- |
| 宿屋 | 1軒 | 2軒 | 3軒 | 泊まる（宿代は取られない） |
| 闘技場 | 建たない | 1軒 | 1軒 | 試合に出る |
| 道場 | 建たない | 1軒 | 2軒 | **まだ出さない**（§3.3） |

宿屋が既に1軒ある村では宿屋は建てられず、闘技場は町からになる。
上限に達した種類は窓口に並ばない。

軒数の目安は実セーブ6世界・56の街を数えて決めた（§3.1）。

### 費用と売上

```text
費用      = 種類の基礎額 × 等級 × 街の規模
1日の売上 = 種類の基礎売上 × 等級 × 街の規模
```

| | 並 | 上等 | 最上 |
| --- | --- | --- | --- |
| 費用の倍率 | ×1.0 | ×1.8 | ×3.2 |
| 売上の倍率 | ×1.0 | ×1.5 | ×2.2 |

| | 村 | 町 | 都市 |
| --- | --- | --- | --- |
| 費用の倍率 | ×0.6 | ×1.0 | ×1.8 |
| 売上の倍率 | ×0.5 | ×1.0 | ×2.0 |

都市は高いが儲かり、村は安いが細い。
上の等級ほど費用の伸びが売上の伸びより大きいので、回収は遅くなる（見栄の値段）。

```text
宿屋・並・町      20,000G で建ち、1日 60G  → 約 330 日で回収
闘技場・最上・都市 691,200G で建ち、1日 1,320G → 約 520 日で回収
```

### 主人

建物を建てると、主人が1人一緒に生まれてその施設の主になる。
雇っているのではない（どこかで雇ってくるわけではなく、施設と一緒に生まれて、施設と一緒に居る）。
名前と人柄は6人の中から建物ごとに決まり、建て直しても同じ人が居る。

主人が居るので、宿屋では本体の宿泊がそのまま動く（宿泊は施設の主を名簿から引く。主が居ないと落ちる）。
「会話する」の一覧にも並ぶはずで、話しかければ出資者として扱われる（§3.3、未確認）。

### 売上は訪ねて受け取る

日数が進んでも勝手には入らない。
建物へ行って「売上を受け取る」を押すと、**前回受け取った日からの日数 × 1日の売上**が入る。
溜まるのは設定の日数（既定 360 日）ぶんまでで、それ以上は放置しても増えない。

窓口の「持っている施設」で、全部の建物の溜まりが一度に見える。

### セーブには残らない

建物も主人もセーブには書かない。
控えは3つに分かれる。

| ファイル | 中身 |
| --- | --- |
| `state\facility_investment\<世界名>.json` | 出資の帳簿（どの土地に何を建てたか、いつ受け取ったか） |
| `state\modfacility\<世界名>.json` | 建物そのもの（ローダが持つ） |
| `state\modnpc\<世界名>.json` | 主人（ローダが持つ） |

MOD を外せば街は素のまま。建物も主人も、そこへ繋がる道も残らない。

| 設定 | 意味 |
| --- | --- |
| 建設費の倍率（%） | 既定 100。表の値段にそのまま掛ける |
| 売上の倍率（%） | 既定 100 |
| 売上を溜めておける日数 | 既定 360。この日数ぶんで頭打ち |
| 自分の宿屋に泊まるときの部屋 | 既定 個室。ゲームの宿屋と同じ語彙。宿代は取られない |

### 困ったとき

| 症状 | 見るところ |
| --- | --- |
| 役場に「出資する」が出ない | 会話・戦闘・買い物の最中は出さない。それ以外で出ないときは `out\facility_investment.log` に `office:` の行があるか |
| 窓口に何も並ばない | 本文に「いま建てられるものは無い」と出ていれば規模か軒数の上限。「出資を受け付けていない」なら、その土地の規模が読めていない（ダンジョンは街ではない） |
| 建てたのに建物が見当たらない | ログの `built:` と `modfacility: built` の行。無ければ `WARN` を見る |
| 建物に入っても選択肢が出ない | ログの `modfacility: where:` の行（`914_real_estate` と同じ見方） |
| 主人が居ない | ログの `modnpc:` の行。`did not spawn` が出ていれば `modnpc` の関所が立っていない世代（`out\status.json`） |
| 売上が増えない | 日数が進んでいない（移動も宿泊もしていない）か、溜まりの上限に達している |
| 宿泊で宿代が引かれた | ログの `stay: refunded` が無ければ返せていない |
| 帳簿をやり直したい | `state\facility_investment\<世界名>.json` を消す。建物と主人はロードし直すと消える（ローダの控えは `unregister` を通らないので `state\modfacility\` と `state\modnpc\` の同名ファイルも消す） |

## 3. 検証の記録（`docs\VERIFICATION.md` §3 相当）

### 3.1 設計の根拠（実セーブ6世界、2026-09-13）

**語彙はゲームのもの。** 種類は `facility_type`、等級は `tier`、規模は `area["size"]`。
実セーブ6世界の施設を全部数えた。

| `facility_type` | 件数 | `tier` |
| --- | --- | --- |
| `inn` | 52 | `basic` / `standard` / `advanced` |
| `colosseum` | 6 | 同じ |
| `training_facility` | 4 | 同じ |

`tier` は全312件がこの3語だけ。`config` は `{"level_of_detail": 0}` だけで、`owner` は主の id。
**主の `job` は `facility_type` と同じ語**（GAME.md §2.13.1 の 67件中66件）なので、主人の `job` にはそれを入れる。

**軒数の上限は街を数えて決めた。** 56の街（村19・町25・都市12）で、

| | 村 | 町 | 都市 |
| --- | --- | --- | --- |
| `inn` の実数 | 0〜1 | 1〜2 | 0〜2 |
| `colosseum` の実数 | 0 | 0〜1 | 0〜1 |
| `training_facility` の実数 | 0 | 0〜1 | 0〜2 |

闘技場は町にも2つあった（村には無い）ので、最低の規模は「町」にした。
本人の指定は「辺鄙な田舎に闘技場ができるのはおかしい」で、村を外せば足りる。

**`area["size"]` は実行時の `Area.size` からは読めない**（`324_` の実機 38/38 で取れず。GAME.md §2.7）。
`save_data_dict["areas"][id]["size"]` から取る。`dungeon` は街ではないので窓口を出さない。

**中身の経路は「落ちない経路」だけ。**
実行時に足した施設で本体の売買を起こすと `world_dict` を引いて `KeyError` で落ちる（GAME.md §2.28）ので店は建てない。
宿屋は `VacationStartManager(app, months, quality)`（`914_` が実機を通した）。
闘技場は `EntryColosseumMatchManager(app)`（`out\recon\targets.txt`。施設 id を引数に取らない）。
道場は `DisplayTrainingChoice(app, training_type)` の `training_type` の語彙が分からない。
実セーブの `game_variables.buttons` に道場の選択肢が焼かれている例が無く、
`training_facility` の `config` にもそれらしい鍵が無い。表には置いたが `enabled: False` にした。

**主人は施設と一緒に生まれる**（本人の指定：雇用ではなく、生成時に同時に生成して配置するだけ）。
`modnpc.register` → `spawn` → `place(owner=True)`。
名前と人柄は6人の候補から建物の id の hash で選ぶので、建て直しても同じ人になる。
`category` は実セーブの NPC 541 人が使う10語（`young woman` / `middle-aged man` …）から取った。

**主人を置くのはこの MOD。** `modnpc` の自動の置き直しは、施設が先に建っている保証を持たない
（フレームワークどうしは順序を約束しない。TECH.md §5.8）。
`apply_holdings` が建物を建てた後に `modnpc.place` を呼ぶ。
`modnpc` 側が先に控えから置こうとして `facility not found` を1行出すことはある（害は無い。次の塗り直しで置く）。

### 3.2 オフラインで直したこと（2026-09-13）

検査の土台で1つ踏んだ。
`setup()` が `main.InstantaleApp` を新しい子クラスで差し替えるので、
2回目以降の `setup()` が**前回の子をさらに継承**し、フックが世代のぶんだけ積み重なった。
3回目には `915 → modfacility → 915 → modfacility → 915` の5段になり、
最初の世代の `apply()` が閉包に抱えていた古い控え（建物1軒）から、新しい世界へ建物が生えた。
`914_` の検査が `BASES` に素の基底を別に持っているのはこのためで、同じ形にした。
MOD 側の不具合ではないが、**閉包が控えを抱えたまま世代をまたぐと、消したはずのものが戻る**という形は実機でも起きうる
（注入し直しの後に古い世代のフックが残っていれば同じ）。ローダの世代管理（TECH.md §3.5）がそれを防いでいる。

### 3.4 オフラインで確かめたこと（`tools\tests\test_wip_facility_investment.py`、70件）

偽の `Facility` / `VacationStartManager` / `EntryColosseumMatchManager` / `Character` / `Clock` を差し込んで、
表・窓口・出資・上限・建物の中・売上・宿泊・闘技場・保存・ロード・例外の11場面を通している。

- 規模ごとの可否と軒数、値段が 100G 単位、名前が鍵で決まる、道場は窓口に出ない
- 役場でだけ「出資する」が出て、塗り直しても増えない。村では宿屋だけ、町では闘技場も並ぶ
- 等級を選ぶと所持金が減り、入口のノードに建ち、id はローダの名前空間（ゲームの台帳は進まない）、種類と等級が施設に載る
- 主人が名簿に居て、施設の主で、職は施設の種類で、施設に立っている
- 村の宿屋は1軒で打ち止め。ゲームが最初から置いた宿屋も数に入れる
- 中では「泊まる」「売上を受け取る」と出口が出る。自前のボタンの spec は無害なクラス、印は `mod_` で始まる
- 宿屋の背景は部屋の絵、闘技場の背景には手を出さない
- 30日ぶんの売上が入り、受け取った日が帳簿に残り、溜まりは `HOLD_DAYS` で頭打ち
- 自分の宿屋の宿代は返り、暦は進み、宿泊中は自前の選択肢を混ぜない。よその宿屋には触らない
- 闘技場の入口が起きる。町の闘技場は1軒で打ち止め
- 保存で主人が名簿と素データの反復から隠れ、建物の中のまま保存し、保存の後は主のまま
- ロードで建物が建ち直り、名前も等級も戻り、主人が主として戻り、入口に道が出て、押すとゲームの移動が起きる
