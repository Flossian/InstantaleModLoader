## 1. 遊び方（`docs\MODS.md` 相当）

### `910_conversation_action`: 会話中に ＜＞ で包めば行動になる

会話中の入力はぜんぶ台詞として扱われる。
「薬草を渡す」と打っても相手が受け取ったことにはならず、
渡す・払う・殴りかかるといった行動は、会話を終えて自由入力に戻ってからでないと通らない。

素のゲームにも会話から行動へ抜ける経路はある（会話の LLM が「これは行動だ」と判断したときだけ上位の GM が動く）が、
判断は LLM 任せで、括弧で書いても大半は台詞として返される。
しかも会話からの GM には所持品の一覧が渡らないので、通ったとしても渡す品の名前が創作されることがある。

この MOD を入れると、会話中の入力を **全体を ＜＞ で包んで** 送ったときだけ、
会話の外の自由入力と同じようにゲーム自身の GM が行動として処理する。
半角の `<>` でもよく、全角と半角が混ざっていてもよい。

```
＜鞄から薬草を取り出してマーサに渡す＞
<金貨を50枚カウンターに置く>
＜剣を抜いて斬りかかる>
```

GM には行動の1行と所持品の一覧（名前と説明）を添えるので、
「薬草を渡す」で実際に持っている薬草が相手へ移る。

### どう動くか

- 相手の返事はふつうに出る。その後に GM の語り（結果・アイテムや金の移動・相手の一言）が続く。
  ここから先はゲーム本来の自由行動と同じ
- 台詞の末尾に添えた所作（「こんにちは（笑う）」）は対象外。台詞のまま
- `<行動: 話しかける>` のようなゲーム自身の記法（`行動:` `状況:` `結果:` `確率N%` など）は対象外
- （）は既定では対象外。設定で入れられるが、（）は所作にもよく使うので、雑談のたびに GM が回るようになる
- 仲間へ確実に品を渡したいなら `402_party_inventory_transfer` の窓のほうが向いている（往復も保証される）。
  この MOD の値打ちは、仲間ではない相手（店主・門番・依頼人）に対する行動

| 設定 | 意味 |
| --- | --- |
| （）も行動として扱う | 既定 OFF |
| GM に所持品を見せる | 既定 ON。OFF にすると会話の外の自由入力と同じ材料が無くなる |
| 見せる所持品の上限 | 既定 30。所持品の並び順でここまで |
| GM に渡す行動の1行 / 所持品の1行 | 会話ログの末尾に足す文。`{action}` / `{items}` が差し込まれる |

### 困ったとき

| 症状 | やること |
| --- | --- |
| ＜＞ で包んだのに台詞として返された | `out\conversation_action.log` に `forced free action` が出ているか。出ていなければ包み方（全体を1組で。中に `>` を含めない）。`WARN ... cannot rewrite` なら報告の材料 |
| 相手の返事の後に何も起きない | 同じログに `master_ai_facilitator_from_conversation: +2 line(s)` があれば GM は回っている。行動の結果は GM の判断（失敗も結果のうち） |
| 渡した品の名前が違う | `+1 line(s)` なら所持品が読めていない。設定の上限が 0 か、所持品が空 |
| 雑談のたびに GM が回る | 「（）も行動として扱う」を OFF に |

## 3. 検証の記録（`docs\VERIFICATION.md` §3 相当）

### 会話中の明示行動（`910_`）: 設計の根拠は記録の計数・実機は未（2026-09-05）

会話の入力を行動として処理する経路は素のゲームにある。
`conversation_facilitator` が `action.call_free_action=True` を返すと
`master_ai_facilitator_from_conversation` が回り、14種の権限（`move_item` を含む）を持つ（GAME.md §2.26）。
足りないのは「プレイヤーから明示する手」と「所持品の材料」の2つで、
Epic 版 `output_data\`（全世界、2026-09-05 時点）を数えて確かめた。

**入るかどうか。** `conversation_facilitator` 1,985 件のうち `call_free_action=True` は 88 件（4.4%）。
最後の user 入力に（）か＜＞を含むもので分けると:

| 入力 | 件数 | 自由行動へ行った |
| --- | --- | --- |
| 括弧を含む | 258 | 34（13.2%） |
| 含まない | 1,727 | 54（3.1%） |

括弧つきで書いた行動の 87% が台詞として返っている。
素の指示が `それ以外のあらゆる要求や取引: casual_responseとして返答を記述する` と倒しているため。
`call_free_action=True` の 88 件はすべて `type=casual_response` で `statement` は空でない
（＝相手の返事を出してから GM が回る形）。

**所持品の材料。** 引数の実シグネチャ（`targets.txt`）:

```
master_ai_facilitator(..., choice_text, skill_choice_text, item_choice_text, master_process_log)
master_ai_facilitator_from_conversation(..., conversation_log, master_process_log)
```

会話の外は `【プレイヤーキャラの行動入力】- 使用アイテム: {'名前': '説明'}` が載り、
`move_item` の `item_id` はその**名前**（`master_ai_facilitator` 1,084 件の `move_item` 53 回はほぼ全て入力文か使用アイテムの名前の写し）。
会話からの GM 167 件では `move_item` 3 回、うち 1 回は prompt に無い名前だった。

**半角 `<>` の衝突。** 会話系 3,025 呼び出しの user 側で半角 `<>` の中身を数えた:
`<行動: 話しかける>` 2,848 / `<会話>` `<出来事>` `<要約>` 系 2,872 / `<行動: ○○を売却した。>` 数十 /
`300_` の `<状況: ...>` 約 100 / プレイヤー本人の `<マスターの工具袋をカウンターに置く>` 6。
`conversation_facilitator` の最終 user メッセージに限れば本人の 1 件だけ。
見出し（`行動` `状況` `会話` `出来事` `要約` `結果` `確率` にコロンか `N%` が続く）で除外する。
