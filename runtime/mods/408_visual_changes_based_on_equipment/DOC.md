# `408_visual_changes_based_on_equipment`: 立ち絵を再生成すると装備の見た目が描き足される

立ち絵を再生成するとき、装備している武器・防具の見た目を英語の短い語にして、その回の画像プロンプトへ足すMOD。

## 動作

- 対象は、NPCの画像の再生成と、主人公の立ち絵を描くとき（`335_player_portrait_regenerate`の描き直しと、主人公の作成）。NPCの最初の立ち絵生成（会話を始めたときなど）には介入しない。
- 装備が無い人物には何も足さない（主人公の作成時はふつう装備が無い）。
- LLMに聞くのは、前回と比べて装備の名称・説明・種別、または設定の要素数が変わったときだけ。変わっていなければ控えの語をそのまま足す。
- 強化値、価格、レアリティ、攻撃力、防御力、内部属性、内部IDの変動は比較しない。
- 足すのは画像生成関数へ渡るその1回の引数だけ。ゲーム本体のキャラクター情報、元の画像プロンプト、セーブデータは変えない。

装備の取得は共有部品`equipment.gear()`を使う。333が無い場合だけ、本体の`equipments`にある`weapon`と`wearable`へ戻る。333の部位情報は取得にだけ使い、LLMへは送らない。

本体は`prompt`を配列で渡し、「, 」で繋いで前置き（`full-body, masterpiece, …`と`category`）と後置き（`empty background, …`）の間に置く。
装備の語はその配列の後ろに足すので、外見の語の直後、後置きの前に入る。

## SD1.5 へ渡すもの

画像生成（Stable Diffusion 1.5）へ渡すのは、英小文字・数字・空白・ハイフン・アポストロフィだけでできた4語以内の要素に限る。
日本語などの非ASCII、長すぎる句、SDの強調記法になる括弧は、LLMの返答からも控えからも落とす。
画像生成関数の直前でも、足す分に非ASCIIが混ざっていれば足さずに素のまま生成する。

足す分は「, 」で繋いで60字まで。
元の立ち絵のプロンプト（本体が前置きを足した後）はすでに161〜303字あり、SD1.5のテキストエンコーダが1度に読む75トークンの大半を使っている。
超えた分は効きが薄れるか、方式によっては切り捨てられる。
元のプロンプトに同じ要素があれば足さない。

LLMへは構造化出力（`prompts`の文字列配列）で頼む。構造化出力を作れない環境では自由文の返答から拾う。

## 設定

`EQUIPMENT_PROMPT_COUNT`で、装備が変わったときに作る要素の最大数を決める。
既定値は1、上限は3、0なら何も足さない。
上限が3なのは、上の字数の余地に収めるため。

## ほかの MOD との組み合わせ

| MOD | 組み合わせたとき |
|---|---|
| `335_player_portrait_regenerate` | 人物欄のボタンで主人公の立ち絵を描き直せる。そのときも装備の語を足す |
| `138_fix_character_image_refresh` | 描き直した立ち絵と顔がその場で画面に出る。この MOD は画面を読み直さない |
| `333_equipment_slots` | 装備欄の MOD。入っていれば装備はそこから読む |

MOD 同士は呼び合わない。どれも同じ画像生成関数を通るので、それぞれがそこで働く。

## 控え

`state/equipment_visuals/`に周回（世界×主人公）ごとに1ファイル置く。形は次のとおり。

```json
{
  "characters": {
    "（人物名）": {
      "fingerprint": "装備の見た目と要素数から作ったハッシュ",
      "prompts": ["black leather armor"]
    }
  }
}
```

`fingerprint`を控えるので、ゲームを終了しても装備が変わっていなければLLMに聞き直さない。
装備を外した人物の項目は、次にその人物を再生成したときに消す。
前の版が同じファイルに置いていた主人公の外見（`player_look`）は、次に書くときに消す（335 が自分の控えに持つ）。

## 依存関係

MOD間の直接importは行わない。
333は`equipment`共有窓口、LLMは`instantale_modloader.llm`の`ask`と`create_structure`、設定はmanifest、保存は`state.WorldStore`を使う。
LLMへ送る装備配列には`slot`を含めない。

画像生成関数は、ゲームの`config.json`で選ばれている方式（`sdcpp_cuda` / `sdcpp_vulkan` / `sdcpp_cpu` / `diffusers_openvino`）のものを包む。
読めなければ4つとも包む（入っていない方式は包まれずに待つだけ）。
