# `236_probe_enemy_stats`

敵と味方の強さの出どころを録る。`319_battle_tactics` を「全員が HP・攻撃・防御を持つ形」に組み直すための下調べ。319 の `hit:` の記録から、同じレベルの敵でも素点（`get_instant_damage` に渡る攻撃）・HP・防御が別々に散っていることは読めた（Lv77 で素点 343〜791、HP 720〜1376、防御 200〜328）。その差が何から来るかを測る。録るのは3つ。敵の能力値の生まれ方（`scripts.functions` の `get_enemy_attributes_base_point(段, 難易度)` / `get_character_attributes(基準点, 型)` / `get_npc_attributes(値)` の引数と戻り。`kind: gen`）。戦闘の開始（`BattleStartManager.start_battle` の戻りの後）の敵全員と味方全員の値（名前・レベル・HP・能力値・`get_npc_defense()`・型や大きさらしい項目・スキルの強度と残り回数・装備・戦闘の種類・ボスの旗。項目名が分からない値もあるので、数と短い文字列の項目は全部写す。`kind: start`）。1手ごとの素点（`BattlePhaseManager.calculate_battle_effect` と `resolve_battle_effect` の中で、その手の裁き（`instant_damage` の `power` / `multiplier` / `category`）と、その間に呼ばれた `get_base_damage_value` / `get_instant_damage` の引数と戻り。`kind: act`）。版2では `calculate_battle_effect` について、呼ぶ前後の `battle_action` の全体、戻り値、前後で変わった全員の HP と状態異常（`state_changed`）も録る。版1の実機で、この段の中では `get_base_damage_value` しか呼ばれず HP に当たる `get_instant_damage` は `resolve_battle_effect` にしか無かったので、この段だけをゲームに試し打ちさせて素点を測れるか（状態を動かさないか、素点がどこに出るか）を確かめる。版2の実機で、この段は HP も状態異常も `battle_action` も動かさず、素点を戻り値の1つ目の枠 `{相手: 素点}` に返すと分かった。そこで版3では、設定「素点の試し打ち」（既定 OFF）を ON にすると、戦闘の開始で敵1体・味方1人ごとに `instant_damage` を1本だけ持つ行動（weak〜extreme の5段 × 物理・魔法、倍率 1。weak の物理だけ倍率 2 と 0.67 も）を作ってゲームのこの段に渡し、返った素点を録る（`kind: dry`。揺らぎを見るため1通りにつき設定の回数だけ呼ぶ）。HP には当てない。呼ぶ前後で全員の HP と状態異常を比べ、動いていたらその場で止めて以後は試さない（`kind: dry_abort`）。319 が1手の値を控えるのはゲームの `handle_battle_situation` の間だけなので、戦闘の開始なら控えを上書きしない。読み込み順で `319_` / `333_` より外側に入るので、`get_instant_damage` の引数は素の値、戻りは 319 が置き換えた後の値になる（ゲーム自身の結果は引き算で出る）。読む用は `out\enemy_stats.log`、数える用は `out\enemy_stats.jsonl`。ゲームは変えない（200番台の約束どおり読み取りだけ。どの包みも `orig` の戻りをそのまま返す）
