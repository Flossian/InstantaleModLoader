# 追加辞書（`../data/*.json`）の作り直し方

ゲーム更新で `Assets\images\item_candidates_dark\` に画像が増えたら、ここで作り直す。
一度きりのビルド用で、実行時には読まれない（実行時に読むのは `../data/` と `../images/` だけ）。
足した画像の分類は、同じ種類の元画像をまとめた単位（`../categories.json`。版10 で119分類を「品の種類：ジャンル」の45分類にまとめ、防具：ファンタジーを中世・ファンタジー（魔法の要素がある品）・ハイファンタジー・ダークファンタジーに分け、防具：魔法とSF と食料：近世を足して50分類、版12 で文書：中世とファンタジーを足して51分類、武器：ハイファンタジー・ダークファンタジー、医療品：近世、宝物：ハイファンタジー・ダークファンタジー・近世、文書：近世を足して58分類。元画像は `sources`）。画像と辞書は分類ごとのフォルダに書く
（`../images/<分類>/Assets/images/item_candidates_dark/<部位>/<鍵>.png`・`../data/<分類>/<部位>.json`）。
書くのは3つのツールに共通の `build_guns.write_categories` で、ツールの受け持つ分類（表の品が入る分類）から、そのツールの品（キーの頭）の画像と埋め込みだけを消して書き直す（防具の分類にはほかのツールの品も入る）。
辞書の JSON は `build_guns.write_lines` で1項目1行に書く（`index` のキー1つ・`vectors` の埋め込み1つが1行。差分で変わった品が分かる）。
辞書は同じキャプションのベクトルを1つにまとめた形（`{"index": {鍵: 番号}, "vectors": [...]}`、小数4桁）。
一枚絵を足すときは、合う分類の `sources` に元画像（一枚絵の呼び名・置き場所・元の名前）を足す。分類を足すときは `categories.json`（id・設定の名前・まとまり・表示名・既定の使い方・sources）と、本体の `IMAGE_SETS` と設定の定数、`mod.json` の settings を揃える（`tools\tests\test_item_image_sets.py` が見る）。
ジャンル内の重みの既定（`../genres.json` の `weights`）にも、足した分類の行を足す（`tools\tests\test_item_image_tool.py` が見る）。

## 一枚絵の置き場所

画像生成 AI で作った元の一枚絵は、リポジトリの `assets/item_images/` に置く（配布の zip には入らない。make_dist は `runtime\` だけを詰める）。
フォルダは分類のまとまりごと（`guns/`・`medieval_weapons/`・`magic_weapons/`・`sf_weapons/`・`wear/`・`parts/`・`food/`・`medical/`・`magic_materials/`・`treasure/`・`tools/`・`monster_materials/`・`japanese/`・`modern_sf/`）、ファイル名は分類の id（`guns/gun_cyber.png` など）。
分類ごとの一枚絵は `categories.json` の `source`（`assets/item_images/` の下の相対パス）。ツールはどれもここを読む。別の場所を読ませるときは `--sheets` か環境変数 `ITEM_IMAGE_ASSETS`。
元の一枚絵の PNG は画素を変えずに詰め直してある。
3つのツールは、品ごとの処理と埋め込みを `build_guns.parallel_map` でプロセスを並べて流す（既定はコア数 - 1。環境変数 `ITEM_IMAGE_WORKERS=1` で1本。結果は同じ）。
キャプションは、本体が外見文にするのと同じく、武器の合成語（battleaxe・longsword など、モデルの語彙に無い語）を2語に分けてから埋め込む（本体の `SPLIT_COMPOUND` を `build_guns.split_pattern` が読む。`build_extra_embeddings.py` も同じ。キャプションの文はそのまま。VERIFICATION.md §3.26）。
塊数え（`build_guns.label`）は OpenCV（cv2）か scipy があればその実装を使い、無ければ Python だけで数える（作り直しの時間の約9割が Python だけの塊数えだった）。
切り出すときは、明るさ 12 より上を品とみなし、外周の背景とつながらない閉じた透明の塊のうち中の平均が 2.5 以上のもの（品の中の暗い影）を品に戻す（`build_guns.fill_enclosed`。依頼の背景は #000000 で、本当に空いている所は平均 0.6〜1.7）。
縮めるときは、透明の色を隣の色で広げてから輪郭を立て（黒のまま立てると白い粒が並んだ）、残った 6px 以下の閉じた穴を埋める（`spread_colors`・`small_holes`）。
切り出した画像は、縮めた後に輪郭を軽く立てて255色に減らし（暗い縁は付けない）、色の数だけのパレットを持つ PNG で書く（`build_guns.save_palette`。画素は同じで大きさはフルカラーの約6割）。一枚絵を足す・描き直すときは、このフォルダに置いて `categories.json` を直す（`tools\tests\test_item_image_sets.py` が、どの分類の一枚絵も在るかを見る）。

## 手順

1. 欠落一覧を出す（`missing_images.json` を作り直す。中身は
   フォルダ → ゲームの元の辞書に無い画像の絶対パスの一覧）。判定は
   「`Assets\images\item_candidates_dark\<folder>\` にあるのに
   `Data\item_embeddings\<folder>.json` にキーが無い」こと
2. 新しい画像1枚ごとに英語一文のキャプションを付け、`captions_<folder>.json`
   （`{拡張子なしファイル名: キャプション}`）に足す。文体はゲームの
   `item_appearance` と同じ（例: "A rusted, chipped small dagger with a worn
   wooden hilt."）。見えるものだけを書く。document フォルダには紙物でない
   画像（鍵・フラスコ等）が多数あるが、正直に書くこと（嘘のキャプションは
   検索を汚す）
3. `python build_extra_embeddings.py` を実行。キャプションを同梱モデル
   （all-MiniLM-L6-v2）の numpy 再実装（`minibert.py`）で埋め込み、
   `../data/<folder>.json` にゲームの元の辞書と同じ形式（`{キー: [384 floats]}`）で書く。
   自己検索（各キャプションが合成辞書で自分を top1 に引くか）まで検査される

## 銃の画像

ゲームの素材に無い銃の画像を足す。
`python build_guns.py [--sheets <一枚絵のフォルダ>] [--preview <見比べ用の一覧 PNG>]` で、
銃の一枚絵45枚の分類（`gun_*`）を書く。初期の一枚絵（1枚に約30丁）のうち現代・未来型・スナイパー・前装式・ファンタジー・ショットガンの6枚は、1枚1行で描き直した28枚（`gun_<組>_v2_<番号>.png`、呼び名 `gmod`・`gfut`・`gsnp`・`gflt`・`gfan`・`gsht`）に替えた。サイバーパンクの初期の1枚（`cyber`）は外し、1枚1行で描いた銃_サイバーパンク2 に無い拳銃と大きめの小銃の2枚（`gcy1`・`gcy2`）を足した。
組んだキャプションの一覧を `guns_captions.txt` に書く。

表は `weapon_asset.json`。

- 画像生成 AI で作った黒背景の一枚絵22枚（20枚は 1536x1024、近接武器の描き直しは 1983x793。銃_サイバーパンク2 は、1行ずつリクエストした7枚を行の順に縦に積んだ 2172x4437）。
  一枚絵は `guns/` から読む（置き場所は「一枚絵の置き場所」）。
  1枚ずつキー（`gun_<一枚絵>_<番号>`）・品種の希望（`pref`）・一枚絵の上の箱（`src` の `@x0,y0,x1,y1`）・回転・種類の名前を書く。
  箱の中でいちばん大きい塊と、その塊の箱に収まる塊を切り抜く（塊は一枚絵全体で数え、明るさ 12 より上を画像とみなす）。
  表の `whole` が真の品は、箱の中にほぼ収まる塊を全部取る（本体から離れて描かれた照準器・銃身・擲弾筒の先）。
  品種は希望の箱から小さいほうへ、画像が箱の高さの 75% に届く箱を選ぶ。
  キャプションは種類の名前と、画像から測った色（本体の色・木の銃床・差し色・光る色）で組む。名前に金属の色の語（silver・gold など）があるか、名前が色の語で始まれば、本体の色は付けない。
  表の `wood` が偽の品は茶色を木の部位に数えない（銃_サイバーパンク2 は錆びた金属の茶色を木と測ったので、木の銃床は種類の名前に書いた）。
  表の `diag` が真の品（縦に描かれた拳銃とナイフ）は、立てたあと銃口や刃先を右上へ 45 度に倒す（`rot` があれば先に回す）。
  表の `melee` が真の品（企業の一揃いの警棒・刃物・大槌・クロスボウ）は、キャプションに `, a gun.` を付けない

寸法はゲームの素材（小型 32x32 / 中型 32x64 / 大型 32x96 / 長物 32x128 / 投擲 32x32）の1.5倍（`build_guns.SCALE` = 1.5。端数は四捨五入）。素材の2倍で作るとゲームの中で素材の画像よりきめ細かく浮き、素材と同じ寸法では 64x64 の防具類よりきめが粗く見えたので、間にした。倍にするのは武器だけで、盾・防具類・消耗品は倍にしない（`shrink` の `scale`）。占めるマスの数は品の種類で決まり、画像の寸法では変わらない（VERIFICATION.md §3.26）。
爆発物は投擲武器に入れ、キャプションの結びは `, an explosive.` にする（茶色は瓶や紙の色なので木の部位を書かない）。
横向きの画像は 90 度回して銃口を上にし、±20 度の中で幅が最小の向きに寄せる。
小型は斜めの画像のまま。
色は元のまま（彩度を落とさない。どの素材も、元のままでゲームの `_dark` の素材より彩度が低い）。

## 中世の武器と防具・魔法武器の画像

`python build_medieval.py --set medieval|magic [--sheets <一枚絵のフォルダ>] [--preview <見比べ用の一覧 PNG>]` で、
`medieval_weapons/`・`magic_weapons/` の一枚絵（画像生成 AI で作った黒背景の画像）から、分類（`med_weapons`・`mag_*`）を書く。
表は `medieval.json`・`magic.json`（キーは `med_`・`mag_`、品種の希望・一枚絵の上の箱・種類の名前）。
防具の希望（`shield`・`body_armor`・`clothing`・`accessory`）はその種類の寸法にそのまま入れる（盾と胴鎧は 64x64。倍にしない）。
表の `whole` が真の品は、箱の中の塊を全部取る（2〜3本の投げナイフや矢の束のように、離れて描かれた1組）。
切り抜き・寸法合わせは `build_guns.py` の部品を使う。
キャプションはゲームの外見文と同じ形で結び（`, a gun.` を付けない）、金属の品は色を素材の言葉に直す（灰→steel、黒→blackened iron、茶→木の柄・革巻きの握り・革の帯）。
木の品（杖・弓・棍棒・盾）は茶色が多ければ wooden と書く。表の `plain` が真の品（名前で見た目を言い切った品）は種類の名前だけにする（測った色から足す宝石や属性が画像と合わない。魔法の剣 `xsw1`〜`xsw3`）。魔法武器は差し色から属性を書く（赤→fire、青→frost、紫→shadow、緑→nature、金と白→holy）。名前に属性の語（holy・burning・ice・shadow・vine など）があればそちらに従い、属性の語そのものが名前にあれば前に重ねない（「A holy magic halberd」）。
組んだキャプションは `medieval_captions.txt`・`magic_captions.txt` に書く。

SF武器は `python build_medieval.py --set sf` で、`sf_weapons/` の一枚絵から分類（`sf_*`）を書く。表は `sf.json`（キーは `sf_`）。
一枚絵は少し傾いて描かれているので、`build_guns.stand_up` で ±20 度の中で幅が最小の向きに立てる。
表の `diag` が真の品（縦に描かれた短剣・ナイフ・投げナイフ）は、立てたあと刃先を右上へ 45 度に倒す（ゲームの小型・投擲と同じ向き）。円盤と手裏剣は回さない。
武器の部位に縮める品は、縮める前に光る品の外側の暗いにじみをはがす（`build_guns.peel_glow`）。
光の芯（橙・黄・金を除く明るく鮮やかな画素）が2%以上ある品だけで、芯と同じ色合いの暗い画素と、芯から同じ距離の中の真っ黒の縁を、透明に接するものから出す画像の約3px 分まではがす。
光る刃や銃の周りに描かれたにじみが、明るさで切り抜くと黒い波の縁として残ったため。黒い本体（色の無い黒）は残る。
芯と同じ色の暗い部分を本体に持つ品（暗い赤の弓・赤い柄・炎の剣の暗い赤の柄）も削るので、表の `halo: false` で外す（36品。弓とクロスボウと矢筒の描き直し、燃える魔法の大剣のように柄ごと消えた品を含む）。
刃の片側に幅の広い黒い帯が描かれた光る刃（白っぽい光は鋼の刃と色で見分けられない）は、表の `glow: true` で、白っぽい光も芯に数えて2倍の幅ではがす（SF武器の光の刃・光の大剣・光の槍の行と、動力の鎚と斧の光る2品、38本）。刃の縁の細い光の線が黒い柄のすぐ上まで続く品は、2倍の幅ではがすと柄まで削れた（無骨な長大な刀の `sf_stw5_10`）ので付けない。素材・消耗品の部位には掛けない（結晶や薬瓶は色の付いた暗い面が多い）。
`diag` と `rot`（左回りの角度。斜めに描かれた長い品を立てる）はどの組の表でも効く（和風の脇差・短刀・苦無は `diag`）。両方を書くと `rot` で回してから倒す（逆さに描かれた魔法の苦無は `rot: 180` と `diag`）。
武器の品種は希望の箱から小さいほうへ選ぶ（画像が箱の高さの 75% に届く箱）。表の `keep` が真の品は希望の箱のまま入れる（横に広い錨 `med_i87_02` が一段小さい箱に回ったため）。
キャプションは光る色（光の刃は芯が白く飛ぶので、色が取れなければ縁の色）か、刃や頭の材質（steel・black alloy など）で結ぶ。茶色を木（wooden）と読むのは、名前に bat か club がある品だけ（錆びた刃・赤いバールの茶色を木と書かない）。
組んだキャプションは `sf_captions.txt` に書く。

依頼のときは、箱の縦横比ではなく画像そのものの全長と幅の比を書く。

## 消耗品と部品の画像

`python build_medieval.py --set item` で、`parts/`・`food/`・`medical/`・`magic_materials/`・`treasure/`・`tools/`・`monster_materials/`・`japanese/`・`modern_sf/` の一枚絵から、
分類（`part_*`・`food_*`・`medic_*`・`magic_materials`・`treasure`・`tool_*`・`creature`・`wa`・`modern_sf`）を書く。表は `items.json`（キーは `itm_`）。
部位（食べ物・飲み物・薬・薬瓶・植物・きのこ・道具・遺物・くず・魔法の素材・その他の素材・魔物の素材・宝石・鉱石・金属・文書・装身具）は素材がどれも 32x32 で、装身具を除く消耗品と素材は `build_guns.ITEM_SCALE`（1.5。試し）倍の 48x48 で作る。装身具は防具類と同じ 64x64（`build_medieval.ITEM_WEAR`。中世の組の矢筒も同じ）。32x32 だと1マスの品を 64px に描く画面で2倍に引き伸ばされ、粗く見えた。表の `pref` のとおりに入れる。手術用のメスだけは小型の武器。
キャプションは「色 + 種類の名前」。表の `plain` が真の品（食材や真鍮の機械のように名前に色や材質が入っている）は種類の名前だけ。ほかの品も、名前に入っている色は前に重ねない。名前に金属の色の語（gold・silver・brass・bronze・copper など）がある品と、名前が色の語で始まる品（`red lacquered`・`navy laced` など）も、測った色を前に付けない（`build_guns.names_own_color`。金は茶色、銀は黒や白に測られる）。光る部分があれば `with a faint <色> glow` を足す。
測った色は画素の数で決めるので、陰の多いドット絵では見た目と違う色になることがある（銀や白の品・暗い緑や紺の品が black、白い陶器が brown）。
どの表の品も、`caption_fixed` に画像を見て書いた一文があれば、組んだキャプションの代わりにそれを使う（`build_guns.fixed_caption`。版12 で目視で食い違いを見つけた 226 品）。
冠詞は `build_guns.sentence` が付ける。対の品（`PAIRED`）は `A pair of`、複数形の品（`PLURAL`。名前の主語の最後の語）と数で始まる名前は冠詞なし（「Grilled sausages.」「Three macarons.」）。複数形の品を足すときは `PLURAL` に語を足す。
組んだキャプションは `item_captions.txt` に書く。
表は塊を行ごとに並べて作る。ほかの塊の左右の幅の中に中心がある小さな塊（こぼれた丸薬・鉗子の片側）は品の一部として表に載せない。
横に2つ繋がった塊は、表の行を決めるときに画像の画素が最も少ない列で割る（SF部品のくず鉄・旅の食料の堅パンの行）。
料理の一枚絵（菓子・肉料理・魚介料理・東南アジア料理・西洋料理）は品が密で上下の段が触れているので、行の帯を横の画素の少ない所で切ってから帯ごとに塊を数え、
帯の中の品の幅の中央値の 1.6 倍を超える塊は品の数に合わせて割る。
戦利品の一枚絵（`i37`〜`i42`。結晶・核と宝珠・霧と粉と雫・薬瓶・宝石と鉱石・牙と角と鱗）と機械の敵の部品の一枚絵（`i43`〜`i45`。魔導機械の核・歯車と部品・壊れた機械の体）は横1行で、リクエストした数（12）になるまで横の位置で塊をまとめた。

## ゲームの元の画像の描き直し

ゲームの元の画像を、同じ物・同じ向きのまま足した画像の絵柄で描き直した画像（`../images/redraw/<品種>/<鍵>.png`）と、描き直しをリクエストした一文の埋め込み（`../data/redraw/<品種>.json`）。
本体はゲームの元の画像を表示するときに描き直しを見せ、選ぶときは描き直しのあるゲームの元の画像の説明をこの埋め込みに替える（設定 `USE_REDRAW`。既定は OFF）。
`images/redraw` は分類ではないので Kivy の探し先に足さず、本体が絶対パスで引く。セーブの `image_src` はゲームの元の画像のパスのまま。
ツールは `redraw/` にあり、取り込みの作業場はリポジトリの `local\item_image_redraw\`（手本・描き直しの一枚絵・切り出し・リクエストした記録。大きいので git の外）。

1. `python redraw/make_refs.py` で、手本の一枚絵を作業場の `refs\<品種>_<番号>.png` に書く（品種ごとに10枚ずつ1行。済んでいれば要らない）。
   リクエストする順番は作業場の `refs\manifest.json` の並び。`python redraw/reach.py` が、記録の外見文で候補に入った回数を `refs\reach.json` に書く
2. 品ごとの一文の候補を3つずつ作り、ゲームの元の埋め込みで引いたときの順位がいちばん良いものを `refs\captions\<手本>.json` に書く（10位を外れたら言い換える）
3. `python redraw/make_prompt.py <手本> ...` でプロンプトを出す。描き直し済みの品と、同じ画像（`refs\same_images.json`）がほかでリクエストされている品は抜き、並びを `refs\requests\<手本>.json` に残す
4. 画像生成 AI の共有リンクを `python redraw/fetch_share.py <手本> <リンク>` で作業場の `sheets\<手本>.png` に取る
5. `python redraw/build_redraw.py <手本> ...` で切り出して `../images/redraw/<品種>/<鍵>.png` に書く。
   作業場の `previews\<手本>.png` の上の段がゲームの元の画像、下の段が描き直し。手本と違う物に描かれた品は `--skip 7,9` のように並びの番号で外す
6. `python redraw/reuse_redraw.py` で、同じゲームの元の画像が別の品種にもある品へ描き直しをコピーする（コピーした組は `refs\reused.json`）
7. `python redraw/build_redraw_data.py` で、`../data/redraw/<品種>.json`（埋め込み）・`../data/redraw/captions.json`（埋め込んだ一文）・
   `../data/tags.json`（色・材質の語の組）を書き直す。一文の無い描き直しは通知する（そのキーは元の説明のまま選ばれる）

手本の読み違いで別の物に描き直した品は、`python redraw/make_prompt.py --redo <{"品種/鍵": 一文} の JSON>` でリクエストし直す。
決まりの同じ品種どうしを10品までの組にして `redo_<番号>` の名前でリクエストし、並びと一文を `refs\redo\<名前>.json` に残す。
取り込みは手順4〜7と同じで、`build_redraw.py redo_<番号>` は品ごとの品種へ書き、そのキーの手本の `refs\captions` の一文を書き替える。

寸法は足した画像と同じ決まり（武器と消耗品・素材はゲームの元の画像の1.5倍、服・頭・手・脚・装身具は 64x64、盾と胴鎧は元の寸法）。
小型武器は縦向き（刃が上）でリクエストし、ゲームの元の画像が正方形の品だけ右上へ 45 度に倒す。
光る刃の外のにじみをはがす処理（`build_guns.peel_glow`）は、`build_redraw.py` の表 `PEEL` に載せた品だけに通す。
一文は描き直した画像に見えるものを書く。ゲームの元の画像の説明（ゲームの辞書）とは別物で、描き直しを使う設定では、こちらで選ばれる。

`../data/tags.json` は、説明文の分かる画像ごとの (色, 材質) の語の組（`"red,white|metal"` の形）。`own` は足した画像（`*_captions.txt`）と追加辞書の画像（`captions_*.json`）、
`redraw` は描き直しの一文から。語の組の決まりは本体の `tags_of`（`COLOR_WORDS`・`MATERIAL_WORDS`）。足した画像を作り直したときも `build_redraw_data.py` を回す。

`../data/captions.json` は、足した画像と追加辞書の画像の説明文（{品種: {鍵: 文}}）。同じ `build_redraw_data.py` が書く。
本体は「物の種類を AI に確かめる」（`KIND_CHECK`）が入のとき、これと `../data/redraw/captions.json` の文を LLM に見せる。
説明文が画像と違う物を指していると、その画像は違う種類として外れるか、違う種類の品に付く。

## 外した画像の付け替え先

`python build_retired.py` で、描き直しで外したキーの付け替え先の表 `data/retired.json` を書く。外したキーは、git の履歴にある分類の辞書に一度でも載って今の辞書に無いキーで、付け替え先は同じ品種の今ある画像のうち、辞書のベクトルがいちばん近い画像（外したキーの最後の分類が今もあればその中から）。本体は、品が作られるとき（セーブの読み込みも通る）に画像が見つからなければこの表で `image_src` を付け替え、次の保存でセーブに残る。一枚絵を外したら、外す前の版をコミットしてから、ほかの build_*.py の後で回す。

## 前提と検証の経緯

- `minibert.py` はゲーム同梱の `runtime/models/embedding/` の重みをそのまま読む。
  ゲームの選択（実セーブで選ばれた画像）の argmax 再現率は 109/114（96%）で、
  埋め込み空間はゲーム本体と互換（VERIFICATION.md §3.26）
- 同梱のキャプション305件は画像を1枚ずつ目視して付けた。自己検索 305/305
- 必要なのは Python + numpy だけ（torch 不要）
