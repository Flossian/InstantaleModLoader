# 追加辞書（`../data/*.json`）の作り直し方

ゲーム更新で `Assets\images\item_candidates_dark\` に画像が増えたら、ここで作り直す。
一度きりのビルド用で、**実行時には読まれない**（実行時に読むのは `../data/` と `../images/` だけ）。
足した絵の分類は、同じ種類の元画像をまとめた単位（`../categories.json`。版10 で119分類を「品の種類：ジャンル」の45分類にまとめ、防具：ファンタジーを中世・ファンタジー（魔法の要素がある品）・ハイファンタジー・ダークファンタジーに分け、防具：魔法とSF を足して49分類。元画像は `sources`）。絵と辞書は分類ごとのフォルダに書く
（`../images/<分類>/Assets/images/item_candidates_dark/<部位>/<鍵>.png`・`../data/<分類>/<部位>.json`）。
書くのは3つの道具に共通の `build_guns.write_categories` で、道具の受け持つ分類（表の品が入る分類）から、その道具の品（鍵の頭）の絵と埋め込みだけを消して書き直す（防具の分類にはほかの道具の品も入る）。
辞書は同じキャプションのベクトルを1つにまとめた形（`{"index": {鍵: 番号}, "vectors": [...]}`、小数4桁）。
一枚絵を足すときは、合う分類の `sources` に元画像（一枚絵の呼び名・置き場所・元の名前）を足す。分類を足すときは `categories.json`（id・設定の名前・まとまり・表示名・既定の使い方・sources）と、本体の `IMAGE_SETS` と設定の定数、`mod.json` の settings を揃える（`tools\tests\test_item_image_sets.py` が見る）。
ジャンル内の重みの既定（`../genres.json` の `weights`）にも、足した分類の行を足す（`tools\tests\test_item_image_tool.py` が見る）。

## 一枚絵の置き場所

画像生成 AI で作った元の一枚絵は、リポジトリの `assets/item_images/` に置く（配布の zip には入らない。make_dist は `runtime\` だけを詰める）。
フォルダは分類のまとまりごと（`guns/`・`medieval_weapons/`・`magic_weapons/`・`sf_weapons/`・`wear/`・`parts/`・`food/`・`medical/`・`magic_materials/`・`treasure/`・`tools/`・`monster_materials/`・`japanese/`・`modern_sf/`）、ファイル名は分類の id（`guns/gun_cyber.png` など）。
分類ごとの一枚絵は `categories.json` の `source`（`assets/item_images/` の下の相対パス）。道具はどれもここを読む。別の場所を読ませるときは `--sheets` か環境変数 `ITEM_IMAGE_ASSETS`。
元の一枚絵の PNG は画素を変えずに詰め直してある。
3つの道具は、品ごとの処理と埋め込みを `build_guns.parallel_map` でプロセスを並べて流す（既定はコア数 - 1。環境変数 `ITEM_IMAGE_WORKERS=1` で1本。結果は同じ）。
塊数え（`build_guns.label`）は OpenCV（cv2）か scipy があればその実装を使い、無ければ素の Python で数える（作り直しの時間の約9割が素の Python の塊数えだった）。
切り出すときは、明るさ 12 より上を品とみなし、外周の背景とつながらない閉じた透明の塊のうち中の平均が 2.5 以上のもの（品の中の暗い影）を品に戻す（`build_guns.fill_enclosed`。依頼の背景は #000000 で、本当に空いている所は平均 0.6〜1.7）。
縮めるときは、透明の色を隣の色で広げてから輪郭を立て（黒のまま立てると白い粒が並んだ）、残った 6px 以下の閉じた穴を埋める（`spread_colors`・`small_holes`）。
切り出した絵は、縮めた後に輪郭を軽く立てて255色に減らし（暗い縁は付けない）、色の数だけのパレットを持つ PNG で書く（`build_guns.save_palette`。画素は同じで大きさはフルカラーの約6割）。一枚絵を足す・描き直すときは、このフォルダに置いて `categories.json` を直す（`tools\tests\test_item_image_sets.py` が、どの分類の一枚絵も在るかを見る）。

## 手順

1. 欠落一覧を出す（`missing_images.json` を作り直す。中身は
   フォルダ → 素の辞書に無い画像の絶対パスの一覧）。判定は
   「`Assets\images\item_candidates_dark\<folder>\` にあるのに
   `Data\item_embeddings\<folder>.json` にキーが無い」こと
2. 新しい画像1枚ごとに英語一文のキャプションを付け、`captions_<folder>.json`
   （`{拡張子なしファイル名: キャプション}`）に足す。文体はゲームの
   `item_appearance` と同じ（例: "A rusted, chipped small dagger with a worn
   wooden hilt."）。**見えるものだけを書く**。document フォルダには紙物でない
   画像（鍵・フラスコ等）が多数あるが、正直に書くこと（嘘のキャプションは
   検索を汚す）
3. `python build_extra_embeddings.py` を実行。キャプションを同梱モデル
   （all-MiniLM-L6-v2）の numpy 再実装（`minibert.py`）で埋め込み、
   `../data/<folder>.json` に素の辞書と同じ形式（`{キー: [384 floats]}`）で書く。
   自己検索（各キャプションが合成辞書で自分を top1 に引くか）まで検算される

## 銃の絵

ゲームの素材に無い銃の絵を足す。
`python build_guns.py [--sheets <一枚絵のフォルダ>] [--preview <見比べ用の一覧 PNG>]` で、
銃の一枚絵45枚の分類（`gun_*`）を書く。初期の一枚絵（1枚に約30丁）のうち現代・未来型・スナイパー・前装式・ファンタジー・ショットガンの6枚は、1枚1行で描き直した28枚（`gun_<組>_v2_<番号>.png`、呼び名 `gmod`・`gfut`・`gsnp`・`gflt`・`gfan`・`gsht`）に替えた。サイバーパンクの初期の1枚（`cyber`）は外し、1枚1行で描いた銃_サイバーパンク2 に無い拳銃と大きめの小銃の2枚（`gcy1`・`gcy2`）を足した。
組んだキャプションの一覧を `guns_captions.txt` に書く。

表は `weapon_asset.json`。

- 画像生成 AI で作った黒背景の一枚絵22枚（20枚は 1536x1024、近接武器の描き直しは 1983x793。銃_サイバーパンク2 は、1行ずつ頼んだ7枚を行の順に縦に積んだ 2172x4437）。
  一枚絵は `guns/` から読む（置き場所は「一枚絵の置き場所」）。
  1枚ずつ鍵（`gun_<一枚絵>_<番号>`）・品種の希望（`pref`）・一枚絵の上の箱（`src` の `@x0,y0,x1,y1`）・回転・種類の名前を書く。
  箱の中でいちばん大きい塊と、その塊の箱に収まる塊を切り抜く（塊は一枚絵全体で数え、明るさ 12 より上を絵とみなす）。
  表の `whole` が真の品は、箱の中にほぼ収まる塊を全部取る（本体から離れて描かれた照準器・銃身・擲弾筒の先）。
  品種は希望の箱から小さいほうへ、絵が箱の高さの 75% に届く箱を選ぶ。
  キャプションは種類の名前と、絵から測った色（本体の色・木の銃床・差し色・光る色）で組む。名前に金属の色の語（silver・gold など）があるか、名前が色の語で始まれば、本体の色は付けない。
  表の `wood` が偽の品は茶色を木の部位に数えない（銃_サイバーパンク2 は錆びた金属の茶色を木と測ったので、木の銃床は種類の名前に書いた）。
  表の `diag` が真の品（縦に描かれた拳銃とナイフ）は、立てたあと銃口や刃先を右上へ 45 度に倒す（`rot` があれば先に回す）。
  表の `melee` が真の品（企業の一揃いの警棒・刃物・大槌・クロスボウ）は、キャプションに `, a gun.` を付けない

寸法はゲームの素材（小型 32x32 / 中型 32x64 / 大型 32x96 / 長物 32x128 / 投擲 32x32）の1.5倍（`build_guns.SCALE` = 1.5。端数は四捨五入）。素材の2倍で作るとゲームの中で素材の絵よりきめ細かく浮き、素材と同じ寸法では 64x64 の防具類よりきめが粗く見えたので、間にした。倍にするのは武器だけで、盾・防具類・消耗品は倍にしない（`shrink` の `scale`）。占めるマスの数は品の種類で決まり、絵の寸法では変わらない（VERIFICATION.md §3.26）。
爆発物は投擲武器に入れ、キャプションの結びは `, an explosive.` にする（茶色は瓶や紙の色なので木の部位を書かない）。
横向きの絵は 90 度回して銃口を上にし、±20 度の中で幅が最小の向きに寄せる。
小型は斜めの絵のまま。
色は元のまま（彩度を落とさない。どの素材も、元のままでゲームの `_dark` の素材より彩度が低い）。

## 中世の武器と防具・魔法武器の絵

`python build_medieval.py --set medieval|magic [--sheets <一枚絵のフォルダ>] [--preview <見比べ用の一覧 PNG>]` で、
`medieval_weapons/`・`magic_weapons/` の一枚絵（画像生成 AI で作った黒背景の絵）から、分類（`med_weapons`・`mag_*`）を書く。
表は `medieval.json`・`magic.json`（鍵は `med_`・`mag_`、品種の希望・一枚絵の上の箱・種類の名前）。
防具の希望（`shield`・`body_armor`・`clothing`・`accessory`）はその種類の寸法にそのまま入れる（盾と胴鎧は 64x64。倍にしない）。
表の `whole` が真の品は、箱の中の塊を全部取る（2〜3本の投げナイフや矢の束のように、離れて描かれた1組）。
切り抜き・寸法合わせは `build_guns.py` の部品を使う。
キャプションはゲームの外見文と同じ形で結び（`, a gun.` を付けない）、金属の品は色を素材の言葉に直す（灰→steel、黒→blackened iron、茶→木の柄・革巻きの握り・革の帯）。
木の品（杖・弓・棍棒・盾）は茶色が多ければ wooden と書く。魔法武器は差し色から属性を書く（赤→fire、青→frost、紫→shadow、緑→nature、金と白→holy）。名前に属性の語（holy・burning・ice・shadow・vine など）があればそちらに従い、属性の語そのものが名前にあれば前に重ねない（「A holy magic halberd」）。
組んだキャプションは `medieval_captions.txt`・`magic_captions.txt` に書く。

SF武器は `python build_medieval.py --set sf` で、`sf_weapons/` の一枚絵から分類（`sf_*`）を書く。表は `sf.json`（鍵は `sf_`）。
一枚絵は少し傾いて描かれているので、`build_guns.stand_up` で ±20 度の中で幅が最小の向きに立てる。
表の `diag` が真の品（縦に描かれた短剣・ナイフ・投げナイフ）は、立てたあと刃先を右上へ 45 度に倒す（ゲームの小型・投擲と同じ向き）。円盤と手裏剣は回さない。
武器の部位に縮める品は、縮める前に光る品の外側の暗いにじみをはがす（`build_guns.peel_glow`）。
光の芯（橙・黄・金を除く明るく鮮やかな画素）が2%以上ある品だけで、芯と同じ色合いの暗い画素と、芯から同じ距離の中の真っ黒の縁を、透明に接するものから出す絵の約3px 分まではがす。
光る刃や銃の周りに描かれたにじみが、明るさで切り抜くと黒い波の縁として残ったため。黒い本体（色の無い黒）は残る。
芯と同じ色の暗い部分を本体に持つ品（暗い赤の弓・赤い柄）も削るので、表の `halo: false` で外す（6品）。
刃の片側に幅の広い黒い帯が描かれた光る刃（白っぽい光は鋼の刃と色で見分けられない）は、表の `glow: true` で、白っぽい光も芯に数えて2倍の幅ではがす（SF武器の光の刃・光の大剣・光の槍の行と、動力の鎚と斧の光る2品、38本）。素材・消耗品の部位には掛けない（結晶や薬瓶は色の付いた暗い面が多い）。
`diag` と `rot`（左回りの角度。斜めに描かれた長い品を立てる）はどの組の表でも効く（和風の脇差・短刀・苦無は `diag`）。両方を書くと `rot` で回してから倒す（逆さに描かれた魔法の苦無は `rot: 180` と `diag`）。
キャプションは光る色（光の刃は芯が白く飛ぶので、色が取れなければ縁の色）か、刃や頭の材質（steel・black alloy など）で結ぶ。茶色を木（wooden）と読むのは、名前に bat か club がある品だけ（錆びた刃・赤いバールの茶色を木と書かない）。
組んだキャプションは `sf_captions.txt` に書く。

依頼のときは、箱の縦横比ではなく絵そのものの全長と幅の比を書く。

## 消耗品と部品の絵

`python build_medieval.py --set item` で、`parts/`・`food/`・`medical/`・`magic_materials/`・`treasure/`・`tools/`・`monster_materials/`・`japanese/`・`modern_sf/` の一枚絵から、
分類（`part_*`・`food_*`・`medic_*`・`magic_materials`・`treasure`・`tool_*`・`creature`・`wa`・`modern_sf`）を書く。表は `items.json`（鍵は `itm_`）。
部位（食べ物・飲み物・薬・薬瓶・植物・きのこ・道具・遺物・くず・魔法の素材・その他の素材・魔物の素材・宝石・鉱石・金属・文書・装身具）は素材がどれも 32x32 で、装身具を除く消耗品と素材は `build_guns.ITEM_SCALE`（1.5。試し）倍の 48x48 で作る。装身具は防具類と同じ 64x64（`build_medieval.ITEM_WEAR`。中世の組の矢筒も同じ）。32x32 だと1マスの品を 64px に描く画面で2倍に引き伸ばされ、粗く見えた。表の `pref` のとおりに入れる。手術用のメスだけは小型の武器。
キャプションは「色 + 種類の名前」。表の `plain` が真の品（食材や真鍮の機械のように名前に色や材質が入っている）は種類の名前だけ。ほかの品も、名前に入っている色は前に重ねない。名前に金属の色の語（gold・silver・brass・bronze・copper など）がある品と、名前が色の語で始まる品（`red lacquered`・`navy laced` など）も、測った色を前に付けない（`build_guns.names_own_color`。金は茶色、銀は黒や白に測られる）。光る部分があれば `with a faint <色> glow` を足す。
組んだキャプションは `item_captions.txt` に書く。
表は塊を行ごとに並べて作る。ほかの塊の左右の幅の中に中心がある小さな塊（こぼれた丸薬・鉗子の片側）は品の一部として表に載せない。
横に2つ繋がった塊は、表の行を決めるときに絵の画素が最も少ない列で割る（SF部品のくず鉄・旅の食料の堅パンの行）。
料理の一枚絵（菓子・肉料理・魚介料理・東南アジア料理・西洋料理）は品が密で上下の段が触れているので、行の帯を横の画素の少ない所で切ってから帯ごとに塊を数え、
帯の中の品の幅の中央値の 1.6 倍を超える塊は品の数に合わせて割る。
戦利品の一枚絵（`i37`〜`i42`。結晶・核と宝珠・霧と粉と雫・薬瓶・宝石と鉱石・牙と角と鱗）と機械の敵の部品の一枚絵（`i43`〜`i45`。魔導機械の核・歯車と部品・壊れた機械の体）は横1行で、頼んだ数（12）になるまで横の位置で塊をまとめた。
外見文の採点で合う絵が足りなかった組は、足す先の分類の今の絵を並べた見本で頼んで足した（SF の電子部品 `i50`・`i51`、薬草茶 `i52`、現代とSF の医療品 `i53`、書類と記章 `i54`・`i54b`・`i54c`。`i54` の3つは同じ一枚絵を品ごとに文書：現代・道具：ジャンル・宝物：ファンタジーへ分けた呼び名。医療の装いは防具類の表の `wmd1`・`wmd2`）。薬瓶（`i55`〜`i57`、医療品：ファンタジー）と宝石（`i58`〜`i60`、宝物：ファンタジー）も、今の絵を並べた見本で同じ形を避けて頼んで足した。
魔導機械には、今の36品を1枚に並べた見本（`work/samples/magitech/reference_magitech.png`）で頼んだ4枚（`i46`〜`i49`。動力と核・部品・自動人形とゴーレムの体・小さな魔導の装置、48品、`whole` と `plain`）を足した。
牙と角・壊れた機械の体の一枚絵は品の箱が横に重なるので、画素5000以上の塊を品の芯にし、小さな塊を中心の近い芯へ寄せた。どれも `whole` と `plain`。
斜めに描かれて隣と箱の重なった一枚絵（銛と錨と杖 `ian1`、荒野の手製の武器 `ipa1`〜`ipa3`）は、縦に続く塊を1品にまとめ、品ごとに幅が最小の向きに立てて重ならない列に並べ直した絵を `assets` に置いた（元の絵ではない）。表の箱はこの並べ直しの上の箱。
ゲームの素材の絵は片手武器 4.2・両手武器 3.7・長物 6.2（中央値）で、箱の比（2:1・3:1・4:1）で頼むと太く短い剣になった。

## 防具・服・装身具の絵

`python build_wear.py [--sheets <一枚絵のフォルダ>] [--preview <一覧 PNG の置き場所>]` で、画像生成 AI で作ったジャンルごとの一枚絵35枚
（`wear/`）から、分類（`wear_*`）を書く。
一枚絵は `w00`〜`w26` と呼ぶ（`categories.json` の `sheet`）。1枚に100〜170品を描いた元の一枚絵（`w00`〜`w21`）は、10-22〜23 に1枚1行の描き直しへ替えたが、元絵のほうが統一感があり絵柄も合うので、元の表のまま戻し、描き直しの組は外した（描き直しの一枚絵のファイルは、ほかの使わなくなった一枚絵と一緒に消した。git の履歴から取り出せる）。学園だけは、銃を持って戦う学園ものの絵柄で描き直した10枚（`ws1`〜`ws10`、鍵は `wrf_`）を使い、元の学生服2枚（w13・w14）は外し、一枚絵も消した。元の学園もの（w12）は残した。後から足した学園の4枚（w27〜w30）は、絵柄が合わず外し、一枚絵も消した。表は `wear.json`（鍵・部位・一枚絵の上の箱・種類の名前、隣と接して分けた箱は `rect`）。元の一枚絵の種類の名前は「hood, helmet or crown」のような部位ごとの大まかな名前。
寸法はどれも 64x64。武器だけ素材の1.5倍にして、きめの差を縮めた。
胴の品は絵を1枚ずつ見て、胴鎧（鎧・鎖帷子・防弾ベストのように身を守る品）か服（シャツ・上着・外套・ローブ）の片方に置く。
ゲームが胴鎧として作る品の外見文は胸当て・革鎧がほとんどで、外套やローブは服として作られる。
キャプションは「色 + 種類の名前」で、ジャンルものの一枚絵は種類の名前にジャンルの語を入れる。和風だけは `Japanese` を使わない
（日本語の外見文は埋め込みで [UNK] になり、`Japanese` を含む文に寄った）。
縦長の服を正方形に近い絵へ付け替えた外套（`wcom` など）とつなぎ（`wjs`）も、元の一枚絵に戻したので外した。

## 外した絵の付け替え先

`python build_retired.py` で、描き直しで外した鍵の付け替え先の表 `data/retired.json` を書く。外した鍵は、git の履歴にある分類の辞書に一度でも載って今の辞書に無い鍵で、付け替え先は同じ品種の今ある絵のうち、辞書のベクトルがいちばん近い絵（外した鍵の最後の分類が今もあればその中から）。本体は、品が作られるとき（セーブの読み込みも通る）に絵が見つからなければこの表で `image_src` を付け替え、次の保存でセーブに残る。一枚絵を外したら、外す前の版をコミットしてから、ほかの build_*.py の後で回す。
