## 1. 遊び方（`docs\MODS.md` 相当）

### `904_party_talk`: パーティーメンバー全員と話す

素のゲームの会話は常に1対1で、仲間を連れていても話せるのは1人ずつ。
`403_` を入れれば会話相手が同行者を認識するようになるが、
同行者は黙って立っているだけで、こちらの発言に横から口を挟むことはない。

この MOD は、「会話する」を押した先の相手一覧に「パーティーメンバーと話す」を1つ足す（「やめる」の手前）。
その場に NPC が居なくて「会話する」自体が無いときは、こちらで「会話する」を足し、
押すと「パーティーメンバーと話す」と「やめる」だけの一覧を開く。
押すと仲間から1人が選ばれ（ランダム）、その相手との普通の会話に入る。
違うのはその会話の間だけで、こちらが一言喋るたびに仲間全員がそれぞれの立場で反応する。

```
「そうだろぉ？お前の射撃も凄いと思ってるけどな、俺は」
アリス・スミス: あら、嬉しいこと言ってくれるのね。（嬉しそうに微笑み、親しげに肩を寄せてくる）
ハナ・ミヤビ: ……非効率な誉め合いです。射撃精度と物理破壊力には相関関係がありません。
```

- こちらの1発言を1ラウンドとし、1ラウンドに各仲間は最大1回しか反応しない。
  反応しない仲間がいてもよく、台詞の代わりに（銃を磨いている）のような行動描写だけでもよい
- 最初に選ばれた1人（アンカー）は本体の会話相手なので毎ラウンド必ず先頭で反応する。
  他の仲間はその後に順に表示される
- 立ち絵は参加者全員が横に等間隔で並ぶ（2人なら 1/3 と 2/3、3人なら 1/4・1/2・3/4。名簿順）。
  本体の相手枠はアンカーのまま位置だけずらし、他の仲間ぶんは同じ形の枠を足す。
  会話を終えると枠は消え、相手枠の位置も戻る。
  設定「仲間の立ち絵を並べる」を切ると、喋った人物へ立ち絵が切り替わり、終わるとアンカーへ戻る
- 仲間の人物像は、ゲーム自身の設定に加えて `311_`（本人の現在像・プレイヤー観）と
  `403_`（仲間同士の関係）の記録を**読むだけ**で載せる。どちらも書かない
- 会話は本体のものなので、終わり方も本体と同じ。「会話を終了する」は
  この MOD の間だけ「話し合いを終了する」と表示される
- この会話では自由記述で何を頼んでもゲームの状態は変わらない
  （移動・売買・戦闘・アイテム操作は起きない。仲間が態度で応じるだけ）

仲間全員に反応させる LLM 呼び出しは会話の LLM を差し替える形で、
本体の1対1の呼び出しは走らない（1発言につき LLM は1回）。
記録は `out\party_talk.log`。`output_data\` には `mod_party_talk` の名で残る。

| 設定 | 意味 |
|---|---|
| 会話開始の選択肢 | 既定「パーティーメンバーと話す」 |
| 会話終了の選択肢 | 既定「話し合いを終了する」 |
| 参加NPC上限 | 既定 6。名簿の先頭から数える |
| LLMへ渡す直近の会話数 | 既定 12 往復 |
| 仲間の立ち絵を並べる | 既定 入。切ると喋った人物へ切り替える方式 |

#### 制約

- **本体の会話要約には仲間の台詞が載らない。** 仲間の台詞は本体の履歴に積まず、この MOD の側で控える。
  積むと `311_` の抽出が会話相手（アンカー）の発言として読んでしまうため
  （本体の `conversation_history_to_text` は assistant を相手の名で描く）。
  したがって会話を終えたときの要約とライフログ、`311_` の記憶に残るのはアンカーの台詞だけ。
  `403_` の関係更新も同じ履歴を読むので、仲間同士のやり取りは関係に反映されない
- `317_reputation` などが会話の LLM へ差し込んでいるものは、この会話では載らない
  （差し替えの外側に居て素通ししない）。載せたければこの MOD のプロンプトへ足す
- 選択肢が出るのは「会話する」を押した先の相手一覧だけ。根のメニュー・宿屋の部屋選び・宿泊中・
  戦闘中・依頼一覧には出ない。ギルドの「冒険者達と話す」の一覧は同じ形だが出さない（`320_` の募集ボタンと同じ見分け方）
- NPC 不在の根のメニュー（出口はあるが「会話する」が無い画面）には自前の「会話する」を末尾に足す。
  本体の「会話する」が在る画面には足さない。会話中・戦闘中・ポップアップ中も足さない
  （店を出た後も残る `in_shopping` は見ない）
- 本体の「会話する」の一覧に相手が居なくても（「やめる」だけ。ギルドなど）「パーティーメンバーと話す」は出る
- LLM が返す名前は参加者の名前と突き合わせ、居ない人物と2回目の反応は落とす（ログに `dropped=` で残る）
- 立ち絵の無い仲間は並べない（素のゲームでは起きない。セーブを手で壊した場合の話で、この MOD は面倒を見ない）
- 並べている間にキャラクターシートを開くと、右側の自分の立ち絵と仲間の枠が重なる（シートの窓が上に載るので実害は薄い）

#### 困ったとき

| 症状 | やること |
|---|---|
| 選択肢が出ない | 仲間が0人か、「会話する」の相手一覧を開いていない。`out\party_talk.log` に `added ... to the talk list` が無ければ一覧と見なしていない（`DisplayTalkChoice.execute` を通っていないか、別の画面の spec が混ざっている） |
| NPC 不在なのに「会話する」が出ない | `party_talk.log` に `added own '会話する'` が無い。`own '会話する' withheld: ...` が出ていればその旗（戦闘・会話・ポップアップ）が立っている。何も無ければ出口（`MovePhaseManager`）の無い画面 |
| 押しても会話に入らない | `party_talk.log` の `pressed` の次を見る。`ERROR ConversationStartManager not found` なら注入が `__main__` の前 |
| 仲間が誰も反応しない | `round N anchor=... extras=[] dropped=[...]` を見る。`nonparty:` が並ぶなら LLM が別名で返している |
| 仲間の立ち絵が黒い | v7 で Clock 経由に直した（§3）。それでも出るなら `modloader.log` に `party talk:` の行があるか |
| 立ち絵が並ばない | `party_talk.log` に `portrait added` が無い。`WARN character_image not found` なら HUD の相手枠が引けていない |
| 会話を終えても仲間の枠が残る | `portraits removed` が出ていない。`modloader.log` の `party talk: cannot remove` を見る。タイトルへ戻れば消える。終了ボタンから数秒残るだけなら v8 2版までの挙動（要約の LLM の後に片付けていた。3版で終了ボタンの直後に移した） |
| `structured -> None; fallback no-structure` | 構造化出力を使えないモデル。`no-structure` で読めていれば動く。読めなければ `WARN fallback unreadable` |

### 仲間の立ち絵（`904_`）: Clock に載せて黒い板が消えるか

提供元の v6 では、仲間の台詞を出すときに立ち絵が黒い板になることがあった
（毎回ではない）。v6 は `conversation_continued` の中、つまり `execute` の
ワーカースレッドから `update_character_image` を直接呼んでいた。

| 分かっていること | 根拠 |
| --- | --- |
| UI は Clock（メインスレッド）から触る。`execute` の中から直接触らない | GAME.md §2.1 |
| 本体自身は `update_character_image` を Clock 経由で呼んでいる | VERIFICATION_LOG.md §2.42（別件の落ち方の起点が2つとも Clock の遅延呼び出し） |
| `add_text` はワーカースレッドから呼んでよい | 本体が `add_text_display` を Clock に載せる（GAME.md §2.3「本文の打ち出し」）。`306_` `308_` `319_` も同じ呼び方 |

**黒くなる原因がスレッドである、という点は未実測**（仮説）。
提供元のログには黒くなった回の記録が無く、区別のつく状態を作れていない。

### 仲間の台詞を本体の履歴に積まない（`904_`）: 次のラウンドが文脈を保つか

v7 は仲間の台詞を本体の `current_conversation_history` に積まず、
この MOD の側で「本体履歴の何件目の後に出たか」を添えて控え、
自分のプロンプトにだけ合流させる（オフラインで位置が揃うことは確認済み）。

実機で見るのは、2ラウンド目以降に仲間が**前のラウンドの自分の台詞**を踏まえて喋るか。
`output_data\` の `mod_party_talk` の【直近の対話ログ】に
`assistant: ハナ・ミヤビ: ...` の行が前のラウンドの位置に在れば経路は通っている。

あわせて、会話を終えたときの本体の要約（ライフログ）にアンカーの台詞だけが載ること。
これは制約として §1 に書いてある挙動で、不具合ではない。

### 立ち絵を並べる（`904_` v8）: 実機で1回通せば決着する

**実機では一度も通していない。** 分かっているのはここまで:

| 分かっていること | 根拠 |
| --- | --- |
| 会話中に見えている立ち絵は `hud.character_image` 1枚（`center_x` 0.5 / `center_y` 0.43、2560×1100、`size_hint=(1, None)`、クラス `NearestNeighborImage`） | `212_` の実測（`out\character_sheet.log`） |
| `hud.character_image_right` はキャラクターシートを開いたときだけ出る自分の立ち絵。会話の要素ではない | 同上。開閉に同期して `opacity` が 1/0 を往復（全件） |
| 絵は各 NPC の `image_src["fullbody"]`（`…\characters\<名前>\reduced_color_image.png`） | `210_` の実測（`out\character_state.log`） |
| HUD 直下に子を足すとアイテム移動・装備が効かなくなる。足すのは中の `FloatLayout` | VERIFICATION_LOG.md §2.33（`ui.overlay_host`） |

**推定のまま残っているもの:**

- 相手枠の `pos_hint` を書き換えても、本体が毎ターン戻さないこと（戻すなら `refresh_choice_buttons` と
  `conversation_continued` のたびに並べ直しているので、一瞬戻って見えるだけで済む読み）
- 立ち絵の透明地。相手枠と同じ幅なので、人物が中央に描かれていれば `center_x` をずらすだけで横に動く。
  絵が左右に寄っていれば重なる
- 相手枠の canvas は `StencilPush … StencilPop` で切り抜いている。複製には付いてこないが、透明地なら要らない読み

#### 確認手順（1回でよい）

1. 仲間を2人以上連れて「パーティーメンバーと話す」を押す
2. 会話画面が出た時点で全員の立ち絵が横に並んでいるか。喋るたびに動かないか
3. 「話し合いを終了する」で仲間の枠が消え、相手枠が中央へ戻るか
4. `out\party_talk.log` を読む

```

[...] portrait added id=64 x=0.67
[...] party talk end: ConversationEndManager
[...] portraits removed
```

| 出た行 | 意味 |
| --- | --- |
| `portrait added` が参加者ぶん（アンカーを除く）出て、画面にも並ぶ | 決着 |

| 並んだが一瞬中央に戻る | 本体が `pos_hint` を戻している。戻す場所を包んで後から並べ直す |

あわせて、3人以上のときの間隔と、キャラクターシートを開閉しても枠が残らないことを見る。

#### 実機1回目（2026-08-28、v8 初版）: 並んだが、仲間が本文の枠の手前に大きく出た

仲間2人（ハンス＝アンカー / ニナ）。`portrait added id=64 x=0.67` が出て、ハンスは左寄り（1/3）、
ニナは右（2/3）に並んだ。ここまでは読みどおり。外れたのは2点（スクリーンショット）:

| 症状 | 原因 | 直し（v8 2版） |
| --- | --- | --- |
| ニナが本文の枠と入力欄の手前に描かれる | `ui.overlay_host(hud)` の FloatLayout に足すと、本文の枠より後に足された子＝手前に描かれる | 相手枠と同じ親の、相手枠のすぐ手前（`children` の同じ添字）に挿す。本文の枠との前後関係が本体と同じになる |
| ニナがハンスより大きく、背景の枠からはみ出す（切り抜かれない） | 相手枠の寸法と切り抜きは kv の canvas（`StencilPush → Rectangle → … → Rectangle（絵）→ … → StencilPop`）で決まっていて、`type(base)()` の複製には付いてこない。複製は素の `Image` として 2560×1100 いっぱいに絵を収める | 相手枠の canvas に並ぶ `Rectangle` を読み、テクスチャ付きの矩形を絵の寸法、先頭の矩形を切り抜きとして自前の枠に写す（`size_hint=(None, None)` にして `size` を直に、`canvas.before/after` に同じ StencilPush/Use/UnUse/Pop を置く）。読めなければウィジェットの寸法に落ちる |

矩形の実測値は `party_talk.log` の `portrait geometry:` に1回出る（相手枠の `size` / `pos` / 絵 / 切り抜き / 置き場所の型と添字）。
実測（2026-08-28〜29、3回とも同じ。窓 1920 幅）:

```
portrait geometry: base size=(1920, 825) pos=(0, 29.11) drawn=(0.0, 29.11, 1920.0, 825.0) clip=(0.0, 29.11, 1920.0, 825.0) host=FloatLayout index=11
```

絵の矩形も切り抜きもウィジェットの矩形と一致していた（相手枠は横幅いっぱい、高さ 825）。
つまり複製が大きく出たのは矩形の差ではなく、`size_hint=(1, None)` と `height` を写しても
`overlay_host` 側の親で解決される寸法が違ったため。いまは寸法を直に写すので親に依らない。
置き場所は相手枠と同じ `FloatLayout` の添字 11。
どの Rectangle が絵でどれが切り抜きかは canvas の並び（`212_` の実測）からの読みなので、
その行と画面を突き合わせて決着させる。

| 2版で出た結果 | 意味 |
| --- | --- |
| ハンスと同じ大きさで、本文の枠の奥に並ぶ | 決着 |
| 大きさは揃ったが切り抜かれない | 切り抜きの矩形の選び方が違う。`portrait geometry:` の `clip=` を見る |
| 大きさが違う | 絵の矩形の選び方が違う。`drawn=` を見る（テクスチャ付きが複数ある可能性） |
| 位置が縦にずれる | `center_y` は絵の矩形の中心を親の高さで割ったもの。親が FloatLayout でなければ `pos_hint` が効かない |

## 4. ゲーム構造からの行き先（`docs\GAME.md` §2.5 の末尾へ戻す）

会話の LLM（`conversation_facilitator` / `_after_retrieval`）を**まるごと差し替えて**
複数人に喋らせるには `904_party_talk`。
本体が読むのは戻り値の `content_violation` と `action.type` / `action.statement` /
`action.call_free_action` だけなので、`llm.create_structure` で同じ項目を持つ型を作って返せば
本体の表示・履歴・終了処理はそのまま動く。
`call_free_action=False` を返す限り自由行動 GM（`master_ai_facilitator_from_conversation`）には入らない。
