# `405_regional_economy`: 街ごとの需給で売買の値段が変わる

素のゲームでは、どの街でも同じ品は同じ値段で売り買いされる。
鉱山の街でも港町でも鉱石の値は変わらず、遠くまで運ぶ理由が無い。

この MOD は街（エリア）ごとに地域経済を1回だけ作り、
その土地で余っている品を安く、足りない品を高くする。
鉱山の街では鉱石が安く薬が高い、という差が街ごとに固定されるので、
安く仕入れて高く売る遊びが成り立つ。

値段そのものは `129_balance_item_price` が付けたものをそのまま使い、
この MOD はその上に土地の倍率を掛けるだけ。

## どう動くか

街に着いた時点で、その街の地域経済を LLM が1回だけ考える。

- 何を産業にしているか、特産品は何か、何が余って何が足りないか
- そのうえで、品のジャンル32種それぞれに 1〜5 の需給の値を付ける
  （ジャンルはゲームが品に書いている細分。武器・防具・飲食と薬・道具と書物・素材と財宝の
  5つの種別に分かれる）
  （3が平常、1に寄るほど余っていて安い、5に寄るほど足りなくて高い）

作った結果は世界ごとのファイルに残るので、同じ街で2度考えることはない。

売買画面を開いたときは、並んだ品のジャンルを見て値段に倍率を掛けるだけ。
**このとき LLM は呼ばないので、画面が出るのが遅れない。**

品ごとに LLM へ聞く形にしていないのは、開くたびに待たされることと、
同じ品が開くたびに違う値段になってしまうため。
値段が動くと、安く仕入れて高く売る遊びが成り立たない。

### 名指しされた品はジャンルより優先する

ジャンルは粗いので、その街の「余っている品」「足りない品」に
名前が当たった品だけは、ジャンルの値を上書きして最も強い倍率にする。
「特産品」に当たった品は値段を動かさない（特産品は関わりの強さであって、
余っているか足りないかの向きを持たないため）。

照合は名前が同じか、名前がそのまま商品名の中に入っているときだけ。
LLM が書いた名前どうしは表記が揺れるので、
「灼熱の鱗」と「炎竜の鱗」のような近い品は当たらない。当たらないぶんはジャンルが受ける。

## 街の経済を作る間、ゲームは止まらない

LLM への問い合わせと控えの読み書きは、ぜんぶ裏のスレッドで行う。
街に着いたときにゲーム側がするのは「今どこに居るか」を控えて積むことだけで、
返事を待たない。作れ終わるまでの間に売買画面を開いても、
補正なしで普通に開く。

## 街を出るとき、セーブするとき

倍率はアイテムそのものに書くので、次の2つで必ず外す。

- **セーブの直前。** 保存が終わってから画面用の値段へ戻す。
  この MOD の倍率がセーブデータへ混ざることはない
- **別の街へ移ったとき。** 元の値段へ戻してから控えを捨てる。
  よその街の倍率が乗ったままの品を持ち歩かない

## 設定

| 項目 | 既定 | 意味 |
| --- | --- | --- |
| エリアの産業や経済の要約文字数 | 300 | その街の経済の説明の長さの目安 |
| エリア産業の項目数 | 3 | 主要産業・特産品・余っている品・足りない品を、それぞれこの数だけ作る |
| 未知の産出物が製品になる段階数 | 2 | 架空の材料が使える品になるまでの採取と加工の回数。ドラゴンストーンからドラゴンランプなら2 |
| 強い変動 | 1.5 | 需給が大きく振れるジャンルの倍率。足りない側は掛け、余っている側は割る |
| 弱い変動 | 1.2 | 需給が振れるジャンルの倍率。同じく足りない側は掛け、余っている側は割る |

## 困ったとき

| 症状 | 見るところ |
| --- | --- |
| 値段が変わっている気がしない | `out\regional_economy.log`。街に着くと `summary queued`、出来上がると `summary saved` に全ジャンルの値が出る。売買画面を開くと `regional overlay: N price(s)` が出る |
| `no regional profile yet` が出た | まだその街の経済が出来ていない。補正なしで開き、裏で作り始めている。次にその街で開いたときから効く |
| `summary not saved: invalid LLM result` が続く | LLM がジャンルの値を返せていない。ジャンルが8種に満たない返答は歪んだ経済になるので保存しない。指示に従えるモデルを使う |
| どの街も似た値段になる | LLM がジャンルの値を全部3に寄せている。`summary saved` の行で確かめられる |
| 値段を作り直したい | `state\regional_economy\<世界名>.json` を消す。その世界の街の経済だけが初期化され、次に着いたときに作り直される |
| 129 を切っている | この MOD だけでは値段は付かない。素のゲームの値段に倍率が掛かるだけになる |

## 出どころ

MoririnJP 氏の試作（`405_regional_economy` v1、2026-08-29）を提供してもらった。

提供された版は品1個ずつを売買画面で LLM に分類させる作りで、
画面を開くたびに最長 120 秒ゲームが止まり、
`129_balance_item_price` より外側に置かれていたため
掛けた倍率がその場で 129 に上書きされていた（画面には一度も出ていない）。
倍率の軸をジャンルへ移して売買画面から LLM を外し、
129 の内側へ入れて値付けの直後に掛かるように直したうえで、
名指しの層と、街を出たときの後始末を足した。

**この MOD は 2026-08-30 に一旦保留にした。**
先に手を付けている MOD が片付いてから再開する。
`runtime\mods\` へは移していないので、いまは注入されない。

再開したら実機で確かめる。とくに次の2点をログで見る。

- 出来上がったジャンルの値が街ごとに違い、極端に偏っていないか
- 売り買いした直後に 129 が値段を付け直すかどうか
  （`set_shop_price_for_owner` / `set_shop_price_for_player` /
  `normalize_shop_inventory_prices` は 129 が元の関数を呼んだ後に値付けするため、
  内側に居るこの MOD では掛け直せない。
  `out\item_price.log` に `shop_owner` / `shop_player` / `normalize/` の行が出るかで分かる）

  既存のログで半分は分かった（2026-08-30 時点の `out\item_price.log`）:

  | 経路 | 件数 |
  | --- | --- |
  | `shop_player`（プレイヤーの売価） | 168 |
  | `shop_owner` | 0 |
  | `normalize/` | 0 |

  **プレイヤーの売価は 129 が付け直している。**
  この MOD が 129 の内側に居る限り、そこへ土地の倍率は乗らない。
  乗せるなら `set_shop_price_for_player` にもこの MOD 自身の層を掛ける。
  残る2経路はこのログの範囲では一度も走っておらず、まだ何とも言えない。
