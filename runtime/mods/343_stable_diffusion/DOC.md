# `343_stable_diffusion`: Stable Diffusion の解像度・サンプラー・モデル・プロンプトを差し替える

ゲームは立ち絵を 256x512 で下描きしてから 512x1024 で描き直し、背景を 1024x512 で、
敵・モンスターを 512x512 で描く（敵だけは1段）。
サンプラーも段ごとに決め打ちで、どちらも設定画面からは変えられない。

この MOD は、**どのバックエンドでも通る1つの出口**でその値を書き換える。
縦横比は保つので絵は歪まない。

種類と段で分けて指定する。

| 分け方 | 何が分かるか | どこで分かるか |
|---|---|---|
| 立ち絵 / 敵・モンスター / 背景 | 解像度をそれぞれに指定できる | 入口の関数（敵は `generate_enemy_image` を通る） |
| 1段目 / 2段目 / LCM の段 | サンプラーを段ごとに指定できる | 上の層の関数（`generate_image_anime` なら1段目、`generate_image_real_lcm` なら LCM の段） |

立ち絵と敵は同じ生成関数を通るので、**サンプラーは段の設定が両方に効く**。
解像度だけは入口で分かるので別々に指定できる。

| 設定 | 既定（ゲームのまま） | 意味 |
| --- | --- | --- |
| 立ち絵の短辺の目標 / 長辺の上限 | 512 / 1024 | 縦横比を保ったまま拡大する。短辺の目標より先に長辺の上限へ当たればそこで止まる |
| 敵・モンスターの短辺の目標 / 長辺の上限 | 512 / 512 | 敵は**正方形 512x512 を1段**で描く（立ち絵とは別物）。立ち絵と別に指定できる |
| 背景の短辺の目標 / 長辺の上限 | 512 / 1024 | 背景はゲームでは 1024x512 |
| 1段目の方法 / steps / cfg / スケジューラ | euler_a / 20 / 8.0 / default | 立ち絵と敵の下描き |
| 2段目の方法 / steps / cfg / スケジューラ | dpmpp2m / 15 / 7.0 / karras | 立ち絵と敵の描き直し。この段だけスケジューラが karras |
| LCM の段の方法 / steps / cfg / スケジューラ | lcm / 5 / 1.0 / default | **背景と敵・モンスターが通る段**。速さ優先の設定なので、方法を変えるなら steps と cfg も上げる |
| チェックポイント / TAESD / VAE / LoRA の置き場 | 空（ゲームのまま） | SDXL のモデルへ移るときに指す。系統は揃えること |
| プロンプトの LoRA タグを外す | 切 | **ゲームが入れた**タグだけ外す。規則で付け替えた先や足したタグは残る。SDXL へ移るときに入にする |
| VAE を渡さずに建てる | 切 | TAESD を差し替えても色が合わないときの逃げ道 |
| モデルの系統に合わせて直す | `auto` | チェックポイントの中身から SD1.5 / SDXL を見分け、壊れる組み合わせだけ直す（VERIFICATION.md §3.65） |
| diffusers 系でも寸法を変える | 切 | `diffusers_openvino` のような変換済みモデルの一族。入にするとモデルの作り直しで RAM を使い切ることがある。使うなら**寸法は1通りに絞る**（種類ごとに別の寸法を指定しない） |
| TAESD を使わずに建てる | 切 | VAE で復号する。遅いが絵は出る |

**既定値はすべて実測したゲームの値**で、既定のままの項目はゲームへ1つも書き込まない。
ゲームが更新で値を変えたときに、こちらの古い既定を焼き付けないため。

短辺の目標を上げても、長辺の上限に先に当たればそこで止まる。
例えば立ち絵の短辺を 832 にしても、長辺の上限が 1024 のままなら何も変わらない。
実際に伸ばすなら上限も比例して上げる（832 / 1664）。
寸法は 64 の倍数へ四捨五入し、片辺 2048 で止める。

効くのはこれから作られる絵だけで、既にある絵は再生成で作り直せる。
書き換えた値は `out\stable_diffusion.log` に1行ずつ出る。

寸法・サンプラー・安全弁・規則は**生成のたびに読み直す**ので、道具画面で保存すれば次の絵から効く。
注入し直しは要らない（元 MOD のホットリロードと同じ）。
モデルの置き場だけは**ゲームを起動し直してから注入する**。
パイプラインが建つ瞬間にしか書けず、ゲームは1プロセスに1回しか建てない。
**タイトルへ戻ってワールドを選び直しても建て直らない**
（実測: `set_ai_models` に入った時点で `txt2img_pipe` が在る回は `load_sd_pipeline` を呼ばない。7回とも）。
差し替えが届いていないときは、ログに1度だけ警告が出る。

```text
sdcpp_cuda.stable_diffusion:StableDiffusion.generate_image [portrait/stage1] width: 256->448 height: 512->832
```

## なぜモデルの指定を MOD が持つのか

ゲーム内にもモデルの選択はあるが、**選べるのはゲームフォルダの中だけ**。
`config.json` に入るのは `model_name: "sotemix_v30"` という名前で、
パイプラインへ渡るのは `runtime/models/sd15/checkpoints/<名前>.safetensors`（実測）。

| やりたいこと | ゲーム内の選択で足りるか |
| --- | --- |
| 同梱の SD1.5 モデルを切り替える | 足りる |
| 外に置いた SDXL（数GB）を使う | 足りない。ゲームフォルダへコピーが要る |
| TAESDXL を使う | 足りない。同梱の TAESD を上書きするしかない |
| SDXL 用の LoRA を別フォルダに置く | 足りない |

DLL 版はこの3つを「ゲームフォルダへ置く・上書きする」で解決していた。
**ゲームのファイルを触らないことがこの MOD の眼目**なので、
チェックポイント・TAESD・VAE・LoRA 置き場の指定は補助ではなく核にあたる。
既定は空（ゲームのまま）で、指したときだけ効く。

ゲーム内の選択がパイプラインまで届くのかは未計測
（選んだと聞いた回も `config.json` は元の名前のままで、建ったのも元のモデルだった）。
届いていても、上の表の3つは変わらない。

## モデルの置き場（`state\models\`）

ゲームのフォルダを触らずに済ませるため、外へ置くモデルの場所を決めてある。

```text
state\models\sd15\checkpoints\  taesd\  vae\  lora\
state\models\sdxl\checkpoints\  taesd\  vae\  lora\
```

**系統を先に切る。**
壊れ方（プロセスごと落ちる）は系統の食い違いで起きるので、
1つのフォルダの中身が常に揃った組になる形にした。
中の名前はゲームの `runtime\models\sd15\...` と同じにして、説明を減らしてある。
`state\` の下に置くのは、手で用意する大きなファイルの前例（`state\musics\battle\`）に合わせたもの。
MOD のフォルダ名では切らない（正式化で番号が変わると行方不明になるため）。

道具画面の「状態 / モデル」から、置き場を開く・中身を数える・
**TAESD デコーダをダウンロードする**ことができる。
ダウンロード元は HuggingFace の `madebyollin/taesdxl`（SDXL 用）と `madebyollin/taesd`（SD1.5 用。
ゲーム同梱と同じもの）で、どちらも MIT・約 9.8MB。
取れない環境では URL と置き場と名前を画面に出す（手で入れられる）。
書き途中のファイルは `.part` に書いてから置き換えるので、失敗しても置き場は汚れない。
ダウンロードは別スレッドで回し、その間も画面は応答する（ダウンロードのボタンだけ押せなくなる）。

## SDXL のモデルへ移る

実機で通った組み合わせ（2026-09-18）。**上の4つが要る**（寸法は好み）。

| 設定 | 値 | なぜ要るか |
| --- | --- | --- |
| チェックポイントの差し替え | SDXL の `.safetensors` | ゲーム内のモデル選択でも選べるが、こちらで指せば確実 |
| TAESD デコーダの差し替え | TAESDXL の `.safetensors` | 系統が違うと復号できない。**ゲームフォルダの外の絶対パスでよい** |
| プロンプトの LoRA タグを外す | 入 | ゲームが入れる SD1.5 用の LCM LoRA が当たると**プロセスごと落ちる** |
| LCM の段の方法 / steps / cfg | `euler_a` / 24 / 5.0 | ゲームの `lcm` / 5 / 1.0 のままだと**マゼンタに潰れる** |
| 立ち絵の短辺 / 長辺 | 1024 / 2048（好みで） | SDXL は 1 メガピクセル前後で学習されているので大きめが向く。**必須ではない**（0.52 メガピクセルでも正しく出る） |

VAE は SD1.5 のままでよい（復号は TAESD を通る）。
ゲーム同梱のファイルは1つも書き換えない。

> SD1.5 のモデルに SDXL 用の LoRA を当てても**ゲームごと落ちる**。系統は必ず揃えること。

## カスタムプリセット

道具画面の「状態 / モデル」に「カスタムプリセット」がある。
現在の設定を名前を付けてプリセットとして保存し、あとで読み込める。
SD1.5 と SDXL のように、チェックポイント・TAESD・解像度・サンプラーを組で切り替えるときに使う。

| 操作 | すること |
| --- | --- |
| プリセットとして保存 | 現在の設定を「プリセット名」で保存する。プリセット名が空なら選択中のプリセットを上書きする（上書きは確認する） |
| 読み込む | 選択中のプリセットの値を欄へ読み込む。**読み込んだだけでは反映されない**。内容を確認して「保存」を押す |
| 削除 | 選択中のプリセットを削除する（確認する） |

保存するのは設定（チェックポイント・TAESD・VAE・LoRA の置き場・解像度・サンプラー・LoRA タグの除去・安全弁など）だけ。
プロンプトの規則は含めない。規則は「モデル別」の行でモデルごとに切り替わる。
チェックポイントなどのファイルが見つからないプリセットを読み込むと、その旨が出る。
チェックポイント・TAESD・VAE・LoRA の置き場の変更は、保存した後にゲームを再起動すると反映される（上の「モデルの置き場」と同じ）。
保存先は `state\stable_diffusion\presets.json`。

## モデルに合わせてプロンプトを直す

ゲームの絵のプロンプトは SD1.5 のアニメ系に向けて書かれている。
SDXL のモデルは、学習した説明文の書き方で効く言葉が違う。
同じ SDXL でも、Illustrious・NoobAI は Danbooru のタグ、Pony は `score_9` などの印、素の SDXL は普通の英文で学習している。

道具画面の「モデル別」のタブで、モデルを指定した規則を持てる。
「モデル」の欄に `sdxl` / `sd15` と書けば系統で、ほかの語はチェックポイントのファイル名の一部で選ぶ（`novaAnimeXL` など）。
`/` でどれか1つ、`!` で除く（`sdxl/!pony`）。
Illustrious と Pony はどちらも `sdxl` なので、分けるならファイル名で書く。
ほかのタブの行はどのモデルでも効く。

タブの上の雛形のボタンは、いまのチェックポイントのファイル名を「モデル」にした行の束を入れる。
同じ雛形を入れ直すと前の行を置き換える。

| 雛形 | 立ち絵 | 背景 | 敵 |
| --- | --- | --- | --- |
| Illustrious / NoobAI 系 | 画質の印を Illustrious の形に替え、`1boy` / `1girl`・`simple background` を足し、`wallpaper` `empty background` を外す。否定に崩れの語と `monochrome, greyscale` | 頭に `no humans, scenery`。`indoor` は `indoors` に | 画質の印を替え、`creature` を外す。否定の `anime` を外す |
| Pony 系 | 画質の印が `score_9, score_8_up, score_7_up, source_anime`、否定に `score_6, score_5, score_4`。ほかは上と同じ | 同じ | 同じ |
| 素の SDXL | `wallpaper` `empty background` を外し、`plain black background` を足す | そのまま | そのまま |

### 語の置き換えと Danbooru のタグとの照合

ゲームの絵の要素は LLM が英語で書くので、Danbooru のタグに無い言い方が多い。
タグの語が紛れた言い方はタグの意味で描かれる（`battle-worn plate mail` で足元に皿が描かれた）。
「モデル別」のタブの下の2つの表で手当てする。どちらもゲームの本文だけに当て、規則が足す語（画質の印など）は見ない。

| 表 | すること |
| --- | --- |
| 語の置き換え | 要素の中の語句を置き換える（`plate mail` → `plate armor`）。置換先を空にすると語句を消す |
| Danbooru のタグとの照合 | `alias` はタグの別名を正しいタグへ直す（`outdoor` → `outdoors`、`watercolor` → `watercolor (medium)`）。タグでない要素は触らない |

タグでない言い方を外す機能は作らない。
ゲームの要素の9割近くはタグでない言い方で、それも絵に効いている。外す型を試したら、人物も場所も別物になり、山賊の敵が成人向けの絵になった（VERIFICATION.md §3.65）。
直すのは、読み違えられている言い方だけ（語の置き換え）。

照合と下の知らせには Danbooru のタグ一覧が要る。タブの「Danbooru のタグ一覧を取る」で `state\stable_diffusion\danbooru.csv` に置く（a1111-sd-webui-tagcomplete、MIT、3.4MB）。
数えるのは一般とメタのタグだけで、絵師とキャラの名前は数えない。

Illustrious / Pony の雛形が入れるのは語の置き換え（`plate mail` → `plate armor`、`chain mail` → `chainmail`）だけ。
照合（`alias`）は、試した範囲で絵の良し悪しの差が見えなかったので、雛形には入れない（使うなら表に行を足す）。
語の置き換えか照合の行がある回は、タグに無い言い方にタグの語が紛れていると、`out\stable_diffusion.log` に `danbooru: タグに無い言い方 '…'（中のタグの語: …）` と1回ずつ出る。
置き換えを足すときの手掛かりにする。

SD1.5 用の LoRA を足す規則を書いているなら、その行の「モデル」を `sd15` にしておく。
系統の違う LoRA が当たるとゲームごと落ちる（安全弁が外すのはゲームが入れたタグだけ）。

書き換えた前後のプロンプトは、種類と段ごとに最初の1枚だけ `out\stable_diffusion.log` に全文で出る（`前:` / `後:` の行）。
規則を保存し直すと、もう1回出る。

## 困ったとき

| 症状 | やること |
|---|---|
| 絵が変わらない | `out\stable_diffusion.log` に `wrapped` の行が出ているか。短辺の目標だけ上げて長辺の上限がゲームのままだと、計算上どこも変わらない |
| 絵が崩れる・落ちる | 目標を既定へ戻す。SD1.5 は学習時の寸法から離れるほど崩れ、系統の違う LoRA を当てるとゲームごと落ちる |
| 顔が出ない（全身の縮小が顔になる） | ゲームが顔を見つけられなかった回。寸法とは関係なく起きる（`131_sharp_portrait` の「顔の検出をやり直す」を入にすると拾える率が上がる） |
| 生成が遅くなった | 寸法と steps を上げれば時間も増える（VERIFICATION.md §3.65 の実測）。**桁で遅くなったら VRAM が溢れている**。LLM を載せたまま拡大すると起きやすい。寸法を下げるか、ゲーム側の詳細設定で VAE のタイル化を入れるか、LLM を降ろす |
| SDXL で人の敵の横に小さな生き物が出る・立ち絵が白黒になる・背景に人が出る | モデルに合った雛形を「モデル別」のタブから入れる（§1） |
| 規則が思った形に当たっているか分からない | `out\stable_diffusion.log` の `前:` / `後:` の行に、書き換えた前後の全文が出る |
| 方法とスケジューラが効かない一族がある | `diffusers_openvino` には同じ口が無い。ログに1度だけ警告が出る |
| diffusers 系で寸法が変わらない | 既定でそうしてある（VERIFICATION.md §3.65）。入にすると RAM を使い切ることがある |
| diffusers 系で RAM が増えたまま戻らない | 寸法ごとにモデルが作り直され、ゲームを閉じるまで常駐する（実測）。寸法は1通りに絞る。2通り以上使うと `out\stable_diffusion.log` に警告が出る |
