# `343_stable_diffusion`: Stable Diffusion の解像度・サンプラー・モデル・プロンプトを差し替える

ゲームは立ち絵を 256x512 で下描きしてから 512x1024 で描き直し、背景を 1024x512 で、
敵・モンスターを 512x512 で描く（敵だけは1段）。
サンプラーも段ごとに決め打ちで、どちらも設定画面からは変えられない。

この MOD は、どのバックエンドでも通る1つの出口でその値を書き換える。
縦横比は保つので画像は歪まない。

種類と段で分けて指定する。

| 分け方 | 何が分かるか | どこで分かるか |
|---|---|---|
| 立ち絵 / 敵・モンスター / 背景 | 解像度をそれぞれに指定できる | 入口の関数（敵は `generate_enemy_image` を通る） |
| 1段目 / 2段目 / LCM の段 | サンプラーを段ごとに指定できる | 上のレイヤーの関数（`generate_image_anime` なら1段目、`generate_image_real_lcm` なら LCM の段） |

立ち絵と敵は同じ生成関数を通るので、サンプラーは段の設定が両方に効く。
解像度だけは入口で分かるので別々に指定できる。

| 設定 | 既定（ゲームのまま） | 意味 |
| --- | --- | --- |
| 立ち絵の短辺の目標 / 長辺の上限 | 512 / 1024 | 縦横比を保ったまま拡大する。短辺の目標より先に長辺の上限へ当たればそこで止まる |
| 敵・モンスターの短辺の目標 / 長辺の上限 | 512 / 512 | 敵は正方形 512x512 を1段で描く（立ち絵とは別物）。立ち絵と別に指定できる |
| 背景の短辺の目標 / 長辺の上限 | 512 / 1024 | 背景はゲームでは 1024x512 |
| 1段目の方法 / steps / cfg / スケジューラ | euler_a / 20 / 8.0 / default | 立ち絵と敵の下描き |
| 2段目の方法 / steps / cfg / スケジューラ | dpmpp2m / 15 / 7.0 / karras | 立ち絵と敵の描き直し。この段だけスケジューラが karras |
| LCM の段の方法 / steps / cfg / スケジューラ | lcm / 5 / 1.0 / default | 背景と敵・モンスターが通る段。速さ優先の設定なので、方法を変えるなら steps と cfg も上げる |
| チェックポイント / TAESD / VAE / LoRA の置き場 | 空（ゲームのまま） | SDXL のモデルへ移るときに指す。系統は揃えること |
| プロンプトの LoRA タグを外す | 切 | ゲームが入れたタグだけ外す。規則で付け替えた先や足したタグは残る。SDXL へ移るときに ON にする |
| VAE を渡さずに建てる | 切 | TAESD を差し替えても色が合わないときの回避策 |
| モデルの系統に合わせて直す | `auto` | チェックポイントの中身から SD1.5 / SDXL を見分け、壊れる組み合わせだけ直す（VERIFICATION.md §3.65） |
| diffusers 系でも寸法を変える | 切 | `diffusers_openvino` のような変換済みモデルの方式。ON にするとモデルの作り直しで RAM を使い切ることがある。使うなら寸法は1通りに絞る（種類ごとに別の寸法を指定しない） |
| TAESD を使わずに建てる | 切 | VAE で復号する。遅いが画像は出る |

既定値はすべて実測したゲームの値で、既定のままの項目はゲームへ1つも書き込まない。
ゲームが更新で値を変えたときに、こちらの古い既定値で上書きしないため。

短辺の目標を上げても、長辺の上限に先に当たればそこで止まる。
例えば立ち絵の短辺を 832 にしても、長辺の上限が 1024 のままなら何も変わらない。
実際に伸ばすなら上限も比例して上げる（832 / 1664）。
寸法は 64 の倍数へ四捨五入し、片辺 2048 で止める。

効くのはこれから作られる画像だけで、既にある画像は再生成で作り直せる。
書き換えた値は `out\stable_diffusion.log` に1行ずつ出る。

寸法・サンプラー・安全弁・規則は生成のたびに読み直すので、ツール画面で保存すれば次の画像から効く。
注入し直しは要らない（元 MOD のホットリロードと同じ）。
モデルの置き場だけはゲームを起動し直してから注入する。
パイプラインが建つ瞬間にしか書けず、ゲームは1プロセスに1回しか建てない。
タイトルへ戻ってワールドを選び直しても建て直らない
（実測: `set_ai_models` に入った時点で `txt2img_pipe` が在る回は `load_sd_pipeline` を呼ばない。7回とも）。
差し替えが届いていないときは、ログに1度だけ警告が出る。

```text
sdcpp_cuda.stable_diffusion:StableDiffusion.generate_image [portrait/stage1] width: 256->448 height: 512->832
```

## 次に描く絵（ツール画面の上の帯）

ツール画面のタブの上に、種類ごとに「次に描く絵」を出す。
どのタブで値を変えても、保存する前にこの帯が変わる。

| 欄 | 中身 |
| --- | --- |
| txt2img | ふだんの生成と「画像の再生成(txt2img)」で描くモデルと、それを決めた場所（ゲーム既定・差し替え・プリセット） |
| 寸法 | txt2img で出口に渡る寸法。立ち絵が2段で描く画質なら2段目の寸法 |
| サンプラー | txt2img で通る段のサンプラー。SDXL をゲームのままの LCM の段で描くときは、安全弁で直した値 |
| img2img | 「画像の再生成(img2img)」で描くモデル。使う設定が OFF なら「切」 |
| txt2img→img2img | 1つ目と2つ目のモデル。使う設定が OFF なら「切」。「通常の生成でも使う」が ON の種類は「（通常の生成も）」と添える |

「ゲーム既定」は、ゲームで選んだモデル。
その名前は表の下に1回だけ出す。
diffusers 系では、img2img と txt2img→img2img は「使えない」と出す。

表の下には、ほかに次を出す。
- 前に描いた絵（ログ）: `out\stable_diffusion.log` に残った、種類ごとの最後の1枚（時刻・描き方・プリセット・寸法）
- いま効いていない設定と、その理由
効いていない設定の例:

- どの種類もプリセットで描くときの、解像度・サンプラーのタブの値
- ゲームの画質では通らない段のサンプラー（立ち絵も LCM の段で描く画質なら1段目・2段目）
- 「種類ごとのプリセット」を OFF にしたまま残っている割り当て
- diffusers 系のときの高度設定・寸法・サンプラーの方法
- ゲームを起動し直すまで効かないモデルの差し替え

どの段を通るかは、ゲームの `config.json` の方式と画質で決まる。
測れている画質は `highres_upscale`（立ち絵を2段）と `highres_faster`（LCM の段1回）だけで、ほかの画質はログに残った前回の段で補う。
前回も無ければ「段が分からない」と出す。

## なぜモデルの指定を MOD が持つのか

ゲーム内にもモデルの選択はあるが、選べるのはゲームフォルダの中だけ。
`config.json` に入るのは `model_name: "sotemix_v30"` という名前で、
パイプラインへ渡るのは `runtime/models/sd15/checkpoints/<名前>.safetensors`（実測）。

| やりたいこと | ゲーム内の選択で足りるか |
| --- | --- |
| 同梱の SD1.5 モデルを切り替える | 足りる |
| 外に置いた SDXL（数GB）を使う | 足りない。ゲームフォルダへコピーが要る |
| TAESDXL を使う | 足りない。同梱の TAESD を上書きするしかない |
| SDXL 用の LoRA を別フォルダに置く | 足りない |

ゲームのファイルを触らないことがこの MOD の目的なので、
チェックポイント・TAESD・VAE・LoRA 置き場の指定はこの MOD の中心の機能にあたる。
既定は空（ゲームのまま）で、指したときだけ効く。

ゲーム内の選択がパイプラインまで届くのかは未計測
（選んだと聞いた回も `config.json` は元の名前のままで、建ったのも元のモデルだった）。
届いていても、上の表の3つは変わらない。

## モデルの置き場（`state\stable_diffusion\models\`）

ゲームのフォルダを触らずに済ませるため、外へ置くモデルの場所を決めてある。

```text
state\stable_diffusion\models\sd15\checkpoints\  taesd\  vae\  lora\
state\stable_diffusion\models\sdxl\checkpoints\  taesd\  vae\  lora\
```

系統で先にフォルダを分ける。
壊れ方（プロセスごと落ちる）は系統の食い違いで起きるので、
1つのフォルダの中身が常に揃った組になる形にした。
中の名前はゲームの `runtime\models\sd15\...` と同じにして、説明を減らしてある。
プリセット・規則・タグの一覧と同じ `state\stable_diffusion\` の下にまとめてある。
MOD のフォルダ名では分けない（正式化で番号が変わると見つからなくなるため）。

v1.18.0 までは `state\models\` に置いていた。
ゲームかツール画面を開いたときに新しい置き場へ移し、古い置き場を指したままの設定とプリセットも新しい置き場として読む。
新しい置き場に同じ名前のファイルが既にあるものは、移さずに残す。

チェックポイントの置き場に、その系統として読めないファイル（Stable Cascade など）があると、ツール画面の置き場の欄に出る。
SDXL プリセットはそれを選ばない。

ツール画面の「状態 / モデル」から、置き場を開く・中身を数える・
TAESD デコーダをダウンロードすることができる。
ダウンロード元は HuggingFace の `madebyollin/taesdxl`（SDXL 用）と `madebyollin/taesd`（SD1.5 用。
ゲーム同梱と同じもの）で、どちらも MIT・約 9.8MB。
取れない環境では URL と置き場と名前を画面に出す（手で入れられる）。
書き途中のファイルは `.part` に書いてから置き換えるので、失敗しても置き場は汚れない。
ダウンロードは別スレッドで回し、その間も画面は応答する（ダウンロードのボタンだけ押せなくなる）。

## SDXL のモデルへ移る

実機で通った組み合わせ（2026-09-18）。上の4つが要る（寸法は好み）。

| 設定 | 値 | なぜ要るか |
| --- | --- | --- |
| チェックポイントの差し替え | SDXL の `.safetensors` | ゲーム内のモデル選択でも選べるが、こちらで指せば確実 |
| TAESD デコーダの差し替え | TAESDXL の `.safetensors` | 系統が違うと復号できない。ゲームフォルダの外の絶対パスでよい |
| プロンプトの LoRA タグを外す | 入 | ゲームが入れる SD1.5 用の LCM LoRA が適用されるとプロセスごと落ちる |
| LCM の段の方法 / steps / cfg | `euler_a` / 24 / 5.0 | ゲームの `lcm` / 5 / 1.0 のままだとマゼンタに潰れる |
| 立ち絵の短辺 / 長辺 | 1024 / 2048（好みで） | SDXL は 1 メガピクセル前後で学習されているので大きめが向く。必須ではない（0.52 メガピクセルでも正しく出る） |

VAE は SD1.5 のままでよい（復号は TAESD を通る）。
ゲーム同梱のファイルは1つも書き換えない。

> SD1.5 のモデルに SDXL 用の LoRA を適用してもゲームごと落ちる。系統は揃えること。

## カスタムプリセット

ツール画面の「状態 / モデル」に「カスタムプリセット」がある。
現在の設定を名前を付けてプリセットとして保存し、あとで読み込める。
SD1.5 と SDXL のように、チェックポイント・TAESD・解像度・サンプラーを組で切り替えるときに使う。

| 操作 | すること |
| --- | --- |
| プリセットとして保存 | 現在の設定を「プリセット名」で保存する。プリセット名が空なら選択中のプリセットを上書きする（上書きは確認する） |
| 読み込む | 選択中のプリセットの値を欄へ読み込む。読み込んだだけでは反映されない。内容を確認して「保存」を押す |
| 削除 | 選択中のプリセットを削除する（確認する） |

保存するのは設定（チェックポイント・TAESD・VAE・LoRA の置き場・解像度・サンプラー・LoRA タグの除去・安全弁など）だけ。
プロンプトの規則は含めない。規則は「モデル別」の行でモデルごとに切り替わる。
チェックポイントなどのファイルが見つからないプリセットを読み込むと、その旨が出る。
チェックポイント・TAESD・VAE・LoRA の置き場の変更は、保存した後にゲームを再起動すると反映される（上の「モデルの置き場」と同じ）。
保存先は `state\stable_diffusion\presets.json`。

### 種類ごとのプリセット（上級者向け）

立ち絵・敵・背景を、それぞれ別のカスタムプリセットで描ける。
人物は SDXL のモデル、背景と敵は SD1.5 のモデル、のように描き分けるときに使う。
「状態 / モデル」の「種類ごとのプリセット（上級者向け）」を開き、「種類ごとのプリセットを使う」を ON にしてから、種類ごとにプリセットを選ぶ。
「（プリセットを使わない）」の種類は、プリセットを使わずに描く（モデルの差し替えと、ほかのタブの値）。

割り当てた種類は、そのプリセットのチェックポイント・TAESD・解像度・サンプラー・LoRA タグの除去で描く。
「モデル別」の規則も、その種類を描くモデルで選ばれる。

ゲームのモデルとは別に、もう1つモデルを読み込む。そのぶん VRAM を多く使う。
VRAM が足りないと、画像の生成がとても遅くなるか、ゲームが落ちる。ローカルの LLM を同じ GPU で動かしているときは特に気をつける。
割り当ては保存した次の画像から効く（ゲームの再起動は要らない）。種類ごとの最初の1枚は、モデルを読み込むぶん数秒遅くなる。
割り当てから外れたモデルは、次に別のモデルを読み込むときに外れる。
割り当てたプリセットが見つからないときは、プリセットを使わずに描く。
「使う」を OFF にすると、割り当ては残したまま、どの種類もプリセットを使わずに描く。

## モデルに合わせてプロンプトを直す

ゲームの画像のプロンプトは SD1.5 のアニメ系に向けて書かれている。
SDXL のモデルは、学習した説明文の書き方で効く言葉が違う。
同じ SDXL でも、Illustrious・NoobAI は Danbooru のタグ、Pony は `score_9` などのタグ、素の SDXL は普通の英文で学習している。

ツール画面の「モデル別」のタブで、モデルを指定した規則を持てる。
「モデル」の欄に `sdxl` / `sd15` と書けば系統で、ほかの語はチェックポイントのファイル名の一部で選ぶ（`novaAnimeXL` など）。
`/` でどれか1つ、`!` で除く（`sdxl/!pony`）。
Illustrious と Pony はどちらも `sdxl` なので、分けるならファイル名で書く。
ほかのタブの行はどのモデルでも効く。

タブの上のテンプレートのボタンは、いまのチェックポイントのファイル名を「モデル」にした行の束を入れる。
同じテンプレートを入れ直すと前の行を置き換える。

| テンプレート | 立ち絵 | 背景 | 敵 |
| --- | --- | --- | --- |
| Illustrious / NoobAI 系 | 画質のタグを Illustrious の形に替え、`1boy` / `1girl`・`simple background` を足し、`wallpaper` `empty background` を外す。否定に崩れの語と `monochrome, greyscale` | 頭に `no humans, scenery`。`indoor` は `indoors` に | 画質のタグを替え、`creature` を外す。否定の `anime` を外す |
| Animagine XL 4.0 | 画質のタグ `masterpiece, high score, great score, absurdres` を最後に置き、`1boy` / `1girl` を先頭に。否定に `low score, bad score, average score`。ほかは上と同じ | 画質のタグを最後に | 画質のタグを最後に。`simple background` を足し、大きい敵の否定の `detailed background` を外す（残すと画像が崩れる） |
| Pony 系 | 画質のタグが `score_9, score_8_up, score_7_up, source_anime`、否定に `score_6, score_5, score_4`。ゲームの否定の `(nsfw, worst quality, low quality:1.4)` を重み無しにする（モデルによっては画像が崩れる）。ほかは上と同じ | 同じ | 同じ |
| 素の SDXL | `wallpaper` `empty background` を外し、`plain black background` を足す | そのまま | そのまま |

### 語の置き換えと Danbooru のタグとの照合

ゲームの画像の要素は LLM が英語で書くので、Danbooru のタグに無い言い方が多い。
タグの語が紛れた言い方はタグの意味で描かれる（`battle-worn plate mail` で足元に皿が描かれた）。
「モデル別」のタブの下の2つの表で手当てする。どちらもゲームの本文だけに適用し、規則が足す語（画質のタグなど）は見ない。

| 表 | すること |
| --- | --- |
| 語の置き換え | 要素の中の語句を置き換える（`plate mail` → `plate armor`）。置換先を空にすると語句を消す |
| Danbooru のタグとの照合 | `alias` はタグの別名を正しいタグへ直す（`outdoor` → `outdoors`、`watercolor` → `watercolor (medium)`）。タグでない要素は触らない |

タグでない言い方を外す機能は作らない。
ゲームの要素の9割近くはタグでない言い方で、それも画像に効いている。外す型を試したら、人物も場所も別物になり、山賊の敵が成人向けの画像になった（VERIFICATION.md §3.65）。
直すのは、読み違えられている言い方だけ（語の置き換え）。

照合と下のメッセージには Danbooru のタグ一覧が要る。タブの「Danbooru のタグ一覧を取る」で `state\stable_diffusion\danbooru.csv` に置く（a1111-sd-webui-tagcomplete、MIT、3.4MB）。
数えるのは一般とメタのタグだけで、絵師とキャラの名前は数えない。

Illustrious / Pony のテンプレートが入れるのは語の置き換え（`plate mail` → `plate armor`、`chain mail` → `chainmail`）だけ。
照合（`alias`）は、試した範囲で画像の良し悪しの差が見えなかったので、テンプレートには入れない（使うなら表に行を足す）。
語の置き換えか照合の行がある回は、タグに無い言い方にタグの語が紛れていると、`out\stable_diffusion.log` に `danbooru: タグに無い言い方 '…'（中のタグの語: …）` と1回ずつ出る。
置き換えを足すときの手掛かりにする。

SD1.5 用の LoRA を足す規則を書いているなら、その行の「モデル」を `sd15` にしておく。
系統の違う LoRA が適用されるとゲームごと落ちる（安全弁が外すのはゲームが入れたタグだけ）。

書き換えた前後のプロンプトは、種類と段ごとに最初の1枚だけ `out\stable_diffusion.log` に全文で出る（`前:` / `後:` の行）。
規則を保存し直すと、もう1回出る。

## 立ち絵の飾りを抑える

背景の切り抜きのモデルは、`131_sharp_portrait` の設定へ移した。入れていた isnet-anime は `131_` が引き継ぐ。
isnet-anime は人物を削らない代わりに、人物に付いた飾り（後光・渦・結晶など）も人物の一部として残す。
飾りが要らないなら、描く段階で抑える。

SD1.5（SoteMix など）の立ち絵の飾りを抑える規則の例（どれも「モデル」は `sd15`、種類は立ち絵）:

| 欄 | 中身 |
|---|---|
| 除去 | `wallpaper`、`empty background` |
| 追加（プロンプト） | `(simple background:1.2)` |
| 追加（否定） | `halo, wings, aura, magic, light rays, particles, sparkles, picture frame, ornate background, scenery` |

背景は黒から灰色の無地になり、後光・翼・額縁などが描かれにくくなる。
外見に結晶や魔法の炎などが書かれている人物は、それが人物の一部として残る。

## 高度設定（今の画像から描き直す・2つのモデルで続けて描く・顔だけ描き直す・表情差分）

ツール画面の「高度設定」のタブで、描き方そのものを変えられる。
どれも既定は OFF（ゲームのまま）。表情差分だけは ON / OFF を持たず、表情を見せる MOD があるときに描く。
使うモデルは、「状態 / モデル」のタブで保存したカスタムプリセットから選ぶ。
画像生成の方式が sdcpp 系（cuda / vulkan / cpu）のときだけ効き、diffusers 系ではふだんどおり描く。
設定は描くたびに読み直すので、保存した次の画像から効く。

### タブの形

タブには「img2img を使う」「txt2img→img2img を使う」「立ち絵の顔だけ描き直す」の3つの枠と、「立ち絵の表情差分」の枠がある。
3つの枠は、見出しのチェックで、その描き方を使うかを決める。
OFF のあいだは枠の中を折りたたみ、ゲームのまま描く。
ON にすると、種類（立ち絵・敵・モンスター・背景）ごとの欄が出る。

プリセットの欄の「（ゲーム既定のモデル）」は、ゲームで選んだモデルで描く。
モデルの差し替えや種類ごとのプリセットを使っていても、ゲームで選んだモデルを使う。寸法・サンプラーはほかのタブの値。
モデルの差し替えを使っているときは、ゲームで選んだモデルをもう1つ読み込むので、そのぶん VRAM を使う。
保存したカスタムプリセットを選ぶと、そのプリセットのチェックポイント・寸法・サンプラーで描く。
選んだプリセットが消えていたら、ゲーム既定のモデルで描き、タブの下にメッセージを出す。

### ゲームの設定の画面の「画像の再生成」

ゲームの設定の画面（歯車）の「画像の再生成」は、描き方ごとのボタンに分かれる。
どの画像を描き直すか（会話の相手・背景・戦闘中の敵）は、ゲームが決める。

| ボタン | 描き方 | 出るとき |
| --- | --- | --- |
| 画像の再生成(txt2img) | ゲームのまま描き直す | いつも |
| 画像の再生成(img2img) | 今の画像を下絵にして描き直す | 「img2img を使う」が ON のとき |
| 画像の再生成(txt2img→img2img) | 2つのモデルで続けて描く | 「txt2img→img2img を使う」が ON のとき |

どちらも OFF のときと、画像生成の方式が diffusers 系のときは、ボタンを分けずにゲームのままにする。

主人公の立ち絵の描き直し（`335_player_portrait_regenerate` のボタン）にも、同じ描き方の一覧が出る（立ち絵の欄のプリセット・強さを使う）。

### 今の画像から描き直す（img2img）

「画像の再生成(img2img)」で、今の画像を下絵にして描き直す。
使うのは再生成のボタンだけで、新しい NPC・場所・敵を描く通常の生成では使わない（今の画像が無いため）。
服の柄や色・ポーズ・持ち物が残りやすく、モデルを替えても同じ人物に見える。
今の画像が無いときは、ふだんどおり描く。

| 欄 | 意味 |
| --- | --- |
| プリセット | 描き直しに使うモデルと設定 |
| 強さ | 下絵をどこまで描き変えるか（0.05〜1.0）。小さいほど今の画像が残り、大きいほどモデルの描き方が出る。既定は 0.5 |

強さ 0.5 では、立ち絵は配置と配色がほぼそのまま残る。
背景は 0.5 でも建物の形が変わることがある。残したいなら強さを下げる。
下絵に使うのは背景を抜いた画像なので、元の画像に残っていた飾り（額縁など）は、別の物に描き変わって残ることがある。

### 2つのモデルで続けて描く（txt2img→img2img、上級者向け）

1つ目のプリセットで描いた画像を下絵にして、2つ目のプリセットで描き直す。
構図と配色を片方のモデルで決め、もう片方で仕上げるときに使う。
ON にするとき、VRAM と時間についての確認が出る。

| 欄 | 意味 |
| --- | --- |
| 1つ目（txt2img） | 最初に描くモデルと設定 |
| 2つ目（img2img） | 描き直すモデルと設定 |
| 強さ | 2つ目がどこまで描き変えるか。既定は 0.6 |
| 通常の生成でも使う | 再生成のボタンを通らずに描く画像（新しい NPC・場所・敵が出たときなど）も、2つのモデルで続けて描く |

再生成のボタンで描き直すときは、押したボタンの描き方で描く（「通常の生成でも使う」は見ない）。
1枚にかかる時間は、およそ2倍になる。
2つ目で描けなかったときは、1つ目の画像をそのまま使う。

### 人間の敵（闘技場の相手など）を立ち絵の描き方で描く

同じタブの「人間の敵（闘技場の相手など）を立ち絵の描き方で描く」を ON にすると、種族が人間の敵だけを立ち絵の行で描く。
既定は OFF（ゲームのまま）。
使うのは、立ち絵に割り当てたプリセット・img2img・txt2img→img2img（「通常の生成でも使う」も立ち絵の欄を見る）。
正方形でなく同じ高さの縦長（幅は高さの 2/3）で描き、左右を画像の端の色で埋めて正方形に戻す。
埋めた部分は背景抜きで消えるので、戦闘画面では見えない。
規則と寸法の目標は敵のままで、人間でない敵は今までどおり敵の行で描く。

異形向けのモデルで敵を描いていると、人間の相手まで骸骨や仮面の顔になり、正方形の枠で頭や足が切れる。
それを避けたいときに使う。
ON のあいだは、上の帯の「ゲーム既定」の行に「人間の敵は立ち絵の行のモデルで描く」と添える。

設定と関係なく、種族が人間の敵は、ゲームが否定に入れる `human` / `people`（女性なら `girl` / `women` も）を外して描く。
本文で人間を指定しながら否定で人間を避ける形になっているため。

### 立ち絵の顔だけ描き直す

同じタブの「立ち絵の顔だけ描き直す」を ON にすると、描き終えた立ち絵の顔だけを描き直す。
既定は OFF（ゲームのまま）。
立ち絵の全体の中では顔が小さく、左右の目の色や形がずれて描かれることがある。
顔の周りを切り出して大きく描き直し、縁をぼかして元の画像へ貼り戻すので、顔の外は変わらない。
新しい NPC を描く通常の生成にも、再生成のボタンにも効く。
txt2img→img2img で描いているときは、2つ目まで描き終えた画像の顔を描き直す。
ゲームが作る背景を抜いた画像と会話中の画像は、描き直した後の画像から作られる。

| 欄 | 意味 |
| --- | --- |
| プリセット | 顔を描き直すモデルと設定。「（立ち絵を描いたプリセット）」なら、その立ち絵を描いたのと同じモデルで描く |
| 強さ | 顔をどこまで描き変えるか（0.05〜1.0）。小さいほど元の顔が残る。既定は 0.4 |
| 既存の立ち絵にもかける | 一括生成の最後に、既に在る立ち絵にも顔の描き直しをかける。既定は OFF |

強さ 0.4 では、目の崩れが直り、表情と顔立ちは元のまま残った。
0.5 では表情や目の形が変わり始めた。
1枚あたり、顔の周りを1回描くぶん時間が延びる（SDXL で約7秒）。
立ち絵と同じモデルで描くなら、VRAM は増えない。
顔が見つからない画像（後ろ向き・顔を覆う兜など）は、元の画像のまま使う。
敵・モンスター・背景には効かない。

「既存の立ち絵にもかける」を ON にして一括生成を流すと、ゲームの仕事を終えた後に、まだ顔を描き直していない NPC の立ち絵へ顔の描き直しをかける。
主人公の立ち絵にはかけない。
立ち絵・背景を抜いた画像・会話中の画像・顔アイコンを書き直し、顔の外は変わらない。
背景を抜いた形は今の画像のものを使い、ドット化と減色はゲームの処理を通す。
描き直した人物は覚えておき、次の一括生成では外す（顔が見つからなかった人物も外す）。
その人物の立ち絵が再生成のボタンなどで描き直されたら、また対象になる。
「立ち絵の顔だけ描き直す」が ON のときに新しく描いた立ち絵は、描いたときに覚えるので対象にならない。
元の画像が変わるので、表情差分（下）はその後に新しい顔から描き直される。
1人あたり、顔の周りを1回描くぶんの時間がかかる（SDXL で約7秒。差分も描き直すなら、そのぶん加わる）。

### 立ち絵の表情差分

会話の表情を見せる MOD（`347_conversation_expressions` など）が入っているときだけ、立ち絵の表情差分を描く。
表情は、基本表情の笑う・怒る・悲しむ・驚くの4つと、自分で足した追加の表情。
追加の表情には、見本として照れる顔（`shy`）が最初から入っている。
描き終えた立ち絵の顔の周りを、表情のタグを足して弱い強さで描き直し、立ち絵と同じ工程（縮小・減色。`131_` が ON なら高画質のまま）を通して置く。
置き場は立ち絵と同じフォルダの `expressions\`。
ここでは ON / OFF を持たない。表情を見せる MOD を外すと描かない。

- 一括生成では、立ち絵に続けて描く
- 一括生成では、ゲームの仕事が済んだ後に、立ち絵が既にあって差分の無い人物へ差分だけ描く（立ち絵は描き直さない）。ゲームの「一括生成が完了しました。」の後、起動して最初の回は画像生成の用意（モデルの読み込み）に数十秒かかり、その間は「NPCの画像: 画像生成を用意しています（表情差分）」と出る。続いて「NPCの画像: 名前（表情差分）」と件数が出て、描き終えるとゲームの一括生成の終わりの表示に戻る。「中断する」で止まり（画面は中断の表示）、次の一括生成で残りから描く。描いた人数は `out\stable_diffusion.log` に出る。1人あたり顔の周りを表情の数だけ描くぶん（1表情あたり SD1.5 で約4.5秒、SDXL で約7秒。最初から入っている5表情なら SDXL で約32秒）かかる
- 表情を足した・タグを変えたときは、描き揃った人物にも、次の一括生成で足した表情とタグを変えた表情だけ描く。描き直すまでは前のタグの絵のまま出る
- それ以外（会話の中・再生成のボタンなど）では、立ち絵を先に出してから裏で描く。ゲームが次の画像を描くときは、ゲームを先に描かせる
- 主人公の立ち絵には描かない（会話の相手に出ないため）
- 描いている途中で立ち絵が描き直されたら止める。前の立ち絵の差分は、描き直した立ち絵には使われない

顔を描くモデルは、上から順に最初に当てはまるもので決まる（ふだんの生成で描いた立ち絵の場合）。
「高度設定」の表情差分の枠に、それぞれの欄のいまのモデルと、いま当てはまる行・その強さが出る。

1. 「立ち絵の顔だけ描き直す」が ON でプリセットを選んでいれば、そのプリセット
2. txt2img→img2img を通常の生成でも使う立ち絵なら、その2つ目
3. 種類ごとのプリセットの立ち絵
4. ゲーム既定のモデル

再生成のボタンの img2img・txt2img→img2img で描いた立ち絵は、1 が無ければそのボタンの描き方のモデルで描く。
プリセットが見つからない欄は、ゲーム既定のモデルで描く。

| 欄 | 意味 |
| --- | --- |
| 描き直しの強さ: SD1.5 のモデル | 顔を描くモデルが SD1.5 のときに、元の顔をどれだけ描き変えるか（0.05〜1.0）。小さいほど元の顔が残り、大きいほど表情がはっきりするが、顔立ちや目の色も元の立ち絵から離れる。既定は 0.5 |
| 描き直しの強さ: SDXL・その他のモデル | 顔を描くモデルが SD1.5 でないとき（SDXL・系統の読めないモデル）の描き直しの強さ。既定は 0.35 |
| 描き直しの強さ: モデルごとに変える | 同じ系統の中でもモデルごとに描き直しの強さを変えたいときに書く。`チェックポイントのファイル名の一部=強さ` を `;` で区切って並べ（例: `anime=0.3; real=0.45`）、前から見て最初に当たった行を使う。当てはまれば上の2つより優先する。書き方はモデル別の規則と同じで、`/` でどれか、`!` で除く。`sd15` / `sdxl` と書くと系統を指す。既定は空 |
| 基本表情のタグ（笑う / 怒る / 悲しむ / 驚く） | 表情ごとに足す画像生成の英語のタグ。空にした表情は描かず、会話でも選ばせない。名前と意味は変えられない |
| 追加の表情 | 自分で足す表情の表。「表情を追加」で行を足し、× で消す。最初は見本の `shy`（照れる・恥ずかしがる／`blush, embarrassed`）の1行が入っている |

追加の表情の欄は次の3つ。

| 欄 | 意味 |
| --- | --- |
| 名前 | 英小文字で始まる英小文字・数字・`_`（32字まで）。会話の AI が返す値と、表情の絵のファイル名になる。基本表情（`neutral` / `smile` / `angry` / `sad` / `surprised`）とほかの行の名前は使えない |
| 意味 | 会話の AI に渡す、どんなときの表情かの説明（例: 照れる・恥ずかしがる）。タグのある行には要る |
| タグ | 表情に足す画像生成の英語のタグ。空にした行は描かず、会話でも選ばせない |

追加の表情は `state\stable_diffusion\expressions.json` に保存される。
このファイルが無いあいだは、見本の `shy` の1行があるものとして描く。
見本が要らなければ、行を消して保存する（空の一覧が保存され、見本は戻らない）。
保存すると、ゲームを起動し直さなくても、次の会話から表情の候補に入り、次に描く立ち絵から描かれる。

| 変えたもの | 立ち絵のある人物の表情の絵 |
| --- | --- |
| 表情を足した | 次の一括生成で、足した表情だけ描く |
| タグ（基本表情も追加の表情も） | 次の一括生成で、その表情だけ描き直す。描き直すまでは前のタグの絵が出る |
| 追加の表情の名前 | 描き直さない。次の一括生成でファイル名だけ変える（それまではその表情は出ない） |
| 追加の表情の意味 | 何もしない（絵に関わらない） |
| 追加の表情を消した | 次の一括生成で、その表情の絵を消す |
| 強さ | 描き直さない（次に描く表情から効く） |

1表情あたり、顔の周りを1回描くぶんの時間がかかる（SD1.5 で約4秒、SDXL で約7秒）。
表の下に、いまの表情の数と、新しい立ち絵1人あたりの時間の目安が出る。
描いた差分は `out\stable_diffusion.log` の `表情差分 [名前]` の行に、表情ごとの秒数と、使った強さ・どの欄で決まったかが出る。

### VRAM

ゲームのモデルと違うプリセットを選ぶと、ゲームのモデルとは別にもう1つモデルを読み込む。
そのぶん VRAM を多く使う。
VRAM が足りないと、画像の生成がとても遅くなるか、ゲームが落ちる。
ローカルの LLM を同じ GPU で動かしているときは、特に気をつける。
最初の1枚は、モデルを読み込むぶん数秒遅くなる。

描き直したか、続けて描いたかは、`out\stable_diffusion.log` の行に `描き直し` / `続けて描く 1/2`・`2/2` と出る。
顔を描き直した画像は `顔の描き直し` の行に、見つけた顔の位置と、かかった秒数が出る。

## 困ったとき

| 症状 | やること |
|---|---|
| 画像が変わらない | `out\stable_diffusion.log` に `wrapped` の行が出ているか。短辺の目標だけ上げて長辺の上限がゲームのままだと、計算上どこも変わらない |
| 画像が崩れる・落ちる | 目標を既定へ戻す。SD1.5 は学習時の寸法から離れるほど崩れ、系統の違う LoRA を当てるとゲームごと落ちる |
| 立ち絵や敵の体の一部が切り抜きで消える | `131_sharp_portrait` の「背景の切り抜きのモデル」と「敵の背景抜きを2つのモデルで合わせる」を使う |
| 顔が出ない（全身の縮小が顔になる） | ゲームが顔を見つけられなかった回。寸法とは関係なく起きる（`131_sharp_portrait` の「顔の検出をやり直す」を ON にすると拾える率が上がる） |
| 生成が遅くなった | 寸法と steps を上げれば時間も増える（VERIFICATION.md §3.65 の実測）。桁で遅くなったら VRAM が溢れている。LLM を載せたまま拡大すると起きやすい。寸法を下げるか、ゲーム側の詳細設定で VAE のタイル化を有効にするか、LLM を降ろす |
| 闘技場の相手が骸骨や仮面の顔になる・頭や足が切れる | 「高度設定」の「人間の敵（闘技場の相手など）を立ち絵の描き方で描く」を ON にする |
| SDXL で人の敵の横に小さな生き物が出る・立ち絵が白黒になる・背景に人が出る | モデルに合ったテンプレートを「モデル別」のタブから入れる（§1） |
| 規則が思った形に当たっているか分からない | `out\stable_diffusion.log` の `前:` / `後:` の行に、書き換えた前後の全文が出る |
| 方法とスケジューラが効かない方式がある | `diffusers_openvino` には同じ API が無い。ログに1度だけ警告が出る |
| 描き直しが効かない | 設定の画面の「画像の再生成(img2img)」を押す。今の画像がある回だけ効き、diffusers 系では効かない |
| 描き直しで別人になる | 「高度設定」の強さを下げる（既定 0.5） |
| 立ち絵の左右の目の色が違う・目や顔が崩れる | 「高度設定」の「立ち絵の顔だけ描き直す」を ON にする。既にある立ち絵は、「既存の立ち絵にもかける」も ON にして一括生成を流すと顔だけ描き直す |
| 表情差分が描かれない | `out\modloader.log` の `表情差分を描かない` の WARN。表情を見せる MOD が入っていない・sdcpp 系でない・顔が見つからない（`表情差分 [名前]: 顔が見つからない`）回は描かない。顔が見つからなかった立ち絵には、立ち絵を描き直すまで描かない |
| 一括生成で、立ち絵のある人物に差分だけ描かれない | `out\modloader.log` の `表情差分だけ描けなかった` の WARN に理由が出る。`呼び方の控えが無い` なら、どこかで立ち絵を1枚描く（再生成のボタンなど）と控え（`state\stable_diffusion\expression_template.json`）ができ、次の一括生成から描く |
| 一括生成で差分だけ描いた顔の描き味が立ち絵と違う | 差分は今の設定のモデル（顔だけ描き直すのプリセット、続けて描くの2つ目、種類ごとのプリセットの順）で描く。立ち絵を前に別のモデルで描いていると、顔の周りだけ今のモデルの描き味になる |
| 表情差分の表情が弱い・きつい | 「高度設定」の表情差分の枠で、いま当てはまる行に出ている欄（SD1.5 のモデル / SDXL・その他のモデル）の描き直しの強さを変える。同じ系統の中で一部のモデルだけ変えたいなら「モデルごとに変える」に行を足す。読めない区切りは飛ばし、`out\stable_diffusion.log` に出る |
| 足した表情・タグを変えた表情が前から居る人物に出ない | ワールドの一括生成をかける。`out\stable_diffusion.log` の `表情差分 [名前]` の行に描いた表情が出る。名前が使えない・重なる行は飛ばされ、`追加の表情で名前が使えない・重なる行を飛ばした` の行に出る |
| 顔の描き直しで表情や顔立ちが変わる | 「立ち絵の顔だけ描き直す」の強さを下げる（既定 0.4） |
| 顔の描き直しが効かない | `out\stable_diffusion.log` に `顔が見つからないので描き直さない` と出た画像は、顔を見つけられなかった。diffusers 系では効かない |
| diffusers 系で寸法が変わらない | 既定でそうしてある（VERIFICATION.md §3.65）。ON にすると RAM を使い切ることがある |
| diffusers 系で RAM が増えたまま戻らない | 寸法ごとにモデルが作り直され、ゲームを閉じるまで常駐する（実測）。寸法は1通りに絞る。2通り以上使うと `out\stable_diffusion.log` に警告が出る |
