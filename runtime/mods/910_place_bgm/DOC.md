## 1. 遊び方（`docs\MODS.md` 相当）

### `910_place_bgm`: 施設と土地のBGMを置いた曲から選んで鳴らす

素のゲームの BGM は土地に1曲ずつ決まっていて（セーブの `areas[id]["bgm"]`）、
宿屋に入ってもギルドに入っても同じ曲が鳴り続ける。
曲を足す手段も、比率で選ばせる手段も無い。

この MOD を入れると、施設に入ったときはその施設の種類の曲を、通りに居るときはその土地の種類の曲を、
置いてある曲から重みで1曲選んで鳴らす。
戦闘の曲は触らない（`322_battle_bgm` の領分）。

| 場所 | 何を置くか |
|---|---|
| `<ゲーム>\Assets\sounds\musics\` | 素の曲が居る場所（`town\calm\…` のように2段。直下の単発曲も含む）。`battle\` は戦闘曲なので見ない |
| `<ローダ>\state\musics\place\` | 足したい曲を置く場所。下にフォルダを切ってよい |

対応は `.mp3` / `.ogg` / `.wav`。
曲は `musics\` からの相対パス（`town\calm\曲.mp3`）で見分け、同じ相対パスが両方にあれば `state\` 側が鳴る。

曲を置いただけでは**鳴らない**。設定画面で「使う」に入れた曲だけが候補になる。
何も入れていない種類の施設では土地の曲がそのまま続き、何も入れていない種類の土地では素の曲が鳴る。
つまり入れただけでは何も変わらず、決めたところだけが変わる。

#### どの曲が鳴るか

いま居る場所から上の段へ順に見て、候補が1曲でもある段の重みで選ぶ。

| 段 | 何で決まるか | どこに書くか |
|---|---|---|
| 1 | その施設（土地 id と施設 id） | `state\musics\place\worlds\<世界>.json` の `facilities`（画面の「ワールド個別設定」） |
| 2 | 施設の種類（宿屋・ギルド・雑貨店 …） | `playlist.json` の `inn` / `guild` / `general_store` … |
| 3 | その土地（土地 id） | 同 `worlds\<世界>.json` の `areas`（同上） |
| 4 | 土地の種類（町・村・都市・ダンジョン） | `playlist.json` の `area:town` / `area:village` / `area:city` / `area:dungeon` |
| 5 | どこにも無い | 素の曲（土地に焼き付いた曲） |

施設の段が土地の段より常に先。
ある町の曲を個別に決めていても、その町の宿に入れば宿の曲になる。
通路（入口・出口・区画・ダンジョンの場所）は施設の段を持たない。

曲が変わるのは場所が変わったときだけ。
宿に入れば宿の曲、通りへ出れば土地の曲に戻り、通りから通りへ歩いても曲は続く。
土地の曲は最初に選んだものをその土地の曲として覚え、次に来たときも同じ曲が鳴る
（素のゲームと同じく土地に曲が付く）。
施設は入るたびに選び直す。どちらも設定で変えられる。
依頼で入るダンジョンは1回きりの土地なので覚えない。

#### 設定画面

ローダの設定画面でこの MOD を選んで「設定…」を押すと、この MOD の画面が開く（TECH.md §3.12）。
直接 `python runtime\mods\910_place_bgm\tool.py` で開いてもよい。

- 左はタブ2つ。「一括設定」は場所の種類の一覧（施設 13 種、土地 4 種）、「ワールド個別設定」はセーブの世界 → 土地 → 施設の木。
  どちらも選ぶと右がその場所の選曲になり、「使う曲」の列に入れた曲の数が出る
- 「ワールド個別設定」は一括設定より先に見る指定。その町だけ・その宿だけの曲を決める。
  世界を開くとセーブ（`savedata.json`）を読んで土地と施設を並べる（通路は出さない。依頼のダンジョンは「ダンジョン（N）」に畳む）。
  施設は初訪問で作られるので、まだ行っていない町の施設は並ばない（GAME.md §2.31）。
  本体が土地に覚えた曲は右の見出しに出て、「覚えた曲を消す」で次に入ったとき選び直す。
  セーブは読むだけで書かない。書くのは `state\musics\place\worlds\<世界>.json`
- 右は左右2段で、左が置いてある曲の全部（曲名・フォルダ・置き場）、右がその場所で使う曲（曲名・フォルダ・置き場・重み・確率）。
  左をダブルクリック（または「使う >>」）で右へ入り、右をダブルクリック（または「<< 外す」）で外れる
- 右で選んだ曲の重みは下の欄で変える。確率の列は重みの合計に対する割合をその場で出す
- 一覧の上の欄で列ごとに絞り込める（曲名は部分一致、フォルダと置き場は選択、重みは下限）。
  絞り込みは表示だけを変え、「全て使う / 全て外す」は表示中の曲だけに効く。
  「町の calm を全部使う」はフォルダで `town/calm` に絞って「全て使う」の2手
- 「保存」で `state\musics\place\playlist.json`・`settings\mod_settings.json`・開いた世界の `worlds\<世界>.json` に書く。
  ゲームを起動したまま保存しても次の移動から効く。世界のファイルは本体も書く（覚えた曲）ので、保存の直前に読み直して指定の分だけ差し替える
- セーブの置き場は `%LOCALAPPDATA%\Darmabeko\Instantale\saves\`。別の場所なら環境変数 `IML_INSTANTALE_DATA` で指す（`323_` と同じ）
- 窓の大きさと位置は覚える（`settings\gui.json` の `tool_window`）

| 種類 | 鍵 | いつ |
|---|---|---|
| 宿屋 / ギルド / 雑貨店 / 専門店 / 鍛冶屋 / 医療施設 / 役場 / 裏の事務所 / 闘技場 / 奴隷市場 / 訓練施設 / 名所 / 自由生成施設 | `facility_type` そのもの | その施設に入っている間 |
| 町 / 村 / 都市 / ダンジョン | `area:town` / `area:village` / `area:city` / `area:dungeon` | 通路に居るとき、または施設の段に候補が無いとき |

| 設定 | 意味 |
| --- | --- |
| 「使う」に入れたときの重み | 既定 100。設定画面で曲を右（使う）へ入れたときの初期値 |
| 前回と同じ曲を続けて選ばない | 既定は入。同じ種類の場所で候補が2曲以上あるときだけ効く。覚える場所には効かない |
| 土地の曲は一度決めたら覚える | 既定は入。切ると土地に入るたびに選び直す |
| 施設の曲は一度決めたら覚える | 既定は切。入れるとその宿・その店ではいつも同じ曲が鳴る |

#### 重みの意味と `playlist.json`

重みは比率で、同じ種類の合計に対する割合が確率になる。合計を 100 に揃えれば書いた数字がそのままパーセント。
`0` か無ければその種類では鳴らない。

画面を使わず `state\musics\place\playlist.json` を直接書いてもよい。

```json
{
  "playlists": {
    "inn":       {"宿.mp3": 100, "town/calm/Medieval Vol. 2 4 (Loop).mp3": 50},
    "guild":     {"guild/酒場.ogg": 100},
    "area:town": {"town/calm/The Streets of Baerlon.mp3": 100, "town/lively/Thought and Memory_44.1kHz_16Bit_4-4_T92_Loop.wav": 100}
  }
}
```

- 鍵は `musics\` からの相対パスをスラッシュ区切りで。`state\musics\place\宿.mp3` なら `宿.mp3`、`state\musics\place\guild\酒場.ogg` なら `guild/酒場.ogg`
- ファイルにあって曲が無い行は消さない（曲を一時的に外しても数字が残る）
- 起動時にファイルが無ければ、全種類が空の形で作られる

#### 覚えた曲と `worlds\<世界>.json`

土地ごとに覚えた曲は `state\musics\place\worlds\<世界名>.json` に入る。

```json
{
  "areas": {
    "7": {"name": "陽光の砦", "chosen": {"level": "area:town", "track": "town/calm/The Streets of Baerlon.mp3"}}
  },
  "facilities": {}
}
```

ある土地の曲を選び直したいときは、画面の「覚えた曲を消す」（またはその土地の `chosen` を消す）で次に入ったとき選び直す。
`playlist.json` からその曲を外したときも選び直す（覚えた曲が候補に無くなるため）。
同じファイルの `playlist` が「ワールド個別設定」の中身で、その土地・その施設だけの曲になる。
施設の鍵は `土地id/施設id`（施設 id は土地の中でしか一意でない。§5）。
世界名を変えると控えが行方不明になる（`311_` と同じ制約）。

#### 困ったとき

ログは `out\place_bgm.log` の `[PLACEBGM]` の行。
曲を決めるたびに1行で、鳴らした曲・決めた段・決め方（`picked` / `remembered` / `kept`）・
そのときの土地と施設・きっかけ（`by game` / `by move_phase` / `by poll`）が並ぶ。

| 症状 | やること |
|---|---|
| 曲が変わらない | `[PLACEBGM]` の行が出ているか。出ていなければ `out\modloader.log` の `applied` にこの MOD があるか（`load_order.local.json` に名前があるか） |
| `no candidate` と出る | その場所の段に「使う」に入れた曲が無い。行の `area`/`fac` の種類と、画面で入れた種類を見比べる |
| `FAILED` と出る | ファイルは在るが鳴らせなかった。`out\modloader.log` の直前の ERROR に例外がある。形式が対応外 |
| 施設に入っても曲が変わらない | 行が `by move_phase` で出ているか。出ていて `fac ?` なら施設が読めていない（§4 の 2）。行そのものが無ければ `move_phase` に当たっていない |
| 通りを歩くたびに曲が頭から鳴る | 行の段と場所が毎回変わっている。`area ?` なら土地 id が読めていない（§4 の 1） |
| 土地に入るたびに違う曲になる | 「土地の曲は一度決めたら覚える」が切れているか、`worlds\<世界>.json` に書けていない（`modloader.log` に `控えを書けなかった`） |
| `playlist.json の … にある曲が見つからない` | 曲を消したか名前を変えた。行を消すか名前を直す |
| 曲を足したのに一覧に出ない | 拡張子が対応外か、`battle\` の下に置いている。画面なら「再走査」 |
| ワールド個別設定に世界が並ばない | セーブの置き場が見つかっていない。画面の下の行に探した場所が出る。別の場所にあるなら環境変数 `IML_INSTANTALE_DATA` で指す |
| ワールド個別設定で決めたのに効かない | 行の段が `world:facility:…` / `world:area:…` になっているか。なっていなければ世界名が違う（`worlds\` のファイル名とログの世界名を見比べる）か、その場所の指定に候補が無い |
| 「設定…」を押しても画面が開かない | 設定画面の下の状態行を見る。`tool.py` が無いか、Python が tkinter を持っていない |

## 3. ゲームの経路（`docs\GAME.md` §2.11 へ戻す知見）

`207_probe_battle_bgm` の記録（`out\battle_bgm.log` と `.log.1`、2026-08-21〜09-01）で、
戦闘曲以外の `play_music_from_src` の呼び出し元を数えた。
`caller` の先頭の枠と `target` の欄で数えているので、同じ経路が2つの書式（`.log.1` は旧書式）で出る分は足してある。

| 呼び出し元（`instantale.py` の行） | 場面 | 渡してくる物 | 回数 |
|---|---|---|---|
| `:1464` の lambda（`Clock` 経由） | ロード直後・題名から入ったとき | app | 100 |
| `:10440` の lambda | 土地の移動 | app | 55 |
| `:8000` の lambda | 戦闘の終わり | app | 154 |
| `:6656` の lambda | 依頼の終わり（`QuestEndManager`） | app | 19 |
| `:6168` の lambda | 依頼の始まり（`QuestStartManager`。ダンジョンの曲） | app | 19 |
| `:1027` / `:8038` / `:8102` の lambda | 少数。場面は特定していない | app | 4 / 3 / 3 |

`MovePhaseManager` からの呼び出しは 0 件。
施設の出入りではゲームは曲を鳴らし直さない。
だからこの MOD は `move_phase` の復帰後に自分で鳴らし直す。

渡してくる物はこの範囲では全部 app だった。
`106_` が直した「app でない物を渡してくる復帰」はこの2世代のログには現れていない（`106_` は main_024 で本体が取り込んだ扱い）。
この MOD は渡された物をそのまま `orig` へ渡し、場所を読むときだけ走っている app を引き直すので、どちらでも動く。

`stop_music` は戦闘の始まり（`:6991` / `:7001`）・戦闘の手番（`:7377`）・題名へ戻る（`:846`）・
依頼の始まりと終わり（`:6100` / `:6549`）から来る。
この MOD は何も鳴っていない間は触らない（切り替えの最中と見なす）ので、これらと競わない。

## 4. 未確認と確認手順（実機で確かめること）

区別のつく状態を先に作る。
`state\musics\place\` に見分けやすい曲を2曲以上置き、設定画面で「宿屋」にその曲、「町」にゲームの `town\calm` を全部入れて保存してから注入する。
確かめるのはログの行で、鳴った音は行の裏付け。

| # | 確かめること | どう分かるか |
|---|---|---|
| 1 | `Area.size` が実行時のオブジェクトで読めるか。`207_` の記録では `size=None` が出ている（`current area = 'エリュシオン' (id='8') size=None`、2026-08-21） | 行の `(town by area)` の `by`。`area` なら読める。`save` / `world` / `src` なら辞書か経路から取っている。`?` なら土地の段が効かない |
| 2 | `move_phase` の復帰後に `player.location` が着いた先の施設になっているか（GAME.md §2.6 は復帰後を「着いた瞬間」としている） | 宿に入った直後の `by move_phase` の行の `fac` が宿か。1つ前の施設なら復帰前に読んでいる |
| 3 | 見張り（1秒ごと）が要るか | `by poll` の行の数と場面。依頼の終わり・ロード直後・戦闘の後で出るか。全部の場面が `by game` / `by move_phase` で拾えているなら見張りは外せる（`POLL_INTERVAL = 0`） |
| 4 | 戦闘の後に場所どおりの曲へ戻るか（衛兵と宿で戦った場合、ダンジョンの中） | `by game` の行が戦闘の後に出て、段が戦闘前と同じか。`106_` の sweep の restart もこの包みを通る |
| 5 | `state\` 側の曲（絶対パス）が施設の切り替えで鳴るか。`322_` は戦闘曲で確認済みだが経路が違う | 宿に入って `FAILED` が出ず音が変わるか |
| 6 | 覚えた曲がロードをまたいで同じか | `worlds\<世界>.json` の `chosen` と、ロード直後の `remembered` の行 |
| 7 | ゲームを起動したまま `playlist.json` を保存して次の移動から効くか | 保存後の最初の `by move_phase` の行の `of N` が変わるか |
| 8 | 通り→通りで鳴らし直していないか | 通りを歩いても行が増えないこと。増えるなら §1 の「困ったとき」の `area ?` |
| 9 | ロード直後（`player.location` が id の文字列）でも施設が読めるか（GAME.md §2.7） | 宿でセーブして読み直し、`:1464` からの `by game` の行の `fac` が宿か |
| 10 | 「宿から通り」で土地の曲が頭から鳴り直すことの体感。曲の続きから鳴らす手段は pygame の `Sound` には無い（位置を指定できない）ので、気になるなら宿の曲を止めて土地の曲を鳴らす以外の形は取れない | 遊んで決める |

確認したら、行を §2 の表に書き足し、`docs\VERIFICATION_LOG.md` に日付・回数・ログの抜粋を残す。
1 で `by area` が取れなかった場合は GAME.md §2.7 の `Area` の属性の一覧に「`size` は無い」と書き足す。
3 で `by poll` が 0 なら見張りを外し、ここにその回数を残す。

## 5. セーブ単位の個別指定

「この町だけ」「この宿だけ」の曲を、セーブの中身から場所を選んで決める。
本体の段 1・3 と、画面の「ワールド個別設定」のタブで実装済み（未実機。§4 の 6 と一緒に確かめる）。

#### 実セーブで分かったこと（2026-09-01、3世界）

`%LOCALAPPDATA%\Darmabeko\Instantale\saves\<世界>\savedata.json` を読んだ。

| 項目 | 実測 |
|---|---|
| 土地 | `areas[id]` に `name` / `size` / `bgm` / `id` / `nodes`。1世界に 37〜54 土地、うち 28〜45 が `size=dungeon`（依頼で作られた土地） |
| 施設 | `areas[id].nodes[nid].facilities[fid]` に `name` / `facility_type` / `id`。1世界に 240〜307 施設、うち 130〜190 が `dungeon_location` |
| 施設 id | **土地の中でしか一意でない**（3世界とも重複あり）。鍵は `土地id/施設id` |
| 世界の見分け | `world_data.name`。ローダの `state.world_key` / `world_filename` と同じ規則で、画面もローダの関数でファイル名を作る |
| 復号 | XOR（GAME.md §2.16）。読むだけで書かない |
| 未生成の施設 | 施設は初訪問で作られる（GAME.md §2.31）ので、未訪問の町の施設は一覧に出ない。土地の指定だけ先にできる |

`world_data.json` ではなく `savedata.json` を読む。
土地の数が違い（依頼の土地は savedata にしか無い）、`bgm` も savedata が正（`104_` が書き換えた後の値）。

#### 作り

| 論点 | 決めたこと |
|---|---|
| 段の順 | 施設 id > 施設の種類 > 土地 id > 土地の種類。「この町の宿だけ」は施設 id で、「この町全体」は土地 id で指定する |
| 本体と画面が同じファイルを書く | 本体は `chosen` を、画面は `playlist` を書く。本体は更新時刻を見て読み直し（`WorldStore.load(fresh=True)`）、画面は保存の直前に読み直して `playlist` だけ差し替える。`playlist` も `chosen` も無くなった項目は消す |
| ダンジョン | 一覧に出すが畳む。依頼の土地は1回きりで、指定する意味が薄い |
| 名前 | `name` を控えに写す（本体は覚えるとき、画面は保存するとき）。id で引くので、セーブ側で名前が変わっても動作には関わらない |
| セーブの復号 | `323_npc_carryover\carryover.py` の `decode` の写しを `tool.py` に置いた。MOD どうしは import しない（TECH.md §3.2.3）ので、正式化するときにローダの語彙（`instantale_modloader.saves`: `data_dir` / `list_worlds` / `read_save`）へ寄せ、`323_` も同じ物を使うよう直す |

#### 手で書く形

  "areas":      {"7":     {"name": "陽光の砦", "playlist": {"town/calm/The Streets of Baerlon.mp3": 100}}},
  "facilities": {"7/106": {"name": "灯火亭", "playlist": {"宿.mp3": 70, "guild/酒場.ogg": 30}}}

## 6. `104_balance_area_bgm` を終える道筋

`104_` は新しく作られた土地の `bgm` をセーブに書き換え、その土地の種類のフォルダにある曲へ均等に散らす
（既にある土地は触らない。まとめて均すのは `tools\rebalance_saved_bgm.py`）。
この MOD は鳴らす瞬間に選ぶので、セーブを書かずに同じ結果へ行ける。
「世界の骨格は書き戻さない」（`world_data.json` は骨格）にも沿う。

#### この MOD で `104_` と同じ体験を作る手順

1. 設定画面の「町」で、フォルダを `town/calm` … と順に絞って「全て使う」（`town` の 20 曲を重み 100 で）。村・都市・ダンジョンも同様
2. 「土地の曲は一度決めたら覚える」は入のまま

これで土地に最初に入ったとき（注入後の初訪問）に、その種類の全曲から一様に1曲が選ばれ、以後その土地の曲になる。
`104_` と違って**既にある土地の曲も一度だけ変わる**（注入前から知っている町の曲が変わる。`104_` はこれを避けていた）。
避けたければ、その土地の `chosen` を素の曲にして `worlds\<世界>.json` に書いておく。

#### 残る差

| | `104_` | この MOD |
|---|---|---|
| 散らし方 | 世界で使用回数がいちばん少ない曲を選ぶ | 重みで選ぶ。曲数が多ければ結果は近いが、同じ曲が続くことはある |
| 効く範囲 | 注入後に作られた土地だけ | 注入後に入った土地（既存も含む） |
| MOD を外したら | 書き換えたセーブが残る | 素の曲に戻る |
| 何も設定しないと | 均される | 素のまま（`playlist.json` が空なら何もしない） |

散らし方の差は、選び方に「使用回数が少ない曲を優先」（`worlds\<世界>.json` の `chosen` を数える）を足せば埋まる。
`AREA_PICK = "weighted" | "least_used"` の1設定で済み、`104_` の `choose()` と同じ規則になる。
「何も設定しないと」の差は、初回起動で土地の4種類にゲームの曲を全部 100 で入れておく（`playlist.json` を作るとき）という既定にすれば埋まるが、
それは「入れただけでは何も変わらない」を崩すので、この MOD を正式にするときに決める。

#### 終えるための条件

1. この MOD を `324_` に振り直し、§4 の 1・3・6 が実機で通っている
2. 「散らし方」の差をどうするか決めている（`least_used` を足すか、重みのままでよいとするか）
3. `docs\GAME.md` §2.11 の「エリアBGM」から `104_` への参照を、この MOD への参照に書き換えている
4. `tools\rebalance_saved_bgm.py` をどうするか決めている（`104_` と一緒に `discontinued\` へ移すか、単体の道具として残すか）
5. `104_` の `DOC.md` の先頭に、終えた理由・どこまで動いていたか・残っている症状・再開するなら、の4点を書いて `discontinued\104_balance_area_bgm\` へ移す（TECH.md §2.6.1）。`104_` は `load_order.json` と `BANDS` と VERIFICATION の表に載っているので、そこからも外す

`104_` を切ったまま遊んでいる人のセーブには何も起きない（書き換えた `bgm` はそのまま残り、この MOD がその上で選ぶ）。
