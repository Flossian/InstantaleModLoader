## 1. 遊び方（`docs\MODS.md` 相当）

### `912_equipment_slots`: インベントリに装備枠を追加

素のゲームの装備は武器1つと防具1つだけで、所持品の窓には装備の欄が無い。
兜も鎧も盾も「防具」の1枠を取り合い、今なにを着ているかは装備印の枠線でしか分からない。

この MOD を入れると、所持品の窓を開いたとき、窓の左に装備欄が出る。

```text
        ［  頭  ］
［左手］［  胴  ］［右手］
［    ］［      ］［    ］
［ 腕 ］［  脚  ］［装飾］
                ［装飾］
```

部位は所持品と同じマスで組んであり、頭・腕・脚・装飾は 2×2、左手・右手・胴は 2×4
（武器は最大 1×4）。グリッドは 6列×10行で、部位の外のマスは見せないので空のマスは見えない。
全体は所持品の窓と同じ白い外枠で囲む。縦4マスの武器も元の大きさのまま入る。
1×1 の品を 2×2 の部位に置くと、部位いっぱい（2×2）に広げて表示する（設定 `SCALE_TO_FIT`。既定は入）。
倍率は縦横比を保った整数（1×1 → 2倍、1×4 の剣は等倍）で、広げる品は部位の左上へ寄せ、
所持品へ戻すと元の大きさに戻る。

#### 設定

| 設定 | 既定 | 意味 |
|---|---|---|
| `SCALE_TO_FIT` | 入 | 小さい品を部位いっぱいに広げて描く。切ると本来の大きさのまま |

| 部位 | 入る品（`item_detail`） |
|---|---|
| 右手・左手 | 武器（種類を問わない）と盾（`shield`） |
| 頭 | `headgear` |
| 胴 | `body_armor` / `clothing` |
| 腕 | `gauntlets` |
| 脚 | `legwear` / `leg_armor` |
| 装飾×2 | `accessory`（知らない種類の防具もここ） |

#### 装備する・外す

- **ドラッグ**: 所持品から部位へ落とす。落とせるのは「その部位に収まる・種類が合う」ときで、
  それ以外は所持品へ戻る。装備欄の中で別の部位へ落とすのも同じ規則（通らなければ元の部位へ戻る）。
  外すのは所持品へドラッグで戻す
- **置換**: 既に品が居る部位へ同じ種類の品を落とすと、居た品が所持品の空きへ出て、落とした品が入る。
  所持品に空きが無ければ置換せず、落とした品は所持品へ戻る
- **右クリック**: 所持品の品で「装備」を押すと空いている部位へ入る（手と装飾は右・1つ目が先）。
  埋まっていれば右手（1つ目の装飾）の品と入れ替わり、出た品は所持品の空きへ。
  装備欄の品で「外す」を押すと所持品の空きへ戻る

装備欄の品は所持品の窓には出ない（別枠）。売買の窓にも出ないので、装備したまま売ることはない。

#### 数字の扱い（合算しない）

本体が読む装備は `weapon` と `wearable` の2つで、ダメージ・防御・画面上部の
Atk/Def はこの2つを見る（GAME.md §2.13 / §2.29）。
読む側はネイティブコードなので差し替えられない。
だからこの MOD は、装備欄の中から

- 手にある武器のうち**攻撃力が最高の1つ**を `weapon` に
- 全部位の防具（盾を含む）のうち**防御力が最高の1つ**を `wearable` に

渡す。**合算はしない。**
兜 439 と装飾 500 を着ていれば Def は +500 で、兜のぶんは乗らない。
外したときは残りの中の最高値へ繰り下がる（実機で確認: 右手の剣 580 を外すと左手の剣 480 へ）。

#### どう動くか

- 装備欄は本体の `InventoryGrid`（6列×8行）をもう1枚作ったもの。
  本体のドラッグの受け渡し（`get_all_inventories` → `try_place_item` → `change_inventory`）がそのまま効く。
  部位はその上の矩形で、`is_valid_placement` を包んで落とせるかを決める
- 装備欄の品は**プレイヤーの持ち物の辞書から抜いて**、装備欄の辞書（`sys` に置く。注入し直しても消えない）
  だけに持つ。本体は窓を開くたびに持ち物の辞書から品を並べ直すので、抜いておけば所持品にも売買・
  クラフト・強化の窓にも出ない。装備欄の品のウィジェットは窓を組んだ 0.1 秒後に MOD が作る（`build_items`）。
  セーブには、書き出す直前の JSON（`write_obfuscated_json_file` に渡る `player_data.inventory`）へ
  装備欄の品を `to_dict()` で足す。生きている持ち物の辞書には触らない
  （`equipments` の `weapon` / `wearable` は本体が id で書く）。ロード直後は品が辞書に居るので、窓を組む前に抜き直す
- 装備欄の品を右クリックで「捨てる」ときは、先に所持品へ戻してから本体に捨てさせる
  （本体は持ち物の辞書から消すので、無いと落ちる）。空きが無ければ捨てない
- 置換は本体の下見で行う。本体はドロップの前に `is_valid_placement` で置けるかを確かめ、
  通らなければ `try_place_item` を呼ばずに品を元へ戻す。その下見で「同じ種類の品が居る部位」なら
  居た品を所持品の空きへ出してから下見をやり直す
- どの品がどの位置に居るかは MOD の控え（`state\equipment_slots\<世界>.json`。
  `{主人公の名前: {品の鍵: [x, y]}}`。y は上から）
- 本体への書き込みは `equipments` の直書き（本体の popup も同じ）と、HUD の更新のための
  `ItemEquipManager.equip_item` / `ItemUnequipManager.unequip_item`
- 所持品の窓を開くたびに控えを持ち物と突き合わせる。
  持ち物に無い品（売った・渡した・捨てた）、部位と種類が合わない品、同じ部位の2つ目の品
  （部位の並びを変えた後の古い控え）は落とし、
  本体が装備しているのに控えに無い品（MOD を入れる前のセーブ）は空いている部位（手は右手が先）へ拾う
- 装備欄は本体の窓より**下**に描く（`FloatLayout` の子の並びで窓の直後に差す）。
  品のウィジェットは窓の `FloatLayout` に居たままなので、ドラッグ中も装備中も装備欄の上に見える。
  窓より下でも暗幕より上に来るのは、暗幕が窓とは別の子で、窓より先に描かれるため
- 窓を開いたときは装備が変わっていなくても本体の `equip_item` を1度通し、Atk/Def の表示を塗り直す
  （本体は装備を変えたときにしか塗り直さないので、売買のあとなどに前の値が残る）
- 右クリックの「装備」「外す」は `ItemPopupMenu` のメソッドを包み、本体の経路を通さず MOD が移す

#### 容量

装備欄は所持品とは別枠なので、持てる量は所持品 24 マス＋装備欄ぶん。
装備中の品は持ち物の辞書に居ないので、本体は所持品 24 マスだけを数え、装備欄が埋まっていても
所持品は満杯まで拾える。外す・置換で押し出す・捨てるは所持品に空きが要り、無ければ何もしない。

セーブには所持品と装備欄の品が全部 `inventory` に書かれる。ロード直後は全部が辞書に居るが、
所持品・売買・クラフト・強化のどの窓を組むときも、本体が並べる前に装備欄の品を抜くので
24 マスへ溢れることはない。

#### 既知の癖

- 窓を開いている間は右側の選択肢（「会話する」など）を隠して押せなくする。閉じると戻る

- 装備欄の品は強化（鍛冶）の窓に出ない。強化するときは一度外す
- 装備中の品は持ち物の辞書に居ないので、会話の GM に見せる所持品（`910_` など）にも出ない
- 所持品に空きが無いとき、断ったドロップの品はその場では戻せない。次に窓を開いたとき所持品へ返す

#### 外すとき

本体のセーブは素のままの形（装備欄の品はセーブの瞬間だけ持ち物へ合流する）。
ただし装備欄の品の `grid_pos` は装備欄の座標（6列×10行）で書かれるので、MOD を外して開くと
所持品の中で他の品と重なって置かれることがある。**MOD を外す前に装備欄を空にしてセーブ**しておけば、
所持品の位置で保存される。`state\equipment_slots\` を消せば控えは残らない。
装備中の品は持ち物の辞書に居ないので、セーブせずに MOD を外す（注入を剥がす）と、その品は
次にセーブされるまで持ち物に居ない。窓を開けば同じプロセスに残っている品を拾い直す（§3.3）。

#### 困ったとき

| 症状 | 見るところ |
|---|---|
| 装備欄が出ない | `out\equipment_slots.log` に `panel built` が無い。`WARN InventoryGrid class not found` か `panel failed`（例外）か、所持品のグリッドを見つけられていない |
| 装備欄が空のまま | `settled N of M items` の N が M より小さい。0.1秒（`SETTLE_DELAY`）では本体が並べ終えていない |
| 落としても所持品へ戻る | `drop ... -> ` の行に理由（`outside a region` / `wrong region` / `occupied` / `not equipment`） |
| 装備欄へそもそも落ちない（枠が反応しない） | `drop` の行も `try_place_item` の行も無ければ、本体が装備欄をグリッドとして見ていない |
| 装備したのに Atk/Def が変わらない | 同じ部位の中で最高値でない。`weapon -> ` / `wearable -> ` の行がその時点の選択 |
| 右クリックの「装備」で何も起きない | `popup equip ...` の行。`ignored` なら装備でない品か窓が閉じている |
| MOD を入れ直した後に挙動が変 | 古い世代の包みが残ることがある（§3.3）。`python tools\injector.py --unload` してから注入し直す |

2. 売買・受け渡し（`402_`）・クラフト・強化の窓を開いたとき、装備欄の品がそちらに出ないか

3. 1920x1080 での位置と大きさ（マスの大きさは所持品のグリッドから採る）
4. 装備欄の品を `402_` で仲間に渡した後、次に開いたとき控えから落ちるか
5. 装備欄の品を捨てる（右クリック「捨てる」）と、控えから落ちるか
6. 装備欄の品が所持品に一度並ぶことで所持品が満杯のとき何が起きるか（本体の `place_existing_item` の空き探し）

### 3.3 分かったこと（作りに効いた順）

- **品の実体を持つ辞書はプロセスに1つで、控え（位置）は世界ごと。** 別の世界をロードすると、前の世界の
  品が「控えに無いのに辞書に残っている品」として新しい世界の所持品へ返された（2026-09-10）。辞書に
  世界の鍵を添え、鍵が変わったら空にする。セーブへの合流も、書き出すセーブの世界名が辞書の世界と
  違えば行わない（`world_key_of_dict`）

- **右側の選択肢は `hud.right_buttons`（入れ物は `right_button_layout`）。** 左の `buttons` は本体が
  窓を開くとき `button_layout` を 0×0 に畳んで隠す。右は本体も `right_button_layout.opacity` を 0 に
  しているが、ボタン（枠は各ボタンの `canvas.after` の矩形）はそのまま描かれる。ボタンごとの
  `opacity` なら消える（16:32）。押せなくするのは入れ物の `disabled`（子の値を変えずに継承で効く）

- **本体の Manager はロード時に束縛した参照で呼ばれる。** `ItemEquipManager.execute` /
  `equip_item` をクラス属性で包んでも popup からの呼び出しには届かない
  （`223_` の包みだけが効いていたのは、`223_` がロード前の注入で当たっていたため）。
  右クリックは `ItemPopupMenu.on_equip_item` / `on_unequip_item`（右クリックのたびに作られる）で受ける
- **`Item.equip()` は `equipments` を書かない。** 書いているのは popup 側。`Manager.execute` は
  窓を閉じるので、HUD の更新には `equip_item` / `unequip_item` を直接呼ぶ
- **Manager はワーカースレッドで走る。** Kivy の描画を触る処理は `schedule` でメインスレッドへ
- **本体のドロップは `try_place_item` の可否に関わらず `change_inventory` まで進み、
  途中で Manager も通す。** 断るときは次のフレームで元へ置き直す。断った後の `equipments` に
  `healing_item` のような余計な鍵が残ることがあるので、`weapon` / `wearable` 以外は落とす
- **`place_existing_item` は `item.grid_pos = [x, 下から y]` で置く。** ウィジェットの座標は見ない。
  同じフレームで置くとマスの位置がまだ無い
- **`InventoryGrid` はマスだけを子に持つ `GridLayout`。** 品を子にすると `GridLayoutException`。
  品はグリッドの親（窓の `FloatLayout`）に置く
- **注入し直すと、今の版が包まなくなった対象に古い世代の包みが残る。**
  `equip_item` の包みをやめた後、古い包みの `after_change` が空の控えで `weapon -> None` を書いた。
  `--unload` してから注入し直す
- 品の説明窓（`ItemDetailBox`）は、カーソルの下から品が消えると閉じず残る。装備欄を片付けるときと
  品を移し終えたときに消す
- **本体はドロップの前に `is_valid_placement` で下見をする**（`on_touch_up`、new_hud.py:924）。
  通らなければ `try_place_item` を呼ばず、品を元へ戻す。だから「品が居る部位への置換」は
  `try_place_item` の包みでは間に合わず、下見の包みで居た品を先に出す
- **装備中の品を持ち物の辞書から抜くなら、その辞書は MOD のモジュールに置いてはいけない。**
  注入を剥がして戻すとモジュールが読み直され、品の参照ごと消える（実機で 4 品を失いかけた）。
  `sys` の属性に置き、念のため窓を開いたとき同じプロセスに残っている品（持ち主がプレイヤーで、
  どの辞書にも居ない `Item`）を1度だけ拾い直す
- 持ち物へ戻った品の `grid_pos` が装備欄の座標のままだと、本体の `place_existing_item` は確かめずに
  置くので他の品の下に隠れる（108_ と同じ）。窓を組む前に所持品の範囲で重なりとはみ出しを直す
- **本体は持ち物の辞書を回している最中にセーブを呼ぶ**（戦利品の窓を組む途中で `save_game`）。
  セーブのために生きている辞書へ足すと `dictionary changed size during iteration` で落ちる。
  合流は書き出す JSON の側で行う（`write_obfuscated_json_file` の `data['player_data']['inventory']`
  へ `Item.to_dict()` を足す。`__main__` へ複製された名前はローダの alias 再束縛が3つ張り替える）

### 3.4 決めた仕様（再検討しない）

- 合算しない。攻撃・防御ともに最高値の1つだけを本体へ渡す
- 右手・左手は武器と盾のみ。他の部位は表のとおり
- 装備欄は所持品とは別枠で品を持つ。ドラッグと右クリックの両方で装備できる
- 部位の大きさは所持品と同じマスで、頭・腕・脚・装飾は 2×2、手と胴は 2×4（武器は最大 1×4）。
  配置は当初案の図のとおり（頭が上中央、手と胴が縦長、腕・脚がその下の左と中央、装飾は右列の右手の下に2つ）。
  グリッドは 6×10。部位の外のマスは見せず、全体を所持品の窓と同じ外枠で囲む
- 部位より小さい品は縦横比を保った整数倍で部位いっぱいに広げて表示し、部位の左上に寄せる。
  占有するマスは品の本来の大きさのまま（受け入れの判定は部位単位なので見た目だけの話）
- 1つの部位に1つ。同じ種類の品を居る部位へ落とせば置換（居た品は所持品の空きへ。空きが無ければ置換しない）。
  右クリックの「装備」は空いている部位が無ければ右手（1つ目の装飾）と入れ替える
- 拡大表示は設定で切れる（`SCALE_TO_FIT`）
- 装備中の品は持ち物の辞書に居ない。合流はセーブの間だけ
- 装備欄の品は本体の窓の `FloatLayout` に置いたまま（移し替えない）。装備欄は窓より下に描く

## 4. ゲーム側の事実（`docs\GAME.md` 相当）

- 装備の種類は `attributes['item_detail']`（`weapon`: `small_weapon` / `medium_weapon` /
  `long_weapon` / `large_weapon` / `throwable`、`wearable`: `shield` / `clothing` /
  `body_armor` / `accessory` / `legwear` / `leg_armor` / `gauntlets` / `headgear`）。
  `Item` に `sub_type` の属性は無く、`ITEM_TYPE_SUBTYPES` の語彙がここに写っている
  （実セーブ 2026-09-08。`leg_armor` と `legwear` は両方 `Data\item_embeddings\` に在る）
- セーブの `equipments` は `{"wearable": "item_2", "weapon": "item_0"}` の形（id 文字列）。
  実行時は `Item` オブジェクト。書いているのは `ItemPopupMenu` 側で、`Item.equip()` は書かない
- `ItemEquipManager` / `ItemUnequipManager` はロード時に1度だけ作られ（`223_` の記録: `__init__` が
  ロード直後）、`execute` はそのとき束縛した参照で呼ばれる。`execute` はワーカースレッドで走り、
  所持品の窓を閉じる。`equip_item` / `unequip_item` が HUD の Atk/Def を更新する
- `InventoryGrid(cols, rows, item_dict, obtainer, ...)` はマス（`InventorySlot`）だけを子に持つ
  `GridLayout`。品（`InventoryItem`）はグリッドの親（窓の `FloatLayout`）に置かれ、
  `item_dict` からは並べない（並べるのは HUD の toggle）
- `InventoryGrid.place_existing_item(widget)` は `widget.item_instance.grid_pos = [x, 下から y]` の
  位置に置く。`is_valid_placement(grid_x, grid_y, w, h)` の `grid_y` も下から。
  `current_slots` の添字は `grid_y * cols + grid_x`。マス 64px + 隙間 1px
- `InventoryItem.on_touch_up`: まず落とす先のグリッドで `is_valid_placement` の下見（new_hud.py:924）、
  通れば `target.try_place_item(self, pos)`（:961）→ 可否に関わらず `self.change_inventory(target)`（:962）。
  途中で `ItemUnequipManager.unequip_item` と `ItemEquipManager.equip_item` を通す。
  `change_inventory` は移動元の `item_dict` から鍵を消し、移動先へ入れる（元に無ければ KeyError）。
  下見で落ちたときは本体が品を元の位置へ戻す
- `InventoryItem.get_all_inventories()` は HUD の `FloatLayout` の中の `InventoryGrid` を全部拾う
  （MOD が足したものも）
- `Manager.execute` を包んでも、popup からの呼び出しは届かない（上記のとおり束縛済みの参照）
