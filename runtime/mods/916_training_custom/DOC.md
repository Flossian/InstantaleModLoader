## 1. 遊び方（`docs\MODS.md` 相当）

### `916_training_custom`: 訓練所の代金・修行の量・1段の期間・再訓練の可否を変える

訓練所は、代金が 300G で固定、1回の修行が3年、
修行内容を1つ選ぶと **その年数ぶんの暦が一度に進む**（1年＝365日）。
`新たな技を学ぶ(3年)` を選べば 1095 日、`ただ鍛える(1年)` でも 365 日。
主人公は3年ぶん歳を取り、世界の側も3年ぶん進む。
この MOD はその3つを設定から変えられるようにする。

**既定値はすべて素のゲームの値**（300G・3年・ベース期間1年で 1/2/2/3 倍）で、
そのままならこの MOD は挙動を何も変えない。
設定を素の値から動かした項目だけが効く。

### 1段の期間は「ベース期間 × 倍率」

ベース期間はいちばん短い修行（`ただ鍛える`）1回で進む暦で、
`1ヵ月 / 2ヵ月 / 3ヵ月 / 6ヵ月 / 1年` から選ぶ。
他の修行はその倍率で決まり、倍率は修行内容ごとに変えられる。
既定の倍率（1/2/2/3）は素のゲームの年数そのものなので、
ベース期間が「1年」のままなら1日もずれない。

```text
[素のゲーム＝ベース1年]   ただ鍛える(1年)   基礎を積む(2年)   技を磨く(2年)   新たな技を学ぶ(3年)
                          365日             730日             730日           1095日
[ベース1ヵ月]             ただ鍛える(1ヵ月) 基礎を積む(2ヵ月) 技を磨く(2ヵ月) 新たな技を学ぶ(3ヵ月)
                          30日              60日              60日            90日
[ベース3ヵ月]             3ヵ月             6ヵ月             6ヵ月           9ヵ月
[ベース1ヵ月・ただ鍛える6倍] ただ鍛える(6ヵ月)                  他は 2/2/3ヵ月のまま
```

ボタンには**実際に進む期間**が出るので、表示と実態は食い違わない
（`314_area_move_custom` と同じ約束）。
素の設定ではその文字列がゲームの表示（`ただ鍛える(1年)`）と一致するため、既定のままなら1文字も変わらない。

### ゲームが数える「年数」には触っていない

修行内容を選ぶたびに減る年数（1年/2年/2年/3年）は
**ゲームの内側で決まっていて、引数にも出てこない**。
残り年数に収まる修行だけを並べる判定も同じ場所に在る。
だからこの MOD はそこを触らず、暦のほうだけを変える。

結果として、**1回の修行で受けられる段数は倍率を変えても変わらない**。
`新たな技を学ぶ` を1倍にしても、ゲームは3年ぶん使った扱いにするのでその場で卒業する。

### 文言の「N年間」も実際の期間になる

ゲームは残りの量も1段の結果も年で言う。
そのままだとベース期間を縮めたとき、暦は縮むのに文言だけが年で残る。

```text
[ゲームの言い方]              [ベース1ヵ月のとき]
あと3年間。どうする？         あと3ヵ月。どうする？
一年間、ひたすら鍛錬した。    1ヵ月、ひたすら鍛錬した。
残り2年間。どうする？         残り2ヵ月。どうする？
```

直すのは**訓練の窓の間に出る文言だけ**で、それ以外の場面の文言には触らない。
素の設定では直した先が同じ文字列になるので1文字も変わらない。
切りたいときは設定の「文言の「N年間」も実際の期間に直す」をOFFにする
（そのときは暦だけが縮んで、文言はゲームの言い方のまま残る）。

`あと3年間` の3はゲームが数える修行の量なので、暦に直すと幅が出ることがある。
倍率を素の比（1/2/2/3）から変えていると、
残り3年を「3年の修行1回」で埋めるか「1年の修行3回」で埋めるかで長さが変わるためで、
そのときは `あと3ヵ月〜18ヵ月。どうする？` のように最短と最長を出す。
倍率が素の比のままなら1つの長さになる。

**AIが書いた文そのものには触らない。**
`これからの三年間、私が責任を持って…` のような文も年で言うが、
あちらは漢数字で文の途中に出るうえ、指しているのが1段ではなく修行全体なので、
段の長さで書き換えると数が嘘になる（実測の4文で確認した。§3）。
直すのは**AIに渡す前の頼み文のほう**（次の節）。

### 卒業した施設でもう一度訓練を受ける

素のゲームは、一度卒業した施設では2回目を断る
（`十分に学んだ。これ以上ここで得るものはないだろう。` 代金も日数も動かない）。

断っている根は、施設に立つ**訓練済みの印**（`config["trained"]`）。
卒業した道場の控え（`state\modfacility\<世界×主人公>.json`）に
`snapshot.config.trained = True` が立っていた（実測 2026-09-16。
`savedata.json` の側には同じ名前の項目が無く、施設そのものが持っている）。

「卒業した施設でも再訓練できる」をONにすると、**その印をキーごと落とすだけ**。
`False` を入れるのでは足りない ― 実機で断られ続けた（2026-09-16）。
一度も卒業していない道場（同じ世界の `天流院`）の config には**キー自体が無い**ので、
ゲームが見ているのは値ではなくキーの有無と読める。未訓練の施設と同じ姿にする。

```text
[素のゲーム]  訓練を受ける(300G) → 十分に学んだ。これ以上ここで得るものはないだろう。
[ON]          訓練を受ける(300G) → （印が立っていないので）いつもどおり訓練が始まる
```

印さえ立っていなければ、ゲームは卒業していない施設とまったく同じ道を通る。
代金も支度（主の絵と背景）も選択肢も文言も、全部ゲームのまま。
この MOD がやるのは押した時点で印を落とすことと、
卒業でまた立った印を次の回までに落とすことの2つだけ。
施設が読めないときは黙って諦めず、`out\training_custom.log` に WARN を残す。

> 版5〜7 は、断られた回を引き取って修行の選択肢を自分で組んでいた。
> 引数の形が実測どおりでも支度が飛ぶので背景の出ない画面になり（実機 2026-09-16）、
> 断りの文言を伏せる・払い戻すといった後始末も要った。
> 印を落とす側に寄せて、それらは全部やめた（本人の指摘）。
> 版8 は印に `False` を入れていたが実機で断られ、版9 でキーごと落とす形にした。

### AI に渡す頼み文の年数も直す

ゲームは頼み文にも年数を焼き込む。
実機1回目では画面が `あと3ヵ月` になっても師範のセリフだけが「三年間」と言い続けた。
元は頼み文のこの4か所（実測。`output_data\<世界>\<PC>\training_conversation_starter\N.json` ほか）。

```text
- 残り訓練年数: 3年                      →  - 残り訓練期間: 3ヵ月
…これは費用と3年の時間を費やす代わりに…  →  …費用と3ヵ月の時間を費やす…
- 入学の希望を受けた場合: 3年間を費やし…  →  …: 3ヵ月を費やし…
新たな技の会得に3年を費やした...          →  新たな技の会得に3ヵ月を費やした...
```

**錨は訓練の頼み文にしか無い言い回しに打ってある。**
素の `N年` に当てると、同じ頼み文に載っている
`…は指導者レオンのもとで3年間の過酷な基礎訓練を終え`（人生ログ。訓練の後に書かれ、
以後あらゆる頼み文へ運ばれる）や
`この土地に合計2年暮らしている`（土地との縁）まで書き換えてしまう。
どちらも**過去の記録**なので、後から期間を書き換えるのは嘘になる。
`out\training_custom.log` に `prompt at <経路>` として残り、
訓練の頼み文なのに1つも当たらなかったときは `kept as is` にその一節が出る。

| 設定 | 意味 |
| --- | --- |
| 訓練の代金 | 既定 300G（素の値。施設によらず固定）。300のままなら触らない。0でタダ。手持ちが足りないと押した時点で「（訓練の代金◯Gに足りない…）」と断る |
| 1回の修行で受けられる量（年） | 既定3年（素の値）。修行内容を1つ選ぶたびにゲームが数える年数が引かれ、0で卒業。増やすと1回の代金で何段も受けられる |
| 1段のベース期間 | 既定「1年」（素の値＝365日）。`1ヵ月 / 2ヵ月 / 3ヵ月 / 6ヵ月 / 1年` から選ぶ |
| 修行内容ごとの倍率 ×4 | 既定 1 / 2 / 2 / 3（素の年数と同じ）。ベース期間の何倍か |
| 訓練を受けるボタンの表示 | 既定 `{name}({price}G)`。代金を変えたときだけこの形で表示し直す |
| 修行内容のボタンの表示 | 既定 `{name}({length})`。`{length}` は実際に進む期間（`3ヵ月` `2年`）。`{days}` `{factor}` `{base}` も使える |
| 卒業した施設でも再訓練できる | 既定 OFF（素のゲームは断る）。ONだと施設の訓練済みの印（`config["trained"]`）をたたむので、卒業していない施設と同じように訓練が始まる |
| 文言の「N年間」も実際の期間に直す | 既定 ON。訓練中に出る `あと3年間` `一年間、ひたすら鍛錬した。` を実際の期間に直す。素の設定では1文字も変わらない |
| AI に渡す頼み文の年数も直す | 既定 ON。頼み文の `残り訓練年数: 3年` などを実際の期間に直す。切ると師範のセリフだけが年で語り続ける。人生ログと土地との縁（過去の記録）は触らない |
| 代金に足りないときの一言 | 既定 `（訓練の代金{price}Gに足りない ― 手持ち{gold}G）` |

設定は2段ある（`314_` / `130_` と同じ形）。
mod.json の設定が全ワールド共通の一括設定で、
ローダの設定画面の「ワールド別の訓練所設定」を開くとワールドごとに上書きできる。
その世界だけ訓練所を安くする、その世界だけ修行を短くする、といった使い方ができる。
個別の控えは `state\training_custom\<世界名>.json` に、
一括設定と違う項目だけが入る（全部同じならファイルは消える）。

> 修行内容の見分けはゲーム内部の種類の名前（`simple` / `fundamental` / `train_skill` /
> `learn_new_skill`。実機で観測した値）で行う。
> ゲームの更新でその語彙が変わったビルドでは、
> **ゲーム自身が言っている年数**（ボタンの `(N年)` と `elapse_days` に来た日数 ÷ 365）を
> 倍率の代わりに使うので、ベース期間の設定はそのまま効く。
>
> 卒業した施設の2回目は、素のゲームでは断られる
> （「十分に学んだ。これ以上ここで得るものはないだろう。」代金も日数も動かない）。
> 設定で受けられるようにできる（次の節）。

### 他の MOD への窓口

訓練の暦を、ローダの窓口 `durations`（TECH.md §3.3.2）に置いている。
窓口は「1段の日数 ＝ 活動の年数 × 1年の日数」の形で持つので、
ベース期間を `days_per_year` に、倍率を `activity_years` に入れている（掛け算の形が同じ）。
訓練の長さに合わせたい MOD はそこに聞く。
この MOD は誰が聞くかを知らないし、この MOD を外せば窓口の答えも素のゲームの式に戻る。

日数を当てる側もローダの関所（日数送りは1枚だけが包む）に望みを出す形なので、
同じ日数送りに別の MOD が絡んでも、決めるのはローダの1か所になる。

## 3. 検証の記録（`docs\VERIFICATION.md` §3 相当）

### 訓練所の代金・修行の量・1段の期間・再訓練（`916_`）: 実機4回で成立（2026-09-16、版10）

`231_probe_training` で録れた訓練の暦（GAME.md §2.17）に当てる MOD。
代金と1回の修行の年数は `TrainingStartManager.__init__` の引数を差し替え、
1段の期間（ベース期間 × 倍率）はローダの関所（TECH.md §3.3.3）へ望みを出す。
ゲームが数える年数（残り年数の減り方と、残り年数に収まる修行だけを並べる判定）は
ゲームの内側に在って引数に出てこないので触っていない。

> 版1 は「1年で進む日数」を直接の設定にしていた。
> 暦は同じように縮むが、**1年が30日になる**ので画面の年数と暦の意味がずれる。
> 版2 で「1段のベース期間 × 修行内容ごとの倍率」に作り直し、
> ボタンにも実際の期間（`ただ鍛える(1ヵ月)`）を出すようにした（本人の指定、2026-09-15）。
> 版3 で、ゲームが年で言う文言（`あと3年間` `一年間、ひたすら鍛錬した。`）も
> 実際の期間に直すようにした（同日の指定）。
> 直す対象は**実測の4文**で切り分けている。
> 算用数字の `N年間` は残りの量、行頭の漢数字の `N年間` は1段の結果、
> 文の途中の漢数字はAIの描写なので触らない。
> 版4 で、**AIに渡す頼み文**の年数も直すようにした（実機1回目の指摘）。
> 版5 で、卒業した施設での再訓練を設定で選べるようにした（実機1回目の指摘。既定は素のまま断る）。
> 版6 で、言い訳の一言（`だが、頭を下げて…`）をやめ、
> **ゲームの断りの文言ごと伏せる**形にした（同日の指定）。
> 版7 で、選択肢を自分で組むのをやめ、ゲーム自身の `training_start()` を呼ぶ形にした。
> 版8 で、その呼び直しもやめて**訓練済みの印（`config["trained"]`）をたたむだけ**にした
> （同日の指摘）。断りの根が見つかったので、引き取る・伏せる・払い戻すが全部要らなくなった。
> 断っているのは `TrainingStartManager` で段には渡っていないので、
> 断られた回を引き取って選択肢を組み直し、**ゲーム自身の段**へ繋いでいる。
> 段のほうも卒業を見ているビルドかどうかは未計測なので、
> そのときは代金を返して WARN を残す形にしてある。
