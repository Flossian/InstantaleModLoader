場所BGMの優先順位

324_place_bgm が「どの設定の曲を鳴らすか」を決める仕組み。ワールド個別設定と一括設定は混ざらず、勝った段だけが使われる。

ワールド個別設定（worlds\<世界>.json） 一括設定（playlist.json） 素の曲（セーブの bgm）

1. 決め方の梯子

いま居る場所から上の段へ順に見る。 使う曲が1曲でもある最初の段で止まり、その段の重みだけで抽選する。 使う曲が無い段（0曲・重みが全部0・曲がディスクに無い）は素通りして下へ落ちる。

2. なぜこの順か（2つの軸の積）

軸は2つあり、強さが違う。 場所の軸（施設が土地より先）が強く、指定の軸（個別が一括より先）は同じ場所の中でだけ効く。 だから「狭い範囲が常に勝つ」のではなく、施設の列を上から使い切ってから土地の列へ移る。

3. 実例: 宿屋を一括設定して、この街だけ個別設定したとき

一括設定の「宿屋」に曲を入れ、ワールド個別設定でこの街（土地 id 7）の曲を決めてある。 ギルドには何も入れていない。 この街を歩くと、勝つ段はこう切り替わる。

この街でも宿の中を街の曲で通したいなら、ワールド個別設定でその宿に曲を入れる（段1になり、宿屋の一括設定より先に見る）。 他の街では、通りは一括設定の「町」（無ければ素の曲）、宿は同じ宿屋の曲が鳴る。

4. 細則

段が「ある」の条件使う曲が1曲以上（重みが正で、曲がディスクに実在する）。指定が在っても曲が消えていれば素通り
混ざるか混ざらない。勝った段の重みだけで抽選し、下の段の曲は候補に入らない
覚えた曲（chosen）段ごとに別。段4で覚えた曲は、後から段3の指定を足すと使われず、段3で選び直して覚え直す
実機での確かめ方ログ out\place_bgm.log の各行に勝った段が出る（<- world:facility:7/106 / <- facility:inn / <- world:area:7 / <- area:town）

出典: 910_place_bgm の place_bgm.py（level_keys / resolve）と DOC.md §1「どの曲が鳴るか」。
