## 1. 遊び方（`docs\MODS.md` 相当）

### `914_real_estate`: 役場で物件を借りて自分の拠点を持つ

素のゲームで腰を落ち着けられる場所は宿屋だけで、泊まるたびに宿代と30日を払い直す。
荷物を置く場所も無く、24マスが埋まったら捨てるしかない。

この MOD は役場（役場の選択肢）に不動産の窓口を1つ足す。

```text
[役場]  労働の募集をみる / 市民権の発行 / 物件を扱う / 出る
                                ↓
        借りる(1,600G・480日) / 建売を買い取る(30,000G) / やめる
                                ↓
        その街の入口に建物が1軒増える

[入口]  中央居住区 / 外縁スラム / 借りている家 ←これ / 街を出る
                                ↓
[家]    滞在する / 保管庫をあける / 家から出る
```

建物はその土地の入口に繋ぐ。
街に着いて最初に立つのが入口で、区画（`ward`）はその先にある。
自分の家は区画の奥ではなく、着いてすぐ入れる場所に置いてある。

物件は土地ごとに1軒。
別の街の役場へ行けば、その街にもう1軒持てる。

### 建物の中でできること

| | |
| --- | --- |
| 滞在する | 宿屋の宿泊とまったく同じ経路。休養・訓練・労働・物乞いから1つを選ぶ。宿代は取られない。暦は宿屋と同じく30日進む（賃貸なら、その30日ぶんの家賃は引かれる） |
| 保管庫をあける | 仲間へアイテムを渡すときと同じ2枚並びの窓が開く。左が自分、右がこの保管庫。ドラッグでどちらの向きにも移せて、移した時点で保存される |
| 家から出る | 入口へ戻る。ゲームは自分で足した施設の出口を作らないので、この1つも MOD が出している（§3.2） |

宿屋の活動のうち2つは自分の家では出ない（宿屋の側はそのまま）。

| 出さない活動 | 理由 |
| --- | --- |
| 他者と交流 | 誰と会うかを決めるのはゲームで、自分の家では大家（物件を貸した役場の役人）が相手になる。その場面は通らない |
| アイテム作成 | 自分の家ではまだ成り立っていない |

1回の滞在でできる活動は1つ（素のゲームの宿泊と同じ「1泊＝活動1回」）。
活動を1つ終えるとその滞在は終わり、建物の選択肢に戻る。
もう一度過ごしたければ「滞在する」を押し直せばよい（宿代は取られず、暦だけ進む）。

> `327_inn_quality` は宿屋で部屋の等級に応じて活動の数を増やすが、
> 自分の家では増えない。ここは等級によらず1回に固定してある。

滞在の部屋の等級は設定で決める（既定は個室）。
効くのは描写と、家の中の背景（部屋の絵をその等級で借りている）と、等級を読む MOD（活動の数以外）。

### 保管庫は建物ごと／世界で1つ、どちらにもできる

既定は建物ごと。
その家に預けた品は、その家でしか出し入れできない。

設定の「保管庫を世界で1つにする」を入れると、どの物件からも同じ中身が開く。
街から街へ荷物を持ち回らずに済む形で、離れた土地の家に預けた品もその場で取り出せる。

切り替えたときの中身は次のように動く。

| 切り替え | 預けてあった品 |
| --- | --- |
| 建物ごと → 世界で1つ | 次に保管庫を開いたとき、各建物の中身が共有の側へ移る（1度だけ。ログに `moved N item(s)` が出る） |
| 世界で1つ → 建物ごと | 共有の側に残る。どの建物へ返すか決められないので動かさない。設定を戻せばまた同じ中身が見える |

契約が切れたときの扱いも少し違う。
建物ごとなら、その家の保管庫が役場の預かりになる。
世界で1つのときは、ほかに物件が残っているあいだは取り上げない（別の家から同じ中身を開けるため）。
最後の1軒を失ったときだけ、開く手段が無くなるので役場へ移る。

### 家賃と期限

賃貸の1期は、宿泊4回ぶんの日数。
1期を1回ぶんにすると、家を借りても宿に泊まり直すのと変わらないので、
既定は4回ぶんをまとめて借りる形にしてある。
その間は何度でも戻って過ごせて、家賃は1度きり。

宿泊1回の長さはゲームの宿屋と同じで、自分の家の滞在もその長さで起きる。
素のゲームは3ヵ月から年齢で伸びる変動式（30代 +1・40代 +2・50代以上 +3、上限6ヵ月）。
`315_vacation_custom` で宿泊期間を変えていれば、そちらが効く。
この MOD は自分では決めず、宿屋で実際に使われた月数を覚えて使う。
まだ宿屋に泊まっていない世界では年齢から見積もる。

```text
31歳・素のゲーム    宿泊4ヵ月＝120日 → 1期 480日
315 で1ヵ月に変更   宿泊30日        → 1期 120日
```

契約の周期は、結んだ時点の長さで固定する。
年を取って宿泊が伸びても、いま借りている契約の期限は動かない。

引かれるのは日数が進んだとき（移動・宿泊・依頼）で、何期ぶんか飛んだ場合はまとめて払う。

期限が近づくと1行出る。

```text
借りている家の契約はあと5日で切れる。
```

所持金が足りない日が来ると契約は切れる。
建物は街から消え、保管庫にあった品は役場が預かる。
預かった品は、どこの役場でも引き取り料（既定 2,000G）を払えば戻る。

建売（買い取り）には家賃も期限も無い。

自分から引き払うときは、窓口の「解約する」。
このときも保管庫の中身は役場の預かりになるので、先に引き取ってから解約するほうが安い。

### 建物はセーブに残らない

足しているのは遊んでいる最中の街だけで、世界のファイルにもセーブにも施設は書かない。
ロードのたびに建て直していて、MOD を外せば街は素のままに戻る。
建物も、そこへ繋がる道も残らない。

控えは2つに分かれている。

| ファイル | 中身 |
| --- | --- |
| `state\real_estate\<世界名>.json` | 契約（いつまで・いくら）と保管庫の中身、役場の預かり |
| `state\modfacility\<世界名>.json` | 建物そのもの（名前・説明・どの土地のどこに建っているか） |

建物のほうはローダが持っている（この MOD だけのものではない）。

保管庫の中身は契約と同じ控えの中にある。
預けた品はプレイヤーの持ち物から外れるので、預けた時点でゲーム自身の保存が走る。

> MOD を外すと、控えは残るが建物は建たない。
> 保管庫に預けたままの品はその控えの中に居るので、入れ直せば戻る。

| 設定 | 意味 |
| --- | --- |
| 家賃 | 既定 1,600。1期ぶん |
| 賃貸の1期＝滞在何回ぶん | 既定 4。宿泊1回の長さは宿屋と同じ（素は3ヵ月から年齢で伸び、315 を入れていればその設定） |
| 建売の価格 | 既定 30,000。買い切りで、以後の家賃も期限も無い |
| 家賃を自動で払う | 既定 ON。切ると、期限が来た時点で必ず契約が切れる |
| 期限を知らせる日数 | 既定 7。0 で知らせない |
| 預かり品の引き取り料 | 既定 2,000 |
| 保管庫を世界で1つにする | 既定 OFF＝建物ごと。ON にすると、どの物件からも同じ中身が開く |
| 滞在の部屋の等級 | 既定 個室（`private_room`）。ゲームの宿屋と同じ語彙（長さは宿屋と同じなので設定は無い） |
| 借りた物件の名前 / 買った物件の名前 | 街の中に並ぶときの名前 |

### 世界ごとに分かれている

契約も、保管庫も、役場の預かりも、**世界ごとに別**。
控えのファイルが世界ごとに1つできる（`state\real_estate\<世界名>.json`）。

| もの | 分かれ方 |
| --- | --- |
| 契約（どの土地に何を借りたか） | 世界ごと |
| 保管庫の中身 | 世界ごと。「世界で1つ」の設定も、その世界の中で1つ |
| 役場の預かり品 | 世界ごと |
| 覚えた宿泊期間 | 世界ごと |
| 建物 | その世界を遊んでいる間だけ建つ。別の世界を読むと消える |

見分けているのは**セーブの世界名**（`world_data.name`）。
だから外部のツールで世界名を書き換えると、その世界の控えは引けなくなる
（ファイルは残るので、名前を戻せば戻る）。
同じ名前の世界を2つ作った場合も、同じ控えを共有する。

| 症状 | 見るところ |
| --- | --- |
| 役場に「物件を扱う」が出ない | 会話・戦闘・買い物の最中は出さない。それ以外で出ないときは `out\real_estate.log` に `office` の行があるか |

| 滞在を押すと「…」のまま戻らない | ログの `WARN stay: the game's stay failed:` の行。ゲームの宿泊が落ちた記録で、例外の種類とそのときの建物の姿が出る。この場合でも宿代は返り、操作は戻るはず（戻らなければその行を添えて報告してほしい） |
| 保管庫が開かない | `WARN storage:` の行。`cannot build the holder` なら、試した3通りの失敗が並んでいる（ゲームの更新で持ち主の作り方が変わった合図）。`the holder has no inventory dict` は持ち物の持ち方が変わった合図 |
| 預けた品が次に遊んだら消えた | ログの `storage sync` と `save_game complete` が並んでいるか。控えは `state\real_estate\<世界名>.json` の `contracts[].storage`（世界で1つの設定なら根の `shared`） |
| 家賃が引かれない | 同じログの `rent:` の行。日数が進んでいない（移動も宿泊もしていない）と引かれない |
| 契約をやり直したい | `state\real_estate\<世界名>.json` を消す。建物はロードし直すと消える（保管庫の中身も一緒に消えるので、先に取り出しておくこと） |

## 3. 検証の記録（`docs\VERIFICATION.md` §3 相当）

### 3.1 設計の根拠（実セーブ・リコン成果物、2026-09-11）

施設の形は実セーブ7本の全施設を数えて決めた。
足す `location` の素データは実データの `location` と同じ8項目・同じ並びにしてある。

| `facility_type` | `tier` | `config` |
| --- | --- | --- |
| `location`（77件） | 全件 `null` | `level_of_detail` だけ |
| `ward`（120件） | 全件 `null` | 同じ |
| `entrance` / `exit`（各51件） | 項目そのものが無い | 同じ |

街の形も同じ数え方で確かめた。
実データの街は `entrance` から `ward` へ入り、宿・ギルド・役場・自由生成施設はすべてその `ward` から枝分かれしている。
建物を繋ぐ先はノード自身が名乗っている入口（`Node.entrance_facility`）で、引けなければ種類（`entrance` → `ward`）で探す。

組み立ては `__main__:Facility.__init__(self, app, parent_node, facility_data)`（`out\recon\targets.txt`）。
施設 id は版19 まで `ids.claim(app, "facility")` で採っていた（`index['facility']` を進める。GAME.md §2.23 の事故と同じ理由）。
版20 からはローダの名前空間（`mod:914_real_estate:<土地 id>`）で、台帳を進めない（§3.5）。

移動のボタンは `MovePhaseManager(app, connected_node_id, facility_move_to_id, area_id)` で、
引数の並びは実測した「出る」のボタンと同じ（GAME.md §2.2）。

滞在は `VacationStartManager(app, months, quality)`（GAME.md §2.17 の実測）。
宿代の引き落としは `execute` の中で1回だけ起きるので、前後の所持金の差から返す
（同じ `execute` の中で暦も進むため、そこで引かれた家賃は差から除く。§3.2）。

保管庫は `toggle_twin_inventory_window(左, 右, 左の見出し, 場面名)` を
ゲームに無い場面名（`real_estate_storage`）で借りる（`402_` と同じ借り方）。
右側に立てるのはその窓の間だけ生きる `Character` で、世界の名簿にも
セーブにも登録しない。移動の同期（`inventory` の辞書・`Item.id` / `obtainer`・
装備の解除）は本体がしないので、こちらで揃える。

自前のボタンは（一覧の保険で足す「建物への道」も含めて）無害な既存クラスを spec に持たせ、
押下は印で横取りしてから本物のマネージャを組む。
`MovePhaseManager` を spec に書くと、そのボタンがセーブに焼かれた後、
MOD を外した環境で押せてしまう（そのときは建物がもう無い。GAME.md §2.2）。

### 3.2 実機で分かったこと（2026-09-11）

ゲームは実行時に足した施設の `connections` を読まない。
契約して建てた家は素データ（`world_dict` / `save_data_dict`）に無いので、
ゲームが組む移動の一覧には繋ぎ先の側にも、建物の中にも現れなかった。

```text
built: '借りている家' id=313 in area '5' node '8' off hub '黄金の回廊'(52)
WARN hub: the game did not list '借りている家'; added the move button myself (args=['8', '313', '5'])
enter: '借りている家' via ['8', '313', '5']      ← 入れた。そこで選択肢が0個
```

入ること自体はできた（`MovePhaseManager` は実行時のノードから引けている）。
落ちてもいない（`crash_log.txt` に当日の記録なし）。
出なかったのは選択肢だけで、GAME.md §2.28 の
「遊んでいる最中に生まれた施設で売買を選ぶと `KeyError`」と同じ側面と読める
（ゲームは施設を素データから引き直す）。

1回目の直し（版2）。

| 症状 | 直し |
| --- | --- |
| 家が区画（`ward`）の下に建ち、役場の奥にあるように見えた | 繋ぎ先を入口（`Node.entrance_facility`）にした。既に建っている家は次の当て直しで入口へ移る（`rehomed:` の行） |
| 建物の中に選択肢が1つも出ず、出ることもできない | 建物の中では「施設の画面か」を問わずこちらで出す。ゲームの移動のボタンが1つも無ければ出口（`家から出る`）も足す |

居場所の読み取りが外れていた場合に備えて、押した移動の控えも併用する（`inside_home`）。
どちらで判定したかは `where:` の行に出る。

#### 宿泊には主が要る（2回目、同日）

建物の中の3つは出て、押せた。
そこで「滞在する」を押すと、ゲームの宿泊の本体が落ちて画面が「…」のまま戻らなくなった。

背景・暦・宿代・「1ヵ月泊まることにした。」までは通っている。
落ちたのはその後で、キーが `None` ＝ 主のいない施設（`owner` が `null`）を名簿で引いた形。
宿屋にはいつも主が居るので、素のゲームでは起きない。

直しは2つ。

| | |
| --- | --- |
| 主を据える | 滞在のあいだだけ `facility.owner` にプレイヤー（世界の名簿に居る id）を据え、終わったら元へ戻す。自分の家の主は自分なので、意味としても通る。名簿にプレイヤーが居ない世界のために、その建物・その土地の住人へ順に落ちる |

同時に、宿代の返し方も直した。
暦が進むのは宿泊の `execute` の中なので、そこで家賃も引かれる（実測の 1,100 ＝ 宿代 100 + 家賃 1,000）。
前後の差をそのまま返すと家賃まで返ってしまうため、こちらが引いた家賃は返す額から除く。

滞在の最中は自前のボタンを足さない（並んでいるのはゲームの活動の選択肢で、
そこへ「滞在する」を足すと同じ画面から滞在が二重に始まる）。

#### 保管庫の持ち主は既定では組めない（3回目、同日）

「保管庫をあける」を押しても窓が開かず、ログに1行だけ出ていた。

`Character(...)` は全引数に既定値があるのに、既定のままでは組めない。
`original_ability_scores` を添字で読むためで、GAME.md §2.23 に同じ記録がある
（`generate_character` 側は `KeyError: 'constitution'`）。

直しは、6つの鍵（`strength` / `dexterity` / `constitution` / `intelligence` /
`wisdom` / `charisma`）を持った辞書を渡すこと。
値は `null` でよいはずだが、値まで要る版に備えて数を入れた形も順に試し、

#### 窓はメインスレッドから開く（4回目、同日）

持ち主が組めるようになった後、「保管庫をあける」を押すと今度は入力を受け付けなくなった。

そこから Kivy の描画に触ると、この例外で窓が半端に開いたまま固まる。

検査では、偽の Clock に「いま Clock の中か」の旗を持たせ、窓が開いた瞬間の値を控える。
`screen.schedule` を外すと落ちることを確かめてある（`[False]`）。

#### 1泊＝活動1回に固定（5回目、同日）

滞在が通り、活動（休養・訓練・労働・社交・物乞い）まで届いた。

#### 背景は自分で描く（6回目、同日）

渡す等級は滞在で使うものと同じなので、泊まったときと同じ部屋になる。

手当ては2段。

| | |
| --- | --- |
| ゲームが背景を決める瞬間に差し替える | 上の2つを包み、行き先が自分の建物なら部屋の絵にして `orig` を呼ばない |
| それでも描かれていなければ自分で描く | 建物に立っていて、その場所に来てからまだ描いていなければ1度だけ描く。ゲームが背景を決める経路は1つとは限らないので、包みだけに頼らない |

##### 2つの手が両方描いていた（7回目、同日）

| 予約が走る瞬間 | 待っているあいだにゲームの経路が描いていたら、そこで降りる |

#### 中に居るあいだに期限が切れると、家から出られなくなった（13回目、同日）

家賃を払えない額（週ぎめ 5,000,000円）にして借り、家に入って滞在したときのログ。

```text
21:58:26.678 stay: starting VacationStartManager months=1 quality='private_room'
21:58:26.699 demolished: id=316 in area '6'      ← 中に居るのに壊した
21:58:26.701 lapsed: '借りている家' in area '6' (seized 0)
21:58:28.129 where: area=6 facility=316 type=location inside=False game_choices=4
```

`the player is inside ...; the demolition waits` が出ていない。
取り壊しを待つ仕掛けは動いていたのに、中に居ることが読めていなかった。

`lapse` は先に `record["lapsed"] = True` を立ててから取り壊しを呼ぶ。
その判定に使っていた `inside_home` は、切れた契約では必ず False を返す
（自分の家として扱ってよいか、を見る関数だった）。
つまり切れた瞬間だけ、中に居ても居ないと読める。
`release`（自分から解約する側）が同じ形で無事だったのは、
印を立てるのが取り壊しの後だったため。

「立っているか」（`standing_in`）と「自分の家か」（`inside_home`）を分けた。
取り壊しの判定は前者、滞在と保管庫は後者。
契約が切れて取り壊しを待つ建物の中では、出口だけを出す。

もう一段、取り残された状態そのものから戻る道も持たせた。
街から引けない施設に立っているなら、その土地の入口へ出る選択肢を出す
（`stranded`。`WARN stranded:` の行が残る）。
このときの画面には選択肢が4つ残っていたが、そこから街へは戻れなかったので、
残っている選択肢の有無では判断しない。

#### 消えた建物に立ったまま保存され、その世界が開けなくなった（14回目、同日）

版13 で取り壊しは直したが、その前に保存されていたセーブが残っていた。
世界を選んだ時点でゲーム自身が落ちる。

```text

AttributeError: 'str' object has no attribute 'name'
  instantale.py:1493 in InstantaleApp.load_game_new
```

ゲームは引けなかった施設に `'facilityが見つからない'` という文字列を入れ、
その後でその文字列の `.name` を読む。
セーブに残るのは施設の id だけなので、
ロードで建て直されない建物の id が残ると、そこで必ず落ちる。
MOD 側はそのとき `WARN stranded:` まで出せていたが、
落ちるのはその後のゲームの処理で、こちらからは止めようがない。

手元のセーブは `player_data["location"]` を `"316"` から

二重に塞いだ。

| いつ | すること |
| --- | --- |
| 保存（`save_game`） | 建て直されない建物の中（契約が切れた／取り壊し待ち／街から消えた施設）に立っていたら、入口に立っていることにして保存し、終わったら元へ戻す |
| ロード（`World.__init__`） | 建て直した後で、立ち位置が街に無い施設を指していたら入口へ直す（読み込みの途中の辞書を直すので、セーブの書き換えではない） |

契約が生きている家の中は、そのまま保存する。
ロードで建て直されるので落ちないし、入ったところから続けられる
（背景の差し替えもそこに乗っている）。

#### 立ち位置を直したら、今度は選択肢が空で動けなかった（15回目、同日）

版14 でセーブの立ち位置を入口へ直し、その世界は開けるようになった。
ところが画面に選択肢が1つも無く、移動もできない。

ロードは選択肢を組み直さない。
`game_variables["buttons"]` に焼かれているものをそのまま戻すだけ
（GAME.md §2.3 の「`refresh_choice_buttons` は組み直さない」と同じ話が、
ロードにも当てはまる）。
壊れたときの画面は選択肢が空だったので、それがそのまま焼かれていた。

```text
game_variables:
  buttons   []                                    ← これが戻ってくる
  in_shopping  true                               ← 保管庫の窓を借りた旗が立ったまま
  location_image  ...\借りている家 - room(private_room)\image.png
```

立ち位置を動かすときは、その場所の選択肢も一緒に置くようにした。
繋ぎ先の名前と `MovePhaseManager` の引数（`[ノードid, 施設id, エリアid]`）は
セーブの形と同じで、実機の入口の並びとも一致する。
自分が建てた建物への道は入れない
― セーブに無い施設への道をボタンにすると、
MOD の無い環境や建物を失った後に押せてしまう（道を出すのは実行中の画面だけ）。

`in_shopping` も下ろして保存するようにした。
保管庫はゲームの売買の窓を借りているので、品を移した直後の保存
（持ち物から外れた品を控えだけに残さないための保存）が
窓を開いたままの形を焼いていた。ロードで窓は開かないので、旗だけ残ると噛み合わない。

手元のセーブには、入口の選択肢3つ（水辺の区画・高台の区画・霧の湖畔 - 出口）を入れ、
`in_shopping` を下ろした（`backups\savedata.before_914_fix2.json` が直す前）。

#### 賃貸を1本立てにし、期間を宿泊4回ぶんにした（仕様変更、版16〜18）

週ぎめ（7日）・月ぎめ（30日）の2本立てをやめ、賃貸を1つにした。
1期の長さは `lease_days(app)` ＝ `RENT_STAYS` × 宿泊1回の日数。
既定は4回ぶんで、その間は何度でも戻って過ごせる。

| 変えたもの | 前 | 後 |
| --- | --- | --- |
| 設定 | `RENT_WEEK` 500 / `RENT_MONTH` 1,600 | `RENT_PRICE` 1,600 |
| 窓口 | 週ぎめで借りる / 月ぎめで借りる / 建売を買い取る | 借りる(1,600G・480日) / 建売を買い取る |
| 契約の種類 | `rent_week` / `rent_month` / `owned` | `rent` / `owned` |
| 1期 | 7日 / 30日 | `RENT_STAYS` × 宿泊1回の日数（宿屋に追従） |

はじめは1回ぶんにしたが、
それでは宿屋に泊まり直すのと変わらないので4回ぶんにした（版17、本人の指定）。

版18 で、宿泊1回の長さを宿屋に合わせた（本人の指定）。
それまでは自前の設定（`STAY_MONTHS`。既定1ヵ月＝30日）で持ち、
その30日を素のゲームの値だと思って書いていたが、これは誤り。
素のゲームの宿泊は3ヵ月から年齢で伸びる変動式
（30代 +1・40代 +2・50代以上 +3、上限6ヵ月）で、
手元が30日だったのは `315_vacation_custom` で1ヵ月に変えていたため。

長さの取り方は「覚える」。
`VacationStartManager.__init__` に渡る `months` が
`elapse_days(months * 30)` の元（218 の実測）で、
年齢の変動式も 315 の設定も、その時点では答えが出ている。
宿屋で泊まるたびにその値を控え（`stay_months`）へ書き、
自分の家の滞在と賃貸の周期に使う。
自分の家の滞在は数えない。
数えると、見積もりが「実測」に化けて、年を取っても更新されなくなる。
まだ宿屋を見ていない世界だけ、年齢から見積もる（`estimated_stay_months`）。

契約の周期は結んだ時点の長さで固定する。
年を取って宿泊が伸びても、いま借りている契約の期限は動かない。

前の控え（`rent_week` / `rent_month`）は、次に読んだときに `rent` へ移す
（`migrate_leases`）。
残りの期限はそのままにしてある。
いま借りている日数を取り上げる理由が無いので、
次に家賃を払うときから新しい周期になる。

### 3.4 オフラインで確かめたこと（`tools\tests\test_wip_real_estate.py`、154件）

偽の `Facility` / `VacationStartManager` / `Character` / `InventoryItem` を差し込んで、
窓口・契約・一覧・建物・滞在・保管庫・家賃・期限切れ・引き取り・世界ごとに分ける・宿屋の宿泊期間に合わせる・ゲームの採番で建てていた頃の控え・中に居るあいだの期限切れ・取り残されたとき・消えた家の id がセーブに残らない・消えた家に立ったままのセーブを読む・保管庫を開いたまま保存・流し込みの最中・ロード・落ちる宿泊・宿屋の21場面を通している。

> 建物そのものの検査（建てる・壊す・控える・建て直す・出口・道・押下・背景）は
> ローダ側へ移した（`tools\tests\test_modfacility.py` 58件）。
> ここに残っているのは、この MOD が決めることと、両者を繋いだときの振る舞い。

特に押さえてあるのは次の26個。
下の20個は、実機で踏んだぶんと、そのとき足した機能。

- 宿屋には手を出さない。自分の建物の外で `VacationStartManager` が走ったときは宿代を返さない
- 塗り直しても選択肢が増えない（印と `prune_stale`）
- 期限切れで建物が街から消え、入口の接続も外れる
- ロード（`World.__init__`）の後に建物が建ち直り、入口の道も張り直る
- 選択肢が1つも無い画面でも、滞在・保管庫・出口の3つが出る（実機で踏んだ側）
- 区画に繋いでいた家が、当て直しで入口へ移る（版1のセーブからの移行）
- 滞在のあいだだけ建物に主が据わり、終わると元へ戻る
- 宿代は返り、同じ `execute` の中で引かれた家賃は返さない
- ゲーム側の宿泊が落ちても、宿代が戻り、操作も建物の選択肢へ戻る（`KeyError(None)` を投げる偽の宿泊で再現）
- 持ち主は能力値の鍵を要る（偽の `Character` も実機と同じく添字で読むので、鍵の無い作り方では組めない）
- 窓はメインスレッド（Clock）から開く（偽の Clock が「いま Clock の中か」を控える。`schedule` を外すと落ちる）
- 活動を1つ終えると滞在が終わる。宿屋の活動では終わらせない
- 中に居るあいだに契約が切れても壊さない（切れた家では滞在も保管庫も出ず、出口だけが出る／外に出た後に壊れる）
- 建て直されない建物の id はセーブに残さない（生きた契約の家の中はそのまま保存する／保存の後は元の場所に戻す）
- 世界ごとに分かれている（別の世界には建物が建たない／控えは世界ごとに1つ／戻ると建ち直る／ゲームの採番台帳はどの世界でも進まない）
- 賃貸の1期は宿泊4回ぶんの日数（値札に日数が出る／宿泊1回ぶんでは家賃が来ない／宿屋で使われた月数を覚えて追従する／自分の家の滞在は数えない／結んである契約の周期は動かない）
- 立ち位置を動かすときは選択肢も一緒に置く（セーブと同じ形。自分が建てた建物への道は入れない）
- 保管庫を開いたまま保存するときは売買中の旗を下ろす（保存の後は戻す）
- 街に無い施設を指しているセーブは、ロードで入口へ直す（偽の `World` も実機と同じく、返る時点で街を組み終えている）
- 街から消えた施設に立っていたら、入口へ出る道を出す（ゲームの選択肢が残っていても出す）
- 本文が流れている最中に足せなかったボタンが、手が空いてから戻る（偽の `add_text` が実機と同じく `is_adding_text` を立てる。やり直しを外すと窓口が消えたままになる）
- 本体の背景の差し替えが落ちても外へ出さない（交流が途中で止まらない）
- 家の主は役場の役人（役人が引けない土地ではその土地の住人へ落ちる）
- 自分の家の滞在からは「他者と交流」と「アイテム作成」が消える（ほかの活動は残る）
- 家の中の背景は部屋の絵になる（立つだけで描かれる／よその施設の背景には手を出さない／二度は描かない。2つの門それぞれに対応する順序を検査に持つ）
- 世界で1つの保管庫（別の土地の建物から同じ中身が開く／建物ごとの品が共有へ寄る／1軒失っても取り上げない）

### 3.5 建物をローダへ移した（版20、2026-09-13。実機は未確認）

同じ形の建物を足す MOD が2本目に差し掛かったので、
建物そのものをローダの共通部品へ寄せた（`modfacility`。TECH.md §5.8）。
**寄せた理由は「セーブに残さない」を守っているのが保存の直前の関所1箇所だけ**で、
そこを MOD ごとに持つと、写した本数だけ漏れる口が増えるため（`modnpc` と同じ）。

| 何を | どこへ |
| --- | --- |
| 建てる・壊す・繋ぐ・入口を探す（`estate.py`） | `modfacility.spawn` / `despawn` |
| 建て直し・控え | `modfacility.restore_world`、`state\modfacility\<世界名>.json` |
| 道・中の選択肢・出口・残骸の掃除・手が空くのを待つ | `modfacility.maintain_buttons` |
| 保存の直前の立ち位置と選択肢、ロードでの救済 | `modfacility` の関所 |
| 背景を呼ぶ場面と二重描きの抑え | `modfacility.paint_background` / `ensure_background` |
| 大家を引く | `landlord.py`（`estate.py` から残した分。施設ではなく人の話） |

この MOD に残るのは、契約（家賃・期限・預かり）と、
建物の中で何ができるか（滞在・保管庫）と、役場の窓口と、何を描くか。

**施設 id がゲームの採番からローダの名前空間へ変わった。**

```text
版19 まで   ids.claim(app, "facility") -> "313"    index['facility'] が進む
版20 から   mod:914_real_estate:<土地 id>          台帳を触らない
```

土地ごとに1軒なので、土地の id をそのまま鍵にしている。
**版19 までの控えの契約は、この id を持っていないので落とす**（`drop_legacy_contracts`）。
落とすのは控えだけで、セーブには何も残っていない
（建物は実行時にしか無く、立ち位置が古い id を指していればローダが入口へ直す）。
保管庫に預けたままの品も一緒に消えるので、移す前に取り出しておくこと。

**中のまま保存してよいかは、層が名乗る**（`keep_inside`）。
ローダの既定は入口へ移すほうで、理由は事故の代償が「その世界が二度と開けない」だから。
生きている契約の建物はロードで必ず建ち直るので、この MOD は中のままでよいと名乗っている。
切れた契約と取り壊し待ちでは偽を返す（建ち直らないため）。

**取り残されたときの出口の文言だけが変わった**（`家から出る` → `出る`）。
壊した建物は層ごと消えているので、ローダの既定になる。
もう自分の家ではない場所なので、そのままにした。

実機では何も確かめていない。
`230_probe_mod_facility` で測る前に、この MOD が最初の使い手になる。
