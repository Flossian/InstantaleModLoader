## 1. 遊び方（`docs\MODS.md` 相当）

### `914_real_estate`: 役場で物件を借りて自分の拠点を持つ

素のゲームで腰を落ち着けられる場所は宿屋だけで、泊まるたびに宿代と30日を払い直す。
荷物を置く場所も無く、24マスが埋まったら捨てるしかない。

この MOD は役場（役場の選択肢）に不動産の窓口を1つ足す。

```text
[役場]  労働の募集をみる / 市民権の発行 / 物件を扱う / 出る
                                ↓
        週ぎめで借りる(500G) / 月ぎめで借りる(1,600G) / 建売を買い取る(30,000G) / やめる
                                ↓
        その街の入口に建物が1軒増える

[入口]  中央居住区 / 外縁スラム / 借りている家 ←これ / 街を出る
                                ↓
[家]    滞在する / 保管庫をあける / 家から出る
```

建物はその土地の**入口**に繋ぐ。
街に着いて最初に立つのが入口で、区画（`ward`）はその先にある。
自分の家は区画の奥ではなく、着いてすぐ入れる場所に置いてある。

物件は**土地ごとに1軒**。
別の街の役場へ行けば、その街にもう1軒持てる。

### 建物の中でできること

| | |
| --- | --- |
| **滞在する** | 宿屋の宿泊とまったく同じ経路。休養・訓練・労働・社交・物乞いから**1つ**を選ぶ。**宿代は取られない**。暦は宿屋と同じく30日進む（賃貸なら、その30日ぶんの家賃は引かれる）。滞在のあいだ、この家の主は自分になる |
| **交流** | 上の活動の「社交」がそれ。誰と会うかはゲームの決め方に従う（`327_inn_quality` を入れていればそちらの決め方） |
| **保管庫をあける** | 仲間へアイテムを渡すときと同じ2枚並びの窓が開く。左が自分、右がこの保管庫。ドラッグでどちらの向きにも移せて、移した時点で保存される |
| **家から出る** | 入口へ戻る。ゲームは自分で足した施設の出口を作らないので、この1つも MOD が出している（§3.2） |

**1回の滞在でできる活動は1つ**（素のゲームの宿泊と同じ「1泊＝活動1回」）。
活動を1つ終えるとその滞在は終わり、建物の選択肢に戻る。
もう一度過ごしたければ「滞在する」を押し直せばよい（宿代は取られず、暦だけ進む）。

> `327_inn_quality` は宿屋で部屋の等級に応じて活動の数を増やすが、
> **自分の家では増えない**。ここは等級によらず1回に固定してある。

滞在の部屋の等級は設定で決める（既定は個室）。
効くのは描写と、**家の中の背景**（部屋の絵をその等級で借りている）と、等級を読む MOD（活動の数以外）。

### 保管庫は建物ごと／世界で1つ、どちらにもできる

既定は**建物ごと**。
その家に預けた品は、その家でしか出し入れできない。

設定の「保管庫を世界で1つにする」を入れると、**どの物件からも同じ中身**が開く。
街から街へ荷物を持ち回らずに済む形で、離れた土地の家に預けた品もその場で取り出せる。

切り替えたときの中身は次のように動く。

| 切り替え | 預けてあった品 |
| --- | --- |
| 建物ごと → 世界で1つ | 次に保管庫を開いたとき、**各建物の中身が共有の側へ移る**（1度だけ。ログに `moved N item(s)` が出る） |
| 世界で1つ → 建物ごと | 共有の側に残る。どの建物へ返すか決められないので動かさない。設定を戻せばまた同じ中身が見える |

契約が切れたときの扱いも少し違う。
建物ごとなら、その家の保管庫が役場の預かりになる。
世界で1つのときは、**ほかに物件が残っているあいだは取り上げない**（別の家から同じ中身を開けるため）。
最後の1軒を失ったときだけ、開く手段が無くなるので役場へ移る。

### 家賃と期限

賃貸は週ぎめなら7日ごと、月ぎめなら30日ごとに家賃が引かれる。
引かれるのは日数が進んだとき（移動・宿泊・依頼）で、何期ぶんか飛んだ場合はまとめて払う。

期限が近づくと1行出る。

```text
借りている家の契約はあと5日で切れる。
```

**所持金が足りない日が来ると契約は切れる。**
建物は街から消え、保管庫にあった品は役場が預かる。
預かった品は、どこの役場でも引き取り料（既定 2,000G）を払えば戻る。

建売（買い取り）には家賃も期限も無い。

自分から引き払うときは、窓口の「解約する」。
このときも保管庫の中身は役場の預かりになるので、先に引き取ってから解約するほうが安い。

### 建物はセーブに残らない

足しているのは遊んでいる最中の街だけで、世界のファイルにもセーブにも施設は書かない。
契約は `state\real_estate\<世界名>.json` に控え、ロードのたびに建て直している。
**MOD を外せば街は素のまま**に戻り、建物も、そこへ繋がる道も残らない。

保管庫の中身も同じ控えの中にある。
預けた品はプレイヤーの持ち物から外れるので、預けた時点でゲーム自身の保存が走る。

> MOD を外すと、控えは残るが建物は建たない。
> 保管庫に預けたままの品はその控えの中に居るので、入れ直せば戻る。

| 設定 | 意味 |
| --- | --- |
| 週ぎめの家賃 | 既定 500。7日ごとに引かれる |
| 月ぎめの家賃 | 既定 1,600。30日ごとに引かれる |
| 建売の価格 | 既定 30,000。買い切りで、以後の家賃も期限も無い |
| 家賃を自動で払う | 既定 ON。切ると、期限が来た時点で必ず契約が切れる |
| 期限を知らせる日数 | 既定 7。0 で知らせない |
| 預かり品の引き取り料 | 既定 2,000 |
| 保管庫を世界で1つにする | 既定 OFF＝建物ごと。ON にすると、どの物件からも同じ中身が開く |
| 滞在の部屋の等級 | 既定 個室（`private_room`）。ゲームの宿屋と同じ語彙 |
| 1回の滞在の月数 | 既定 1ヵ月＝30日 |
| 借りた物件の名前 / 買った物件の名前 | 街の中に並ぶときの名前 |

## 3. 検証の記録（`docs\VERIFICATION.md` §3 相当）

### 3.1 設計の根拠（実セーブ・リコン成果物、2026-09-11）

**施設の形**は実セーブ7本の全施設を数えて決めた。
足す `location` の素データは実データの `location` と同じ8項目・同じ並びにしてある。

| `facility_type` | `tier` | `config` |
| --- | --- | --- |
| `location`（77件） | 全件 `null` | `level_of_detail` だけ |
| `ward`（120件） | 全件 `null` | 同じ |
| `entrance` / `exit`（各51件） | 項目そのものが無い | 同じ |

街の形も同じ数え方で確かめた。
実データの街は `entrance` から `ward` へ入り、宿・ギルド・役場・自由生成施設はすべてその `ward` から枝分かれしている。
建物を繋ぐ先はノード自身が名乗っている入口（`Node.entrance_facility`）で、引けなければ種類（`entrance` → `ward`）で探す。

**組み立て**は `__main__:Facility.__init__(self, app, parent_node, facility_data)`（`out\recon\targets.txt`）。
施設 id は `ids.claim(app, "facility")` で採る（`index['facility']` を進める。GAME.md §2.23 の事故と同じ理由）。

**移動のボタン**は `MovePhaseManager(app, connected_node_id, facility_move_to_id, area_id)` で、
引数の並びは実測した「出る」のボタンと同じ（GAME.md §2.2）。

**滞在**は `VacationStartManager(app, months, quality)`（GAME.md §2.17 の実測）。
宿代の引き落としは `execute` の中で1回だけ起きるので、前後の所持金の差から返す
（同じ `execute` の中で暦も進むため、そこで引かれた家賃は差から除く。§3.2）。

**保管庫**は `toggle_twin_inventory_window(左, 右, 左の見出し, 場面名)` を
ゲームに無い場面名（`real_estate_storage`）で借りる（`402_` と同じ借り方）。
右側に立てるのは**その窓の間だけ生きる `Character`** で、世界の名簿にも
セーブにも登録しない。移動の同期（`inventory` の辞書・`Item.id` / `obtainer`・
装備の解除）は本体がしないので、こちらで揃える。

自前のボタンは（一覧の保険で足す「建物への道」も含めて）**無害な既存クラス**を spec に持たせ、
押下は印で横取りしてから本物のマネージャを組む。
`MovePhaseManager` を spec に書くと、そのボタンがセーブに焼かれた後、
MOD を外した環境で押せてしまう（そのときは建物がもう無い。GAME.md §2.2）。

### 3.2 実機で分かったこと（2026-09-11）

**ゲームは実行時に足した施設の `connections` を読まない。**
契約して建てた家は素データ（`world_dict` / `save_data_dict`）に無いので、
ゲームが組む移動の一覧には**繋ぎ先の側にも、建物の中にも**現れなかった。

```text
built: '借りている家' id=313 in area '5' node '8' off hub '黄金の回廊'(52)
WARN hub: the game did not list '借りている家'; added the move button myself (args=['8', '313', '5'])
enter: '借りている家' via ['8', '313', '5']      ← 入れた。そこで選択肢が0個
```

入ること自体はできた（`MovePhaseManager` は実行時のノードから引けている）。
落ちてもいない（`crash_log.txt` に当日の記録なし）。
出なかったのは**選択肢だけ**で、GAME.md §2.28 の
「遊んでいる最中に生まれた施設で売買を選ぶと `KeyError`」と同じ側面と読める
（ゲームは施設を素データから引き直す）。

1回目の直し（版2）。

| 症状 | 直し |
| --- | --- |
| 家が区画（`ward`）の下に建ち、役場の奥にあるように見えた | 繋ぎ先を入口（`Node.entrance_facility`）にした。既に建っている家は次の当て直しで入口へ移る（`rehomed:` の行） |
| 建物の中に選択肢が1つも出ず、出ることもできない | 建物の中では「施設の画面か」を問わずこちらで出す。ゲームの移動のボタンが1つも無ければ**出口（`家から出る`）も足す** |

居場所の読み取りが外れていた場合に備えて、押した移動の控えも併用する（`inside_home`）。
どちらで判定したかは `where:` の行に出る。

#### 宿泊には主が要る（2回目、同日）

建物の中の3つは出て、押せた。
そこで「滞在する」を押すと、ゲームの宿泊の本体が落ちて画面が「…」のまま戻らなくなった。

```text
stay: starting VacationStartManager months=1 quality='private_room' at '借りている家'
rent: '借りている家' paid 1000 (next due 746)
VacationStartManager done: gold 5678486 -> 5677386 (moved 1100) days=[30] bg=['private_room']
  → crash_log.txt: instantale.py:8916 in ufl_method_1  KeyError: None
```

背景・暦・宿代・「1ヵ月泊まることにした。」までは通っている。
落ちたのはその後で、**キーが `None`** ＝ 主のいない施設（`owner` が `null`）を名簿で引いた形。
宿屋にはいつも主が居るので、素のゲームでは起きない。

直しは2つ。

| | |
| --- | --- |
| 主を据える | 滞在のあいだだけ `facility.owner` にプレイヤー（世界の名簿に居る id）を据え、終わったら元へ戻す。自分の家の主は自分なので、意味としても通る。名簿にプレイヤーが居ない世界のために、その建物・その土地の住人へ順に落ちる |
| 落ちても戻す | ゲーム側の `execute` で例外が出たら、引かれた宿代を返し、待機表示を解いて建物の選択肢へ戻す。**ここで例外を通すと画面が「…」のまま戻らない**（ワーカースレッドが終わるだけで、誰も操作を返さない） |

同時に、**宿代の返し方も直した**。
暦が進むのは宿泊の `execute` の中なので、そこで家賃も引かれる（実測の 1,100 ＝ 宿代 100 + 家賃 1,000）。
前後の差をそのまま返すと家賃まで返ってしまうため、こちらが引いた家賃は返す額から除く。

滞在の最中は自前のボタンを足さない（並んでいるのはゲームの活動の選択肢で、
そこへ「滞在する」を足すと同じ画面から滞在が二重に始まる）。

#### 保管庫の持ち主は既定では組めない（3回目、同日）

「保管庫をあける」を押しても窓が開かず、ログに1行だけ出ていた。

```text
pressed '保管庫をあける' (storage kind=None)
WARN storage: Character(name=...) raised
  → scripts\characters.py:111 __init__  TypeError: 'NoneType' object is not subscriptable
```

`Character(...)` は全引数に既定値があるのに、**既定のままでは組めない**。
`original_ability_scores` を添字で読むためで、GAME.md §2.23 に同じ記録がある
（`generate_character` 側は `KeyError: 'constitution'`）。

直しは、6つの鍵（`strength` / `dexterity` / `constitution` / `intelligence` /
`wisdom` / `charisma`）を持った辞書を渡すこと。
値は `null` でよいはずだが、値まで要る版に備えて数を入れた形も順に試し、
どれで組めたかをログに残す（`the holder was built with ...`）。

あわせて、窓の右の見出し（借りている売買 UI では「所持品」で固定）を
保管庫の名前に描き替えた（`402_party_inventory_transfer` と同じ気配り）。

#### 窓はメインスレッドから開く（4回目、同日）

持ち主が組めるようになった後、「保管庫をあける」を押すと今度は**入力を受け付けなくなった**。

```text
pressed '保管庫をあける' (storage kind=None)
storage: rebuilt 0/0 item(s)
ERROR real estate: toggle_twin_inventory_window failed
  → kivy\graphics\instructions.pyx  TypeError:
    Cannot change graphics instruction outside the main Kivy thread
```

窓を開く手が**ワーカースレッドの中**にあった。
自前のフェーズは `process_choice` に渡され、その `execute` は別スレッドで走る（GAME.md §2.1）。
そこから Kivy の描画に触ると、この例外で窓が半端に開いたまま固まる。
ゲーム自身は売買の窓を Clock でメインスレッドへ回している（GAME.md §2.13.1）。

直しは `screen.schedule(...)` を1枚挟むだけ。
`402_party_inventory_transfer` がこれを踏まなかったのは、
あちらが `on_button_press`（メインスレッド）の中から直接開いているから。

> 同じ理由で、ゲーム側の宿泊が落ちたときの後始末（待機表示を解く）も Clock へ回した。

検査では、偽の Clock に「いま Clock の中か」の旗を持たせ、窓が開いた瞬間の値を控える。
`screen.schedule` を外すと落ちることを確かめてある（`[False]`）。

#### 1泊＝活動1回に固定（5回目、同日）

滞在が通り、活動（休養・訓練・労働・社交・物乞い）まで届いた。
このとき個室の等級で入っているので `327_inn_quality` が活動を2回に増やしていた。
自分の家は**等級によらず1回**に固定する（遊ぶ側の判断）。

締め方は「活動の `execute` が返ったら、画面が落ち着いてからゲームの
`VacationEndManager` を起こす」。
社交だけは2段（`VacationSocializeManager` → `...ResolveManager`）なので後段で締める
（前段で締めると相手との場面が来ない）。
宿屋での宿泊には触らない（自分の建物の中に立っているときだけ動く）。

#### 背景は自分で描く（6回目、同日）

家の中でセーブしてロードすると、**背景が街の外の景色のまま**だった。

ゲームは背景を施設 id から引く（`change_background_image_from_location_id` /
`..._to_current_location`）。自分で足した施設は素データに無いので引けず、
前の絵が残る。移動の一覧を出さないのと同じ理由（§3.2 の冒頭）。

家の中では宿屋の部屋の絵を借りる（`change_background_image_to_inn_room`）。
渡す等級は滞在で使うものと同じなので、泊まったときと同じ部屋になる。

手当ては2段。

| | |
| --- | --- |
| ゲームが背景を決める瞬間に差し替える | 上の2つを包み、行き先が自分の建物なら部屋の絵にして `orig` を呼ばない |
| それでも描かれていなければ自分で描く | 建物に立っていて、その場所に来てからまだ描いていなければ1度だけ描く。ゲームが背景を決める経路は1つとは限らないので、包みだけに頼らない |

どちらも Kivy に触るので、後者はメインスレッドへ回す（§3.2 の4回目と同じ理由）。

### 3.4 オフラインで確かめたこと（`tools\tests\test_wip_real_estate.py`、82件）

偽の `Facility` / `VacationStartManager` / `Character` / `InventoryItem` を差し込んで、
窓口・契約・一覧・建物・滞在・保管庫・家賃・期限切れ・引き取り・ロード・繋ぎ直し・落ちる宿泊・宿屋の13場面を通している。

特に押さえてあるのは次の14個。
下の10個は、実機で踏んだぶんと、そのとき足した機能。

- **宿屋には手を出さない**。自分の建物の外で `VacationStartManager` が走ったときは宿代を返さない
- **塗り直しても選択肢が増えない**（印と `prune_stale`）
- **期限切れで建物が街から消え、入口の接続も外れる**
- **ロード（`World.__init__`）の後に建物が建ち直り、入口の道も張り直る**
- **選択肢が1つも無い画面でも、滞在・保管庫・出口の3つが出る**（実機で踏んだ側）
- **区画に繋いでいた家が、当て直しで入口へ移る**（版1のセーブからの移行）
- **滞在のあいだだけ建物に主が据わり、終わると元へ戻る**
- **宿代は返り、同じ `execute` の中で引かれた家賃は返さない**
- **ゲーム側の宿泊が落ちても、宿代が戻り、操作も建物の選択肢へ戻る**（`KeyError(None)` を投げる偽の宿泊で再現）
- **持ち主は能力値の鍵を要る**（偽の `Character` も実機と同じく添字で読むので、鍵の無い作り方では組めない）
- **窓はメインスレッド（Clock）から開く**（偽の Clock が「いま Clock の中か」を控える。`schedule` を外すと落ちる）
- **活動を1つ終えると滞在が終わる。宿屋の活動では終わらせない**
- **家の中の背景は部屋の絵になる**（立つだけで描かれる／よその施設の背景には手を出さない）
- **世界で1つの保管庫**（別の土地の建物から同じ中身が開く／建物ごとの品が共有へ寄る／1軒失っても取り上げない）
