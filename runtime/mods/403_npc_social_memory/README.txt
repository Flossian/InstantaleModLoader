403_npc_social_memory v6

v6変更:
・R01氏の311と共有UI部品に合わせ、World.generate_characterで全NPCを捕捉する処理を廃止。
・ui.character_of / ui.character_name / ui.party_member_idsで会話参加者だけを取得。
・NPC間の各方向の事実は最大10件に制限し、重複を除去。
・関係本文は時系列ログではなく、現在の認識を短い要約へ再編纂する。
・旧stateの事実件数も読み込み時に10件へ整理する。

v5変更:
・311の方針に合わせ、ゲーム側人物情報と311記録の会話への再注入を短縮。
・NPC間の関係記録を中心に注入し、同じ人物情報の重複によるプロンプト肥大を抑制。
・311のstateは引き続き読み取り専用。403自身のstateだけをworld_filenameで分離して保存。

v4変更:
・最新版ローダーの llm.create_structure() + llm.ask(..., structure=...) を優先利用。
・providerごとの構造化応答差はローダー共通部品へ委譲。
・構造化経路が利用不能/解読不能な場合のみ旧no-structure JSON経路へfallback。
・NPC ID検証、自己参照除外、有向関係、重複方向除外など403固有の安全検証は維持。

表示:
【参加NPC】
- id / 名前 の一覧

以降は人物ごとに、
【○○の基本情報】
【311:別MODにより、形成された○○の現在情報】
【311: 別MODにより、形成された○○から見た<プレイヤーキャラ名>】
【403: 過去のやり取りより追加された、○○から見た△△の人物像】
の順に表示。同席NPCが複数なら403欄を相手ごとに追加する。

安全性:
・本体character_valueは変更せずdeepcopyして観測するだけ。
・311はimport/変更せずstateをread_jsonするだけ。
・403だけ自分のstateへ書く。
・発火タイミングは変更なし。
