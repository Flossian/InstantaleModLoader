# `135_fix_inn_button_order`: 宿屋の選択肢を 宿泊する／出る／会話する の順にする

宿屋だけゲームが `出る` を先頭に並べる（`出る / 宿泊する(Nヵ月) / 会話する`）。
店や道場や役場は自分の操作が先（`売買する / 出る / 会話する`）なので、
宿屋の `宿泊する` を `出る` の前へ動かして他の施設と揃える。
MOD を1つも当てない状態でも同じ並びなので、原因はゲームの側（GAME.md §2.2）。
原因は `232_probe_facility_choices` で測った。施設が持つ `choices` は挿入順の dict で、
宿屋は `出る` の1つだけ。ゲームはその並びでボタンを組んでから宿屋の `宿泊する` を後ろに足し、最後に `会話する` を足す。
店の `売買する` は `choices` の中に `出る` より前で入っているので先に出る。宿屋だけ操作が `choices` の外に居る。

描く直前に `app.buttons` を並べ直すだけで、選択肢の中身は変えない。
`出る` より前に `宿泊する` が並んでいれば何もしない。
見分けは文言ではなく spec のクラス名（`DisplayVacationChoice` と `MovePhaseManager`）。
記録は `out\inn_button_order.log`（動かしたときだけ。同じ並びは2度書かない）。

`331_facility_investment` の自分の宿では、ゲームの `宿泊する` を伏せて
`無料で泊まる` をその場所に出す（ローダの `modfacility`）。
こちらが先に動かすので `無料で泊まる` も先頭に出る。

## 困ったとき

| 症状 | やること |
|---|---|
| 並びが変わらない | `out\inn_button_order.log` に `reordered:` の行があるか見る。無ければ `出る` の spec が `MovePhaseManager` ではない画面（ロード直後の焼かれた並びなど）。一度出て入り直す |
| 宿屋以外の並びが変わった | `DisplayVacationChoice` を出す施設は宿屋だけのはず。変わった施設の spec を `out\inn_button_order.log` の `reordered:` で確かめる |
