## 1. 遊び方（`docs\MODS.md` 相当）

### `918_town_incidents`: 街の出来事

素のゲームの街は、プレイヤーが何もしなければ何も変わらない。
この MOD を入れると、日数が進むうちに各地の街で盗賊・疫病・魔物の襲来などの出来事が起きる。
放っておくと 兆し → 悪化 → 深刻 と進み、最後は自然に収まる。
その街のギルドの掲示板に出る依頼で片付けられる（`911_rival_adventurer` のライバルが先に片付けることもある）。
出来事の起きている街では、値段・会話・情景描写に情勢が出る。

```text
[宿に泊まる・街を移る]
[灰の都に着く]
咳き込む人の姿が、街のあちこちで目に付く。
灰の都冒険者ギルドに行けば、この件で人手を求める依頼が出ているかもしれない。
[店に入る]
病が流行り、薬の類が飛ぶように売れて値が上がっている。
[ギルドで掲示板を開く]
掲示板に、感染症の流行にまつわる依頼が新しく貼り出されている。
                ↓ 放っておくと 兆し → 悪化 → 深刻 → 自然に収まる
[依頼を片付ける]
灰の都の感染症の流行は、これで収まるだろう。
```

呼び名や情景の文は、出来事が起きたときに LLM がその世界の言葉で1回だけ書く（上の例は LLM を使わないときの文）。
西部劇の世界なら「無法者の一味」、サイバーパンクなら「ギャングの抗争」のように、出来事の中身はその世界に合わせて書かれる。

### 決まり

- 日数が進むと（宿泊・街の移動・自由行動。依頼の最中は進まない）、通算30日ごとに世界全体で1回だけ抽選し、25%で出来事が起きる
- 起きるのは、訪れたことがありギルドのある街だけ（村・町・都市）。いまいる街にも起きる
- 1つの街に起きるのは1つまで。世界全体で同時に2つまで。終わった街には180日のあいだ起きない
- 一度に何日進んでも、起きるのは1つまで（徒歩の90日で3つ起きることはない）
- 段階は 兆し → 悪化 → 深刻 の3つ。放っておくと60日ごとに次の段階へ進み、深刻になってから90日で自然に収まる
- 一度に進む段階は1つまで。徒歩の移動のように一度に長く日数が進んでも、兆しから深刻へ飛ぶことはない
- 発生から自然に収まるまでは、既定だと宿で7泊、徒歩の移動なら3回ぶん
- 片付ける依頼は、その街のギルドで掲示板を開いたときに作られる（ゲーム自身の依頼の生成に、出来事の説明を渡す）。難易度と報酬はゲームが決めたまま
- 依頼は掲示板に普通の依頼として並ぶ。ライバル（911）がその依頼を先に片付けたら、出来事はそこで終わる
- 依頼をしくじっても、放棄しても、出来事は続く
- 自然に収まったときは、片付けられないまま残った依頼を世界から片付ける（受けている最中なら、帰ってから）
- 自然に収まると「〜らしい」の一文で知らせる。その街に居ればその場で、よその街に居れば次にその街に着いたときに1度だけ
- プレイヤーが片付けた依頼は普通の依頼と同じく残り、その街の功績になる（`317_reputation` の評判や `321_area_chronicle` の案内文に拾われる）

### 起こりうる出来事

値段は段階（兆し / 悪化 / 深刻）ごとの上げ下げ。買値は店の品、売値は手持ちを売る額。

| 出来事 | 世界ごとの例 | 値段への影響 |
|---|---|---|
| 無法者の横行 | 盗賊団／無法者の一味／ギャング／略奪者 | 全品の買値 +10 / 20 / 35% |
| 感染症の流行 | 疫病／コレラ／生体ウイルス／変異病 | 薬の類の買値 +25 / 50 / 100%、食べ物の類 +10 / 20 / 30% |
| 外敵の襲来 | 魔物の群れ／狼やコヨーテの群れ／暴走した戦闘ドローン／変異生物の群れ | 武器・防具の買値も売値も +15 / 30 / 50% |
| 騒乱 | 一揆／鉱夫のストライキ／暴動／配給を巡る騒ぎ | 全品の売値 -10 / 20 / 35%、買値 +5 / 10 / 15% |
| 物資の途絶 | 凶作／旱魃／工場の停止・物流の断絶／水源の汚染 | 食べ物の類の買値 +20 / 40 / 80%、宿代 +20 / 40 / 80% |
| 災害の後 | 大火／竜巻／大規模な停電・設備の崩落／砂嵐・地震 | 素材・道具の買値も売値も +15 / 30 / 50% |
| 通貨の信用の揺らぎ | 偽金／偽札／決済の改竄・クレジットの偽造／配給札の偽造 | 全品の売値 -10 / 20 / 35% |
| 買い占め | 商人の結託／鉄道会社の独占／企業の独占／水を握った一派 | 品の種類を1つ選び、その買値だけ +30 / 60 / 120% |
| 不可解な怪事 | 怪異／幽霊話／謎の信号・電脳の幽霊／異常地帯の拡大 | 道具の買値 +15 / 30 / 50%、宿代 +10 / 25 / 50% |
| 失踪の続発 | 人さらい／人狩り／臓器狩り／奴隷狩り | 宿代 +20 / 40 / 80% |
| 闇物資の氾濫 | 密輸品／密造酒／違法な改造部品／略奪品の横流し | 全品の買値も売値も -10 / 15 / 25% |
| 締め付けの強化 | 衛兵の検問／保安官の締め付け／企業警備の戒厳／軍閥の統制 | 武器・防具の買値 +20 / 40 / 60%、全品の売値 -5 / 10 / 15% |
| 権力の空白 | 領主の急死／保安官の殺害／企業幹部の暗殺／首領の死 | 全品の買値 +5 / 10 / 20%、売値 -5 / 10 / 20% |
| 人の流入 | 難民／開拓民／移民／避難民 | 食べ物の類の買値 +10 / 25 / 50%、宿代 +25 / 50 / 100% |
| にわか景気 | 新しい鉱脈／ゴールドラッシュ／技術の流行／遺物の発見 | 全品の買値 +10 / 20 / 30%、売値 +10 / 25 / 40% |

- 食べ物の類は、ゲームの分類で回復の品に入っている食べ物・飲み物も含む（保存食・酒など）。薬の類は、それ以外の回復の品
- 外敵の襲来・にわか景気は売値が上がり、闇物資の氾濫は買値が下がる。片付けずに稼ぐこともできる
- 街の規模で起こりやすさが変わる。村は外敵・物資の途絶・失踪、町は無法者・買い占め・人の流入・にわか景気、都市は感染症・騒乱・通貨・闇物資・締め付け・権力の空白が起きやすい。災害の後と不可解な怪事はどこでも同じくらい
- LLM が「この世界には合わない」と答えた出来事は、別の種類に引き直す（2回まで）。平和な世界観で血なまぐさい出来事を避けるため。ただ、たいていは LLM がその世界にありうる形へ書き換える（争いもお金も無い動物の島々では、外敵の襲来が「正体不明の獣の群れ」、偽金が「貝殻札の偽物」になった）。特定の種類を起こしたくないときは、設定の「出来事の種類」で切る
- 値段は、出来事の起きている街に居る間だけ動く（保存のときは外れるので、セーブには残らない）

### 各地の状況を見る

画面左下のアイコン（持ち物・設定・キャラ情報・クラフト）の右に、アイコンが1つ増える。
ゲームの4つは少し左に詰まる。
押すと、各地で進行中の出来事と、この1年に終わった出来事が並ぶ一覧が開く。

```text
進行中
灰の都　感染症の流行（悪化）
概要: 灰の都で咳の病が広がり、働き手が次々と寝込んでいる。
発生から75日。悪化するまで約45日。
影響: 薬の類の買値 +50%、食べ物の類の買値 +20%。
依頼: 掲示板に出ている。冒険者〈名前〉が狙っている。

この1年に終わったもの
北の村　騒乱　自然に収まった（150日目）
```

概要は、出来事が起きたときに LLM が呼び名と一緒にその世界の言葉で書く1文。
LLM が使えなかったときは、出来事の種類ごとの説明（「街で病が広がり、人々が倒れている」など）が出る。
依頼がまだ出ていない出来事には「依頼: まだ出ていない（〈その街のギルドの名前〉で掲示板を開くと出る）。」と出る。

日付と影響の出し方は設定で変えられる。

| 設定 | 出し方 |
|---|---|
| 一覧の日付の出し方 | 日数（「発生から75日。悪化するまで約45日。」「（150日目）」）／あいまい（「長く続いている。しばらく先に悪化するかもしれない。」「（少し前）」） |
| 一覧の値段の影響の出し方 | 数字（「薬の類の買値 +50%」）／言葉（「薬の類が値上がり」）／出さない。「値段への影響の大きさ」の設定を掛けた後の値で出す |

アイコンの絵は注意の標識（黄色の三角に感嘆符）。ゲームの4つと同じく、乗せると白い縁、押すと白い影絵になる。

### 控えの形（他の MOD との取り決め）

`state\town_incidents\<世界×主人公>.json`。
同じ世界で主人公を作り直したら引き継がない。
読む MOD は `WorldStore(ctx, "town_incidents", own=False)` で読み、`mod.json` の `shares` に `town_incidents` を書く（TECH.md §3.2.3）。
この形を変えるときは、読む側と揃える。

```json
{"events": [{"id": 3, "area": "2", "area_name": "灰の都", "kind": "epidemic", "stage": 2,
             "status": "active", "started": 120, "stage_day": 180, "ended": null,
             "end_by": null, "quest": "57", "goods": null, "tries": ["epidemic"],
             "text": {"name": "…", "rumor": "…"}, "told": {}}],
 "seq": 3, "next_roll_day": 210, "cooldown": {"5": 400}, "cleanup": []}
```

| 項目 | 中身 |
|---|---|
| `events[].area` / `area_name` | 土地の id（文字列）と、起きたときの街の名前 |
| `events[].kind` | 出来事の英名。世界観に依らない（`outlaws` `epidemic` `invaders` `unrest` `shortage` `aftermath` `counterfeit` `hoarding` `anomaly` `abductions` `contraband` `crackdown` `power_vacuum` `influx` `boom`） |
| `events[].stage` | 1〜3（兆し・悪化・深刻） |
| `events[].status` | `pending`（文の答え待ち。まだ何も効かない）／`active`／`ended` |
| `events[].started` / `stage_day` / `ended` | 始まった日、今の段の起点の日、終わった日（ゲームの通算日数） |
| `events[].end_by` | `player`（プレイヤーが片付けた）／`rival`（ライバルが片付けた）／`natural`（自然に収まった） |
| `events[].quest` | 片付ける依頼の id。まだ作っていなければ null |
| `events[].goods` | 買い占めで選んだ品の種類。ほかは null |
| `events[].text` | LLM が書いた文（呼び名・段階ごとの情景・店・収まり・依頼・噂）。無ければ表の文 |
| `cooldown` | 土地の id → 次に起きてよい日 |

終わった出来事は直近の20件まで残す（勢力 MOD は「前回から」の出来事を材料にする）。

### 設定

設定は GUI の「設定…」で開く独自の画面で変える。
タブは6つで、起こり方・進み方・値段と文章・一覧・出来事の種類の5つが設定、記録が出来事の記録を読む欄。
一覧のタブには、選んだ出し方で描いた一覧の見本が出る。
出来事の種類のタブでは、出来事ごとに中身の説明と段階ごとの値段への影響が並ぶ。
記録のタブは、記録（世界と主人公の組ごとに1つ）を選んで、一覧と同じ行を日数と数字で並べ、次が起きるまで休んでいる街も出す。
「記録を消す」はゲームを閉じてから使う（起動中に消すと、次のセーブで書き戻される）。

| 設定 | 既定 | 意味 |
| --- | --- | --- |
| 抽選の間隔（日） | 30 | 通算でこの日数が経つたびに1回引く |
| 起きる確率（%） | 25 | 0 で新しく起きない |
| 同時に起きる数の上限 | 2 | 世界全体で |
| 終わった街に次が起きるまで（日） | 180 | |
| 悪化する間隔（日） | 60 | |
| 深刻になってから収まるまで（日） | 90 | |
| 一度に進む段階の上限 | 1 | 自然に収まるのも1段階に数える |
| 値段への影響の大きさ（%） | 100 | 表の率に掛ける。0 で値段も宿代も動かない |
| 街の規模で起こりやすさを変える | ON | |
| 呼び名と文章を LLM に書かせる | ON | OFF にするか書けなかったときは決まった文 |
| 世界観に合わない出来事を避ける | ON | 合わなければ別の種類に引き直す（2回まで） |
| 街に着いたときに様子を知らせる | ON | 収まった後に初めて着いたときも1行 |
| ギルドへの案内を添える | ON | 様子の1行のあとに、その街のギルドの名前で依頼への案内を1行。依頼が掲示板に出た後は添えない |
| 店に入ったときに値段が変わった理由を知らせる | ON | |
| 一覧の日付の出し方 | 日数 | 「あいまい」なら、残りの日数・発生からの日数・終わった日を言葉で出す |
| 一覧の値段の影響の出し方 | 数字 | 「言葉」なら値上がり・値下がりの言葉で、「出さない」なら行ごと出さない |
| 〈出来事の名前〉（15個。出来事の種類のタブ） | ON | OFF の出来事は起きない |

### 困ったとき

| 症状 | やること |
| --- | --- |
| 出来事が起きない | `out\town_incidents.log` の `roll:` の行。行が無ければ抽選の日に届いていないか、外れ。候補の街（訪れたことがありギルドのある街）が無いと起きない |
| 起きたのに何も変わらない | 同じログの `start:` の行。`roll:` だけで `start:` が無ければ、LLM の答え待ち（`mod_town_incidents_text` の行）。答えが返らなければ表の文で始まる |
| 掲示板に依頼が出ない | 同じログの `quest:` の行。`no quest was generated` ならゲームの依頼の生成が失敗した（次に掲示板を開くと作り直す） |
| アイコンが出ない | `out\town_incidents.log` の `hud icons:` の行。`icon row was not found` ならゲームのアイコンの列を見つけられなかった |

## 2. 設計の根拠

### 2.1 依頼は、その街の掲示板を開いたときに作る

ゲームの依頼の生成（`DisplayQuestChoice.generate_random_quest`）は引数を取らず、いまいる街の依頼を作る（GAME.md §2.9「掲示板で作った依頼と、それを消す」。2026-10-10 に3回とも）。
出来事はプレイヤーの居ない街で起きることが多いので、起きた時点では作れない。
掲示板を開いたとき（`DisplayQuestChoice.execute`。ゲームの別スレッドで、待機の表示もゲームが出す）に作らせる。

### 2.2 自然に収まった依頼は5か所から消す

生きた一覧（`world.quests`）だけから消すと、読み直したときに依頼が戻る（`save_data_dict['quests']` に残っているため。GAME.md §2.9）。
依頼1件ごとにダンジョンの土地も1つ作られる。
消すのは、生きた一覧・セーブの辞書・街の依頼の並び・ダンジョンの土地の2か所の5つ（ローダの `ui.remove_quest`）。
5か所とも消して読み直し、掲示板を開き、次の依頼を作らせるまで誤りは出なかった（各1回）。
依頼と土地の id は使い回されないので、控えの `quest` を id で持っても取り違えない。

### 2.3 アイコンの列

ゲームの4つのアイコンは、`icon_button_layout`（FloatLayout）の中で位置を比率、大きさを 40px の固定で持つ（GAME.md §2.34）。
足すアイコンもゲームと同じ型（`HoverableButton(普段, 乗せた時, 押した時)`）で作る。
絵は 32×32 で描き、40×40 に引き伸ばしてから同梱する（`tools\make_town_incidents_icon.py`）。
ゲームは 32×32 の絵を 40px へ近いドットで引き伸ばし、4列に1列（0・4・8…番）を 2px にする。その並びは中心に対して左右対称でないので、左右対称の標識がゲームの中では崩れて見えた。
こちらで太らせる列と行を中心に対して左右対称に選んで（1・5・9・13・18・22・26・30番）40×40 にしておくと、ゲームはそのまま 1:1 で描く。2026-10-10 に画面の写真と同梱の絵を比べ、不透明なドット 656 個がすべて一致した。
太る列の数はゲームの絵と同じ8列なので、ドットの粒の大きさは変わらない。
足すアイコンを並べるのはローダの `hudicons`（TECH.md §3.3.15）。
左の余白（0.07）を右にも取り、5つを等間隔に置き直す。
1980 幅の画面で、間は 51px から 35px になる。
ボタンの箱どうしを等間隔にすると、絵ごとに端のドットの明るさが違うため（袋は端が暗く、背景に溶けて細く見える）、見えている絵どうしの間が 43・40・40・42px とばらついて見えた。
ローダの `hudicons` が見えている部分どうしの間で並べるように直し、42・41・41・42px になった（残る1px は 32 ドットの絵を 40px に引き伸ばす丸め）。

ゲームの4つの「乗せた時」の絵は、HUD の画面が自分の4つにだけ知らせて切り替えている。
同じ型のボタンを足しただけでは知らせが届かず、一度乗せた絵のまま戻らなかった（2026-10-10 に指摘を受けた）。
ローダの `hudicons` がマウスの位置を見張り、足したアイコンにも同じ知らせを出す。
一覧を開くときは、キャラ情報と同じ音（`アイコン_キャラシート.wav`）を開くときだけ鳴らす（ゲームのキャラ情報も、閉じるときは鳴らさない）。

### 2.4 宿代

宿代を効かせる処理（ボタンの額・手持ちの断り・前払い調整）は、v1.15.0 までは `315_vacation_custom` が持っていた。
315 が入っていないときにもこの MOD の宿代の段が効くように、ローダの宿代の関所（`prices.install_inn`。TECH.md §3.3.4）へ移した。
315 の決めた額の上に、この MOD の段が掛かる。

### 2.5 依頼を作らせる間の待機の表示はゲームに任せる

掲示板の `execute` はゲームの別スレッドで走り、ゲームは押した時点でボタンの旗を下ろして待機の表示（点送り）を出している（GAME.md §2.4）。
版1の作りかけでは、その中で `ui.Screen.busy_on` / `busy_off(restore=False)` を重ねていた。
`busy_on` はその時点の旗（ゲームが下ろした後の False）を覚え、`busy_off` はそれを戻す。
2026-10-10 の実機では、掲示板が出た後に依頼を押しても画面が変わらず、手で操作すると動き出した。
原因はこの重ねとみて外した。

外した後の実機（同じ日）では、依頼は作られたが掲示板の一覧が組まれず、ギルドの画面のままだった。
`206_probe_quest_flow` の記録では、作らせた後に続けて呼んだゲームの掲示板の処理の `update_button_display` が、選択肢を1つも変えていなかった。
依頼を作らせるために掲示板の部品（`DisplayQuestChoice`）をもう1つ作ることが、ゲームの中の状態と噛み合わないとみている（中身は読めないので確かめていない）。
そこで、作らせた回はその掲示板の続きを呼ばず、手が空いてから同じボタンの押下と同じ形（`process_choice`）で掲示板を開き直す。
開き直した回は依頼がもうあるので作らず、ゲーム自身の掲示板がそのまま出る（§4 #5）。
