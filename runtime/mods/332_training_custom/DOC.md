# `332_training_custom`: 訓練所の代金・修行の量・1段の期間・再訓練の可否を変える

訓練所は、代金が 300G で固定、1回の修行が3年、
修行内容を1つ選ぶとその年数ぶんの暦が一度に進む（1年＝365日）。
`新たな技を学ぶ(3年)` を選べば 1095 日、`ただ鍛える(1年)` でも 365 日。
主人公は3年ぶん歳を取り、世界の側も3年ぶん進む。
この MOD はその3つを設定から変えられるようにする。

既定値はすべて MOD なしのゲームの値（300G・3年・ベース期間1年で 1/2/2/3 倍）で、
既定のままならこの MOD は挙動を変えない。
設定を既定値から動かした項目だけが効く。

## 1段の期間は「ベース期間 × 倍率」

ベース期間はいちばん短い修行（`ただ鍛える`）1回で進む暦で、
`1ヵ月 / 2ヵ月 / 3ヵ月 / 6ヵ月 / 1年` から選ぶ。
他の修行はその倍率で決まり、倍率は修行内容ごとに変えられる。
既定の倍率（1/2/2/3）は MOD なしのゲームの年数と同じなので、
ベース期間が「1年」のままなら1日もずれない。

```text
[素のゲーム＝ベース1年]   ただ鍛える(1年)   基礎を積む(2年)   技を磨く(2年)   新たな技を学ぶ(3年)
                          365日             730日             730日           1095日
[ベース1ヵ月]             ただ鍛える(1ヵ月) 基礎を積む(2ヵ月) 技を磨く(2ヵ月) 新たな技を学ぶ(3ヵ月)
                          30日              60日              60日            90日
[ベース3ヵ月]             3ヵ月             6ヵ月             6ヵ月           9ヵ月
[ベース1ヵ月・ただ鍛える6倍] ただ鍛える(6ヵ月)                  他は 2/2/3ヵ月のまま
```

ボタンには実際に進む期間が出るので、表示と実態は食い違わない
（`314_area_move_custom` と同じ約束）。
既定の設定ではその文字列がゲームの表示（`ただ鍛える(1年)`）と一致するため、既定のままなら1文字も変わらない。

## 行動できる回数は暦とは別に数えられている

1回の修行で行動できる量が決まっていて（MOD なしのゲームは3回ぶん）、
行動ごとの消費量がそこから引かれ、0 で卒業する。
消費量は `ただ鍛える` 1・`基礎を積む` 2・`技を磨く` 2・`新たな技を学ぶ` 3。
決まるのは回数で、期間ではない。
そのため3なら「`新たな技を学ぶ` を1回」でも「`ただ鍛える` を3回」でも同じように終わる。

この消費量と、残りで払える行動だけを並べる判定は
ゲームの内側にあって、引数にも出てこない。
そのためこの MOD はそこを触らず、暦だけを変える。

結果として、1回の修行で取れる行動の回数は倍率を変えても変わらない。
`新たな技を学ぶ` を1倍にしても、ゲームは3ぶん使った扱いにするのでその場で卒業する。

ゲームはこの数を年で言う（`あと3年間`）。
画面の文言を実際の期間に直す設定は下の節にある。

回数を変えたときは、訓練が始まった直後の1行だけゲームが元の回数のまま書く。
2行目以降はゲームも新しい回数で数えるので、そこは合っている。
この MOD は自分が渡した回数を知っているので、その1行だけ設定値で読み替える
（画面と、AI へ渡るプロンプトの「残り訓練年数」の両方）。
読み替えたときは `out\training_custom.log` に `the start line still said N year(s)` が残る。

## 文言の「N年間」も実際の期間になる

ゲームは残りの量も1段の結果も年で言う。
そのままだとベース期間を縮めたとき、暦は縮むのに文言だけが年で残る。

```text
[ゲームの言い方]              [ベース1ヵ月のとき]
あと3年間。どうする？         あと3ヵ月。どうする？
一年間、ひたすら鍛錬した。    1ヵ月、ひたすら鍛錬した。
残り2年間。どうする？         残り2ヵ月。どうする？
```

直すのは訓練の画面の間に出る文言だけで、それ以外の場面の文言には触らない。
既定の設定では直した先が同じ文字列になるので1文字も変わらない。
直したくないときは設定の「文言の「N年間」も実際の期間に直す」をOFFにする
（そのときは暦だけが縮んで、文言はゲームの言い方のまま残る）。

`あと3年間` の3はゲームが数える修行の量なので、暦に直すと幅が出ることがある。
倍率を既定の比（1/2/2/3）から変えていると、
残り3年を「3年の修行1回」で埋めるか「1年の修行3回」で埋めるかで長さが変わるためで、
そのときは `あと3ヵ月〜18ヵ月。どうする？` のように最短と最長を出す。
倍率が既定の比のままなら1つの長さになる。

AIが書いた文そのものには触らない。
`これからの三年間、私が責任を持って…` のような文も年で言うが、
あちらは漢数字で文の途中に出るうえ、指しているのが1段ではなく修行全体なので、
段の長さで書き換えると数が合わなくなる（実測の4文で確認した。VERIFICATION.md §3.64）。
直すのは AI に渡す前のプロンプト（次の節）。

## 卒業した施設でもう一度訓練を受ける（既定 ON）

MOD なしのゲームは、一度卒業した施設では2回目を断る
（`十分に学んだ。これ以上ここで得るものはないだろう。` 代金も日数も動かない）。
この MOD を入れると受けられる（他の設定と違い、ここだけ既定が MOD なしのゲームの値ではない）。
ゲームのとおり断ってほしいときは設定を OFF にする。

断る原因は、施設に立つ訓練済みのフラグ（`config["trained"]`）。
卒業した道場の記録（`state\modfacility\<世界×主人公>.json`）に
`snapshot.config.trained = True` が立つ（実測。
`savedata.json` の側には同じ名前の項目が無く、施設そのものが持っている）。

「卒業した施設でも再訓練できる」がONのあいだは、そのフラグをキーごと削除する。
`False` を入れるのでは足りない（実機で断られ続けた）。
一度も卒業していない道場（同じ世界の `<別の道場名>`）の config にはキー自体が無いので、
ゲームが見ているのは値ではなくキーの有無と読める。未訓練の施設と同じ状態にする。

```text
[素のゲーム]  訓練を受ける(300G) → 十分に学んだ。これ以上ここで得るものはないだろう。
[ON]          訓練を受ける(300G) → （印が立っていないので）いつもどおり訓練が始まる
```

フラグが立っていなければ、ゲームは卒業していない施設と同じ処理を通る。
代金も準備（主の画像と背景）も選択肢も文言も、ゲームのまま。
この MOD が行うのは、押した時点でフラグを削除することと、
卒業でまた立ったフラグを次の回までに削除することの2つ。
施設が読めないときは `out\training_custom.log` に WARN を残す。

## AI に渡すプロンプトの年数も直す

ゲームはプロンプトにも年数を書き込む。
プロンプトを直さないと、画面が `あと3ヵ月` になっても師範のセリフだけが「三年間」と言い続ける。
直すのはプロンプトの次の4か所（実測。`output_data\<世界>\<PC>\training_conversation_starter\N.json` ほか）。

```text
- 残り訓練年数: 3年                      →  - 残り訓練期間: 3ヵ月
…これは費用と3年の時間を費やす代わりに…  →  …費用と3ヵ月の時間を費やす…
- 入学の希望を受けた場合: 3年間を費やし…  →  …: 3ヵ月を費やし…
新たな技の会得に3年を費やした...          →  新たな技の会得に3ヵ月を費やした...
```

置き換えの目印は、訓練のプロンプトにしか無い言い回しにしてある。
`N年` だけを目印にすると、同じプロンプトに載っている
`…は指導者<相手の名>のもとで3年間の過酷な基礎訓練を終え`（人生ログ。訓練の後に書かれ、
以後あらゆるプロンプトへ運ばれる）や
`この土地に合計2年暮らしている`（土地との縁）まで書き換えてしまう。
どちらも過去の記録なので、後から期間を書き換えると誤りになる。
`out\training_custom.log` に `prompt at <経路>` として残り、
訓練のプロンプトなのに1つも一致しなかったときは `kept as is` にその一節が出る。

| 設定 | 意味 |
| --- | --- |
| 訓練の代金 | 既定 300G（ゲームの値。施設によらず固定）。300のままなら触らない。0でタダ。手持ちが足りないと押した時点で「（訓練の代金◯Gに足りない…）」と断る |
| 1回の修行の行動回数 | 既定3回ぶん（ゲームの値）。行動ごとの消費量（1/2/2/3）がここから引かれ、0で卒業。決めるのは回数で、期間ではない。ゲームはこの数を年で言うので画面には「あと3年間」と出る |
| 1段のベース期間 | 既定「1年」（ゲームの値＝365日）。`1ヵ月 / 2ヵ月 / 3ヵ月 / 6ヵ月 / 1年` から選ぶ |
| 修行内容ごとの倍率 ×4 | 既定 1 / 2 / 2 / 3（ゲームの年数と同じ）。ベース期間の何倍か |
| 訓練を受けるボタンの表示 | 既定 `{name}({price}G)`。代金を変えたときだけこの形で表示し直す |
| 修行内容のボタンの表示 | 既定 `{name}({length})`。`{length}` は実際に進む期間（`3ヵ月` `2年`）。`{days}` `{factor}` `{base}` も使える |
| 卒業した施設でも再訓練できる | 既定 ON。施設の訓練済みのフラグ（`config["trained"]`）を削除するので、卒業していない施設と同じように訓練が始まる。OFF にすれば MOD なしのゲームどおり断る（「十分に学んだ。…」で代金も日数も動かない）。ON の間に訓練を始めた施設はフラグを削除しているので、OFF に戻しても断らない |
| 文言の「N年間」も実際の期間に直す | 既定 ON。訓練中に出る `あと3年間` `一年間、ひたすら鍛錬した。` を実際の期間に直す。既定の設定では1文字も変わらない |
| AI に渡すプロンプトの年数も直す | 既定 ON。プロンプトの `残り訓練年数: 3年` などを実際の期間に直す。OFF にすると師範のセリフだけが年で語り続ける。人生ログと土地との縁（過去の記録）は触らない |
| 代金に足りないときの一言 | 既定 `（訓練の代金{price}Gに足りない ― 手持ち{gold}G）` |

設定は2種類ある（`314_` / `130_` と同じ形）。
mod.json の設定が全ワールド共通の一括設定で、
ローダの設定画面の「ワールド別の訓練所設定」を開くとワールドごとに上書きできる。
その世界だけ訓練所を安くする、その世界だけ修行を短くする、といった使い方ができる。
個別設定は `state\training_custom\<世界名>.json` に、
一括設定と違う項目だけが入る（全部同じならファイルは消える）。

> 修行内容の見分けはゲーム内部の種類の名前（`simple` / `fundamental` / `train_skill` /
> `learn_new_skill`。実機で観測した値）で行う。
> ゲームの更新でその名前が変わったビルドでは、
> ゲーム自身が言っている年数（ボタンの `(N年)` と `elapse_days` に来た日数 ÷ 365）を
> 倍率の代わりに使うので、ベース期間の設定はそのまま効く。

## 他の MOD との連携 API

訓練の暦を、ローダの連携 API `durations`（TECH.md §3.3.2）に置いている。
連携 API は「1段の日数 ＝ 活動の年数 × 1年の日数」の形で持つので、
ベース期間を `days_per_year` に、倍率を `activity_years` に入れている（掛け算の形が同じ）。
訓練の長さに合わせたい MOD はそこから取得する。
この MOD は誰が取得するかを知らない。この MOD を外せば連携 API の値も MOD なしのゲームの式に戻る。

日数を変える側もローダの共通フック（日数送りをフックするラッパーは1つだけ）に希望を出す形なので、
同じ日数送りに別の MOD が関わっても、決めるのはローダの1か所になる。

## 困ったとき

| 症状 | やること |
| --- | --- |
| 代金が設定どおりに引かれない | `out\training_custom.log` の `price:` の行。「the game charged its own 300」が出ていたら、お使いのビルドは代金を引数ではなく別の場所で決めている（差額はその場で戻すので所持金は合う）。デバッグモードで `231_probe_training` を入れて録って、ログを添えて報告してほしい |
| 期間が変わらない | 同じログの `phase:` と `days:` の行。`WARN phase: no elapse_days call` が出ていたら、お使いのビルドの訓練の日数送りが `elapse_days` を通っていない。`231_probe_training` で録って報告してほしい |
| 倍率を下げたのに卒業が早まらない | 仕様。段数を決めているのはゲームが数える年数で、倍率は暦の長さだけを変える（上の注記） |
| ボタンの表示が変わらない | 代金が既定の300G・ベース期間が「1年」で倍率も既定のままなら、表示も元のまま（仕様＝実質何も変わらないため） |
| 修行内容のボタンだけ表示が変わらない | 同じログの `no activity and no years in the phase label` の行。種類も年数も読めないビルドでは触らない |
| 文言が年のまま残る | 「文言の「N年間」も実際の期間に直す」がOFFなら仕様。ONなのに直らないときは `out\training_custom.log` の `text passing through` の行を見てほしい。ゲームの言い回しが実測の4文から変わっていれば、その文がそこに出る |
| AI の描写が「三年間」と言い続ける | 「AI に渡すプロンプトの年数も直す」が OFF になっていないか見る。ONなのに直らないときは `out\training_custom.log` の `prompt at ... kept as is:` の行。ゲームの言い回しが実測の4つから変わっていれば、その一節がそこに出る。なお過去に書かれた人生ログ（`3年間の過酷な基礎訓練`）はそのまま運ばれるので、以前の訓練の記述は年のまま残る（仕様） |
| 手持ちが少ないと訓練を受けられない | 設定した代金未満なら仕様。元の300G未満で断られるときはゲーム自身の判定 |
| 「十分に学んだ」で受けられない | 「卒業した施設でも再訓練できる」がOFFなら仕様（MOD なしのゲームのまま）。ONなのに断られるときは `out\training_custom.log` に `retrain: dropped the 'trained' mark` が出ているか見る。出ていなければ、お使いのビルドは別の場所で断りを決めている（`231_probe_training` で録って報告してほしい） |
| `<エリア>の風は今日はここまでのようだ。` と言われて進まない | ゲームがその修行を断っている。実機では版5〜7 の作り（準備の処理を飛ばしていた回）でだけ出て、版9 では出ていない。もし出たら `231_probe_training`（版2）を入れて録り、段の中のどの分岐で折り返したかを添えて報告してほしい |
