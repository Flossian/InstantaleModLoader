## 1. 遊び方（`docs\MODS.md` 相当）

世界の設定に書かれた勢力（国・教団・組織など）ごとに、主人公がどう見られているかを持つ。
その勢力の街の NPC は、見られ方に応じた態度で接する。
同じ主人公でも、ある勢力の街では歓迎され、別の勢力の街では警戒される。

### 決まり

- 世界ごとに有効にする（設定の「世界ごと」のタブ）。有効にしていない世界では何もしない
- 「新しく作る世界に組織を設ける」を入れておくと、世界を作るときに世界観に合った組織が2〜4つ設けられ、地理の説明と街の案内文に書き込まれる。その世界では勢力が最初から有効になる。組織を自分で決めたいときは、世界を作るときの概要に書けばよい（`145_fix_world_overview` を入れていれば、書いたとおりに残る）
- 有効にした世界を読み込むと、世界の設定と街の案内文から勢力を読み取る。初回だけ少し時間がかかる（裏で LLM に2回聞く）
- 設定に勢力が2つ以上書かれていない世界（一つの国が治める世界・勢力の話が無い世界）では、勢力を作らない
- 設定に書かれていない勢力・関係は作らない
- 冒険者に当たる人々（設定での呼び名が何であれ）、職業や身分の呼び名、一人の人物や役職は勢力にしない
- 会話で口先だけ調子を合わせても、見られ方は上がらない
- 見られ方は勢力ごとに -100〜100 で、段階は 敵視（-61 以下）・警戒（-21 以下）・中立・好意（20 以上）・信頼（60 以上）
- 最初の見られ方は、読み取った後に1回だけ決める。新しく始めた主人公は出自（経歴）だけから決める。
  遊んでいる途中の主人公は、その勢力の街での功績の数・滞在日数・手配から土台を決め、功績の中身と経歴しだいで1段階まで上下する。
  手配されている勢力は功績があっても警戒より上にならず、手配度 -40 以下なら敵視
- 世界ごとの設定で「この世界に組織を設ける」を入れると、設定に勢力が書かれていない世界にも組織が設けられる（勢力の仕組みの中だけで、ゲームの依頼や街の案内文には出てこない）
- 勢力の街の NPC は、見られ方の段階に応じた態度で話す。中立なら何も変わらない。段階によっては、その勢力の者たちのあいだでの主人公の呼び名も知っている
- 仲間にしている NPC は、主人公を個人として知っているので態度は変わらない
- 会話を閉じるたびに、その会話での主人公の言動が相手の勢力にどう映ったかを判定し、見られ方が動く。上がるのは同じ勢力から1日1回、下がる方は毎回
- ある勢力に好かれると、その勢力と対立している勢力からは少し疎まれる
- その勢力の街で手配されている間は、会話や出来事で見られ方が警戒より上へ上がらない。手配度が -40 以下なら敵視より上へ上がらない
- 見られ方が一度 -81 以下まで落ちた勢力は、会話や出来事でいくら上がっても敵視のまま。
  ただし、その勢力の者との会話で、敵意を改めるに足る理由（確かな証し・償い・筋の通った説得など）を示して相手を納得させれば、この縛りは外れる。謝罪や口先だけでは外れない
- 宿泊や移動で日数が進むと、勢力どうしの仲もときどき動く。起きたことは噂として NPC が知っている
- 世界の設定にもともと書かれている勢力どうしの関係は、簡単には動かない
- 穏やかな世界観では、勢力どうしが敵対まで悪くなることはない

## 2. 設計の根拠

### 2.1 勢力は設定に書かれたものだけ

ゲームには勢力・派閥に当たるデータが無い。
素直に LLM に作らせると、どの世界も王国・商人ギルド・盗賊団のような似た顔ぶれに寄る（`132_` `104_` `128_` が対処してきたのと同じ種類の偏り）。
加えて、手元の6世界のうち勢力をはっきり書いていたのは1つだけで、残りは滅びかけた世界・政治の語彙が無い世界だった。
設定に無い対立を足すと世界観そのものが変わり、統一された世界とは矛盾する。
だから版1は「設定に2つ以上書かれている世界だけ」で動き、書かれていない世界で事実から導く機能は持たない。

LLM には根拠の原文を一字一句抜き出させ、コードが材料の中に本当にあるかを照合する（空白と括弧は無視、4字未満は認めない）。
見つからない勢力・街・関係は捨てる。
根拠の途中を「...」「…」で省いて返すことがある（2026-10-11、Haiku 5.5）ので、省いた根拠は切れ目ごとに照合する。
短い語をつないで原文に無い文を作れないよう、切れ目のうち一番長いものが8字に届かなければ認めない。
街の根拠には、その勢力の名前が入っていることも求める。
Haiku 5.5 が、勢力の名前の無い一文（「聖者の遺構を模した行政庁舎」）から推して、街を教会に割り振ったため。
勢力の名前そのものも、設定の文の中にあるかを照合する。
近未来とポストアポカリプスの世界で、LLM が「〇〇の支配勢力」「〇〇の武装集団」と街の説明から呼び名を組み立てた（2026-10-11、クラウド）ため。
設定が「冒険者の代わりに〜がいる」と書いた人々（主人公の仕事）は、頼み文で外させても残ったので、名前と「冒険者の代わり」「冒険者に当たる」が同じ文にあればコードでも捨てる。

業種・職業の呼び名（警備会社・闇金・漁り屋・武装集団・自警団など）は勢力にしない（2026-10-11 に決めた）。
認めれば名前の付いた組織が無い世界でも動くが、読むたびに顔ぶれと街の割り振りが変わり（同じ世界で3回読ませて 5・4・2 個）、
その街の住人の全員が業種の者として話すことになり、裏社会の業種は `336_crime_overhaul` の領分と重なる。
「数えない」と書くだけでは残ったので、勢力ごとに name_type（この世界の特定の一つの組織を指す「固有」か、同じ種類の人々をまとめた「一般」か）を答えさせ、「一般」を捨てる。
問うのは言葉が普通かどうかではなく、設定がその名前でこの世界の一つの勢力を書いているかどうか。
「教会」「機関」「工房」のような普通の言葉の名前で三勢力を書いた世界で、ローカルの LLM が3回とも「一般」と答えて全部落ちた（2026-10-11）ため、頼み文にそう書き、「数えない」例から「工房」を外した。
論理は渡さない（`902_city_case` と同じ考え）。LLM が決めるのは「何が書いてあるか」と文章だけで、点数・段階・幅・下限はコードが決める。

### 2.2 元の案内文を読む

`321_area_chronicle` は依頼のクリアごとに `Area.descriptions` を実行中だけ書き換え、元の文を残さない。
勢力はセーブの辞書（`save_data_dict["areas"][id]["descriptions"]`）の元の文から読む。
`area_description`（周辺の土地の文）にも勢力や土地柄が書かれていることがあるので材料に入れる。

### 2.3 最初の見られ方（新しいキャラは出自、途中導入は規則の土台＋1段階までの調整）

版1の始めは、経歴・手配度・功績・ライフログを LLM に読ませて段階を直接決めさせていた。
同じ材料で台帳を作り直すと、勢力の段階が2段振れた例が2回あった（2026-10-11 の実機）。
1回きりの判定なので、その揺れが一周の遊びに残る。そこで2つに分けた（2026-10-11 に決めた）。

| 主人公 | 決め方 |
|---|---|
| 新しいキャラ（功績も手配も無く、滞在の合計が 90 日未満） | 出自（経歴）と勢力の一覧だけを LLM に読ませ、段階を決めさせる |
| 途中導入 | その勢力が力を持つ街での記録から規則で土台の点数を出し、LLM には功績の中身と経歴を読ませて -1 / 0 / +1 段階だけ動かさせる |

土台の点数（`rules.baseline_scores`）は、功績1件 +10（上限 +50）、通算 90 日以上の滞在 +10。
その街を治める勢力なら、そこで起きたことは知っている、という読み。
手配は功績で打ち消さない（2026-10-11 に決めた）。
手配されていれば、功績と滞在の点に -40 を足し、警戒の上端（-21）より上にはしない。
手配度 -40 以下は功績によらず -80（敵視）。
LLM の調整も、この上限より上へは動かさない（下げるのは動かす）。
殺人1件で手配度が -10〜-20 動くので、-40 以下は殺人を重ねた重さ（境目は 2026-10-11 に決めた）。
初めは手配を功績と足し引きしていたが、功績5件・滞在229日・手配度 -170 の勢力が中立になった。
後から設けた組織（§2.11）は物語にもライフログにも名前が出てこないが、街ごとの記録は残っているので、同じ決め方が使える。
ライフログは読まない（組織の名前が出てこず、長い世界では材料が大きくなりすぎる）。
調整が 0 なら土台の点数のまま、動いたら動いた先の段階の真ん中の点数にする。
経歴に「NPC が知る情報ではない」と前書きする書き方があるので、頼み文で「その勢力が知りえたことだけで判断する」と縛る。

### 2.4 見られ方は会話の構えに出す

ゲームの会話の記録 213 件で、足された文が応答に使われたかを数えた（2026-10-09）。

| 足された文 | 応答が使った回 |
|---|---|
| 功績の欄（プレイヤーの情報として事実を並べる） | 0 / 63 |
| 317 の評判の文のうち出来事 | 0 / 63 |
| 317 の二つ名（「あなたも耳にしている」） | 5 / 63（プレイヤーが先に言った回は 0） |
| 321 が書き直した土地の文 | 0 / 17 |
| 911 のライバルの構え（「あなたは〜を見下していて、口を開けば嫌味や挑発が出る」） | 読んだ6件とも嫌味と挑発の口ぶり |

出来事の事実は NPC の側から話題にならないが、「あなたはこの人をこう見ている、だからこう振る舞う」という構えは口ぶりを変え、短い呼び名は第一声で使われる。
勢力の態度に欲しいのは口ぶりなので、911 の書き方に揃えた（構えの文と、段階を判定したときの呼び名）。
構えの文には舞台の物（地形・制度・技術など）を書かず、人と人の関係と振る舞いだけを書く（どの世界観でも成り立つように）。
足す口はローダの `modnpc` の `notes`（会話の5関数）。

相手の勢力は、相手が住人・冒険者として名簿に載っている街で決める。載っていなければ主人公がいま居る街。

### 2.5 会話の判定は要約に相乗りする

`337_` と同じく、会話を閉じるときのゲームの要約に項目を足す（ローダの窓口 `talk_summary`。TECH.md §3.3.16）。
別に呼ぶと会話を閉じる待ちが延びる。337 と同じ要約に2本乗っても送信は1回。
判定は「相手個人の好き嫌い」ではなく「その勢力の者として見た印象」。

### 2.6 勢力どうしの情勢（向きは LLM、幅は規則）

一個人で世界の勢力に抗うのは無理で、個人の知らない所で情勢が動くのは自然なので、勢力どうしの仲は日数の経過でも動く。
LLM に決めさせるのは「何が起きたか・どの2つの勢力か・近づいたか離れたか」と噂の文。
1回で動くのは1組の1段階まで。設定に書かれた関係は同じ向きに2回押されて初めて1段動く（逆向きに押されたら数え直す）。
穏やかな世界観では緊張より下げない。
一度に何日進んでも1回だけ（徒歩の移動は1回で 90 日進むので、LLM を続けて呼ばない）。
起きなかったとみなすのは happened に "false" と書かれたときと、2つの勢力か向きが読めないとき。
Haiku 5.5 が happened に出来事の文を書いて返した（2026-10-11）ので、"true" でない文でも起きた回として読む。
起きたことは、全部の NPC の会話に「各地の噂」として足す（317 と同じ「あなたも耳にしている」の形）。
ゲームの噂（`world_data.story.current_rumor`）は遊んでいる間に書き換わらず、会話の第一声の頼みに毎回載っているが、そこを書き換えるとセーブに焼かれる。会話に足す口のほうが外したときに何も残らない。

### 2.7 街の出来事（918）との連動

向きは 918 → この MOD の一方向だけ。この MOD が 918 の控え（`state\town_incidents\`）を読み、無ければ何もしない。918 はこの MOD を読まない。
主人公が片付けた出来事は、その街の勢力の見られ方を上げる（出来事ごとに1回）。
前回の情勢から後に起きた・進んだ・終わった出来事は、情勢を決める材料に渡す。

### 2.8 控えの置き場所

| 何 | どこ |
|---|---|
| 台帳（勢力・街・関係・見られ方・情勢の記録） | `state\town_factions_ledger\<世界×主人公>.json` |
| 世界ごとの設定 | `state\town_factions\<世界>.json`（設定画面が書く） |

同じ世界で主人公を作り直したら台帳は引き継がない（見られ方は主人公の行いで決まるため）。
世界ごとの設定と台帳のフォルダを分けたのは、周回の鍵へ移す処理（`WorldStore.playthrough` の `adopt`）が同じフォルダの `<世界>.json` を古い控えとみなして移してしまうため。

### 2.9 台帳を作り始める時点

読み込み（`InstantaleApp.load_game_new`）の後に作り始める。
起動直後の注入が2回入り、2回目の掛け替えと世界の読み込みが重なると、読み込みの包みが呼ばれないまま遊べる画面になる（2026-10-11 の実機で2回。GUI と `relaunch.sh` の両方が注入する）。
そのときのために、選択肢が組み直されるたび（ローダの窓口 `choices` の `refresh`）に、まだ見ていない周回なら台帳を確かめる。
会話の頼みと日数の経過でも確かめる。

### 2.10 世界を作るときに組織を設ける

名前の付いた組織が設定に書かれた世界は少ない（手元の世界では1つだけ）。
遊んでいる最中に作ると「設定に従う」から外れ、業種の呼び名から作ると読むたびに顔ぶれが変わる（§2.1）。
世界を作るときに設定そのものに組織を入れれば、世界の物語・街の案内文・キャラの出自にまで組織が通り、919 は書かれた組織を読むだけになる。

- 世界の生成の頼み（`send_request("create_world_overview", …)`。概要の有無によらずこの名前）の【注意】の前に【勢力】の段を足す
- 書かせる先は地理の説明（`structure_description`）と拠点の概要文（`settlement_overview` → 街の案内文 `descriptions.overview`）。
  世界の概要には書かせない（`145_` が入力どおりの文に差し替えるため）
- 欄の名前（`structure_description`）を名指ししないと、地理の説明には書かれなかった（2026-10-11 の実機の1回目。2回目は名指しして後半に「勢力は三つ存在する」の段が入った）
- 生成のときは冒険者ギルドにも名前が付いた（「ギルド『〇〇』の支部」）。勢力にしないよう頼み文で断り、抽出でも照合する（§2.1）
- 作った世界は、`world_data.json` を書き出したところで 919 の世界ごとの設定を有効にする（`save_world_json:write_obfuscated_json_file`。世界の名前は書き出す `world_data.name`）
- 組織と街の割り振りは台帳へ直接は書かない。読み込んだときに抽出が読む（名前の付いた組織なので読み取りは揺れなかった）
- 組織だけ欲しい（見られ方の仕組みは要らない）なら、世界を作るときの概要に書けばよいので、別の MOD にはしない

### 2.11 設定に勢力が無い既存の世界に組織を設ける

世界を作るときの組織（§2.10）は、これから作る世界にしか効かない。
世界ごとの設定「この世界に組織を設ける」を入れた世界では、抽出で勢力が2つ以上読み取れなかったとき、
今の世界の文（概要・地理の説明・街の案内文）を材料に、LLM に組織を2〜4つ設計させて台帳へ直接書く（`rules.build_designed_ledger`）。

- 組織は台帳の中だけにある。ゲームの依頼・語り・街の案内文は組織を知らない（効くのは 919 が会話に足す構え・噂と、見られ方の仕組み）
- 街の案内文にも足す形（321 と同じ実行時の差し替え）は、321 と同じ欄を取り合うので見送った
- 設計した関係は、設定に書かれた関係と同じく動きにくくする
- 遊び途中の世界では、それまでの物語に無かった組織が急に現れる。世界ごとに自分で入れる形にしてあるのはそのため

### 2.12 手配と敵視の上限（2026-10-11 に決めた）

会話・918 の出来事で上がる動きには上限を置く（`rules.gain_ceiling`）。

| 状態 | 上がる先の上限 |
|---|---|
| その勢力の街で手配度 0 未満 | 警戒の上端（-21） |
| その勢力の街で手配度 -40 以下 | 敵視の上端（-61） |
| 見られ方が一度 -81 以下になった | 敵視の上端（-61）。手配が解けても外れない（会話で納得させたときだけ外れる） |

- 手配度はその時点の主人公の記録を読む。勢力が力を持つ街が複数あれば、いちばん重い手配で決める
- 上限にいる・上限より上にいるときは動かず、張り合う勢力への響きも無い。上限の手前から上がったときは、響きは実際に上がった分から引く
- 上限は上がる動きだけに掛かる。下がる動き・情勢・最初の見られ方の決め方（§2.3）は変えない
- 手配されたときに見られ方を引き下げることはしない（上がらないだけ）
- -81 以下で付けた印（台帳の `locked`）は、数の上下では外れない。外れるのは会話の判定で相手が納得したときだけ（下記）

印を外す判定は会話の要約に相乗りする（§2.5 と同じ1回の頼み）。
項目 `faction_reconcile` は毎回の要約に載るが、判定の決まりを足すのは印のある勢力の者と話したときだけで、それ以外は "false" と書かせる。
"true" を読むのも、印のある相手に頼んだ会話だけ（頼んでいない会話の "true" は捨てる）。
外れたら、同じ会話の判定（+1 / +2）からは敵視の上端を越えて上がれる。手配の上限はそのまま掛かる。
数の上下（通常の操作）では外れず、自由入力などで LLM を納得させられたら外れてよい（2026-10-11 に決めた）。

最初の見られ方で手配を功績と足し引きしていたら、殺人を重ねた手配の街の勢力が中立になった（§2.3）。
遊んでいる間も同じで、手配されたまま依頼や会話で好かれていくのはおかしいので、上がる側に上限を置いた。
敵視が外れない境目を -81 にしたのは、最初の見られ方で置く敵視（-80）にはまだ印を付けず、そこから更に下げたときに付けるため。
