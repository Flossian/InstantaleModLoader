# `321_area_chronicle`: エリアの状況を更新（依頼クリアで案内文が変わる）

依頼を片付けると、その土地の案内文が変わる。
湿地の霧を晴らす依頼をクリアすれば、以後の案内文から霧の記述が消え、
会話と依頼の生成が「実際に変わった土地」を読むようになる。

MOD なしのゲームにも記録の仕組みはある。
依頼クリアごとに `area_history` の `achievements` へ1〜2文の要約が入り、
「湿地の霧は晴れ」の粒度で土地の状態変化まで書かれる。
その全文は会話プロンプトにも毎回載っている。
それでも NPC が自発的に言及した回は 0/775（GAME.md §2.24）。
そこでこの MOD は、読み手が毎回読む
土地の描写の原文（`Area.descriptions`）を書き直す。

```text
依頼クリア → 新しい功績 ＋ 現行の案内文 → LLM が書き直す（別スレッド）
              「変化を織り込む。土地の正体は変えない。長さは維持」
           → 実行中の Area.descriptions を差し替え
           → state\area_chronicle\<世界名×主人公名>.json（ロード時に当て直す）
```

`descriptions` は2つあり、差し替えれば読み手全員に一度で届く。

| 何 | どこへ描画されるか |
| --- | --- |
| `overview`（1文） | 会話の【土地情報】に毎回一字一致で載る |
| `facilities`（数文） | 依頼の生成・要約の4マネージャに載る |

## 編纂の入力は「新しい功績だけ」

記録（`done`）より後に増えた功績だけを渡す。古い功績は前回までの編纂で
既に文面へ織り込まれているので、毎回全部渡すと同じ変化が何度も適用される。
一度に増えた分が多いときは直近の件数（設定）に絞り、絞ったことをログに書く。

編纂が走らないままゲームを終了しても巻き戻らない。
`done` が進んでいないので、次の到着・日数経過・クリアの照合で立ち直る。

書き直しの受け入れには条件がある。空の欄と、元の長さの2倍
（概要は最低100字、様子は最低300字を下限とする）を超えた文面は捨てて、
前の文面を残す。プロンプトには案内文の全文が毎回載るので、
編纂のたびに文面が伸びるとプロンプトが肥大する。

## セーブにも world_data.json にも書かない

`world_data.json` はゲームが書き戻さない世界の骨格で、この MOD も書かない。
実行時の dict は骨格側と共有されている可能性があるので、
中身を書き換えず、新しい dict を作って属性ごと差し替える。

差し替えはセーブに残らないので、ロードすると案内文は元へ戻る。
戻ったぶんはロードのときに `state\` から再適用するので、
遊んでいる側からは連続して見える。利点は `318_` と同じ2つ。

- MOD を外せば世界は元のまま。外すために何かする必要は無い
- おかしくなったら `state\area_chronicle\<世界名×主人公名>.json` を消せば、
  その主人公の案内文は元に戻る（功績の記録はゲーム側のものなので消えない）

記録は主人公ごとに持つ。同じ世界で主人公を作り直すと、案内文は元の文面から始まり、
その主人公の功績だけが織り込まれていく。
以前の版が作った世界名だけの記録（`<世界名>.json`）は、見つけた時点で遊んでいる主人公のものとして移し、元のファイルは消す。
その世界に別の主人公の周回の記録があるときは、その主人公の記録だったかもしれないので移さない（TECH.md §5.4）。

## 設定

| 設定 | 既定 | 意味 |
| --- | --- | --- |
| 1回の編纂に渡す功績の数 | 5 | 一度に見つかった未織り込みの功績が多いときの上限 |
| 第一声で近況に触れてよいと断る | OFF | 会話の第一声にだけ、複製の profile へ1行を足す補助の手段。年代記のある土地でしか足さない |
| 第一声に足す1行 | 上記の断り文 | 空にすると何も足さない |
| 実行時の形をログに残す | ON | `Area.descriptions` のキーと長さを起動ごとに1回だけログへ |

第一声の1行が既定 OFF なのは、MOD なしの挙動を既定にするためと、
まず案内文の差し替えだけで言及が増えるかを測るため（介入前の基準値は 0/775）。

## 困ったとき

| 症状 | 見るところ |
| --- | --- |
| 案内文が変わらない | `out\area_chronicle.log`。クリア後に `編纂を予約:` と `編纂できた:` が対で出る。`新しい功績が現れなかった` ならゲーム側の要約待ちに間に合っていない（次の到着・日数経過で立ち直る） |
| 変わった文面がロードで戻った | 同じログの `load: 周回 … を当て直した`。出ていなければ `state\area_chronicle\` に記録が無い |
| 書き直しが下手 | `output_data\<世界>\<PC>\mod_area_chronicle\` にプロンプトと返答がそのまま残る。出来事の並べ直しになっていないかはここで見る |
| 差し替え自体が効かない | ログの `descriptions:` 行。dict でない形が出ていたらこの版のゲームでは差し替えられない |
