# MODS: 同梱している MOD

何がどこまで直るか・何が増えるかの一覧。
1行ずつ見渡したいときは [MODLIST.md](MODLIST.md)。
ローダと GUI の使い方は [README.md](README.md)。

**この文書は `tools/build_mods.py` が各 MOD の `DOC.md` を綴じたもの。**
手で書き換えても次の生成で消える。
直す先はその MOD のフォルダの `DOC.md`。

フォルダ名の先頭の番号が種類と適用順を表す。

| 番号帯 | 種類 | 中身 |
| --- | --- | --- |
| `000`-`0xx` | 調査・記録 | ゲームは変えない。構造の書き出しとクラッシュ記録 |
| `100`-`1xx` | 修正 | ゲームのバグ・不便の修正 |
| `200`-`2xx` | 計測 | ゲームは変えない。原因を測るための道具。デバッグモードのときだけ動く |
| `300`-`3xx` | 追加 | ゲームに無かった遊びの追加 |
| `400`-`4xx` | 提供 | 提供を受けて取り込んだ MOD。この帯だけは中身ではなく出どころを表す |

提供を受けた MOD は `4xx` だけではない。
この帯が出来る前に取り込んだものは種別どおりの帯に入っている
（番号を振り直すと、遊んでいる人の `state\` と設定が行方不明になるため動かしていない）。
どの節にも、提供があればその名乗りを節の頭に置いてある。
一覧は [MODLIST.md の「提供を受けた MOD」](MODLIST.md#提供を受けた-mod)、
権利の所在は [NOTICE](../NOTICE)。

各項の「設定」は GUI の `設定` 列から変えられるもの。
変え方は [README.md の「設定の変え方」](README.md#設定の変え方)。

## 調査・記録（0xx）

### `000_recon`: ゲームの内部構造を書き出す

ゲームの内部構造を走査し、パッチ対象の一覧を `out\recon\` に書き出す。
ゲームは変更しない。
MOD を作るときの下調べ用。

書き出しは毎回上書きになる。
ただし**ゲームが更新されていれば、上書きする前に前回ぶんを退避する**。
退避先は `out\recon_snapshots\<版>_<日付>.zip`（`main_025_20260809.zip` の形）。
更新の前後で「何が増えて何が消えたか」を突き合わせるための材料。
走るのは版が変わったときだけなので、同じ版を何度遊んでも zip は増えない。

| 設定 | 意味 |
|---|---|
| ゲーム更新時に前回の走査結果を退避する | 既定 ON |

### `001_crash_recorder`: クラッシュの全文を残す

クラッシュ時のトレースバックとフレーム変数を、
省略なしで `out\live_crashes.log` に残す。
不具合を報告するときはこのファイルを見る。

本体自身のクラッシュ記録（`<ゲームdir>\crash_log.txt`）も、今までどおり書かれる。

#### 作者のサーバへの送信は止める

本体にはクラッシュの記録を外へ送る段があるが、**注入している間はこれを止める**。
MOD を入れて遊んでいる間の記録にはローダと MOD の枠が混ざっていて、
素のゲームで起きたことの記録にはならないため。
止めたことは `out\modloader.log` に1行残る。

```
[...] crash recorder: not sending the crash log to the server (1635 chars);
      mods are loaded, so it would not be a report about the plain game
```

MOD 無しで起きた不具合を作者へ報告したいときは、
`MOD を外す`（または MOD を入れずに起動）してから再現すれば、本体の送信がそのまま働く。

### `126_ui_title_version`: タイトル画面にローダの版を出す

タイトル画面の右上に `modloader vx.y.z` の1行が出る。
出るのはタイトル画面だけで、「開始する」を押せば消える。
遊びには何も影響しない。

ローダは注入で入るので、**ゲームの見た目はどこも変わらない**。
起動しただけでは、MOD が効いているのか判断できない。
注入に失敗しても画面は変わらない。
不具合を報告するときも「MOD 入りかどうか」の確認から始めることになる。
この1行がその答えになる。

ゲームを起動したままローダを注入し直したときも、
目の前のタイトル画面にその場で出る（一度タイトルへ戻る必要は無い）。

| 設定 | 意味 |
| --- | --- |
| 出す文字 | 既定 `modloader v{version}`。`{version}` はローダの版、`{mods}` は今入っている MOD の本数に置き換わる |
| 出す場所 | 右上（既定）／左上／右下／左下。右下はゲーム自身のバグレポートのボタンの場所 |
| 文字の大きさ | px（既定 14）。ゲーム側の画面拡縮に合わせて調整される |
| 文字の濃さ | 既定 0.55。1.0 で真っ白 |

#### 困ったとき

| 症状 | 見るところ |
| --- | --- |
| 文字が出ない | `out\modloader.log` の `title version: installed` の行。出ていなければ MOD が入っていない |
| 注入し直しても古いまま | 同じログの `title version: N title screen(s) already open`。`0` ならタイトル画面が見つかっていない（ゲーム内の画面に居るときは `0` で正しい） |
| 文字が四角に化ける | 日本語に変えた場合のみ。フォントはタイトル画面から写しているが、写す相手が見つからないと Kivy の既定（日本語を持たない）になる |

### `120_fix_npc_name_collision`: NPC の名前が重複するのを直す

生成される NPC の名前が、世界に居る誰かと同じに読めるとき、
同梱の名簿から空いている名前を選んで改名する。
完全一致だけでなく、読んで同じ人に見える名前を重複として扱う。

| 形 | 例 |
| --- | --- |
| 表記ゆれ | バルガス / ヴァルガス（`ヴァ` と `バ`、`ティ` と `チ`、長音の有無、濁点） |
| 修飾語付き | バルガス / 「隻眼の」バルガス |
| 姓名の片方だけ一致 | バルガス / バルガス・ドレイク |

小さい LLM（Gemma 系）ほど同じ語を繰り返し引くので、そこが効く。

付け直す名前は名簿から選ぶ。
名前を機械が組み立てたり LLM に書かせたりすると読み物として当たり外れが出るので、
用意した名前だけを使う。
男女はセーブの `category`（`young man` / `teenage girl` など）で選び分ける。

```
ヴァルガス（middle-aged man）  ->  ランスロット
「隻眼の」バルガス（old man）  ->  エドワード
バルガス・ドレイク（young man）->  孤独なアルマン
ばるがす（young woman）        ->  アドリアナ
```

二つ名は 10%（設定で変えられる）。
`「死神」` `沈黙の` `死を運ぶ` の形が名前の前に付く。
元の名前に付いていた二つ名は引き継がない（新しい名前は別人のものなので）。

名簿は `runtime\mods\120_fix_npc_name_collision\npc.default.json`（名前 各600・二つ名
300）。
差し替えるときは同じフォルダに `npc.json` としてコピーしてから編む（そちらが優先され、
MOD を新しい版にしても消えない）。
書式は `{"male": [...], "female": [...], "epithets": [...]}`。
読むのはこの3つの鍵だけで、
他の鍵が入っていても無視する（別の道具で作った名簿もそのまま置ける）。

どの名前になるかはそのとき引くので、世界を作り直すと顔ぶれも変わる。
ただし一度付いた名前は変わらない（改名はセーブにも書かれるので、
次からその NPC は重複していない）。
名簿が読めないとき・名簿の名前を使い切ったときは、
名前を発明せずに記録だけして元のまま通す。

設定で、重複していなくても新しい NPC の名前を全部この MOD が付けるようにできる（「新しい NPC の名前を必ず MOD が付ける」。
既定 OFF）。
LLM が書いた名前は捨てて名簿から引くので、世界に出てくる名前の傾向が名簿で決まる。
既に世界に居る NPC は ON でも変わらない（新しく生まれる NPC だけが対象）。

敵と魔物は対象外（同じ戦闘に「ゴブリン」が3体並ぶのは重複ではない）。
プレイヤーも改名しない。
改名の記録は `out\npc_name.log` に残る。

| 設定 | 意味 |
| --- | --- |
| 新しい NPC の名前を必ず MOD が付ける | 既定 OFF（重複したときだけ付け直す）。ON にすると、これから生まれる NPC の名前を全部名簿から付ける |
| 二つ名を付ける割合（%） | 既定 10。0 で付けない。「必ず MOD が付ける」を ON にすると世界の1割に二つ名が付く |
| どこまで近ければ重複とみなすか | `strict` は読みが完全に一致したときだけ／`normal`（既定）は1文字違いまで／`loose` は短い名前や2文字違いも拾う |
| 濁点・半濁点の違いも同じ音とみなす | 既定 ON。バルガスとバルカスを重複にする。濁点を落として**完全に一致**したときだけで、上の「どこまで近ければ」とは足し合わせない |
| 既に世界に居る重複も改名する | 既定 OFF（記録だけ）。既存 NPC の画像は名前のフォルダに入っているので、改名すると次に作る画像だけが新しい名前の側へ行く |

#### 困ったとき

| 症状 | やること |
| --- | --- |
| 似た名前の NPC が並ぶ | 入れ直す。以後に生成される NPC から効く。既に居る重複も直したいなら「既に世界に居る重複も改名する」を ON |
| 別人のはずの NPC が改名された | 「どこまで近ければ重複とみなすか」を `strict` にする。`out\npc_name.log` にどの相手と衝突したかが残っている |
| 世界観に合わない名前が付く | `npc.json` を置いて名簿を差し替える（上記）。既に付いた名前は変わらない |
| 同じ名前を何度も見る | 名簿から引くので、名簿が小さいと繰り返す。`npc.json` に名前を足す |
| LLM が付ける名前そのものが好みでない | 「新しい NPC の名前を必ず MOD が付ける」を ON にする。以後に生まれる NPC は全部名簿から付く |
| 重複しているのに改名されない | `out\modloader.log` に `no roster` と出ていれば名簿が読めていない（`npc.json` の書式を確認）。`no free name in the roster` なら名簿を使い切っている |

### `123_fix_new_character_level`: 新規キャラがレベル60で始まるのを直す

新しく作ったキャラクタが、経験値0のままレベル60で始まってしまうのを直す。
ゲーム本体がプレイヤーを組む行で、レベルに 60 を渡しているのが原因。
その数行あとでは体力上限をレベル1として計算するので、
1体の中で食い違っている（HP はレベル60ぶんの `耐久 × 52`、体力上限はレベル1の 10）。
原因の特定までは VERIFICATION_LOG.md §2.36。

> **main_025 で本体が取り込んだため無効化**。
> デバッグモードのときだけ読み込まれます（README「デバッグモード」）。
> 新しく作るキャラはレベル1で始まるようになりました。
> ただし本体の修正は既存のセーブには効きません。
> このバグでレベル60のまま保存されたキャラを直したい場合だけ、
> 下の設定を入れてそのセーブを読み込んでください。

レベルを 1 に戻すので、HP もレベル1ぶん（実測では耐久の
4.7〜4.9 倍）で計算し直される。
効くのは **この食い違いが揃ったときだけ**で、本体が直れば自動的に何もしなくなる。
記録は `out\new_character_level.log`。

既にレベル60で保存されたセーブは、既定では直さない（遊んでいたキャラのレベルと
HP が黙って下がるほうが事故になるため）。
記録に警告だけ出るので、直したい場合は設定を入れる。

| 設定 | 意味 |
|---|---|
| レベル60で保存済みのキャラも読み込み時に直す | 既定は切。入れると、このバグで作られたセーブを読み込んだ時点でレベル1に戻す |

### `125_balance_charisma_impression`: 魅力が高いと初対面から全員に好かれるのを直す

NPC がプレイヤーに対して抱いている感情は2つの文で持たれていて、1つ目が好感度、
2つ目が見た目の魅力。
この2つ目はプレイヤーの魅力だけで決まり、
相手が誰かもどこまで打ち解けたかも入らない。
そのため魅力に振ったキャラは、
初対面から世界の全員に最上段「耐え難いほど魅力的に見えている」で見られ続ける。

この文は会話のたびに、LLM へ渡るプロンプトに丸ごと載る。
そのため**誰に何を頼んでも無条件に友好的な返事が返る**。
交渉や説得が勝手に通り、難易度が下がる。

段（文言）はゲームのものをそのまま使い、どの段になるかだけを2つの要素で決め直す。

- 相手ごとの好み … 同じ魅力でも、相手によって見え方が違う。
  相手ごとに固定なので、同じ人はいつも同じように見る（会話のたびに揺れない）
- どこまで打ち解けたか … 好感度が浅いうちは上の段まで行かない。
  最上段は「多少の好意がある」以上の相手にだけ出る

魅力が低いキャラを不利にはしない。
好みや親しさで「ひどく醜く思っている」に落ちることはなく、
素で最下段のキャラの段を下げることもない。
好感度の段そのものにも触らない。

段の並びと閾値は**起動のたびにゲーム自身から読む**ので、
ゲームが更新されて段が増減しても追従し、日本語以外の言語でも効く。
読み取った並びは
`out\charisma_impression.log` の先頭に出る（ここが「効いているか」の確認箇所）。

| 設定 | 意味 |
| --- | --- |
| 相手ごとの好みの幅（段） | 既定 1。0 にすると誰から見ても同じ段になる（親しさだけが効く）。2 以上にすると散り方が大きくなる |
| 魅力が満額で効くまでに要る好感度の段数 | 既定 4（＝「多少の好意がある」）。最上段が出るのもここに届いてから。0 にすると初対面から満額で効く |
| 最上段「耐え難いほど魅力的に見えている」を残す | 既定 入。打ち解けた相手にだけ出る。切ると上限が「強い魅力を感じている」になる |

| 症状 | やること |
| --- | --- |
| 何も変わらない | `out\charisma_impression.log` の先頭を見る。段の並びが出ていなければゲーム側の作りが変わっている（その理由も同じ行に出る） |
| 相手による差が出ない | 同じログに `相手が拾えない` が出ていれば、話している相手を特定できていない（親しさのぶんだけが効いている状態）。その下に、そのときの呼び出し元の中身が写してある。**そこごと報告してほしい**（相手がどこに居るかが分かれば拾えるようになる） |
| 誰からも冷たく見られる | 「相手ごとの好みの幅」を下げるか、「魅力が満額で効くまでに要る好感度の段数」を小さくする |
| 元の一律に戻したい | MOD を切る。既に保存された文は、その相手と次に会話した時点で書き直される |

### `128_item_image_variety`: アイテム画像の偏りを均す

アイテムの画像は、生成時の外見文（英語一文）に最も似た1枚が毎回選ばれる。
乱数が無いので、外見文が定型的な品種では同じ画像に集中する（実測ではポーション 52個中35個が同じ1枚。調査の数値は
VERIFICATION.md §3.26）。

直し方の芯は1つの表（版6）。**「外見文 → 絵」の対応を世界ごとに
`state\item_image\<世界>.json` に残す**。

- **同じアイテムの再入手は同じ絵**。同じ敵の同じドロップは、クエスト生成時に
  保存された同じ外見文で選定に来るので、表がそのまま同じ絵を返す
- **初めての外見文には、似た候補（top1 の類似度の一定割合以上、最大枚数まで）の
  中からまだ使われていない絵**を割り当てる。「別の名前なのに同じ絵」がここで消える
- 表はファイルに残るので、再起動・別セッションをまたいで効く。乱数は無く、
  同じ履歴・同じ手順なら同じ絵になる

もう1つ、**埋め込み辞書に載っていない305枚**に説明文を付けた追加辞書を同梱し、
選択肢に加える。
内訳は document 105 / creature_part 171 / mushroom 28 / accessory 1。
この305枚は素のゲームでは一度も選ばれない。

既に持っているアイテムの画像は変えない。
効くのは MOD を入れてから新しく生成される分だけ。

| 設定 | 意味 |
| --- | --- |
| 候補にする枚数の上限 | 既定 10。1 にすると素のゲームと同じ |
| 候補にする類似度の下限（top1比） | 既定 0.8。上げるほど見た目に忠実、下げるほど多様 |
| 同梱の追加辞書を使う | 既定 ON。切ると素の辞書だけで均す |

| 症状 | やること |
| --- | --- |
| 何も変わらない | `out\item_image.log` に `chose` の行が出ているか見る。無ければフックが効いていない |
| 見た目と説明が合わない画像が出る | 「候補にする類似度の下限」を上げる（0.9 なら素にかなり近い） |
| それでも同じ画像ばかり出る | その品種の在庫自体が少ない可能性（medicine は4枚しかない）。ログの `qualified` の数を見る |
| 履歴をリセットして最初からにしたい | その世界の `state\item_image\<世界>.json` を消す。世界を消したときにこのファイルが残っても、消してよい |

### `129_balance_item_price`: アイテムの値段を付け直す

素のゲームの値付けは**レア度をほとんど見ていない**。
同じ価値段階なら common でも mythic でもほぼ同じ額になり、店への売値はさらに低い。
実セーブから拾った例:

| 品 | 素のゲーム |
| --- | --- |
| mythic の財宝（価値段階 66） | 売価 **102G** |
| epic の魔法素材（価値段階 4） | 売価 **3G** |
| mythic の遺物（価値段階 12） | 売価 **7G** |
| magical の短剣（攻撃力 245） | 買価 1,831G |

宿の一番安い部屋（簡易寝台）が 10G、一番高い部屋（高級個室）が 1000G。
どちらも3ヶ月ぶんの前払いという物価なので、
伝説級の戦利品を売っても高級個室ひと部屋にも届かない。
拾った品を売る意味がなく、店に並ぶ品を買う理由も薄くなる。

この MOD は値段を**その品自身から組み直す**。
元の額に倍率を掛けるのではないので、効いていなかったレア度もここで効く。

```
値段 = 種別ごとの基準額 × レア度倍率 × 種別の倍率 × スキル/強化 × 全体倍率
```

- 能力値を持つ品（武器の攻撃力・防具の防御力・薬の回復量）は**能力値**を軸にする。
  同じ段階でも強い品のほうが高い
- 能力値を持たない品（素材・財宝・道具・書物）は**価値段階**を軸にする
- 店に売るときの値段は、店が売る値段の 4 割（既定）

既定でどのくらいになるか:

| 品 | 素のゲーム | この MOD |
| --- | --- | --- |
| 短剣 common（攻撃力 23） | 72 | 282 |
| 短剣 common（攻撃力 96） | 463 | 2,090 |
| 短剣 magical（攻撃力 245） | 1,831 | 15,500 |
| 革鎧 common（防御力 227） | 1,833 | 6,260 |
| 薬草 common（回復 8） | 14 | 52 |
| 薬 magical（回復 198） | 353 | 2,970 |
| 魔法素材 magical（段階 24）買 | 128 | 1,210 |
| 魔法素材 magical（段階 24）売 | 20 | 484 |
| 遺物 mythic（段階 12）売 | 7 | 1,910 |
| 財宝 mythic（段階 66）売 | 102 | 22,400 |

素のゲームより安くなる品は無い。

装備（武器・防具）が素材や財宝より控えめなのは、既定の種別倍率でそう寄せてあるから。
装備は店で買うより道中で拾うほうが早く、
素材と財宝は店に売る以外の使い道が無い。
同じ総額なら素材側を厚くしたほうが、拾った物の行き先として釣り合う。
装備を店で揃えて進めたいなら、武器と防具の倍率を 1.0 に戻せばよい。

| 設定 | 意味 |
| --- | --- |
| 全体の倍率 | 既定 1.0。値段すべてに最後に掛かる。高いと感じたら 0.5、安いと感じたら 2.0 |
| 店の買取率 | 既定 0.4。店に売るときの値段は、店が売る値段のこの割合 |
| 武器 / 防具・装身具 の倍率 | 既定 0.7 |
| 回復アイテム / 消耗品 の倍率 | 既定 1.0 |
| 道具・書物 の倍率 | 既定 0.8 |
| 素材・財宝 の倍率 | 既定 1.5 |
| レア度 rare / magical / epic / legendary / mythic の倍率 | 既定 1.4 / 2.0 / 3.0 / 4.5 / 7.0（common は常に 1.0） |
| 強化1段あたりの上乗せ | 既定 0.3。鍛冶で強化した装備に段数ぶん足す |
| スキル付きの倍率 | 既定 1.5 |
| 値段の下限 / 上限 | 既定 5 / 9,999,999 |
| 手持ちの品も開いたときに付け直す | 既定 ON。切ると、これから作られる品だけが新しい値段になる |
| 売買した金額を表示どおりに合わせる | 既定 ON。下の「表示と決済がずれたら」を参照 |

細分ごとの基準額（短剣・宝石・財宝…の32種）は GUI ではなく
`runtime\mods\129_balance_item_price\balance_item_price.py` の `RATES` にある。
「宝石だけもっと高く」のような調整はそこを直す。

#### 古いセーブの品

値段はアイテム自身に書かれてセーブに残る。
この MOD は**売買画面を開いた時点**と**説明欄に出した時点**で付け直すので、
遊んでいる途中の世界でも次に店へ行けば新しい値段になる。
逆に、この MOD を外しても付け直した値段はそのまま残る
（ゲームが値付けし直す品から順に元へ戻る）。

#### 表示と決済がずれたら

ゲームが表示どおりの額で決済しているかは、外から確かめられない。
この MOD は売買の前後で所持金を測り、
**動いた額が表示と違えば、その差だけ所持金を直す**。
所持金が負になることはない。
直した回は `out\item_price.log` に `reconcile` として残り、
逆に**表示どおりだった回も1度だけ** `settled` として残る。
売り買いを1回すればどちらかが出るので、
「合っていた」のか「まだ売買していない」のかがログで分かる。

#### 困ったとき

| 症状 | やること |
| --- | --- |
| 値段が変わらない | `out\item_price.log` を見る。`installed` の行だけで `->` の行が無ければ、まだ値付けの経路を通っていない（店を開くか、アイテムにカーソルを合わせる） |
| 高すぎる・安すぎる | 「全体の倍率」を動かす。種別ごとなら種別の倍率 |
| 特定の品だけおかしい | 同じログの `[...]` が値段の軸（`攻撃力=96` か `value=24`）。`skip` が出ていれば、その品は価値段階も能力値も読めていない |
| `reconcile` が大量に出る | ゲームは表示と違う額で決済していて、この MOD が毎回直している。動作としては正しいが、この行を添えて報告してほしい |
| 元の値段に戻したい | この MOD を切ってから、店を開いて品揃えが入れ替わるのを待つ（`312_shop_restock` を併用していれば入れ替えの日で戻る） |

### `130_currency_unit`: 通貨の呼び名と所持金の表示を変える

素のゲームの通貨は「ゴールド」。
画面には長い形（`1000ゴールドを支払った。`）と
短い形（`馬車(1000G)` / `簡易寝台(10G)` / `貴族権(1,000,000G)`）の2つで出る。
この MOD はその2つを好きな表記に差し替える。
「円」「シルバー」「ドル」「クレジット」など、入れた文字がそのまま使われる。

ゲーム内の LLM も同じ表記で話す。
ゲームが LLM へ送る指示文にも通貨は書かれている
（雇用費・治療費・宿代・市民権の値段）。
それも画面と同じ1点（`scripts.languages:tr`）を通るので、
差し替えた表記のまま LLM に届く。
NPC はその呼び名で値段を言い、こちらの入力もその呼び名の世界として読まれる。

表記を変える前に貯まった人生ログ・会話の記憶・世界観には
「ゴールド」が残っている。
これらは送る直前に直すので（設定「LLM へ送る文章も直す」。既定 ON）、
古いセーブで始めても LLM から見える通貨は1つに揃う。

同梱の他の MOD が出す文言も一緒に変わる
（`309_` の罰金、`314_` の馬車代、`315_` の宿代）。

#### 画面上部の `Gold:` も変えられる

画面上部の能力欄（`Atk` `Def` `Exp` `Gold:` `Age:` …）は翻訳の表に載っておらず、
日本語で遊んでいても `Gold:13184` と英語のまま出る。
ここの `Gold` も通貨の呼び名なので、**呼び名を変えれば一緒に変わる**。
「シルバー」にすれば `シルバー:13184` になる。設定は要らない。

見た目そのものを決めたいときは、設定「画面上部の所持金の表示」に書式を書く:

| 書いたもの | 画面 |
| --- | --- |
| `Gold:{amount}` | 既定。呼び名に合わせて `シルバー:13184` |
| `所持金:{money}{short}` | `所持金:13,184Slv` |
| `{money} {long}` | `13,184 シルバー` |
| `${money}` | `$13,184` |

使える変数は4つ。
`{amount}` はゲームが書いた数字そのまま、`{money}` は3桁ごとに区切ったもの、
`{long}` と `{short}` は上で決めた通貨の表記。
呼び名は素のままにして表示だけ変える、という使い方もできる。

変えないのは**額そのもの**で、値段も所持金も1つも動かない。
文中の短い形は数の後ろにしか置けない（`$1000` のような書き方は
画面上部の欄でだけできる）。
画面上部の他の見出し（`Atk` / `Def` / `Exp` / `Age` / `Sta` / `Location`）と、
キャラクタ作成画面の `所持金` には触らない。

効いたかどうかは `out\currency_unit.log` に置換の例が出ることで分かる
（既定で 20 件）。
呼び名も書式も素のままなら、何も仕掛けない。

> セーブには跡が残る。
> `1000Gを手に入れた。` のような行動ログは表記を差し替えてから書かれるので、
> 変えた後に貯まるぶんは新しい表記で残る。
> 古い行と混ざるが増えるものは無く、外せば以後は素の表記に戻る
> （既に書かれた行はそのまま）。

| 設定 | 意味 |
|---|---|
| 長い表記 | 既定「ゴールド」。文中で使われる形 |
| 短い表記 | 既定「G」。数のすぐ後ろに付く形（`馬車(1000G)` の `G`） |
| 画面上部の所持金の表示 | 既定 `Gold:{amount}`。見出しは呼び名に合わせて自動で変わる。使える変数は `{amount}` `{money}` `{long}` `{short}` |
| LLM へ送る文章も直す | 既定 ON。古いセーブに残った「ゴールド」も送る直前に直す |

### `131_sharp_portrait`: 立ち絵の縮小・減色を通さず、顔の検出をやり直す

ゲームは Stable Diffusion で描いた NPC の絵を、保存する前にわざと荒くしている。
512x1024 で描いた絵を 165x330 まで縮め、2倍に伸ばして 16色に減色したものが立ち絵になり、
顔画像もそこから切り出される。
立ち絵 330x660 の中身は 165x330 ぶんの細かさしか無い（経路は GAME.md §2.30）。

この MOD は2つのことをする。

1. **縮小と減色を通さない**（設定で入れたとき）。背景を抜いた 512x1024 の絵がそのまま立ち絵になり、
   顔もそこから 256x256 で切り直す
2. **顔の検出が外れた回は、前処理した絵で検出をやり直す**。
   素のゲームは 16% の NPC で顔を見つけられず、全身の小さな縮小（32x64）を顔の代わりにする。
   やり直しで、外れたうちの7割ほどを拾う

効くのは**これから作られる画像だけ**。既に居る NPC の絵は荒いまま残る。
効くのは NPC の絵だけで、**敵・モンスター（衛兵や、NPC の戦闘用の絵も）と背景は触らない**。
戦闘画面の敵は素のドット絵寄りのまま。

| 設定 | 意味 |
| --- | --- |
| 立ち絵を荒くしない | 既定は切（ゲームのまま。330x660 のドット絵寄り）。入れると 512x1024 の絵がそのまま立ち絵になる。**縮小と減色は別々には切れない**。縮めた絵の減色だけ飛ばしても細かさは戻らず、縮小だけ飛ばすと 1024x2048 の 16色になる |
| 顔の検出をやり直す | 既定は入。ゲームが顔を見つけられなかった回だけ動く。検出は縮小の前の絵に対して走るので、立ち絵の設定と関係なく効く |

既定で効くのは顔のやり直しだけで、立ち絵の画風はゲームのまま。
ドット絵寄りの画風は縮小と減色が作っていたもので、通さなければ滑らかな絵になる。
滑らかな絵にしたいなら「立ち絵を荒くしない」を入れる。絵の見た目は変わる。

やり直しで拾った顔の1割ほどは、顔でないもの（暗い鎧・肩章など）を切ることがある。
素のゲームでは全身の縮小になっていた回なので、素より悪くはならない。
気になる個体は `out\sharp_portrait.log` の `箱` の座標で分かる。

顔のやり直しはゲームが同梱している `cv2` / `numpy` / `PIL` を使う。
ゲームが同梱をやめれば、やり直しだけが効かなくなり、素の結果に落ちる。

立ち絵を後から差し替える外部の道具（`InstantaleLauncher` の PortraitWatcher など）とは衝突しない。
あちらはゲームが書き終えた後に立ち絵を上書きするだけで、顔の切り出しには間に合わないので、
顔の側はこの MOD の持ち分になる。

##### 既に居る NPC の顔を切り直す（設定画面から）

MOD 本体はこれから作る絵にしか効かない。
既に居る NPC の顔を直すには、ローダの設定画面でこの MOD を選んで「設定…」を押す。
MOD の設定（上の2つ）もその画面で変える。

| できること | 内容 |
| --- | --- |
| 数える | 手元の全世界の NPC を、顔が切られているか・全身の縮小のままか・顔画像が無いかで数える |
| 検出し直す | 顔が見つかっていない個体（既定）か全員に、ゲームと同じ検出を素の絵で試し、外れたら前処理で拾い直す |
| 切り出し元 | 立ち絵（いまの見え方に合わせる）か、背景を抜いた元絵（立ち絵が荒くても顔だけ高画質に） |
| 検出だけ | 書かずに、何体で顔が見えるかだけ見る |
| 元に戻す | 書く前に `face_image.orig.png` を残す。1体ずつ、または控えのある全員を戻せる。前と今の顔を並べて見られる |

手元の Python に `cv2` が要る（ゲームの同梱は別の Python なので借りられない）。
無ければ画面に「cv2 を入れる」のボタンが出る。押すと `pip install "opencv-python-headless<5"` で入れ、
入ったら画面が開き直る（ネットワークを使う。それまでは設定の部分だけ使える）。
書くのは `worlds\<世界>\characters\<名前>\face_image.png` とその控えだけで、セーブは触らない。

記録は `out\sharp_portrait.log` に1体につき4〜5行（NPC の生成のたびにしか書かない）。

```
縮小: 512x1024 をそのまま通す
減色: 1024x2048 を控えの 512x1024 に戻す
顔: ゲームが見つけた (146, 33, 402, 289)
顔: (94, 21, 259, 186) を (146, 33, 402, 289) に戻して切り直した
```

#### 困ったとき

| 症状 | やること |
| --- | --- |
| **NPC の生成が進まない** | `out\live_crashes.log` に `Thread-N (generate_images)` のクラッシュが無いか見る。あれば縮小の工程の戻り値の形がゲームの更新で変わっている。この MOD を切って確かめる |
| ピクセル化した絵のまま | `out\sharp_portrait.log` に `減色: ... を控えの 512x1024 に戻す` の行が出ているか見る。無ければ経路を通っていない。行が出ているのに絵が荒いなら、その NPC の絵は前から在ったもの |

### `132_npc_variety`: NPC の外見・性格・経歴に種を渡す

LLM に NPC を作らせると、髪も瞳も肌も書かれず、役職の型で埋まる。
宿屋の主人は皺と灰色のローブ、鍛冶師は筋肉質でエプロン、書記官は眼鏡とインクの染みが町をまたいで再現され、
画像の頼み文もそれを写すので、立ち絵まで同じ顔になる（ローカル経路で確定した 124 人のうち髪色を書いたのは 15 人。
VERIFICATION_LOG.md §2.82）。

原因は頼み文にある。単体生成は名前・概要1行・ランクだけ、町生成は世界の概要1つで住民10人前後を1回で書かせる。
人を見分ける材料が渡っていない。
「没個性を避けよ」と言っても（`111_` の既定ルールに入っている）動かず、
「髪色を必ず書け」と要素名を足しても値は同じになる（宿屋の主人の瞳は 10 回とも「鋭い灰色」）。

この MOD は、人物ごとに**値を引いて渡す**。

- 外見9軸（髪色・髪の長さ・髪型・瞳・肌・体格・年齢の見え方・目立つ特徴・服）、
  性格6軸（口数・人との距離・大事にするもの・弱み・癖・気分の傾向）、
  来歴9軸（出自・過去の一件・ここにいる理由・隠し事・家族・前の生業・今の悩み・恩と恨み・町での評判）の表から語を引く
- 軸の順は混ぜ、性格は3つ・来歴は3つだけ渡す（全部渡すと書き出しが表の語に寄る）
- 目立つ特徴（顔を横切る傷・眼帯・入れ墨・片腕が無い）は 25% の人物にしか付けない。
  細部（欠けた前歯・短い指）は LLM も画像生成も描き分けられないので表に入れていない
- 鍵=値ではなく句点で繋いだ文で渡し、「見出しや「=」は書かない」と添える（鍵=値で渡すと本文に「髪=…」が写る）
- 町生成は必須施設の主5人・住民4人・冒険者3人を番号で名指しして人数ぶん渡す。生成される人数が少なければ余りは捨てられる

```
【この人物について決まっていること】
赤茶の髪を短く刈っている。鳶色の瞳。そばかすだらけ。小柄で丸い。左耳が欠けている。苔色の服。無口。金より義理。川向こうの漁村の生まれ。火事で店を失った。
これらを description・personality・look_description の文章に溶かして書くこと。見出しや「=」の形は書かない。
```

効き目はローカル LLM（Gemma4 26B）で測ってある（`tools\npc_variety_probe.py`。VERIFICATION_LOG.md §2.82）。
指定は 94〜99% で本文に載り、髪色・瞳・肌・体格が入った率は 18% / 3% / 3% / 9% から 97% / 96% / 96% / 97% へ、
役職の型の語は 59% → 15%、「鋭い眼光」は 17% → 3%。
この MOD の形（文で渡す・性格3軸・来歴2軸・髪3軸・年齢の軸・特徴は25%）で測り直しても役職の型の語 10%・「鋭い眼光」5% で、
本文に書式が写った人物は 0、短髪と編み髪の同居も 0、老人と子どもも素と同じ幅で出る（108人で特徴付きは 25人）。

対象は単体生成（`master_ai_npc_generater`）と町生成（`create_settlement_detail`）。
衛兵と闘技場の敵は頼み文の形が同じ「【生成するNPC】」でも触らない（あちらには「- 名前:」「- 概要:」が無く、
「衛兵NPC」「闘技場で戦う」の語がある。実機で衛兵に種が1回付いてから見分けを直した。VERIFICATION_LOG.md §2.82）。
`320_` の募集は自前の頼み文なので対象外。
効くのは新しく生まれる NPC だけで、既に世界に居る NPC は変わらない。

表は `runtime\mods\132_npc_variety\seeds.default.json`。
差し替えるときは同じフォルダに `seeds.json` としてコピーしてから編む（そちらが優先され、MOD を新しい版にしても消えない。
保存すると次の生成から効く）。
書式は `{"look": {"軸": ["句", ...]}, "personality": {...}, "description": {...}}` で、軸の名前は自由（表示には使わない）。
軸を `{"chance": 25, "rows": ["句", ...]}` の形にすると、その軸は人物ごとに 25% でしか付かない（同梱の「目立つ特徴」がこの形）。
`{"rows": [...], "drops": {"句": ["軸名"]}}` と書くと、その句を引いたときに後ろの軸を省ける
（同梱は「髪は短く刈っている」で「髪型」を省き、短髪の三つ編みのような矛盾を避ける。
節をまたいでもよく、「まだ子どもと言ってよい年頃」で来歴の「家族」「前の生業」「今の悩み」を省いて、子どもに元傭兵や借金の悩みが付かないようにしてある）。
`{"rows": [...], "not_for": {"owner": ["句"]}}` と書くと、その役の人物にはその句を出さない。
役は `owner`（町の必須施設の主）/ `resident` / `adventurer` / `single`（単体生成）の4つ。
句の並びの代わりに `true` を書くと、その役にはその軸ごと付けない。
同梱は施設の主に子どもの年齢を出さず（十代は出る。住民と冒険者には子どもも出る）、
単体生成には年齢の軸を付けない（概要に「中年男性」のように年齢が書かれていて、種と食い違うため）。
頼み文に載った語はそのまま世界に現れるので、読み物として置ける句にする。
性別は種を引く時点では決まらない（名前と概要からモデルが決める）ので、妻・夫・娘のように性別を決める語は句に入れない
（同梱は「連れ合い」「遠くに嫁いだ妹」の言い方にしてある）。
付けた種は `out\npc_variety.log` に残るので、セーブの look_description と突き合わせられる。

| 設定 | 意味 |
| --- | --- |
| 種を付ける割合（%） | 既定 100。人物ごとに引く。0 で素のゲームと同じ |
| 外見の軸をいくつ渡すか | 既定 9（全部）。目立つ特徴は表の側で 25% |
| 性格の軸をいくつ渡すか | 既定 3。6 で全部 |
| 来歴の種をいくつ渡すか | 既定 3。9 で全部 |
| 町生成で種を付ける住民の人数 | 既定 4 |
| 町生成で種を付ける冒険者の人数 | 既定 3（素のゲームが作る人数） |
| 付けた種を記録する | 既定 ON。`out\npc_variety.log` の `[SEED]` |

| 症状 | やること |
| --- | --- |
| 何も変わらない | `out\npc_variety.log` に `[SEED]` が出ているか見る。無ければ `[TABLE]` の行で表が読めているか、`modloader.log` の `armed on` で仕掛かっているかを見る |
| 本文に「髪=」のような書式が写る | 表の句に `=` や見出し語を入れていないか見る。同梱の表では出ない形にしてある |
| 老人や子どもばかりになる | 「年齢の見え方」の軸を `seeds.json` で薄くする（句を減らすか、`chance` で軸ごと間引く） |
| 子どもの役人が出る | 同梱の表では出ないようにしてある（`not_for`）。十代の店主は出る。冒険者や住民にも出したくなければ、その役を `not_for` に足す |
| 傷や眼帯の人物が多すぎる・少なすぎる | 「目立つ特徴」の `chance`（既定 25）を変える |
| 語がそのまま本文に出て読みにくい | 表の句を文に近い形へ書き直す。モデルは頼み文の語を写す |

### `111_llm_prompt_replace`: LLM への指示文を置換ルールで書き換える

ゲームが LLM へ送る文章を置換ルールで書き換える。
NPC の言動や要約の指示を調整するルールと、
ゲーム側の誤字・崩れた改行を直すルールが同梱されていて、そのまま効く。

はっきり違いが出るのは前者（LLM への指示そのものを書き換えるので、
使うモデルに依らず効く）。
後者は保険で、賢いモデルほど崩れた改行を自力で読み分けるため差は小さい。
JSON の書き方を直すルールも入っていたが、
既定では止めてある（VERIFICATION_LOG.md §2.24）。
出力の形は LLM 側の仕組みで既に保証されていて、意味が無いため。

自分で書き換えるときは、まず `runtime\mods\111_llm_prompt_replace\` を開く。
その中の `llm_replacements.default.txt` を、
同じフォルダに `llm_replacements.txt` としてコピーする。
編むのはそのコピー（そちらが優先され、MOD を新しい版にしても消えない）。
書き方は「置換前=>置換後=>確率」で1行1ルール。
保存すると次の応答から効く（ゲーム再起動は不要）。
`InstantaleLlmProxy` のルールファイルは書式が同じなので、
`llm_replacements.txt` として置けばそのまま動く。

LLM をローカル（llama.cpp）で動かす場合も、APIキーで外部サービスに繋ぐ場合も効く。
APIキー経由で効かなかったのは v1〜v3 の不具合。
v4 はプロバイダに依存しない形へ置き換え、v5 で取りこぼしをなくした。
効いているかは `out\prompt_bloat.log` に `[REPLACE]` が出ることで確かめられる。

> プロバイダを切り替えたら注入し直すこと。
> 送信の入口はプロバイダを選んだときに作られるので、
> 切り替えた後のぶんは入れ直すまで包まれない。

| 設定 | 意味 |
| --- | --- |
| 置換したことを記録する | 既定 ON。`out\prompt_bloat.log` の `[REPLACE]` |
| ルールの読込を記録する | 既定 ON。`out\prompt_bloat.log` の `[RULES]`（書式の誤りは切っても必ず残る） |

### `117_message_text_integrity`: 長い応答が途中で切れるのを直す

ゲーム本体は、1回の会話量が多いとラベルへ載せ切る前に本文を勝手にカットする。
1,000文字にも届かないことがある。
この MOD は保持している本文はそのままに、表示ラベルだけを末尾まで広げ直す。
それより前は省略表示にする。
入ったかどうかは `out\modloader.log` の
`message text integrity installed` の行で分かる。

| 設定 | 意味 |
|---|---|
| 表示する末尾の文字数 | 既定 1000。表示ラベルに載せる最新本文の上限 |

### `127_llm_response_speed`: ローカル LLM の応答を速くする

ローカル（llama.cpp）で遊んでいるときの応答を速くする。
設定は既定のままでよい。

ゲームは `llama-server` を「4スロットで1つの KV を共有する」形で起こす。
だが実際には並列でほとんど走らない（実測でリクエストの94%が逐次）。
この MOD は専用の1スロットで起こし直す。
窓の広さは変えないまま KV の確保量が減り、そのぶん速くなる。

効き方はモデルと環境による。

| モデル | VRAM に余裕あり | VRAM がぎりぎり |
| --- | --- | --- |
| gemma 系（SWA あり） | 生成 +3〜11% | さらに大きい（実測で最大 +40%） |
| SWA を持たないモデル | 変化なし（害も無い） | KV は減るので余裕が生まれる |

生成が長いほど、また会話が長く続くほど利得が大きくなる。

VRAM がぎりぎりの環境ほど大きく効く。
溢れた分は Windows が共有メモリへ逃がすため、
エラーにならず「異様に遅い」状態になる。
KV が減ればそもそも溢れなくなる。

クラウド（APIキー）で遊んでいる場合は何もしない。

> 効くのは次にサーバが起きるときから。
> 既に走っている `llama-server` の引数は変えられない。
> 注入してからゲームを起動するか、ゲーム側で LLM を開き直すこと。
> 効いたかどうかは `out\llm_speed.log` に `[REWRITE]` が出ることで分かる。

#### 窓を広げたいとき（上級者向け）

育った `life_log` を持つ NPC と会話すると、
『リクエストを再実行』の表示が出たまま進まなくなる。
プロンプトが窓（既定 16384 トークン、日本語でおよそ26,000字）を超えてサーバに撥ねられている状態で、
再実行しても同じ文章を送り直すだけなので必ず同じ所で止まる。
ゲームの設定画面からは変えられない（ゲームが `--ctx-size` だけを取り除く）。

「1リクエストが使えるトークン」を上げれば窓は広がる。
それでも既定の 0 のままにしておくことを勧める。
窓に比例して VRAM を余分に使い、
足りなくなると上に書いた「異様に遅い」状態へ落ちるため。
必要な量はモデルの構造で変わるので、勘で上げないこと。

上げる場合は `tools\llm_ctx_probe.bat` を実行する。
ゲームを終了した状態で走らせると、
候補を順に試して**そのマシンで安全に使える最大値**を出す。
数分かかる。

| 設定 | 意味 |
| --- | --- |
| 同時に持つスロット数 | 既定 1（この MOD の本体）。変える理由はほぼ無い。0 にすると素のゲームと同じ共有4本に戻す。2 以上は窓を保つために VRAM を余分に使い、既定より重くなる |
| 1リクエストが使えるトークン | 既定 0（ゲームの値のまま触らない）。上げるときは `llm_ctx_probe.bat` の出す値を使う |
| 書き換えず記録だけする | 既定 OFF。ON にすると実際の起動引数を記録するだけで何も変えない |

### `112_ui_text_spacing`: 広すぎる本文の行間を詰める

LLM の応答やシステムメッセージの行間を詰め、段落の間に入る空行を減らす。
画面に出る見た目だけを変えるので、会話履歴やセーブの中身は元のまま。

| 設定 | 意味 |
| --- | --- |
| 行間 | ゲームの元の値に対する倍率（既定 0.8）。`1.0` でゲームのまま、空欄なら行間に触らない |
| 段落の間に残す空行の数 | 既定 0（空行なし）。`1` でゲームのまま、空欄なら本文の改行に触らない |

元の行間の値は `out\text_spacing.log` に出る（ゲームの値は `1.8`。
既定の 0.8 倍で `1.44` になる）。
詰めすぎ・緩すぎと感じたら 0.7〜0.9 で調整する。

### `113_ui_text_expand`: 本文の表示域をボタンで広げる

画面の隅に小さなボタンが1つ増える。
押すと本文（情景描写・LLM の応答）の枠が広がってまとめて読めるようになり、
もう一度押すと元の寸法に戻る。
広げるのは枠だけで、本文・会話履歴・セーブには触らない。
広げたままでも遊べる（選択肢は今までどおり使える）。

| 設定 | 意味 |
| --- | --- |
| 広げたときの幅 | 元の枠の何倍か（既定 1.0 ＝ 幅には一切触らない）。上げると右へ広がる |
| 広げたときの高さ | 元の枠の何倍か（既定 4.0 ＝ 上限）。下端は動かず上へ伸びるので、入力欄や状態表示はずれない。画面に入る分（窓の 98%）で頭打ち |
| ボタンの置き場所 | キャラの欄（画面右下の立ち絵と HP）の上（既定）／枠の右上（本文の枠の内側。枠が伸びると一緒に上がる）／右上／左上／右下／左下 |
| ボタンの大きさ | px（既定 32）。アイコンは正方形、文字なら幅はこの2倍 |
| ボタンの絵柄 | 二重山形（既定）／山形／矢印／伸縮／枠／文字。背景なしの白い線で描き、押すと上下が入れ替わる |
| アイコンの線の太さ・濃さ | 既定 2.0px / 0.85。背景に溶けて見にくいときに上げる |
| ボタンの文字 | 絵柄に「文字」を選んだときだけ使う（広げる前「拡張」／広げた後「戻す」） |
| 最初から広げておく | 既定 OFF |

倍率をいくつにしても窓の外へははみ出さない（窓の 98% で頭打ち）。
元の枠の寸法と、実際に広げた寸法は `out\text_expand.log` に出る。
ボタンが他の表示に隠れて押せないときは、置き場所を変えるか高さを小さくする。

ウィンドウの大きさを変えても、ボタンの位置と枠の広がりは追従する（広げたままでも一度たたんで、
新しい寸法で広げ直す）。

本文の枠と一緒に、
その枠線・背景も広がる（同じ場所に重なっているものをまとめて扱う）。
もし本文だけが広がって枠線が元のままなら、
`out\text_expand.log` の `frame neighbours:` の行を見ると、
枠のまわりに何が置かれているかが分かる。

### `114_ui_input_focus`: 自由入力のあと入力欄にフォーカスを戻す

自由入力を送るたびに入力欄からフォーカスが外れ、
次の一言を打つのに毎回クリックし直していたのを、
送ったあともそのまま打てるようにする。
Enter で送っても、送信ボタンを押しても戻る。
入力欄の中身や送信の仕組みには触らない。

LLM の応答を待つ間はゲームが入力を塞ぐので、その間は戻さず、応答が返った瞬間に戻る。
別の窓が開いているとき・他の入力欄に打っているときも横取りしない。

| 設定 | 意味 |
| --- | --- |
| フォーカスが外れたら戻す | 既定 ON。送信でも、画面のどこかを触ったときでも入力欄に戻る。OFF にすると次の項目だけが効く |
| 応答待ちが明けたら戻す | 既定 ON。応答が返って入力が解けた瞬間に戻す |
| 戻すまでの待ち（秒） | 既定 0.05。戻ってもすぐまた外れるようなら 0.1〜0.2 に上げる |

フォーカスが常に入力欄にあるので、
キーボードで他の操作をしている場合はそちらが効きにくくなる。
そのときは「フォーカスが外れたら戻す」を OFF にすると、送信の後だけ戻る形になる。
どの入力欄を掴んでいるかは `out\input_focus.log` に出る。

### `115_ui_item_list_fit`: はみ出すアイテム一覧を画面内に収める

入力欄の左下のアイコンから開くアイテム（スキル）の一覧は、
入力欄を下端にして上へ積まれる。
持ち物が増えると画面の上端を突き抜け、先頭の数件が画面の外に出て押せなくなる。
何件で溢れるかは画面の解像度で変わるので、そのときの窓の高さに合わせて収める。

収め方は列を増やすことだけ。
一覧が1列で入り切らなくなったら 2列・3列…と折り返す。
位置も行の大きさも文字の大きさも変えないので、見え方は今までのまま高さだけが減る。
行は1件も隠さない。

| 設定 | 意味 |
| --- | --- |
| 一覧が画面の高さに占めてよい割合 | 既定 0.9。小さくすると早く2列目へ折り返す |
| 列数の上限 | 既定 4。1 にすると列を増やさない（＝この MOD は何もしない） |
| 列数を固定する（0 で自動） | 既定 0 ＝ 件数と画面の高さから自動。2 にすると、収まっていても常に2列 |

一覧が1列で収まっているときは何も触らない。
上限の列数でもまだはみ出す件数のときは `out\item_list.log` にその旨が出るので、
「列数の上限」を上げる。
見つけた一覧の構成（型・親・行数・矩形）も同じログに出る。

### `124_ui_craft_window_fit`: クラフト画面の枠の重なりを直す

クラフト画面は左から「所持品」「クラフト」、その右に生成先のグリッドが並び、
あいだに矢印と「作成」ボタンが置かれている。
ボタンは枠線を持つので、置き場所がグリッドと重なると枠が2本交差して見える。
矢印のほうは生成先グリッドの裏に埋もれて読めない。
ボタンの幅もグリッドの隙間もその時の窓の大きさで決まるので、
解像度によって起きたり起きなかったりする。

ボタンと矢印を、重なっているぶんだけ動かす。
グリッドは1つも動かさない。
順に、

1. ゲームが置いた位置にいちばん近い空きへ滑らせる（元の位置が空いていれば何もしない）
2. その空きに入らなければ、隙間の幅までボタンを詰める
3. 詰めても入らなければ、グリッドの下（入らなければ上）へ逃がす

遠くの広い空きへ飛ばすより、近くで詰めるほうを選ぶ。
ボタンと矢印は「クラフト」と生成先のあいだに在ってこそ意味を持つため。
矢印はボタンを片付けた後に、ボタンの居場所も避けて置く。

| 設定 | 意味 |
| --- | --- |
| 枠と枠の間に残す隙間（px） | 既定 6。0 にすると枠線どうしが接する |
| ボタンを詰めてよい下限（元の幅に対する割合） | 既定 0.6。1.0 にすると幅を変えず、代わりにグリッドの下へ逃がす |
| 矢印も動かす | 既定 ON。OFF にすると矢印は動かさず、「ボタンが避ける相手」としてだけ数える |

重なっていなければ何もしない。
測った矩形と、何をしたかは `out\craft_window.log` に出る。
印は `clear` ＝ 重なっていない、`slid` ＝ 滑らせた、`narrowed` ＝ 詰めた、
`moved` ＝ 上下へ逃がした。

### `116_ui_party_expand`: 4人目以降の仲間も表示する

仲間を3人雇って4人パーティになっても、画面右のパーティ欄には3人までしか出ない。
ゲームが欄の枠を3つしか作らないため。
名簿から漏れているわけではなく、会話と戦闘は4人目を含めて進んでいる。

4人目が居るときだけ、パーティ欄のすぐ上に小さなボタンが1つ出る。
押すと欄が上へ伸びて足りないぶんの枠が現れ、もう一度押すと元の3枠に戻る。
1人ぶんの大きさは変わらない（欄が伸びるだけ）。
増えた枠も押せば、その仲間との会話に入る。

元から出ている3人の枠は1ドットも動かない。
増えた枠にはゲームと同じ枠線が付く。
仲間を雇った・別れた・入れ替えたときは、その場で枠の数と中身が追う。

広げると、そこに元から在ったものが欄の下に入る。
始末は相手によって2通り。

- ゲームの選択肢ボタンには触らない。
  代わりに、新しく覆った場所を黒い板で塞ぐ。
  下の文字は透けず、
  そこを押しても板で止まる（欄の枠を押したときは今までどおり会話に入る）。
  戻すと板を外すだけなので、ゲーム側の状態は一切書き換わらない
- 他の MOD が足したボタン（既定では `113_ui_text_expand` の切り替えボタンがちょうどこの位置に出る）は、
  広げている間だけ見えなくなり押せなくなる。
  戻すと元に戻る

| 設定 | 意味 |
| --- | --- |
| 広げたときに出す人数の上限 | 既定 8。画面に入る行数のほうが少なければそちらで頭打ち |
| 広げている間、重なるボタンを隠す | 既定 ON。OFF にすると、隠れたボタンがそのまま押せる状態で残る |
| 足した枠の立ち絵の入れ方 | 枠に収める（既定・縦横比のまま枠内に収める）／枠いっぱい（縦横比を無視して枠を埋める。元の3枠は絵を切り取って埋めているので、そちらに近づけたいとき） |
| ボタンの置き場所 | 帯の上（既定・右寄せ）／帯の右上（欄の内側）／右上／左上／右下／左下 |
| ボタンの絵柄 | 二重山形（既定）／山形／矢印／人／枠／文字。背景なしの白い線で描き、押すと上下が入れ替わる |
| アイコンの線の太さ・濃さ | 既定 2.0px / 0.85 |
| ボタンの大きさ | px（既定 32） |
| ボタンの文字 | 絵柄に「文字」を選んだときだけ使う（広げる前「仲間」／広げた後「戻す」） |
| 収まっているときもボタンを出す | 既定 OFF（3人までのときは出さない） |
| 最初から広げておく | 既定 OFF |

名簿・セーブ・戦闘には触らない。
増やした枠は、今そこに在る枠を実行時に複製して作る。
見つけた欄の構成と、複製した枠に誰を入れたかは `out\party_expand.log` に出る。
4人目の枠が空のまま出るときは、そのログの `cell fields:` の行を見ると、
枠のどこに何を入れているかが分かる。

### `121_ui_character_sheet`: 人物欄に手配度・スキル・特性を出す

> `317_reputation` を入れていると、レベル行の続きに二つ名が出て、
> その右に引き直しのボタンが付く（控えのファイルを読むだけなので、
> あちらを切れば何も出ない）。

プレイヤーのプロフィール画面を左・上・下へ広げ、そこに手配度・スキル・特性を足す。
素のプロフィール欄は右半分が能力値と空の箱、左半分が出自と健康状態だけで、
キャラクタが持っている手配度・スキル・特性はどこにも出ていない。

特性はゲームが作ったまま一度も使っていない空の箱を借り、
手配度とスキルは新しく2枚足す。
文字の書体・大きさ・色は隣の健康状態の欄から写すので、
見た目はゲームのまま変わらない。
枠線もゲーム自身の描画を借りている。
能力値だけは中央寄せから左詰めに直す（列に並べると中央寄せは浮いて見え、
書体によっては右端が欠けるため）。
出自・手配度・能力値の3列は上端を揃えてある。

手配度は土地ごとに並ぶ（ダンジョンは除く）。
0 未満が犯罪者で、平常値は 10。
どの土地でいくつ手配されているかは、ここで初めてまとめて見られる。

立ち絵は人物欄の外にあるので動かない。
広げるのは左・上・下で、右は立ち絵に被らないところで止めてある。

| 設定 | 意味 |
| --- | --- |
| 枠の左端／右端 | 画面幅に対する割合（既定 0.02 / 0.645）。左端は画面下のステータス欄に揃え、右端は立ち絵の手前 |
| 枠の上端／下端 | 画面高さに対する割合・上から測る（既定 0.03 / 0.65）。下端は画面下の情報欄の手前 |
| 手配度に並べる土地の数の上限 | 既定 24。箱に入り切らないぶんは並べない |

人物欄はゲームが開くたびに寸法を入れ直すので、この MOD も開いた直後に毎回当て直す。
窓の大きさを変えたときも同じ。
遊んでいる途中で MOD を外すと、
広げた寸法はその回のあいだ戻らない（ゲームを起動し直せば戻る）。

#### 困ったとき

| 症状 | 見るところ |
| --- | --- |
| 欄が広がらない | `out\modloader.log` の `character sheet: panel at ...` の行。出ていなければ人物欄を掴めていない |
| 他の欄に食い込む | 同じ行に実際の四辺が出る。`枠の下端`（既定 0.65）を小さくすると上へ戻る |
| 手配度が空のまま | `character sheet: N area(s)` の N が 0 なら、その土地でまだ手配度が付いていない |

### `118_batch_message_render`: 本文の出し方（逐次／一括）と既読の色を選ぶ

本文の出し方を選べるようにし、読み終わった本文を灰色にする。
会話履歴やセーブ本文は変えない。

| 設定 | 意味 |
| --- | --- |
| 本文の出し方 | `click`（既定）／`always` |
| 古い本文の見分け方 | `seconds`（既定）／`sessions` |
| 白色を維持する秒数 | 既定 10.0。見分け方が `seconds` のとき |
| 白色を維持するセッション数 | 既定 1。見分け方が `sessions` のとき |

`click`（既定） はゲーム本来の1文字ずつの打ち出しをそのまま使い、
打っている最中に画面のどこかをクリックすると、残りを一度に出して打ち終わりにする。
クリックは横取りしないので、そのまま選択肢を押してもよい。
ホイールの回転は打ち切りにならない（本文を読み返しているだけなので）。

`always` は文字単位の再描画を止め、本文を一括でテクスチャへ反映する。
新着部分の先頭へスクロールした後、覆いを1行ずつ外して末尾まで表示する。
新着位置を見失わず、最終行が先に見えることもない。
新着範囲を特定できない場合だけ短いフェードへ戻る。

ゲームは1文字足すたびに本文ラベル全体のテクスチャを作り直しており、
その塗り直しが打ち出しの時間の大半を占める。
v1.3.0 で `112_` / `117_` の二度手間を外し、
1文字あたり 8.1 ミリ秒（打ち出し間隔の21%）まで下がった。
残りはこの作り直しのぶんなので、そこから先を詰めたい場合だけ `always` にする。

読み終わった本文は50%の灰色にする。
どこからが「読み終わった本文」かは2通りで選べる。
`seconds` は追加からの経過時間、`sessions` はその後に本文が何回追加されたか（本文1つ＝1セッション。1なら最新の本文だけが白、
3なら直近3つが白のまま残る）。
どちらでも色が変わるのは本文が追加された瞬間だけで、読んでいる最中に色は動かない。

### `122_ui_conversation_log`: 流れた本文を後から読み返す

本のアイコンが1つ増える。
押すと、これまで画面に流れた本文（情景描写・LLM の応答・システムメッセージ）が古い順に並んだ窓が開き、
上へ遡って読み返せる。
もう一度押すと閉じる。
ゲームの本文・会話履歴・セーブには触らない（読み取って控えるだけ）。

ゲーム自身は流れた本文をどこにも残さないので、
次の本文が来ると前のものは確かめようがなくなる。
会話の履歴も、その会話を閉じた時点で捨てられる。

アイコンは `113_ui_text_expand` が入っていればそのすぐ左に、
入っていなければ 113 と同じ場所（本文の枠の内側・右上）に出る。
113 のボタンが動けば一緒に動き、高さもそちらに揃う。

控えは世界ごとに `state\conversation_log\<世界名>.jsonl` へ残る。
ゲームを閉じても次に遊ぶときまで残り、`out\` を掃除しても消えない。
読み返しが要らなくなったらフォルダごと消してよい（ゲームの側には何も残らない）。

| 設定 | 意味 |
| --- | --- |
| ボタンの置き場所 | 113の左（既定）／枠の右上／右上／左上／右下／左下 |
| ボタンの絵柄 | 本（既定）／本（閉じた）／一覧／吹き出し／文字。背景なしの白い線で描く |
| アイコンの線の太さ・濃さ | 既定 2.0px / 0.85。背景に溶けて見にくいときに上げる |
| ボタンの高さ | px（既定 32）。113 の隣に並ぶときはそちらの高さに合わせるので使われない |
| 113 のボタンとの間隔 | px（既定 6） |
| 残しておく本文の件数 | 既定 500。超えたぶんは古いほうから落ちる |
| 日時を出す | 既定 ON。本文ごとに `── 08-06 12:34 ──` の見出しが付く。OFF にすると本文どうしは空行1つで区切られる |
| 窓に白い枠を付ける | 既定 ON。窓の縁に白い線を1本引く。背景との境目が分かりにくいときに |
| 窓の文字の大きさ | 本文の何倍か（既定 1.0 ＝ ゲームの本文と同じ大きさ）。一度に読める量を増やしたいときだけ下げる |
| ボタンの文字 | 絵柄に「文字」を選んだときだけ使う（既定「記録」） |

窓を開いたままでも遊べる状態ではない（窓を閉じるまで操作は窓の側に移る）。
開いている間に新しい本文が来たら、いちばん下まで読んでいたときだけ下へ追従する。
途中を読んでいる位置は動かさない。

#### 困ったとき

| 症状 | 見るところ |
| --- | --- |
| アイコンが出ない | `out\modloader.log` の `conversation log: keeping the last ...` の行。出ていなければ MOD が入っていない |
| 窓が空のまま | `out\conversation_log.log` の `loaded N entr(y/ies)` の行。まだ本文が流れていないか、世界名が変わっている |
| ボタンが 113 の隣に来ない | 同じログの `button placed by the ...` の行。`beside 113` でなければ 113 のボタンを掴めていない |
| 古い本文が出ない | 窓に組む量には上限（20万字）がある。あふれるのは古いほうで、`state\conversation_log\<世界名>.jsonl` にはそのまま残っている |

### `119_fix_crime_attribution`: 他人の犯罪が主人公のものになるのを直す

NPC や第三者が起こした犯罪を、ゲームが主人公の犯罪として扱ってしまうのを防ぐ。
記録は `out\crime_attribution_fix.log`。
判定を取り違えて本物の犯罪を消すより、誤判定を残してログに出す方を選ぶ作りなので、

ローカル（llama.cpp）でも、APIキーで外部サービスに繋いでいる場合でも効く。
v1 はローカルの1か所しか見ていなかった。
APIキー経由では、判別の目印をプロンプトへ入れる処理が走らない。
そのため、この MOD は何もせず素通しになっていた（`crime_attribution_fix.log` に
`marker_missing` だけが並ぶ）。
v2 で、`111_llm_prompt_replace` が使っているのと同じ仕掛け口を共有して直した。

### `300_event_facility_arrival`: 施設でNPCから話しかけてくる

宿屋や店へ入ると、そこに居る NPC の方から会話を始めてくることがある。
ゲーム本来の会話なので、立ち絵と履歴が普通に付く。

| 設定 | 意味 |
| --- | --- |
| イベントの出方 | 会話が始まる（既定） / 情景描写に一言足すだけ |
| 発生率を固定 | 空欄なら施設ごとの既定値。`1.0` にすると必ず発生（動作確認用） |
| 同じ施設で続けて出さない訪問回数 | 一度出たら、その施設に何回入るまで出さないか（既定 2 ＝ 3回に1回まで）。`0` で毎回抽選 |
| NPCから話しかけた体裁にする | 既定 ON。切ると、こちらから話しかけたときと同じ第一声になる |
| 無視された相手が黙るまでの回数 | 話しかけられて一言も返さずに終えた回数（既定 2）。達した相手はその世界で二度と声をかけてこない。`0` で止めない |
| 施設ごとの発生率 | 宿 0.50 / ギルド 0.30 / 雑貨屋 0.25 / 専門店 0.25 / 鍛冶屋 0.15 / 診療所 0.20 / 市政庁 0.25 / 闇市 0.20。`0` にするとその種類の施設では出なくなる |

> 発生率は「その施設に入った1回あたり」の値。
> 同じ宿に何度も寄れば、そのたびに抽選する。
> 同じ相手に何度も話しかけられると感じたら、**「同じ施設で続けて出さない訪問回数」を増やす**。
> 数えているのはその施設への訪問回数なので、間に別の場所へ寄っても回数は進まない。

> 相手を黙らせたいときは、返事をせずに会話を終える。
> 既定では2回でその NPC は声をかけてこなくなる。
> こちらから話しかける分は今までどおりで、止まるのは「NPC の方から始まる」イベントだけ。
> 数えた結果は `state/arrival_event/` に世界ごと残るので、ゲームを閉じても続く。
> やり直したいときはそのファイルを消す。

#### 困ったとき

| 症状 | やること |
| --- | --- |
| NPC の立ち絵が消えず、移動しても付いてくる | その NPC ともう一度会話して、普通に「会話を終了する」を押す |
| 一度戦闘したらNPCから話しかけられなくなった | `107_fix_battle_flag_stuck` を入れて注入し直す |

### `301_quest_from_conversation`: 会話から依頼を受けられる

会話中に「依頼を受ける」が出る。
いま話した内容から依頼を1件作らせることもできる。

会話から開いた依頼一覧には、**その相手の依頼と「やめる」しか出さない**。
ゲーム自身の「クエストを探す」も、他の MOD が掲示板に足したボタンも出ない（会話の流れで受注する画面なので、
そこで土地の依頼を新しく探し始めると噛み合わない）。
ギルドの「クエスト掲示板」から普通に開いたときは今までどおり全部出る。

依頼を片付けると、そのことが依頼人との会話に伝わる（版2）。
それまでは、クリアしてから依頼人に話しかけても
「まだ出発していないのか」と言われた。
会話に毎回渡っている4つの欄のどこにも依頼の結末が入らないため、
NPC の側は依頼を頼んだところで時間が止まっている。
伝わるのはその相手に出してもらった依頼だけで、判定は上の絞り込みと同じ。
自分から話を切り出させはしない。
食い違うことを言わなくなるだけで、話題にするかは会話の流れ任せ。

仲間になっている NPC は依頼人から外れる（既定）。
同行している相手に依頼を出してもらうと、受注した時点でその相手は隣に居る。
依頼人が現地へ付いて来ている形になるので、
パーティに居る間は「依頼を受ける」も「この話から依頼を作る」も出さない。
外れてまた話しかければ、今までどおり出る。

| 設定 | 意味 |
| --- | --- |
| その NPC の依頼だけを見せる | 既定 ON。初対面だと一覧が「この話から依頼を作る」だけになるので、全部見たいときは OFF |
| 「この話から依頼を作る」を出す | 既定 ON |
| 一覧に並べる依頼の数 | 既定 8 |
| 依頼を作るのに使う会話の発言数 | 既定 12。多いほど話の流れを汲むが、生成が長くなる |
| 同じく文字数の上限 | 既定 2500 |
| 会話の内容を覚えている移動回数 | 既定 3。`0` にすると、会話を出た時点で作れなくなる |
| 仲間になっている NPC は依頼人にしない | 既定 ON。同行中の相手との会話には「依頼を受ける」も「この話から依頼を作る」も出さない。切ると仲間からも依頼を受けられる |
| 依頼人の人物像を依頼の生成に使う | 既定 ON。`311_npc_profile_memory`（NPCが会話を覚える）が覚えた人物像を添えて、依頼人の口ぶりをその人物に寄せる。その MOD を入れていなければ何も起きない |
| 片付いた依頼を依頼人との会話に伝える | 既定 ON。その相手に出してもらった依頼をクリアしていると、会話にその事実が伝わる。切ると、クリア済みでも「まだ出発していないのか」と言われる |
| 会話に伝える依頼の件数 | 既定 3。新しいものから数える。`0` にしても伝わらなくなる |

#### 困ったとき

| 症状 | やること |
| --- | --- |
| 依頼一覧に「この話から依頼を作る」しか出ない | その NPC の依頼がまだ無い状態。すべて見たいなら「その NPC の依頼だけを見せる」を切る |
| 会話から開いた一覧に「クエストを探す」が出ない | 仕様。会話から受注する画面なので、依頼と「やめる」だけに絞っている。ギルドの掲示板から開けば出る |
| 依頼人の人物像が反映されている気がしない | `out\quest_offer.log` の `inject:` の行に `persona=N chars` が出る。`0` なら記録がまだ無いか、`311_` を入れていない |
| クリアしたのに「まだ出発していないのか」と言われる | `out\quest_offer.log` の `starter:` / `facilitator:` の行を見る（第一声か、そのあとの入力か）。`no completed quest for` なら、その依頼が `state\quest_clients.json` に無いか、依頼の状態がまだ完了になっていない。`+N chars into profile` が出ているなら渡ってはいるので、モデルが古い記憶の方を取っている |
| 別の人が出した依頼まで片付いたことになっている | 依頼人の名前がその NPC と同じ。ゲームが元から持っている依頼の依頼人名は実在の NPC と結び付いていないので起こりうる。「片付いた依頼を依頼人との会話に伝える」を切ると止まる |

### `307_area_move_dungeon`: 第3の移動手段「危険な道を行く」を足す

土地を移るとき、徒歩・馬車に並んで 「危険な道を行く」 が出る。
選ぶと、その2つの土地を繋ぐ道中を舞台にしたクエストがその場で作られ、
いつもの受注画面が開く。
踏破すれば目的地に着き、放棄すれば出発地に留まる（移動そのものが失敗する）。

道の難易度は移動元と移動先の間から抽選される。
安全な村から危険な土地へ向かえばその中間、
隣の同じような町へ行くだけなら軽い道になる。

危険だが早い。
最後のエリア移動が 14日（馬車と同じ）で済む。
道中のクエストそのものは日数を進めない。
徒歩の3ヵ月を待たずに済み、馬車の 1000G も要らない代わりに、道中で戦うことになる。

踏破して「帰還する」を押し、
報酬を受け取った直後にそのまま目的地へ移動する（元の街を歩き直す必要はない）。
道中のクエストの生成には数分かかることがある。

体力が3分の1を切っていると行けない。
「この道を行くには、今は体力が無い。」と出て、
ダンジョンは作られない（宿で休むこと）。

依頼の説明の末尾には、LLM が書いた文に続けて次の1行が足される。
掲示板に残った道を後から見ても、それが移動の依頼だと分かる。

```
※このクエストをクリアすると「澱みの宿場町」に移動します。
```

移動の紐付けが切れたとき（別の依頼を受けた・普通に移動した・道を選び直した・放棄した）は、
この一文も消えてただの依頼に戻る。
LLM が書いた本文はそのまま残る。

| 設定 | 意味 |
| --- | --- |
| 道の難易度の決め方 | 既定「移動元と移動先の間から抽選」。「移動先に合わせる」「高いほう」も選べる |
| 難易度に足す下駄 | 既定 0。道中を素の依頼より重くしたいときに足す |
| 道にかかる日数 | 既定 14（馬車と同じ）。エリア移動にかかる日数になる（上限ではない）。道中のクエストは日数を進めない。0 なら日数が進まない |
| 踏破した後の移動手段 | 既定「徒歩」（所持金が要らない。日数は上の設定になる）。「馬車」にすると 1000G がかかる |
| 体力がこの割合を切ったら断る | 既定 33（＝3分の1）。下回っていると「この道を行くには、今は体力が無い。」と出て道を行けない。0 にすると体力を見ない |
| 依頼概要に移動先を明記する | 既定 ON。依頼の説明の末尾に「※このクエストをクリアすると「〜」に移動します。」が付く |
| 「長旅だ…」を出さない | 既定 ON。踏破した後の移動で「徒歩で目指す。長旅だ...」が出るのを伏せる（普通の徒歩・馬車の移動はそのまま） |
| 出発時に道の危険度を出す | 既定 ON。「危険度: 6 ／ かかる日数: 14日」と出る |

#### 困ったとき

| 症状 | やること |
| --- | --- |
| 踏破したのに目的地に着かない | 「帰還する」を押して報酬が出た直後に移動する。動かないときは `out\road_travel.log` に `cleared:` の行があるか見る（無ければ、その道のクエストとして認識されていない） |
| 道を選んだ直後に MOD を入れ直した | 入れ直しをまたいでも道は続く（控えは `state\road_travel.json`）。道中のクエストを進めていれば、次に画面が切り替わったときに拾い直す（`armed: the game is running quest ...`） |
| 受注をやめた道の依頼が掲示板に残る | 生成された時点で世界に登録されるので残る。依頼の説明に移動先が書いてあるので、後から受ければ踏破で移動する。ただしその場を離れる（別の依頼を受ける・普通に移動する・道を選び直す）と移動の紐付けは切れ、説明の一文も消えてただの依頼になる |
| ゲームを再起動したら着けなくなった | 道中の控えは `state\road_travel.json` に残るので、消していなければ続きから着ける |
| 日数が上限を超えて進んでいる | `out\road_travel.log` に `days:` の行が出ているか見る。1行も出ていなければ、お使いのゲームの日数送りが `elapse_days` を通っていない（`WARN arrived: elapse_days was never seen` が出る）。その場合は「踏破した後の移動手段」を馬車にすると 14 日で着く |

### `308_battle_damage_display`: 戦闘のダメージ表示

戦闘の地の文の後ろに、その1手で実際に動いた HP が出る。
自分や味方が敵に与えたぶんも、敵が自分や味方に与えたぶんも、同じように数字で出る。

```text
テストプレイヤーは剣を振り抜き、斥候の脇腹を裂いた。
ゴブリンの斥候 に 23 のダメージ（残り HP 11/34）
テストプレイヤー は 8 のダメージを受けた（残り HP 52/60）
```

毒や状態異常による増減（`319_battle_tactics` が効かせているもの）には、
何によるダメージかが付く。地の文と関係なく数字が出ても、理由が分かる。

```text
エリス は 泥の浸食 で 29 のダメージを受けた（残り HP 1498/1560）
```

とどめの一撃は残り HP の代わりに撃破と出る。

```text
ゴブリンの斥候 に 11 のダメージ（撃破）
```

行の頭に記号を付けたいときは設定から選べる（既定は付けない）。

```text
● ゴブリンの斥候 に 23 のダメージ（残り HP 11/34）
```

毒などの継続ダメージや回復も同じ仕組みで出る（HP が動いたぶんを測っているので、
どういう理由で動いたかは問わない）。
ゲームの側は何も変えない。
読むのは HP だけで、書くのは画面のこの数行だけ。

| 設定 | 意味 |
| --- | --- |
| 行の頭に付ける記号 | 既定「なし」。`- * > ・ → ※ ● ◆ ■ ★` から選べる（選ぶと記号と半角空白が各行の頭に付く）。機種依存文字は候補に入れていないので、どれを選んでも文字化けしない |
| 敵に与えたダメージを出す | 既定 ON |
| 自分や味方が受けたダメージを出す | 既定 ON |
| 回復も出す | 既定 ON。HP が増えたときも1行出る |
| 残りの HP を添える | 既定 ON。「（残り HP 11/34）」の部分 |
| 身体の負傷の増減も出す | 既定 OFF。HP とは別の数字なので普段は邪魔になりやすい |
| この値未満の増減は出さない | 既定 1。0 にすると 0 ダメージの行まで出る |

#### 困ったとき

| 症状 | やること |
| --- | --- |
| 戦闘しても数字が出ない | `out\battle_damage.log` を見る。`battle start:` の行すら無ければ、お使いのゲームでは戦闘の入口が違う。行はあるのに数字が出ないなら、HP の持ち方が違うので、このログを添えて報告してほしい |
| 残りの HP が「11/34」でなく「11」と出る | お使いのゲームでは最大 HP の呼び名が違う。ダメージの数字自体は正しい |
| 数字が地の文より先に出る | 出す位置がお使いのゲームと合っていない。同じくログを添えて報告してほしい |

### `309_office_pardon`: 役場で罰金を納めて手配を解く

その土地で手配されている（手配度が 0 未満）と、
役場の選択肢に「罰金を納めて手配を解く」 が出る。
押すと金額を出して確認し、払えば手配度が平常値（10）に戻る。

```text
[役場]  労働の募集をみる / 市民権の発行 / 罰金を納めて手配を解く(10,000G) / 出る / 会話する
                                              ↓
                        10,000ゴールドを納める / やめておく
                                              ↓
                        所持金 -10,000 ／ この土地での手配は取り消された
```

扱うのは今いるエリアの手配だけ。
手配は土地ごとに別々に付くので、よその土地の分はその土地の役場で払うことになる。

罰金は 手配度1あたり 1000ゴールド（既定）。
手配度が3なら 3,000ゴールド。
所持金が足りなければ何も起きない（金と手配度は動かない）。

| 設定 | 意味 |
| --- | --- |
| 手配度1あたりの罰金 | 既定 1000。0 にすると無料で解ける |
| 手配とみなす手配度 | 既定 0（手配度が 0 未満なら犯罪者）。罰金はこの値との差で決まる |
| 罰金を納めた後の手配度 | 既定 10（素の平常値）。今の値より低い値を入れても下がらない |
| 役場に入ったら手配を知らせる | 既定 ON。手配されているときだけ1行出る |

#### 困ったとき

| 症状 | やること |
| --- | --- |
| 役場に入っても選択肢が出ない | その土地では手配されていない（手配度が 0 以上）ときは出ない。手配されているはずなのに出ないときは `out\office_pardon.log` を見る。`offer:` の行が1つも無ければ、お使いのゲームでは手配度の持ち方が違うので、このログを添えて報告してほしい |
| 会話中に出ない | 会話・戦闘・買い物の最中は出さない。会話を終えれば出る |
| 払ったのに次に遊んだら戻っている | ゲームがセーブする前に終了している。罰金も一緒に戻っているので損はしない（この MOD からはセーブを書かない） |
| よその土地の手配が消えない | 仕様。手配は土地ごとで、その土地の役場でしか解けない |

### `311_npc_profile_memory`: NPCが会話の内容を覚える

会話1ターンごとに、バックグラウンドの LLM が2つの記録を更新する。

- 人物像: その NPC がどういう人物か（性格・好み・経歴・目標）
- あなたについての記録: その
  NPC から見たあなた（呼び方・抱いている感情・交わした約束・貸し借り）

どちらも以降の会話でゲーム本体のプロフィール欄に毎回載るので、
前に話した内容を踏まえた受け答えになる。
2つに分けてあるのは、
1つにまとめると要約のたびに「約束した」の類が人物像に呑まれて真っ先に消えるため。

**出来事のあらすじは覚えない**（v3）。
会話の経過はゲーム自身が覚えていて、同じ相手との次の会話に毎回載る（GAME.md
§2.25）。
この MOD まで語り直すと、同じ内容がプロンプトへ二重三重に並ぶ。
そこで覚えるのは、
会話から分かった「人物像として続くもの」（性格・嗜好・経歴・関係・約束）だけに絞ってある。

日が飛んだことに気付く（v5）。
宿で寝ると数ヶ月進むことがあるのに、次の会話が数秒前の続きのように始まっていた。
前に話したゲーム内の日を控えて、次の会話で「何日経ったか」を添えるようにした。
ただし**毎回「久しぶり」にはならない**。
同じ土地に留まっている間は日々見かけているはず、
という但し書きを一緒に渡してある（実際に離れていたかはゲーム自身が渡す滞在歴で判断される）。

**一度覚えた事実は忘れにくくなった**（v4）。
人物像は会話のたびに書き直すので、
そのままだと統合の過程で細部（金額・約束の条件・固有名）が少しずつ落ちる。
そこで判明した事実の控え（下の表の4つめ）を次の抜き出しに差し戻し、
人物像から抜けていたら書き戻させるようにした。
差し戻すのは抜き出しのときだけなので、**会話そのものが重くなることはない**。

| 設定 | 意味 |
| --- | --- |
| 抜き出しに載せる直近のやり取りの数 | 既定 8。増やすと取りこぼしが減るが、抜き出しが遅くなる |
| 追加プロフィールの目標長 | 既定 1200。抜き出し LLM が要約で収める目安。保存や注入では切らない |
| その人物から見たあなたの記録も残す | 既定 ON。切ると人物像だけになる |
| 前に話してからの日数を伝える | 既定 ON。宿泊などで日が飛んでも、直前の会話の続きのようには話さなくなる。同じ土地に居る間は日々見かけている前提なので、毎回「久しぶり」にはならない |
| 判明した事実を残しておく件数 | 既定 200。書き換えではなく追記で伸びる唯一の控え。次の抜き出しに差し戻して、要約で人物像から消えた事実を書き戻させる（会話のプロンプトには載らない）。0 で残さない |

覚えた内容はセーブではなく `state\npc_profiles\<世界名>.json` に入る。
この配布フォルダを消すと記憶も消える。
人物1人につき次の形で入っている。

```json
{ "<NPCのid>": { "name": "名前", "updated": "更新日時",
                 "profile": "人物像", "about_player": "あなたについての記録",
                 "facts": [{"at": "日時", "text": "判明した事実"}],
                 "day": 594 } }
```

`day` は最後に話したゲーム内の日（世界の経過日数）。
次に話したときの「何日ぶりか」はここから出す。

`301_quest_from_conversation`（会話から依頼を受けられる）を一緒に入れていると、
この記録を読んで依頼人の口ぶりを人物像に寄せる。
どちらか片方だけでも動く。

#### 困ったとき

| 症状 | 見るところ |
| --- | --- |
| いつまでも何も覚えない | `out\npc_profile.log`。`send_request_with_no_structure unavailable` なら、まだ一度も会話していないので推論の部品が読み込まれていない（会話を1回してから見る） |
| 覚える内容が的外れ | 同じログの `updated:` の行に、何文字から何文字になったかが出る。`extract: nothing to change` が続くなら、抜き出し LLM が「新しい情報なし」と答えている |
| 別の世界の人物像が出てくる | 世界は名前で見分けている。データ改変ツールで世界名を変えると別物として扱われる。ログに `no profiles for world ...` が出て、`state\npc_profiles\` にある世界名の一覧が並ぶ |
| 身に覚えのないことを覚えている | その人物の `facts` に、いつ分かったことになっているかが残っている。`state\npc_profiles\<世界名>.json` からその人物の項を消せば忘れる |
| 書き込み中にゲームが落ちた | 記憶は失われない。書き出しは隣に作ってから差し替えているので、落ちた場合は**前回までの内容がそのまま残る**。`.writing` で終わるファイルが残っていたら消してよい |

### `312_shop_restock`: 日数経過で店の在庫を更新

売買画面に並ぶのは、その店の主が持っている品物そのもの。
ゲームにはそれを入れ替える仕組みが無いので、

- 品揃えが初めて開いたときのまま変わらない
- あなたの売った品はそのまま主の持ち物に積まれ、
  24マスが埋まり切るとそれ以上その店へ売れなくなる

この MOD は、ゲーム内で一定の日数が経った店を次に開いたときに、
主の持ち物をまっさらにする。
品物を作るのはゲーム自身なので、値段も品揃えの傾向も普段どおり。

| 設定 | 意味 |
| --- | --- |
| 品揃えを入れ替える日数 | 既定 30（ゲーム内の日数）。最後に入れ替えてからこれだけ経った店を、次に開いたときに入れ替える |
| 初回の来店でも入れ替える | 既定 OFF。切っていると、初めて開いた店は日付を控えるだけで素の品揃えのまま |

入れ替えのときに**あなたが売った品も一緒に消える**。
売り戻す（買い直す）つもりがあるなら、入れ替えの日を跨ぐ前に買い戻すこと。

最後に入れ替えた日はセーブではなく `state\shop_restock\<世界名>.json` に入る。
消すと、次の来店が「初回」の扱いに戻る（品揃えはそのまま）。

#### 困ったとき

| 症状 | 見るところ |
| --- | --- |
| いつまでも入れ替わらない | `out\shop_restock.log`。`not due:` なら日数がまだ足りない（`day=` が今日、`last=` が最後に入れ替えた日）。`first visit:` しか無ければ、その店はまだ基準を控えただけ |
| 店が空になった | 同じログの `WARN not refilled:`。ゲーム側が空の持ち物を補充しなかった場合で、品物はその場で書き戻され、以後この MOD は空にしない。次に開けば元の品揃えが並ぶ |
| 主が引けないと出る | `skip: cannot resolve the shop owner`。主のいない施設（通路・入口）では何もしない。店で出るなら、その施設に `owner` が設定されていない |
| 売った品を買い戻したい | 入れ替えの日を跨ぐと消える。日数を長くするか、売ったその足で買い戻す |

### `313_event_ability_check`: 行動の成否判定に能力値を効かせる

クエストの道中で起きるミニイベント（落石を避ける、罠を見抜く、
崖を登る…）で自由入力した行動が成功するかは、
LLM が付けた 説得力 だけで決まっている。

```text
確率 = 説得力(1〜10) × 10 + 20
```

LLM は同時に「この判定に最も関わる能力値」も選んでいるのだが、**ゲームはそれを使っていない**。
実データ 121 回（8キャラ）で、能力値が高いことで確率が上がった回は1度も無かった（GAME.md
§2.9）。
素早さに振っても、力に振っても、同じ入力なら同じ確率になる。

この MOD は、LLM が選んだその能力値の実際の値で説得力を上下させる。

```text
確率 = (説得力 + 能力値の補正 + 底上げ) × 10 + 20
```

既定の効き方は 15 から 3 点ごと、上限 +20%。

| 参照能力値 | 加点 |
| --- | --- |
| 〜15 | なし |
| 16〜18 | +4% |
| 19〜21 | +8% |
| 22〜24 | +12% |
| 25〜27 | +16% |
| 28〜30 | +20% |

低い能力値でも減点しない。
素のゲームより不利になることは既定では無い（減点したいなら「減点の上限」を
1 以上にする）。

基準を 15 に置いてあるのは、**能力値がレベルでは伸びない**から。
同じキャラのセーブをレベル3から73まで追っても合計 142 →
149 しか動いておらず（伸びるのは宿の訓練だけ）、
作成時に振った値がほぼそのまま最後まで続く。
平均（24前後）を基準にすると「素早さに振ったのに補正0」が普通になってしまう。
上限が 28 で頭打ちなのは、実セーブで見た能力値の上端が 30 前後だから。

底上げ（既定 0）は能力値と無関係に毎回足すぶん。
既定では**素のゲームの成功率そのままで、能力値の差だけ**が効く。
全体を易しくしたいなら 10 にすると一律 +10%（素の 59.5% が概ね 70% になる）。

> 作成直後のキャラでは、しばらく何も起きない。
> 才能点が既定なら各能力値は 9〜16 で（GAME.md §2.17）、
> 基準の 15 を超えるのは1つか2つ。
> **訓練で伸ばすまで加点は出ない**のが既定の姿。
> すぐ効かせたいなら「加点が始まる能力値」を下げるか、底上げを 10 にする。
> 加点が 0 だった回も `補正なし: dexterity=12 (基準 15 以下)` の形でログに残るので、
> 動いているかどうかはそこで分かる。

| 設定 | 意味 |
| --- | --- |
| 加点が始まる能力値 | 既定 15。ここまでは補正なし。1点でも超えれば1段目 |
| 1段ぶんの能力値の幅 | 既定 3 |
| 1段ぶんの加点(%) | 既定 4。成功率にそのまま足す割合 |
| 加点の上限(%) | 既定 20（能力値28以上で頭打ち）。0 にすると能力値は効かなくなる |
| 減点の上限(%) | 既定 0（低い能力値でも素のゲームより不利にならない）。1 以上にすると、基準を下回るぶんが同じ幅で下がる |
| 全体の底上げ(%) | 既定 0（素のゲームの水準のまま能力値の差だけが効く）。10 にすると一律 +10% |
| 10%未満の刻みを使う | 既定 ON。下の「10% 未満の刻み」を参照 |
| 使う能力値 | 既定 `raw`（素の能力値）。`condition` にすると負傷や体力で目減りした値になる |

#### 10% 未満の刻み

ゲームの確率は `説得力 × 10 + 20` なので、**説得力を整数で渡す限り
10% 刻み**にしかならない。
4% のような刻みを出すには説得力に端数（`5.4` → 74%）を渡す必要があり、
この MOD は既定でそうする。

端数を受け付けないビルドだった場合は**自動で整数に丸めて入れ直す**（刻みは
10% に落ちるが、加点そのものは効く）。
丸めに落ちたことは `out\event_roll.log` に 1度だけ出る。
最初から 10% 刻みで動かしたいなら「10%未満の刻みを使う」を切る。

この端数の経路は実機で通っている。
ゲームは `説得力 5.6` / `7.6` をそのまま受け取っていて、
丸めに落ちたことを示す行は一度も出ていない。
確率の刻みが本当に 4% になっているかまでは突き合わせていないので、
おかしいと感じたらこの設定を切ってほしい。

#### 街や会話での自由入力にも効く

ゲームの判定は2系統ある。
街・施設・会話中の自由入力は別の仕組みで、**確率を
LLM 自身が決めている**（そちらのプロンプトにも能力値は載っていない）。
この MOD はそちらにも同じ加点を足す。

ただし、こちらは「どの能力値の判定か」を LLM が言わない。
そこで**行動文から推定する**:

| 設定 | やり方 |
| --- | --- |
| `llm`（既定） | 行動文を渡して、6つのどれかを1問だけ LLM に選ばせる。判定のたびに短い推論が1回増える |
| `keywords` | 語句の表だけで決める。追加の推論は起きないが、決まるのは半分ほど（実データ190件で56%）。決まらない回は加点なし |
| `off` | この経路には触らない |

`llm` の問いと答えは `output_data\<世界>\<PC>\mod_ability_for_action\` に残る。
返ってこない場合に備えて時間切れを設けてある。
失敗したら黙って `keywords` へ降りる（自由入力の応答を止めるほうが害は大きい）。
同じ行動文には聞き直さない。

行動入力の意味は変わらない。
「その行動がもっともらしいか」の採点は LLM に任せたままで、
キャラクタの強さだけをこちらから足している。
LLM が「確実に成功」「確実に失敗」と判断した回（入力全体の 8%）にも手を出さない。

#### 困ったとき

| 症状 | 見るところ |
| --- | --- |
| 効いているか分からない | `out\event_roll.log`。判定のたびに `能力値補正: dexterity=26 -> +16%(能力値) +10%(底上げ) \| 説得力 5 -> 7.6 \| 確率の見込み 70% -> 96%` の形で1行出る |
| `能力値を読めなかった` と出る | そのキャラクタが能力値を普段と違う形で持っている。底上げだけは効いている。この行を添えて報告してほしい |
| `説得力を書き換えられなかった` と出る | ゲームの更新で戻り値の型が変わり、代入を受け付けなくなっている。判定はゲームの元どおりに進むので害は無い |
| 簡単すぎる | 「全体の底上げ」を 0 に、それでも簡単なら「能力値による補正の上限」を 1 に下げる |
| 相変わらず失敗ばかり | 上のログの `能力値=` を見る。15 以下なら補正は付かない（素のゲームと同じ確率）。能力値は宿の訓練でしか伸びないので、伸ばすならそちら |
| `補正なし` ばかり出る | そのキャラの能力値が基準（既定 15）以下。作成直後は 9〜16 が普通なので想定どおり。すぐ効かせたいなら「加点が始まる能力値」を下げる |
| 街での行動が重くなった | 「街や会話での自由入力にも効かせる」を `keywords` にすると、判定のたびの推論が1回減る。`off` で元どおり |
| 見当違いの能力値で判定される | `out\event_roll.log` の `mod_ability_for_action:` の行に、LLM が選んだ能力値が出る。`keywords` のほうが素直なこともある |
| 確率の動きが 10% 刻みのまま | 同じログに `説得力に端数を入れられないビルド` が出ていないか見る。出ていれば刻みは 10% に落ちている（加点は効いている） |

### `314_area_move_custom`: エリア移動の日数・料金・文言を変える

土地から土地への移動は `徒歩(3ヵ月)` と `馬車(1000G)` に固定されている。
この MOD はその日数・馬車の料金・移動中の文言を設定から変えられるようにする。

ボタンには実際の日数が出る。
徒歩を 14 日にすれば確認画面のボタンが `徒歩(14日)` になり、実際に 14 日で着く。
表示に使う値と暦を進める値が同じ設定値なので、表示と実態は食い違わない。

**既定値はすべて素のゲームの値**（徒歩90日・馬車14日・1000G）で、
そのままならこの MOD は挙動を何も変えない。
設定を素の値から動かした項目だけが効く。
例外は馬車のボタンの表示だけ: 素のゲームは馬車の所要日数をどこにも出さない（徒歩は
`3ヵ月` と出るのに）ので、**既定でも `馬車(1000G・14日)` と日数を表示する**。
足している 14 は実測の素の値で、実際にかかる日数と同じ。

```
[素のゲーム]         徒歩(3ヵ月)  /  馬車(1000G)
[既定＝入れただけ]   徒歩(3ヵ月)  /  馬車(1000G・14日)  ← 表示だけ。挙動は素のまま
[徒歩を14日に]       徒歩(14日)   /  馬車(1000G・14日)
[全部変えた例]       徒歩(30日)   /  竜車(500G・7日)    ← 呼び名・料金・日数すべて変更
```

呼び名（`{name}`）を変えると、ボタンと移動中の文言の両方に効く。
文言はテンプレートで、
`{name}`（手段の名前）`{target}`（行き先）`{origin}`（出発地）`{days}`（日数）`{price}`（料金）が使える。
空にすればゲームの文言のまま。

徒歩は日数が素の値のままならボタンの表示もゲームのまま（`3ヵ月` 表記が残る。
呼び名だけ差し替わる）。
日数を変えると `徒歩(14日)` の形になる。
馬車は上記のとおり常に `{name}({price}G・{days}日)` の形で出る。

料金の変更は前払い調整方式: ゲームが運賃（素の 1000G）を引き落とす前に、
差額のぶんだけ所持金をずらしておく。
引き落としは1回でちょうど設定額になり、
「1000引いてから払い戻す」ような紛らわしい動きは画面に出ない。
手持ちが「設定した料金以上・素の 1000G 未満」でも、
調整で残高チェックに弾かれず乗れる。

| 設定 | 意味 |
| --- | --- |
| 徒歩の日数 | 既定 90（素の値＝3ヵ月）。90 のままなら触らない |
| 馬車の日数 | 既定 14（素の値）。14 のままなら実際の日数には触らない（ボタンには既定でも日数が出る） |
| 馬車の料金 | 既定 1000（素の値）。1000 のままなら触らない。0 でタダ。手持ちがこの額に満たないと乗れない |
| 徒歩・馬車の呼び名 | 既定「徒歩」「馬車」。ボタンと文言の `{name}` に入る |
| ボタンの表示 | 既定 `{name}({days}日)` / `{name}({price}G・{days}日)`。徒歩は日数を変えたときだけ、馬車は常にこの形になる |
| 出発・到着の文言 | 既定は出発の2つがテンプレート（内容は素のゲームと同じ文）。空でゲームのまま。馬車の文はゲームが金額を焼き込むので、料金を変えると既定テンプレートが文中の金額を実際の引き落としに揃える |

`307_area_move_dungeon`（危険な道を行く）と一緒に使える。
踏破後の移動は徒歩の経路を借りているので、
徒歩の日数を縮めていればそちらにも効く（小さいほうの日数で着く）。

#### 困ったとき

| 症状 | やること |
| --- | --- |
| ボタンの表示が変わらない | 徒歩は日数が素の値（90）のままだと表示も元のまま（仕様）。馬車は既定でも `馬車(1000G・14日)` になるはずなので、ならないときは `out\area_move_custom.log` に `label:` の行があるか見る |
| 日数が設定どおりに進まない | 同じログの `days:` の行。1行も無ければ、お使いのビルドの日数送りが `elapse_days` を通っていない |
| 馬車の文言の金額がおかしい | 素のゲームは料金をいくらに変えても「1000ゴールドを支払った」と言う。既定のテンプレートが金額を実際の引き落としに揃えるので、「馬車の出発の文言」を空にしているなら戻す |
| 料金の引かれ方がおかしい | 同じログの `fare:` の行に前払い調整と引き落としの内訳が並ぶ。`WARN fare:` が出ていたらその行を添えて報告してほしい |
| 手持ちが少ないと馬車に乗れない | 設定した料金未満なら仕様（「（馬車代◯Gに足りない…）」と出る）。素の 1000G 未満で乗れないときは、お使いのビルドが確認画面より前に残高を見ている可能性がある。デバッグモードで `217_probe_area_move` を入れて録ってほしい |

### `315_vacation_custom`: 宿の宿泊期間・部屋・宿代を変える

宿の宿泊は、期間がゲーム任せで、部屋が4つに固定されている。
期間はボタンに `宿泊する(3ヵ月)` と出るが、**プレイヤーの年齢で
3〜6ヵ月に変わる変動式**。
部屋は `犬小屋(0G)` / `簡易寝台(10G)` / `個室(100G)` / `高級個室(1000G)`。
この MOD は宿泊期間・部屋の名前・宿代を設定から変えられるようにする。

**既定値はすべて素のゲームの値**（部屋4つの名前と 0/10/100/1000G。
期間は「デフォルト」＝ゲームのまま）で、そのままならこの MOD は挙動を何も変えない。
設定を素の値から動かした項目だけが効く。

宿泊期間は選択式:
`デフォルト / 1週間 / 2週間 / 1ヵ月 / 2ヵ月 / 3ヵ月 / 4ヵ月 / 6ヵ月`。
ゲームに無い週単位の短期滞在も選べる（部屋代1回ぶんで 7日/14日だけ泊まる）。
さらに、ゲーム自身の期間が年齢の変動式なのに合わせて、
選んだ期間に年齢の加算を掛けられる（ON/OFF可、既定ON）:

```
20代まで  そのまま         30代      +1週間 / +1ヵ月
40代      +2週間 / +2ヵ月  50代以上  +3週間 / +3ヵ月
上限は 4週間 / 6ヵ月。週の加算は週単位（1・2週間）を選んだとき、
月の加算は月単位（1ヵ月以上）を選んだとき。
```

```
[素のゲーム]           宿泊する(3ヵ月) → 犬小屋(0G) / 簡易寝台(10G) / 個室(100G) / 高級個室(1000G)
[1週間・30代]          宿泊する(2週間) → 「2週間泊まることにした。」14日で終わる
[1ヵ月・40代]          宿泊する(3ヵ月) → ゲームと同じ月数になり、実質何も変わらない
[部屋を変えた例]       馬房の隅(5G) / 相部屋(10G) / 個室(100G) / 王侯の間(300G)
```

表示と実態は食い違わない（`314_area_move_custom` と同じ約束）。
ボタンに出す期間・料金は設定値そのもので、
ゲームに渡す値も同じ設定値（年齢の加算まで含めて同じ計算から出す）。
名前を変えても部屋の中身（休まり方・部屋ごとの背景）は元のまま。
週単位のときはゲームの「1ヵ月泊まることにした。」も実際の期間に置き換わる。

宿代の変更は前払い調整方式（`314_` と同じ）: ゲームが素の宿代を引き落とす前に差額ぶん所持金をずらしておく。
引き落としは1回でちょうど設定額になる。
手持ちが「設定した宿代以上・素の宿代未満」でも泊まれる。
設定額に満たないときは押した時点で「（◯◯の宿代◯Gに足りない…）」と断る。

| 設定 | 意味 |
| --- | --- |
| 宿泊期間 | 既定「デフォルト」＝ゲームのまま（素のゲームは年齢で3〜6ヵ月）。週単位は部屋代1回ぶんの短期滞在になる |
| 年齢による期間の加算 | 既定 ON。選んだ期間に 30代+1・40代+2・50代以上+3（週/月）を足す。「デフォルト」では意味を持たない |
| 部屋の名前 ×4 | 既定「犬小屋」「簡易寝台」「個室」「高級個室」（素の値）。ボタンの表示に入る |
| 部屋の宿代 ×4 | 既定 0 / 10 / 100 / 1000（素の値）。素の値のままなら触らない。0 でタダ。手持ちがこの額に満たないと泊まれない。**タダの犬小屋を有料にすることもできる** |
| 部屋・宿泊のボタンの表示 | 既定 `{name}({price}G)` / `宿泊する({length})`。変えた項目があるときだけこの形で表示し直す |
| 宿泊開始の文言（週単位） | 既定 `{length}泊まることにした。`。空でゲームのまま（そのときは文言が1ヵ月のまま残る） |
| 週単位のときAIの描写も揃える | 既定 ON。AI に渡す文の「数ヵ月の宿泊」を実際の期間に直す。切ると描写だけが「数ヶ月」と言い続ける |

> **部屋の見分けはゲーム内部の部屋の名前**（`kennel` / `bunk` / `private_room` /
> `luxury_suite`。実機で観測した値）で行う。
> ゲームの更新でその語彙が変わったビルドでは、
> ラベルの料金（0/10/100/1000）で当てる保険が働く。
> どちらにも当たらない部屋には一切触らない（表示だけ変わって実態が変わらない、
> という食い違いを作らないため）。
> そのときは `out\vacation_custom.log` に `unknown room` が残る。
>
> 週単位にすると AI の描写も揃う。
> ゲームは AI に渡す文へ「このエリアで数ヵ月の宿泊をし」と月数を焼き込んでいる（実測）ので、
> そのままだと2週間の滞在でも描写だけが「数ヶ月にわたる滞在」と言う。
> この MOD は週単位の宿泊のあいだだけ、
> その月数を実際の期間に直す（「週単位のときAIの描写も揃える」。既定 ON、
> 切ればゲームのまま）。
> 月単位の宿泊では何もしない。

#### 困ったとき

| 症状 | やること |
| --- | --- |
| ボタンの表示が変わらない | 名前も宿代も素の値のままの部屋は表示も元のまま（仕様）。月単位の期間が年齢の加算でゲームと同じ月数になったときも元のまま（仕様＝実質変わらないため）。変えたのに変わらないときは `out\vacation_custom.log` に `label:` の行があるか見る |
| 宿代が設定どおりに引かれない | 同じログの `price:` の行。「the game did not charge」が出ていたら、お使いのビルドは宿代を別の場所で徴収している（所持金は1Gも狂わない作りだが、設定は効かない）。デバッグモードで `218_probe_vacation` を入れて録って、ログを添えて報告してほしい |
| 週単位にしたのに日数が縮まない | 同じログの `days:` の行。1行も無く `WARN stay: ... no elapse_days call` が出ていたら、お使いのビルドの宿泊の日数送りが `elapse_days` を通っていない。`218_probe_vacation` で録って報告してほしい |
| 年齢の加算が効かない | 同じログに `age: cannot read app.player.age` があれば、年齢が読めないビルド（加算なしで動く）。ログを添えて報告してほしい |
| 手持ちが少ないと泊まれない | 設定した宿代未満なら仕様（「（◯◯の宿代◯Gに足りない…）」と出る）。素の宿代未満で部屋のボタン自体が出ないときは、ビルドが部屋選びより前に残高を見ている可能性がある。`218_probe_vacation` が部屋選びの時点の所持金を録る |
| 連泊すると宿代も日数も2回ぶん | 仕様（ゲーム自身がそう作られている。`まだ宿泊する` は宿代の徴収も日数送りももう1回。実機で実測） |
| 週単位なのに描写が「数ヶ月」と言う | 「週単位のときAIの描写も揃える」が切れていないか見る。ONなのに直らないときは `out\vacation_custom.log` の `prompt at` の行を見てほしい。`kept as is:` が出ていれば、その活動のプロンプトがまだ知らない言い回しをしている（その一節がログに出るので、添えて報告してもらえれば足せる） |

### `316_bounty_hunter`: 手配されていると追手が来る

手配されたまま旅を続けると、賞金を目当てにした追手が行く手を塞ぐ。

```text
[陽光の砦に着いた]
首にかけられた賞金を目当てに、追手が行く手を塞いだ。
                ↓
戦闘（3体。強さは手配の重さで決まる）
```

出てくるのは**ゲーム自身が手配された者に差し向ける衛兵の戦闘**そのもの。
この MOD が決めるのは「いつ来るか」「どれだけ強いか」「何と呼ぶか」だけで、
戦闘も戦利品も戦闘後の要約もゲームのまま。セーブには何も足さない。

#### 来る条件は2つ（どちらかを満たせば来る）

| 条件 | 既定 |
| --- | --- |
| 今いる土地の手配度 | -20 以下 |
| すべての土地の手配度の合計 | -40 以下 |

合計の側があるので、手配されていない土地へ逃げても追ってくる。
既定の線は NPC 1人の殺害で手配度が 10 動くことから取ってあり、
1人では来ず、2人以上でお尋ね者になる。
手配されていない土地（平常 10）は合計に入らない。

#### 強さは手配の重さで決まる

```text
敵のレベル = 21 + 手配の重さの合計      上限 76
```

手配が軽いうちはゲーム自身の衛兵と同じ（レベル21・HP 230前後）。
上限まで重ねるとレベル76・HP 800前後になる。
重さは手配度が 0 からどれだけ下かで数えるので、手配度の合計 -55 で上限に届く。
敵の数はゲームが決める（3体。設定できない）。

#### 出る間合い

追手が決まるのは移動や宿泊の途中なので、実際に出るのは画面が落ち着いてから。
戦闘中・会話中・自由入力中や、宿泊のような何段階かに分かれた場面の最中には割り込まず、
その場面が終わるまで持ち越す（宿泊の途中で決まった追手は、宿泊が終わってから来る）。
場面が続いたまま画面が20回変わっても出られなければ、その回は諦める。

追手を倒しても手配度は増えない（既定）。
素のゲームでは衛兵と戦うとその土地の手配度が 10 下がるので、
そのままだと追手が追手を呼ぶ。逃げて終わった場合も同じ。

ゲーム自身の衛兵イベントとは重ならない。
ゲームが衛兵を出した回も1回の遭遇として数えるので、
続けて追手が来ることはない（設定で切れる）。

| 設定 | 意味 |
| --- | --- |
| 追手が来る手配の重さ（今いる土地） | 既定 20（＝手配度 -20 以下 ＝ NPC殺害2人ぶん） |
| 追手が来る手配の重さの合計（全ての土地） | 既定 40 |
| 1回あたりの発生率（％） | 既定 30。条件を満たした場面ごとに抽選。100 で必ず来る（動作確認用）、0 で来ない |
| 次の追手までに空ける日数 | 既定 10（ゲーム内の日数）。0 で毎回抽選 |
| 追手の難易度の下限 | 既定 20（＝レベル21。ゲーム自身の衛兵と同じ） |
| 手配の重さ1あたりの難易度 | 既定 1.0 |
| 追手の難易度の上限 | 既定 75（＝レベル76） |
| 土地に着いたときに来る | 既定 ON |
| 施設に入ったときに来る | 既定 OFF。町を歩くたびに抽選が回るので、入れるなら発生率を下げる |
| 日数が進んだときに来る | 既定 ON。訓練・休養・移動の後。留まっていても来る |
| 自由行動のときに来る | 既定 OFF |
| 追手の名前 | 既定「賞金稼ぎ」。戦闘では連番が付く（賞金稼ぎ1／賞金稼ぎ2…）。空にするとゲームのまま（衛兵） |
| 追手を倒しても手配度を増やさない | 既定 ON。切ると倒すたびに手配が重くなる（ゲームのまま） |
| ゲーム自身の衛兵に先を譲る | 既定 ON。切ると、ゲームの衛兵イベントと続けて起きうる |
| 追手が来たときの1行 | 既定「首にかけられた賞金を目当てに、追手が行く手を塞いだ。」。空にすると何も出さずに戦闘へ入る |

#### 困ったとき

記録は `out\bounty_hunter_send.log`。来た回も、来なかった回とその理由も1行ずつ残る。

| 症状 | 見るところ |
| --- | --- |
| 追手が来ない | 条件を満たしていれば、抽選に外れた回もクールダウン中の回も記録に残る。1行も無いなら条件を満たしていない（手配度は `121_ui_character_sheet` の人物欄で土地ごとに見られる） |
| 追手が続けて来る | 「次の追手までに空ける日数」を増やす。日数は暦が動いたぶんだけ数えるので、暦の動かない場面（クエスト中）では進まない |
| 手配を解いても来る | よその土地の手配が合計に残っている。土地ごとに役場で解く（`309_office_pardon`）か、合計の閾値を上げる |
| 決まったのに出ない | 記録の `画面が20回変わっても出せなかった`。場面が続いている間に決まると諦める（次の契機でまた抽選される） |
| 倒したら手配が重くなった | 記録に `手配度を戻した` が出ているか。`書き戻せなかった` が出ていたら、お使いのビルドは手配度の持ち方が違う |
| 名前が `衛兵` のまま | 記録の `（N体を賞金稼ぎに改名）`。ゲーム自身が出した衛兵は `衛兵` のままで正しい |
| 強さが変わらない・場面が巻き戻る・画面が重なる | どれも記録に理由の行が残る（`難易度 20 -> N` / `場面の最中(…) なので出さない` / `選択肢を塗り直した`）。出ていない行があれば、デバッグモードで `220_probe_bounty_hunter` を入れて録り、ログを添えて報告してほしい |

### `317_reputation`: 評判と二つ名

プレイヤーの行いから土地ごとの評判を編み、会話する NPC に渡す。
初対面の相手が「噂は聞いている」から入り、世界に1つの二つ名で呼ばれることもある。

```text
【アッシュでのアーリの評判】
盗賊団を退けた者としてよく知られている。
土地を問わず「灰の街の盾」の二つ名で知られている。
これはこの土地に広まっている噂で、あなたも耳にしている。
アーリへの好悪はあなた自身の性格が決める。
```

素材は**ゲーム自身が既に書いているもの**だけ（`area_history` の成した事・手配度・
完了した依頼・滞在日数）。この MOD が新しく記録を始めるものは無い。
素材が変わったときだけ別スレッドで LLM を1回回して評判文へ編纂し、
会話フックの中では編纂済みの文字列を注入するだけなので、会話は遅くならない。
セーブには一切書かず、編纂した文は `state\reputation\` に置く。

#### 評判は土地ごと、二つ名は世界に1つ

- 評判が立つのは「成した事＋完了した依頼が既定2件以上」または「手配中」の土地だけ。
  何も成していない土地では**何も注入しない**（素のゲームと同じ挙動）
- 注入するのは NPC が「知っている」情報だけで、好悪は書かない
  （好意・敵意の向きは NPC の性格が決める。`125_` が直した轍を踏まないため）
- 二つ名は各地の評判文から編み、**質的な変化**（評判の立つ土地の増減・手配の反転・
  行いの倍増）のときだけ編み直す。頼み文にいままでの名を渡すので、
  覆す材料が無ければ同じ名が続く
- 二つ名は `121_ui_character_sheet` の人物欄（レベル行の続き）に出る。
  右の ⟲ ボタンで引き直せる（いまの名を除いて編み直す）

#### 設定

| 設定 | 既定 | 意味 |
| --- | --- | --- |
| 会話に効かせる | ON | 会話5関数で、話し相手の複製の profile に評判を足す |
| 情景描写に効かせる | OFF | narrator に渡る player_profile に評判を足す |
| 二つ名を使う | ON | OFF なら評判文のみ。二つ名の編纂も止まる |
| 二つ名の文字数の上限 | 8 | 超えた名は切り詰めずに捨てて前の名を残す |
| 二つ名の長さを揺らす | ON | 編纂のたびに狙う長さを3〜上限で引いて頼み文に載せる |
| 評判が立つ最低件数 | 2 | 満たない土地では何も注入しない。手配中の土地は件数を問わない |
| 注入の長さ | 短い | 短い=1文120字 / 詳しい=3文300字。プロンプトは毎回全文載るので短い方が安全 |
| 素材の形をログに残す | ON | 起動ごとに1回、`out\reputation.log` に素材の形を出す |

#### 二つ名が編み直される契機

二つ名は噂話が属人化したものなので、行いが1件増えるたびに変わっては困る。
編み直すのは**質的な変化**の3つだけで、どれも既にある素材から数えている。

| 契機 | 意味 |
| --- | --- |
| 評判の立つ土地が増減した | 噂の届く範囲が変わった。役場で手配を解いて外れる側も拾う |
| 手配が反転した（`lawfulness` が 0 をまたぐ） | 善悪の転換。人物像を覆す筆頭 |
| 全土地の行いの合計が**前回編纂時の2倍**になった | 「駆け出しの◯◯」が古びる頃合い。倍々なので終盤ほど動かない |

加えて頼み文にいままでの名を渡し「明確に覆すのでなければ同じ名を返す」と縛る。
契機で回数を、指示で結果を絞る二段構えなので、
節目が来ても人物像が変わっていなければ名は据え置かれる。

#### 素材とプロンプトの重なり

ゲーム自身が会話に `area_achievements`（その土地で成した事）を渡している
（GAME.md §2.24）。素材をそのまま要約し直すと同じ事実が言い換えで2度載るので、
編纂の頼み文で「出来事を並べ直さない」と縛り、注入は既定で1文120字までにしてある。
プロンプトは毎回全文が送られる（`311_` 併用時は会話開始時点で2,206字の実測）ので、
長くするほど他の内容を押し出す。

#### 控えの形（`121_` と共有している）

編纂した文は `state\reputation\<世界名>.json` に入る。
人物欄に二つ名を出す `121_ui_character_sheet` はこのファイルを読む
（MOD どうしは import しない決まりなので、繋がるのはファイルだけ。TECH.md §3.2.3）。
**鍵と並びは MOD をまたいだ取り決め**なので、読む側が居る前提で固定してある。

```json
{"areas": {"4": {"area": "4", "name": "ルナ・ミスト", "day": 4393,
                 "updated": "2026-08-24 15:43:07",
                 "reputation": "崩落や怪物を討ち果たした流れ者として知られている。",
                 "fingerprint": "650e28d622cf021b"}},
 "epithet": {"epithet": "浄化の嵐",
             "description": "各地の脅威を払ったという評判から来た名。",
             "day": 4393, "updated": "2026-08-24 15:50:11",
             "mark": {"qualifying": ["4"], "wanted": [], "deeds": 6}}}
```

- `description` は**ゲームには出さない内部データ**。
  後から控えを読んだときに名の由来を追うためのもの
- `fingerprint` / `mark` は編纂し直すかの判定に使う印。手で消すと次の照合で編み直る
- 人物欄の引き直しボタンは `<世界名>.reroll.json` を書き、この MOD が次の照合で消す
  （在ることが頼みで、中身は読まない）
- この MOD を切ると人物欄の二つ名も消える（`121_` はファイルが無ければ何も足さない）

#### 困ったとき

| 症状 | 見るところ |
| --- | --- |
| 評判が出ない | `out\reputation.log`。「素材が薄いので評判を立てない」なら件数が既定未満（そのまま遊べば立つ）。「評判はまだ無い」なら編纂前（移動か日送りで編纂が走る） |
| 二つ名が付かない | 同ログの「二つ名:」の行。「読めなかった」が続くなら LLM が JSON を返していない。素材が揃っていれば次の照合で引き直す |
| 二つ名が変わらない | 仕様（質的な変化のときだけ編み直し、覆す材料が無ければ据え置く）。変えたければ人物欄の引き直しボタン |
| 引き直しても同じ名になる | 同じ評判からは同じ連想が出やすい。もう一度押すか、上限や「長さを揺らす」を変えると散る |
| 会話が重くなった気がする | この MOD は会話中に LLM を呼ばない。編纂は別スレッドで、`output_data\` の `mod_reputation_compile` / `mod_reputation_epithet` に頼み文と返答が残る |

### `318_area_difficulty_growth`: 土地が育つ（依頼の難易度が上がる）

同じ土地で依頼を片付け続けると、その土地で受けられる依頼が少しずつ手強くなる。
合わせて店の品揃えも上がる。

素のゲームでは、土地の難易度は世界を作った時点で決まったまま動かない。
最初の町の依頼は 3・4・5 のまま何十回通っても 3・4・5 で、
店に並ぶ品も、鍛冶で打てるものもそこで止まる。
強くなりたければ土地を移るしかなく、**居着いた土地は何も育たない**。

この MOD が動かすのは依頼の難易度という数1つだけ。
**依頼を1つ片付けるたびに 3〜10 の乱数を引いて積み上げる**（上限まで）。

```text
最初の町（依頼 3 / 4 / 5）
  1回クリア（+7）    → 10 / 11 / 12
  2回目  （+4）      → 14 / 15 / 16
  3回目  （+9）      → 23 / 24 / 25
```

上がり幅が毎回違うので、同じ回数でも育ち方が世界ごとに変わる。
幅は設定で変えられ、最小と最大を同じ値にすれば固定になる。

#### 在庫とクラフトが一緒に上がる理由

その土地の物価と品揃えは、その土地の依頼の難易度そのものだから。
実セーブ3世界・店23軒を突き合わせた結果、
店に並ぶ品の `value` は**その土地の依頼の難易度以外の数を取らない**
（完了済みの依頼も母数に入る。GAME.md §2.13.1）。

だからこの MOD は在庫にもクラフトにも手を触れない。
依頼の難易度を上げれば、ゲーム自身がそこから決めているものが全部付いてくる。

| 何が付いてくるか | 効き始め |
| --- | --- |
| 敵の強さ（レベルはおよそ 難易度+1） | 次に受ける依頼から |
| 報酬・才能・訓練・日雇いの実入り | 次に受ける依頼から |
| 店の品揃え | 品揃えが入れ替わってから（`312_shop_restock` が入れ替える。入れていない場合は初回のまま） |
| クラフトの成果物 | 素材が上がってから（成果物の値段 ＝ 素材の合計値段 × 倍率） |

4つとも実機で確かめてある。
土地0 の店に、素のデータからは出ない value 33 の武器と防具が並んだ。
素材 value 2 + 8 で打ったクラフトは value 27・攻撃力 116 の短剣になった
（GAME.md §2.13.1.2 / §2.14.2）。

#### 設定

| 設定 | 意味 |
| --- | --- |
| 1回のクリアで上がる最小 | 既定 3。難易度は敵のレベルと能力値の両方を決めるので、+3 はレベル3ぶん |
| 1回のクリアで上がる最大 | 既定 10。最小と同じにすると乱数を回さず固定になる。最小より小さい値は最小まで引き上げて扱う |
| 1つの土地で上がる上限 | 既定 60。1回あたり平均 6.5 なので9回ほどで頭打ち。最初の町（3〜5）が最果ての土地（67〜73）を追い越さないための歯止め |
| 難易度の上限 | 既定 76（ゲーム自身の上限）。下げると世界全体の天井が下がる |
| 引き上げる依頼の範囲 | 既定 all。incomplete にすると掲示板だけが上がり、品揃えは元のままに近くなる（在庫は完了済みの依頼も母数に入れるため） |
| 上げた分を元に戻す | 既定 OFF。下の「セーブには残らない」 |
| 難易度が上がったときの1行 | 既定「この地に貼り出される依頼は、以前より歯応えのあるものになっている。」上限に達した後は出ない。空にすると何も出さない |

クリアは**依頼の出所の土地**に付く。
道中で受けた依頼を別の町で終わらせても、育つのは出所の土地。

数えた回数と素の難易度は `state\area_difficulty\<世界名>.json` に入る。

```json
{"0": {"cleared": 7, "bonus": 43, "day": 4270,
       "base": {"1": 3, "2": 4, "3": 5, "27": 4}}}
```

`bonus` がその土地に積み上がった上昇量。
乱数なのでクリア回数から計算し直せないため、値そのものを持っている。
`base` は素の難易度（この MOD が初めてその依頼を触ったときの値）。
**新しい依頼は素の難易度で生まれてくる**ので、そのまま控えてよい
（ゲームは今の難易度を見ずに、世界を作った時点の帯から選ぶ）。
だからこの MOD は、依頼を作らせるたびにその場で上げ直す。
上げないと、いま作らせた1件だけが素の難易度で差し出される。

#### セーブには残らない（そういう作り）

書き換えているのは、遊んでいるあいだの依頼の一覧1箇所だけ。
ここはセーブに残らないので、**ロードすると難易度は素へ戻る**。
戻ったぶんは**セーブを読み込んだその瞬間に、世界じゅうまとめて書き直す**ので、
遊んでいる側からは切れ目なく続いて見える。

書き直す場面は5つ。

| いつ | どこを |
| --- | --- |
| セーブを読み込んだ直後 | 世界のすべての土地 |
| 依頼を探して新しく作らせたとき | その依頼（新しい依頼は素の難易度で生まれてくる） |
| 依頼を受ける直前 | その土地 |
| 掲示板を開いたとき | その土地 |
| 依頼を片付けたとき | その土地 |

ロードで世界ぜんぶを直すのは、**掲示板を通らない読み手のため**。
店の品揃えがその筆頭で、あれは「その土地の依頼の難易度」を直接読んでいる。
掲示板を開いた町だけ直していると、
まだ行っていない町の店だけ素のレベルで品を作ってしまう。

セーブに残らないことの見返りは大きい。

- MOD を外せばセーブは素のまま。外すために何かする必要は無い
  （`上げた分を元に戻す` は、いま動いているゲームを戻したいときの逃げ道）
- MOD の計算違いがセーブを壊すことがない。おかしくなったら
  `state\area_difficulty\<世界名>.json` を消せば、その世界は素に戻る

代わりに、**続きを持っているのは `state\` のほう**（クリア回数と素の難易度）。
ここを消すと、その世界の育ちがまるごと戻る。

#### 困ったとき

| 症状 | 見るところ |
| --- | --- |
| 上がらない | `out\area_difficulty.log`。`clear: 土地 0 は 4 回目（3〜10 から +7 を引いて、いま +27）` の形で毎回出る。出ていなければ数えられていない |
| 作りたての依頼だけ低い | 同じログの `search:` 行。`頼み文へ渡す難易度 3 -> 23` と `依頼 N 難易度 3 -> 23` が対で出ていれば効いている（新しい依頼は素の難易度で生まれてくるので、この MOD が生成のたびに上げ直している） |
| クリアしたのに数えられない | 同じログの「終わった依頼の土地が読めなかった」。依頼に `neighboring_settlement_id` が無い場合で、その回は数えない |
| ある土地だけ上がらなくなった | 同じログの「上限に届いた」、または `clear:` の行の `いま +60` が動かない。`1つの土地で上がる上限` か `難易度の上限` に達している |
| 店の品揃えが上がらない | 品揃えは入れ替わるまで初回のまま。`312_shop_restock` を入れる（入れていれば `out\shop_restock.log` の `restocked:` を待つ） |
| 難易度だけ上がって歯応えが変わらない | 敵は次に**受ける**依頼から変わる。既に受けてある依頼は受注時の内容のまま |

### `319_battle_tactics`: 戦闘を複数手の駆け引きにする

素の戦闘は、レベルが上がるほど「先に殴ったほうが一撃で終わらせる」になっていく。
数字を調べたら理由は単純で、ダメージが「攻撃力 − 防御力」の引き算だから
（GAME.md §2.10.2）。攻撃力は武器と一緒にどこまでも伸びるのに、
敵の体力はそこまで伸びない。だから必ずどこかで一撃を超える。

この MOD を入れると、ダメージは
**「相手の体力を何割削るか」**で決まるようになる。
互角の相手とは必ず数手の殴り合いになり、どれだけ格上でも削れない相手はいなくなる。
そのうえで、**格がまるごと離れていれば一撃は出る**。
最強の英雄は初期村の魔物を一撃で払えるし、
圧倒的な強敵は駆け出しを一撃で沈める。おかしいのは「互角なのに一撃」だけで、
そこだけを塞いである。

#### 一撃の重さは AI の審判が裁く

このゲームの戦闘は、毎回の攻撃を AI の審判が見ていて、
「今回の一撃はどれくらい重いか」を5段階で裁いている
（弱い／普通／強い／大技／必殺級。状況が良ければ1.5倍などの補正も付ける）。
素のゲームではこの裁きがほとんど数字に出ていなかった。
この MOD では裁きがそのまま削る割合になる:

| 審判の裁き | 削る割合（既定） |
| --- | --- |
| 弱い | 10% |
| 普通 | 16% |
| 強い | 25% |
| 大技 | 38% |
| 必殺級 | 55% |

つまり、戦い方の描写（弱点を突く、体勢を崩してから追撃する）が
審判の裁きを動かし、裁きがダメージを動かす。
互角〜そこそこの格差では1発の上限は 65%（既定）で、
**互角の相手から満タンで即死することはない**。
格の差が大きく開くとこの上限は外れる（上の一撃の話）。

#### 武器は今まで以上に効く

同じ裁きでも、武器と能力が強いほど実際に削る割合は増える。
**一段いい武器に替えるたびに、同じ相手への手数が目に見えて減る**:

| 持っている武器 | 格下の敵 | 同格の敵 | 体力2倍のボス |
| --- | --- | --- | --- |
| 最強クラス（攻撃力500） | 3手 | 8手 | 14手 |
| 上等（攻撃力245） | 4手 | 10手 | 18手 |
| 中くらい（攻撃力96） | 5手 | 14手 | 22手 |
| 初期装備級（攻撃力23） | 9手 | 20手 | 22手 |

（実測のキャラクタ、普通の一撃どうしの場合。防具は受けるダメージを減らす）

武器を買い替えれば今の狩場が楽になり、難しい土地へ行けばまた歯応えが戻る。
効きの急さは設定「武器の効きの強さ」で変えられる
（上げると差はもっと開き、最強武器は格下を2手で落とす）。
同格の相手は、どれだけ武器を盛っても一撃にはならない。
一撃が出るのは格がまるごと離れた相手だけ。

#### レベル差は「格の差」

レベルの離れた相手は、数字の上でもはっきり別格になる:

| レベル差 | 扱い | 効き（既定） |
| --- | --- | --- |
| 10 まで | 適正 | 補正なし。対等の殴り合い |
| 15 | 強敵 | 上の側の与えるダメージ2倍。下の側は半分 |
| 20 以上 | 格が違う | 上の側3倍で、一撃で倒すことがある |

間は徐々に効き始める（1レベルで景色が変わる崖は無い）。
15 上のボスは痛く硬い強敵で、20 上はそもそも勝負にならない。
逆に自分が 20 上なら、駆け出しの獲物は一薙ぎで終わる。
しきい値も倍率も設定で変えられる。

#### 同行の仲間はちゃんと戦力になる

仲間の攻撃はプレイヤーと計算の通り道が違い（武器の値が乗らない。実測）、
素朴に組むと体力の低い仲間が無力になる。
そこで**仲間は常に「その場に立てている一員」として対等に数え**、
同格の敵に弱い一撃でも1割前後は削る。
仲間の成長は本人のレベルで効く（宿の訓練で仲間も育てる `306_party_train_exp`
と噛み合う）。仲間の武器が数字に乗らないのは素のゲームも同じ
（NPC は武器を参照しない、という公式の回答がある）。
この MOD もそれに合わせて、仲間の強さは本人のレベルで見る。

#### 毒や能力低下がちゃんと効く

審判は「泥に足を取られて筋力が落ちた」のような状態異常をよく語ってくるが、
素のゲームではそれは**文章だけ**で、数字は1つも動いていない。
この MOD を入れると:

- 毒などの継続ダメージは、ターンごとに体力を削る（ただしそれだけでは死なない。
  とどめは誰かの攻撃で刺す）。`308_battle_damage_display` を入れていれば
  「エリス は 泥の浸食 で 29 のダメージを受けた」と**何によるダメージかまで出る**
- 能力の上げ下げは、与えるダメージ・受けるダメージに響く（±10〜40%）。
  掛かった瞬間に「（筋力低下: 与えるダメージが下がる）」と画面に出る

MOD を外せば元の「文章だけ」に戻る。セーブに余計なものは残らない。

#### 「防御」ができる

- 戦闘のスキルのボタンが**「スキル・防御」**になり、開いた一覧に
  「防御」が並ぶ（スキル1・（スキル2）・**防御**・やめる の順）。
  押すと1回の行動を使って身を固め、次に自分が動くまで受けるダメージが
  半分になる。ボスが大技を溜めていそうな場面で使う。
  戦闘画面に直接ボタンを足さないのは、5つ目のボタンが画面右へあふれて
  右側の表示と重なるため
- ボタンを使わず、自由入力に「盾を構えて受ける」のような防御的な文を
  打っても同じ構えになる。描写は審判がそのまま拾う

#### 設定

| 項目 | 既定 | 意味 |
| --- | --- | --- |
| 弱い〜必殺級の削る割合 | 10/16/25/38/55 | 審判の裁き5段階それぞれが、相手の体力の何%を削るか |
| 一撃の上限 | 65% | 互角の戦いで1発が削れる上限。格が大きく離れると外れて一撃が出る |
| 防具の効きにくさ | 800 | 小さくすると防具が強く効く。防御力がこの値と同じで被ダメほぼ半分 |
| 武器の効きの強さ | 75 | 大きいほど武器の良し悪しがダメージに強く出る |
| 適正と見なすレベル差 | 10 | ここまでは互角扱いで補正なし |
| 強敵と見なすレベル差 | 15 | この差で「強敵の倍率」が丸ごと掛かる |
| 格が違うと見なすレベル差 | 20 | この差以上は勝負にならない領域。一撃も出る |
| 強敵の倍率 | 200% | レベルが上の側の与ダメに掛かる。下の側は同じ率で割られる |
| 格が違う倍率 | 300% | 「格が違う」差での倍率。一撃の上限も外れる |
| 防御中のダメージ軽減 | 50% | 「防御」してから次に動くまでの被ダメージから引く分 |
| 毒や能力低下をちゃんと効かせる | ON | OFF にすると素のゲームと同じ文章だけに戻る |
| スキル一覧に「防御」を出す | ON | スキルのボタンが「スキル・防御」になる。OFF でも自由入力の防御は効く |

#### 困ったとき

| 症状 | 見るところ |
| --- | --- |
| ダメージが素のまま大きい | `out\battle_tactics.log`。効いた1発ごとに `hit:` の行が出る。代わりに `unmatched` が出ていたら、その戦闘の形をこちらが読めていない ＝ ログを添えて報告 |
| 「防御」がスキル一覧に出ない | `out\battle_tactics.log` の `guard into the skill list at N:` の行。並んだボタンの一覧が写るので、想定と違う画面ならそのまま報告の材料になる |
| 防御を押しても敵の番が来ない | 同じログの `battle input spec:` の行。`BattlePhaseManager` 以外が写っていたらその画面は未対応で、構えだけ付いて行動は消費されない（`guard button (no turn)`） |
| 状態異常が文章のまま | 同じログに `restored ...` が無ければ、審判がその状態異常に中身を付けてこなかった回（無いものは作らない）。設定の「毒や能力低下をちゃんと効かせる」が OFF になっていないかも見る |
| ダメージの数字を画面で見たい | `308_battle_damage_display` を一緒に入れると、1手ごとに増減が並ぶ |

### `320_guild_adventurer_recruit`: ギルドの冒険者の補充

素のゲームは、土地の初回生成で町の冒険者を3人作ったきり、あとは補充しない。
雇ったり死なせたりして減ると、その町のギルドの「冒険者達と話す」は
以後ずっと閑散としたままになる。

このMODは、一覧で会話できる冒険者が設定人数以下のとき
「冒険者を募集する」のボタンを足す。
押すと新しい冒険者を1人（設定で最大3人）LLMに書かせて、
その町のギルドに入れる。
名前・経歴・性格・口調・見た目はその場で書かれ、
強さはその土地の水準（居る冒険者と依頼の難易度の高いほう）に合わせる。
`318_` で土地が育っていれば、来る冒険者もその分強くなる。

| 設定 | 意味 |
| --- | --- |
| 募集ボタンを出す人数 | 既定 1。一覧で会話できる冒険者がこの人数以下のときだけボタンが出る。0 にすると誰も居なくなるまで出ない |
| 一度に補充する人数 | 既定 1。1人ごとにLLMの生成を1回待つので、多いほど募集に時間がかかる |

募集には所持金はかからない。
生成の間はボタンが「…」の待機表示になる（1人あたり十数秒〜1分程度。LLMの速さ次第）。

作った冒険者はゲーム自身の `npcs` 項目としてセーブに残る。
**MODを外しても消えない**（「MODを消せば完全に元通り」からは外れる）。
HP・スキル・立ち絵は空のまま作り、最初に会話や戦闘をするときにゲーム自身が埋める。

#### 困ったとき

| 症状 | 見るところ |
| --- | --- |
| ボタンが出ない | `out\adventurer_recruit.log` に `offered` の行があるか。無ければ一覧の人数が設定より多いか、画面を冒険者一覧と見分けられていない |
| 押しても誰も来ない | 同ログの `mod_adventurer_recruit:` の行。LLMの応答が読めなかったときは `募集をかけたが、応じる者は現れなかった。` と出て何も作らない |
| 別の町へ移ったら、店主が募集した冒険者になっている | ローダ 1.9.0 より前の `make_npc` はゲームの採番台帳 `index['npc']` を進めなかった。ゲームは町の生成でそこから id を振るので、募集した冒険者の id を踏んで店主の素データを差し替える（GAME.md §2.23）。同ログに `make_npc: index['npc'] -> N` の行が出ていれば直った版 |
| 作られたのに一覧に出ない | 同ログの `make_npc: created` と `enroll:` の行。`enroll: ... via nothing` なら名簿へ書けていない。ゲームがどの名簿から一覧を組むかの確認手順は VERIFICATION.md §3.39 |
| 同じ町で何度も募集できてしまう | 仕様。ただし一覧が設定人数以下のときしかボタンは出ないので、際限なくは増えない |

### `321_area_chronicle`: エリアの状況を更新（依頼クリアで案内文が変わる）

依頼を片付けると、その土地の案内文が変わる。
湿地の霧を晴らす依頼をクリアすれば、以後の案内文から霧の記述が消え、
会話と依頼の生成が「実際に変わった土地」を読むようになる。

素のゲームにも記録層は在る。
依頼クリアごとに `area_history` の `achievements` へ1〜2文の要約が入り、
「湿地の霧は晴れ」の粒度で土地の状態変化まで書かれる。
その全文は会話プロンプトにも毎回載っている。
**載っているのに、NPC が自発的に言及した回は 0/775**（GAME.md §2.24）。
だからこの MOD は素材の載せ方を強化せず、読み手が毎回読む
**土地の描写の原文（`Area.descriptions`）そのもの**を書き直す。

```text
依頼クリア → 新しい功績 ＋ 現行の案内文 → LLM が書き直す（別スレッド）
              「変化を織り込む。土地の正体は変えない。長さは維持」
           → 実行中の Area.descriptions を差し替え
           → state\area_chronicle\<世界名>.json（ロード時に当て直す）
```

`descriptions` は2枚あり、差し替えれば読み手全員に一度で届く。

| 何 | どこへ描画されるか |
| --- | --- |
| `overview`（1文） | 会話の【土地情報】に毎回一字一致で載る |
| `facilities`（数文） | 依頼の生成・要約の4マネージャに載る |

#### 編纂の入力は「新しい功績だけ」

控え（`done`）より後に増えた功績だけを渡す。古い功績は前回までの編纂で
既に文面へ織り込まれているので、毎回全部渡すと同じ変化が何度も適用される。
一度に増えた分が多いときは直近の件数（設定）に絞り、絞ったことをログに書く。

編纂が走らないままゲームを終了しても巻き戻らない。
`done` が進んでいないので、次の到着・日数経過・クリアの照合で立ち直る。

書き直しの受け入れには線がある。空の欄と、元の長さの2倍
（概要は最低100字、様子は最低300字を底とする）を超えた膨張は捨てて、
前の文面を残す。プロンプトには案内文の全文が毎回載るので、
編纂のたびに伸びる文面はそのまま肥大になる。

#### セーブにも world_data.json にも書かない

`world_data.json` はゲームが書き戻さない世界の骨格で、この MOD も書かない。
実行時の dict は骨格側と共有されている可能性があるので、
中身を書き換えず、**新しい dict を作って属性ごと差し替える**。

差し替えはセーブに残らないので、ロードすると案内文は素へ戻る。それでよい。
戻ったぶんはロードの1回で `state\` から当て直すので、
遊んでいる側からは連続して見える。見返りは `318_` と同じ2つ。

- MOD を外せば世界は素のまま。外すために何かする必要は無い
- おかしくなったら `state\area_chronicle\<世界名>.json` を消せば、
  その世界の案内文は素に戻る（功績の記録はゲーム側のものなので消えない）

#### 設定

| 設定 | 既定 | 意味 |
| --- | --- | --- |
| 1回の編纂に渡す功績の数 | 5 | 一度に見つかった未織り込みの功績が多いときの絞り |
| 第一声で近況に触れてよいと断る | OFF | 会話の第一声にだけ、複製の profile へ1行を足す保険。年代記のある土地でしか足さない |
| 第一声に足す1行 | 上記の断り文 | 空にすると何も足さない |
| 実行時の形をログに残す | ON | `Area.descriptions` の鍵と長さを起動ごとに1回だけログへ |

言及の保険が既定 OFF なのは、素の挙動を既定にするためと、
まず案内文の差し替えだけで言及が増えるかを測るため（介入前の基準値は 0/775）。

#### 困ったとき

| 症状 | 見るところ |
| --- | --- |
| 案内文が変わらない | `out\area_chronicle.log`。クリア後に `編纂を予約:` と `編纂できた:` が対で出る。`新しい功績が現れなかった` ならゲーム側の要約待ちに間に合っていない（次の到着・日数経過で立ち直る） |
| 変わった文面がロードで戻った | 同じログの `load: 世界 … を当て直した`。出ていなければ `state\area_chronicle\` に控えが無い |
| 書き直しが下手 | `output_data\<世界>\<PC>\mod_area_chronicle\` に頼み文と返答がそのまま残る。出来事の並べ直しに堕ちていないかはここで見る |
| 差し替え自体が効かない | ログの `descriptions:` 行。dict でない形が出ていたらこの版のゲームでは差し替えられない |

### `322_battle_bgm`: 戦闘BGMを置いた曲から選んで鳴らす

素のゲームの戦闘 BGM は `Assets\sounds\musics\battle\1. Echoes of Valhalla.mp3` の1曲に固定。
変えるには同名のファイルで上書きするしかない。

この MOD を入れると、次の2箇所にある曲から戦闘のたびに1曲を選んで鳴らす。

| 場所 | 何を置くか |
|---|---|
| `<ゲーム>\Assets\sounds\musics\battle\` | 素の曲が居る場所。ここに足してもよい |
| `<ローダ>\state\musics\battle\` | 足したい曲を置く場所。ゲームのフォルダを触らずに済む |

対応は `.mp3` / `.ogg` / `.wav`。同じ名前が両方にあれば `state\` 側が鳴る。

**曲を置いただけでは鳴らない**。設定画面で「使う」に入れた曲だけが候補になり、
何も入れていない種類の戦闘では素の曲がそのまま鳴る。

#### 設定画面

ローダの設定画面でこの MOD を選んで「設定…」（または一覧の「設定」列）を押すと、
宣言の設定ダイアログの代わりにこの MOD の画面が開く（TECH.md §3.12）。
直接 `python runtime\mods\322_battle_bgm\tool.py` で開いてもよい。

- タブは3つ（通常戦闘 / ボス戦闘 / 闘技場戦闘）。どのタブも左右2段で、左が置いてある曲の全部、右がその戦闘で使う曲。
  左をダブルクリック（または「使う >>」）で右へ入り、右をダブルクリック（または「<< 外す」）で外れる
- 右で選んだ曲の重みは下の欄で変える。確率の列は重みの合計に対する割合をその場で出す
- 一覧の上の欄で列ごとに絞り込める（曲名は部分一致、置き場は選択、重みは下限）。絞り込みは表示だけを変え、
  「全て使う / 全て外す」は表示中の曲だけに効く
- 「保存」で `state\musics\battle\playlist.json` と `settings\mod_settings.json` に書く。
  ゲームを起動したまま保存しても次の戦闘から効く
- 窓の大きさと位置は覚える（`settings\gui.json` の `tool_window`）

| 種類 | いつ |
|---|---|
| 通常戦闘 | 依頼中の遭遇、会話からの戦闘、衛兵 |
| ボス戦闘 | 依頼のラスボス戦 |
| 闘技場戦闘 | 闘技場の試合 |

| 設定 | 意味 |
| --- | --- |
| 「使う」に入れたときの重み | 既定 100。設定画面で曲を右（使う）へ入れたときの初期値 |
| 前回と同じ曲を続けて選ばない | 既定は入。候補が2曲以上あるときだけ効く |

#### 重みの意味と `playlist.json`

重みは比率で、同じ種類の合計に対する割合が確率になる。合計を 100 に揃えれば書いた数字がそのままパーセント。
`0` はその種類では鳴らない。

画面を使わず `state\musics\battle\playlist.json` を直接書いてもよい。

```json
{
  "tracks": {
    "1. Echoes of Valhalla.mp3": {"normal": 70, "boss": 0,   "colosseum": 50},
    "決戦.mp3":                   {"normal": 0,  "boss": 100, "colosseum": 0},
    "喝采.mp3":                   {"normal": 30, "boss": 0,   "colosseum": 50}
  }
}
```

- 見つけた曲は次の戦闘（または次の注入）で重み `0` の行として増える。書いた数字は消えない
- ファイルにあって曲が無い行は消さない（曲を一時的に外しても数字が残る）

#### 困ったとき

ログは `out\battle_bgm.log` の `[BGMPICK]` の行。1戦闘につき1行で、
選んだ曲・種類・決め手・そのときのフラグが並ぶ。

| 症状 | やること |
|---|---|
| 曲が変わらない | `[BGMPICK]` の行が出ているか。出ていなければ `out\modloader.log` の `applied` に `322_battle_bgm` があるか |
| `no candidate:` と出る | その種類で「使う」に入れた曲が無いか、`playlist.json` の曲名がファイル名と違う。`pool=0` が目印 |
| `FAILED` と出る | ファイルは在るが鳴らせなかった。`out\modloader.log` の直前の ERROR に例外がある。形式が対応外 |
| 通常戦闘なのに `boss by flag in_boss_battle` | `in_boss_battle` が下りていない。行の `pending=` が `None` ならフラグの残骸（VERIFICATION.md §3.42） |
| `playlist.json にある曲が見つからない` | 曲を消したか名前を変えた。行を消すか名前を直す |
| 曲を足したのに一覧に出ない | 拡張子が対応外か、サブフォルダに入れている。直下だけを見る。画面なら「再走査」 |
| 「設定…」を押しても画面が開かない | `out\modloader.log` ではなく設定画面の下の状態行を見る。`tool.py` が無いか、Python が tkinter を持っていない |

### `323_npc_carryover`: 別の世界のNPCを連れてくる

遊び終えた世界の NPC を書き出しておき、別の世界に登場させる。
再会したときに同じ人物として話せるよう、見た目・人物像・好感度を引き継ぐ。
`311_npc_profile_memory` と `403_npc_social_memory` が覚えていたことも引き継げる。

持ち込んだ NPC は、その世界をロードしたときに
**どこかの街のギルドか宿**に旅の冒険者として現れる。
「〈名前〉が旅の末に〈土地〉の〈場所〉へ流れて来たらしい。」と出たら着いている。

元の世界の NPC は消えない。**移すのではなく写す**ので、同じ人を何度でも連れて行ける。

#### 設定画面

ローダの設定画面でこの MOD を選んで「設定…」を押すと、この MOD の画面が開く（TECH.md §3.12）。
直接 `python runtime\mods\323_npc_carryover\tool.py` で開いてもよい。
タブは2つ。

##### エクスポート

元の世界を選ぶと、その世界の NPC が並ぶ。
列は 名前 / エリア / 施設 / 職 / 分類 / レベル / 親密度で、
選んだ人の顔と人物像は右に出る。

1世界の NPC は 100人を超えるので、**列ごとの絞り込み**が付いている
（名前は部分一致、エリア・施設・職・分類・親密度は選択、レベルは下限）。
先頭のチェックを入れた全員を一度に書き出せる。
見出しのチェックで、表示中の全員に入り切りできる。

書き出したものは `state\npc_carryover\<元の世界名>\<名前>.zip`。
1体 2〜2.5MB（立ち絵が6〜7枚入る）。
形式はセーブエディタの NPC 移植と同じなので、**あちらで書き出した zip も読める**。

##### インポート

書き出した NPC が並ぶ。選ぶと中身が右に出るので、置き先の世界を選んで「インポートを予約する」。

- **置き先に同じ名前の人物が居ると予約できない**。ゲームを起動する前にその場で分かる
- 引き継ぐもの（記憶 / 好感度・関係 / 経歴）は予約ごとに選べる
- 予約はロードのときに1回だけ果たされる。繰り返しロードしても増えない
- 予約の一覧では、まだ置いていない行は「予約を取り消す」、置いた後の行は「記録を消す」。
  **記録を消しても世界に居る NPC は消えない**（消すならセーブエディタで）

| 設定 | 意味 |
| --- | --- |
| 記憶を引き継ぐ | 既定 ON。`311_` の人物像とあなたについての記録、`403_` の社会関係を新しい世界へ写す |
| 好感度・関係を引き継ぐ | 既定 ON。切ると初対面から始まる |
| 経歴を引き継ぐ | 既定 ON。切ると経歴は空で来る |
| 到着を知らせる | 既定 ON。現れた場所と、見送ったときの理由をゲーム内の文で出す |

いずれも**予約するときの既定値**で、予約ごとに変えられる。

#### 持ち込まないもの

- **持ち物と装備**。アイテムの id は世界ごとの台帳で振られるうえ、
  値段はその世界の経済に紐づいている（GAME.md §2.13）ので、移す意味が薄い。
  そもそも素のゲームは NPC に装備を持たせない（実データ5世界 369体が全て空）
- **元の世界での id**。置き先の台帳で採り直す。記憶の相手も名前で引き直すので、
  置き先に居ない相手についての記憶は落ちる

作った NPC はゲーム自身の `npcs` 項目としてセーブに残る。
**MOD を外しても消えない**（「MOD を消せば完全に元通り」からは外れる）。
`320_guild_adventurer_recruit` と同じ性質で、消したいときはセーブエディタで消せる。

#### 困ったとき

| 症状 | やること |
| --- | --- |
| 予約したのに現れない | `out\npc_carryover.log`。`skipped` なら同名の人物が居て見送っている（ゲーム内にも1度出る）。行が無ければ、その世界の名前が予約の置き先と違う |
| 置いたのに次に開いたら居ない | **保存していない**。この MOD が触るのは動いているゲームの中で、ファイルが書かれるのは保存したとき。予約は `saved` が付くまで果たされたことにならないので、次のロードで置き直される |
| 顔が出ない・立ち絵が出ない | その NPC はまだ絵が作られていない（初回の会話まで生成されない）。書き出し画面で「顔画像なし」と出ているなら元の世界にも無い |
| 別の名前で現れた | `120_fix_npc_name_collision` が改名した。似た名前（表記ゆれ・修飾語付き）が置き先に居ると起きる。`out\npc_name.log` に相手が出ている |
| 世界の一覧が空 | セーブの置き場が見つかっていない。既定は `%LOCALAPPDATA%\Darmabeko\Instantale\saves\`。別の場所にあるなら環境変数 `IML_INSTANTALE_DATA` で指す |
| 記憶が引き継がれない | 予約のとき「記憶を引き継ぐ」が入っていたか。入っていても、元の世界に控えが無ければ写すものが無い（`311_` / `403_` を入れていない世界など） |

## 提供（4xx）

ユーザから提供を受けて取り込んだ MOD。
`4xx` の番号は出どころを表すもので、中身の種別は他の帯と同じく
`mod.json` の `"kind"` が名乗る（提供された計測 MOD は 2xx に入る。`223_` がそれ）。
取り込みの際にこちらの環境へ合わせて調整しており、経緯は各 MOD の説明にある。

この節の4本は MoririnJP 様の提供。うち `404_party_talk` はこちらとの共同。

### `401_battle_character_context`: 戦闘の審判へ同行者の人物と装備を見せる

このゲームの戦闘は、毎回の攻撃をAIの審判が見て、描写と裁きを返している
（GAME.md §2.10）。その審判が知っているのはプレイヤーと敵の情報が中心で、
一緒に戦っているパーティーメンバーが何者かをほとんど知らない。
だから同行者は名前だけの脇役として描かれ、口調が素に戻ったり、
渡したはずの武器と関係ない戦い方をしたりする。

この MOD は、審判へ送る文章の末尾に同行者の紹介を1枚足す。実物はこの形:

```
【パーティーメンバー戦闘情報】
パーティーメンバーについては、以下の人物・装備情報を優先して参照してください。
- party_member: 重装のハンス
  HP: 576/576
  weapon: 鉄の大盾(歪んだ縁に無数の刃こぼれが残る)
  profile: かつては名のある騎士だったが、今は泥の中で盾を構える男。
  speech_style: 寡黙でぶっきらぼう
```

同行者が武器を持ち替えていれば描写が変わり、口調が決まっていれば戦闘中もその口調で喋る。
プレイヤー自身の情報は足さない（本体が既に渡している）。

#### どう動くか

- 足す先は戦闘の審判（`referee_*` の9種）だけ。会話や生成など他のLLM処理には触らない
- 戦闘中かどうかは、107_fix_battle_flag_stuck が正常化した `in_battle` で判定する。
  ボス戦もこのフラグで拾えることは実機で確認済み。闘技場が別挙動だった場合は
  ログに `NOTE in_colosseum_battle is set ...` が1度だけ出る仕掛けにしてある
- 人物・口調・装備は今の値（runtime）を優先し、欠けている項目だけ、
  ロード時にゲーム自身が読んだ保存辞書から補う。この控えはタイトルへ戻ると捨てる
  （別セーブへ人物情報を持ち越さないため）
- 装備は本体の表記に寄せて `weapon: 名前(説明)` で書き、攻撃力等の attributes は
  別の行に分ける

#### 大きさに蓋がある

審判は1手ごとに呼ばれるので、この紹介は毎ターン送られる。
野放しにすると1人あたり最大2万字が毎手載ってしまうため、項目ごとと全体の両方に上限を置いた。

| 項目 | 上限（字） |
| --- | --- |
| profile | 800 |
| personality | 500 |
| speech_style / tactics | 400 |
| traits / status | 300 |
| job | 200 |
| 装備の名前 / 説明 / attributes | 120 / 400 / 300 |

全員あわせて 6,000 字が目安。人数で割り、溢れた分は末尾の項目から落とす
（1人あたり最低 900 字は確保し、名前とHPだけになることはない）。
並びがそのまま優先順位で、名前・HP → 装備 → 人物・口調の順に残る。

#### 数字には触らない

攻撃力・防御力をダメージへ直接加算することはしない。装備が効くのは、
審判が描写と裁きを決める材料としてだけ。`319_battle_tactics` を入れていれば
審判の裁きがそのままダメージの割合になるので、良い装備の描写が裁きを押し上げる形で
間接的に数字へ届く。

#### 困ったとき

| 症状 | 見るところ |
| --- | --- |
| 補足が載っているか確かめたい | `out\battle_character_context.log`。載せるたびに `appended N character(s), M chars` が出る。実物は `output_data\<世界>\<PC>\referee_*\` の最新 JSON の user message 末尾（世界名が解決できない場合は `unknown\unknown\` に入る） |
| `appended 0 character(s), 29 chars` が出る | 同行者がいない戦闘の正常な記録。「パーティーメンバーなし」とだけ伝えている |
| `WARN cannot resolve party member` が出る | 名簿に id はあるのに実体が引けていない。名簿の在り処も同じ行に写るので、そのまま報告の材料になる |
| `NOTE in_boss_battle is set ...` が出る | `in_battle` が落ちているのに別の戦闘フラグが立っていた記録。戦闘中判定を広げるかの判断材料なので、出たら報告 |

### `402_party_inventory_transfer`: 仲間とアイテムを受け渡しできる

素のゲームには、同行している仲間へアイテムを渡す手段が無い。
拾った武器も薬も全部プレイヤーが抱えたままで、自由入力で渡すほかに仲間へ持たせる方法が無い。
また、受け渡しが自由入力である以上、渡したアイテムが帰ってくる保証がない。

この MOD を入れると、現在のパーティーメンバーとの会話にだけ
「＜アイテムの受け渡し＞」という選択肢が増える（「会話を終了する」の直前）。
押すと、店の売買と同じ2枚並びの窓が開く。左が自分、右がその仲間で、
アイテムをドラッグすればどちらの向きにも移り、そのままセーブされる。

右側（仲間側）の武器・防具を右クリックすると
MOD専用の「装備する／外す」ボタンも出るが、
これで仲間に武器・防具を装備させることはできない（次の節）。

#### 「装備する」ボタンでは装備できない

素のゲームに NPC の装備装着は存在しない（NPC は武器を参照しない、という公式回答がある。
`319_battle_tactics` の DOC 参照）。「装備する」が書くのは
セーブの `equipments` 欄（全キャラクターが持つ項目）への記録だけで、
素のゲームは読まない。つまり仲間は武器・防具を装備できず、
渡したアイテムは持たせた状態にしかならない。

この記録を読むのは `401_battle_character_context` だけで、戦闘の審判へ
「この仲間は何を装備しているか」という文として渡る。
装備としてダメージや防御の数字に乗る仕組みは無い。

#### どう動くか

- 選択肢が出るのは、会話相手が今のパーティーメンバーのときだけ。
  他人や、別れた後の元仲間には出ない
- 受け渡しの窓はゲーム自身の売買UIを場面名 `party_transfer` で借りている。
  右側の見出し「所持品」は仲間の名前に描き替える
- ドラッグで移すと、持ち物の実体・アイテムの id・持ち主の記録を同期し、
  少し待ってからゲーム自身の `save_game` で保存する。連続で動かしたときは
  最後の1回だけ保存が走る
- **装備したままのアイテムを渡すと、装備は自動で外れる**。
  外し方はゲーム自身の解除処理（`Item.unequip`）をそのまま呼ぶので、
  装備欄の表示も一緒に片付く（v17 までは装備の記録だけ直していたため、
  「装備中」の表示が残り、そこから外そうとするとゲームごと落ちた。v18 で修正済み）
- 保険として、装備の記録と食い違う「外す」操作はゲームへ通さず、
  1行記録して無視する。本体はその状況で必ず落ちるため
- 「装備する／外す」は、その仲間の `equipments` の weapon / wearable へ記録を直接書く。
  外すときは欄ごと消す（本体がプレイヤーの装備を外した後と同じ形）
- タイトルへ戻ってロードし直しても、会話中なら選択肢は復元される

#### 外すとき

MOD を外しても受け渡し済みのアイテムはそのまま相手の持ち物に残る（セーブの正規の形なので無害）。
仲間の装備の記録もセーブに残るが、素のゲームは読まないので実害はない。
気になるなら、外す前に仲間の装備を全部「外す」にしておけばセーブから消える。

#### 困ったとき

| 症状 | 見るところ |
| --- | --- |
| 選択肢が出ない | 会話相手が現在のパーティーメンバーか確認。仲間なのに出ないなら `out\party_inventory_transfer.log` に `added` の行があるか |
| 移したのに保存されていない気がする | `out\party_inventory_transfer.log` に `transfer synced` と `save_game complete` が並んでいれば保存は走っている。`WARN save skipped` なら移した品を見失っている |
| 装備したまま渡したら装備が残った | v18 で本体の解除処理ごと外れる。外れていなければ `out\party_inventory_transfer.log` を添えて報告。過去のセーブに残った宙ぶらりんは 2026-08-27 に修復済み |
| `stale unequip ignored` が出た | 古い「装備中」表示から外す操作が飛んだのを無視した記録。素通しすると本体が落ちるため。頻発するなら報告の材料になる |
| 「装備する」ボタンが見えない | 画面の右上・上端で右クリックした場合、本体popupの枠外に出る可能性が未確認のまま残っている。位置を変えて出るならその報告が材料になる |
| 装備の実際の動きを記録したい | デバッグモードで `223_probe_party_equipment` を有効にすると、popup と装備欄の中身が `out\party_equipment_probe.log` に写る |

### `403_npc_social_memory`: NPC同士がお互いを認知し、関係を覚える

`311_npc_profile_memory` を入れると、NPC はプレイヤーとの会話を覚えるようになる。
だが NPC 同士はお互いを知らないままで、仲間を連れて誰かと話しても、
会話相手はその仲間が視界に入っていないかのように振る舞う。
昨日プレイヤーと口論した仲間を連れて同じ店に入っても、店主は何も覚えていない。

この MOD は、その「NPC から見た別の NPC」を作る。仕事は2つ。

#### 1. 会話の場に同行者を立たせる

仲間を連れて NPC と話すと、会話相手のプロンプトに1枚足される:

```
【現在この場に同行している人物】
以下の人物は現在プレイヤーと同行し、この会話の場にいる。あなたが演じるのは
会話相手であるあなた自身だけで、同行者の台詞を代行してはならない。
ただし存在・発言・既知の関係は認識してよい。
- プレイヤー (id=80)
  ゲーム側の基本情報（短縮）: profile: 宿の娘。...
  311の人物像（短縮）: ...
  プレイヤーから見た主人公: ...
  403が記録した関係（短縮）: 信用していない。値切りの件を根に持っている。
```

会話相手は同行者の存在と関係を踏まえて話すが、同行者の台詞は演じない。
まだ関係の記録が無い相手については「初対面か既知かを捏造しない」と明示する。

#### 2. 会話が進むたびに関係を更新する

会話が1ターン進むごとに、直近のやり取り（既定10往復・最大2,600字）と
参加者全員の情報を抽出用のLLMへ渡し、
「誰が誰をどう認識し直したか」を裏で更新する。記録は**方向つき**で、
プレイヤー→仲間と仲間→プレイヤーは別々に持つ。プレイヤーについての記録は作らない
（そちらは 311 の仕事）。

- 記録は各方向「現在の認識の短い要約」（既定600字目安）と、
  確定した事実の控え（既定で最大10件）の2本立て
- 抽出は裏のワーカーが1本ずつ処理する。会話はその間も止まらない
- 311 が既に持っている人物像・プレイヤー観は抽出の材料として読む。
  嫉妬や対抗心のような反応は、その人物設定から自然に導けるときだけ記録される
- 参加者は会話相手＋同行者で、既定6人まで。1対1で同行者がいなければ何もしない

#### しまい方

- 記録は `state\npc_social_memory\<世界名>.json`。世界ごとに別で、
  この MOD だけが書く。消せば関係の記憶だけが消え、ゲーム本体は無傷
- 311 の記録は読むだけで、書き換えない
- MOD を外しても、セーブや 311 側には何も残らない

#### 設定

| 項目 | 既定 | 意味 |
| --- | --- | --- |
| 関係抽出に載せる直近のやり取りの数 | 10 | 増やすと取りこぼしが減るが、抽出への入力が増える |
| NPC→NPC関係記録の目標長 | 600 | 各方向の要約の目安。保存や注入で機械的には切らない |
| NPC間で判明した事実を残す件数 | 10 | 方向ごとの追記控え。要約で落ちた認識を次回抽出へ戻す。0で残さない |
| 会話相手へ同行NPCの人物情報も見せる | ON | OFF にすると名前と関係だけになる |
| 1回の関係抽出で扱うNPC上限 | 6 | 大人数時のプロンプト肥大を防ぐ |

#### 困ったとき

| 症状 | 見るところ |
| --- | --- |
| 関係が育っている気がしない | `out\npc_social_memory.log`。ターンごとに `extract queued`、更新されれば `updated 誰→誰` が出る |
| `extract skipped: fewer than two NPC participants` | 1対1の会話で同行者がいない。記録するNPCのペアが無いので何もしない、の正常な報告 |
| 反映が1歩遅れる | 仕様。抽出は裏で走るので、今の会話の変化が載るのは次のターン以降 |
| `structured route unusable` が出た | 構造化応答を返せない LLM 構成。以後は普通の JSON で聞き直す経路に固定される。ローカルLLMでは正常な切り替え |
| 覚え違いをリセットしたい | `state\npc_social_memory\<世界名>.json` を消す。その世界のNPC同士の記憶だけが初期化される |

### `404_party_talk`: パーティーメンバー全員と話す

素のゲームの会話は常に1対1で、仲間を連れていても話せるのは1人ずつ。
`403_` を入れれば会話相手が同行者を認識するようになるが、
同行者は黙って立っているだけで、こちらの発言に横から口を挟むことはない。

この MOD は、「会話する」を押した先の相手一覧に「パーティーメンバーと話す」を1つ足す（「やめる」の手前）。
その場に NPC が居なくて「会話する」自体が無いときは、こちらで「会話する」を足し、
押すと「パーティーメンバーと話す」と「やめる」だけの一覧を開く。
押すと仲間から1人が選ばれ（ランダム）、その相手との普通の会話に入る。
違うのはその会話の間だけで、こちらが一言喋るたびに仲間全員がそれぞれの立場で反応する。

```
「そうだろぉ？お前の射撃も凄いと思ってるけどな、俺は」
アリス・スミス: あら、嬉しいこと言ってくれるのね。（嬉しそうに微笑み、親しげに肩を寄せてくる）
ハナ・ミヤビ: ……非効率な誉め合いです。射撃精度と物理破壊力には相関関係がありません。
```

- 選択肢が出るのは仲間が2人以上のとき。1人なら普通の会話と変わらないので出さない
- こちらの1発言を1ラウンドとし、1ラウンドに各仲間は最大1回しか反応しない。
  反応しない仲間がいてもよく、台詞の代わりに（銃を磨いている）のような行動描写だけでもよい
- 最初に選ばれた1人（アンカー）は本体の会話相手なので毎ラウンド必ず先頭で反応する。
  他の仲間はその後に順に表示される
- 立ち絵は参加者全員が横に等間隔で並ぶ（既定は画面幅の 0.32〜0.68 の範囲。2人なら 0.32 と 0.68、3人なら 0.32・0.5・0.68。名簿順）。
  両端は設定で動かせる。左の選択肢の列（〜0.2）と右の仲間欄（0.78〜）に掛からない値が既定
  本体の相手枠はアンカーのまま位置だけずらし、他の仲間ぶんは同じ形の枠を足す。
  会話を終えると枠は消え、相手枠の位置も戻る。
  設定「仲間の立ち絵を並べる」を切ると、喋った人物へ立ち絵が切り替わり、終わるとアンカーへ戻る
- 仲間の人物像は、ゲーム自身の設定に加えて `311_`（本人の現在像・プレイヤー観）と
  `403_`（仲間同士の関係）の記録を**読むだけ**で載せる。どちらも書かない
- 会話は本体のものなので、終わり方も本体と同じ。「会話を終了する」は
  この MOD の間だけ「話し合いを終了する」と表示される
- この会話の間は「ここで別れる」（`302_`）と「＜アイテムの受け渡し＞」（`402_`）は出ない。
  どちらも相手1人との会話に向けた選択肢で、全員と話している場面では相手が定まらないため
- この会話では自由記述で何を頼んでもゲームの状態は変わらない
  （移動・売買・戦闘・アイテム操作は起きない。仲間が態度で応じるだけ）

仲間全員に反応させる LLM 呼び出しは会話の LLM を差し替える形で、
本体の1対1の呼び出しは走らない（1発言につき LLM は1回）。
記録は `out\party_talk.log`。`output_data\` には `mod_party_talk` の名で残る。

| 設定 | 意味 |
|---|---|
| 会話開始の選択肢 | 既定「パーティーメンバーと話す」 |
| 会話終了の選択肢 | 既定「話し合いを終了する」 |
| 参加NPC上限 | 既定 6。名簿の先頭から数える |
| LLMへ渡す直近の会話数 | 既定 12 ラウンド（こちらの発言の回数で数える。仲間の台詞が何行あっても減らない） |
| 仲間の立ち絵を並べる | 既定 入。切ると喋った人物へ切り替える方式 |
| 立ち絵の左端の位置 / 右端の位置 | 既定 0.32 / 0.68（画面幅に対する比。両端の仲間の中心）。人物が UI に掛かるなら内側へ、間隔が詰まりすぎるなら外側へ |

#### 制約

- 本体の会話要約には仲間の台詞が載らない。仲間の台詞は本体の履歴に積まず、この MOD の側で控える。
  積むと `311_` の抽出が会話相手（アンカー）の発言として読んでしまうため
  （本体の `conversation_history_to_text` は assistant を相手の名で描く）。
  したがって会話を終えたときの要約とライフログ、`311_` の記憶に残るのはアンカーの台詞だけ。
  `403_` の関係更新も同じ履歴を読むので、仲間同士のやり取りは関係に反映されない
- `317_reputation` などが会話の LLM へ差し込んでいるものは、この会話では載らない
  （差し替えの外側に居て素通ししない）。載せたければこの MOD のプロンプトへ足す
- 選択肢が出るのは「会話する」を押した先の相手一覧だけ。根のメニュー・宿屋の部屋選び・宿泊中・
  戦闘中・依頼一覧には出ない。ギルドの「冒険者達と話す」の一覧は同じ形だが出さない（`320_` の募集ボタンと同じ見分け方）
- NPC 不在の根のメニュー（出口はあるが「会話する」が無い画面）には自前の「会話する」を末尾に足す。
  本体の「会話する」が在る画面には足さない。会話中・戦闘中・ポップアップ中も足さない
  （店を出た後も残る `in_shopping` は見ない）
- 本体の「会話する」の一覧に相手が居なくても（「やめる」だけ。ギルドなど）「パーティーメンバーと話す」は出る
- LLM が返す名前は参加者の名前と突き合わせ、居ない人物と2回目の反応は落とす（ログに `dropped=` で残る）
- 立ち絵の無い仲間は並べない（素のゲームでは起きない。セーブを手で壊した場合の話で、この MOD は面倒を見ない）
- 並べている間にキャラクターシートを開くと、右側の自分の立ち絵と仲間の枠が重なる（シートの窓が上に載るので実害は薄い）

#### 困ったとき

| 症状 | やること |
|---|---|
| 選択肢が出ない | 仲間が2人未満か、「会話する」の相手一覧を開いていない。`out\party_talk.log` に `added ... to the talk list` が無ければ一覧と見なしていない（`DisplayTalkChoice.execute` を通っていないか、別の画面の spec が混ざっている） |
| NPC 不在なのに「会話する」が出ない | `party_talk.log` に `added own '会話する'` が無い。`own '会話する' withheld: ...` が出ていればその旗（戦闘・会話・ポップアップ）が立っている。何も無ければ出口（`MovePhaseManager`）の無い画面 |
| 押しても会話に入らない | `party_talk.log` の `pressed` の次を見る。`ERROR ConversationStartManager not found` なら注入が `__main__` の前 |
| 仲間が誰も反応しない | `round N anchor=... extras=[] dropped=[...]` を見る。`nonparty:` が並ぶなら LLM が別名で返している |
| 仲間の立ち絵が黒い | 立ち絵の切り替えは Clock 経由で行っている。出るなら `modloader.log` に `party talk:` の行があるか |
| 立ち絵が並ばない | `party_talk.log` に `portrait added` が無い。`WARN character_image not found` なら HUD の相手枠が引けていない |
| 会話を終えても仲間の枠が残る | `portraits removed` が出ていない。`modloader.log` の `party talk: cannot remove` を見る。タイトルへ戻れば消える |
| パーティー会話中に「ここで別れる」「＜アイテムの受け渡し＞」が出る | `party_talk.log` に `hid the party-only choices` が無い。302 / 402 の印のキーが変わっている（`HIDDEN_MARK_KEYS`） |
| `structured -> None; fallback no-structure` | 構造化出力を使えないモデル。`no-structure` で読めていれば動く。読めなければ `WARN fallback unreadable` |
