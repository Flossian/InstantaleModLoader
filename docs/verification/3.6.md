# 3.6 その後の予定（優先順）

**実装が要るもの**

1. 空 `Literal[]` の修正（[§2.40](2.40.md)）。
   差し替え先の型をゲームがどう食うかだけ先に確かめる
2. `ValueError: ... image_portrait`（[§2.42](2.42.md)）。
   塞ぐのは1行だが、None のときの正しい振る舞いを決めてから
3. 送信の入口を1つだけ包んでいる MOD が他に無いかの点検（[§2.41](2.41.md)）

**実機で1回踏めば片付くもの（まとめて1セッションで消化できる）**

1. 仲間を1人連れて、**雇った町とは別の町で**クエストを1件終える → `303_` の置く側（[§3.3](3.3.md)）
2. **仲間を1人連れて**宿屋で訓練を1回 → `306_` のレベルアップ（[§3.12](3.12.md)）
3. `313_` を**切って**、フィールドイベントで差が 0 でない回を数件集める →
   `215_` の負の差（[§3.17](3.17.md)）。`313_` 側はもう決着している
4. コロシアムに入る／味方を1人倒れさせる → `308_` の残り2点（[§3.14](3.14.md)）
5. 体力を3分の1未満にして「危険な道を行く」を押す → `307_` の断り（[§3.13](3.13.md)）
6. レベル60のまま保存されたセーブを `REPAIR_LOADED` を入れて読み込む → `123_` の残り用途
7. 店を初めて開く → `128_` 版6の対応表（[§3.26](3.26.md)）と `129_` の `generated*`（[§3.19](3.19.md)）
8. 土地の移動で読み込みが延びた回に `316_` の戦闘へ入る → 塗り直しの時機（[§3.35](3.35.md) #9）。
   「選択肢が戦闘のものになった最初の合図」へ直した側が実機未確認
9. `epithet_probe.py --current <名>` を通す → `317_` の統合後の頼み文（[§3.36](3.36.md) #5）。
   [§2.63](2.63.md) の実測は旧1段目の頼み文でのもの
10. `311_` と `317_` を併せて入れて `204_probe_prompt_bloat` で測る →
    プロンプト長の重なり（[§3.36](3.36.md) #4）
11. `320_` で募集したあと別の町へ移り、店主が新規に生まれることを見る →
    採番の衝突の直し（[§3.39](3.39.md)）
12. 言及率を前後で数える → `321_`（[§3.40](3.40.md)）
13. `in_battle` が焼かれたセーブを読む → `322_` のロード直後の `[BGMPICK]`（[§3.42](3.42.md)）
14. 仲間を2人以上連れて「パーティーメンバーと話す」 → `404_` のレビュー9点の再確認（[§3.41](3.41.md)）
15. 道具で拾った顔を目で見る・敵と戦う → `131_` の3点（誤検出率・旗・敵の除外。[§3.43](3.43.md)）
16. `403_` の控えのある NPC を `323_` で持ち込む → 社会関係（[§3.44](3.44.md)）

**遊び続けないと出ないもの（1セッションでは決まらない）**

1. `316_` を既定の設定（発生率30% / クールダウン10日 / 土地と日数のみ）のまま遊ぶ →
   出る頻度が遊べる範囲か（[§3.35](3.35.md) #8）。ここまでの確認はすべて動作確認用の設定だった
2. 遊び込んだセーブで各地の評判を編ませる → `317_` の編纂の質（[§3.36](3.36.md) #1）
3. 質的な変化を何度か起こす → `317_` の据え置き（[§3.36](3.36.md) #2）。
   変化のたびに名が揺れないかを `out\reputation.log` で見る
4. 新しい世界と遊び込んだセーブで `achievements` の件数を見る（[§3.36](3.36.md) #3）。
   増える契機が分かると `317_` の `MIN_DEEDS` の既定を判断できる
