# 3.122 計測（2xx）の見直し2: 測り方の取り違え・決まりの破れ・書く量（オフラインで通過・主なものは実機で成立）

2026-11-03 に 200〜245 の全本を読み直し、`out\` の実ログを数えた。
[§3.78](3.78.md) の見直しの後に足した計測と、その後の版の分も入る。
対象の関数が無くなって空振りしている包みは無かった。
見つかった型は4つ。決着した計測も無効にせず、有効のまま直した。

- **測った値が事実と違う、または測れていない**。
  `204_` のサイドカーの包みは llama-server の起動190回のうち2回しか録れていなかった。
  `206_` は「次」（ページ送り）の押下を8件目の候補の押下として書いていた。
  `243_` の `link` は入口の戻り値（tuple）を品として読み、全511行が空だった。
  `214_` は他の計測の試し打ちをゲームの呼び出しとして書き（窓のログの約半分）、`MOD frames` の判定はほぼ常に陽性だった（9,301/10,773 行）。
  `219_` の `mods in path` も同じ理由でいつも yes だった（46/46）。
  `244_` の魅力の出どころは、ローダの能力値の窓口が足す補正と比べられず、11-01 から一致なしが続いた。
  `207_` の `mixer` の本数は効果音も数え、曲の重なりを見分けられなかった。
  `230_` は画像生成が落ちた回を残していなかった（10-29 の access violation 77件）。
  `236_` の解決の段の行はいつも `actor=None` だった
- **他の計測の記録を汚していた**。
  `243_` の一括計測が `221_` の価格表を毎回61〜103行埋め、`215_` の換算が `244_` の枠を食っていた
- **決まりを守っていなかった**。
  `required=False` の抜け（208・211・212・227 の10本）、`safe=True` の抜け（209・210・213・216〜219・225）、`hasattr`（225・227・240・242・244）、
  apply ごとに作り直されて注入し直しで0に戻る上限（209・210・212・213・214・237・245 など）、
  注入し直しのたびに同じボタンへ観測者が積もる `fbind`（227）
- **書く量や手間が多かった**。
  `234_` の見張りの行の45%は値1つの往復で全項目を書き、`222_` の継続効果の行の 1,901/1,970 が空、`225_` の乱数の行の85%が `tempfile` の呼び出し、
  `223_` のログの90%が毎回同じ `__init__` の行、`210_` は人物の全文の JSON を30日で約9MB、`209_` は毎回自分のログ（10.7MB）を丸ごと読み直していた

試し打ちの印 `sys._instantale_probe_dry_run_thread` は、立てる側が立てる前の値を控えて戻す形に揃え（入れ子でも外側を消さない）、
印の立っている自分のスレッドの呼び出しは 214・215・220・221 も記録しないようにした（GAME.md §2.10.4）。
ローダの値段の関所にも、同じ戻り値の読み違い（品を作る入口の付け直しが tuple を受けて何もしない）と、引数を位置に直して渡す包みがある。ローダは別に直す。
