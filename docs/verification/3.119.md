# 3.119 能力値の補正の窓口（`abilities`）と、装備の能力値補正・武器の効果（`411_equipment_bonuses`。提供の `802_` を乗せ替え）: 窓口と能力値補正・武器の効果は実機で成立

2026-11-01 に作った。
提供を受けた `802_equipment_ability_bonus`（わさの 様）は、能力値を読む計算の最中だけ主人公の値を書き換え、抜けたら戻す形だった。
この形は、途中でゲームが組み直すと引き過ぎ、包みの層の順で他の MOD の記録とずれる。
今後も一時の強化（134）・宿の食事・病気や怪我と、能力値を動かす MOD が増えるので、補正をローダの窓口で分け合う形にした（TECH.md §3.3.27）。

## 測ったこと（11-01、テストワールド。`244_probe_ability_reads`）

| 読む所 | 読む値 | 根拠 |
|---|---|---|
| 素点 `calculate_battle_effect` | `attack_power` / `magic_power` だけ | 攻撃力を2倍にすると主人公は ×√2、仲間と敵は ×2。能力値はどちらを +10 しても動かない |
| 防御 `get_npc_defense` | 呼ぶたびに `ability_scores` の6つの平均 | +10 で Lv72 なら +154。`original_ability_scores` は読まない |
| 手番の順 `get_initiative`（`BattlePhaseManager.battle` の中の入れ子の関数） | `ability_scores` の器用さ | ずらした値が渡った |
| 依頼の出来事 `QuestEventManager.execute` | `ability_scores` の6つ | ずらした値が渡った |
| 印象 `document_emotion_scores_new` | 第2引数に主人公の `ability_scores` の魅力 | ずらした値が渡った |

- 「ずらした」は、主人公の `ability_scores` だけをスクリプトで元の値と違う値にした試し（素の遊びでずれる経路は見つかっていない）
- 11-01 の途中から `244_` の `charisma given=34 ability_scores=30 original=30 matches=[]` が29行続いた。ローダの窓口が一番外側で第2引数に魅力の補正を足した結果で、`244_` が補正込みの値と素の値を比べていた。直した後は `bonus` と `boosted`（素の魅力＋補正）を並べ、一致すれば `matches` に `ability_scores+bonus` が入る（[§3.122](3.122.md)）
- セーブに残るのは `original_ability_scores` と `body_parts` だけ。`ability_scores`・`attack_power`・`max_hp` はロードの `Character.__init__` が作り直す
- `update_ability_scores` は休養・依頼・戦闘・ロードのどれでも走らなかった。`attack_power` はロードの後に組み直されない

## 決めた仕様

- 補正は人物に書き込まない。ゲームが能力値を読む場面の間だけ、`Character` の読み口が補正を足した写しを返す
- 筋力・知力の補正は、攻撃力・魔力に「補正 × レベル係数」で直して見せる（素点が能力値を読まないため）
- 包む場面は `calculate_battle_effect` / `get_npc_defense` / `BattlePhaseManager.battle` / `QuestEventManager.execute` と、印象の引数（決めた範囲。battle と出来事は LLM を待つ長い関数だが、その間に能力値への書き込みは無かった）
- 期限は日数・`REST`・`BATTLE`・無期限の4つ。`REST` は宿で部屋を選んだ時点で切れる（宿泊の中で何をするかによらない）
- ステータス画面の能力値の後ろに `(+4)` の形で補正の合計を出す
- 最大 HP には効かせない（延期）
- 802 の判定の窓（マスター AI の4本）は外す。313 は窓口に聞く

## 411 で変えたこと（802 から）

- 品に補正を付ける部分（抽選・説明欄への書き込み・入口）は 802 のまま
- 効かせる部分を、身に着けている品の補正を `abilities.declare` で答えるだけにした。計算の最中に書き換えて戻す包み・保存の間だけ外す包み・仲間の防御の戻り値に足す包みを外した
- 設定「効かせる場面: 戦闘 / 判定」を外した。残るのは「効かせる相手: 仲間」
- `after`（313 / 333）を外した（包みの順に頼らない）
- 版は 2。author の末尾に R01/Flossian を足した

## 実機（11-01、テストワールド Lv72、411 と窓口を入れて1回の起動）

主人公の武器に「筋力 +4」をスクリプトで書き、期限つきの補正を2つ置いた（次の戦闘の終わりまで器用 +5、次の部屋選びまで魅力 +3）。

| 確かめたこと | 結果 |
|---|---|
| ステータス画面 | `筋力: 30(+4)`・`器用: 30(+5)`・`魅力: 30(+3)`。欄に収まった（121 入り） |
| 会話の終わりの印象 | 魅力 33 が渡った（素は 30） |
| 宿の部屋選び | 魅力の補正だけが切れた（`1 bonus(es) ended at the rest`） |
| 最初の戦闘の防御 | 6つの平均 27.83（筋力 34・器用 35 を足した値） |
| 最初の戦闘の手番の順 | 器用 35 |
| 素点 | `get_base_damage_value` に攻撃力 524（462 + 4 × 15.4）。6手とも |
| 最初の戦闘の終わり | 器用の補正が切れた（`1 bonus(es) ended at the battle`）。2戦目の防御は 27.0・手番の順は 30 |
| 依頼の出来事 | 筋力 34 が渡った |
| 場面の外 | 素の能力値・攻撃力のまま（`244_` の試しは素の関数を呼ぶので 406 / 462） |
| 控え | `state\abilities\テストワールド×ヴェイン・カスティロ.json` に書かれ、切れた補正は消えた |
| 例外 | 無し |

試しの後は控えへ戻した。

## 武器の効果（11-04 に足した）

能力値補正だけでは、武器ごとの違いが出なかった。
筋力の補正は「補正 × レベル係数」で攻撃力に溶け、防具の補正と見分けが付かない。
そこで武器に、一撃の効き方を変える効果を足した。
同時に、MOD の名前を `411_equipment_ability_bonus` から `411_equipment_bonuses` に変えた（v1.20.0 の公開前なので、配った先への影響は無い）。

### 決めた仕様

- 効果は6種類（特効・会心・吸収・貫通・毒・怯み）。epic 以上の武器に、レア度ごとの数（既定 epic 0〜1・legendary 1・mythic 1〜2）だけ、同じ種類を重ねずに付ける。強さはレア度で決まる（DOC.md の表）
- 特効の相手は、画面で見分けられるものだけにした（ボス戦・格上・手負い・無傷）。敵の段（雑魚・中ボス・ボス）と型（tank など）は、生成のときに使われるだけで Character に残らない（`out\enemy_stats.jsonl` の項目の一覧で確かめた）
- 効かせるのは、主人公と仲間の手で、敵に当たる一撃だけ。敵の武器には効かない
- LLM に頼らない。審判のプロンプトに武器の特性を書く案は、効いたかを測れないので外した

### どこで効かせるか（GAME.md §2.10.2 の1手の流れ）

| 効果 | 場所 | 319 との関係 |
|---|---|---|
| 会心 | `calculate_battle_effect` の前に、敵に当たる `instant_damage` の power を1段上げる | 319 は呼んだ後に同じ `battle_action` から裁きを読むので、上げた裁きで計算する |
| 貫通 | `get_instant_damage` に渡る防御を減らす（`frames.replace_arg`） | 319 は防御の値で受け側を確かめられなくなるが、素点の照合で受け側を見つける |
| 特効 | `get_instant_damage` の戻りに掛ける | 411 は 319 より読み込みが後で外側に居るので、319 の割り算の式の後のダメージに掛かる |
| 吸収 | `get_instant_damage` の中で、その手で敵に与えたダメージ（敵の残りの体力まで）の累計から戻す量を決め、当たった時点で体力を戻す。`ui.note_damage` で出どころを控え、行は 308 が同じ手で出す | 同上 |
| 毒刃・怯み | 命中した敵の `status` にゲームと同じ形で書く。毒刃は `reduce_status_turns_and_log` の前に削り、怯みはその敵の一撃に掛ける | 319 の継続ダメージの帳簿とは別に持つ。308 は status の差で付いたことを出す |

- 受け側は、直前に `get_npc_defense` を聞かれた敵で、その値が `get_instant_damage` の防御と一致したときだけ決める（319 と同じ見分け方）
- 計測 MOD の試し打ちの印（`sys._instantale_probe_dry_run_thread`）が立っている間は何もしない

### オフラインの検査（`tools\tests\test_equipment_bonuses.py`）

抽選（武器だけ・種類が重ならない・切った種類は付かない・6種類とも出る）、説明欄の書き読み（日本語・英語、能力値補正の行と混ざらない）、まとめ方（sum / max・確率は100で止める）を確かめた。
戦闘の1手は、偽のゲームの1手（素点 → 敵の防御 → 引き算の防御）を通して確かめた。
素点 400・防御 100 で、会心は normal → strong、貫通 50% で防御 50、特効（無傷）+40% で 490、吸収 10% で体力 +49、毒刃と怯みが敵の status に付く。
怯んだ敵の 200 の一撃は 140、毒刃は最大体力 500 の敵を毎ターン 20 削り、体力 1 で止まった。

### 実機（11-04、テストワールド、依頼の戦闘）

効果はスクリプトで武器に書き、確率は 100% にした。
319 入りの戦闘は、敵が一撃で倒れないように 319 の `ENEMY_HP` を 20000% にした。
どちらも動きを見るための設定で、釣り合いの検証ではない。

| 効果 | 319 入り | 319 なし |
|---|---|---|
| 会心 | weak → normal。319 の計算も normal で動いた | weak → normal |
| 貫通 | 防御 57 → 28.5 | 防御 86 → 43 |
| 特効（無傷 +40%） | 12707 → 17790。2発目は無傷でないので掛からない | 3527 → 4938。同名の別個体も防御の値で見分けた |
| 吸収 15% | 敵の残り 550 を上限に +82。体力の上限でも止まる | 敵の残り 376 を上限に +56 |
| 毒刃 | 最大体力の4%ずつ減る（52000 の敵で 2080） | 付いたが、減る前に敵が倒れた |
| 怯み | 敵の一撃 480 → 336。0 ダメージの手は触らない | 付いたが、弱まる場面は見ていない |

- 生成の入口で武器を6本作ると、epic は 0〜1 個、legendary は 1 個、mythic は 1〜2 個の効果が付き、強さも表のとおりだった。店とクラフトは同じ入口だが、その経路で効果が付いたのは見ていない
- 説明欄に `会心: 20%`・`毒: 命中時 40%` が能力値補正の後ろに出て、起動し直してもセーブから読み直せた

最初の形は吸収の体力を1手の閉じる時に戻していて、1回の吸収で2行出た。
`（…は体力を 1045 吸収した）`（411）と、次の手の `… は 1045 回復した`（308 が差分として拾う）。
308 のフックは 411 の内側で、報告は 411 が1手を閉じるより先に済むため。
当たった時点で戻して `ui.note_damage` で控える形に変え、`… は 吸収 で 968 回復した（残り HP 1968/1968）` の1行が同じ手に出るのを実機と写真で確かめた。
308 を切っていると行は出ず、体力の数字だけが変わる（319 の継続ダメージと同じ扱い）。

## 残っていること

- 武器の効果のうち、特効の相手のボス戦・格上・手負い（実機で動いたのは無傷だけ）と、319 なしの毒刃の減算・怯みの減算（通るコードは 319 入りと同じ）
- 店とクラフトで作った武器に効果が付くところ
- 333 を入れていないときの装備の読み方（ゲームの武器1つ・防具1つ）と、411 の付け方の実機のうち店で epic 以上が出たとき（クラフトは 11-01 に成立。[§3.120](3.120.md)）
- `BattleEndInFreeAction` / `BattleEndInColosseum` の終わり方での期限切れ（通常の戦闘の終わりだけ実機）
- 逃走・倒れたときの終わり方での期限切れ
- 仲間のステータス画面の表示（相手は名前で引く。ゲーム抜きの検査まで）
