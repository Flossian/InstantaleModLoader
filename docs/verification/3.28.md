# 3.28 宿の宿泊期間・部屋・宿代（`315_`）: 実機3回で成立・残るは4点

部屋と `宿泊する(Nヵ月)` のラベル・宿泊期間（選択式）・年齢による加算・宿代を設定で変える。
月単位は `period_months` を差し替え、
**週単位は months=1 を渡して宿泊マネージャの `execute` の窓の間だけ日数を切り詰める**。

実装時に未実測だった仮定は実機1回目で全部決着した。
宿代の徴収は `VacationStartManager.execute` の中、
`quality` は部屋ボタンの `args` の2番目で実値は `'kennel'` / `'bunk'` /
`'private_room'` / `'luxury_suite'`、
`period_months` を差し替えれば下流（部屋の args・文言・日数）が揃う、
宿泊の日数送りは `elapse_days` を通り**開始で全期間ぶんが進む**（活動マネージャでは動かない）、
`app.player.age` は int、部屋のボタンは `refresh_choice_buttons` を通って表に出る。

実機3回で成立（`2週間`×相部屋で3泊 / 同じ設定の v4 / `1週間`×豪華な部屋）。
ラベル・`period_months` の差し替え・日数の切り詰め・文言の置き換え・連泊の積み直しまで確認し、
`315_` / `218_` 由来の ERROR / WARN は無し。

想定外の発見が2つあり、どちらも対処済み。
**部屋は4つで `犬小屋(0G)` がある**（料金表に無いので触らずに済ませていた ＝
安全側には倒れていたが設定できない部屋があった）。
**週単位のとき LLM の描写が食い違う**（ゲームがプロンプトに月数を焼き込む）。
v4 で錨（`の宿泊` / `の滞在`）に当てて置換し、
実機で `二週間にわたる滞在` と実際の期間で語ることまで確認した。

> `218_` の記録に `1ヵ月泊まることにした。` が残るのは正しい。
> probe は `315_` より外側なのでゲームの生の文言を録る（TECH.md §3.2.2）。
> 画面に出るのは `315_` が書き換えた方で、`vacation_custom.log` の `text:` 行がその対を残す。

**残る未確認**

1. 年齢による加算の実機（3回とも加算OFF・設定も `AGE_SCALING: false` のまま）。
   とくに月単位の加算でゲームと同じ月数になる場合、「何も動かない」こと
2. 犬小屋のリネームと、**タダの部屋を有料にしたとき**の前払い調整
3. 宿代を変えたときの `price:` の対（`314_` の馬車では確認済みだが宿では未確認）
4. LLM の描写は休養・社交・社交の解決で成立。
   **訓練・労働・物乞いのプロンプトはまだ通っていない**。
   錨から外れた言い回しなら `prompt at ... kept as is:` にその一節が残るので、出たら錨を足す

## 宿の主に渡る文（版9）: 実機で成立（11-04・テストワールド）

1週間の設定で、宿の主が「三ヵ月単位の宿だよ。簡易寝台は前払いで10G…」と言った（2026-11-04）。
それまでに直していたのは描写の「数ヵ月の宿泊」だけで、宿の主に渡る次の2つは対象にしていなかった（GAME.md §2.17）。

| 文 | 食い違い | 決めた直し |
|---|---|---|
| 会話の指示文 `response_prompt_instruction` | 期間・部屋の名前・宿代がすべて素の値。設定の相部屋も、月単位の設定も、338 の宿代の倍率も届かない | `conversation_facilitator`（位置 10）と `_after_retrieval`（位置 9）のフックで今の値へ差し替える。宿代は `prices.inn_room` |
| 主の `life_log` の記録 | 週単位はゲームに 1 を渡すので「1ヵ月間」・範囲 30 日で残る。部屋は素の名前 | `VacationStartManager.execute` の間に増えた記録だけを直す |

- 差し替えは `wrap_outgoing` でなく引数で行う。出ていく本文では 130 が直した通貨の表記が混ざり、照合が表記に左右される
- 引数の段でも `tr` を通った後のことがあるので（`10円`）、金額は照合の条件に入れない
- 素の設定では同じ文ができるので、何も変わらない。文が見つからないときは `WARN keeper: the inn terms did not match` を1回残す
- 記録の範囲は「宿泊を終えた日で終わる」形（実プレイのセーブで、1週間ずつ2泊して `-23〜7`・`-16〜14`。そのとき21日目）。`day_end` が今日でないときは `WARN memory:` を残して範囲を触らない
- 主人公の `life_log` の活動の記録（休養・訓練）も同じ範囲で残るので、宿泊の各段の間に増えた `生活の記憶` の範囲を週単位の日数へ縮める。範囲が実際の日数に収まる記録には触らない
- 主の記録は `VacationStartManager.execute` の中で書かれる（実機の `memory:` の行）

**実機で確かめたこと**（設定は 1週間・加算なし・相部屋。通貨は 130 で円）

| 確かめたこと | 結果 |
|---|---|
| 主の台詞（到着の会話から宿泊の条件を尋ねた） | 「宿は一週間単位だ。相部屋が一週間で10円、個室が100円、高級個室が1000円」「犬小屋で良けりゃ宿泊は無料」。`keeper:` の行は `conversation_facilitator` |
| 主の記録 | `〈生活の記憶〉…を相部屋に1週間宿泊させた。` 範囲 562〜569。連泊で 569〜576 |
| 主人公の活動の記録 | 休養 562〜569、訓練（連泊）569〜576 |
| セーブ | 3つの記録とも直した形で残る |
| 直した記憶が会話に届く（泊まった長さを尋ねた） | 「相部屋を一週間、前払いで使ってる。二回ともな」。`keeper:` の行は `_after_retrieval` |
