# 3.62 家を借りる・買う（`330_`）: 管理人まで実機で成立・残るは4件と別件1つ

決まりと設定は `330_` の DOC.md。
開発中は `914_real_estate` の名前で動かした。
建物そのものは版20 でローダの `modfacility` へ移した（TECH.md §5.8）。
この MOD に残るのは契約（家賃・期限・預かり）と、建物の中でできること（滞在・保管庫）と、役場の窓口。

## 設計の根拠

施設の形は実セーブ7本の全施設を数えて決めた。
足す `location` の素データは実データと同じ8項目・同じ並び。

| `facility_type` | `tier` | `config` |
| --- | --- | --- |
| `location`（77件） | 全件 `null` | `level_of_detail` だけ |
| `ward`（120件） | 全件 `null` | 同じ |
| `entrance` / `exit`（各51件） | 項目が無い | 同じ |

街は `entrance` から `ward` へ入り、宿・ギルド・役場・自由生成施設はすべてその `ward` から枝分かれする。
建物の繋ぎ先はノードの入口（`Node.entrance_facility`）、引けなければ種類（`entrance` → `ward`）で探す。
組み立ては `Facility.__init__(self, app, parent_node, facility_data)`、移動は `MovePhaseManager(app, connected_node_id, facility_move_to_id, area_id)`（GAME.md §2.2）、滞在は `VacationStartManager(app, months, quality)`（GAME.md §2.17）。
保管庫は `toggle_twin_inventory_window` をゲームに無い場面名（`real_estate_storage`）で借りる（`402_` と同じ）。

## 実機で成立したこと

| | |
| --- | --- |
| 契約 | 賃貸・建売・別の土地に2軒目。窓口から結べて、控えに残る |
| 建つ | 契約した土地の入口に1軒。ロードのたびに控えから建ち直る |
| 入る | 「滞在する」「保管庫をあける」「家から出る」が出て、押せる |
| 滞在 | 宿代は前払いで打ち消され、活動を1つ終えると建物の選択肢へ戻る |
| 保管庫 | 預ける → 開き直す → 取り出す。移した時点で保存が走る |
| 共有倉庫 | 「世界で1つ」にすると各建物の中身が共有へ寄り、別の土地からも同じ中身が開く |
| 解約・預かり・引き取り | 解約で建物が消え、中身は役場の預かりへ。どこの役場でも引き取り料で戻る |
| 家賃 | 暦が進んだときに精算する（自分の家の滞在でなくても引かれる） |
| 期限切れ | 払えない額で借りると契約が切れ、建物が消える |
| 別のノードに建った家 | 繋ぎ先をプレイヤーの居るノードから選び直す修正の後、当て直しで移る |
| 滞在の描写 | 頼み文に泊まり先を1文添えると、描写がその場所になる |
| 管理人 | 建物ごとに1人立ち、主として滞在を通す。`会話する` に出さず、セーブにも残さない |

家賃の精算は滞在の外へ出した（版31）。
滞在中は見送り（`rent: postponed`）、終わってから1回だけ精算する。

残る穴: `331_facility_investment` の建物で無料の滞在の最中にこの MOD の家賃の期限が来ると、あちらの帳尻が家賃ぶんを拾う。
見送りの判定が自分の家の滞在（`staying_home`）しか見ないため。
「いま滞在が走っている」をローダが持たないと、330 単独では塞げない。

ローダへ移した後の通し（中に立ったまま保存 → ロード、ロード後の保管庫、セーブを外から見る）は3つとも成立した。
`restored 5 entr(y/ies)` が `where:` より前に出て、`dropped 3 stale button(s) without our mark` の後に組み直す。
`230_probe_mod_facility` は要らない。

## 作りに効いたこと

- ロードの後にログが静かでも異常とは限らない。`where:` は前回と同じ token なら書かず、その覚えはプロセスに残る。活動の画面では `modfacility` が選択肢を足さない。出ているかは層の積み直し（`330_real_estate registered ...`）で見る
- ゲームは実行時に足した施設の `connections` を読まない。道も、中の選択肢も、出口も MOD が出す（GAME.md §2.28 と同じ側面）
- 宿泊には主が要る。主のいない施設で `VacationStartManager` を起こすと名簿の引き当てで落ちる。プレイヤー自身は `world.characters` に居ない世界があるので使えない
- 名簿に居る人物は保存が `.id` を読む。居場所を据えずに名簿へ足すと `AttributeError: 'NoneType' object has no attribute 'id'`。保存の直前に名簿から引き上げるのはローダの `modnpc`（TECH.md §5.7）に預け、一覧に出さないのは `place(listed=False)` で足りる
- `spawn` / `place` の手前にガードを置かない。何度呼んでもよく、飛ばすと記録が歯抜けのまま `unplace` も効かない
- 注入し直しは画面を組み直すまで効かない。建物から出て入り直してから押す
- ゲーム側が落ちても操作は返す。宿代を返し、待機表示を解いて建物の選択肢へ戻す
- 窓はメインスレッド（Clock）から開く。フェーズの `execute` は別スレッドで走る（GAME.md §2.1）
- 滞在の最中は自前の選択肢を出さない。判断はローダの `is_top_screen` に任せる（331 が旗で別に持って片方だけ穴になった。[§3.63](3.63.md)）
- 1泊＝活動1回。活動の `execute` が返り画面が落ち着いてから `VacationEndManager` を起こす。社交は2段なので後段で締める
- 自分の家の滞在から「他者と交流」と「アイテム作成」を落とす。見分けは spec のクラス名で、宿屋の側には触らない
- 背景は MOD が描かない。ゲームが名前で引き、無ければ生成する（331 と合わせて6回直した。TECH.md §5.8）
- 自前の画面から戻す塗り直しは、本文が流れている間は落ちる（GAME.md §2.6）。手が空いてから1度だけやり直す（`retry_when_idle`）
- 「立っているか」（`standing_in`）と「自分の家か」（`inside_home`）は別の問い。契約が切れた瞬間に中に居るのに取り壊していた。街から引けない施設に立ったときの逃げ道（`stranded`）も別に持つ
- 立ち位置を動かすときは、その場所の選択肢も一緒に置く。ロードは焼かれた `game_variables["buttons"]` を戻すだけ。自分の建物への道は入れない（MOD の無い環境で押せる）
- 保管庫を開いたまま保存するときは売買中の旗を下ろす
- 宿泊の長さはローダの窓口 `durations.inn_stay` に聞く（TECH.md §3.3.2）。MOD が建てた建物の中の宿泊は数えない（自分の家で拾うと見積もりを「実測」として固める）
- 契約の周期は結んだ時点の長さで固定する。日数には測った月数を添え、月数が変わったら使わない
- 滞在の描写に泊まり先を1文添える。ゲームは頼み文に泊まり先を渡さず、エリアの一覧だけを渡す（GAME.md §2.17）。自分の家がある街の滞在だけで、本文は削らない
- 控えの鍵は世界×主人公（TECH.md §5.4）。ロードの間は `World.__init__` の引数のセーブから鍵を決める
- 自前のボタンは無害な既存クラスを spec に持たせ、押下は印で横取りする。`MovePhaseManager` を書くと MOD の無い環境で押せる（GAME.md §2.2）
