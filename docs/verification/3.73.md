# 3.73 戦闘の後の残骸の片付け（`107_`）: 版4まで実機で成立・撤退の後の依頼の戦闘も記録で成立

`107_fix_battle_flag_stuck` は、戦闘の終わりとロードの直後に、ゲームが片付け忘れたものを片付ける。
仕組みは GAME.md §2.10（戦闘終了マネージャ・逃げたときと倒れたとき・戦闘の最中のセーブ）。

| 版 | 何を片付けるか | 実機 |
|---|---|---|
| 2 | 闘技場から撤退すると `in_colosseum_battle` が残り、次の戦闘の終わりにゲームが闘技場用の後始末を選んで `KeyError: 'current_phase'` で止まる。戦闘の終わりに旗を下ろす | ✓ 撤退の直後に `BattleEndManager.end_phase: cleared in_colosseum_battle` |
| 3 | 戦闘の最中に保存したセーブのロード。戦闘の画面に戻ったときは旗に触らず、場所の画面になったときは旗を下ろして残った敵も空にする | ✓ 2通りとも（下の表） |
| 4 | 逃げる手で敵も倒れて勝ちになると、逃げた者が `escaped_member_in_battle` に預けられたまま一覧へ戻らない。戦闘の終わりとロードの直後に一覧へ戻す（主人公は先頭へ） | ✓ 勝ちの終わり方の直後に `brought player back from escaped_member_in_battle` |

ロードの見分けは2回やり直した。

| 見分け | 戦闘の画面に戻ったロード | 場所の画面になったロード |
|---|---|---|
| 版2（旗が立っていれば下ろす） | 戦闘の欄が畳まれたままボタンだけが残り、攻撃した後に `ZeroDivisionError`（`new_hud.py:2306`）で落ちた | 普段どおり |
| 版3の最初（敵が居れば触らない） | 戦闘の続き | セーブの敵は画面に関係なく `current_enemy_dict` に戻るので旗が残り、旗と闘技場の相手を残したまま依頼を始めて、闘技場の相手と依頼の敵が1つの戦闘に混ざった（そのままセーブに焼かれた） |
| 版3（ロードの後に並んだボタンが戦闘のものか） | ✓ `the battle screen came back -- ... not touching` で戦闘の続き。長い試合の途中で読み込んでも決着まで通った | ✓ `not a battle screen (buttons: MovePhaseManager, …)` のあと旗を下ろし、`cleared 1 stale enemy` |

撤退の後に依頼の戦闘を通して落ちないこと（版2 の本来の症状）は、2026-10-13 に遊びの記録（`out\battle_bgm.log`。`107_` も書く）で確かめた。
09-25 17:53 に闘技場の試合が旗を残したまま終わり、`BattleEndManager.end_phase: cleared in_colosseum_battle` が出た。
読み直しを挟まず（`load_game_new` の行が無い）、17:54:57 と 17:55:53 に依頼の戦闘（`enemy_type='in_quest'`）が始まり、どちらも `in_battle=0` へ戻って終わった。
その間の `modloader.log` に `KeyError: 'current_phase'` も WARN も無い。09-23 17:27 にも同じ流れ（試合の後 57 秒で依頼の戦闘）が1回ある。
