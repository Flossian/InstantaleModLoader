# 2.38 NPC の記憶と会話プロンプトの重複（`213_` の計測）

会話を終えると `conversation_resolver` が要約を作り `current_log` に追記する。
`current_log` は一時置き場で、日付が変わると `life_log` へ移り、
以後は毎回全文プロンプトに載る（`relationship` / `profile` / `personality` も毎回全文）。
構造は GAME.md §2.25。

落としているのは移送ではなく `resolver` の方。
出力量が会話の長さにほとんど依らず一定で、
**8ターン・5,597字の会話が 118字**になった。
書き直すたび同じ短さへ圧縮されるので、この経路の情報は単調に減る。

要約が走らない抜け方がある。
`resolver` の呼び出し元は `ConversationEndManager.execute` の1本だけで、
終了ボタンを通らない抜け方は全部素通りする（実際に2件観測）。
抜け方ごとの網羅は未了。

ゲーム側にも重複がある（`life_log` に同一要約の5連コピー、プロフィール行が4回）。
`memory`（5鍵の dict）と `knowledge` の更新契機は分かっていない。

受けて入れたもの: `311_` v4（記録済みの `facts` を抽出プロンプトへ差し戻す。
人物像は毎回まるごと書き直されるので確定した事実も数ターン後に消える）と、
`111_` の置換ルール1行（要約の指示を書き換え。実効は実機で未検証）。

計測側で踏んだ穴が2つ:

- 照合を JSON の器のまま行うと2通りに誤る
  （空の `[]` は「全文相当」に化け、中身のある dict は「無し」に倒れる）。
  文字列の葉だけを照合する形に直した
- NPC の鍵を id だけで持つと、別世界の同じ id を同一人物として diff する。
  世界名を鍵に混ぜた
