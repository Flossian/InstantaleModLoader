# 3.46 `safe=True` の呼び直し（`patch.py`）: 素の関数の例外で 2^N 回走る

セーブエディタで足したエリア（世界側の `world_data.json` に無いもの）へ馬車で移動し、
ゲーム本体の `save_area_json.write_area_data_to_world_dict` が `KeyError: '21'` を投げて移動スレッドが死んだ（`out\live_crashes.log`）。
ここまではゲーム側の前提（エリアは両方の辞書に在る）が崩れただけで、エディタ側で対処済み（v10.5、両方へ書くようになった）。

ローダ側の問題はその増幅。
`AreaMoveManager.execute` を `safe=True` で包む MOD が4本（`220_` / `316_` / `317_` / `321_`）あり、
`_guard` が素の関数の例外を「フックの失敗」と読んで呼び直し、層ごとに倍々になって 2^4 = 16 回走った
（`safe hook failed on __main__:AreaMoveManager.execute` 15 行、`live_crashes.log` の連鎖 `[1/16]`〜`[16/16]`、
運賃 1000G × 16 で 106526 → 90526（`area_move_custom.log`）、経過日数 14 日 × 16）。
[§3.20](3.20.md) で「まだ手を出していない」と書いていた形そのもの。

直した点は TECH.md §3.1.5（素の関数の例外はそのまま通す。呼び直すのは `orig` にまだ入っていないときだけ。
素通しは `WARN` 1行で、落ちた記録は `001_crash_recorder` が取る。フック側の失敗は従来どおり `ERROR`）。
検査は `tools/tests/test_patch_registry.py` の `safe=True` の節4通り（素の関数が投げる・3層重ねる・フックが握って投げ直す・`from e` で包む）で、
素の関数が**1回**しか走らないことを見る。

実機で決着（直した後の1回）。世界側に無いエリア（id 37。エディタで足したもの）へ馬車で移動して同じ `KeyError` を踏ませた。

| 観測 | 修正前 | 修正後 |
|---|---|---|
| `safe hook failed on __main__:AreaMoveManager.execute` | 15 行 | 0 行 |
| `safe hook on __main__:AreaMoveManager.execute: the original raised KeyError: '37'; passing it through` | 無し | 4 行（層の数） |
| 例外の連鎖（`live_crashes.log`） | 16 段 | 1 段 |
| 運賃 | 1000G × 16 | 1000G × 1（105526 → 104526） |
| `elapse_days` | 16 回 | 1 回 |

スレッドが落ちること自体は変わらない（ゲーム本体の例外なので、素のゲームと同じ）。
同じ起動で `QuestChoiceManager.__init__`（`318_` の1層）の `KeyError: '26'` も素通りしている（11行。修正前には同じ 11 行が `safe hook failed` で呼び直されていた）。
ゲームが依頼ごとに呼んで自分で握る例外なので落ちてはいない。直した経路は移動だけの話ではない。

その後のレビューで3点直した（実機は未確認、検査は通過。いまの形は TECH.md §3.1.5）:
記録を「最後の結果」1つに / 投げ直しを except 節の外へ（`__context__` の連鎖が逆さに読めていた）/ 通した `WARN` を例外1つに1行にして投げた場所を添えた（上の表の「4 行（層の数）」は以後1行になる）。
検査の3層の節は世代を変えて重ねていて実際は1層だったので、同じ世代で重ねて深さ3を見るようにした。
