# 3.50 新たな道を探す（`325_`）: 実機で成立・残るは連打の門だけ

要件は work\HANDOVER_world_structure.md §5（Mod B）。遊び方と設定は `325_` の DOC.md。
実装で決めたこと: 開通は両側の `Area.connections` を**新しい list に差し替えて**足す（骨格の list に触らない）。
記録は `state\road_opening\<世界名>.json`、`World.__init__` の後と一覧を開く直前に当て直す。
踏破は `307_` と同じ機構を自前で持つ（番号で import しない）。
到着の移動は実測の `mode`（`on_foot`）で `AreaMoveManager` を組み、組めなければその街の確認画面へ落とす。
委託（版2）は `PAY_DAYS`（既定 14、0 で即時）後に開通。期日は `world.days_elapsed` で数え、`elapse_days` の後と画面の組み直しで見る。開通の1行は `when_idle`。
オフラインは `tools\tests\test_road_opening.py` 123件。

実機で出て直した不具合は3つ（版1）:

- 街の種類: 候補 0 件（`no unlinked town`）でボタンが出なかった。実行時の `Area.size` は読めない（GAME.md §2.7）ので、`324_` の `size_of` と同じ順（属性 → `save_data_dict` → `world_dict`）に直した。版2で確認済み
- ページ送り: 候補が 8 枠に収まらない一覧で「次」を押すと8つ目の候補に飛んだ。ローダの `ui.pressed_entry` が整数でない枠（`'next'`。GAME.md §2.2）を添字に落としていたので、None にして `orig` へ素通しさせる形に直した（`ui.py`、TECH.md §8）。`on_button_press` を包んで印で横取りする MOD 全部に効く。直した後に確認済み（直す前は `次` で `pressed '<街名>…' (pick target=21)`、直した後は `次` で MOD のログに1行も出ず、狙った候補 `pick target=8` が押せた）。判定は「その一覧の間に身に覚えのない `pick` が出ないこと」。2ページ目の戻る側の枠の値だけは未実測
- 連打: 「お金を支払う」の連打で二重に徴収された。直しは旗（`acting`）と `already linked` の検査の2段。二重に引かれたぶんは MOD からは戻せない（セーブエディタで所持金を直す）。**実機で未発火**

**実機（版2）で #1〜#5 が全部通った。** 3経路とも `state\road_opening\<世界名>.json` に残っている:
委託（3,000G を払い `due day 210 (today 196 + 14)` → `days: commission due` → `opened: ... via commission` → 功績を両側の `area_history` へ）、
踏破（難易度 47 → `cleared:` → `opened: ... via dungeon` → `arrive: process_choice(AreaMoveManager, '7', 'on_foot')` → 「長旅だ」を伏せ → `days: 90 -> 14` → `arrived:`）、
支払い即時（版1の `via pay`）。
ロード後の当て直し `load: applied 2 edge(s) from 1 road(s)` も同じ回。WARN / ERROR は 0 件。
HANDOVER §6 の1と3も決着: **一覧は `Area.connections` を読む**（`WARN list:` 0 件で開いた道が素の一覧に並んだ）、
**開いた道は `AreaMoveRestriction` に阻まれない**（踏破で着いた街から、この MOD が開いた道でしか戻れない街へ移動）。

残るのは連打の門（`ignored ...: the previous press is still running` と `already commissioned`。版2では二重に払おうとしていないので出ていない）。
他に見ていないのは、放棄・体力での拒否・MOD を切ったとき素に戻ること・委託の期日をまたぐセーブ→ロード（今回のロードは `roads` だけで `commissions` は空だった）。

判定は `out\road_opening.log` の行。距離補正の検算はオフラインでできる（world_data の connections で BFS した値と画面の金額・難易度の突き合わせ）。

| # | 確かめること | どう分かるか |
|---|---|---|
| 1 | 一覧の形 | 済。`candidate:` の行が候補の数だけ出て、`hops=` が world_data の木で数えた「挟む街の数」と一致（金額 2000+1000×hops、難易度は `levels origin= target=` の間＋2×hops。孤立の街は `isolated` で hops=5） |
| 2 | お金で開く（`opened: ... via pay` / `via commission` の後） | 済。開通の1行と所持金、開き直した一覧にその街が並んで移動できる（HANDOVER §6 の3）、`WARN list: the game did not list the opened road` が**出ない**（HANDOVER §6 の1） |
| 3 | セーブ→ロード後も残る | 済（`roads` のみ）。`load: applied N edge(s)`。MOD を切って起動すると素の接続に戻る（`state\` は残る） |
| 4 | 踏破。難易度が距離補正どおりか | 済。`dungeon: ... hops= difficulty=` が受注画面の難易度と一致（`318_` 入りなら `armed: difficulty` の行）。「帰還する」の後に `cleared:` → `opened: ... via dungeon` → `arrive:` → `days: 90 -> 14` → `arrived:` |
| 5 | 放棄と、別の手段での移動 | 放棄で「道を引き返した。〜は開かれなかった。」が出て `opened:` が無い。道を選んだ後に徒歩で別の街へ行くと `pending: dropped (the player travelled by other means` が出て、依頼の説明の一文が消える |

`307_` と同じフック（`QuestEndManager.execute` / `elapse_days` / `add_text` / `AreaMoveManager.__init__`）を包むが、
互いの控えは別（`307_` は `state\road_travel.json`、こちらは `pending`）で、
こちらの道中のクエストが始まると `307_` は自分の道を「別のクエストが始まった」で捨てる。それでよい。
`133_` の帯は MOD が自前で足した落とし所のボタン（#2 の (c)）には付かない。
