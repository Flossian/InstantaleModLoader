# 3.116 到着の会話が売買の窓の上から始まり、店を出ても立ち絵が残る（`300_event_facility_arrival`・ローダの `when_idle`）: 原因はログで特定・直しは検査で成立・実機は未

2026-10-25 に作った。
きっかけは、ヴェスティアで診療所の売買を終えて「出る」で通路へ戻った後も、店主の立ち絵が画面の真ん中に残ったこと。

## 測ったこと（10-25。ヴェスティアの遊んでいる最中を読むだけ。`out\events.log`・`out\busy_display.log`・`out\player_events.log`・`out\game_flags.log`）

- 残っていた画面は `hud.character_image` が店主の立ち絵のまま `opacity` 1.0、`app.in_conversation` は店主の id のまま
- 起きた順（秒は着いた後から）

| 時刻 | 起きたこと |
|---|---|
| 0.00 | 診療所に着く。300 の抽選が当たる（`fire: … roll 0.15 < 0.15`）。手が空いていたので `when_idle` は `settle`（0.6秒）の後に会話を始める予約をした |
| 0.50 | プレイヤーが「売買する」を押す。売買の窓が開き（`in_shopping` が True）、選択肢は施設のまま塗り直された |
| 0.61 | 予約が走る。300 の取り消しの判定（施設を出たか・会話や戦闘の旗・施設の最初の画面か）はどれも通り、窓の上から `ConversationStartManager` を起こした（`launch: process_choice(ConversationStartManager, …)`） |
| 16〜22 | 会話の選択肢（`売買する / この話から依頼を作る / 会話を終了する`）の上で、窓から2品買う |
| 26.0 | 窓の外を押して閉じる。ゲームの後始末（`close_shopping_window_process`）は窓を開いた時の選択肢（`app.buttons_backup_for_shopping`。GAME.md §2.13.1 の窓の外側を押したときの閉じ方）を戻すので、施設の `売買する / 治療する / 出る / 会話する` に戻った。`in_conversation` は残ったまま |
| 27.9 | 「出る」。会話の終了処理を通らないので立ち絵が付いてきた |

- `when_idle` は手が空いたのを見てから `settle` 待って `then` を走らせ、走らせる直前には見ていなかった。その 0.6秒の間に押されると、押した後の画面の上で走る
- 300 の取り消しの判定は売買の窓を見ていなかった。`in_shopping` は店を出ても下りないので使えない（ローダの `BUSY_FLAGS` の注記）。売買の窓が開いている間は `is_popup_window_opened` が立つ（09-04 の `画面が戻った: … busy=['is_popup_window_opened']`）

## 直したこと

- ローダの `ui.Screen.when_idle`: `settle` の後、走らせる直前にもう一度見る。塞がっていれば見張りに戻り（期限は最初の呼び出しから数える）、`cancel_if` が理由を返せば取り消す。TECH.md の `Screen` の表にも書いた
- `300_`: 待っている間と会話を始める直前の取り消しの判定に、売買の窓（`ui.busy_signals` の `is_popup_window_opened`）を足した。着いた後に手を付けたなら、窓を閉じた後に声をかけても場面に合わないので待ち直さない
- 検査: `test_common_parts.py` の `Screen.when_idle`（`settle` の間に窓が開けば見張りに戻り、空いたら走らせる。前提が崩れたら取り消す）、`test_arrival_event.py` の 4b（予約の後に窓が開けば押さず、閉じた後も押さない）

まだ見ていないもの: 実機での再現と直った後の確かめ（着いた直後 0.6秒以内に「売買する」を押す必要があり、発生率を 1.0 にしたテストワールドで試す）。
