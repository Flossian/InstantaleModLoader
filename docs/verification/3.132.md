# 3.132 会話の相手の表情を台詞に合わせて変える（`347_conversation_expressions`・`343_stable_diffusion` 版30 の表情差分・`404_party_talk` 版13・ローダの `expressions`）: 会話・パーティー会話・一括生成（差分だけ描くを含む）とも実機で成立

2026-11-16〜17。
会話の返事ごとに LLM に相手の表情（ふだん・笑う・怒る・悲しむ・驚く）を選ばせ、立ち絵をその表情の差分に替える。
差分は `343_` が描き、表情を選んで見せるのは `347_`（パーティー会話は `404_`）。2つはローダの窓口 `expressions`（TECH.md §3.3.29）でつなぐ。
遊び方は各 MOD の DOC.md。

## 決めたこと（試作で選んだ値）

- 差分は、描き終えた立ち絵の顔の周りを表情のタグを足して img2img で描き直し、貼り戻した絵。顔だけ描き直す（[§3.65](3.65.md)）と同じ切り出し・貼り戻し
- 強さ 0.35。SDXL（WAI Illustrious v17・種 101・10人×5表情）で 0.5・0.4 はきつく、0.35 にした。重み付きのタグ（0.8）は目の色のずれが増えた
- 描き直しの強さは顔を描くモデルの系統で分ける（SD1.5 のモデル 0.5・SDXL・その他のモデル 0.35）。同じ系統の中で分けたいときは「モデルごとに変える」（`EXPRESSION_STRENGTH_BY_MODEL`。条件はプロンプトの規則の `model` 列と同じ書き方で、最初に当たった行。系統の欄より先に見る。既定は空）
- タグ: 笑う `light smile, closed mouth`／怒る `annoyed, slight frown`／悲しむ `sad, worried`（`worried, slight frown` は弱すぎた）／驚く `surprised, :o`
- 目の色が少しずれる差分がある。WD タガー（1.26GB）なら拾えたが容量で見送り、ずれは受け入れた。立ち絵の look に目の色が無い人物・look と絵の色が食い違う人物があり、プロンプトに目の色を足す手当ても採らなかった
- 第一声（`conversation_starter`）は型の無い送り口を通るので選べず、ふだんの顔にした
- 台詞が空（自由行動の GM へ渡った）返事でも、LLM が返した表情を使う
- 描く時機: 一括生成では立ち絵に続けて描き、ほかの場面では立ち絵を先に出してから裏で描く。`343_` に ON / OFF は置かず、表情を見せる MOD の宣言で描く
- 一括生成では、ゲームの仕事が済んだ後に、立ち絵が既にあって差分の無い人物へ差分だけ描く（下の「一括生成で差分だけ描く」）

## LLM の表情の選び方（`local\probe_expression`）

返事の返却型に `expression`（5択の Literal）を足し、台詞ごとの表情を記録した。

| LLM | 結果 |
| --- | --- |
| Claude（ゲームのクラウド設定） | 型に足すだけで台詞の書きぶりに合った表情を返した（10回: neutral 3・angry 4・smile 3） |
| ローカル（Fenrir-X-26B-A4B、思考なし） | 型に足すだけでは外れが多かった（喜ぶ台詞に neutral、驚いて感謝する台詞に angry）。ゲームは型の description をプロンプトに書かないため。【返答の要素】（`response_prompt_instruction`）に説明を1行足すと、設定に沿った12の話でほぼ台詞どおりになった（外れは照れに sad の1件） |

`347_` は型に足すのに加えて【返答の要素】に説明を1行足す。
ローカルへ直に送るときは `chat_template_kwargs: {"enable_thinking": false}` が要る（無いと数千トークン考えて本文が空になった）。
設定に無い出来事を投げると「捏造しない」の指示で疑って angry になるので、試す話は人物の設定に沿わせた。

## 実機（2026-11-17、テストワールド）

LLM はゲームの設定がクラウドのまま、`local\probe_expression` でテストワールドの会話だけを手元の llama-server（Fenrir-X-26B-A4B）へ回した（型と説明は `347_` が足す）。
画像は sdcpp_cuda、立ち絵は種類ごとのプリセット「SoteMix 3.0」（SD1.5）、顔だけ描き直すは ON、`131_` の高画質化は ON。

| 確かめたこと | 結果 |
| --- | --- |
| 会話の相手（ラミロ）を設定の画面の「画像の再生成(txt2img)」で描き直す | 立ち絵が出し直された直後（12:41:53.119）に差分の1枚目を描き始め（.185）、4枚を計 15.3 秒（1枚 3.7〜4.0 秒）で描いて `expressions\` に置いた。寸法は立ち絵と同じ 640x1280、透明度も同じ |
| 返事を出す（金貨の袋を差し出す） | `surprised` が返り、会話の立ち絵が `expressions\surprised.png` に替わった（写真で確かめた） |
| 続けて返事を出す（野良犬を蹴る） | `angry` が返り、`angry.png` に替わった |
| 会話を閉じて話し直す | 第一声でゲームの立ち絵（`reduced_color_image.png`）に戻った |
| 表情の差 | SD1.5（SoteMix 3.0）では、強さ 0.35 の差分はふだんの顔とほとんど見分けられなかった（怒る・悲しむがわずかに動いた程度）。0.35 は SDXL で決めた値 |

最初の起動では差分を描かず、`ゲームの立ち絵の工程（縮小・減色）の呼び方が控えられていない` の WARN が出た。
`131_` が `343_` の外側に居て、`131_` の高画質化は減色の元の関数を呼ばずに返すので、`343_` の控えに減色が届かなかった（縮小は届いた）。
`343_` の mod.json に `"after": ["131_sharp_portrait"]` を足し、読み込み順も `131_` → `343_` に入れ替えて成立した。

試した後、テストワールドは控えへ戻し、描き直したラミロの立ち絵も元のファイルへ戻した（差分の見本は scratchpad に残した）。

## SD1.5 の強さ（2026-11-17、sd-cli で描き比べ）

実機で 0.35 の差がほとんど見えなかったので、SoteMix 3.0（ゲーム同梱の `sotemix_v30.safetensors`）で強さを描き比べた。
差分を描くときと同じ条件にした（顔の周りを 768 四方、dpm++2mv2・15 歩・cfg 5・karras、プロンプトは `variants.expression_prompt`、種 101）。
人物はテストワールドの4人（青年2人・中年の男・褐色の肌の女）×4表情で、貼り戻してから顔の周りを並べて見た。

| 強さ | 見え方 |
| --- | --- |
| 0.35・0.45 | ふだんの顔とほぼ同じ |
| 0.5 | 笑う・怒る・驚くが読める人物が出始め、顔立ちは保つ |
| 0.55 | 4表情とも読みやすいが、中年の男の皺と無精ひげが消えて若返り、褐色の肌が明るくなった |
| 0.6・0.65 | 表情は強いが、若返りと肌の色のずれがはっきり出た |

悲しむ（`sad, worried`）はどの強さでも他より弱かった。
目の色のずれは SDXL より目立った（橙の瞳が青紫になる人物がいた）。
SD1.5 の顔だけ描き直す（強さ 0.4）より 0.35 は弱く、顔をなぞり直すだけになっていた。
SD1.5 のモデルの強さを既定 0.5 にした（初めは「モデル名で分ける」の既定 `sd15=0.5` として足し、道具画面が分かりにくいと言われて SD1.5・SDXL・その他・モデル名の3つの欄に分けた。下の「道具画面」）。

## 道具画面（2026-11-17）

高度設定の表情差分の枠は、初めは8行の説明と `条件=強さ` を書く1つの欄だった。
どのモデルで顔を描き、強さがいくつになるかが画面に出ず、書き方も規則の書式を知らないと分からなかった。
説明を2行にし、顔を描くモデルの決まり方（顔だけ描き直すのプリセット → 通常の生成の txt2img→img2img の2つ目 → 種類ごとのプリセット → ゲーム既定）を4行で並べ、各行のいまのモデルと系統、いま当てはまる行とその強さを出すようにした（`outlook.expression_models`。欄を変えるとすぐ書き換わる）。
強さは SD1.5 のモデル・SDXL・その他のモデル・モデル名で分けるの3つの欄にした。
欄の説明に具体的なモデル名を例として書かない（使うモデルは遊ぶ人による）。
見出しの「強さ」が何の強さか分かりにくかったので、「描き直しの強さ（小さいほど元の顔が残り、大きいほど表情がはっきりする）」の1行にし、枠の先頭にあった向きの説明を外した。
説明の行と例を足した形は情報が多すぎたので採らなかった。
「モデル名で分ける」は「モデルごとに変える」にし、ログと `mod.json` の項目名も「描き直しの強さ」に揃えた（これより上の記録は前の名前のまま）。
「モデルごとに変える」の注記に書き方の例を足したら、既定の窓（940x780）で右へ 90px 切れたので、注記を欄の下の行へ移した。
モデルの表の「← いまはこれ。強さ N（欄の名前）」も既定の窓で 7px 切れていたので、文字の印をやめ、いま当てはまるモデルの行と、強さを決めた欄の名前を青太字にし、「顔を描くモデル」の見出しの右に青太字で「青太字は使用中」と添えた（太字だけでは項目の見出しと見分けにくかった）。

## 実機（2026-11-17 午後、テストワールド）

会話は前と同じく `local\probe_expression` で手元の llama-server（Fenrir-X-26B-A4B）へ回した。
一括生成は題の画面から走り、送り口の別名は開始時に作り直されるので、試しの MOD（`local\probe_bulk_portrait`）で一括生成の間の LLM の送り口7つを止め、仕事を立ち絵だけに絞った。
最初の回はこの試しの MOD の誤り（開始後の当て直しで止めの状態が消えた・世界のパスの引数の位置）で、人物の詳細（`npc_detail_generater`）1件がゲームの設定のクラウドへ送られた。それ以降は止めが効いた（`blocked` の行）。

| 確かめたこと | 結果 |
| --- | --- |
| `sd15=0.5`（ラミロを「画像の再生成(txt2img)」で SoteMix で描き直す） | 差分は `強さ 0.5（sd15=0.5 に当たった）` で描かれ（1枚約4.5秒）、会話で驚く・怒るが 0.35 のときより見分けやすく替わった。落盤の知らせにも LLM は怒るを選び、悲しむは見ていない |
| `404_` のパーティー会話（仲間のリュウ・ジーンの差分を一括生成で描いてから） | 3ラウンドとも2人がそれぞれ選ばれた表情に替わった（褒美: 笑う / 驚く、盗みの疑い: 驚く / 悲しむ、家系の侮辱: 悲しむ / 驚く）。第一声はふだんの顔 |
| 一括生成で立ち絵に続けて描く | 立ち絵の無い人物の立ち絵の後に差分4枚を描いた。直す前は「裏で描いた」になっていた（下の不具合） |
| 描く順番の譲り合い | 差分を描いている間にゲームが別の人物の立ち絵を3枚続けて描き始め、差分は待って、ゲームの絵が終わった直後に続きを描いた（その1枚は待ちを含めて 21.1 秒） |

### 一括生成の印が当て直しで 0 に戻っていた

一括生成のモジュールは「開始／再開」の後に読み込まれ、ローダが MOD を当て直す（GAME.md の一括生成）。
`343_` は一括生成が走っている数をモジュールの変数に持っていたので、当て直した新しいモジュールでは 0 になり、一括生成でも差分を裏へ回していた（ログに「裏で描いた」）。
数と工程の引数の控えを `sys` の属性に置いて当て直しをまたぐようにし（`241_` と同じ）、直した後は「一括生成なので続けて描いた」になった。

### 一括生成で差分だけ描く

立ち絵が既にある人物には、ゲームの一括生成は仕事を作らない。
そこで `343_` は一括生成の本体（`run_world_bulk_generation`）を抜ける前に、骨格とセーブの名簿の人物のうち、立ち絵があって差分の印が合わない人物へ差分だけ描く（主人公は除く）。
文は人物のフォルダの `prompts.json`、部品の引数と工程（縮小・減色）の引数は、立ち絵を描いたときに `state\stable_diffusion\expression_template.json` へ控えたものを使う。
描いている間は、一括生成の画面へゲームの仕事と同じ鍵（`status`・`completed`・`remaining`・`failed`・`kind`・`label`）で件数を渡す。

| 確かめたこと | 結果 |
| --- | --- |
| 控え | 立ち絵を1枚描いた後に、部品の引数（`width`・`height`・`cfg_scale`・`sample_method`・`sample_steps`・`seed`）と段（`lcm`）、工程の引数（縮小は `pixelation_width=165, pixelation_height=330`、減色は `64`）が残った |
| 差分だけ描く | 「立ち絵のある 120 人に差分だけ描く」で始まり、1人約25秒（WAI v17、続けて描くの2つ目の組）。行政官ガレス・店主エルザ・宝石商レナの差分ができた |
| 一括生成の画面 | 「一括生成中... / NPCの画像: 宝石商レナ（表情差分） / 完了 2 件 ／ 残り 118 件 ／ 失敗 0 件」と出て、進み具合の棒も伸びた |
| 中断する | 描いていた人物は印を書かずに止まり、`中断した（3 人描いて、残り 116 人）`。再開すると「立ち絵のある 117 人」で、描き終えた3人を飛ばした |
| 最後まで流す（2026-11-17 夕方、手で一括生成） | 120 人中 119 人に描いた（計 3025 秒。描けなかった1人は顔が見つからなかった）。ただし画面は「完了 118 件 ／ 残り 1 件 ／ 失敗 1 件」の実行中のまま終わらなかった（下） |
| 描き味 | 前に別のモデルで描いた立ち絵（店主エルザ）は、顔の周りだけ今の設定のモデルの描き味になった（そばかすと目の色が落ちた）。立ち絵をどのモデルで描いたかは残っていないので、今の設定の組で描く |

最初の版は、差分だけ描く1枚目から全員 `OSError: exception: access violation writing 0x0000000000000000` で落ちた（ゲームは落ちなかった）。
部品は生きていた（`sd_ctx` のポインタは3つとも有効）。
ゲームの `StableDiffusion.generate_image` は `progress_callback` を受け取り、ゲームは描くたびに関数の中で作ったコールバックを DLL へ登録する。
立ち絵の後に描く差分はゲームの呼び方をそのまま持ち込むので生きたコールバックが渡るが、控えた呼び方には数と文字列しか残さないので渡らず、DLL は前に登録された消えたコールバックを呼んだ。
差分だけ描く前に `clear_progress_callback`（部品を建てる前に外すのと同じ。[§3.65](3.65.md)）で外すようにして、落ちなくなった。

最後まで流した回は、処理は終わったのに画面が「残り 1 件」の実行中のまま止まって見えた。
ゲームは自分の仕事を終えたところで画面へ `complete` を渡し（記録の 17:42:35.239）、差分だけ描く処理はその後で実行中の件数を渡していたので、最後に渡った実行中の件数が残った。
ゲームに渡す `progress` を包んでゲームが最後に渡した中身を控え、差分だけ描いた後にそれを渡し直すようにした（途中で「中断する」が押されたら `stopped`）。
直した後の実機は下の「実機（2026-11-17 夜、作成画面テスト）」で見た。

## 実機（2026-11-17 夜、作成画面テスト）

テストワールドとは別の世界で、立ち絵に続けて描く・差分だけ描く・画面の戻りを1回の一括生成で通した。
作成画面テストは一括生成を流していない世界で、名簿の住人10人に立ち絵が無かった（立ち絵のフォルダ8つはキャラ作成の候補で、名簿の外）。
立ち絵があって差分の無い人物を素の遊び方で作るため、表情を見せる MOD（`347_`）を外して一括生成を流して途中で止め、`347_` を戻してもう一度流した（後から `347_` を入れた遊び方と同じ）。
仕事は試しの MOD で立ち絵だけに絞った。試しの後にセーブ・骨格・state\ を控えへ戻した。

| 確かめたこと | 結果 |
| --- | --- |
| `347_` を外した一括生成 | 立ち絵だけ4人描き、差分は描かなかった（宣言が無いので差分だけ描くも動かない）。「中断する」で「中断しました。次回は残りから再開できます。完了 4 件 ／ 残り 6 件 ／ 失敗 5 件」（失敗は止めた LLM の仕事） |
| `347_` を戻した一括生成 | ゲームが残りの立ち絵 16 人を描き（1人約53秒）、それぞれに続けて差分4枚を描いた（「一括生成なので続けて描いた」、1人約27秒、強さ 0.35（SDXL・その他のモデル）） |
| 差分だけ描く | ゲームの仕事の後に「立ち絵のある 5 人に差分だけ描く」で始まり、1回目に立ち絵だけ描いた4人に描いた（「一括生成で差分だけ描いた」、1人約27秒）。残る1人は続けて描くときも差分だけ描くときも顔が見つからず描かなかった |
| 一括生成の画面 | 差分だけ描く間は「NPCの画像: 名前（表情差分） / 完了 0 件 ／ 残り 5 件」。描き終えると「一括生成が完了しました。完了 16 件 ／ 残り 0 件 ／ 失敗 3 件」に戻った（ゲームが渡した `complete` と同じ件数） |

この試しの途中で、ゲームの設定のクラウド（Sonnet 5.5）へ集落の詳細（`create_settlement_detail`）と集落の依頼（`settlement_quest_generator`）が1件ずつ通った（ほかに 400 で断られた送信が2件）。
起動直後（2度目の注入の前）に一括生成の画面を開いて開始した回で、試しの MOD の一括生成のフックが呼ばれず、止めが掛からなかった。
フックが呼ばれなかった理由は確かめていない。
一括生成の画面を開くと `scripts.hud.hud_world_bulk` の読み込みで3度目の当て直しが走る。
試しの MOD は、有効な間はいつでも送り口と Anthropic の送信を止める形にした。
止めのフックは `safe=False` にした。`safe=True` では orig の前に投げた例外が「フックの失敗」として扱われ、元の関数が呼び直される（`patch._guard`）。
返事で書かれた集落の詳細は控えへ戻して消した。

### ゲームの仕事が無い一括生成では差分だけ描けなかった

同じ夜に、立ち絵が 147 人とも揃った世界で、試しの MOD でゲームの仕事を空にして（254 件 → 0 件）起動直後に一括生成を流した。
差分だけ描く処理は「ゲームの立ち絵の工程（縮小・減色）の呼び方の控えが無い」の警告で 147 人とも描かずに止まった（世界には何も書かれなかった）。
控えのファイル（`expression_template.json`）は揃っていた。
無かったのは画像生成のモジュールで、ゲームはそれを `AIManager.set_ai_models` の中で読み込んで部品を建てるが、仕事が1件も無い一括生成は `set_ai_models` を呼ばなかった（送り口の作り直しの行も出ていない）。
テストワールドと作成画面テストの回は、ゲームが先に立ち絵を描いていたので揃っていた。
`343_` は、差分だけ描く前に画像生成のモジュールが読み込まれていなければ、ゲームの用意（`set_ai_models`。`AIManager` がまだ組まれていなければゲームと同じ引数で組む）を呼ぶようにした。
用意の後にローダが MOD を当て直すので、描いている間に登録が新しくなったら残りの人物を新しい登録に任せる。

#### 起動して最初の一括生成で、差分の描き足しを飛ばしていた

| `highres_faster` | `lcm` | 512x1024・`lcm` / 5 / 1・seed -1 | 165x330・64色 |
| `highres_upscale` | `stage2` | 512x1024・`dpmpp2m` / 15 / 7 / `karras`・seed -1 | 165x330・64色 |
| `highres` | `stage1` | 512x1024・`euler_a` / 20 / 8 / `default`・seed -1 | 165x330・64色 |

測る途中で、`highres` では顔の描き直しも表情差分も動かず、控えに段と引数が書かれないのが分かった。
`343_` は `stage1` を2段で描くときの下描きとみなして飛ばしていたが、`highres` は1段目の1回で仕上げる。
`highres` を選んでいると、立ち絵を何枚描いても控えができず、差分も顔の描き直しも付かない。

直したこと:

- どの段が仕上げかを画質で決める（`variants.PORTRAIT_FINISH` と `is_draft_stage`。画質が読めなければ今までどおり1段目を飛ばす）。画質はローダの `imagegen.quality`（足した。TECH.md §5.11）で読む
- 一括生成の描き足しで控えが無い・段と引数が欠けていれば、画質の設定と上の表から仮の控えを組んで描く（ファイルには書かない。ログに「立ち絵の呼び方の控えが無いので、画質の設定（…）のゲームの値で描く」）。知らない画質なら、これまでどおり描かずに理由を WARN に出す
- 控えの確認を「画像生成を用意しています」の知らせより前に移した（描けないのに用意の表示を出さない）
- 本物の控えが書かれたときに仮の値と比べ、違えば WARN（`expression-template-differs`）。ゲームの更新で値が変わったときに気づくため
- 道具画面の見通しの段の表（`outlook.STAGES_BY_QUALITY`）に `highres` を足した

検査は `test_sd_variants.py` の仕上げの段・仮の控え・食い違いの単体と、控えの無い起動の一括生成（画質から組んで描く・知らない画質なら描かずに用意の表示も出さない）。結合の2つは直す前の形で落ちるのを確かめた。

直した後の実機（同じ夜、テストワールド。クラウドの設定のまま LLM を止める試しの MOD を入れ、ゲームの仕事が残らないよう前によけた立ち絵を戻した。LLM へのリクエストは0件）:

| 確かめたこと | 結果 |
| --- | --- |
| 控えの無い起動の一括生成（画質 `highres_faster`） | 「立ち絵の呼び方の控えが無いので、画質の設定（highres_faster）のゲームの値で描く」の後に2人へ差分を描いた（1表情 7.2〜13.9 秒）。控えのファイルは書かれなかった |
| 画質 `highres` で主人公を描き直す | 1段目の1回（`[portrait/stage1]`）の後に顔の描き直し（4.8 秒）が走り、控えに `stage1`・cfg 8・20 ステップ・512x1024 と工程の引数が書かれた。直す前は顔の描き直しが走らず、控えは工程の引数だけだった |
| 続けて一括生成（画質 `highres`、その控え） | 2人へ `[portrait/stage1]` で差分を描いた（途中の当て直しは新しい登録が引き継いだ） |
| 食い違いの WARN | 出なかった（`highres` の控えはサンプラーの名前を持たず、比べたのは cfg・ステップ・寸法・seed・工程） |

試しの後に、画質の設定・控え・差分・主人公の立ち絵・セーブを控えへ戻した。

## 未把握の画質をログに出す（2026-11-25、検査だけ）

`highres` の不具合では、道具画面は未把握の画質に「（前回の段から）」と出していたのに、描く側は黙って「1段目は下描き」の前提で進み、ログに原因が残らなかった。
立ち絵を描くときに、画質の設定が `variants.PORTRAIT_FINISH` に無い値か読めなければ、`stable_diffusion.log` に1プロセスで1回だけ書くようにした（描き方は変えない）。
文は「立ち絵の画質の設定（〇〇）は 343 で未把握の値なので、2段で描く画質とみなす。1段で描き終える画質なら、顔の描き直しと表情差分は付かない」。
読めないときは前半が「ゲームの設定から立ち絵の画質を読めないので」になる。
検査は `test_sd_variants.py` の文の言い分けと、画質を読めない起動で立ち絵を何枚描いても1回だけ出ること（直す前の形で落ちるのを確かめた）。
