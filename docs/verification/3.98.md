# 3.98 街の勢力（`339_`）: 13項目とも実機で成立・ローカル LLM で街が結び付かなかった照合を直した・勢力と情勢の窓（版2）は実機で成立・住人の立場（版3）は判定まで実機で成立・勢力の刺客（版5）は実機で成立

開発中は `919_town_factions` の名前で動かした。遊び方と設定は `339_` の DOC.md、実機の経緯は [§2.93](2.93.md)。
記録は `out\town_factions.log`。頼み文をゲーム抜きで実際の LLM と実セーブに通す道具は `tools\faction_probe.py`。
決めた日はどれも 2026-10-11（窓は 10-13、住人の立場は 10-14）。

## 決めた仕様と根拠

### 勢力は設定に書かれたものだけ

ゲームには勢力のデータが無い。
LLM に作らせると、どの世界も王国・商人ギルド・盗賊団に寄る（`132_` `104_` `128_` と同じ種類の偏り）。
手元の6世界で勢力をはっきり書いていたのは1つだけで、設定に無い対立を足すと世界観が変わる。
だから設定に2つ以上書かれている世界だけで動く（組織を設ける2つの道は下）。

- LLM に根拠の原文を一字一句抜き出させ、コードが材料の中にあるかを照合する（空白と括弧は無視、4字未満は認めない）。見つからない勢力・街・関係は捨てる
- 省いた根拠（「...」「…」。Haiku 5.5）は切れ目ごとに照合し、一番長い切れ目が8字未満なら認めない
- 街の根拠にはその勢力の名前を求める（名前の無い一文から推して街を教会に割り振った）。根拠が原文に無い・名前が無いときでも、設定に勢力と街の名前を同じ文に含む一文があれば差し替えて認める（`rules.sentence_naming`。名前は2字以上）。入れる前はローカル（Eclipsed-Phoenix）で5回とも街が1つも残らず、入れた後は 7・7・7・6・7
- 勢力の名前そのものも設定の文の中にあるかを照合する（近未来・ポストアポカリプスで「〇〇の支配勢力」と組み立てた）
- 「冒険者の代わりに〜がいる」と書かれた人々（主人公の仕事）は、名前と「冒険者の代わり」「冒険者に当たる」が同じ文にあればコードでも捨てる
- 業種・職業の呼び名（警備会社・闇金・漁り屋・武装集団・自警団など）は勢力にしない。認めると読むたびに顔ぶれが変わり（3回で 5・4・2 個）、住人の全員が業種の者として話し、裏社会は `336_` の領分と重なる。勢力ごとに name_type（設定がその名前でこの世界の一つの組織を書いているか＝「固有」か、「一般」か）を答えさせ、「一般」を捨てる。普通の言葉の名前（「教会」「機関」「工房」）で三勢力を書いた世界でローカルが3回とも「一般」と答えたので、問いの形を直し、例から「工房」を外した
- LLM が決めるのは何が書いてあるかと文章だけで、点数・段階・幅・下限はコードが決める

### 元の案内文を読む

`321_` は `Area.descriptions` を実行中だけ書き換えて元の文を残さないので、セーブの辞書（`save_data_dict["areas"][id]["descriptions"]`）の元の文から読む。
`area_description`（周辺の土地の文）も材料に入れる。

### 最初の見られ方

LLM に段階を直接決めさせると、同じ材料で2段振れた例が2回あった。
1回きりの判定なので揺れが一周の遊びに残る。そこで2つに分けた。

| 主人公 | 決め方 |
|---|---|
| 新しいキャラ（功績も手配も無く、滞在の合計が 90 日未満） | 出自と勢力の一覧だけを LLM に読ませ、段階を決めさせる |
| 途中導入 | その勢力の街での記録から規則で土台を出し、LLM には功績と経歴を読ませて -1 / 0 / +1 段階だけ動かさせる |

- 土台（`rules.baseline_scores`）: 功績1件 +10（上限 +50）、通算 90 日以上の滞在 +10。治める勢力はそこで起きたことを知っている、という読み
- 手配は功績で打ち消さない。手配されていれば -40 を足し、緊張の上端（-21）より上にしない。手配度 -40 以下（殺人を重ねた重さ）は -80（敵対）。LLM の調整もこの上限より上へは動かさない。足し引きしていた頃は功績5件・滞在229日・手配度 -170 の勢力が中立になった
- ライフログは読まない（組織の名前が出ず、長い世界では大きすぎる）。調整が 0 なら土台のまま、動いたら動いた先の段階の真ん中
- 経歴に「NPC が知る情報ではない」と前書きする書き方があるので、「その勢力が知りえたことだけで判断する」と縛る

### 見られ方は会話の構えに出す

ゲームの会話の記録 213 件で、足された文が応答に使われたかを数えた。

| 足された文 | 応答が使った回 |
|---|---|
| 功績の欄（事実を並べる） | 0 / 63 |
| `317_` の評判の出来事 | 0 / 63 |
| `317_` の二つ名（「あなたも耳にしている」） | 5 / 63 |
| `321_` が書き直した土地の文 | 0 / 17 |
| ライバル冒険者の MOD（開発中）の構え（「あなたは〜を見下していて…」） | 6件とも嫌味と挑発の口ぶり |

出来事の事実は話題にならないが、構えは口ぶりを変え、短い呼び名は第一声で使われる。
だから構えの文と、段階を判定したときの呼び名の形にした。
構えの文には舞台の物を書かず、人と人の関係と振る舞いだけを書く。
足す口はローダの `modnpc` の `notes`（会話の5関数）。
相手の街は、相手が名簿（`resident_npcs` / `adventurer_npcs`）に載っている街、載っていなければ生まれた街（`initial_location.area`）、どちらも無ければ主人公がいま居る街。
名簿に載るのは冒険者だけで、店や施設の主は載らない（10-14 にセーブで確かめた）。版2 までは生まれた街を見ず、店の主はいま居る街の勢力になっていた。

### 住人の立場

版2 までは勢力の街の住人を全員その勢力の者として扱い、敵対している街では宿の主も闇商人も同じ敵意で話した。
実際の住人の人物紹介には、勢力に追われた者・勢力に関心の無い者・別の勢力に通じる者が書かれている。
そこで住人ごとに立場を決め、会話に足す文を立場で書き分ける（10-14 に決めた。立場は画面に出さない）。

| 立場 | 会話に足す文 | 会話で見られ方を動かすか |
|---|---|---|
| 一員（`member`） | 今までどおりの構えと呼び名 | 動かす |
| 従う住人（`follower`） | 勢力が主人公をどう見ているかを知っていて、勢力の目を気にする。中立なら足さない | 動かさない |
| 面従腹背（`dissenter`） | 表向き従い内心は反感。勢力の敵意（好意）を、主人公を嫌う（好く）理由にしない。人目のある所では本音を出さない | 動かさない |
| 無関心（`indifferent`） | 足さない | 動かさない |
| 他の勢力寄り・公然（`other`、`open: true`） | その勢力の者として街にいて周りも知っていることと、その勢力からの見られ方の構えと呼び名 | その勢力を動かす |
| 他の勢力寄り・隠れ（`other`、`open: false`） | その勢力からの見られ方の構えを、表に出さない形で | その勢力を動かす |

- 決めるのは LLM で、勢力の一覧と街の勢力、住人の人物紹介（名前・職業・人物・性格。各 400 字まで）を街ごとに1回見せる（20人ずつ）。台帳ができた後と、住人が増えたときに裏で聞く（`people:` の行）
- 理由（`reason`）を立場（`role`）より先に書かせる。後に書かせた形では、86人中3人で理由と立場が食い違った（理由は「反感は書かれていない」なのに面従腹背、など）。先にしてからは食い違いが無かった（Haiku 5.5）
- 「務めに就く者は自分への迷いがあっても一員」「別の勢力との結び付きが書かれているときだけ他の勢力寄り」「反感が書かれていなければ面従腹背にしない」と縛る。職業や施設の主であることだけで一員にしない
- 面従腹背の反感は、その街の勢力そのもの、または勢力の役人・教え・やり方・要求に向いたものだけ数え、【勢力】に無い組織や個人への恨みは数えない。勢力を概要に後から書き足した世界（住人の人物紹介に勢力が出てこない）で、「教会に家族を奪われた」住人が商人の連合の街の面従腹背になった（4人）。「反感の相手がその街の勢力でなければ面従腹背にしない」とだけ書くと締めすぎ、役人に褒められて拳を握る者や教義に背く研究を続ける者まで外れた（実際の世界で6人→2人）ので、勢力の役人・教え・やり方に向いた反感は数えると書き添えた
- 結び付いている勢力（`faction`）は役と別に全員に答えさせ、街の勢力と違う勢力が書かれていれば、役が何でも他の勢力寄りにする。公然か隠れかは `open`（一員と答えて別の勢力を書いた者は、隠れと答えなければ公然）。役の選び方の中で勢力を聞いていた形では、理由に「教会の守護に就いている」と書きながら役を一員や従う住人にして勢力の欄を空にし、工房の街の工房の一員として書かれた（Haiku 5.5、同じ人物が回ごとに割れた）
- 過去に属して離れた（出奔した・追われた・除籍された）勢力は、結び付きに数えない。Haiku は守るが、ローカルは教会を出奔した医師を教会の隠れた側と読み続けた
- 答えに無い住人・読めない立場・無い勢力の他の勢力寄りは、従う住人にする（聞き直し続けない）。答えが無かった街は、読み込み直すまで聞き直さない
- 決める前の住人と、住まいの分からない相手は従う住人
- 版2 までは、勢力と関わりの無い住人（宿の主・闇商人など）との会話でも、その街の勢力の見られ方が動いていた。勢力の者でない人の印象で勢力全体の見方が変わるのは誤りなので、一員（他の勢力寄りならその勢力）との会話だけにした
- 立場は台帳の `people`（`{npc_id: {town, faction, role, reason}}`）。住まいが変わった住人は、決めた街と違えば決める前と同じに扱い、次に読み込んだとき（住人の数が変わったときも）いまの街で決め直す
- 版2 までに作った台帳には `people` が無い。版3 を入れて読み込むと、その場で全部の勢力の街を順に決める（作り直しはしない。見られ方・噂・来歴はそのまま）

実際の世界（8街・住人91人）をゲーム抜きで通した（読むだけ。数は最後の頼みの1回）。
この世界の人物紹介で、住む街とは別の勢力の名前が出るのは5人だけで、別の勢力に仕えていると読めるのは1人（聖域の守護を志願して教会に受け入れられた剣士。回によって割れる）。他の勢力の者が街にいることは、人物紹介に書かれていなければ拾えない。

| モデル | 一員 | 従う住人 | 面従腹背 | 無関心 | 他の勢力寄り | 1街の時間 |
|---|---|---|---|---|---|---|
| Haiku 5.5 | 28 | 37 | 3 | 21 | 2（公然2） | 4〜8秒 |
| Eclipsed-Phoenix-26B-A4B（ローカル） | 27 | 53 | 4 | 4 | 3（公然1） | 4〜7秒 |

教団の総本山の14人では、審問官・法規の役人・治療院の長が一員、教会を追われた者が面従腹背、教義に関心の無い宿の主と実利だけの闇商人が無関心になった（両モデルとも）。
ローカルは無関心が少なく従う住人に寄るが、従う住人の文は弱いので、どちらに転んでも敵意をそのまま浴びせることはない。
ローカルの面従腹背9人のうち1人は、反感の相手が街の勢力でない読み違い（工房の街で教会のやり方に疑問を持つ者）。
ローカルが【勢力】に無い名前（「貴族」）や街の勢力そのものを他の勢力寄りの相手に書いた回は、従う住人に倒れた。
勢力を概要に後から書き足したテストワールド（7街・住人100人）では、人物紹介に勢力が出てこないので、Haiku は89人を従う住人にした。

ゲームの中（テストワールド、Haiku 5.5）でも、読み込んだ後に7街を順に決め（28人の街は20人と8人の2回）、立場ごとに会話へ足す文が分かれた（一員は構えと呼び名、従う住人は勢力の見方と目を気にすること、面従腹背は内心の反感、無関心は何も足さない、他の勢力寄りは表に出さない心の向き）。実際に話して口ぶりを見るところ（#18 の後半）はまだ。

### 会話の判定は要約に相乗りする

`337_` と同じく、会話を閉じるときのゲームの要約に項目を足す（ローダの窓口 `talk_summary`。TECH.md §3.3.16）。
337 と同じ要約に2本乗っても送信は1回。
判定は相手個人の好き嫌いではなく、その勢力の者として見た印象。
口先だけ調子を合わせた発言では上がらない。

### 勢力どうしの情勢

一個人で世界の勢力に抗うのは無理で、知らない所で情勢が動くのは自然なので、仲は日数の経過でも動く。

- LLM が決めるのは何が起きたか・どの2つの勢力か・近づいたか離れたかと噂の文
- 1回で動くのは1組の1段階まで。設定に書かれた関係は同じ向きに2回押されて初めて1段動く（逆向きで数え直す）。穏やかな世界観では緊張より下げない
- 一度に何日進んでも1回だけ（徒歩は1回で 90 日進む）
- 間隔は `TREND_DAYS` に 0〜`TREND_SPREAD_DAYS`（既定 15）を足した日数。足す日数は台帳の `trend.extra` に持ち、台帳を作ったときと情勢を1回進めるたびに引き直す（版5）。決まった日数ごとに起きるのは不自然なため。
  ばらつきを後から狭めたら、引いてある日数も狭めた幅で見る。`extra` の無い版4までの台帳は、次に日数が進んだときに引く。
  引くのは MOD が別に持つ乱数（`random.Random()`）で、ゲームの `random` の並びは動かさない
- 起きなかったとみなすのは happened が "false" のときと、勢力か向きが読めないとき。Haiku 5.5 は happened に出来事の文を書いたので、"true" でない文も起きた回と読む
- 起きたことは全部の NPC の会話に「各地の噂」として足す。ゲームの噂（`world_data.story.current_rumor`）は書き換えるとセーブに焼かれるので使わない

### 街の出来事（338）との連動

向きは 338 → この MOD の一方向だけ。338 の控え（`state\town_incidents\`。[§3.97](3.97.md)「控えの形」）を読み、無ければ何もしない。
主人公が片付けた出来事は、その街の勢力の見られ方を上げる（出来事ごとに1回）。
前回の情勢から後に起きた・進んだ・終わった出来事は、情勢の材料に渡す。

### 控えの置き場所

| 何 | どこ |
|---|---|
| 台帳（勢力・街・関係・見られ方・情勢） | `state\town_factions_ledger\<世界×主人公>.json` |
| 世界ごとの設定 | `state\town_factions\<世界>.json`（設定画面が書く） |

主人公を作り直したら台帳は引き継がない。
フォルダを分けたのは、`WorldStore.playthrough` の `adopt` が同じフォルダの `<世界>.json` を古い控えとみなして移すため。

### 手で直した台帳

設定から勢力をうまく読み取れなかった世界（「魔王」と「魔王の軍勢」だけになった、など）では、台帳を手で直して勢力を足せる。
手で直すと書き漏らしが起きるので、読み込むたびに `rules.repair` で揃え、直したら書き戻してログに `repair:` を出す。

- 見られ方の無い勢力は中立（0）で足す。手で足した勢力の最初の見られ方は判定しない
- 勢力どうしの組は全部要る。無い組は中立・設定由来でない（`from_setting: false`）で足す。`f3|f1` のように並びの違う鍵は並べ直す。
  組が欠けていると、情勢がその組を選んだときに `apply_trend` が `KeyError` で落ちていた（10-16、手で直す手順を書くときに見つけた）
- 知らない勢力を指す関係・街・住人の立場は外す。住人の立場が知らない勢力を指したままだと、会話の構えで勢力を引けずに落ちる
- 段と点数は範囲の整数に均す（文字列や範囲外を書いた場合）
- 同じ id の2つ目と、id か名前の無い勢力は外す

BOM 付きの UTF-8 で保存すると読めず、台帳が無いものとして設定から作り直され、手で直した分が上書きで消えていた。
ローダの `read_json` が BOM 付きも読むようにした（[TECH.md §3.11.1](../TECH.md)）。

### 勢力の刺客

敵対している勢力の街を歩いていると、その勢力の刺客が呼び止めて勝負を挑む（10-21。版5。本体は `hunter.py`）。
決めたのは次の5つ。

- 339 の中に作る（台帳を読む MOD がほかに無く、ローダに勢力の窓口も無い）
- 出るのは敵対の勢力の街。緊張の街でも出す確率は設定（既定 0）
- 勝ったら刺客は死ぬ（`config['is_dead']`）。見られ方と手配度が下がる
- 負けたらゲームオーバー（ゲームのまま）
- 口で切り抜ける道は外す（動作の確かめの後に考える）

作り方と、そう作った理由:

| 何 | どうしたか | 理由 |
|---|---|---|
| 刺客 | 移動の処理（`MovePhaseManager.move_phase` の後）で、LLM に人物を書かせて `npcs.make_npc` と `generate_npc_detail`。役職は勢力の種類と説明から LLM が決める | `336_` の同房の囚人と同じ形。背景のスレッドで作ると、ゲームの保存が人物の一覧を舐めている間に人物が増えうる |
| 作る間 | 待機表示（`Screen.busy_on`）を出す | `move_phase` の後でも、ゲームはもう選択肢を押せる状態に戻している。作っている間に次の移動ができて、2人目を作り始めた（実機） |
| 到着の取り合い | 作る前に `arrivals.offer`（優先度 20） | 作る間に、同じ到着で `300_` が店の主に話しかけさせていた（実機）。先に申し出ると `300_` が譲る（`launch: yielded to 339_town_factions:hunter`。実機） |
| 呼び止める | 手が空いてから `ConversationStartManager`。第一声は `conversation_starter` の最後の文を「行く手を塞ぎ、勝負を挑む」に差し替える（`300_` と同じ） | 待つ間に勢力の街を出た・会話中・施設の画面でない（衛兵に見つかった画面）なら、次の到着まで待つ。衛兵の画面の上から呼び止め、衛兵の場面を飛ばしていた（実機） |
| 逃げた刺客 | 生きたまま控える。次の刺客までの日数と抽選は新しい刺客と同じに通り、当たったら新しく作らずにこの刺客が現れる。第一声は「以前にも挑んだが逃げられている」 | 同じ人物と因縁が続く。逃げてすぐ同じ街で呼び止め直すと、逃げた意味が無い（10-21 のコードレビューで、書きぶりをコードに合わせた） |

### 台帳を作り始める時点

読み込み（`InstantaleApp.load_game_new`）の後に作り始める。
GUI と `relaunch.sh` の2回目の注入が世界の読み込みと重なると、読み込みの包みが呼ばれないまま遊べる画面になる（実機で2回）。
そのため選択肢が組み直されるたび（窓口 `choices` の `refresh`）、会話の頼み、日数の経過でも、まだ見ていない周回なら台帳を確かめる。

### 世界を作るときに組織を設ける

名前の付いた組織が書かれた世界は少ない。
世界を作るときに設定そのものに組織を入れれば、物語・街の案内文・出自にまで通り、この MOD は読むだけになる。

- 世界の生成の頼み（`send_request("create_world_overview", …)`）の【注意】の前に【勢力】の段を足す
- 書かせる先は地理の説明（`structure_description`。欄の名前を名指ししないと書かれなかった）と拠点の概要文（`settlement_overview` → `descriptions.overview`）。世界の概要は `145_` が差し替えるので書かせない
- 冒険者ギルドにも名前が付く（「ギルド『〇〇』の支部」）ので、頼み文で断り、抽出でも照合する
- `world_data.json` を書き出したところで世界ごとの設定を有効にする（`save_world_json:write_obfuscated_json_file`）
- 組織と街の割り振りは台帳へ直接書かず、読み込んだときの抽出が読む（揺れなかった）
- 組織だけ欲しいなら世界を作るときの概要に書けばよいので、別の MOD にはしない

### 設定に勢力が無い既存の世界に組織を設ける

世界ごとの設定「この世界に組織を設ける」を入れた世界で、勢力が2つ以上読み取れなかったときは、今の世界の文を材料に LLM に組織を2〜4つ設計させて台帳へ直接書く（`rules.build_designed_ledger`）。

- 組織は台帳の中だけにある。効くのは会話に足す構え・噂と見られ方だけ
- 街の案内文に足す形は `321_` と同じ欄を取り合うので見送った
- 設計した関係も、書かれた関係と同じく動きにくくする
- 遊び途中の世界では組織が急に現れるので、世界ごとに自分で入れる形にした

### 手配と敵対の上限

会話・338 の出来事で上がる動きに上限を置く（`rules.gain_ceiling`）。

| 状態 | 上がる先の上限 |
|---|---|
| その勢力の街で手配度 0 未満 | 緊張の上端（-21） |
| その勢力の街で手配度 -40 以下 | 敵対の上端（-61） |
| 見られ方が一度 -81 以下になった | 敵対の上端（-61）。手配が解けても外れない |

- 手配度はその時点の記録を読み、勢力の街が複数あればいちばん重い手配で決める
- 上限以上にいれば動かず、張り合う勢力への響きも無い。上限の手前から上がったときは実際に上がった分から引く
- 上限は上がる動きだけに掛かる。手配されたときに引き下げることはしない
- -81 以下で付けた印（台帳の `locked`）は数の上下では外れず、会話で相手が納得したときだけ外れる。判定は同じ要約の項目 `faction_reconcile` で、決まりを足すのは印のある勢力の者と話したときだけ。それ以外の "true" は捨てる。外れたら同じ会話の +1 / +2 から敵対の上端を越えられる
- -81 にしたのは、最初の見られ方で置く敵対（-80）にはまだ印を付けず、更に下げたときに付けるため

### 勢力と情勢の窓

画面左下の MOD 用のボタン（ローダの `hudicons`。TECH.md §3.3.15）の一覧に「勢力と情勢」の行を出し、押すと窓を開く。
行はその世界で 339 を有効にしているときだけ。
中身は `view.build`（辞書と文字列だけ）、描くのは `window.py`。

- ゲームと同じ黒地を細い白の枠で区切る。地は不透明（0.96 では下の字が透けた）
- 字の大きさは4段（見出し・勢力の名前・本文・添え書き）。添え書き（種類・影響下の街・日付・理由）は小さく灰色
- 段階を色と5段の目盛りで見せる（中立から今の段まで塗り、今の段は濃く）。色は 敵対 赤・緊張 橙・中立 灰・友好 若草・盟友 緑
- 左に勢力の札、右に「最近の噂」と「主人公への態度の推移」。それぞれスクロールできる

| 所 | 書き方 |
|---|---|
| 見出しの下 | 現在地　ミストル（霧の船団の影響下） |
| 札の右上 | 主人公への態度　〔段階〕 |
| 呼び名 | 勢力内での呼び名　「〜」（付けた段階と今の段階が同じときだけ） |
| 札の行 | 影響下の街　A、B（街の名前に「・」が入るので「・」で区切らない。10-20） ／ 他勢力との関係　〇〇と敵対関係　△△と友好関係（関係の語を段階の色で） |
| 注意の行 | 手配が解除されるまで、これ以上関係性が改善する見込みはない。（手配の上限）／並大抵の働きでは、この敵意が解ける見込みはない。（縛りの印） |
| 噂 | 日付の下に引用の形で。段が変わったときは「これにより、AとBは〇〇関係となったようだ。」 |
| 噂（段が変わらない） | 設定の関係の1回目は「関係には改善の兆し／悪化の兆しが見えるようだ」、端では「溝は一層深まったようだ／結束は一層強まったようだ」 |
| 来歴 | 会話により、〇〇の態度は〔段階〕となった。／会話により、〇〇の評価が上がった・下がった。（理由を小さく添える）。出来事は「ゼニスの疫病を解決したことで、〜」、響きは「〇〇への働きが伝わり、〜」、縛りが解けた回は「説得が実り、〇〇の敵意に和らぐ余地が生まれたようだ」 |

- 段階の名前は勢力どうしの関係と同じ言葉（敵対・緊張・中立・友好・盟友）。「好意」「敵視」「信頼」は向きが読み分けられなかった。一番上は「同盟」でなく「盟友」（主人公ひとりに合う語）
- 勢力どうしの関係が動いたことは札に書かず、噂の下の一文だけで伝える（「（40日前まで中立関係）」は主語が複数に読めた）
- 来歴（`history`、新しい 40 件）は点数が実際に動いた回だけ。1日1回・上限で止まった回と、最初の見られ方は書かない。噂と来歴は 1 年以内
- 知らせの印（`hudicons.notify`）は、情勢の噂・段階の変化・縛りが解けたときに立て、行を押すと消える。プロセスの中だけ
- 一覧の行は起動時に1回だけ登録し、出すかは並べるときにその場で聞く（`hudicons.add` の `visible`）。有効・無効は周回ごとに1回読む。読み込みのときに出し入れしていた頃は、読み終える前に「無効」と見て外す順と、2回目の注入で前の世代の行が用済みになる順があり、行が出なかった（10-13）
