# 3.98 街の勢力（`339_`）: 13項目とも実機で成立・ローカル LLM で街が結び付かなかった照合を直した・勢力と情勢の窓（版2）は実機で成立

開発中は `919_town_factions` の名前で動かした。遊び方と設定は `339_` の DOC.md、実機の経緯は VERIFICATION_LOG.md [§2.93](2.93.md)。
記録は `out\town_factions.log`。頼み文をゲーム抜きで実際の LLM と実セーブに通す道具は `tools\faction_probe.py`。

## 決めた仕様と根拠

### 勢力は設定に書かれたものだけ

ゲームには勢力・派閥に当たるデータが無い。
素直に LLM に作らせると、どの世界も王国・商人ギルド・盗賊団のような似た顔ぶれに寄る（`132_` `104_` `128_` が対処してきたのと同じ種類の偏り）。
加えて、手元の6世界のうち勢力をはっきり書いていたのは1つだけで、残りは滅びかけた世界・政治の語彙が無い世界だった。
設定に無い対立を足すと世界観そのものが変わり、統一された世界とは矛盾する。
だから「設定に2つ以上書かれている世界だけ」で動き、書かれていない世界で事実から導く機能は持たない（組織を設ける2つの道は下の「世界を作るときに組織を設ける」「設定に勢力が無い既存の世界に組織を設ける」）。

LLM には根拠の原文を一字一句抜き出させ、コードが材料の中に本当にあるかを照合する（空白と括弧は無視、4字未満は認めない）。
見つからない勢力・街・関係は捨てる。
根拠の途中を「...」「…」で省いて返すことがある（Haiku 5.5）ので、省いた根拠は切れ目ごとに照合する。
短い語をつないで原文に無い文を作れないよう、切れ目のうち一番長いものが8字に届かなければ認めない。
街の根拠には、その勢力の名前が入っていることも求める。
Haiku 5.5 が、勢力の名前の無い一文（「聖者の遺構を模した行政庁舎」）から推して、街を教会に割り振ったため。
ただし、根拠が原文に無い・勢力の名前が無いときでも、設定に勢力の名前と街の名前を同じ文に含む一文があれば、その文を根拠に差し替えて認める（`rules.sentence_naming`。名前は2字以上）。
この照合を入れた後、ローカルの LLM（Eclipsed-Phoenix）は「カスティアとヴァルガルドを治める『白翼騎士団』」と概要に書いた世界でも、根拠に街の案内文を選ぶか言い換えて返し、5回とも街が1つも残らなかった（勢力に街が結び付かず、MOD が何もしない形）。
差し替えを入れた後は、同じ5回で街が 7・7・7・6・7 残った（VERIFICATION_LOG.md [§2.93](2.93.md)）。
勢力の名前そのものも、設定の文の中にあるかを照合する。
近未来とポストアポカリプスの世界で、LLM が「〇〇の支配勢力」「〇〇の武装集団」と街の説明から呼び名を組み立てた（クラウド）ため。
設定が「冒険者の代わりに〜がいる」と書いた人々（主人公の仕事）は、頼み文で外させても残ったので、名前と「冒険者の代わり」「冒険者に当たる」が同じ文にあればコードでも捨てる。

業種・職業の呼び名（警備会社・闇金・漁り屋・武装集団・自警団など）は勢力にしない（2026-10-11 に決めた）。
認めれば名前の付いた組織が無い世界でも動くが、読むたびに顔ぶれと街の割り振りが変わり（同じ世界で3回読ませて 5・4・2 個）、
その街の住人の全員が業種の者として話すことになり、裏社会の業種は `336_crime_overhaul` の領分と重なる。
「数えない」と書くだけでは残ったので、勢力ごとに name_type（この世界の特定の一つの組織を指す「固有」か、同じ種類の人々をまとめた「一般」か）を答えさせ、「一般」を捨てる。
問うのは言葉が普通かどうかではなく、設定がその名前でこの世界の一つの勢力を書いているかどうか。
「教会」「機関」「工房」のような普通の言葉の名前で三勢力を書いた世界で、ローカルの LLM が3回とも「一般」と答えて全部落ちたため、頼み文にそう書き、「数えない」例から「工房」を外した。
論理は渡さない。LLM が決めるのは「何が書いてあるか」と文章だけで、点数・段階・幅・下限はコードが決める。

### 元の案内文を読む

`321_area_chronicle` は依頼のクリアごとに `Area.descriptions` を実行中だけ書き換え、元の文を残さない。
勢力はセーブの辞書（`save_data_dict["areas"][id]["descriptions"]`）の元の文から読む。
`area_description`（周辺の土地の文）にも勢力や土地柄が書かれていることがあるので材料に入れる。

### 最初の見られ方

始めは、経歴・手配度・功績・ライフログを LLM に読ませて段階を直接決めさせていた。
同じ材料で台帳を作り直すと、勢力の段階が2段振れた例が2回あった。
1回きりの判定なので、その揺れが一周の遊びに残る。そこで2つに分けた（2026-10-11 に決めた）。

| 主人公 | 決め方 |
|---|---|
| 新しいキャラ（功績も手配も無く、滞在の合計が 90 日未満） | 出自（経歴）と勢力の一覧だけを LLM に読ませ、段階を決めさせる |
| 途中導入 | その勢力が力を持つ街での記録から規則で土台の点数を出し、LLM には功績の中身と経歴を読ませて -1 / 0 / +1 段階だけ動かさせる |

土台の点数（`rules.baseline_scores`）は、功績1件 +10（上限 +50）、通算 90 日以上の滞在 +10。
その街を治める勢力なら、そこで起きたことは知っている、という読み。
手配は功績で打ち消さない（2026-10-11 に決めた）。
手配されていれば、功績と滞在の点に -40 を足し、緊張の上端（-21）より上にはしない。
手配度 -40 以下は功績によらず -80（敵対）。
LLM の調整も、この上限より上へは動かさない（下げるのは動かす）。
殺人1件で手配度が -10〜-20 動くので、-40 以下は殺人を重ねた重さ。
初めは手配を功績と足し引きしていたが、功績5件・滞在229日・手配度 -170 の勢力が中立になった。
後から設けた組織は物語にもライフログにも名前が出てこないが、街ごとの記録は残っているので、同じ決め方が使える。
ライフログは読まない（組織の名前が出てこず、長い世界では材料が大きくなりすぎる）。
調整が 0 なら土台の点数のまま、動いたら動いた先の段階の真ん中の点数にする。
経歴に「NPC が知る情報ではない」と前書きする書き方があるので、頼み文で「その勢力が知りえたことだけで判断する」と縛る。

### 見られ方は会話の構えに出す

ゲームの会話の記録 213 件で、足された文が応答に使われたかを数えた。

| 足された文 | 応答が使った回 |
|---|---|
| 功績の欄（プレイヤーの情報として事実を並べる） | 0 / 63 |
| 317 の評判の文のうち出来事 | 0 / 63 |
| 317 の二つ名（「あなたも耳にしている」） | 5 / 63（プレイヤーが先に言った回は 0） |
| 321 が書き直した土地の文 | 0 / 17 |
| ライバル冒険者の MOD（開発中）の構え（「あなたは〜を見下していて、口を開けば嫌味や挑発が出る」） | 読んだ6件とも嫌味と挑発の口ぶり |

出来事の事実は NPC の側から話題にならないが、「あなたはこの人をこう見ている、だからこう振る舞う」という構えは口ぶりを変え、短い呼び名は第一声で使われる。
勢力の態度に欲しいのは口ぶりなので、構えの文と、段階を判定したときの呼び名の形にした。
構えの文には舞台の物（地形・制度・技術など）を書かず、人と人の関係と振る舞いだけを書く（どの世界観でも成り立つように）。
足す口はローダの `modnpc` の `notes`（会話の5関数）。

相手の勢力は、相手が住人・冒険者として名簿に載っている街で決める。載っていなければ主人公がいま居る街。

### 会話の判定は要約に相乗りする

`337_` と同じく、会話を閉じるときのゲームの要約に項目を足す（ローダの窓口 `talk_summary`。TECH.md §3.3.16）。
別に呼ぶと会話を閉じる待ちが延びる。337 と同じ要約に2本乗っても送信は1回。
判定は「相手個人の好き嫌い」ではなく「その勢力の者として見た印象」。
口先だけ調子を合わせた発言では上がらない（2026-10-11 に決めた）。

### 勢力どうしの情勢

一個人で世界の勢力に抗うのは無理で、個人の知らない所で情勢が動くのは自然なので、勢力どうしの仲は日数の経過でも動く。
LLM に決めさせるのは「何が起きたか・どの2つの勢力か・近づいたか離れたか」と噂の文。
1回で動くのは1組の1段階まで。設定に書かれた関係は同じ向きに2回押されて初めて1段動く（逆向きに押されたら数え直す）。
穏やかな世界観では緊張より下げない。
一度に何日進んでも1回だけ（徒歩の移動は1回で 90 日進むので、LLM を続けて呼ばない）。
起きなかったとみなすのは happened に "false" と書かれたときと、2つの勢力か向きが読めないとき。
Haiku 5.5 が happened に出来事の文を書いて返したので、"true" でない文でも起きた回として読む。
起きたことは、全部の NPC の会話に「各地の噂」として足す（317 と同じ「あなたも耳にしている」の形）。
ゲームの噂（`world_data.story.current_rumor`）は遊んでいる間に書き換わらず、会話の第一声の頼みに毎回載っているが、そこを書き換えるとセーブに焼かれる。会話に足す口のほうが外したときに何も残らない。

### 街の出来事（338）との連動

向きは 338 → この MOD の一方向だけ。この MOD が 338 の控え（`state\town_incidents\`。[§3.97](3.97.md)「控えの形」）を読み、無ければ何もしない。338 はこの MOD を読まない。
主人公が片付けた出来事は、その街の勢力の見られ方を上げる（出来事ごとに1回）。
前回の情勢から後に起きた・進んだ・終わった出来事は、情勢を決める材料に渡す。

### 控えの置き場所

| 何 | どこ |
|---|---|
| 台帳（勢力・街・関係・見られ方・情勢の記録） | `state\town_factions_ledger\<世界×主人公>.json` |
| 世界ごとの設定 | `state\town_factions\<世界>.json`（設定画面が書く） |

同じ世界で主人公を作り直したら台帳は引き継がない（見られ方は主人公の行いで決まるため）。
世界ごとの設定と台帳のフォルダを分けたのは、周回の鍵へ移す処理（`WorldStore.playthrough` の `adopt`）が同じフォルダの `<世界>.json` を古い控えとみなして移してしまうため。

### 台帳を作り始める時点

読み込み（`InstantaleApp.load_game_new`）の後に作り始める。
起動直後の注入が2回入り、2回目の掛け替えと世界の読み込みが重なると、読み込みの包みが呼ばれないまま遊べる画面になる（実機で2回。GUI と `relaunch.sh` の両方が注入する）。
そのときのために、選択肢が組み直されるたび（ローダの窓口 `choices` の `refresh`）に、まだ見ていない周回なら台帳を確かめる。
会話の頼みと日数の経過でも確かめる。

### 世界を作るときに組織を設ける

名前の付いた組織が設定に書かれた世界は少ない（手元の世界では1つだけ）。
遊んでいる最中に作ると「設定に従う」から外れ、業種の呼び名から作ると読むたびに顔ぶれが変わる（「勢力は設定に書かれたものだけ」）。
世界を作るときに設定そのものに組織を入れれば、世界の物語・街の案内文・キャラの出自にまで組織が通り、この MOD は書かれた組織を読むだけになる。

- 世界の生成の頼み（`send_request("create_world_overview", …)`。概要の有無によらずこの名前）の【注意】の前に【勢力】の段を足す
- 書かせる先は地理の説明（`structure_description`）と拠点の概要文（`settlement_overview` → 街の案内文 `descriptions.overview`）。
  世界の概要には書かせない（`145_` が入力どおりの文に差し替えるため）
- 欄の名前（`structure_description`）を名指ししないと、地理の説明には書かれなかった（実機の1回目。2回目は名指しして後半に「勢力は三つ存在する」の段が入った）
- 生成のときは冒険者ギルドにも名前が付いた（「ギルド『〇〇』の支部」）。勢力にしないよう頼み文で断り、抽出でも照合する
- 作った世界は、`world_data.json` を書き出したところでこの MOD の世界ごとの設定を有効にする（`save_world_json:write_obfuscated_json_file`。世界の名前は書き出す `world_data.name`）
- 組織と街の割り振りは台帳へ直接は書かない。読み込んだときに抽出が読む（名前の付いた組織なので読み取りは揺れなかった）
- 組織だけ欲しい（見られ方の仕組みは要らない）なら、世界を作るときの概要に書けばよいので、別の MOD にはしない（2026-10-11 に決めた）

### 設定に勢力が無い既存の世界に組織を設ける

世界を作るときの組織は、これから作る世界にしか効かない。
世界ごとの設定「この世界に組織を設ける」を入れた世界では、抽出で勢力が2つ以上読み取れなかったとき、
今の世界の文（概要・地理の説明・街の案内文）を材料に、LLM に組織を2〜4つ設計させて台帳へ直接書く（`rules.build_designed_ledger`。2026-10-11 に決めた）。

- 組織は台帳の中だけにある。ゲームの依頼・語り・街の案内文は組織を知らない（効くのは、この MOD が会話に足す構え・噂と、見られ方の仕組み）
- 街の案内文にも足す形（321 と同じ実行時の差し替え）は、321 と同じ欄を取り合うので見送った
- 設計した関係は、設定に書かれた関係と同じく動きにくくする
- 遊び途中の世界では、それまでの物語に無かった組織が急に現れる。世界ごとに自分で入れる形にしてあるのはそのため

### 手配と敵対の上限

会話・338 の出来事で上がる動きには上限を置く（`rules.gain_ceiling`。2026-10-11 に決めた）。

| 状態 | 上がる先の上限 |
|---|---|
| その勢力の街で手配度 0 未満 | 緊張の上端（-21） |
| その勢力の街で手配度 -40 以下 | 敵対の上端（-61） |
| 見られ方が一度 -81 以下になった | 敵対の上端（-61）。手配が解けても外れない（会話で納得させたときだけ外れる） |

- 手配度はその時点の主人公の記録を読む。勢力が力を持つ街が複数あれば、いちばん重い手配で決める
- 上限にいる・上限より上にいるときは動かず、張り合う勢力への響きも無い。上限の手前から上がったときは、響きは実際に上がった分から引く
- 上限は上がる動きだけに掛かる。下がる動き・情勢・最初の見られ方の決め方は変えない
- 手配されたときに見られ方を引き下げることはしない（上がらないだけ）
- -81 以下で付けた印（台帳の `locked`）は、数の上下では外れない。外れるのは会話の判定で相手が納得したときだけ（下記）

印を外す判定は会話の要約に相乗りする（「会話の判定は要約に相乗りする」と同じ1回の頼み）。
項目 `faction_reconcile` は毎回の要約に載るが、判定の決まりを足すのは印のある勢力の者と話したときだけで、それ以外は "false" と書かせる。
"true" を読むのも、印のある相手に頼んだ会話だけ（頼んでいない会話の "true" は捨てる）。
外れたら、同じ会話の判定（+1 / +2）からは敵対の上端を越えて上がれる。手配の上限はそのまま掛かる。
数の上下（通常の操作）では外れず、自由入力などで LLM を納得させられたら外れてよい。

最初の見られ方で手配を功績と足し引きしていたら、殺人を重ねた手配の街の勢力が中立になった（「最初の見られ方」）。
遊んでいる間も同じで、手配されたまま依頼や会話で好かれていくのはおかしいので、上がる側に上限を置いた。
敵対が外れない境目を -81 にしたのは、最初の見られ方で置く敵対（-80）にはまだ印を付けず、そこから更に下げたときに付けるため。

### 勢力と情勢の窓

画面左下の MOD 用のボタン（ローダの `hudicons`。TECH.md §3.3.15）の一覧に「勢力と情勢」の行を出し、押すと窓を開く（2026-10-13 に決めた）。
行は、その世界で 339 を有効にしているときだけ出す。
中身は `view.build`（辞書と文字列だけ。検査で通せる）、描くのは `window.py`（Kivy）。

見た目（文字だけで同じ大きさの字が並ぶのは味気ないので、アイコンは足さずに次で分ける）:

- ゲームの画面と同じ黒地を、細い白の枠で区切る。地は不透明（0.96 では下の白い字が 4% 透けて読めた）
- 字の大きさを4段に分ける（見出し・勢力の名前・本文・添え書き）。添え書き（種類・影響下の街・日付・理由）は小さく灰色
- 段階を色と5段の目盛りで見せる。目盛りは中立から今の段まで塗り、今の段は濃く。色は 敵対 赤・緊張 橙・中立 灰・友好 若草・盟友 緑
- 左に勢力の札、右に「最近の噂」と「主人公への態度の推移」。札の欄（4勢力で見切れる）・噂・来歴はそれぞれスクロールできる

| 所 | 書き方 |
|---|---|
| 見出しの下 | 現在地　ミストル（霧の船団の影響下） |
| 札の右上 | 主人公への態度　〔段階〕 |
| 呼び名 | 勢力内での呼び名　「〜」（付けた段階と今の段階が同じときだけ） |
| 札の行 | 影響下の街　A・B ／ 他勢力との関係　〇〇と敵対関係　△△と友好関係（関係の語を段階の色で） |
| 注意の行 | 手配が解除されるまで、これ以上関係性が改善する見込みはない。（手配の上限に届いているときだけ）／並大抵の働きでは、この敵意が解ける見込みはない。（縛りの印があるとき） |
| 噂 | 日付の下に噂を引用の形で。その下に「これにより、AとBは〇〇関係となったようだ。」（段が変わったとき。関係を段階の色で） |
| 噂（段が変わらない） | 設定の関係の1回目は「関係には改善の兆し／悪化の兆しが見えるようだ」、端では「溝は一層深まったようだ／結束は一層強まったようだ」 |
| 来歴 | 会話により、〇〇の態度は〔段階〕となった。／会話により、〇〇の評価が上がった・下がった。（会話の回は「理由」を小さく添える）。出来事は「ゼニスの疫病を解決したことで、〜」、響きは「〇〇への働きが伝わり、〜」、縛りが解けた回は「説得が実り、〇〇の敵意に和らぐ余地が生まれたようだ」 |

段階の名前は勢力どうしの関係と同じ言葉に揃えた（敵対・緊張・中立・友好・盟友）。
「好意」「敵視」「信頼」は、勢力から主人公へなのか主人公から勢力へなのかが読み分けられなかった。
一番上だけ「同盟」ではなく「盟友」にした（同盟は組織と組織が結ぶもので、主人公ひとりに合わない）。
勢力どうしの関係が動いたことは、札には書かない。
「（40日前まで中立関係）」は主語が複数に読め、「40日前から友好関係」も引っかかったので、噂の下の一文だけで伝える。

来歴（台帳の `history`、新しい 40 件）は、点数が実際に動いた回だけを書く。
1日1回で止まった回・上限で止まった回は書かない。最初の見られ方も書かない（札に出ているので）。
窓に出す噂と来歴は 1 年以内。

知らせの印（`hudicons.notify`）は、情勢の噂が出たとき・会話や出来事で段階が変わったとき・縛りが解けたときに立てる。一覧の行を押すと消える。
印はプロセスの中だけに持つ（起動し直すと消える）。

一覧の行は起動時に1回だけ登録し、出すかどうかはローダが並べるときと一覧を開くときにその場で聞く（`hudicons.add` の `visible`）。
世界ごとの有効・無効は周回ごとに1回だけ設定から読んで覚え、読み込み直したら読み直す。
初めは読み込みと選択肢の組み直しのときに行を出し入れしていたが、世界をまだ読み終えていない瞬間に「無効」と見て外す順と、
GUI の2回目の注入で前の世代の行が用済みになる順があり、次の操作で画面が組み直されるまで行が出なかった（2026-10-13 の実機）。

| 1 | 勢力を読み取る | 世界ごとの設定で有効にして読み込む。`build: … queued` → `build: … ready:`。読み取った勢力と街が設定どおりか |
