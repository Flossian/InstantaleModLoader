**実機で見えたこと**（上の表の版の最初の起動）:
起動は `boot complete: 111/111` で、`apply-error` と `Traceback` は無かった。
`314_` と `315_` は設定を既定から変えた起動で `VERIFY FAILED` を出さなかった（`313_` は既定のままで未確認）。
世界名だけの控えの移し替えは、**持ち主ではない主人公へ移った**。
主人公が死んで同じ世界で作り直した直後に読み込み、前の主人公の周回で書かれた `321_` の案内文・
`325_` の開いた道・`333_` の仲間の装備欄の位置が、新しい主人公の周回へ移った
（`321_` と `325_` は `世界名だけの控え … を周回 … へ移した`、`333_` は `moved 1 owner(s)`）。
その世界には前の主人公の周回の控え（`330_` / `331_` / `modnpc` / `modfacility`）が在ったので、
在るときは移さないように直した（上の `333_` 版19 とローダの `state.WorldStore.playthrough` の行）。
すでに移った分は直しでは戻らない（周回のファイルが在るので、以後は移し替えを確かめない）ので、
ゲームを閉じて手で世界名だけのファイルへ戻してから、同じ主人公で読み込み直した。
`321_` と `325_` は読み込みで、`327_` は宿泊で、`333_` は所持品の窓を開いたときに、それぞれ移さなかった旨を1行出した。
その後の保存でできた周回のファイルは、新しい主人公の分だけだった（`333_` は主人公自身の位置1件で仲間の分は無い。`327_` はその宿泊の1件）。
世界名だけのファイルは4本とも書き換わらなかった。
別の主人公の周回が無い世界では、読み込んだ主人公へ移った。
`321_` と `325_` は読み込みで `世界名だけの控え … を周回 … へ移した`（`321_` は案内文7件を当て直し、`325_` は道1本を当て直した）、
`333_` は同じ読み込みの後に `moved 1 owner(s)`、`327_` は宿の会話で同じ1行。
`321_` / `325_` / `327_` の世界名だけのファイルは消え、`333_` のものは中身が空（`{}`）のファイルとして残った。
移さなかった仲間の id は、新しい主人公が仲間にした別人と同じ番号だった（id は周回をまたいで重なる）。移していれば、前の周回の仲間の位置がその別人に乗っていた。
