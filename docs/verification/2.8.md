# 2.8 施設到着イベント（両モードとも実機で発火）

narration 3件、conversation 6件。
conversation は6回とも `conversation_starter` まで到達した（会話フェーズが実際に始まった）。

この確認の副産物が2つあり、どちらも他の mod の土台になった。

- スレッドの扱いが確定（`process_choice` はメインスレッド、`execute` は別スレッド）
- **`in_shopping` が当てにならない**（通常の移動38回すべて True。
  不発39件のうち38件がこれ。GAME.md §2.6）

その後に分かったこと:

- 同じ施設で続けて出さない間隔を移動回数（`COOLDOWN_MOVES = 3`）で数えていた間は、出入りするだけで間隔が抜け、
  同じ宿の同じ NPC が1日に3回発火した（ログの `roll <…> / <…> / <…>`）。
  数える単位をその施設への訪問（`COOLDOWN_VISITS`）に変えた
- narration モードのセリフの送信は、送信モジュールを名前の一覧（`llama_cpp` と `any_server`）で引いていた間、
  Gemini / OpenAI / Claude では毎回空振りしていた。いまは `llm.ask` が `llm_manager` の別名から引く（TECH.md §5.3）
