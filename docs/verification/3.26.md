# 3.26 アイテム画像の偏りと拡充（`128_`）: 均しは成立・銃の絵はクラウドで実機成立・110分類の絵とジャンルの重みはゲーム抜きで成立・対応表は実機未確認

アイテム画像の選定を包み、「最も似た1枚」固定を
「top1 の類似度の 0.8 倍以上・最大10候補の中で使用回数が最少の1枚」に変える（乱数は無い）。
併せて素の埋め込み辞書に無い305枚の追加辞書を同梱し、実行時に合成する。

オフラインで確認済み:

- **偏りの実測**。5世界494個の集計で potion は52個中35個（67%）が同じ1枚
- **原因の切り分け**。生成ログの `item_appearance` が定型的で、
  決定的 argmax が同じ画像に落とすのが主因。
  「ハブ画像」仮説は否定（最頻画像は重心類似ランクで軒並み下位）
- **埋め込みの再現**。同梱モデルを numpy で再実装し、argmax 再現率 109/114（96%）
- **通しシミュレーション**。実クエリ2,471件で top1 シェアが
  potion 47.2%→8.3%、small_weapon 26.2%→4.8%、clothing 34.2%→9.6%
- **追加辞書の自己検索**。305キャプション全件が合成辞書の中で自分の画像を top1 に引く
- **document フォルダの実態**。追加画像の大半は紙物でなく小物だった
  （紙らしい外見文からは引かれにくい）

実機。1回目は `ctx.mod_dir` の控え忘れで全件フォールバックした
（apply() の外では None になる仕様で、ローダの docstring に明記があるのに控え忘れた）。
2回目で選定経路が成立し、類似度の足切りも設計どおり
（近傍が密な品種は `10 qualified`、まばらな品種は `1 qualified`）。
**同一品種2個目からの散りも成立**（同じ外見文でも2個目が別の絵）。
同じ回で追加辞書の合成も実機初（`base=171 merged=342`）。

**版3（実機未確認）**。
要件が確定した。
問題は「今世界に在る絵との重複」ではなく**見た目の再登場そのもの**
（クラフトで4回中3回が別名なのに同じ見た目の剣になる）。
版2の世界走査では消費・クラフトで消えた絵の履歴が消えるのでこの要件を満たさない。
選んだ累計を `state\item_image\<世界>.json` へ永続化し、
世界走査は**下限の合成**に降格した（合算すると二重になる）。

**実機で確かめること**

1. `seed '<世界>': stored X kinds + world Y items -> Z kinds` の行が出るか
2. `state\item_image\<世界>.json` が選定のたびに更新されるか
3. **再起動またぎの潰し**（版3の眼目）。前の起動で選ばれた絵が次の起動の同品種で避けられるか。
   とくに**クラフトの連打で同じ剣が続かなくなるか**
4. **返り値キー → 画像パスの解決**。
   キーから `image_src` を組む処理は読めておらず `<folder>/<キー>.png` と推測している。
   creature_part の追加分はキーが日本語ファイル名なので、
   その回にアイコンが正常に表示されるかを見る。
   **壊れたら設定「同梱の追加辞書を使う」を OFF**（均しだけは効き続ける）
5. 見た目と外見文の乖離が気にならないか（気になるなら SIM_FLOOR を 0.9 へ）

正しい。版3は名前を知らないため、同じ品の2個目にも均しがかかって個体ごとに

素のゲームでも外見文の揺れで起きる）。

  （Nuitka の生きたフレームは `f_locals` が空。`125_` の実測、[§3.23](3.23.md)）。
  `119_` と同じ「manager を包んで戻り値を読む」方式で、アイテムを生む manager 4つ
  （`shop_item_generator_ordinary` / `shop_additional_item_generator_ordinary` /
  `item_craft_generator` / `master_ai_item_generate`。応答に `item_name` と
  `item_appearance` が揃うことを output_data 268ファイル・642対で確認）を
  観測だけの `required=False, safe=True` で包み、「外見文 → 名前」を

  応答の形の揺れは `instantale_modloader.llm.as_dict` で吸収

  割当が無ければ均しで選んで記録。名前が引けない経路は均しに落ちる

  控えが優先）ので、導入前からの品も次の入手から絵が安定する
- オフライン検算: 控え書式の往復、実セーブからの割当取り込み

**版5（版4の実機1回目の失敗を受けて）: 名前は世界データからも引く**。
版4の実機で「同じ名前でも別画像になる」（実機で気づいた）。ログでは全選定が
`name ?` で、manager 4つの観測フックは装着済みなのに（modloader.log の
`wrapped ...` 4行）、名前が一度も届いていなかった。同時刻の output_data は
クエスト戦闘系のみで、店・クラフト・`master_ai_item_generate` の呼び出しは皆無。

原因: **敵のドロップの定義（名前と外見文）はクエスト生成時に作られ、セーブの
`quests/*/enemies/*/data/drops/*`（`story_quests` / `game_variables.
current_quest_data` も同形）に保存されている。ドロップの瞬間には LLM は
呼ばれない**ので、応答の観測では原理的に拾えない。実際、ログの
ある外見文（rank 0→1→2 と3枚に散った実例）は
セーブ内のドロップ定義の1つと一致した。

直し方は二段:

- **world_dict の全域走査**で「外見文 → 名前」を作る（世界替わりの seed 時＋
  引けない外見文に出会ったとき、前回走査から 10 秒以上空いていれば再走査。
  実測 4.6ms/319対なので負荷は誤差）。走査中にゲーム側が書き換えたら
  拾えたぶんだけ使う（RuntimeError を握って次回に任せる）
- 観測対象に**クエスト生成の manager 3つ**
  （`llm_manager_world_generate` の `settlement_quest_generator` /
  `random_quest_generator` / `story_quest_generator`）を追加。応答にドロップ対が
  入っていることは output_data で確認（最新応答に 13対 / 6対）

版5の実機確認点: ドロップの選定行で `name` が埋まり、同じドロップの2個目で
`kept` が出るか。`seed` の直後に `names '<世界>': N appearance pairs` の行が
出るか。それでも `name ?` が残る経路があれば、その外見文を報告
（quests 以外の置き場所か、world_dict に載らない生成がある）。

**版6（実機未確認）: 仕様に立ち返って作り直し**。版5は実機に出す前に
レビューで棄却された（「世界データの全域走査は冗長。元のコードの維持を
目的とせず、仕様の達成を目指すべき」）。指摘のとおりで、名前を引くために
manager 観測7本・全域走査・再走査スロットル・対応表2枚・割当表と装置が
積み上がっていた。

仕様は「同じアイテムの再入手は同じ絵、別のアイテムには別の絵」の2行。
これは**「外見文 → 絵」の対応表1つを世界ごとに永続化する**だけで達成できる。
同じドロップはセーブに保存された同じ外見文で選定に来るから、表のヒットが
そのまま「同じ絵」になり、**名前の解決という問題そのものが消える**。
初めての外見文には、足切り後の候補から使用数最少の絵を割り当てる（使用数は
表の値から導出。counts の別持ちも廃止）。版4・5の機構（manager 観測・
world_names・assigned・KEEP_SAME_NAME 設定）と実機確認点 6〜8 は全て廃止。
旧版の counts は `legacy_counts` として使用数の下駄に引き継ぐ（見せた履歴は
捨てない）。表のヒットは埋め込み計算より先に返るので、再入手は素より速い。

- オフライン検算: 実在の旧控え（counts 38種）からの移行、
  同一文の再入手が `kept`・類似の別文が別の絵になる通し、新形式の往復まで確認
- 実機確認点（これが現行）:
  1. 同じドロップの2個目で `kept` が出て、同じ絵になるか
  2. 別名の品に `chose` の rank>0 が出続けるか（均しの維持）
  3. `state\item_image\<世界>.json` が `images` 形式で育つか
  4. 追加辞書の画像（日本語キー）のアイコン目視（従来からの残項目）

**版9（クラウドで実機成立）: 素材に無い銃と爆発物の絵644枚を足す**。
素材の 32 フォルダに銃が無く、銃の外見文は剣・槍・機械くずに落ちていた。
同梱の埋め込みの再実装で測った top1 の類似度は、銃の外見文 6 件で 0.48〜0.64、
素材に合う絵がある品（鉄の槍・錆びた短剣）で 0.79〜0.82。

決めた仕様:

- 絵は作者が画像生成 AI で作った黒背景の一枚絵8枚（574枚）と CC0 の素材（70枚。出どころと許諾は `build/cc0/SOURCES.md`）から起こす。
  寸法はゲームの武器の素材と同じで、小型 32x32（168枚）/ 中型 32x64（101枚）/
  大型 32x96（179枚）/ 長物 32x128（160枚）/ 投擲 32x32（36枚）。拳銃は斜めの 32x32 のまま。
  斜めに描かれたソードオフ（2枚の一枚絵で各12枚）は、45 度回して立てた中型と、斜めのままの小型（鍵の末尾 `s`）の両方に置く
- 一枚絵の品種は種類の希望から、絵が箱の高さの 75% に届く箱を小さいほうへ探して決める。
  SF の狙撃銃は縦横比が 2.3〜3.4 しかなく、32x128 では幅でつかえて高さの 7 割前後にしか届かないので、多くが大型に入る
- キャプションは種類の名前と、絵から測った色（本体・木の銃床・差し色・光る色）で組む。
  一枚絵は配布物に入れない（4枚で約 6MB）。作り方は `build/README.md`
- ゲームのフォルダには書かない。ゲームは絵を `Assets/images/item_candidates_dark/<品種>/<鍵>.png`
  の相対パスで引き、Kivy 2.3.0 の `Image` は `resource_find` を通す。
  `resource_find` はカレントにそのパスが無いと `resource_add_path` の探し先を順に見る（wheel のソースで確認）。
  MOD の `images/<組>/` を探し先に足し、その下にゲームと同じ相対パスで置く。
  セーブの `image_src` は素の絵と同じ形の相対パスのまま
- 絵と辞書は組ごとのフォルダに分ける（銃と爆発物は `images/guns/`・`data/guns/<品種>.json`）。
  組は設定（銃と爆発物は `USE_GUN_IMAGES`）で切れ、切るとその組の辞書を読まない。組のフォルダは消しても動く。
  中世の武器・防具など後から足す組も同じ形にする（作者の指示。銃だけを止めたいときにフォルダごと読まずに済むように）
- 探し先は組を設定で切っても足す（探し先に足すだけでは絵を読まない。既に銃の絵が付いた品の表示を保つ）
- 銃の絵の鍵は `gun_` で始め、候補は top1 と同じ側だけにする（top1 が銃なら銃だけ、そうでなければ素の絵だけ）
- 色は元のまま（彩度を落とさない）。ゲームの `_dark` の武器の絵は彩度の平均 0.097・明るさの平均 0.379。
  縮めた銃の絵は彩度を落とさなくても、一枚絵の分が彩度 0.057、CC0 の分（SVG 以外）が 0.067 で、すでにゲームより控えめ。
  初めは `_dark` に寄せて彩度を 6 割にしていた（ゲームの明るい版 `item_candidates` と `_dark` の同じ番号の絵は、彩度の平均が 0.191 → 0.098）。
  そうすると一枚絵の分は彩度 0.035 になり、元の絵より地味に見えたのでやめた。
  明るさは銃の絵のほうが低い（0.22 前後）。黒い金属の銃が多いのと、縮めるときに黒い輪郭が混ざるため

分かったこと（作りに効いた順）:

- 使用数最少の規則は、未使用の銃の絵を優先して選ぶ。素の絵も合わない外見文
  （大型・長物の枠に来た大剣。top1 が 0.28〜0.47）では、銃の絵が候補の下限を越えると選ばれる。
  手元の武器の外見文 331 件（output_data の生成応答と `item_image.log` から集めた）を
  128_ と同じ選び方で流すと、最初のキャプションでは候補に銃が入るのが 7 件、銃が選ばれるのが 3 件
- キャプションに `old` / `worn` / `long` などの剣と重なる語があると、錆びた大剣・すり切れた柄の短剣が銃に寄る。
  その語を外して `, a gun.` を付けると候補に銃が入るのは 3 件、同じ側だけを候補にする規則を足して 1 件
  （光る核を埋めた SF の大剣が大型の SF の銃になる）
- 銃の外見文 11 件は 10 件が銃の絵になる。残りは中型の枠に来たソードオフ・ショットガン（中型に散弾銃の絵が無い）
- 一枚絵を足した後も、ファンタジーの武器の外見文 331 件で銃が選ばれるのは同じ1件。
  前装式の銃と散弾銃の一枚絵を足す前は、実機のフリントロック式拳銃が SF の拳銃に、中型と小型のソードオフが中型の素の絵と現代の拳銃になっていた。
  足した後は、フリントロック式拳銃・ホイールロック式拳銃・火縄銃・ラッパ銃・ソードオフ（中型・小型）・レバーアクション式散弾銃がそれぞれの絵に当たる
- ショットガンの最初の一枚絵は、前装式の一枚絵に続けて描かせたため木と真鍮の古風な絵柄に寄り、現代の散弾銃の外見文にも古風な絵が付いた
  （黒いタクティカル・ポンプ式で候補10件中6件、黒い樹脂のセミオートで10件中10件）。
  種類名に rustic・brass fittings・frontier を足しても、現代の絵が少ないので候補の多くは古風なまま（5件・8件）。
  新しい会話で現代の散弾銃を描き直した一枚絵を足して、現代の外見文の候補の8〜9割が現代の絵になった。古風な一枚絵は作者が外した
- 爆発物（手榴弾・火炎瓶・ダイナマイト・閃光弾・発煙弾）も `gun_` の側に入れる。ゲームの投擲武器の素材は12枚で手裏剣・ブーメランと同じ側にあり、
  素の側に足すと使用数最少の規則で手裏剣の外見文にも手榴弾が混ざるため。投げナイフ・手裏剣・黒色火薬の爆弾の外見文は素の絵のまま。
  キャプションが大まかだと（`A black hand grenade`）軍用の手榴弾の外見文でもゲームの素材の手榴弾が top1 になったので、種類名を具体的にした（安全ピン・ダイナマイト1本と束）。
  ダイナマイトの束の外見文は、ゲームの素材の説明とほぼ同じで（類似度 0.946）素の絵が選ばれる
- 切り抜きの縁を 1px 広げるのに np.roll を使うと端で折り返し、銃床の一番下の行が箱の一番上へ回って横棒になった。
  横棒の分だけ絵の幅が増え、縦横比が下がって長物 19 枚が1つ小さい箱に落ちていた。折り返さない広げ方に直した
- 縦向きの一枚絵は回さない絵の上下を判定しない。細い側を銃口とする判定は、銃口の広がったラッパ銃を逆さにした
- 一枚絵からの切り抜き: 背景は (0,0,0) で、明るさ 12 より上を絵とすると黒い部品も1つの塊につながる（40 では細い銃身と黒い弾倉が割れる）。
  箱で切ってから塊を数えると、箱の線で切れた隣の銃がかけらとして入り、幅が増えて品種が下がる。塊は一枚絵全体で数える
- 横向きの銃の立て方: 一枚絵の銃はほぼ水平に描かれていて、幅が最小になる追加の回転はほぼ全部 0 度。
  斜めに見えるのは見下ろした描き方のためで、銃身の線で角度を決めるとかえって 10 度前後傾く
- 埋め込みは小数5桁に丸める（似ている度合いの差は 1e-4 未満、辞書は半分ほど）

実機（クラウド LLM。Claude API・136 で Claude Haiku 5.5。テストワールド）:

1. 選定の関数をゲームの中で呼ぶと、拳銃・短機関銃・突撃銃・狙撃銃・マスケットの外見文に `gun_` の鍵、短剣と槍に素の鍵が返る。
   返った鍵の相対パスを `resource_find` が MOD の `images/` の下に見つける（組に分ける前の置き場所で確認）
2. 品の `image_src` を銃の絵のパスにすると、装備欄に銃の絵が出る。
   同じプロセスで題の画面から読み直しても、プロセスを起動し直しても出る（探し先を足すのは注入の時で、品の表示より先）
3. 自由行動で銃を拾うと、ゲームが作った外見文に 128_ が `gun_` を選び（`chose gun_fantasy_013 … for 'An old rusted revolver pistol …'`）、
   受け取りの窓（「入手」の欄）に銃の絵が出る
4. 品の説明の箱は、素の品でも絵を出さない（説明の箱で確かめることは無い）

実機（ローカル LLM・テストワールド）で、テストワールドの控えに銃を切る1行を書くと、注入し直さずに次の選定から銃の外見文が素の絵になり（`settings 'テストワールド': USE_GUN_IMAGES=False`）、控えを消すと初めての外見文はまた銃の絵になった。一度選んだ外見文は対応表のとおり同じ絵のまま

組に分けた後の実機（ローカル LLM・テストワールド）: 設定 ON で探し先が `images/guns` になり、銃の外見文に `gun_` の鍵が返って絵が見つかる。
設定 OFF では銃の辞書を読まず（`pool long_weapon: base=76 merged=76`）、銃の外見文にも素の絵が返る。前の起動で銃の鍵が付いた外見文も選び直す

**版9 の実機（10-18、ローカル LLM の Fenrir 26B・テストワールド）**:

- 売買の窓で、所持品の側の銃の絵、店の側の入れ替えた品の絵（中世の短剣 `med_`・中世の服のマント 64x64 `wfa_w09`・食料・道具・装飾品・宝石の `itm_`）が崩れずに出た
- `312_` の入れ替えで、ローカル LLM が作った 12品の外見文がすべて英語。銃以外の分類が選ばれた（`med_m5`・`wfa_w09`・`itm_i7`・`itm_i2`・`itm_i15`・`itm_i30`）
- 世界のジャンルの重み: 設定画面と同じ保存の関数（`modtool.save_world_settings`）でテストワールドに SF 1・サイバーパンク 0.5 を書くと、注入し直さずに次の選定から読まれ（`settings 'テストワールド': GENRE_SF=1.0, GENRE_CYBER=0.5`）、SF の外見文6件のうち5件の絵が SF・現代の分類（`wsf_`・`itm_i27`・`wmo_`）に替わった（重み 0 では素の絵と `wfa_` が中心）。ログに `+genre 0.150` が出る。候補の下限は B 案の形で、加算の無い候補は `rank 1 of 10 qualified` のように残る
- ジャンル内の重み: 設定画面を組み、「ジャンル内の重み」タブで籠手と装甲の分類の SF・サイバーパンクを 0 にして「重みを保存」を押すと `weights.json` が書かれ（`.tmp` は残らない）、ゲームを開いたままの次の選定でその分類の加算が `+genre 0.000` になって別の絵に替わった。窓は4つのタブで開いた
- イベントの品の外見文: 依頼2件でフィールドイベントが1回起きた（品は出なかった）。ゲームの記録（`output_data`）は書き換えの前の文を残すので一文は写らない（`144_` の書き換えも写らない）。`204_` の記録の本文の長さが、判定 4144 → 4258・結末 4310 → 4424 と、どちらも足す一文の長さ（114字）だけ長く、送った頼みに入っていた。品が出たときに英語で返るかはゲームの中では未（ゲーム抜きでは成立）

残り: イベントで品が出たときの外見文（ゲームの中）、版6 の対応表（`kept`）の実機
