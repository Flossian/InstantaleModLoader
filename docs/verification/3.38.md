# 3.38 土地が育つ（`318_` / `221_`）: 実機で成立・セーブの出所は決着

同じ土地に居続けても何も育たない、を直す MOD。
土地ごとにクリア回数を数え、その土地の依頼の難易度を上げる。
在庫もクラフトもゲーム自身がその数から決めているので、触らずに付いてくる。

版1は実機1周で前提が2つとも崩れて作り直した（[§2.66](2.66.md)）。
版2は続く1周で通り、**鎖が依頼の難易度から店の品とクラフトの成果物まで繋がった**（[§2.67](2.67.md)）。

| 崩れた読み（版1） | 実測 | 版2での直し方 |
| --- | --- | --- |
| 新しい依頼は土地の帯から生まれる | 帯を 23〜25 まで上げても 3 で生まれた | 生成のたびに上げ直す（`generate_random_quest` を包む） |
| `world_dict['quests']` はセーブの中身 | あれは世界の雛形（12件 / セーブは22件） | 生きた一覧（`app.world.quests`）にだけ書く |

## 済んでいること

| 何 | どこまで |
| --- | --- |
| **在庫は依頼の難易度そのもの**（[§2.65](2.65.md)） | 実セーブ6世界。持ち物のある店23軒・品190個のうち **186個がその土地の依頼の難易度**。完了済みも母数に入る |
| **ゲーム自身の読み手は生きた一覧を読む**（[§2.66](2.66.md)） | `get_quest_difficulties` が返した5件に、雛形へ現れない依頼（id 13 / 19）が入っていた |
| **敵が実際に強くなる**（[§2.67](2.67.md)） | `318_` が書いた難易度 23 がそのまま `get_enemy_exp_lvl` へ渡り、レベル 24 / boss 基準点 16.57 |
| **作りたての依頼がその場で上がる**（[§2.67](2.67.md)） | `頼み文へ渡す難易度 5 -> 25` と `依頼 22 難易度 5 -> 25` が対で出た。2例 |
| **ロードの一括寄せ**（[§2.67](2.67.md)） | `load: 世界 … を寄せ直した（8件）`。その2分後の戦闘に上げた値が渡った |
| **雛形を触らない / セーブに残らない**（[§2.67](2.67.md)） | 雛形は版1が焼いた 25/24/23 のまま動かず、セーブは全依頼が素の値 |
| **店の品揃えが上がる**（[§2.67](2.67.md)） | 土地0 の店に value 33 の武器と防具。セーブ上の土地0 は `[3,3,3,4,4,4,5,5,5]` なので素からは出ない数 |
| **クラフトの式**（[§2.67](2.67.md)） | `calculate_modification` は float の倍率。成果物の値段 = 素材の合計値段 × 倍率。副産物はその 1/5 |
| 版2の挙動 | オフライン全通（`tools\tests\test_area_difficulty_growth.py`）。ロード時の一括寄せ・生成での引き上げ・受注の直前の書き直し・雛形へ書かないこと・上限3種・範囲・戻し・世界の分離・安全側 |

## 残っていること

| # | 確かめること | やること | 見るところ |
| --- | --- | --- | --- |
| 1 ✓ | **セーブが依頼をどこから組んでいるか**（2026-10-10 決着。下の段落） | `scripts.save_codec:write_obfuscated_json_file(file_path, data)` を包み、(a) `data['quests']` の件数、(b) 上げた依頼3件の `difficulty` と同じ瞬間の `world.quests[id].difficulty`、(c) `vars(app)` と `vars(app.world)` の全属性について `v is data` / `v.get('quests') is data['quests']` の**同一性**、(d) `data['quests'][id] is world_dict['quests'][id]` を録る | 属性が名指しできれば、そこが保存の実体。どこにも一致しなければ保存の直前に組み立てている（次は `save_game` を包む）。`Quest` オブジェクトが素の値を抱えている線は既に消えている（`vars(quest)` の19属性に控えが無い） |
| 2 | `tier` の式 | 段の違う店を何軒か開く | `221_` の `get_area_quest_difficulty_for_tier(…, N) -> M`。実測は1点（2 → 33）だけで、素の並びの3番目と一致するにとどまる |
| 3 | クラフトの倍率の式 | 種別と値段を変えて何度か打つ | `221_` の `クラフトの式` 行。実測2点では形が出ない |
| 4 | 上限に当たった土地 | 最果ての土地（67〜73）で段を重ねる | `上限に届いた` の行。76 を超えないか |

1 は 2026-10-10 に決着した（GAME.md §2.9.1）。
セーブの中身は `app.save_data_dict['quests']` で、生きた一覧へ書いた値はそこへ写らない。

- 依頼を消して読み直す試しで、消えたままになったのは `app.save_data_dict['quests']` からも消した回だけだった（GAME.md §2.9「掲示板で作った依頼と、それを消す」）
- 実プレイのセーブ1件で、`325_` が生きた一覧へ書いた難易度 74 が、受注・クリア・その後の保存と読み直しをまたいでもセーブに出ず、ゲーム自身の 67 のままだった

1 は `318_` のためではなくローダのためだった。
`ui.quest_stores` は「格納場所は2つ、書くときは必ず両方」という前提で、2つ目を雛形（`world_dict['quests']`）にしていた。
掲示板で作った依頼は雛形に居ないので、`301_` / `307_` / `325_` / `336_` が書いた値は生きた一覧にしか届いていなかった。
ログの書けた数は、`307_` / `325_` とも毎回 `1 store(s)` だった。

| MOD | 書いていた値 | 読み直すと |
| --- | --- | --- |
| `307_` | 道中の依頼の難易度・依頼概要の「クリアすると〜へ移動」 | ゲーム自身の難易度と素の概要に戻る |
| `325_` | 道を拓く依頼の難易度・同じ移動の一文 | 同上 |
| `336_` | 裏の仕事の依頼概要の注記（倍率と失うもの） | 注記が消える。倍率と損失の控えは `state\` にあるので精算は変わらない |
| `301_` | 依頼人の名前（会話の相手で上書き） | 生成が返した名前に戻る。ログに残る5回は、どれも生成が会話の相手の名前をそのまま返していて、上書きの前後で同じだった |

v1.15.1 で `quest_stores` の2つ目を `save_data_dict['quests']` に替えた。
4本とも書き方は変えずに直る。
オフラインの検査（`test_area_move_dungeon` / `test_quest_offer`）は、元の部品では3件落ち、直した部品で通った。
実機では未確認。
生成の直後に新しい依頼がもう `save_data_dict['quests']` に入っているかは測っていない。
`307_` / `325_` の `N store(s)` が生成の直後に 2 なら入っている。
1 のままなら受注の時点の2回目で揃う。
`301_` と `336_` は生成の直後に1回しか書かないので、そのときに入っていなければ今までと同じく生きた一覧にしか届かない。

## 分かっていて直していないもの

- **上げた難易度はセーブに残らない。これは仕様として選んだ**（[§2.66](2.66.md) / [§2.67](2.67.md)）。
  ロードすると素へ戻り、**ロードの1回で世界じゅうを書き直す**（＋生成・受注・掲示板・クリア）。
  ゲーム自身の読み手が生きた一覧を読んでいるので、遊びの上では連続して見える。
  裏を返すと **MOD を外せばセーブは素のまま**で、後始末が要らない。
  続きを持つのは `state\area_difficulty\<世界名>.json` のほう
- セーブへ書く案と比べて消せるフックは**ロード時の1本だけ**で、
  代わりに「`state\` を失うと素の値が分からなくなり、
  再インストールで二重に乗る」壊れ方を抱え込む。
  版1の計算違い（`base` が 0 に沈んだ）は、この作りだから1セッションの傷で済んだ
- 版1が世界の雛形へ焼いた難易度は、控えの `base` から戻せる。
  手元で焼けたのは `世界B` の3件だけで、
  **戻していない**（テスト用の世界なので、不可逆な変更のまま置く）
- 既に**受けてある**依頼の中身は変わらない。敵が変わるのは次に受ける依頼から
- `SCOPE=incomplete` では、いま終わらせた依頼も動かない
  （ゲームが `completed` にしてから寄せ直すため）。既定は `all`
- `307_` の道中の依頼は、あちらが受注の時点で自分の難易度を書く。
  こちらが生成時に上げた値はあちらが上書きし、
  片付いた後はまたこちらの管理下に戻る（土地の在庫の母数として）
