# 2.36 新規キャラが最初からレベル60（本体が main_025 で修正して決着）

セーブを復号した実測で、以前の新規開始は全て `lvl 1`、
直近の新規は `lvl 60`（`experience_point=0`）。
後から生えた壊れ方。

バグと判断した決め手は**同じセーブの中で辻褄が合っていない**こと:

| 項目 | 値 | どのレベルの値か |
|---|---|---|
| `max_physical_integrity` | 10 | レベル1 |
| `max_hp` | 832 | レベル60（耐久 16 × 52） |
| `experience_level` | 60 | - |

原因は `instantale.py:876` が `Character(..., experience_level=60, ...)` を渡していたこと。
同じ関数の883〜885行は `get_max_physical_integrity(1)` を呼んでいる。
`levelup` / `gain_exp` は作成中に一度も呼ばれておらず、
属性の違う2体がどちらもちょうど 60 ＝ 計算結果ではなく定数。
MOD 側の関与も排除した（スタックに載る3本はいずれも `orig()` の後に走るロード後の掃除）。

副産物として**レベル → 体力上限の対応**が取れた（GAME.md §2.19 の未確認を1つ埋めた）:
1→10 / 5→11 / 8→12 / 15→15 / 22→19 / 25→22 / 30→26 / 41→34 / 49→39 / 50→40 /
55→42 / 58→43 / 73→50。
HP はレベル60で `耐久 × 52`。

main_025 で 876 行が 1 を渡すようになり決着。
行番号は同じで渡す値だけが変わった ＝ こちらが読んだとおり 876 行だけが食い違っていた。
このとき **`123_` は何もしていない**。
効く条件（レベルが最小値より大きい）が外れるためで、
**「本体が直れば自動で無効になる」という設計が実機で確かめられた**。

本体の修正は既存セーブには効かない。
レベル60のまま保存されたキャラの修復（`REPAIR_LOADED`）は実機未確認で、
新規作成の経路は本体が先に直したため実機では一度も通らずに終わった。
