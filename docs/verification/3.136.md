# 3.136 役場の罰金（`309_office_pardon`）と追手（`316_bounty_hunter`）を `336_crime_overhaul` に取り込む: ゲーム抜きの検査は取り込む前と同じ項目で通過・設定の引き継ぎ（ローダの `merge_settings`）も検査で通過・実機は未

手配を増やす側（衛兵・追手）と減らす側（時効・裁判・無罪・罰金）を1本で読めるよう、`309_` と `316_` を `336_` の機能（`pardon.py` / `hunter.py`・`hunt.py`）に移した。
振る舞いは変えていない。`309_` と `316_` は `"superseded": "336_crime_overhaul"` で伏せた（105・406 と同じ扱い。フォルダは残す）。

| どこ | 変えたこと |
| --- | --- |
| `336_crime_overhaul` 版7→8 | 設定に `PARDON_*`（4項目）・`HUNTER_*` / `BOUNTY_*`（18項目）を足した。うち `PARDON_ENABLED` と `HUNTER_ENABLED` は新しい入切で、ほかは 309・316 の項目の名前を変えたもの（既定値は同じ）。309 の「手配とみなす手配度」（`WANTED_THRESHOLD`）は外し、罰金も窓口 `wanted` の境目（手配度 0 未満）で数える（変えると罰金だけが追手・時効と違う土地を手配と見ていた。値は引き継がない）。罰金の額は固定のまま（土地で変えない）。控え `state\bounty_hunter\<世界>.json` は 316 の頃の名前と形のまま 336 が宣言して読む。窓口の持ち主は `336_crime_overhaul:hunter`。記録は `out\bounty_hunter_send.log` / `out\office_pardon.log` のまま。設定の画面に「役場で手配を解く」「追手」を足した |
| `336_` の入口 | 機能の宣言を窓口 `choices` に預ける処理を関数 `provide_choices` に切り出した（中身は同じ。罰金の検査が本物を通すため）。追手は機能の中で最初に入れる（316 の頃は 336 より前に適用され、ゲームの関数を包む層が内側だった） |
| ローダ | `MERGED_MODS` と `merge_settings` を足した。309・316 で選んでいた値を 336 の新しい名前へ移し、順序ファイルで切っていたら `PARDON_ENABLED` / `HUNTER_ENABLED` を切る。1回だけ（`settings\loader.json` の `merged_mods`）。`drop_renamed` の中で呼ぶので、GUI の起動・更新の展開・watcher の起動で走る |
| `309_` / `316_` | `superseded` と、336 と同じ印・控えの名前を `shares` で断った（`check_mods.py` の取り合いの検査）。DOC の冒頭に取り込んだことを書いた |
