# 2.11 オフライン検証（ゲーム不要）

各本は単独で走る。
まとめて走らせるなら `tools\tests\test_*.py` を順に叩く。

ここに本の一覧と件数を写さない。
何を通すかはその本の docstring の冒頭に1画面でまとまっている。
写すと検査を足すたび二重の書き換えが要り、実際にずれる（TECH.md §6.1）。

ローダ全体の読み込み確認:

```powershell
python -c "import sys; sys.path.insert(0,'runtime'); import instantale_modloader as l; print(l.boot('out/test/bootcheck'))"
```

`boot complete: N/N mod(s) applied` が出れば読み込み側は健全。
N は公開ぶんの本数（同梱から `debug` と `superseded` を伏せた残り）で、
`load_order.local.json` を使っている間はその本数ぶん多く出る（TECH.md §1.3）。

検証台の作り方で踏んだもの:

- 偽の `on_button_press` も本物と同じ形にする
  （`getattr(__main__, cls_name)(app, *args)` を組んで `process_choice` に渡す）
- 解散の検出はスタックで行うので、テストも `QuestEndManager.method_1` の中から呼ぶ。
  app のメソッドを直接叩くと本番と違う経路になり、検出そのものを検証できない
- テストのクラスをグローバル名から派生させない（TECH.md §4.3）。
  派生元は `BASES` の表に控える
