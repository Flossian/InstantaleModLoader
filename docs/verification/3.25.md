# 3.25 ローカルLLMの応答速度（`127_`）: 決着・残るは4点（他の GPU・短縮形の別名・窓縮小・`-c` の素通り）

`llama-server` を専用1スロット（`--parallel 1`）で起こす。
窓（`--ctx-size`）は既定では触らない。
機構は GAME.md §2.12.2、実測は §2.48。

確認済み: 書き換えが実際に届くこと（起動15回すべて。別モデル
`Chimera-X-26B-A4B` を含む）/ 速くなること / 効き方の条件分け（SWA の有無 × VRAM の余裕の4条件）/
別セッションによる独立再測定で4主張とも再現 / VRAM の余白（プレイ15分の実測で最大 15,873 MiB、
目安 16,200 を一度も超えず）/ `--parallel 1` の待ち（プロセス内実測260件で真の多重は 7.7%・
深さは常に2まで・追加待ちは 0.4〜0.9 秒）/ 応答長の分布 / `--cache-reuse 256` は効果ゼロ /
SWA のチェックポイント復元 / 画像側サイドカーの素通しは実機でも無害。

**残っている未確認**

- 他の GPU・他のモデル。
  実測は RTX 4070 Ti SUPER 1台のみ。
  SWA を持たないモデルで余裕がある場合は効果ゼロと確認済みだが、
  害が無いことの確認は Qwen3.5-9B 1本だけ
- 短縮形の別名（`-c` / `-np` / `-cpent`）の扱い。
  MOD は長い旗しか見ないので、欄に短縮形があると SLOTS=0 が効かない・
  欄の `-cpent` を尊重できない。別名表を持たせるかは判断待ち
- SLOTS>=2 & CTX_SIZE=0 の窓縮小。
  窓が 16384÷N に縮み、SLOTS=2 では実機分布の p99 が超える。
  mod.json の note に縮む側の警告が無い
- ゲームの欄剥がしは `-c` にも効くのか。
  起動15回はすべて長い旗だけで `-c` は一度も現れていないので素通り検証ができない。
  もし素通りなら欄に `-c` を書くだけで MOD 抜きでも窓が変わる。実機1回で決まる
