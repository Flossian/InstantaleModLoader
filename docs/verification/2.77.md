# 2.77 MOD が作った NPC の id をゲームの町生成が踏んだ（ローダ `npcs.py`）

世界A の都市（area 2）で、施設の主が別エリアの冒険者になっていた。
ゲームのバグか MOD のバグかの切り分け。

結論はローダ `npcs.free_id` のバグ。
採番を「実在する id の最大値+1」で決め、
ゲームの採番台帳 `index['npc']` を読みも進めもしていなかった。

セーブと `world_data.json` を復号して突き合わせた:

- area 2 の施設 102〜110 の `owner` は両方とも 50〜57 で一致。
  壊れているのは施設ではなく、同じ id に別の NPC が居ること
- world 側の 50〜60: 執政官・ギルドマスター・商人など
  （job は施設種別、`initial_location` は area 2、29項目＝生成直後）。
  ゲームが正しく作った店主
- save 側の 50〜60: 全員 job=adventure、`initial_location` は area 0 の施設 0〜3、33項目。
  手元の MOD が作った登場人物
- バックアップ4本すべてで `index.npc = 50` のまま NPC は 0〜63。
  47〜63 は台帳を進めずに足されていた
- 馬車移動で area 2 が生成され、ゲームは 50 から 11 体分を振って
  `index.npc = 61` に。`generate_character` は `save_data_dict['npcs']` を id で
  引くので、組み上がったのは先住の冒険者。save 側 58・59 の `current_area` が 2 に
  なっているのは、ゲームが「新ギルドの冒険者」として置いたため
- `320_` の募集（64・65）も台帳は 50 のまま。`320_` 単体でも同じ経路を踏む

直し（`npcs.py`）: `index_stores` で `index` を持つ辞書（`world_dict` /
`save_data_dict`）を集め、`free_id` は実在 id の最大値+1 と `index['npc']` の
大きいほうを採る。`make_npc` は作ったあと `advance_index` で両方の台帳を
id+1 へ進める（戻しはしない）。`tools/tests/test_npc_make.py`（17件）。

再発防止: 6種類すべてに広げてローダ `ids.py` に置いた
（`claim` / `next_id` / `advance` / `audit`。TECH.md §3.2.3）。`npcs.py` は
`ids` へ委譲。`tools/tests/test_ids.py`（29件）。

自前で id を振っている箇所は全 MOD を洗って2つだけだった:
`npcs.free_id`（今回）と `402_` の `next_item_id`（元の鍵をそのまま使い、
衝突したときだけ `item_0` から空きを探す）。`402_` の代替採番は実セーブでは
発火していない: 持ち物の鍵 `item_<n>` は世界全体で一意（2世界で 70 鍵・104 鍵とも重複 0）なので、
渡し先に同じ鍵が別の実体で居る状況がそもそも無い。
`item_0` はゲーム自身の最初の品（プレイヤーの持ち物に在る）。

`ids.audit` を実セーブに当てた結果: 世界A は npc（台帳 61・実在 65）だけ。
世界G は facility（台帳 230・実在 234）。後者はセーブエディタで
足した施設で、エディタ側も台帳を進めていない。

実機は未確認（次に `320_` で募集したあと、別の町へ移って店主が新規に
生まれることを見る）。壊れた世界A は破棄し、世界B を立ち上げた。
世界名が違うので旧世界の `state\` の控え（11ファイル）は新世界に当たらない。
控えは残してある。
