# 2.60 枠を動かしている段（`220_` → `316_`）

```text
display_button_load(選択肢7)  -> right_button_layout opa 1 -> 0
update_button_texts           caller: update_ui <- display_button_load
```

**`display_button_load` → `update_ui` → `update_button_texts` の系統**が
`right_button_layout` の `opacity` を決めている。
`update_enemy_display` / `update_enemy_info` はこの枠を触っていない。

ボタンから入る戦闘では押下の流れでこれが通る。`316_` はボタンを押さずに起こすので
抜けていた。`app.display_button_load(0)` を1回通す形にして解けた
（座標も `opacity` も MOD からは触らない）。

通す時機は**選択肢が戦闘のものになった最初の合図**。
はじめは「敵が揃った直後」に通していたが、
土地の移動で読み込みが延びた回に**まだ戦闘前の選択肢が並んでいて**、
その数で右の欄が決まって重なった（実機）。

> 1回目に `枠が動いた` が0件だったのは、**その注入に見張りが入っていなかった**から。
> 計測を足したら注入し直すこと。0件は「動いていない」の証拠にならない。
