# 2.65 店の在庫はその土地の依頼の難易度だった（実セーブ6世界、`318_` / `221_`）

「その土地の依頼の難易度を上げれば、店の品揃えも上がるか」を、
ゲームを起動せずに `world_data.json` を復号して確かめた
（XOR 鍵は `tools\rebalance_saved_bgm.py` と同じ）。

対象は `%LOCALAPPDATA%\Darmabeko\Instantale\worlds\` の6世界。
持ち物を持っている主の居る施設は23軒、品物は190個。

190個のうち 186個が、その土地の依頼の難易度そのものだった。

| 世界 / 土地 | 依頼の難易度 | 施設（tier） | 在庫の `value` |
| --- | --- | --- | --- |
| 世界D 2 | 27 / 30 / 31（3件とも完了済み） | general_store（standard） | 5,5,27,27,30,30,31,31,31 |
| 世界D 2 | 〃 | medical_facility（basic） | 27,27,27,27,27,30,30,31 |
| 世界D 3 | 48 / 54 / 55（3件とも完了済み） | specialty_shop（advanced） | 48,48,48,54,54,54,54,54,55,55 |
| 世界D 8 | 67 / 69 / 71（3件とも完了済み） | general_store（standard） | 67,67,67,67,67,69,69,71 |
| 世界E 1 | 5 / 10 / 12（10 だけ完了済み） | general_store（basic） | 5,5,5,10,10,10,10,12 |
| 世界E 4 | 17 / 18 / 21 | medical_facility（advanced） | 17,17,17,17,18,18,21 |
| 世界F 7 | 42 / 44 / 45 | general_store（advanced） | 42,44,44,44,44,44,45,45 |

分かったことが4つ。

1. 品揃えの段は土地の依頼の難易度から来ている。
   外れた4個は2軒に集まっていて、どれもその土地には無い難易度だった（上表の 5,5 を含む）。
   プレイヤーが売った品が主の持ち物へ積まれる経路（GAME.md §2.13.1）で入ったものと読める
2. 完了済みの依頼も母数に入る。
   世界D のエリア 2 / 3 / 8 は依頼3件とも `config['status'] == 'completed'` だが、
   在庫はその難易度で並んでいた。
   `get_quest_difficulties(area, world, include_completed=True)` の既定そのまま
3. 施設の `tier` は在庫の段を1つに絞っていない。
   `basic` の店にもその土地の最高難度の品が並ぶ。
   `tier` の語彙は `basic`（140）/ `standard`（138）/ `advanced`（36）の3語だけで、
   6世界の施設 1,244件を数えて他の値は出ていない（主の居ない施設は `None`）。
   誰が `get_area_quest_difficulty_for_tier` の `tier` に何を渡しているかはここでは未実測
   （→ §2.67 で判明。整数で、品揃えを作るのは `generate_item_in_shopping`）
4. 依頼は土地ごとに3件ずつ、難易度が固まって置かれている。
   世界を作った時点で 0..76 を9つの土地へ割り振る形で、最初の町が 2〜5、最果てが 67〜75。
   `206_` の記録では、新しく作られる依頼の難易度もこの帯の中に落ちる
   （帯 `[5,4,3]` の町から 3 と 5、帯 `[9,3,7,8,7]` の町から 9）

これで `318_area_difficulty_growth` は在庫にもクラフトにも触らずに済む。
残るのはクラフト側の実測（`ItemCraftManager.calculate_modification` の実引数と戻り値の型）で、
`221_probe_item_level` がそこだけを録る。
