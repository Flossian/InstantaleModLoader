# 2.25 `112_` 本文の行間（画面から採寸）

起点は実機のスクリーンショット1枚。
文字 31px 前後・行間 70px・段落間 138px（＝行間のちょうど2倍）から、
**段落の間に空行が1行入っている**ことと、
本来の行間そのものが広い（既定 1.0 なら 42px 前後のはず）ことが読めた。

実機で確定した値は採寸の推定より1つ広く、
`hud.text_display` の `line_height` は 1.8（推定は 1.6）、`font_size` 27（推定 31）。
既定 0.8 倍で 1.44 になり、750文字の本文の高さが 3738 → 1776（約 2.1 倍縮んだ）。

一致は完全一致では取れなかった。
当たったのは `match=2`（ラベルの `text` が `display_text` で終わる）で、
**ゲームは塗るときに前へ何かを足している**。
完全一致だけを条件にしていたら、このラベルは1回も見つからなかった。

倍率は絶対値ではなくゲームの値に対する比で持ち、設計値はラベル自身に控える
（注入し直すたびに掛け直して縮み続けるのを防ぐ）。
