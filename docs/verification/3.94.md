# 3.94 Claude で新しい店が空のまま（`406_` 版3・`312_` 版5）: 実機で成立

記録は `out\modloader.log` の `406_user_role_fix:` と `stall guard:` の行、`out\shop_restock.log`。

| MOD | 版 | 変えたこと | 確かめ方 |
| --- | --- | --- | --- |
| `406_user_role_fix`（旧 `406_gemini_user_role_fix`） | 2→3 | Claude でも user role を足す。フォルダの名前・表示名・題を Gemini と Claude の両方に合わせた | Claude で初めて開く店。`inserted user role for shop_item_generator_ordinary` が出て品揃えが並ぶ |
| `312_shop_restock` | 4→5 | 持ち物が空で雛形（`config["goods"]`）がまだ無い店は、控えがあっても初めて品揃えを作る回として素通しにする | 初めて開いたときに品揃えの生成が落ちた店を、もう一度開く。`kept sold out:` が出ずに品揃えが並ぶ |

## 分かったこと

- 素のゲームの品揃えの依頼（`shop_item_generator_ordinary`）は system の役割2件だけで組まれる。Claude の API は system を別の欄へ移すので messages が空になり、`400 messages: at least one message is required` で断られる。ローダの `stalls` が3回目で打ち切り、本文の欄に知らせて選択肢を戻した（§3.92）
- 品揃えを一度も作っていない施設の `config` には `level_of_detail` しか無く、作った後は `goods` / `stock_tier` / `stock_update_date` が足される（2026-10-11、2つの世界の街の施設をすべて読んだ）
- 初めて開いたときに生成が落ちると、`312_` は品0の控え（`first visit: … items=0`）を書き、ゲームは雛形を書かない。版4はそこを売り切れの店と読み、次に開いたときにゲームが作った9品を全部外した（`kept sold out: … dropped 9 refilled item(s)`）。版4のうちに空になった店は、ゲームが雛形を書いた後なので版5でも売り切れの扱いのまま残り、入れ替えの日に戻る
- テストワールドなど遊び込んだ世界の店は品揃えができた後なので、Claude に替えても表に出なかった。新しく作った世界では、どの店も最初に開いたときに止まる

## 確かめたこと（2026-10-11、新しく作った2つの世界。Claude Haiku 5.5）

- `406_` 版3: 世界 B の雑貨屋で `inserted user role for shop_item_generator_ordinary` が出て、LLM が品揃えを返した（このときは版4の `312_` が外した。下の項）
- `312_` 版5: 世界 A の隣の村の雑貨屋で、`406_` の `NEEDS_USER` を `m` で空にして最初の生成を 400 で落とし（`first visit: … items=0`）、戻してからもう一度開いた。10品が店主の持ち物に残り、画面にも並んだ。`kept sold out:` は出なかった
- `tools\tests\test_shop_restock.py` に、生成が落ちた店を開き直す場面と、その後の買い占めが空のままの場面を足した。版4のコードでは2件落ちる
- 確かめていないもの: Gemini での `406_` 版3（手を入れたのは送信モジュールの見分けだけ）。エピローグと自由施設の要約の3件の Claude での実機
