# 3.51 アイテム効果の調整・回復アイテム（`134_`）: 実機で成立・残るは3点

`226_` の実測（GAME.md §2.13.2）を受けて書いた。効き方と式は `134_` の DOC.md
（細分で分け、スタミナは払わない。医薬品・ポーションは版3から**最大 HP の割合**。素の `回復` の伸びが HP の伸びと合わず序盤の薬が数% しか戻らないため）。
本体との噛み合わせ: `疲労負荷` は 0 で書き残す（本体の `usable` が常に真になる印を兼ねる。説明欄では伏せる）。
使う時は本体の `consume_item` を `usable=True`・`回復` を間だけ 0 にして呼び、持ち物が減っていればこちらの効果を乗せる。
本体の1行は同じスレッドの `add_text` で差し替える。
割合を量に直すのは使う時で、使う人の `max_hp`（無ければ `current_hp`）が底。版2 までに作り直された品（`回復` が数）は数のまま効く。
本体の版が変わって `consume_item` が文を出さなくなっても、こちらが1行出す（`shown` が偽のとき）。
`refused`（持ち物が減っていない）が出たら本体が消費していないので効果を乗せない。
オフラインは `tools\tests\test_item_effects.py` 70件。

実機で見るもの（済は簡易2回）:

| --- | --- | --- |
| 1 | 新しく作られた品の `attributes` | 済。説明欄に新しい項目が出て `疲労負荷` の行が**無い**。`out\item_effects.log` に `generated` |
| 2 | 古いセーブの品 | 済。持ち物の窓を開いた時点で `window/center` または `window/left` の行 |

**簡易2回（Lv60・スタミナ上限 45）で #1〜#4 と #8 が通った。**
`out\item_effects.log`: 窓を開いた時点で `window/left` に食料（`スタミナ回復: 28`）・ポーション（`回復: 408` / `状態異常: 解除`）・医薬品（`回復: 435`）が作り直され、`226_` の記録では `疲労負荷: 0` が残って本体は `usable=True` で通っている。
食料2回で `physical_integrity` が 4→32（+28）→45（上限で切れた）。
版3では医薬品 rare（価値段階 75）が `回復: 37%` / `40%` / `36.8%`、食料 common（価値段階 70）が `スタミナ回復: 21` / `23`（式は 22 ± 10%）に作り直され、HP 1 の状態で `40%` の品を使って `current_hp` 1 → 563（最大 HP 1404 × 0.4 = 561.6。`planned={'hp': 562}`）。
持ち物は毎回1つ減り、`refused` は 0、WARN / ERROR は 0。
値段は `129_` が価値段階の軸で付け直し、`405_` の地域倍率も乗った（買価 1250 → 1875。#8）。
画面の文言は**ログでは確かめられない**。`205_` と `226_` は `134_` より外側なので本体の「HPを0だけ回復した。」を写す（`205_` の版3からは1プロセス500行まで）（差し替えは内側で起きる。2回目にその1行が `consume_execute` の側に付いたのは、本体が `consume_item` のスレッドで文を出す間にメインスレッドの `execute` が戻っていないため。文はワーカースレッドから出ているので差し替えは効く）。
残るは #5・#6・#7。
