# 3.60 日数送りをローダの関所へ寄せた（`307_` / `314_` / `315_` / `325_`）: 実機で9項目とも成立

`elapse_days` に渡る日数を差し替えていた4本から包みを外し、
ローダの `durations` が1枚だけ包む形にした（TECH.md §3.3.3）。
MOD は「その1回に何日にしたいか」を望みとして出し、
複数あるときは**先に始まった事情が決め、残りは頭打ちだけ**掛かる。

これで消えたのは `314_` の「渡された数が素の値（90 / 14）と同じかどうか」の見分け。
素の値と違えば外側（`307_`）が既に減らしたと推測していたので、
`314_` は相手の名前と挙動を知っている必要があった。
いまは誰が何を望んだかを関所が全部知っているので推測が要らない。

遊びとしての挙動は変えていない（望みの値も勝ち負けの結果も、今までと同じ数になるように作った。実機で確認済み）。
オフラインは `test_durations`（決め方・1世代1枚・`orig` を必ず呼ぶ）と4本の検査で通っている。
検査の偽 `ctx` は、同じ対象に2枚当たったときに層にするよう直した
（`325_` は日数の**後処理**だけ自分で包むため。1枚しか覚えないと後から当てたほうだけが残る）。

**実機の確認項目**（1セッションで通せる順。`✓` は済み）。
手元の設定は `314_` 徒歩30日・馬車7日、`315_` 1週間・年齢加算オフ、
`307_` の `TRAVEL_DAYS` と `325_` の `ARRIVAL_DAYS` は既定14日（計測時点）。
この組み合わせなら**設定を変えずに #6 / #7 の「先に始まったほうが決める」まで見られる**
（`307_` / `325_` の14日 < `314_` の30日なので、頭打ちではなく決め手の違いが出る）。

| # | 操作 | 出るはずの行 | 合格 |
|---|---|---|---|
| ✓1 | 起動して注入するだけ | `area_move_custom.log` に `durations: the day gate was declared on __main__:InstantaleApp.elapse_days` | **世代ごとに1行**（注入し直しで増える）。同じ世代で2行なら二重。`WARN durations` がどこにも出ない |
| ✓2 | 宿屋で1泊 | `vacation_custom.log` に `days: 30 -> 7 (315_vacation_custom decided 7)` と `stay: 1週間 spent 7 left 0` | 暦が7日だけ進む |
| ✓3 | 続けて「まだ宿泊する」 | 同じ2行がもう1組 | 2周目も7日（予算が積み直る）。`WARN stay: … no elapse_days call` が出ない |
| ✓4 | 他の街へ徒歩 | `area_move_custom.log` に `days: 90 -> 30 (314_area_move_custom decided 30)` | 暦が30日。ボタンの `徒歩(30日)` と一致 |
| ✓5 | 他の街へ馬車 | 同じログに `days: 14 -> 7 (314_… decided 7)` | 暦が7日。運賃も設定どおり1回で引かれる |
| ✓6 | 「危険な道を行く」で到着まで | `road_travel.log` **と** `area_move_custom.log` の両方に `days: 90 -> 14 (307_area_move_dungeon decided 14; 314_area_move_custom wanted 30)`。続けて `road: the road to '…' takes 14 day(s)` と `arrived: '…' reached; the road took 14 day(s) (set to 14)` | **決めるのが `307_`**（`314_` の30に膨らまない）。暦は14日。日数送りが2回目も来たときだけ `days: … left alone`（来なければ出ない） |
| ✓7 | 「新たな道を探す」→ **踏破か即時開通**で開けて到着（委託で開いた道を普通に渡るのは `314_` の移動） | `road_opening.log` に `days: commission due (day … >= …); opening …`、到着で `days: 90 -> 14 (325_road_opening decided 14; 314_… wanted 30)` と `road: the road to '…' takes 14 day(s)` | 到着が14日。**期日の来た委託が日数送りの後に開く**（後処理の包みが残っている証拠） |
| ✓8 | 道場で訓練を1段（1年） | `days:` の行が**どのログにも出ない** | 暦が365日進む（窓の外の日数送りには触らない） |
| ✓9 | 依頼・休養など、ふだんの日数送り | 同上。`days:` が出ない | 暦は素のまま |

`#8` / `#9` は「触っていないこと」の確認なので、`#2`〜`#7` のついでに暦の進み方だけ見ればよい。

**実機1セッションで9項目とも通った。** そのセッションの ERROR は0件、`WARN durations` も1件も無い。

- **#1**: 起動から `boot complete` が5回（再適用4回 ＋ 注入し直し1回）で、
  `durations: the day gate …` も5行。**世代ごとにちょうど1行**で二重は無い
- **#2 / #3**: 宿泊7回すべてが `days: 30 -> 7 (315_vacation_custom decided 7)` ＋ `stay: 1週間 spent 7 left 0`。
  連泊（2組）でも2周目に予算が積み直っている。
  暦は `325_` が独立に数えた日付で裏が取れた（day 1218 → 宿泊2回 → day 1232 ＝ ちょうど 7+7）
- **#4 / #5**: 徒歩 `days: 90 -> 30`（day 1167 → 1197）、馬車 `days: 14 -> 7`。ボタンの表示と一致
- **#6**: `days: 90 -> 14 (307_area_move_dungeon decided 14; 314_area_move_custom wanted 30)` が
  `road_travel.log` と `area_move_custom.log` の**両方**に出た。
  続けて `road: … takes 14 day(s)` → `arrived: … the road took 14 day(s) (set to 14)`、暦も +14（1204 → 1218）。
  **決めたのは `307_` で、`314_` の 30 には膨らまなかった**。
  `days: … left alone` は出ていない（この道では日数送りが1回しか来なかった ＝ 保険の出番が無かっただけ）
- **#9**: このセッションの `days:` の行は上の4種だけ。依頼・エリア生成・その他の日数送りには1行も出ていない。
  計測の `217_`（関所より外）は `elapse_days(90) / (14) / (90) / (14)` と**素の数**を録っていて、
  「計測は関所より外」の性質も保たれている
- **ついでに確かめられたこと**: ある馬車の移動は `325_` が開いた道（挟む街1）で、
  設定 7日 × 距離補正 = 14 ＝ **素の値と同じ**なので `days_limit=None`（望みを出さない）。
  `days:` は出ず、ゲームの 14 日がそのまま進み、ラベルも `馬車(2000G・14日)` で一致した。
  運賃だけは前払い調整で 2000 を1回（`fare: charged 2000 in one deduction`）

- **#7**: 2つの経路が別々に出た。
  **後処理の包み**は、宿泊の日数送りで day 1232 に達し、その直後に
  `days: commission due (day 1232 >= 1232)` → `opened:`（委託で開通）。
  **到着で決める側**は、ダンジョン（難易度15）を踏破して道が開き、
  `days: 90 -> 14 (325_road_opening decided 14; 314_area_move_custom wanted 60)` が
  `road_opening.log` と `area_move_custom.log` の両方に出て、
  `road: … takes 14 day(s)` → `arrived: '<街名>' reached; the move took 14 day(s) (set to 14)`。
  `314_` の望み 60 は距離補正（徒歩30×挟む街1）で、**そちらには膨らまなかった**。
  計測（`217_`）はこの回も窓の中に `elapse_days(90)` を1回だけ録っている（関所より外＝素の数）

- **#8 / #9**: 訓練（`DisplayTrainingChoice` → `TrainingStartManager` → `TrainingPhaseManager` ×2）で、
  暦は day 1261 → 1626（1年＝365日）→ 2356（2年＝730日）と**素のまま**進み、
  `days:` の行はどのログにも出ていない。関所は窓の外の日数送りに触っていない。
  選択肢も4つ → 2つと減っていて、残り年数の挙動（GAME.md §2.17）と合う
