# 2.41 `119_` の注入がローカル LLM 専用だった（原因確定 → v2 で修正）

同じログを時系列で並べると、プロバイダをクラウドへ切り替えた時点から
`rewritten` が 0 件になり、`marker_missing` だけが並んでいた。

原因は注入の入口が `llama_cpp_runtime_completion:LlamaCppClient.chat` の1つしかないこと。
クラウド経由はこの関数を通らないのでマーカーが差し込まれず、既定のそのまま通す側へフォールバックする。
「安全側に倒す」設計が効いているので壊れはしないが、**MOD が丸ごと無効になる**。

二段構えのうち効かなかったのは1段目だけだった
（戻り値を直す2段目は `llm_manager` の `master_ai_*` をラップしているのでプロバイダに依存しない）。
`111_` が v4 で解決したのとまったく同じ注意点。

## 修正（`119_` v2 / `111_` v6）

**`111_` のフックの入口をコピーせず、ローダへ移した**（`instantale_modloader.llm`。TECH.md §5.3）。
コピーすればその場は直るが、ドリフトは予告されている（TECH.md §3.2.3）。
移したのは**どこで捕まえるか**だけで、どう書き換えるかは両方の MOD に残っている。

- 世代管理は問題にならない（`wrap` は既存のラッパーを壊さずラップする）
- ラップする順序はローカルでは `after` / `before` どおりだが、
  **クラウドの別名では約束しない**（後生えを監視して適用するので先に適用した方が内側になる）。
  互いの書き換えが相手の目印を壊さない前提で書く
- 「1回の推論で1回だけ」のフラグは登録ごとに分ける
  （共有すると先に通った MOD が後の MOD を塞ぐ）

実機は [§2.49](2.49.md) で確認（`openai` で4件）。

別名の後生えへの掛け直しの時点は、ローダが `modloader.log` に `late-armed on` で残す。
`119_` の監査ログにも写していたが、起動ごとに6行で記録の8割を占めたので外した。
