# 2.41 `119_` の注入がローカル LLM 専用だった（原因確定 → v2 で修正）

同じログを時系列で並べると、プロバイダをクラウドへ切り替えた時点から
`rewritten` が 0 件になり、`marker_missing` だけが並んでいた。

原因は注入の入口が `llama_cpp_runtime_completion:LlamaCppClient.chat` の1つしかないこと。
クラウド経由はこの関数を通らないのでマーカーが差し込まれず、既定の素通し側へ倒れる。
「安全側に倒す」設計が効いているので壊れはしないが、**MOD が丸ごと無効になる**。

二段構えのうち効かなかったのは1段目だけだった
（戻り値を直す2段目は `llm_manager` の `master_ai_*` を包んでいるのでプロバイダに依存しない）。
`111_` が v4 で解決したのとまったく同じ落とし穴。

## 修正（`119_` v2 / `111_` v6）

**`111_` の仕掛け口を写さず、ローダへ移した**（`instantale_modloader.llm`。TECH.md §5.3）。
写せばその場は直るが、ドリフトは予告されている（TECH.md §3.2.3）。
移したのは**どこで捕まえるか**だけで、どう書き換えるかは両方の MOD に残っている。

- 世代管理は問題にならない（`wrap` は既存の層を壊さず包む）
- 包む順序はローカルでは `after` / `before` どおりだが、
  **クラウドの別名では約束しない**（後生えを見張って当てるので先に当てた方が内側になる）。
  互いの書き換えが相手の目印を壊さない前提で書く
- 「1回の推論で1回だけ」の印は登録ごとに分ける
  （共有すると先に通った MOD が後の MOD を塞ぐ）

実機は §2.49 で確認（`openai` で4件）。
