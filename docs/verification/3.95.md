- 新しい世界の町では、ギルドが「便利屋組合・ネオン支部」、裏の事務所が「闇改造工房・火花堂」の名で作られた
- 最初の語り（`narrator_initial` / `narrator`）・背景の頼み（`background_image_creator`）・NPC の詳細（`npc_detail_generater`）で `role+world`。最初の語りは「ガラス張りのビルが林立する場所」「配送ドローン」、組合の主人との会話は端末・ドローンの荷揚げ・倉庫街の夜の仕事・借金取り

## 概要を全文足しても窓に収まるか（2026-10-31）

同梱の llama-server の窓は 16,384 トークン（`127_` の `--parallel 1` で1件ごとに全部使える）。
`output_data/` のローカルの記録（本文にスキーマ入り）を同梱モデルで数えた値（[§2.3](2.3.md)「105 を外しても窓に収まるか」の数え）から、`144_` が概要を足す頼み（役の一文があり、世界の情報の印も足さない印も無い）だけを抜いた。

| 型 | 件数 | 最大（頼み＋出力） |
|---|---|---|
| `vacation_scene_generator` | 2 | 7,371 |
| `quest_referee_with_free_action` | 154 | 6,491 |
| `quest_starter` | 29 | 6,385 |
| `life_detail_setter` | 1 | 5,638 |
| `field_event_evaluator` | 39 | 5,423 |
| `npc_detail_generater` | 151 | 2,338 |
| `background_image_creator` | 743 | 472 |

- 手元の世界の概要は最長で 1,643字。最大の頼み（18,773字 = 10,049 トークン）で約 1.9字に1トークンなので約 900 トークン。足し先の最大 7,371 に全文を足しても約 8,300
- 世界の情報を持つゲーム自身の頼みは、概要を切らずに載せている（長く遊んだ世界の自由行動の進行で世界観 1,574字。この頼みがローカルの記録で最大の 10,049 トークン）。概要が窓を圧迫するほど長ければ、`144_` の足し先より先にこちらが溢れるので、`144_` だけ切っても防げない
- `143_` の足し先（さいころ・立ち絵の要素）はもっと小さい（`create_look` の最大 825）
- 全文にして残る差は、同梱のローカル LLM の読み込みの時間だけ（1,643字の世界で、切っていた600字との差は1回あたり約 550 トークン）

## 確かめていないもの

- 概要を全文にした版4の実機。上の数えはゲーム抜き
- diffusers_openvino・sdcpp_cuda 以外の方式（sdcpp の vulkan / cpu）。敵の絵の前置き
- 世界の概要を足した分のローカル LLM での遅さ。足さない形と比べてはいない。Eclipsed-Phoenix-26B-A4B では、さいころから立ち絵まで約20秒、世界の生成は約70秒で、遅いと感じる長さではなかった（[§3.93](3.93.md) の「書き直した種の表で、ゲームの経路を通した実機」）
- （決着）町の生成で弾かれた施設の種類の値。クラウドだけで出ていたのは、Claude の SDK が場所の `type` の const を外し、`facility` と書けたため。`136_` 版5で直した（[§3.71](3.71.md)）
- ローダの `stall guard` が世界の生成を止めた後、画面が「世界を生成しています…」のまま「生成する」が押せず、ゲームを起動し直すしかなかった（`144_` とは別の件。ローダの不具合として 2026-10-11 に直した。[§3.92](3.92.md)「世界作成の画面で止まった件」）
