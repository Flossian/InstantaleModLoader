# 3.130 主人公の特質を能力値・戦闘・店の値段に効かせる（`346_player_trait_effects`）: 置き換え・条件・値段・LLM への添え書き・人物欄は実機で成立、戦闘の効果はオフラインで通過・実機は未

2026-11-13 に `924_player_trait_effects` として作り、同じ日に正式化した。
主人公の特質（`player_data.traits` の name / description / severity）を、LLM に1回頼んで決まった効果の一覧に置き換え、能力値の窓口（`abilities`。TECH.md §3.3.27）と値段の窓口（`prices`）に効かせる。
遊び方と量の決め方は MOD の DOC.md。

## 分かったこと

- 素のゲームの severity は、作成画面で才能点を数えるのに使われるだけで、作った後はどこにも使われない
- 説明の文は会話・戦闘・依頼の頼みに載るが、数値には何も効かない
- 実行時の `Area` は規模を持たない。ダンジョンは依頼の中にしか無いので、「ダンジョンで」は「依頼中」と見分けられない。条件は「常に・依頼中・戦闘中・ボス戦・体力半分以下」の5つにし、場面の見分けはローダの `abilities.situations` に置いた（人物欄の灰色と同じ見分けを使うため）
- `output_data` には書き換える前の頼みが残る。LLM への添え書きは `out\trait_effects.log` の `LLM: 効果の一覧を足した` の行で確かめる
- 特質の見本は、作ったモデルで偏りが大きい。Gemma4 の 46 件は約半分が「致命傷で倒れない」で、Haiku 5.5 の 88 件は環境への耐性・察知・交渉が中心だった

## 量の物差し

最初の物差し（条件の割引が大きく、目安の重さが severity と同じ）では、テストワールドの severity 3 の特質が「戦闘中判断+4」になった。
装備の能力値補正（`411_`。1品で epic +1〜2・legendary +2〜3・mythic +3〜4）に揃えて、次のように直した。

- 条件の割引: 依頼中・戦闘中 0.8、体力半分以下 0.6、ボス戦 0.4
- 重さの目安: severity ÷ 2
- 1つの効果の量: ±3 まで
- 1つの特質の中で、同じ能力値の利点・代償は1つずつ（「依頼中判断+3・戦闘中判断+2」が依頼の中の戦闘で +5 になっていた。頼み文に決まりを足しても 159 件中 14 件残ったので、検算でも量の大きい方だけを残す）
- 決まりの版（`RULES_VERSION`）を控えに書き、古い版で置き換えた特質は次の照合で置き換え直す

ゲームと同じ Haiku 5.5・effort high で、主人公4人と見本 45 件の特質 53 個を3回ずつ（159 回）置き換えて比べた。

| | 前 | 後 |
| --- | --- | --- |
| 能力値の量の分布 | +2: 96、+3: 66、+4: 26、+5: 1 | +1: 69、+2: 127、+3: 3、+4 以上: 0 |
| severity 3 の正の補正の合計（平均） | 3.3 | 2.1 |
| severity 8 の正の補正の合計（平均） | 6.3 | 4.0 |
| severity と向きが合う | ほぼ同じ | 121/145 |

主人公4人の結果は3回ともほぼ同じだった。
文と severity が食い違う特質（利点だけの文に severity -3）は、文の側に沿った正の効果になった。設定「寄せる」は向きが逆のときは触らないので、結果は変わらない。

| 人物欄のマウスオーバー | 特性とスキルの箱に乗せると、名前・効果・説明の窓が出た。いまの場面で効いていない効果は灰色で出た |

ほかに直したこと:

- スキルの属性が英語（`physical`）のまま出ていたので、よく出るものを日本語にした
- 説明の窓は、最初の幅（窓の 26%）では長い特質の説明が18行まで伸びた。36% に広げた（広げた後の実機は未）

実プレイの世界のログ（読むだけ）では、ボス戦の条件も立っていた。

## 戦闘の効果（決まりの版3、2026-11-14）

最初の版は能力値と値段だけで、戦闘の効果（軽減・不屈・耐性など）は付けられなかった。
411 の武器・防具の効果を流用すると 411 を入れないと効かなくなるので、411 の `battle.py` の処理をローダの窓口 `battle_effects`（TECH.md §3.3.28）へ移し、411 と 346 の両方が答える形にした。
特質に開いたのは14種類（会心・吸収・貫通・特効・毒・怯み・不屈・棘・再生・守護・耐性・軽業・火事場と、品に付かない「軽減」）。
上限は 411 の legendary の強さ、重さ 1 は epic の強さの半分。
呪い・成長・処刑・連携・重装・呪縛は品の性質（代償や討伐数を持つ）なので開かなかった。

411 は品への抽選と書き込みを残し、身に着けている品の効果を窓口へ答える。
防具の説明欄に武器の種類（会心など）が書かれていても効かせない形は、411 の答えの側で守る（窓口へ移した最初の形では効いてしまい、411 の検査で見つかった）。
検査: 411 の検査（品の効果の戦闘の1手）と、346 の検査（411 を読み込まずに特質の軽減が効く。200 → 170）を通した。素の venv で検査177本が通った。

見本（Haiku 5.5・effort high、特質 53 個を1回ずつ）:

| | 結果 |
| --- | --- |
| 戦闘の効果が付いた特質 | 19 / 53 |
| 付いた戦闘の効果 | 不屈 5・怯み 4・軽業 3・火事場 3・耐性 3・軽減 2・吸収 1 |
| 重さの平均（目安） | severity 3: 1.41（1.5）、severity 4〜5: 2.26（2.25） |
| severity と向きが合う | 42 / 53 |

例: 戦場での直感（3）→ 戦闘中判断+2・軽業 5%、不屈の戦魂（4）→ 不屈 40%・火事場 -10%、毒耐性の体質（4）→ 耐性 30%・依頼中耐久+2。
怯みは「死臭への慣れ」「実験体の記憶（severity -2）」のように、文に敵を怯ませる話が無い特質にも付いた（4件中2件）。

## 戦闘の効果の実機（テストワールド、2026-11-14）

主人公の武器に会心 100%・吸収 50%、防具に棘 40%・不屈 100% を書き、依頼3件で戦った（控えを取ってから試し、最後に控えへ戻した）。
窓口のまとめた効果は 411 の品の分と 346 の特質の軽業 5% を足したものだった。
会心は攻撃の手で毎回効き、ログの行と本文の `（…の会心の一撃）` が出た。

受ける側は確かめられなかった。
仲間を外して防御を続けても、審判が敵の攻撃を毎回空振りに裁き、窓口の受ける側の処理まで届かなかった（主人公 Lv72 と敵の差が大きい）。

防御の手と、審判が逃走に裁いた手でも会心の行が出た。
審判はどちらの手にも敵へのダメージの欄を付けて返し、会心はその欄を1段上げて行を足していた（411 の `battle.py` の時と同じ条件）。
防御の手では一撃の戻りが 0（ログの `dmg=0`）なのに、敵の体力は 9〜10 減っていた。
行は手の終わりに、上げた相手の体力が手の前より減っていたときだけ出すようにした。体力の読めない相手が居れば出す。
この形でも、上の防御の手のように敵の体力が減った手では行が出る（会心で上げた裁きがその減りに入っているかは測っていない）。
出さなかった手はログに `critical: … dealt no damage; the line is not shown` が残る。
検査は `test_equipment_bonuses.py`（体力が減らない手では出さない・戻りが 0 でも体力が減れば出す）。この形での実機はまだ。

## 戦闘の代償（決まりの版4、2026-11-14）

版3 は戦闘の効果を利点だけにしていたので、負の特質は能力値を下げるか note に回すしかなかった。
版3 の見本では、効果が空の特質が4個（書写の癖 -2・灰色の濁り目 -2・濃い霧に慣れた肺 2・氷結の呪い -3）あり、
「受けるダメージが増える」「治療の効きが極端に薄い」「無理を重ねると後に反動が来る」は note に回っていた。

窓口に品に付かない種類を5つ足し、特質に開いた。

| 種類 | 効かせ方 | 上限（特質） | 重さ 1 |
|---|---|---|---|
| 脆さ | 軽減などを掛けた後に上乗せ | 15% | 5% |
| 隙 | 手の最初の一撃で1回引き、当たればその手の敵への一撃をすべて 0 | 15% | 5% |
| 治りにくさ | ゲームの回復（`resolve_battle_effect` の前後の体力の増え）と、窓口の吸収・再生を減らす | 45% | 15% |
| 反動 | `check_battle_end` が真を返したときに最大体力の割合を失う（体力 1 で止まる。戦闘に1回） | 15% | 5% |
| 治りやすさ（利点） | 治りにくさの逆 | 30% | 10% |

代償の重さは負に数え、どれも上限で -3（能力値の補正の -3 と同じ）。
窓口の上限は、隙・反動 50%、治りにくさ 90%（品の側の答えと足しても毎手空振り・回復が消える形にしない）。
検査: `test_battle_effects.py`（偽の持ち主で、脆さ・隙・回復の直し・反動を通す）と、346 の検査の代償の段。

見本（Haiku 5.5・effort high、特質 53 個を1回ずつ）。プロンプトを2回直して3回流した:

| | 版3 | 版4 1回目 | 2回目 | 3回目（採用） |
|---|---|---|---|---|
| 直したこと | | 代償の一覧と「場面が書かれているときだけ」 | 「severity の向きの側を主にし、反対の側は軽くする」 | 「治療の話の無い特質に unmend を付けない。重さを合わせるために説明に無い代償を足さない」 |
| 戦闘の効果が付いた特質 | 19 | 19 | 26 | 27 |
| 代償の効果 | 0 | 6 | 11 | 13 |
| 怯み | 4 | 0 | 1 | 1 |
| severity と向きが合う | 42 | 38 | 43 | 43 |
| severity 3 の重さの平均（目安 1.5） | 1.41 | 1.1 | 1.28 | 1.44 |

1回目は、利点と代償をほぼ同じ重さで付けて合計が 0 になる特質が増えた（霧の残滓・夜目が利きすぎる・鈍い痛覚・痛みを噛み殺す・魔障の肉体）。
2回目は、治りにくさが7件に増え、うち5件は治療の話の無い特質だった（重さを合わせる小さな代償として使われた）。
3回目の代償 13 件のうち、文に不利な場面がある付き方は8件（書写の癖の隙、過去に囚われた眼差しの隙、痛みを噛み殺すの反動、冥府の心臓と魔障の肉体の治りにくさ、氷結の呪いの脆さ、境界を越えし者の脆さ 2件（「基礎的な頑健さが常人より低い」））。
文から遠い読みが1件（鈍い痛覚の治りにくさ。「負傷の程度を見誤りやすい」を手当ての遅れと読んだ）。
文に無い代償が4件（穢れへの耐性の脆さ（斑紋の話だけ）、不屈の精神の隙（代償の文が無い）、獣の飢餓の治りにくさ（飢餓感を読み替えた）、冥府の心臓の脆さ）。
冥府の心臓は利点の耐性を note に回し、重さ -3.0 で severity 5 と向きが逆になった。
ヴェスティアの境界を越えし者には、文に無い利点の軽減 -5% が付いた（「遺物と魔術の反動を軽減する」を受けるダメージの軽減と読んだと見られる）。

文に無い代償や読み違えは、LLM による曖昧さとして受け入れ、プロンプトの決まり足し・根拠の検算・多数決などでは制御しない。
遊ぶ側のモデルは想定できず、手元の Haiku で合わせ込んでも効き目が薄いため。
代わりに、キャラ作成画面で効果を見て振り直せるようにした（次の節）。

## キャラ作成画面の効果（2026-11-14）

作成画面の特質にも効果を出し、物語を始める前に振り直せるようにした（`charamake.py`）。
作成画面の作りは `246_probe_charamake_traits` と読み取りのスクリプトで測った（GAME.md §2.35）。
特質の欄は `character_vm.trait_1` の1つだけで、`to_dict()` がセーブの特質と同じ形なので、作成画面の結果は物語を始めた後の特質の印とそのまま一致する。

実機（試し用に作った世界「作成画面テスト」。クラウドの Haiku 5.5）:

| 確かめたこと | 結果 |
| --- | --- |
| さいころの後に頼む | 通った（「血に弱い」severity -3 → 隙 10%、約1秒）。さいころで特質が空のときは頼まない |
| 窓の「生成」の後に頼む | 通った（空の箱の窓に名前と説明を入れて「生成」→「鉄の胃袋」→ 依頼中耐久+2・耐性 20%）。窓は開いたまま効果の欄が書き換わった |
| 箱の下の1行・窓の効果の欄・区切りの線・「効果を再生成」のボタン | モックの形で出た |
| 効果を再生成 | 頼み直しは通った。同じ頼み文では同じ答えが返ったので、前の効果を添えて違う置き換えを頼む形にした。「鉄の胃袋」では耐性の量だけが変わった（15% ⇔ 20%） |
| 物語を始めた後 | 照合で作成画面の効果を引き継ぎ（`引き継ぎ: 疑り深い（作成画面で置き換えた効果）`）、頼み直さなかった |

直したこと:

- 窓は作った直後にはまだ画面に付いていない。付いているかを見て文字を入れていたので、効果の欄が空のままだった
- 区切りの線は、位置の変化を受けたその場で引くと y だけが位置の決まる前の値のまま残った（`pos`・`x`・`y` のどれに追従しても同じ）。次の描画の前に1回引き直す形にした
- 効果の欄の高さ（説明の欄の 38%、約114px）では、効果が3つの特質で3行目が切れた（告知の写真を撮るときに見つけた）。説明の欄の 48% に広げた。説明の文には5行ぶん残る
- 起動直後の当て直し（boot #2）でモジュールが読み直され、前の世代の入れ物が別の型になって作り直していた。窓を作った入れ物と結果を書く入れ物が別になり、窓に結果が届かなかった。当て直しのたびに中身を写し、包みの中では最新の入れ物を呼ぶ形にした

検査: 346 の検査の作成画面の段（頼む・控える・表示・再生成で前の効果を添える・読めないとき・設定を切ったとき・引き継ぎ）。
怯みは「周囲の生物に本能的な恐怖を与える」死の気配に付いた1件だけになった。
