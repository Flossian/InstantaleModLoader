# 3.141 出資した建物の説明の生成と帳簿からの書き換え（`331_facility_investment` 版49）: ゲーム抜きの検査は通過・実機は未

2026-11-25 に、出資した建物の説明を建てるときに名前と一緒に生成し、帳簿（`state\facility_investment`）の `description` に控えるようにした。
帳簿の `name` と `description` を書き換えて読み直すと、建物はその値で建つ。
遊び方は MOD の DOC.md「建物の名前と説明」。

## 変える前の形

説明は種類と等級で決まる表の文（6種類 × 3等級）で、施設ごとには持っていなかった。
帳簿の `name` を書き換えても、読み込みの順によっては元の名前で建った。

## 読み込みの順

読み込みでは、331 が `World.__init__` の前に帳簿から層を積み、その後にローダの `restore_world` と 331 の `apply_holdings` が建物を建てる。
`restore_world` が先に建てると、控えの写し（`state\modfacility`）の値が層の `fields` に勝つ（`spawn` は `fields.update(snapshot)`）。
写しは前の保存のときの値なので、帳簿を書き換えた後でも古い名前と説明で建つ。
`apply_holdings` が先に建てた場合は帳簿の値で建ち、写しは `config` だけが戻る（[§3.126](3.126.md)）。
どちらが先かはフックを重ねる順で決まる。

`apply_holdings` で建てた後に、実体の `name` と `description` を帳簿の値に揃えるようにした（`match_ledger`）。
写しは次の保存（`snapshot_all`）で揃えた値に書き直される。

## 生成

主人を作るリクエスト（`FacilityKeeper`）に `facility_description` を足した。
最初の一文に見た目（屋内か屋外か・場所の姿・主な物 2〜3 個・光）を書かせる（背景のプロンプトが説明から作られるため）。
施設名が表へ降りたときは、説明も表の文にする。
同じリクエストのシステムプロンプトの「ダークファンタジーRPGの」を外し、渡す施設の情報から表の概要を外した。

版49 より前に建てた持ち株には、読み込んだときに表の文を `description` として `name` の後に書き込む（`fill_descriptions`）。

## 検査

`test_facility_investment.py` の「建物の名前と説明は帳簿から」。
生成した説明が帳簿と建物に入ること、帳簿を書き換えて読み直すと名前と説明がその値になり、次の保存で写しも揃うこと、古い帳簿への書き込み、空の説明が表の文になること、施設名が表へ降りたときの説明。
`match_ledger` を外すと、書き換えた名前と説明の検査を含む5件が落ちた。
