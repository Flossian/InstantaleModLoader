# 2.14 `OSError: [WinError 123]`: 名前が原因で画像が生成できない（新種）

`crash_log.txt` の114件には無い新種。
キャラクタ名に含まれていた ASCII の `"` が Windows のパスに使えず、
`os.makedirs` が失敗して画像が生成されないまま無言で終わる（2回・同一人物）。
バックグラウンドスレッドなのでゲームは落ちない。

調査結果:

- `worlds/<世界>/characters/` のディレクトリ名はキャラクタ名そのもの
- 名前の唯一の入口は `scripts.characters:Character.__init__`
  （LLM 生成・プリセット・プレイヤー・ロードが全部ここを通る）
- 名前からパスを組む箇所は5つある。
  書き込みと削除で消毒がずれると別の不整合を生むので、**入口で正すほうが安全**
- 不正文字を含むディレクトリは作成できない ＝ 旧名のディレクトリは存在し得ないので、
  既存キャラクタを改名しても迷子は出ない
- 残る懸念: セーブ側 JSON には次の保存まで旧名が残る。
  名前で突き合わせる処理があると食い違う（実測では id で突き合わせているように見えるが未確証）

実装（`110_`）は入口ひとつで消毒する。
`< > : " / \ | ? *` → `＜ ＞ ： ” ／ ＼ ｜ ？ ＊`（消さずに全角へ写す）、
末尾の空白・ピリオドと制御文字を落とす。
予約デバイス名と、消毒すると空になる名前は触らず記録だけ残す。
旧名を必ずログへ残すのは上の懸念のため。

オフライン36件の最後の2件は実地で、落ちた名前そのものでこの OS 上の
`os.makedirs` を叩いている（生の名前では今でも `winerror == 123`）。
