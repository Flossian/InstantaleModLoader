# 2.66 前提が2つとも実機で外れた（`318_`）

初版を実機で回した1時間で、設計の土台にしていた読みが2つとも崩れた。
どちらも「ゲームがこう作っているはず」という推測で、実データで確かめていなかった側。
生ログは `out\area_difficulty.log` と `out\quest_flow.log`（`206_`）、
それに世界A の `world_data.json` と `savedata.json` の復号。

## 1. 新しい依頼は「いまの帯」ではなく素の帯で生まれる

```text
board: 土地 0 依頼 0 難易度 5 -> 15 / 依頼 1 4 -> 14 / 依頼 2 3 -> 13
random_quest_generator(settlement='<最初の街>', difficulty=4)   ← 206_
clear: 土地 0 依頼 0 難易度 15 -> 25 / 依頼 1 14 -> 24 / 依頼 2 13 -> 23
random_quest_generator(settlement='<最初の街>', difficulty=3)   ← 206_
```

土地の依頼を 13〜15、次いで 23〜25 まで上げた状態で作らせて、生まれた依頼は 4 と 3。
ゲームは今の難易度を見ていない。

初版は「ゲームは土地の依頼の帯から新しい依頼の難易度を選ぶ」を前提にして、
生成には手を出さず、初見の素の値を「いまの難易度 - いま乗せている量」で控えていた。
前提が逆だったので、作りたての依頼だけ素の難易度のまま差し出され、
控えた素の値も 4 - 20 = 0 まで沈んでいた（実データで2件）。

直した形は、生成のたびに上げ直す（`generate_random_quest` を包む）ことと、
初見の素の値をそのまま控えること。
頼み文へ渡す難易度も同じだけ上げるので、文章と数が食い違わない。

> 帯の中で生まれた過去の観測（`[5,4,3]` の町から 3 と 5）は、
> たまたま素の帯と一致していただけだった。
> 素の帯を動かした状態で採っていれば、その時点で分かっていた。

## 2. `world_dict['quests']` はセーブの中身ではなく世界の雛形

同じ瞬間の2つのファイル:

| | 依頼の数 | 依頼 0 の難易度 | 依頼 0 の状態 |
| --- | --- | --- | --- |
| `worlds\<世界>\world_data.json` | 12 | **25**（MOD が書いた値） | incomplete |
| `saves\<世界>\savedata.json` | 22 | 5（素の値） | completed |

- 掲示板で作られた依頼（id 13 / 19 / 20 / 21）は雛形の側に無い。
  `206_` の記録でも `app.world_dict['quests'] = 12 entries`
- 状態も食い違う（雛形 incomplete / セーブ completed）＝ 雛形は遊びに追随していない
- MOD が雛形へ書いた難易度は `world_data.json` に焼かれた。
  同じ世界で新しく始めた別のキャラクタにまで乗る

GAME.md §2.9 の「`world_dict['quests']` がセーブに出るほう」「書くときは必ず両方」は
これで否定された（GAME.md §2.9.1 に訂正を書いた）。
`318_` は生きた一覧（`app.world.quests`）にだけ書く形へ直し、
雛形に焼けた3件は控えの `base` から戻した。

## 3. ゲーム自身の読み手は生きた一覧を読んでいる

これが「セーブに残らなくてよい」と決められた根拠。
同じ時刻の記録に `get_quest_difficulties(area, world) -> list(len=5) [5, 4, 3, 4, 5]`。
土地0の依頼は、雛形（`world_data.json`）には 3件（id 0 / 1 / 2）しか無い。
5件返ったということは、雛形に無い id 13 / 19 まで数に入っている
＝ この関数は生きた一覧を読んでいる。

`get_quest_difficulties` は店の品揃え・値付け・敵の強さの源（[§2.65](2.65.md) / GAME.md §2.13.1.1）。
つまり `318_` が書いている側を、ゲーム自身の読み手がそのまま読む。
セーブに残らなくても遊びは成り立つ。

そのうえで `318_` は `World.__init__` でロードの1回に世界じゅうを寄せ直す形にした。
掲示板を開いた土地だけ直していると、
掲示板を通らない読み手（店がその筆頭）が素の値を見る。

## 残った問い

生きた一覧へ書いた難易度は `savedata.json` には出ていない（依頼 21 は画面で 20、セーブで 3）。
セーブが依頼をどこから組んでいるかは未特定。
`318_` は残らない前提で作ったので遊びは成り立つが、
「MOD が書いた値がセーブに残るのはどの経路か」は他の MOD にも効く問いとして残る。
入口は `scripts.save_codec:write_obfuscated_json_file(file_path, data)` の1点
（両ファイルともここを通る）。
