# 3.9 アイテム説明の横幅（`109_`）: 決着

縦・横とも実機で確認済み（324 → 405。§2.39）。
短い説明の回が同じログに `box=324x486 (design 324x486)` で並ぶので、
「長い文だけ伸びる」も成立している。
以後は `item_detail_autosize.log` に `(design ...)` と食い違う行が出るかを時々見るだけ。

**折り返しの計測をオフスクリーンへ移した**

初版は表示中のラベルに `text_size = (幅, None)` を書いて `texture_update()` を呼び、
`texture_size[1]` を読んでいた。困りごとが2つあった。

- 測るだけでテクスチャが焼き直される。幅の候補を試すループは
  `WIDEN_STEP=1.25` / `WIDEST=3.0` で最大5周まわるので、
  初回のホバーで**ラベル3枚 × 最大6ラウンド ＝ 18回**焼くことになる
  （2回目以降は `measured` の控えが効いて0回）
- 測り終えた時点で `text_size` が測定用の `(幅, None)` のまま残る。
  確定値は `resize` が入れ直すが、その前に `capture()` が走ると
  測定用の値を設計値として控える

`118_batch_message_render` が §2.34 の事件の後に確立していた
`kivy.core.text.Label`（画面に出ない複製）で焼く手へ寄せた（`_probe_height`）。
計測の種類は同じで、表示中のラベルには触らない。
寄せなかった理由の記載はどこにも無く、単に `109_` のほうが先だっただけ。

検査は `tools/tests/test_item_detail_autosize.py` の
`measuring does not re-bake the on-screen labels`（偽ラベルの焼き直し回数が
0 のままであること）。
