# 3.121 店で値切った額が、値段の MOD を入れると効かない（ローダの値段の関所）: 原因を実機で確かめ、関所で固定するように直した。買う・売る・店を出る・読み直し・起動し直し・宿屋・鍛冶屋・盗品買取商は実機で成立。売ってすぐ買い戻すとゲームの額で買えた抜けと、品を作る入口の包みが効いていなかったのも直した

2026-11-02 に作った。
値段の MOD を入れると、NPC との会話で値切った額が反映されない、という指摘があった。

## 測ったこと（11-02、テストワールドの港湾区の雑貨屋。`245_probe_shop_negotiation`）

売買の窓の入力欄で値切ると、ゲームの `ShoppingNegotiateManager.execute` が LLM の `shopping_negotiator` を呼ぶ。
値切りなら `player_attempt` は `bargaining`（`trade_direction` / `target_item` / `decision` / `new_offer`）で返る。

| 分かったこと | 根拠 |
| --- | --- |
| ゲームは `new_offer` を品の `attributes` へ直に書く。店主の逆提示（`decision='counter'`）でも書く | `execute` の前後で、店の品の `買価` が 10000 → 9000 |
| 買う側は店の品の `買価`、売る側は手持ちの品の `売価` に書く | 短剣の `買価`・革鎧の `売価`（734 → 700） |
| 書くのは `execute` の中で、同じ処理の中で保存も走る | 値段の MOD を入れた回の `out\item_price.log` に、`execute` と同じ時刻の `save/strip 買価 '錆びた短剣' 9000 -> 10000` |
| 未検品の品を売ろうとすると、ゲームは先に検品し（`inspect_item`）、`app.inspected_item_ids` に足す | 検品の後の頼みで値段が返る |
| 素の状態では、値切った額は窓を閉じても・店を出ても・読み直しても残る（セーブに入る） | 店主の持ち物の `item_317` が 9000 のまま |
| 店の窓を開き直しても、ゲームは値切った額を付け直さない | 同上 |
| 売買の額は値切った額どおり | 素の状態で -9000（買う）・+700（売る） |
| 売買で持ち主が変わると、ゲームが額を付け直す | 店へ移った革鎧は `買価` 3849、手持ちへ移った短剣は `売価` 703 |

## 原因

値段の MOD（`129_` / `336_` / `338_` / `341_` / `405_`）のどれかが入っていると、ローダの値段の関所（`prices`）が品の額を受け持つ。
関所は、品が画面に出たときと保存の前後に、式と段から額を組み直す。
式（`129_`）があれば式の額、段だけなら初めて見たときに控えたゲームの額が元になる。
ゲームが関所の地点を通らずに書いた額は元にならないので、値切りの中の保存でその場で戻っていた。
確認の表示も引かれた額も、値切る前の 10000 だった。

## 直したこと（ローダの `prices.py`。TECH.md §5.9）

- `ShoppingNegotiateManager.execute` を関所が包み、前に額を控える（売買の窓の相手・主人公・台帳の品）。中でゲームが書き換えた額は、その品の固定の額にする。関所が自分で組み直した額は固定しない
- 固定した鍵には式も段も掛けず、保存の前後も外さない
- 品の額が固定から動いたら外す（売買で鍵が替わった・ゲームが付け直した）
- 固定は `state\prices\<世界×主人公>.json` に持ち、世界を組み立てる前に読む。売買の窓を開いたとき、相手がもう持っていない品の分を捨てる

試しの道具 `tools\drive\sell.py` / `buy.py` は、2x2 の品を左下のマスの真ん中で掴むと動かなかった（店主の所持金とは関係しない）。
真ん中を掴むように直し、2x2 の革鎧を買う・売るの両方で確かめた。

## 売ってすぐ買い戻すとゲームの額で買えた（値切りとは別の抜け。直した）

売買の窓で売った品をすぐに買い戻すと、ゲームの額で買える。
値段の地点を通らない `buy_item` / `sell_item` の中で、ゲームが新しい持ち主の鍵の額を付けるため。
片手剣は関所の額 9333 で売れ、同じ窓で 4667 で買い戻せた（11-03。1回で +4666）。
手持ちに戻った品は、次に窓を開くと関所の額（9333）へ戻る。そのため、開き直すたびに繰り返せる。
逆に、買った直後に同じ窓で売ると、ゲームの額で売れる（革鎧は 666。関所の額は 3670）。

直し方: 関所が `InstantaleApp.buy_item` / `sell_item` も包み、`orig` の後で動いた品を組み直す（ゲームが付けた新しい鍵の額を軸として控え、式と段を掛ける。TECH.md §5.9）。
直した後（11-03）は、片手剣を 9333 で売ると店の買価はゲームの 4455 ではなく関所の 23333、買い戻した剣の売価はゲームの 769 ではなく 9333 になった。

## 盗品買取商で値切れるようにした（`336_` 版5）

他の店と同じく値切れる仕様にした。
窓を開いたら、ゲームの店と同じく入力欄の行き先を `ShoppingNegotiateManager` に差し替え、閉じたら開く前の行き先へ戻す（GAME.md §2.13.1.4）。

閉じたときの後始末は `InstantaleApp.on_close_window` の包みに置いていたが、HUD は作られたときの `on_close_window` を握っている。
そのため注入より前に作られた HUD では、窓の外を押して閉じても包みを通らなかった（版4から。選択肢の組み直しの合図で、次に何か押したときに片付いていた）。
HUD がその場で引く `InstanTaleHUD.turnoff_window_visibility` も包み、次のフレームで同じ後始末をするようにした。

| 項目（11-03、テストワールド。同じ見立ての施設、主は文字列の "98"） | 結果 |
| --- | --- |
| 窓を開く | 入力欄の行き先が `FreeInputStart` → `ShoppingNegotiateManager` |
| 値切る（盗品の強化鉄材。7割で 546） | 主の LLM に渡った額は 546（参考買取価格）。主は 450 と逆提示し、450 が固定された |
| 売る | 確認の表示も増えた額も 450（`fence: sold '強化鉄材' (450)`） |
| 窓の外を押して閉じる | 入力欄が `FreeInputStart` に戻り、`fence: closed; cleared 1 item(s)`、選択肢が事務所のもの（盗品が無いので「出る」「会話する」）に戻った |

見立ての施設の主を数の 98 で入れた回は、値切りの中でゲームが `KeyError: 98` でスレッドごと落ちた。本物の施設の主は文字列の id なので、試しの手順の誤り。

ゲーム抜きの検査は `tools/tests/test_prices.py` の「値切りで決まった額」（式と一時の段、段だけ、関所が組み直した額は固定しない、同じ額の逆提示、売買と付け直しで外れる、店から消えた品の片付け、周回の控えと読み直し、別の周回）と「売買で持ち主が替わった品」（売った品・買った品をその場で組み直す、式の無い品、値切った売価は売ったら外れる）。

## 品を作る入口の包みが一度も効いていなかった（関所・`134_` 版5・`409_` 版3。直した）

関所は品を作る3つの入口を包み、`orig` の戻りを品として組み直していた。
戻りは品ではなく（GAME.md §2.13.1.5）、`generate_item_from_item_data` は `(Item, 鍵)`、`generate_item_from_dict` は None だった（11-03、テストワールドで入口を直に呼んだ）。
`item_price.log` に `generated` の行は1つも無く、同じ形で包んでいた `134_`（`item_effects.log` の作り直し 547 回はすべて画面に出た時点）と `409_`（`crafted_item_type.log` は `window/*` だけ）も、作った時点では何もしていなかった。

| 入口 | 直す前に何が遅れていたか |
| --- | --- |
| `generate_item_from_item_data` | 関所: 影響なし（作った時点では主人公へ作っても店の主へ作っても `買価` / `売価` が無く、関所は在る鍵しか書かない）。`134_` / `409_`: 効果と種別の書き換えが、品が画面に出るまで遅れた |
| `generate_item_from_dict`（読み込みで組み直す品など） | 関所: セーブの額のまま、画面に出るか店が付け直すまで残った。`134_` / `409_`: 上と同じ |

直し方: ローダの `items.made_item` が入口の名前と引数から品を取り出す（tuple なら品の要素、None なら渡した鍵で持ち主の持ち物から引く。TECH.md §5.7）。
関所・`134_`・`409_` の生成の包みはこれを通す。
`312_`（版9）・`407_`（版5）の「品が持ち物に入らなかったら戻りを自分で入れる」逃げ道も、tuple のまま入れないように同じ関数を通した（今のゲームは必ず持ち物へ入れるので、この道は通らない）。
`243_` は版3で `Item.__init__` から品を拾う形に直っていた。

| 項目（11-03、テストワールド） | 結果 |
| --- | --- |
| 起動し直して世界を読み込む | `item_price.log` に `generated/dict` が7行（主人公の装備の売価。セーブの 4200 → 式の 11200 など）。直す前は画面に出るまでセーブの額のままだった |
| `generate_item_from_item_data` で consumable の食べ物を主人公へ作る（作った品は抜いて戻した） | 作った直後に `healing_item` になり、`スタミナ回復` 10 が付いた。`crafted_item_type.log` と `item_effects.log` に `generated` の行 |
| 起動し直した後の `modloader.log` | 例外なし |

ゲーム抜きの検査は `tools/tests/test_prices.py` の「品を作る入口の戻り」（tuple の戻り、None の戻りを鍵で引く、キーワードで来た引数）。
