# 3.89 会話による好感度の変動（`337_`）: 10項目とも実機で成立

開発中は `912_conversation_affinity` の名前で動かした。遊び方と設定は `337_` の DOC.md、
実機の経緯は VERIFICATION_LOG.md §2.91、好感度の動き方（ゲーム側の事実）は GAME.md §2.25.1。
記録は `out\conversation_affinity.log`。

## 決めた仕様（再検討しない）

- 判定は LLM を別に呼ばず、ゲームの会話の要約の頼みに相乗りさせる。
  別に呼ぶ形は、ゲームが要約を待つ間は会話を閉じきらない（GAME.md §2.5）ため、会話を閉じる待ちが判定のぶん延びた。
  ローカルの LLM は `127_` で1本ずつ順に受けているので、裏へ回しても次の行動が判定の後ろに並ぶ。並列に戻すことはしない
- 動いても本文には何も出さない（「〜は少し心を開いたようだ」のようなナレーションは要らない）。動きはログにだけ残す
- 上がる1段 +2・下がる1段 -4。会話だけで上げられるのは 60（「仲間だと感じている」）まで。依頼のクリア1回の +20 より十分小さく
- 上がるのは同じ相手から1日1回。下がる方は回数を制限しない（怒らせ続ければ嫌われるのが自然）
- 他の MOD が相手ごとに上限を狭められる（ローダの窓口 `talk_affinity`、TECH.md §3.3.8）。好感度を関係の進み具合に使う MOD が、
  会話だけで関係が進みすぎないようにするため。この MOD は特定の MOD を知らず、窓口に聞くだけ
- 判定する会話は「何か言った」か「開け閉め（話しかける・会話を終了する・取引を終了する）以外の行動がある」もの。
  開け閉めの3つは、実際の要約の記録の user の行に出たものから選んだ（72・64・10件）。
  ゲームが入れる売り買い（「〜を購入した。」）と仲間との別れも判定に入る
- `404_party_talk` で同席した仲間は判定しない。広げるには要約とは別に LLM を呼ぶことになり、上の待ちの延びがまた出る

## 分かったこと（作りに効いた順）

- 要約の頼みの返却型は `Result{summary: str}` の1項目。本文は system 2件（スキーマ文と GM の指示）と会話の全文で、
  GM の指示に相手の人物像・「プレイヤーに対する感情」・ライフログが載っている。判定の材料は足さなくてよい
- 要約は `llm_manager:send_request(manager_name, message, structure, ...)` を、要約の関数と同じスレッドで通る（ローカルでも同じ別名）。
  スキーマ文は `send_request` の中で型から作られる（入口では4件、記録では5件）。
  型を「元の型＋`affinity_change: int`＋`affinity_reason: str`」の子の型（`create_model(__base__=元の型)`）に差し替えれば、
  足した項目がスキーマ文と grammar の両方に出る。summary が先なので、要約を書いてから判定する順になる
- 判定の決まりは先頭の system に書き足す（system を先頭にしか置けないチャットテンプレートがあるので、末尾に足さない）
- 返ってきたら2項目を抜き、来た形（モデル・辞書・JSON 文字列）のまま元の型に戻して返す。要約の記録・人生ログ・セーブに判定は残らない
- 足した形で失敗したら元の頼みで送り直す（要約を落とさない。その回は判定なし）
- 好感度を書くのは要約の関数が返った直後。ゲームは同じ `resolve_conversation` の中で、その後に感情の文を作り直すので、
  その会話の終わりに新しい値の文が出る
- 会話を閉じる処理は判定込みで全体 1.8 秒（ローカル）

## 確認項目と手順

| # | 確かめること | 手順 | 合格 |
|---|---|---|---|
| 1 | 判定が走る | 誰かと何往復か話して閉じる | `conversation_affinity.log` に `judge:` の行。`237_` の `conversation_end` に `change` |
| 2 | 判定の具合 | 好意的な話・用件だけの話・失礼な話・おだてるだけの話を1回ずつ | 段が正・0・負。おだてるだけで上がらない |
| 3 | 感情の文がその会話で作り直される | 段の境目を越える会話をする | 会話の終わりに `237_` の `emotion` の行が新しい値で出る |
| 4 | 1日1回 | 上がった相手ともう一度話し、宿泊の後にまた話す | 2回目は `daily`、宿泊の後はまた上がる |
| 5 | 足した型がそのまま通る | 1回話して閉じる | 要約の記録のスキーマ文に `affinity_change`、`response` に要約と2項目。ログに `retry` が無い |
| 6 | セーブに残る | 上がった後に読み直して話す | `judge:` の `before` が上がった値から始まる |
| 7 | 要約と会話の記憶に混ざらない | 5 の後のセーブ | その相手の要約・人生ログに判定の語も理由も無い |
| 8 | 会話を閉じる待ちが延びない | 会話を閉じてから操作が戻るまで | 素のゲームと体感で変わらない |
| 9 | 窓口で狭めた上限で止まる | 上限を狭める MOD と一緒に入れ、その相手と好意的な話を日をまたいで何度か | `judge:` の行末に `[ceiling … by <MOD>]`、その値で `ceiling` |
| 10 | 行動だけの会話も判定する | 店の主人に話しかけ、言葉を交わさず品を1つ買って閉じる | `skip:` ではなく `judge:`、段はほぼ 0 |
