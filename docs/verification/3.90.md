# 3.90 会話の外で送った文を本文に残す（`141_`）: 自由行動・戦闘・会話は実機で成立・裁判と値切りは未確認

遊び方は `141_` の DOC.md。記録は `out\free_input_echo.log`。

## 決めた仕様（再検討しない）

- 形は送った文そのままの1行で、名前も印も付けない。会話の発言と同じ「主人公名: 文」にすると、行動が発言に見える（実機で出して見た）。頭に「＞ 」を付ける形も実機で出したが、要らないとした。足す先は本文の待ち行列（`ui.Screen.say`）で、ゲームの処理より先に足す
- 足すのは入力欄の送信（`on_text_input`）の中で `process_choice` が来たときだけ。文は `process_choice` に渡った文字列を使う。ボタンの押下には足さない
- 送り先が `ConversationPhaseManager` / `ConversationInQuestPhase` のときは足さない（ゲームが出す）

## 分かったこと

- 会話の外の自由行動は、入力文を本文に出さない。122 の記録では、自由行動の前に入力文の行が無く、GM の語りから始まっていた（10-04 の盗みなど）
- 入力欄の送信は `on_text_input` の中で `process_choice` を同期で呼ぶ。自由行動は `FreeInputStart`、戦闘は `BattlePhaseManager` に流れた
- 戦闘の入力文もゲームは本文に出さない（141 が足した1行だけが出た）

## 確かめたこと（2026-10-08、ペルディションの闘技場）

- 自由行動: `FreeInputStart: echoed`。本文に入力文の行（このときは「主人公名: 文」の形）が GM の語りの前に出た（写真でも見えた）。122 の記録にも同じ行が入った。「＞ 文」の形でも、同じ場面で語りの前に出て、写真で見えた。印を外した今の形は実機で出していない
- 会話: `ConversationPhaseManager: the game shows it`。本文の発言の行は1つだけ
- 戦闘（試合）: `BattlePhaseManager: echoed`。入力文の行は1つだけで、続けて審判の語りとダメージの行が出た
- 確かめていないもの: 裁判の釈明（`TrialPhaseManager`）、店の値切り（`ShoppingNegotiateManager`）、依頼の中の自由入力と会話（`ConversationInQuestPhase` がゲーム自身で出すかも測っていない）
