# 2.71 構え・自由入力の防御・AttributeEffect が実機で決着（`319_` 版3〜5）

クエスト戦闘3つ（ボスを含む）。
生ログは `out\battle_tactics.log`。`unmatched` 0件のまま。

## 1. 構えの二段（版3の修正）が機能

ボタン押下の回:

    guard button pressed → guard begins → guard armed（構えた手が閉じた）
    → 被弾 fraction 0.030 final 45  guard mults=(1.00,0.55)
    → guard ended: <主人公> acted（次の自分の手で消費）

版2の「立てた手自身に食われる」は消えた。
0.55 は 構えの0.5 × 耐久低下の1.1 ＝ 倍率の合成も式どおり。

## 2. 同じ一斉攻撃での対照実験になった（自由入力の防御）

「防御」を自由入力で打った直後、ボスの very_strong が2人へ同時に来た:

| 受け手 | 構え | final |
| --- | --- | --- |
| 主人公 | あり (×0.5) | 102 / 87 |
| 仲間 | なし | 224 / 191 |
| 主人公（構えが切れた後の同じ技） | なし | 175 |

ちょうど半分。構えが切れた後の被弾（175）が非構えの水準へ戻ることまで一致。

## 3. `AttributeEffect` を初観測。復元も機能

審判が「耐久低下」（reduction / con / weak）を出し、
`in_mult 1.1` の帳簿になって直後の被弾に乗った
（weak×1.2 の被弾が `mults=(1.00,1.10)` で final 53。素の構図なら45前後）。
スキーマにあるのに一度も出なかった `AttributeEffect` が、
戦闘が複数手になったことで実戦に現れた。

## 4. その他

- 継続ダメージは敵側にも乗る（拘束系の状態異常が敵を毎巡8点）。
  「困惑」は2人同時（主人公27点・仲間15点＝各自の max_hp 比）
- ボタンと自由入力の防御が重なった回は `guard refreshed` で二重にならない
- 版5を注入した瞬間、版4の古い「防御」ボタンを
  `dropped 1 stale button(s)` が掃除した（印なし残骸の始末が機能）
- multiplier の新値 1.2 / 0.83。表の通り数が貯まりつつある

まだ無い。この回の押下は版5の注入前）と、一撃の解禁域（レベル差20以上）。
