# 3.20 打ち切った本文の後始末（`118_`）: クラッシュの原因と対処

戦闘直後に `IndexError: pop from empty list`（`add_text_display` の終端が1回多く走った）。

何が起きていたか:

1. 打ち出し中の `on_touch_down` で打ち切りが走る。
   `touch.button` を見ていなかったので**ホイールを回しただけでも走っていた**
2. 打ち切りは残りの鎖をその場で回し、飛んでくる予約を捨てる印（`dropped`）を置く
3. 終端はその場で次の本文を始める。
   印が1枠しか無かったので、回している最中に始まった次の本文が印を消した
4. 印を失った残りがゲームへ渡り、終端をもう一度踏んで空の行列を pop した

> `safe=True` は効かない。
> 例外を出したのはフックではなくゲーム自身で、`patch.py` の保護は素の関数を呼び直すだけ。

直した点: `dropped` を1枠から一覧へ / 終端を踏んだかを自分の帳簿（`starts`）で見る
（ゲームの `is_adding_text` は次の本文ですぐ True へ戻るので見分けられない）/
打ち切りの最後に帳簿を畳むのはそれがまだ自分の本文のときだけ / ホイールを弾く。

`tools/tests/test_batch_message_render.py` の偽ゲームを2点だけ実機に寄せてある
（**空の行列を pop したら例外**・**終端はその場で次の本文を始める**）。
修正前のコードを置くと実機と同じ場所で落ちる。

まだ手を出していないもの: 打ち切りのログが一度きりで後から見えないこと。
`patch.py` の `safe=True` が `orig` 自身の例外で素の関数をもう一度呼ぶことは、
後に実害（16回走行）が出て直した（§3.46）。
