# 2.33 HUD への置き場所を「先頭の子」で選んでいた（コードで確定）

`113_` / `116_` はどちらも HUD 直下ではなく、その中の `FloatLayout` へボタンを足す
（HUD の子を増やすとアイテムの移動・装備が壊れる。[§2.26](2.26.md)）。
その `FloatLayout` を `children` の**先頭**から探していた。
Kivy の `children` は新しい順なので、HUD 直下に何かが載っている瞬間はそちらを掴む。
除外していたのは自分のボタンだけで、2本目（`116_`）が入った時点で相互に掴み合える状態だった。

規則を `ui.overlay_host` へ移し（同じ発見を2箇所に書かない。TECH.md §6.1）、2点を変えた。

1. `children` の**最後尾**から探す（ゲームの `FloatLayout` はいちばん古い子）
2. 除外を `_instantale_` で始まる属性を持つウィジェット全部へ広げる（どの MOD が足したものも）

1 だけでは、ゲームが後に作る子が居るビルドで再発する。
2 だけでは、ゲームの一時的な窓（印を持たない）を掴む穴が残る。
先頭走査に戻すと両方の検査が落ちることを確認済み。

同じ点検で `107_` の `hasattr` を `frames.attr(...) is not frames.MISSING` へ置き換えた
（TECH.md §6.3）。
同梱 MOD の `hasattr` はこれで 0 件。
