# 3.66 置換ルールの編集画面（`111_`）: オフラインで成立・残るは実機の往復

外部プロキシ（`InstantaleLLMProxy`）の管理 GUI の「置換ルール」タブを `tool.py` として移植した。
判定は写さず、本体（`llm_prompt_replace.py`）の `parse_rules` → `group_rules` → `decide` → `apply_chosen` を呼ぶ。

オフラインで見たもの:

| 確かめたこと | やり方 | 結果 |
| --- | --- | --- |
| 読んで書き戻して1行も変わらない | `tools/tests/test_llm_prompt_replace_tool.py` | 同梱の既定と、取りこぼしやすい形（連続する `#memo:`・タブ行の直前の `#memo:`・先頭の説明・空行・書式を誤った行）の両方で成立 |
| 往復でゲームが見るルールが変わらない | 同上（本体の `parse_rules` の結果で突き合わせ） | 成立 |
| 入力の検査 | 同上（置換前が空・確率の範囲・`=>` の混入・不正な正規表現・`regex:` 始まり・タブ名の重複） | 6項目とも断る |
| 読む先の優先順 | `tools/tests/test_llm_prompt_replace.py`（指定 → `state\` → 旧い置き場 → 同梱の既定） | 実経路（偽クライアント）でも切り替わる。指定しない限り外は見ない |
| 書き先は `state\`（指定が在ればそこ） | `tools/tests/test_llm_prompt_replace_tool.py`（置き場を差し替えて保存） | 同梱の既定も旧い置き場のファイルも変わらない。BOM 付きの CRLF のまま |
| 置換テストが本体と同じ判定 | 同上（当たる・当たらない・止めてあるタブ・正規表現の後方参照） | 成立 |
| 窓が出るか | `python tools/check_tool_screens.py --only 111` | `python` と `pythonw` の両方で出た（1256x899） |

残っているのは実機の往復:

- ゲームを起動したまま保存して、**次の応答から**効くか（本体はリクエストのたびに更新時刻と大きさで読み直す）
- 手元のルールがまだ無い状態からの最初の保存（同梱の既定が `state\llm_prompt_replace\` へ写る）
- 旧い置き場（MOD のフォルダ）のルールを読んでいる状態からの保存（`state\` へ移り、次の応答からそちらが効く）
- 設定「ルールファイルの置き場」で別名・別フォルダ・外部プロキシのファイルを指したとき
- タブを並び替えて保存したあと、ファイルのタブの順がそのとおりか

目で見るものが3つある。
`out\tool_screens\` に撮ったもの、「すべて」タブの検索の絞り込み、右クリックのメニュー
（機械は窓が出たことしか見ない。[§3.58](3.58.md) と同じ理由）。
画面は一覧を主役にして、置換テストは畳み、置き場と記録の設定は「設定…」の小窓に置いた
（最初の版は案内を7行常設していて、一覧が4行しか見えなかった）。

窓を開いて操作を通す検査（一時フォルダへ置き場を差し替え、行の選択・欄の入力・有効と正規表現の入切・
ルールとタブの出し入れ・キー操作・「すべて」タブ・置換テスト・仕切り・設定の小窓・保存・再読込・閉じる）で
108 項目を見て、次の3件を直した。

| 何が起きていたか | 原因 | 直し |
| --- | --- | --- |
| 欄にフォーカスを置いたまま別の行を押すと、前の行の中身が次の行へ書き込まれる | 書き戻す先を一覧のいまの選択から引いていた。欄の `<FocusOut>` が届く時点で選択はもう次の行で、欄の載せ替え（`<<TreeviewSelect>>`）は後から届く | 欄に載せたルールを控え、書き戻す先をその控えにした |
| 設定の小窓を開いてすぐの Enter / Esc が効かない | 小窓がフォーカスを取っておらず、キーが元の窓へ届く | 開いた時点で指定の欄へフォーカスを入れる |
| タブを組み直した後に別のタブへ移ると、欄が使えない姿で開く | 組み直したタブは行の選択を持たない | 移った先で行が選ばれていなければ先頭を選ぶ |

1件目は配布した版に入っていた（保存すると次の行の置換前・置換後・メモが前の行と同じになる）。
