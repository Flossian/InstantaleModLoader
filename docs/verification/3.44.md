# 3.44 別の世界の NPC を連れてくる（`323_`）: 実機で成立・残るは `403_` の社会関係だけ

実機7回の記録と、踏んだ不具合3つの直しは VERIFICATION_LOG.md §2.81。
ここには、まだ実機で見ていないものと、確認の項目に挙げない理由だけを置く。

## 済んでいること

- 1体あたりの zip の大きさは実測した（5本）。
  1本 2.09〜2.41MB（画像6〜7枚ぶん）、5本で 11.32MB。
  100体書き出しても `state\` は 250MB 前後

## 残っていること（実機は1点だけ）

1. `403_` の社会関係。
   相手の記録を書くのはこの MOD の責任で、相手の id を置き先の世界のものへ付け替え、
   居ない相手は落とす（`relink_social`）。
   書式を外すと `403_` は黙って無視するので、そこは検査で押さえる。
   読んで会話に載せるのは `403_` の担当で、この MOD が新しい経路を作ってはいない。
   見るのは「書いたものを `403_` 自身のコードで引けるか」までで、
   `normalize_bucket` を通し、`relation_record` と同じ引き方で新しい id から
   引けることをゲーム抜きで確かめてある（検査6項目）。
   実機で遊んでいるうちに `403_` の控えができたら、そのとき1回持ち込めば裏は取れる。
   リリースを止める理由にはしない

## 確認の項目に挙げないもの

- 改名は `120_` の管轄。
  `120_` は `World.generate_character` を包んで、似た名前（表記ゆれ・修飾語付き・
  姓名の片方一致）なら改名する。
  こちらが見送るのは完全一致だけなので、修飾語の付いた名前は通る
  （実データ5世界で、完全一致ではないが `120_` が同一視する組は 384組）。
  `120_` から見れば出どころは関係なく、名前を見て判断するだけで、
  この MOD が新しい経路を作っているわけではない。
  この MOD の担当は改名されたことに気づいて知らせるところだけで、
  そこはゲーム抜きの検査4項目で見ている。
  実機の5体は改名されなかった（§2.81）
