# 3.2 会話からの依頼受注（`301_`）: 実機確認（4段階）

1〜3 は先に通った（§2.13）。
4 は後から第一声の経路で通った（§2.62）。
以下は回帰を見るときの手順として残す。

先に `python tools/tests/test_quest_offer.py` を通しておくこと。
実機で見るのは「オフラインでは確かめられないもの」だけ。

1. **設置** … NPC と会話し「会話を終了する」の手前に「依頼を受ける」が並ぶ
2. **既存依頼の受注** … 一覧に `【難易度】タイトル` が並び、選ぶとゲーム本来の受注画面へ。
   `WARN difficulty mismatch` が出たら絞り込みの前提（`neighboring_settlement_id`）が崩れている
3. **会話からの生成** … 少し会話してから押すと先頭に「この話から依頼を作る」が出る。
   LLM が1回走り（30〜60秒）、生成された依頼が会話で頼まれた内容になっているかを目で見る
4. **片付いた依頼の通知** … その NPC から受けた依頼をクリアしてから、同じ相手ともう一度話す。
   `quest_offer.log` に
   `facilitator: '<名前>' (<id>) +N chars into profile` が出て、
   会話で「まだ出発していないのか」が出なくなる
5. **仲間は依頼人にしない** … NPC を雇ってから、その相手に話しかける。
   「依頼を受ける」も「この話から依頼を作る」も出ないこと。
   `quest_offer.log` に `no offer: party member ...` が出る。
   パーティから外してもう一度話しかけると、今までどおり出る

画面の塗り替えは `quest_offer.log` の `quest board:` 行で見る。
`via (nothing)` や `hud not found` なら HUD の構成が変わった合図。

未実測のまま残っているのは2点。
**選択肢のページ送り**（実測できたのは1ページに収まる場合だけで、
`display_button_map` が恒等写像だったため「表示位置」と「buttons の添字」を区別できていない。
TECH.md §8）と、**`generate_random_quest()` を掲示板の外から呼んだときの副作用**。

## 3.2.1 `test_quest_offer.py` の赤1件は、製品ではなくテストハーネスの人工物（決着）

`FAIL 閉じた後で掲示板が開く`。
実機で2回計測して切り分けた。
`end conversation` から `open board:` までは 0.6 秒で、
`IDLE_TIMEOUT`（30秒）には実機で一度も到達していない。
疑っていた「自分の立てた合図で自分を待たせている」筋を、この 0.6 秒が否定した。

赤の正体は**偽 Clock が実時間を進めないため `when_idle` が進行しない**というハーネス側の限界。
直すのはテストハーネスで、**製品側には手を入れないこと**
（以前 `ignore=` を足す案を試して、この1件が通る代わりに同じスイートの2件が落ちた。
存在しないバグを直そうとしていたため）。

改めて計測したところ、この赤は出ない。
`301_` の版2 を当てる前の HEAD で `test_quest_offer.py` を走らせて 56 件すべてが
`ok`、終了コード 0 だった。
いつどの変更で通るようになったかは追っていない。
「製品側に手を入れない」の判断はそのまま残す。

## 3.2.2 版2 で残っているもの

片付いた依頼の通知は、第一声の経路（`conversation_starter`）が
通った（§2.62）。
プロンプトへの載り方と `311_` との重なり方もそこで確かめてある。
残っているのは4つ。

- **自由入力の経路（`conversation_facilitator`）が未発火**。
  §2.62 の回は第一声で会話を閉じたので、この行が1つも出ていない。
  片付けた相手に話しかけ、**そのまま何か入力して**
  `facilitator: ... +N chars into profile` が出るのを見る。
  依頼の件を直接尋ねたときに片付いたものとして答えるかも、そこで初めて分かる
- `quest_belongs_to` の名前照合が実データで誤爆しないか。
  ゲームが元から持っている依頼の `client_name` は実在の NPC と結び付いていないので、
  同名が出れば拾う。
  §2.62 は控えのある依頼だったので、この経路は通っていない
- **仲間を依頼人から外す設定が未発火**。
  オフラインでは名簿を作って通してあるが、実機の名簿の形（`app.party` か
  `game_variables['party']` か、id か `Character` か）で読めるかは
  `302_` の実績に乗っているだけで、この mod からは確かめていない。
  NPC を雇って話しかけ、`no offer: party member ...` が出るのを見る
- 放棄や時間切れで終わった依頼が `status` の上でどう見えるか。
  census で観測できているのは `incomplete` と `completed` の2値だけなので
  （GAME.md §2.9）、放棄が `completed` に倒れるなら「果たし終えている」と言ってしまう。
  依頼を1件わざと放棄して `out\quest_flow.log` の
  `config.status census` を見れば決着する

見るのは `out\quest_offer.log` の `starter:` / `facilitator:` の行。
`311_` を入れているときは、あちらの節とこちらの節が
`profile` 欄に両方載る（§2.62 で確認済み）。
