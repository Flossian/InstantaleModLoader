# 2.82 NPC の外見・性格・経歴が同じ形に寄る。記録の検分と probe の煙試験

「LLM に生成させた NPC がほぼ同じ見た目になる（特に Gemma4）」の検分。
ゲームの `output_data\` のうち、`prompt_bloat.log` の時刻と突き合わせてローカル経路（`chat`）と確定した分だけを数えた
（log の無い古い記録は経路が分からない。ゲーム公式配布や書き換え済みの世界は除外）。

| 記録 | 件数 | NPC | モデル（`llm_speed.log`） |
|---|---|---|---|
| `master_ai_npc_generater` | 6 | 6 | Chimera-X-26B-A4B（Gemma4 系） |
| `create_settlement_detail` | 9 | 118 | Gemma4-ShadowSiren（一部は未確定） |
| `320_` の募集 | 4 | 4 | Chimera-X |

| 観測 | 値 |
|---|---|
| 髪色を書いた人物 | 15 / 124 程度（銀髪4・茶髪3・金髪3・黒髪2） |
| 瞳の色・肌・体格 | ほぼ無し |
| 役職で決まる語 | エプロン10・ローブ10・鎧9・筋肉9・眼鏡7（宿屋の主人＝皺と灰色のローブ、鍛冶師＝筋肉質でエプロン、書記官＝眼鏡とインクの染み、が町をまたいで再現） |

look_description と `image_generation_prompt` は `master_ai_npc_generater`（単体。入力は名前・概要1行・ランク）と `create_settlement_detail`（町。世界の概要1つで住民10人前後を1回で書かせる）の同じ応答の中で出る。
look_description からタグを作る別建ての呼び出しは `output_data\` の全関数に無く、後から走る `npc_detail_generater`（283件）は外見に触らない。
`111_` の「没個性を避けること」の1行は確率 100 で当たっている（`[REPLACE]` で確認）。
サンプリングは temp 1.0 / top-p 0.95 / top-k 64、seed 無し。

読み: 頼み文に人を見分ける材料が無く、モデルが役職の型で埋め、画像側も髪・目・肌の指定を欠いたまま既定の顔で埋める。
personality / description が似るのも同じ理由。

道具: `tools\npc_variety_probe.py`（頼み文の写しは `tools\npc_variety_prompts.json`、検査は `tools\tests\test_npc_variety_probe.py` 40件）。
ゲームの system 2通と型定義をそのまま使い、`111_` のルールも実機と同じに当てる。
条件は plain（実機のまま）/ fields（要素名だけ足す）/ seed（人物ごとに髪色・瞳・肌・体格・特徴・性格の軸・経歴の種を表から引いて渡す）/ mod（`132_npc_variety` の `inject` をそのまま通す）。
測るのは、髪色・瞳・肌・体格が本文に入った率、役職の型の語と「鋭い」の率、personality の書き出しの異なり、種の指定が本文に載った率、同じ役どうしの似方（文字 2-gram の Jaccard）。
Gemma4-ShadowSiren-26B-A4B、`--reasoning-budget 0`、json_schema で強制。読めない返答は煙試験（seed のみ 5回。単体 4〜8 秒、町 32 秒）と本測定を通して 0。

本測定（単体4役×10回 ＋ 町5回を条件ごとに。plain / fields / seed は 136回 15分）:

| 条件 | 人物 | 髪色 / 瞳 / 肌 / 体格 | 役職の型の語 | 「鋭い」 | 定型語 | 書き出しの異なり | `=` の写り | old / teen・child |
|---|---|---|---|---|---|---|---|---|
| plain | 101 | 18% / 3% / 3% / 9% | 59% | 17% | 45% | 79 / 101 | 0 | 10 / 11 |
| fields | 99 | 87% / 77% / 52% / 48% | 59% | 21% | 26% | 67 / 99 | | |
| seed（probe の形） | 105 | 97% / 96% / 96% / 97% | 15% | 3% | 13% | 49 / 105 | 14（見出し語 22） | 3 / 0 |
| mod 版1（16軸 108句） | 111 | 77% / 63% / 65% / 63% | 11% | 2% | 12% | 92 / 111 | 0（見出し語 0） | 16 / 20 |
| mod 版2（20軸 238句。最終） | 108 | 79% / 55% / 69% / 69% | 10% | 5% | 13% | 98 / 108 | 0（見出し語 0） | 18 / 18 |

- plain は冒頭の記録どおり。宿屋の主人 10回は全部「日焼け・皺・革のエプロン・傷跡・鋭い眼光」で髪色は 3 / 10。書記官は 0 / 10
- fields は項目は埋まるが値が同じ（宿屋の主人の髪は 10回中 8回「白髪混じり」、瞳は 10回とも「鋭い灰色」）。
  役職の型の語も「鋭い」も減らず、同じ役どうしの似方は 0.09 → 0.15 と上がる
- seed は指定の語が本文に載る（外見 96〜99%、性格 94〜97%、経歴 65〜94%。「隠し事」65% が最低）。宿屋の主人の髪は 茶3・銀2・灰1・黒1 と割れる。
  副作用が3つ: 頼み文の形が本文に写る（「髪=煤けた灰色の髪、髪型=短く刈った」）、personality の書き出しが種の語彙に寄る（「無口で」9、「聞き役に回ることが多く」9）、年齢の幅が消える（old 10 → 3、teen/child 0）。
  単体の category は名前と概要で決まる（宿屋の主人は3条件とも middle-aged man 10 / 10）
- mod は種を鍵=値でなく句点で繋いだ文にし、外見に「年齢の見え方」を足し、「見出しや「=」の形は書かない」と添えたもの。副作用3つは消えた。
  髪色などの率が seed より低いのはモデルが言い換えるため（探し方は色語＋髪の正規表現。「頭を剃り上げている」のような色の無い句は拾えない）。
  同じ役どうしの似方は 0.07〜0.10 で plain（0.09）と同じ（seed の 0.15 は種の書式が写っていたぶん。見分ける情報の有無はこの値では測れない）
- 版2は表の組み直し。髪を髪色・長さ・髪型の3軸に分け（髪の軸は隣り合わせ）、目立つ特徴を立ち絵で描ける大きさの10句に絞って軸ごとの割合 25%、性格6軸・来歴5軸で各軸 12〜16句、短い髪で髪型を省く `drops`（「この句を引いたら後ろのこの軸は付けない」）。
  108人で特徴付き 25人（23%）、短髪と束ね髪・編み髪の同居 0、category は10種すべて（middle-aged man 28・young man 18・young woman 15・middle-aged woman 11・old man 11・old woman 7・teenage boy 7・young boy 4・young girl 4・teenage girl 3）

実機（Gemma4-ShadowSiren）。1回目は世界B で隣の村へ移動して町生成を1回、2回目は新しい世界C を作って物語 NPC が1人出るまで。[§3.47](3.47.md) の6手順は全部通った。

`output_data` の記録は `chat` より上流なので、頼み文の側には種が映らない（GAME.md §2.12）。種が渡ったことは応答の中身と `[SEED]` の突き合わせで見る。

見えた副作用と直し（表の直しは検査の件数で追う）:

| 副作用 | 直し |
|---|---|
| 年齢と家族が食い違う（「まだ子どもと言ってよい年頃」の少女に「遠くに嫁いだ娘がいる」） | `drops` を節をまたいで効くようにし、子どもの年齢の句で来歴の「家族」を省く（検査 64件） |
| 年齢の軸が役職を見ない（十代のギルドマスター、子どもの役人） | 表に `not_for`（この役にはこの句を出さない）を足し、必須施設の主と単体生成には子どもを出さない。十代の店主は許容、住民と冒険者には子どもも出る（検査 73件） |
| 単体生成は概要に年齢がある（「痩せこけた中年男性」に種の「二十歳そこそこ」。モデルは「二十歳そこそこに見えるが老けて見える」と辻褄を合わせた） | `not_for` に「軸ごと省く」（`true`）を足し、単体生成には年齢の軸を付けない（検査 76件） |
| 衛兵（`guard_npc_generator`）に種が付いた。応答の `look` に `red hair, very long hair, hair slicked back, potbelly, purple eyes`。以前の記録（52 件）と違い、今の衛兵の頼み文は system に `- personality:` `- look_description:` を持つ（出力の型は `look` のまま） | 見分けを「【生成するNPC】の下に `- 名前:` と `- 概要:` がある」に変え、「衛兵NPC」「闘技場で戦う」の語があれば触らない（衛兵と闘技場の頼み文は「- 強さのランク」だけ。検査 79件）。注入し直しの後、別の村の衛兵で `[SEED]` が増えず `look` が `weathered male guard, heavy dark leather armor, …` の素の形なのを確認。種が付いた村の衛兵はその1回の種を持ったまま（非ユニークの型なので、その土地の衛兵は全員その見た目） |
| 男の人物に「夫と暮らしている」（性別は種を引く時点では決まらない。名前と概要からモデルが決める） | 「家族」の句から性別を決める語（妻・夫・娘）を外し、「連れ合い」「遠くに嫁いだ妹」に。表の全句に性別を決める語が無いことを検査に入れた（検査 80件） |

直していない: 種の句が別の項目へ落ちる（「並外れて大柄」が personality へ。読み物としては通る）。住民1人目の種が任意施設の主と residents[0] の両方に使われる（同じ見た目の2人。害は薄い）。

付随して直した: `epithet_probe.py` は config.json の `ai_setting` の下を見ておらず、サンプリングと backend が既定値に落ちていた。
実値と既定が一致していたので [§2.63](2.63.md) の結果は変わらない。
