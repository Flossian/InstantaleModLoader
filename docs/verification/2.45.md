# 2.45 `118_` 本文の出し方と打ち切り（実機で5回外した）

打ち切りは実機で5回外している。
決着したのは**書くのをやめたとき**。
`hud.display_text` は正本ではなくコピーで、書いても 0.1 秒後に作り直されていた。

外した5点: 正本を `app.display_text` から読もうとした（`frames.attr` の既定値が
文字列の `MISSING` なので `isinstance(str)` を素通りした。TECH.md §5.2）/
終端の呼び出しより先に本文を書いた / 正本へ書けば塗り直されると思っていた /
塗り直しても高さが古いまま / 正本の末尾が本文の切り出しと文字単位で一致しない
（ゲームは打ち出しの最中に改行を混ぜる）。

いまは1文字ずつの呼び出しをその場で最後まで回し、
回している間だけ塗り直しを止めて、終わってから1回だけ塗る。
書くのはゲーム自身なので、正本の在り処も打ち出し中の整形も知らなくてよい。

> 他人の状態は名前で当てて書かない。他人の経路を回す。

灰色化も同じ根（打ち出し中に混ざる改行）で外していた。
空白を除いて突き合わせ、位置だけ元へ戻す。
`markup` を除く順序も1つ外している（元の本文に戻してから除く）。

多重塗り直しは出していない（実機実測 `render x1.00/tick`、
打ち切り中は 0.22/tick ＝ 回している間の塗り直しが実際に止まっている）。
MOD 側の手間はオフライン実測で1文字あたり +0.001〜0.16ms。

一括表示（`always`）の側で外した2点:
Clock の予約の中でローダに無い `ui.hud_of` を呼び、ゲームごと落とした（`out/live_crashes.log`。Clock の中は `safe=True` の外）。
待ち行列 `to_add_text_list` から取り除くのと `is_adding_text` を下ろすのを真似て自分でやり、行列を放置した結果、次の本文が出なくなり、消えない先頭が何度も出た。
行列が 1 から 0 に減るのは `index == len(context)` の呼び出しと同時だった（`out/text_viewport.log`）ので、後始末は鎖の最後の呼び出しに任せている。
その終端の呼び出しが何も足さずに完了だけする、というのは実測3件からの推定で、外れたら一度だけ WARN を出す。

打ち切りがクラッシュを起こした件は [§3.20](3.20.md)。
