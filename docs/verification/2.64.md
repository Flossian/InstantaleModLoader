# 2.64 通貨の呼び名が実機で通った（`130_`）

`シルバー` / `Slv` に差し替えた状態で、画面上部の欄と宿の部屋選びを実機で確認。
`out\currency_unit.log` の要点:

```text
hud: '...\nGold:13184\n...' -> '...\nシルバー:13184\n...'   （書式は既定のまま）
hud: '...\nGold:13184\n...' -> '...\nSilver:13184\n...'     （書式に Silver:{amount} を入れた回）
tr:  '簡易寝台(10G)' -> '簡易寝台(10Slv)'                   （部屋4種とも1回の描画で通った）
```

分かったことが4つ。

1. 見張りは渡された `value` を塗っている。
   `hud repaint` の行が1本も出ていない（保険の経路。GAME.md §2.29）。
   `update_status_texts(self, instance, value)` は `self.status_texts` を読み直してはいない。
   保険はそのまま残してある（ビルドが変われば逆に振れる側で、
   外すと次に分かるのが「画面が変わらない」だけになる）
2. 所持金は桁区切りの無い整数で書かれている（`Gold:13184`）。
   `number()` が float と桁区切りも受けるようにしてあるが、実機で来たのは int だけ
3. 呼び名の追随と、書式を書く経路の両方が通った
4. `tr` は宿の部屋選びまで届いている。4つのボタンすべてが1回の描画で通った

## `315_` との噛み合いも同じ回で通った

`out\vacation.log` では部屋選びのボタンが `相部屋(10Slv)` で並び、
`VacationStartManager.execute` の `choice='相部屋(10Slv)'` の後に所持金が 13184 → 13174 と動いた。
`相部屋` は `315_` の `SIMPLE_NAME`。
つまり `315_` は `tr` が書き換えた後のラベル（`簡易寝台(10Slv)`）から
`ui.parse_coin` で 10 を読み、`ui.rewrite_coins` を通して組み直している。
宿代も 10 だけ動いていて、額はずれていない。
ローダへ寄せた2つ（`parse_coin` / `rewrite_coins`）が実データで噛み合った。

## LLM 側の行は出ていない（想定どおり）

`llm ...:` の行は0本（記録の上限 20件には遠く、打ち切りではない）。
ゲームが組む指示文は先に `tr` を通ってから送信の口に来るので、
そこに着く頃には `ゴールド` も `G` も残っていない。
送信側の書き換えが仕事をするのは、
表記を変える前にセーブへ貯まった文（人生ログ・会話の記憶・世界観）だけ。
その経路はまだ実機で出ていない。
