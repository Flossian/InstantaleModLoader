## 決めた仕様（再検討しない）

- 盗みは売買画面の右クリックから（2026-10-04）。施設の選択肢の「盗みを働く」（棚から無作為に1つ、同じ店は1日1回）は外した。回数の制限は無く、続けるほど下がる
- 盗みの判定の物差しは能力値そのもの（基準 15 は `313_` と同じ）。ゲームの `get_quest_appropriate_stat` は、ゲーム自身が呼ばず値も測っていない（[§2.84](2.84.md)）ので使わない
- 「裏の依頼掲示板」は公式の未実装の枠だが、裏の仕事と同じ役割なので、公式が未実装のあいだだけ乗っ取る（公式の未実装の枠は埋めない決まりの例外）。
  はじめは別のボタンで足していたが、事務所の選択肢が増えたので枠へ移した（2026-10-05）。一覧はギルドの掲示板と同じ形
- 裁判の介入の効き目は2か所で確かにする（判事の頼みへの一文と、判決のボタンの直し）。
  上限は「求刑 × 割合」で、判事の年数からは減らさない（判事が頼みの一文で既に軽くしていると二重に減るため）
- 司法取引の締め出しは牢を出てから数える（売った日から数えると、刑期は年単位なので服役の間に明けた）
- 脱獄は年をかけて備える形。行動は「脱獄を試みる」の下にまとめる。決行で倒れたらゲームオーバー（はじめはローダの窓口 `defeat` で死なせず牢へ戻していた）
- 盗んだ店には売れない。断りの文は主人公の気づきで、店主に言わせない。
  盗品の買い取りは、よその店で正規の半分、盗品買取商で7割。盗品買取商は裏の事務所に置く
- 衛兵の買収が突き返されたら、大人しく捕まるか抵抗するかを選ぶ（2026-10-06。前はそのまま連行した）。贈賄の罰を裁判へ持ち越すのは、捕まるを選んだときだけ
- 処刑場からの脱出はダンジョンで、起きるのは好感度の高い人物がいるとき。撤退は処刑
- 同房の囚人は既存の冒険者ではなく新しく作る。服役の始まりに確率で入り、会話と年ごとに親しくなり、決行に加勢し、出所後はギルドで雇える

## 分かったこと（作りに効いた順）

- 盗みの判定は、行動の締めの要約（`master_ai_process_summarizer*`）の頼みに `loot_scale` / `loot_reason` を相乗りさせ、返ってきたら2項目を抜いて元の型でゲームへ返す。要約の包みは `119_` より外側
- 判定の頼みに「売買も 0」と1行添えただけでは、品物を売った代金を盗みと判定した（2026-10-10。遊んだ人からの報告。10,000G の売却が 12G に削られた）。
  ゲームの要約の記録を元に場面だけ差し替え、ゲーム抜きでローカルの LLM（Eclipsed-Phoenix-26B）に5回ずつ投げて比べた（VERIFICATION_LOG.md [§2.88](2.88.md)）。
  直したのは3つ。理由（金を誰からどう受け取ったか）を規模より先に書かせる。1〜4 は金銭そのものを相手の意に反して取ったときだけと先に言う。売った代金は品物の出どころや入力文の言い回しを問わず 0 と、理由を添えて書く
- 「LLM が渡した額」は、行動の最初の facilitator の前の所持金と、要約の後の所持金の差。
  目安の物差しは `get_quest_reward(get_area_average_difficulty(土地))`（実測 1→7G、10→326G、30→4,234G）
- 時効の日数は `elapse_days` の前後の暦の差。`residency.last_stay_end` は、いつ書き換わるかを測っていないので使わない
- 盗んだ品の持ち主の切り替えは、購入と同じ `Item.buy` に任せ（何を書き換えるかはゲームが知っている）、払った額を主人公と店主の両方へ戻す。置き場所はゲームの `place_new_item` が決める
- 盗む確認は、ゲーム自身の売買の確認の窓を出させ、文言を差し替えて借りる。自分で作った窓は並ばず見えなかった（GAME.md §2.13.1）。「はい」はゲームの「買う」を止める
- 裏の仕事は、`random_quest_generator` の `area_description` に種類の指示を足して作る（`307_` と同じ形）。
  `328_` は街の描写を伏せた文に置き換えることがあるので、この MOD は `328_` より内側に居る。依頼の辞書には鍵を足さず、id は控えに持つ（GAME.md §2.9）
- 一覧は `apply_buttons` で塗るまでやる。`app.buttons` を差し替えて組み直しの合図を出すだけでは、画面は事務所の選択肢のままだった
- 掲示板に出さない依頼は、ローダの窓口 `board`（TECH.md §3.3.12）に置く。窓口が無いと、掲示板の依頼を片付けていく MOD に裏の仕事まで狙われた
- 報酬の倍率は、`QuestEndManager.execute` の間だけ帰還の文の額を書き換え、差を所持金に足す（`334_` の懸賞金と同じ形）
- 判事は贈賄の露見を重く見て求刑の2倍を言い渡し、この MOD の5年と二重の罰になった。判事の頼みに「贈賄の分の刑は別に加えるので、求刑を大きく超えて重くしないこと」を足して直した
- 決行はローダの窓口 `guards`（TECH.md §3.3.10）で組み、難易度を差し替える（実機で 76、備え2つで 53）
- 盗品買取商の売買の窓は、店でない施設でも開く（GAME.md §2.13.1）。実機で直したことは4つ。
  売った後に右の欄が窓の上に出た（選択肢を絞り、組み直しの合図を出す）。閉じても選択肢が戻らなかった（`set_buttons_to_normal`）。
  売った品が主の持ち物に積もった（閉じたら外す）。入ったときの話しかけの会話の上で開いた（施設の最初の画面にだけ出す）
- 同房の囚人は `npcs.make_npc` で作り、すぐゲーム自身の `generate_npc_detail` で HP・スキルを埋める（埋めないまま戦闘に出すと落ちる）。
  `make_npc` は世界の骨格（`world_data.json`）にも書くので、実機で試すときは骨格も控えて戻す
- 関係の印を「初対面」で作ると、出所後の会話で初対面の名乗りをした。「同房の囚人」で作る
- 牢の中の会話では `301_` の依頼の選択肢が出て、受ければ牢から出られた。ローダの窓口 `confinement`（TECH.md §3.3.13）で止める。会話の「行動」欄は、今のゲームでは画面に出ない
- 牢の出来事を囚人の側へ知らせるのは、自分の本文を予約した後（先に知らせると、囚人の行が「牢獄の外へ出た」より先に出た）
- ロードの途中の組み直しでは、人物（`world.characters`）がまだ 0 人。人物を見て出すボタン（盗品を売る・手引きに賭ける）はそこで出ない。ローダの「ロード後の組み直し」は走らない回があったので、人物が揃ってから 336 自身が1度組み直す。ボタンの条件にはなるべく人物を入れない
- ボタンの出し分けや効き目に効く状態（突き返された印・裁判の効き目・裁判へ持ち越す罰）は、メモリだけに持つとロードで消える。控えに持ち、払った後はゲーム自身の保存を呼ぶ（この押下ではゲームは保存しない）

コードの分け方は `crime_overhaul.py` の先頭の表、ゲーム抜きの検査が何を通すかは `tools/tests/test_crime_*.py` の docstring。

## 分かっていて直していないもの

- 脱獄の決行で、ゲームの `process_choice` が例外を投げて戦闘を起こせなかった場合、先に加勢させた同房の囚人がパーティに残る（`prison.break_out` は加勢を知らせてから戦闘を起こす）。届くのはゲームの中が壊れたときだけで、素の遊び方では通らず、実機で確かめられない。取り消すには冒険者の一覧から外すローダの部品が要る（2026-10-06 のコードレビュー）
- 脱獄の戦闘の終わりでは終わり方（`end_type`）を見ていない。`107_` を切っていて、闘技場から撤退した後の `in_colosseum_battle` が残っていると、決行で倒れた戦闘を `334_` が負けの切り上げ（逃走の終わり方）で受け止め、牢の外へ出られる。`107_` は同梱で既定 ON なので素の構成では起きない（2026-10-06 のコードレビュー）
- 時効の「まだ戻しに使っていない日数」の控えは、`elapse_days` の直後（ゲームの保存より前）に確定する。その間に落ちると、手配度は戻らないのに日数は使ったことになる（失うのは最大で1回ぶん）。落ちる瞬間に左右され、実機で確かめられない（2026-10-06 のコードレビュー）
