# 3.13 危険な道を行く（`307_`）: 実機3回で成立

実機1回目で生成から到着まで通った。
確かめられたこと: 確認画面への設置と押下 / `mode` の実値（`'on_foot'` / `'coach'`）/
道中クエストの生成（166秒。題名が2つの土地を繋ぐ道になっている ＝ 差し込みが効いている）/
難易度の抽選（エリアの水準 72 と 39 の間で 59。ゲーム自身の値は 69）/
受注・進行・完了 / `elapse_days` が日数送りそのもの / 到着で控えが外れる。

そこから直した点（1回目〜3回目）:

| 直した点 | 中身 |
| --- | --- |
| 移動が遅れて起きる | 帰還先はエリアの入口で集落の選択肢が出ないため拾えなかった。`QuestEndManager.execute` が返った直後に移動する形へ。**戦利品は完了より前**なので「漁る」を取り上げる心配は無かった（GAME.md §2.9） |
| 難易度が片方の格納先にしか書けない | 生成直後は `world.quests` にだけ在る。受注の時点でもう一度書く |
| 注入し直しで道が切れる | 控えはファイルが正本にし（更新時刻を見て読み直す）、受注・完了の検出を**合図から状態へ**移した（`app.current_quest_data` を見る） |

足した仕様が3つ。
**移動中の文言を伏せる**（`徒歩で目指す。長旅だ...` は道中を踏破した後に出ると筋が合わない。
`moving` の間だけ名指しした文言のみ。到着の合図は通す。馬車側は未実測）。
**体力が3分の1を切っていたら断る**（実体は `Character.physical_integrity`。GAME.md §2.19。
生成にも世界のデータにも触らず、確認画面は残るので選び直せる）。
**依頼概要に移動先を明記する**（紐付けが切れたらこの一文も消す。
着いた場合だけ残す。その時点では本当だったから）。

ファイルは3つに分けてある（`area_move_dungeon.py` / `journey.py` / `world.py`。TECH.md §3.1.1.1）。

## 暦が止まる経路を設計変更で消した（決着）

日数を `TRAVEL_DAYS` の**予算**で頭打ちにしていたので、
使い切ると `elapse_days` に 0 が渡り続け、
控えが外れないまま残ると**その世界の暦が止まっていた**（画面には何も出ない）。

「控えが外れない経路」を塞ぐ方向で2度直そうとして、どちらも検証不足で戻した（§2.50）。
3度目に予算という形そのものを疑ったところ前提が崩れた。
**道中のクエストは日数を進めない**（`output_data` のクエスト側 2,029 件すべてで
`elapse_days` の実行が0件。GAME.md §2.18）。
予算は存在しない費目のために作られていて、その積み上げが凍結を生んでいた。

直した形は `ダンジョン踏破（0日） → エリア移動 → 指定の日数が経過`。
切り詰めるのは段階 `moving` の**最初の1回だけ**で、`armed` 以降の控えは `elapse_days` に触れない。
渡された日数は見ず常に `TRAVEL_DAYS` を渡す（上限ではなく**かかる日数**）。
**これで控えが外れなくても暦は止まらない**ので、
寿命が効かない・`arriving` で固まる・古いセーブに控えが残る、はいずれも害が消えた（別件として放置）。

> **なぜ控えをファイルに残すのか**（実測で確定）。
> `elapse_days` は `process_choice` が返った 2ms 後に来る（`execute` が返るのは 5.7 秒後）。
> `314_` が呼び出し内の窓で足りるのは `AreaMoveManager.execute` **そのもの**を包んでいるからで、
> 自分で `process_choice` を呼ぶ `307_` には同じ形が取れない。
> **これは設計の正解であって穴ではない**（§2.50）。
