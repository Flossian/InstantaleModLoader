# 3.114 宿屋と鍛冶屋の売買と、店の種類ごとの品揃えの傾向（`340_shop_lineup`。旧 `340_inn_shop`）・窓口 `shop_lineup`: 鍛冶屋の入口と会話・鍛冶屋と診療所の傾向・312 の入れ替えの傾向は実機で成立・雑貨屋と専門店と一括生成は実機が未

2026-10-23 に作った。`340_inn_shop`（[§3.105](3.105.md)）を広げて改名した。

## 決めた仕様

| 項目 | 決めたこと |
| --- | --- |
| 「売買する」を足す店 | 宿屋と鍛冶屋。施設の画面と、主との会話の両方 |
| 傾向 | 雑貨屋は幅広く万能に、鍛冶屋は武器・防具、宿屋は料理・飲み物・酒に回復薬を少し、診療所（薬屋）は回復薬・ポーション・薬、専門店は店の名前と説明（看板）に合う品 |
| 混ざる品 | 止めない（鍛冶屋に回復薬が入ってもよい）。前の版で宿屋の棚から武器・防具・素材を外していた処理と、312 の宿屋の除外はやめた |
| 名前 | 宿屋だけの名前では目的より狭いので改名した（公開前） |
| 外した分の補い（10-24 に足した） | 武器・防具を外して棚が寂しく見えるので、初めて開いた店（主の持ち物が空から並べた回）で外したときだけ、傾向の品を 2〜6 品（ランダム）足す。価値はその段の雛形の値を順に使う。2回目からの来店では足さない（繰り返し来ても増えない） |

## 作り

- ゲームの店（雑貨屋・専門店・診療所・鍛冶屋・宿屋）で `ShoppingStartManagerRemake.execute` が走る間だけ、プロンプトの「武器と防具を必ず作る」の1文（初回と、売買のたびに足す品の2つ）を `LINEUPS` の文へ替える。雑貨屋の2つ目はゲームの文のまま
- 世界の一括生成の店の仕事（`scripts.world_bulk_backend:GameGenerationBackend.generate`）でも同じ差し替えを掛ける。仕事の `ids` は `(エリア, ノード, 施設, 段)` で（`241_` の記録）、世界の辞書から施設の種類を引く
- 傾向の一文はローダの窓口 `shop_lineup`（TECH.md §3.3.22）に出し、`312_shop_restock` が入れ替えの頼みに入れる。誰も出さなければ 312 は今までどおり「武器と防具をそれぞれ1つ以上含める」
- 鍛冶屋の画面の目印は `EquipmentReinforcementStart`（装備の強化）。会話では、ゲームが鍛冶屋の主に足す「装備の強化を」の前に入れる

検査は `tools\tests\test_shop_lineup.py`（94項目）と `test_shop_restock.py` の傾向と並べない種類の9項目。

## 分かったこと

- テストワールドの店は、主の持ち物が空でも、雑貨屋・専門店・診療所の全部が品揃えの雛形（`goods` 5〜14品）を持っていた。鍛冶屋と宿屋は雛形が無い。雛形がある店は売買を開いても LLM を呼ばず、雛形から作り直す（GAME.md §2.13.1.3）ので、差し替えが掛かるのは雛形の無い店・一括生成・312 の入れ替えだけ
- 雛形の有無は施設の `config.level_of_detail` でも見ている。試しで `goods` だけ消して詳細度 3 を残すと、ゲームの `set_item_from_world_data` が `KeyError: 'goods'` で落ちた（素のゲームでは起きない形。詳細度を 0 に戻すと LLM で作った）
- 差し替えたプロンプトには店の名前が載っている（`shop name in prompt: yes`。鍛冶屋・診療所とも）。専門店の傾向が頼る看板は LLM に届いている
