# 3.109 選択肢のボタンを組み直しのたびに作り直す宣言型の口（窓口 `choices`）: 段階1〜4（同梱の MOD で古い口と自前の包みが無くなった）と `120_` 版9。実機は段階1で9項目・段階2で4項目・段階3で8項目、残りの確認で12項目成立。`920_` の2件・`301_`・`106_` の不具合を見つけて直した。残るのは `326_`・`902_` の実機

2026-10-21。
窓口 `choices` を作った後も（[§3.85](3.85.md)）、ボタンの不具合は MOD を問わず続いた。
きっかけは `339_` の刺客の会話（[§3.98](3.98.md)）。
自前の「受けて立つ」が、会話の途中で保存して読み直すと印が付け直されず、押すとゲームの `JustSetButtonToNormalPhase` が走って会話が半端に抜けた（`in_conversation` が残ったまま宿の選択肢）。
`301_` が後から「依頼を受ける（話を切り上げる）」を足し、戦わずに抜けられた。

## 分かったこと

git log と VERIFICATION を洗い、ボタンの不具合 35 件を分けた。

| 種類 | 件数 |
| --- | --- |
| 時機（ロードの途中・塗る前のフレーム・待機表示） | 10〜11 |
| セーブ・ロードで印・欄・文言が落ちる | 7（ほかに未修正1。MOD だけの確認画面で保存すると戻り先が無い。[§3.85](3.85.md)） |
| MOD 間の順序 | 4〜5 |
| 押下がゲームの spec へ流れる | 3 |
| 二重 | 1 |
| その他（並び・画面の判定・保存の抜け） | 11 |

1件ずつ塞いできたので、同じ種類が出続けた。
原因と見たのは3つ。

- MOD のボタンをゲームの一覧（`app.buttons`）に物として置き、印はゲームのデータの外にある。保存の直前に控え、ロードの後に「画面の文言の並びが丸ごと同じ」ときだけ付け直す（`choices.record_marks` / `restore_marks`）。保存の時機や画面のずれで外れる
- 組み立ては包みの順に一覧を書き換える形で、最後に書いた者が勝つ
- 自分で包む所が残っている（ローダの `modfacility`、`333_`、`404_`、`902_`、計測の 2xx）

窓口のいまの穴（10-21 時点）: `trim` は `orig` の前なので、`after` で足すもの（`330_` / `331_` / `402_`）と `modfacility` が `orig` の後に足すものは絞れない。
`buttons_backup` / `buttons_backup_for_shopping` の印は控えない（ゲームはそれも保存する）。
付け直しは世界が替わった後の最初の組み直しの1回だけ。
切った MOD の印も戻り、誰も掃除しない。
`intercept` が True を返しても保存しない。
`check_mods` に「自分で包む MOD を知らせる」決まりが無い。

使えないと確かめたこと: `JustSetButtonToNormalPhase.__init__` は `(self, app)` だけで、spec の args に MOD の印を入れると、MOD 無しで起動したセーブで押したときにゲームが落ちる。
自前のクラス名も `PhaseSpec` に書けない（GAME.md §2.2）。
