# 3.1 戦闘まわり（`106_` / `107_`）: 見張り方（未確認は無し）

`106_`（[§2.5](2.5.md)）も `107_`（[§2.12](2.12.md) / [§2.39](2.39.md)）も決着済み。
以後この節は、本体が退行したときの見張り方として残す。
見るのは `out/battle_bgm.log`。

合格条件は `mixer = n/8 channel(s) busy` が1本を超えて増えていかないこと。
この行を出すのは `207_`（版3で曲の呼び出しとミキサーの本数の見張りに縮めた。呼び出し元は口ごとに1プロセス最初の10件だけで、以後は `<omitted>`）。
BGM が正常に聞こえること自体は合格条件にならない（一度これで誤判定した。[§2.5](2.5.md)）。
実績は定常が常に `1/8`（182行）、`2/8` は `after stop` の瞬間だけ（33行）、3本以上は0行。

| ログ | 意味 |
| --- | --- |
| `[FLAGFIX] BattleEndInFreeAction.end_phase: cleared in_battle` | フラグ側が効いた |
| `[FLAGFIX] load_game_new: cleared in_battle` | 残骸入りのセーブを読んだときに出る |
| `[BGMFIX] sweep after ...: handed <曲> back to the app` | 曲の引き取り成功 |
| `orphan: <曲> was attached to <型> instead of the app` | ゲーム側のバグが発火（毎回出る。正常）。**別の型名で出たら未知の経路** |
| `sweep after ...` が1行も出ないまま `mixer` が増える | 後始末が走っていない。起点の条件を疑う（GAME.md §2.10） |
| `[FLAGFIX] ...: in_boss_battle still set -- not touching` | 観測できていなかった組み合わせ。`107_` の対象を広げる材料 |

`107_` が効いていれば施設到着イベント（`300_`）も戦闘後に復活するので、
`player_events.log` に `skip: ... busy ['in_battle']` が出なくなることが裏取りになる。
