# 3.72 仲間との受け渡しの窓を閉じると会話中の印が残る（`402_`）: 残った印は会話を終えると下りる・直しは実機未確認

**症状**: 役場に `331_` の「施設の建設（出資）」が出なくなった。
同じ画面の `330_` の「家を借りる・買う」は出ている。

**経過**（`out\` の各ログとセーブの突き合わせ）:

| 時刻 | 何が起きたか | 出どころ |
|---|---|---|
| 14:41:39 | 鍛冶屋で「装備の強化」を開く。ゲームが鍛冶屋の選択肢（装備の強化／出る／会話する）を `buttons_backup_for_shopping` へ退避する | `events.log` の `process_choice` |
| 14:42:04 | 同じ鍛冶屋で仲間（78）と会話を始める | `player_events.log` の `observed ConversationStartManager` |
| 14:42:15 | 「＜アイテムの受け渡し＞」で受け渡しの窓を開く | `party_inventory_transfer.log` の `opened twin inventory` |
| 14:42:23 | 窓を閉じる。選択肢が会話のもの（ここで別れる／＜アイテムの受け渡し＞／会話を終了する）から鍛冶屋のものに戻る | `regional_economy.log` の `shop closed:` の前後 |
| 14:44:04 | 会話を終えないまま「出る」で鍛冶屋を離れる。会話の終わり（`ConversationEndManager`）は来ていない | `events.log` |
| 15:56:12 | 役場で `331_` が足すのを控える | `player_events.log` の `busy ['in_conversation']` |

セーブの `game_variables` を読むと、`in_conversation = "78"` が立ったまま保存されていて、
`buttons_backup_for_shopping` は鍛冶屋の3つのままだった。
閉じたときに戻ったのは、この古い退避そのものである。

**原因**: 売買の窓を閉じると、ゲームは売買を始める前に退避した選択肢を戻す。
退避を書くのは売買や装備の強化の入口で、`toggle_twin_inventory_window` は書かない。
`402_` は入口を通らずに窓だけを借りるので、前に開いた店の退避が戻っていた。
ここまでは推定で、ゲームのコードは読んでいない。
根拠は、退避の中身と閉じた直後の選択肢が3つとも一致したこと。
過去のログで、窓を開いた後の最初の `画面が戻った:`（`bounty_hunter.log`）を 10 回分見ると、
会話の選択肢だったのは 1 回だけで、ほかは会話相手の一覧か街の移動先だった。
会話中の印は会話を終えるまで下りないので、戻った画面から施設を離れると印だけが残る。
`331_` の役場の窓口はこの印（`modfacility.game_is_busy`）を見て足すのを控え、
`330_` の窓口は見ないので出ていた。

**直し（版21）**: 窓を開く直前に、今の会話の選択肢を `buttons_backup_for_shopping` へ入れる。
戻す処理はゲームのものをそのまま使う。
閉じた後の選択肢と `in_conversation` を `closed the window:` の行で 1 本残す。
オフラインの検査は `tools/tests/test_party_inventory_transfer.py` に 5 件足した。

**残った印の下ろし方**: 誰かと会話して「会話を終了する」で終えれば下りる。
実機で成立（16:07:17 に宝石商の店主と会話を始めて 16:07:20 に終え、16:07:32 の役場で「施設の建設（出資）」が並んだ。
その前の 16:06:55 の役場と 16:07:15 の宝石商では `busy ['in_conversation']` で控えていた）。

**閉じ方は2通りある。** 窓を閉じたときに `close_shopping_window_process` を通る回と通らない回がある
（通らない回は `turnoff_window_visibility` だけが来る。どの操作がどちらかは測っていない）。
選択肢が入れ替わるのは通る回だけで、通らない回は会話の選択肢がそのまま残る。
受け渡しの窓の開閉 45 回（09-11〜09-25 のログ）のうち、通ったのは 14:42 の1回だけで、閉じ方の操作の違いではなさそうである。
その回だけ、直前に同じ鍛冶屋で「装備の強化」の窓を開いていた（14:41:39 に1回開いたのに、`shop closed:` が 14:41:41 と 14:42:02 の2回出ている）。
売買の窓を開いて閉じた直後の回（09-25 17:24）は通らなかった。
装備の強化の窓がゲームの側に何かを残し、次に閉じた窓が売買の閉じ方になる、という推定（1例のみ。ゲームのコードは読んでいない）。
09-25 に強化の窓を2回開いて閉じたときは、`shop closed:` はどちらも1回だけだった（2回出たのは再現していない）。
その後に受け渡しの窓はまだ開いていない。
