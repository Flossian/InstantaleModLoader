## 採番の衝突（後から発覚、ローダ側で修正）

ローダの `npcs.free_id` がゲームの採番レジストリ `index['npc']` を進めていなかった。
ゲームは新しい町の生成でレジストリから id を振るので、募集した冒険者の id と
衝突して店主の生データが差し替わる（世界Bの街X。
VERIFICATION_LOG.md [§2.77](2.77.md)、GAME.md §2.23）。
`free_id` がレジストリも見て、`make_npc` が両方のレジストリを進めるように直した
（`tools\tests\test_npc_make.py` 17件）。続けて、6種類の id すべてに広げて
ローダ `ids.py`（`claim` / `audit`。TECH.md §3.2.3、`tools\tests\test_ids.py`
29件）に置き、`npcs.py` はそこへ委譲。**実機は未確認**:
募集のあと別の町へ移り、店主が新規に生まれることを見る。
募集のログに `ids: index behind existing ids:` が出たら、そのセーブは
既にレジストリが遅れている。壊れた世界Bは破棄し、世界Cで
続ける。
