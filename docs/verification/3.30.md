# 3.30 NPC 名の誤検出（`120_`）: 別人を改名していた（修正済み）

`out/npc_name.log` に、**別人どうしを重複と判定して改名していた行が3件**あった。

```text
'ボルテス・…' -> '（別名）'  (clashed with id='7' '“…”オルテス')
'“…”オルテス' -> '（別名）'  (clashed with id='__player__' 'ヴォルテス・…')
'“…”オルテス' -> '（別名）'  (clashed with id='__player__' 'ヴォルテス・…')
```

2件目と3件目は**プレイヤー名との衝突**で NPC が改名されている。

**原因: 濁点落としと編集距離が二重に効いていた**

鍵を作る段階で濁点を落としていた（`ボルテス` → `ホルテス`）ところへ、
`SIMILARITY="normal"` の許容（4文字以上で1文字違いまで）が乗る。
結果として「濁点で1文字寄せて、さらに1文字違ってもよい」＝
実質2文字違いが同一人物になり、`ホルテス` と `オルテス` が重なっていた。

**直し方: 判定を2段に分けた**

濁点は鍵に残し、比べるときだけ落とす（`_near`）。

1. 濁点を残したまま近いか（`SIMILARITY` の許容まで）
2. 濁点を落として**完全に一致**するか（`FOLD_VOICING`）

`ダイン` / `タイン` は 2 で拾い、`ボルテス` / `オルテス` はどちらでも拾わない。

**あわせて `_strip_epithet` の助詞判定を絞った**

`rfind("の")` で最後の「の」以降だけ残していたので、
`たけのうち` の鍵が `ウチ` に化けていた。
`の` の手前が仮名だけなら切らないことにした
（二つ名は `隻眼の` `重鉄の` `元傭兵の` のように漢字を含む）。
仮名だけの二つ名は取りこぼすが、名前を壊すよりはよい。

**検算**

`tools/tests/test_npc_name_dedup.py` に、ログに出た12件を回帰として入れた
（捕まえたい9件・別人の3件）。既存の期待16件と合わせて全件通る。
切り分けの比較は次のとおりで、**`rfind("の")` の除去だけでは誤検出は1件も減らない**
（原因が濁点落としの側にあるため）。

| 案 | 取りこぼし | 誤検出 |
| --- | --- | --- |
| 修正前 | 0 | 3 |
| `rfind("の")` 除去のみ | 2 | 3 |
| `FOLD_VOICING=False` | 2 | 0 |
| 判定を2段に分ける（採用） | 0 | 0 |
