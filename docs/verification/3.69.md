## 負けの切り上げ（#8）の経過

どの回も、根はこちらが判定の外から終わり方を起こしていたことで、
ゲーム自身の逃走がその前後でしている準備と片付けが1つずつ抜けていた（仕組みは GAME.md §2.10）。

| 回 | 症状 | 原因 | 直し |
|---|---|---|---|
| 1 | ゲームごと落ちた（`ZeroDivisionError`、`new_hud.py:2306`） | 敵の手番の途中で終わらせたので、戦闘の欄が畳まれた（大きさ 0）約1秒後に、敵の一撃の演出が予約した敵の欄の更新が走った | 切り上げてから10秒の間、この例外だけを握る。起こす前にもログを書く |
| 2 | 画面は戻ったが、裏でワーカースレッドが死んだ（`KeyError`、`resolve_opponents`） | `check_battle_end` から `None` を返し、ゲームが戦闘の繰り返しを抜けず、一覧から消えた敵の次の手を処理した | `True` を返す（素と同じ）。予備に、切り上げた戦闘の残りの手を飛ばす（実機では一度も動かなかった） |
| 3 | 主人公が画面から消え、331 の闘技場に出口が出ない | 倒れた主人公が預けられず一覧に戻らなかった。敵も一覧に残り、`modfacility` が「ゲームが忙しい」と見た | 敵の一覧を空にし、倒れて外された主人公を `escaped_member_in_battle` に預けてゲームに戻させる（`233_` 版3 でゲームの逃走と前後の差を比べて決めた） |
| 4 | 成立 | | |

同じ流れで、逃げて終わった試合の締めの要約（`guard_battle_summarizer` の名前で直接来る）にも死なない一文を足すようにした（主人公が消え去る締めが書かれていた）。

## 死なない描写（#12）の経過

1回目の一文は「殺し合いではない」だけで、判定と決着の話をしていなかった。
長引いた試合で審判が描写の中で「審判が試合を止めた」と書いてダメージを付けず、
以後の手も戦闘ログのその一文を引き継いで効果を出さなくなり、敵の体力が残ったまま試合が終わらなかった。
審判への一文に「言葉づかいだけの指示で、判定は普段どおり。決着はゲームが体力で判定する。
体力が残っている者を描写の中で倒したり試合を止めたりしない（戦闘ログにそう書かれていても続いている）」を足し、
要約には判定の話を省いた短い一文を渡すようにして、長い試合でも普通に決着した。

## 手配度（#8c / #8d）

きっかけは実機の手配。闘技場から逃げる（負けて切り上げるのも逃走の終わり方）たびにその土地の手配度が10下がり、
0 を下回って手配された（GAME.md §2.20）。負けて手配されるのは筋が通らないので戻すことにした。
自分で逃げたぶんも、設定を足して戻せるようにした。
控えるのは申し込みの時点（下がるのが終わり方の前か後かを測っていないため）。
実機では、どちらも終わり方の直後にはまだ下がっておらず、最初の画面が整った合図の時点で下がっていた。
勝った試合では控えを捨てる（勝つと +5 になるが触らない）。

逃げる手に審判が敵へのダメージを付けることがある（逃げる手8件のうち3件。334 の一文の有る無しに関わらず、闘技場の外でも起きた）。
その一撃で敵が倒れると、判定は全滅を先に見て勝ちとして終わる。素の審判のふるまいとしてこのままにした。
その回に主人公が一覧へ戻らない側は `107_` 版4 が直す（[§3.73](3.73.md)）。

## 分かったこと

- `D`（土地の難易度）は依頼の難易度の一覧の平均を四捨五入した値。切り捨てとは平均 31.67 の土地で分かれ、告げる格が1ずれていた
- ゲームは敵の数値を施設に焼いた格から作る。焼く格を揃えれば敵の数値も揃う（敵の数値の包みは揃える前の値が来たときの控え）
- 懸賞金は施設に焼いた格からは決まらない。上限で下げても下げる前の格の額が出る（GAME.md §2.11）
