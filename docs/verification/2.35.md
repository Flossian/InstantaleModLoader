# 2.35 NPC の名前が重複する（オフライン検証済・実機未確認）

小さい LLM ほど同じ語を繰り返し引く。
完全一致より表記ゆれのほうが多い。

| 形 | 例 | 見分け方 |
|---|---|---|
| 表記ゆれ | ボルテス / ヴォルテス | 拗音の綴り・長音・濁点を落とした鍵で比べる |
| 修飾語付き | 「隻眼の」ボルテス | 括弧とその中身、先頭の `〜の` を落とす |
| 姓名の片方だけ一致 | ボルテス・ドレイク | 姓名に割って、片方が姓名だけの名前に含まれるかを見る |

付け直しは**名簿から選ぶ**。
版1（元の名前の末尾の音を機械的に差し替える）は綴り間違いのような名前になり、
版2（LLM に書かせる）は検算を厚くしても「使えるが良くはない名前」を落とせなかった。
名簿方式なら名前の質が入力で決まり、乱数も推論も要らない。
名簿は `male` / `female` / `epithets` の3つだけ読む（他の鍵は在っても無視）。
男女はセーブの `category`（実データ8種）で決め、
`woman` は `man` を含むので**女性を先に見ないと全員が男になる**。

オフライン111件で確かめたことのうち、肝は2つ。
**別人を巻き込まないこと**（`アレン・スミス` と `アレン・ジョーンズ`、`ジル` と `ジン`、
`ナナシ` と `ナシ` を分ける）と、
**改名が素データ（`npcs`）まで届くこと**（届かないと次の保存で古い名前が戻る）。
乱数は MOD 専用の `random.Random` から引く。
名簿が読めない・使い切ったときは名前を発明せず元のまま通し、`WARN` で名指しする。

`ALWAYS_RENAME`（名づけを丸ごと引き取る側。既定 切）で要ったのは2つ。
**同じ NPC を二度裁かない番人**（`generate_character` で付けた名前を
`Character.__init__` がもう一度付け直す。重複を見る既定側では「衝突なし」が歯止めになっていた）と、
控えに素データの `npcs` も全部登録すること
（`world.characters` だけだと後から組み立てられた古参が新顔に見える。GAME.md §2.23）。

分かっていないこと: 名前で NPC を突き合わせている処理があるか（`110_` から引き継いだ未確証）。
改名した NPC の立ち絵は名前のフォルダに入るので、
既存 NPC を改名すると古い画像が取り残される（`FIX_EXISTING` を既定で切ってある理由）。
