# 3.23 魅力の一律反映（`125_`）: 決着

`document_emotion_scores_new(affinity, player_charisma)` が返す2つ目の文
（見た目の魅力の段）は**プレイヤーの魅力だけで決まる**。
相手が誰かも打ち解け具合も入らないので、
魅力に振ったキャラは世界の全員から最上段「耐え難いほど魅力的に見えている」で見られる。
この文は保存され会話プロンプトに毎回全文載るため、応答が無条件に友好的になる（GAME.md §2.25.1）。

初発火まで一度も走っていなかったのは総当たりの作りの欠陥（[§2.50](2.50.md) で修正）。
初発火で未確認4件のうち**4件とも答えが出て、うち1件は外れ**だった。

| 何 | 答え |
| --- | --- |
| 魅力の閾値 | **8 / 11 / 14 / 17 / 20**（直した後の記録。GAME.md §2.25.1 に表）。初発火のログに出た `2 / 5 / 11 / 14` は**記録の側のずれ**で、ゲームが受け付けない点を飛ばした後の行に飛ばす前の値を並べていた（好感度側が `-180から'憎悪している'` で始まっていたのが同じ症状）。値と行を組で持つよう直したら好感度側も `-40から'憎悪している'` に揃った。定数の並びから読んだ 6/8/11/14/17 は**外れ**（1段ずれ） |
| 文の付かない帯があるか | **あった。魅力 11〜13 の帯**（段は `None` を含めて6つ）。初発火のログでは**その帯から出る境目が1つ落ちていた**（「まだ始まっていない」と「文が無い」を同じ `None` で持っていたため）。直した後の記録では 5つの境目がすべて出ている |
| 呼び出し元から NPC を拾えるか | **拾えるようになった**（直した後の記録に `NPC A:` と相手の名前が出た）。初版が拾えなかったのは、実機の呼び出し元 `ConversationStartManager.conversation_start_method_1(self)` に**マネージャしか居ない**ため。相手は `__init__(self, app, character_id)` の id として抱えられている（`out/recon/targets.txt` の93行）。拾い方を4通りへ広げて解決 |
| 呼び出しの回数と時機 | **会話1回につき1行**。`MAX_LINES` を下げる必要は無い |

**効いている部分**: 初対面（好感度0）に対し `親しさ=-2` で
`耐え難いほど魅力的に見えている` → `魅力を感じている` へ引き下げている（初発火で2回、
直した後にも同じ形）。狙った害（初対面の全員が最上段）そのものは消えている。

**好みが散ることも確認**（同じ回、初対面の3人）。同じ魅力・同じ好感度で行き先が割れている:

| 相手 | 好み | 行き先 |
| --- | --- | --- |
| NPC A | ±0 | 魅力を感じている |
| NPC B | +1 | 強い魅力を感じている |
| NPC C | -1 | 文が付かない（`None`） |

**同じ回に見つかった別の穴**: `document_emotion_scores_new` は
**会話1回につき2度**呼ばれる（開始の `ConversationStartManager` と、終了の
`ConversationEndManager.resolve_conversation`。GAME.md §2.25.1）。
終了側は包んでいなかったので相手が決まらず、`好み=+0` で計算し直した値が
**セーブに残る側**になっていた（会話中のプロンプトは正しく、終わると差が消える）。
`ConversationEndManager` の3メソッドも包んで解決。**実機で確認済み**（3メソッドを包んだ後の
再注入で、`NPC D` で開始・終了の両方に名前が出て、行き先も同じ段になった）。

> **この MOD でいちばん大きい発見**: ゲームの生きたフレームは `f_locals` が**空**。
> 拾えなかった回の記録が「ローカル 0件」を3フレーム続けて出していた（Nuitka は
> トレースバックに載るときしか中身を作らない。クラッシュ記録で locals が読めるのは
> そちら経由だから）。**呼び出し元を遡る手はこのゲームでは使えない**。
> 相手が引数として届く場所を包むしかなく、実際に効いているのはその受け皿のほう。
> TECH.md §6.3 に移した。

**あわせて直したもの**（いずれも実機未確認）:

- **相手の拾い方**（上の表）。加えて会話の入口4メソッド
  （`ConversationStartManager.execute` / `conversation_start_method_0` / `_1` / `_3`）を包み、
  通っている間だけ相手の id をスレッドごとに控える受け皿を置いた。
  フレームがまったく読めない環境でも相手が決まる
- **初対面の NPC を相手と認めない条件**。`relationship` に `"player"` の欄が在ることを
  求めていたが、初めて会う相手にはまだ無い可能性がある。
  **いちばん効かせたい相手だけ外れる**条件だった。いまは Character らしさ
  （`profile` / `personality` / `life_log` など2つ以上）で見分ける
- **記録の閾値のずれ**（上の表の2件）

拾えなかったときは、その場のローカルと `self` の属性を1度だけ記録に写すようにした。
まだ外れていれば、次の起動のログに**相手がどこに居るのか**がそのまま出る
（初版はこれを持たず、拾えないことしか分からないまま実機を1往復した）。

**確認は5件とも通過**。

| | 何 | 結果 |
| --- | --- | --- |
| 1 | 段の並びと閾値が記録に出る | 通過（上の表） |
| 2 | 行き先が全員同じでない | 通過（±0 / +1 / -1 に割れた） |
| 3 | セーブの `affinity_text` の2つ目が行き先と一致する | 通過（実機で確認） |
| 4 | 好感度が「多少の好意がある」以上の相手でだけ最上段が出る | 通過。`NPC E`（`仲間だと感じている` ＝ 段差+5）で `親しさ=+0` となり、最上段がそのまま残った（`5段目→5段目（そのまま）`）。初対面の相手は同じ回のログで全員が引き下がっている |
| 5 | 会話の終了側でも相手が決まる | 通過（開始・終了の両方に名前が出る） |

つまり**魅力に振った価値は残したまま、初対面の相手が無条件に折れる状態だけが消えた**。
最上段が出るのは打ち解けた相手だけで、そこでは1段も引かない。

オフライン61件全通・`tools/tests/test_charisma_impression.py`
（実機の呼び出し元と同じ「self しか居ないフレーム」からの呼び出しも検査に入れてある）。

段の文言は mod 側に1つも持っていない（起動時にゲームから読む）ので、
言語設定や段の増減に追従する。
並びが読めない・魅力で動く位置が2つある等の場合は何もしない（推測した並びで書き換えない）。
