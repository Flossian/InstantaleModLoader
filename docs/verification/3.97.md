# 3.97 街の出来事（`338_`）: 引き直し（#10）と手のマウス（#1）のほかは実機で成立・宿代の素の額の取り違えをローダで直した・良い出来事と表のファイル（版2）は実機で成立

開発中は `918_town_incidents` の名前で動かした。遊び方と設定は `338_` の DOC.md、実機の経緯は [§2.92](2.92.md)。
記録は `out\town_incidents.log`。依頼を消す経路は GAME.md §2.9、画面左下のアイコンの列は GAME.md §2.34。

## 決めた仕様（再検討しない）

- 名前は「街の出来事」（疫病・魔物も入るので「治安」より広い）
- 出来事は表のファイルから読む（同梱の `incidents.default.json` の18種と、足す出来事の `kinds\`。10-13）。どの世界観でも成り立つものにし、呼び名と文は LLM がその世界の言葉で書く
- 困り事（15種）は放っておくと2段悪化し（兆し・悪化・深刻）、最後は自然に収まる。段の間隔（60日で1段・最後の段から90日で収まる・1回の日数送りで1段まで）と頻度（30日ごとに25%・同時に3つ（10-13 に2から変えた）・終わった街は180日休み）は設定で変えられる
- 抽選の間隔は、基準の日数（既定 30 日）を前後にばらつきの日数（既定 15 日）までずらす（既定なら 15〜45 日）。ずらす日数は抽選のたびに引き直し、1日より短くしない。幅が 0 なら乱数を引かない（10-21。版3）
- 掲示板では、出来事の依頼のボタンの題の後ろに「（街の出来事）」を付ける。ゲームのボタンは書き換えず、窓口 `choices` の `replace` の写しで出す（セーブには素の題が残る）。一覧の札の依頼の行にも題を添える（10-23。依頼の題は同じになることがあり、ヴェスティアでは重ねて作られた6件のうち 64 と 69 が同じ題だった）
- 良い出来事は依頼を作らず、出来事ごとの段を進む（10-13）。祝祭・豊作・交易の活況は 兆し → 盛況 → 収束、にわか景気は 予兆 → 過熱 → 崩壊 → 収束。起こりやすさは困り事の半分（`weight` 0.5）
- 街の規模で起こりやすさを変える（出来事ごとの `size` と `weight`。`incidents.weights`）
- 効くのは値段・宿代・会話・情景描写。難易度には触らない（`318_` と共有する窓口が無い）
- 宿代の段はローダの宿代の関所に置き、`315_` が決めた額の上に掛ける
- 様子は掲示板の貼り紙ではなくゲーム内の一覧の窓で見せる。日付（日数／あいまい）と影響（数字／言葉／出さない）は設定で切り替える。設定は独自の画面（6タブ・一覧の見本・記録）
- `339_` との連動は 339 がこの MOD の控えを読む一方向
- ほかの冒険者が出来事の依頼を片付けたら出来事は終わる。誰が狙い・片付けたかはローダの窓口 `quest_claims`（TECH.md §3.3.18）に聞く（10-13 まではライバル冒険者の MOD の控えを直に読んでいた）。片付けた人の名前を `end_by_name` に残し、終わった欄はその名前で書く（無ければ「ほかの冒険者」）
- 困り事の依頼は `quest_claims` に「急ぎ」として置く。ライバル冒険者の MOD はこれを先に狙う（その MOD の設定で切れる）
- ライバルが目を付けた状態は「解決に向けて動き始めた」と書く（版1 の「狙っている」は街の困り事に合わない。10-13）

## 控えの形

`state\town_incidents\<世界×主人公>.json`。
同じ世界で主人公を作り直したら引き継がない。
読む MOD は `WorldStore(ctx, "town_incidents", own=False)` で読み、`mod.json` の `shares` に `town_incidents` を書く（TECH.md §3.2.3）。
形を変えるときは読む側（`339_`）と揃える。

```json
{"events": [{"id": 3, "area": "2", "area_name": "灰の都", "kind": "epidemic", "stage": 2,
             "status": "active", "started": 120, "stage_day": 180, "ended": null,
             "end_by": null, "quest": "57", "goods": null, "tries": ["epidemic"],
             "text": {"name": "…", "rumor": "…"}, "told": {}, "good": false, "stage_name": "悪化"}],
 "seq": 3, "next_roll_day": 210, "cooldown": {"5": 400}, "cleanup": []}
```

| 項目 | 中身 |
|---|---|
| `events[].area` / `area_name` | 土地の id（文字列）と、起きたときの街の名前 |
| `events[].kind` | 出来事の英名（同梱は `outlaws` `epidemic` `invaders` `unrest` `shortage` `aftermath` `counterfeit` `hoarding` `anomaly` `abductions` `contraband` `crackdown` `power_vacuum` `influx` `boom` `festival` `harvest` `trade`。`kinds\` の英名も入る） |
| `events[].stage` | 1〜段の数（困り事は 1〜3、にわか景気は 1〜4） |
| `events[].good` / `stage_name` | 良い出来事か、いまの段の名前（版2 から）。版1 の控えには無いので、読む側は 1〜3 を兆し・悪化・深刻と読む |
| `events[].status` | `pending`（文の答え待ち。何も効かない）／`active`／`ended` |
| `events[].started` / `stage_day` / `ended` | 始まった日、今の段の起点、終わった日（ゲームの通算日数） |
| `events[].end_by` | `player` ／ `rival` ／ `natural` |
| `events[].quest` | 片付ける依頼の id（未作成なら null） |
| `events[].goods` | 買い占めで選んだ品の種類 |
| `events[].text` | LLM が書いた文（呼び名・段ごとの概要と情景・店・収まり・依頼・噂）。無ければ表の文。版1 の概要は1文（`summary`） |
| `cooldown` | 土地の id → 次に起きてよい日 |

終わった出来事は直近の20件まで残す（`339_` が「前回から」を読む）。

## 作りの根拠

### 出来事の表

版1 は表を `incidents.py` の中に持っていた。
良い出来事に合わせてファイルへ出した（書き方は DOC.md「出来事を足す」）。

- MOD のフォルダの `incidents.json` があればそれ、無ければ同梱の `incidents.default.json`（TECH.md §3.1.1.1）。書き換えた既定は更新のときに `incidents.json` へ改名して残す（`gui.SHIPPED_DEFAULTS`）
- `kinds\` は1ファイル1出来事。名前の順に読み、同じ `key` は差し替え、`{"key": …, "enabled": false}` だけならその出来事を止める
- 読むのは注入のとき（`incidents.reload_kinds`）。設定画面も同じ関数
- 書き間違い（要る項目が無い・`tone` や品の種類が決まった語でない・2段目から `into` が無い・壊れた JSON）は理由を集めて飛ばし、ログの `WARN kinds:` と設定画面の「出来事の種類」タブに出す
- 値段は段ごとに `prices` の並びで書き、`(品の種類, 買い/売り, 段ごとの %)` にまとめる。買値と売値を別の率にできる（崩壊は買値 -10%・売値 -25%）
- 種類ごとの入切は1つの `DISABLED_KINDS`（英名のカンマ区切り）。版1 の15個の設定は控えから拾って足し、設定画面で保存すると消える（`modtool.save_settings` は宣言の項目だけ書く）

### 良い出来事の筋

- 表の `quest` が `null` なら良い出来事。掲示板で依頼を作らせず（`needs_quest`）、ギルドへの案内も依頼の行も出さない
- 概要（`summary_1`〜`summary_4`）と着いたときの1行（`arrive_1`〜`arrive_4`）は段の数だけ書かせ、残りは空。5段目からは表の文
- 概要は段ごとに書かせる（最初の1文だけの形では崩壊の段でも「大いに賑わっている」と出た）。段が進むたびに頼む形は頼む回数が3〜4倍になり語りの頼みと重なるので採らず、起きたときの1回に欄を足した。ゲーム抜きで Haiku 5.5 とローカル（Eclipsed-Phoenix）に各2回送り、全回で段ごとに書き分け、余った欄と良い出来事の依頼は空、最長 72字（上限 90字）。1回は Haiku 4.2〜6.0秒、ローカル 2.3〜3.1秒。窓に段ごとの文が出るのはオフラインの検査のみ
- 窓の色は段の `tone`（`bad`・`good`・`calm`）から。`bad` が3つなら黄・橙・赤、1つなら赤、`good` は薄い緑・緑、`calm` は灰
- 次の段への言い方・収まるまでの言い方（`end`）・終わった欄の言い方（`ended`）も表から引く
- `339_` は `good` と `stage_name` を読み、趨勢の材料に「（良い出来事・過熱）」と書く

### 依頼は、その街の掲示板を開いたときに作る

ゲームの `DisplayQuestChoice.generate_random_quest` は引数を取らず、いまいる街の依頼を作る（GAME.md §2.9。3回とも）。
出来事はプレイヤーの居ない街で起きることが多いので、掲示板を開いたとき（`DisplayQuestChoice.execute`。別スレッド）に作らせる。

### 自然に収まった依頼は5か所から消す

生きた一覧（`world.quests`）だけから消すと、読み直したときに戻る（GAME.md §2.9）。
依頼ごとにダンジョンの土地も1つ作られるので、生きた一覧・セーブの辞書・街の依頼の並び・ダンジョンの土地の2か所の5つを消す（ローダの `ui.remove_quest`）。
消して読み直し、掲示板を開き、次の依頼を作らせるまで誤りは出なかった。
依頼と土地の id は使い回されない。

### アイコンの列

版2（10-13）から、アイコンは左下に直接並ばず、ローダの MOD 用のボタンの一覧の1行になった（TECH.md §3.3.15。1280×720 では6つ目で箱が重なる計算だった）。
版1 で分かったことはローダの `hudicons` に残っている。

- ゲームのアイコンは `icon_button_layout` の中で位置を比率、大きさを 40px の固定で持つ（GAME.md §2.34）。足すアイコンも `HoverableButton(普段, 乗せた時, 押した時)`
- ゲームは 32×32 の絵を 40px へ引き伸ばし、4列に1列を 2px にする。その並びは左右対称でないので、太らせる列を中心に対して対称に選んで 40×40 で同梱する（`tools\make_town_incidents_icon.py`）。画面の写真と不透明なドット 656 個が一致した
- 箱どうしでなく見えている絵どうしの間で並べる（43・40・40・42px → 42・41・41・42px）
- 「乗せた時」の絵は HUD がゲームの4つにだけ知らせるので、`hudicons` がマウスを見張って足したアイコンにも知らせる。開くときだけキャラ情報と同じ音を鳴らす

### 各地の出来事の窓

版2 で `339_` の勢力と情勢と同じ作りにした（ローダの `panels`。TECH.md §3.3.17）。中身は `incidents.view_model`、描くのは `window.py`。設定画面の見本は `view_lines`。

| 所 | 書き方 |
|---|---|
| 見出しの下 | 現在地　ミストル（この街で霧の市場の買い占めが進行中）／（この街で進行中の出来事はない） |
| 札の上段 | 街の名前・呼び名・段階の札（困り事は兆し 黄・悪化 橙・深刻 赤、良い出来事は兆し・盛況 緑・収束 灰、崩壊は赤） |
| 目盛り | 段の数だけ。今の段まで段ごとの色で塗り、今の段は濃く。下に「発生から75日。悪化するまで約45日。」（設定であいまいな言葉にもなる） |
| 札の行 | 概要、影響（数字は主人公から見て得＝緑・損＝赤・売り買いが同じ向き＝橙）、依頼（困り事だけ。掲示板に出ている／まだ出ていない＝灰／冒険者の〇〇が解決に向けて動き始めた。＝橙／掲示板から消えている＝灰） |
| 右の欄 | この1年に終わったもの。日付・街と呼び名・終わり方（解決した＝緑、冒険者の〇〇が解決した＝橙、自然に収まった・落ち着いた・収束した＝灰） |

### 宿代

宿代を効かせる処理（ボタンの額・手持ちの断り・前払い調整）は v1.15.0 まで `315_` が持っていた。
315 が無くても効くよう、ローダの宿代の関所（`prices.install_inn`。TECH.md §3.3.4）へ移した。

宿代の額はセーブに数としては残らず、部屋選びの文言（「個室(125G)」）だけが残る。
関所は文言から素の額を控えるので、ロードで戻った文言が前の起動で段を掛けたものだと、段つきの額を素の額と取り違えた。
実機では、部屋選びで保存 → 段の強さを 0 にして起動し直すと `room: quality 'private_room' shows 125G` と控え、個室で 75 しか減らなかった。
窓口 `choices` に `from_save()`（ロードで戻った選択肢を、人物が揃った後の組み直しまで真）を足し、その間は控えない。
「最初の組み直し」だけでは人物が揃う前の組み直しで文言が書き直されず、揃った後に控えていた。
直した後は `back to the game's own` に戻り、ちょうど 100 が引かれた。

同じ取り違えは v1.15.0 の `315_` 単体でも起き得た（宿代だけ変えて部屋選びで保存し、設定を変えて起動し直す）。
`tools\tests\test_vacation_custom.py` に2場面を足し、`from_save()` の条件を外すと 200 のところ 150、100 のところ 50 で落ちる。
実機では起こしていない。v1.16.0 のリリースノートのバグ修正に 315 として載せる。

### 依頼を作らせる間の待機の表示

掲示板の `execute` は押下ごとに別スレッドで走る。
初めは、ゲームが押した時点でボタンの旗を下ろして点送りを出していると見て、待機の表示をゲームに任せていた。
作りかけの版は `busy_on` / `busy_off(restore=False)` を重ね、`busy_off` が下りていた旗を戻したので、依頼を押しても画面が変わらなかった。外した。

10-23 にヴェスティアで、依頼を作らせる数秒の間に画面が止まったように見え、その間に掲示板を5回押せて、依頼が少なくとも3件作られた（`injected the brief` が6回、`quest: made` が 64・68・69）。
`out\busy_display.log` では5回とも `process_choice phase=DisplayQuestChoice … enabled=True` で、点送り（`dots_start`）も始まっていない。
掲示板の `execute` では、ゲームは旗を下ろさない（ふだんは一覧を出すだけで待たないため）。
そこで版3 から次のようにした（`board`）。

- 作らせる間はこちらで待機表示を出す（`busy_on`）。旗がもう下りていれば重ねない（上の失敗の形）
- 作れたら選択肢を塗らずに解き（`busy_off(restore=False)`）、下のとおり開き直す。作れなければ同じく解いて、ゲームの掲示板を出す
- 作らせている最中に届いた押下（待機表示を出す前の一瞬に押された分）は、錠（`making_quest`）で捨てる。ログに `ignored another press of the board`

検査は `tools\tests\test_town_incidents.py`（作らせる途中でもう一度押す形。直す前は依頼が2つ作られて落ち、直した後は1つ）。実機では見ていない。

待機の表示を外した後は、依頼は作られたが掲示板の一覧が組まれなかった。
`206_` の記録で、作らせた後のゲームの `update_button_display` が選択肢を変えていない。
掲示板の部品（`DisplayQuestChoice`）をもう1つ作ることがゲームの状態と噛み合わないとみている（読めないので確かめていない）。
作らせた回は続きを呼ばず、手が空いてから同じ押下の形（`process_choice`）で開き直す。
開き直した回は依頼がもうあるので作らず、ゲーム自身の掲示板が出る。

## 実機（10-25、テストワールド。クラウド LLM と ローカル LLM。試した後は控えへ戻した）
