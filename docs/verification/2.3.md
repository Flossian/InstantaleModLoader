# 2.3 プロンプト肥大化対策

DEDUP / EVENTLOG は実経路で発火。
スキーマブロックは**最大3コピーまで増殖する**。

COMPACT のオフライン検証（`output_data/` 12,067 件 / 66 マネージャ種 / 46,931 メッセージ）:

| 項目 | 結果 |
|---|---|
| 埋め込みスキーマを検出 | 7,967 件 |
| 解析失敗 / 誤爆 / フィールド・enum の欠落 | 0 |
| 2回通すと結果が変わる / 1メッセージに2個目 | 0 |
| 合計 | 16,508,011 → 4,529,299 文字（72.6% 減） |

実機（33 リクエスト）は 67,475 → 17,870 文字（73.5% 減）でオフラインと一致。
発火した site は **chat 33 / payload 0**。
ストリーミング経路は `_post_with_model_loading_retry` を通らない。
プロキシと同位置（payload）だけに移植していたら、
何も起きないまま「移植した」と報告するところだった。

後日の再集計（`out/prompt_bloat.log`、2,803 件）: 6,506,367 → 1,736,469 文字（73.3% 減）、site は chat 2,803 / payload 0。
`chat` が上流で先に圧縮するとマーカーが残らないので、payload 側は構造上発火しない。
併せて payload 側の仕掛けを外し、`tools/tests/test_schema_compact.py` を足した。
