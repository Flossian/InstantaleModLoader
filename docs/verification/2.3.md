## 105 版2: 一覧から骨組みへ（2026-10-30）

「スキーマ説明の圧縮を入れると、会話の『雇いたい』の後に『雇う（40G）』が出なくなる」との報告。
雇用の可否は会話進行（`conversation_facilitator`）の返事の `Reply` で決まる。

    元:   {'$defs': {'Reply': {'properties': {'type': {'enum': ['casual_response', 'recruitment_response'], ...
          'accepted': {'anyOf': [{'type': 'boolean'}, {'type': 'null'}], ...
    版1:  Reply: type:∈{casual_response,recruitment_response}, accepted, statement, call_free_action
    版2:  Reply = {"type": "casual_response"|"recruitment_response", "accepted": boolean|null, "statement": string, "call_free_action": boolean}

10-15 以降の雇用の記録はクラウド（Haiku 5.5）で録ったもので、本文にスキーマが無い。
ローカルの頼みと同じ形にするため、10-06 のローカルの記録の先頭の system（スキーマを書いた1通）を足して投げた。
ゲームと同じモデル・起動引数（`quest_gen_probe` の部品）、`111_` の置換も当てた。
記録10件（「雇いたい」7件・値段の交渉・前払いの申し出・名乗っての誘い 各1件）を各5回。
数えたのは `recruitment_response` かつ `accepted=true` の回数。

| 送り方 | 回数 |
|---|---|
| 圧縮なし | 44/50 |
| 版1の一覧 | 19/50 |
| 版1に `accepted:boolean?` だけ足す | 10/50 |
| 版2の骨組み | 41/50 |

- 版1で増えたのは `casual_response`（文では応じている回を含む）。
  `accepted` の型名を足しても戻らなかったので、崩れの元は1欄の型ではなく書き方そのもの
- 断る流れの記録（同じ人物に何度も頼んだ 75.json）は、圧縮なしでも 0/5。版2も 0/5
- 実データ（`output_data/` 31,045 メッセージ）: スキーマ 3,896 件をすべて圧縮、2回目で変わる回 0、10,085,779 → 3,388,907 文字（66.4% 減。メッセージ全体での値）
- スキーマ 782 種類だけで比べると、版1が 73% 減、版2が 67% 減。元より長くなるものは 0
- ゲームの中（テストワールド・ローカル LLM）で冒険者3回に「雇いたい」と言い、3回とも「雇う」のボタンが出た

### 範囲・件数・説明も残す

骨組みでも、元のスキーマにある次の項目を落としていた（783 種類を数えた）。

| 項目 | 出る数 | 出る所（例） |
|---|---|---|
| `minimum` / `maximum` | 1,591 / 1,293（14種類） | 年齢 20..50、`Trait.severity` -10..10、`RollRequired.credibility` 1..10 |
| `minItems` / `maxItems` | 158 / 290（8種類） | `story_quests` ちょうど5件、`enemies` 1..3 件（`139_` の上限） |
| `description` | 8（3種類） | `342_` が審判の `vfx` に足した演出の選び方 |
| `example` | 10（8種類） | `Skill.element` の `'火'` |
| `default` | 103 | 値はすべて `None` |

同梱の llama-server（b10642）の `llama-common.dll` に `exclusiveMinimum` があり、整数の範囲と件数は grammar が縛る。
形は崩れないが、雇用と同じく文から見えないと選び方が変わる恐れがあるので、`integer(1..10)`・`Enemy[1..3]`・`/* … */` の形で残した。
`default` だけは任意の印と `|null` で足りるので落とす。

同じ組み立てで、落とす（版2の骨組みのまま）／残す／圧縮なし を投げ比べた（各記録 3〜4 回、計 165 回）。

| 型 | 記録 | 見たもの | 結果 |
|---|---|---|---|
| 審判の `vfx` | 9件（手引き入り） | 圧縮なしの多数と同じ演出を選んだ回 | 落とす 18/27、残す 18/27 |
| 野外の出来事 | 6件 | `credibility` | 3つとも 4〜6 に収まる |
| キャラ作成 | 2件 | 年齢・`severity`・`modifier` など | 3つとも範囲内で、端への寄りは無い |

- 雇用のときのような差（19/50 → 41/50）は、この回数では出なかった
- 演出は記録ごとに割れ方が違い、残すと圧縮なしに近づく記録（1415：光）も離れる記録（1414：爆発→土）もある
- 範囲の端への寄りは、落とした場合にも出なかった
- 残すと縮み方は 66.4% → 65.9%（3,918 件、2回目で変わる回 0）

### 雇用の 41/50 の内訳と、短いスキーマを触らない理由

骨組みの 41/50 と圧縮なしの 44/50 の差は、全体では偶然でも出る大きさ（フィッシャーの正確検定で p≈0.36）。
外れを記録ごとに分けた。

| 記録 | 場面 | 圧縮なし | 骨組み |
|---|---|---|---|
| 75 | 何度も頼んで「しつこい」と断られる | 0/5 | 0/5 |
| 73 | 一度断られた相手に「雇いたい」 | 5/5 | 4/5 |
| 74 | 武勲を並べて渋る相手を誘う | 4/5 | 2/5 |
| 残り7件 | 素直な「雇いたい」など | 35/35 | 35/35 |

各20回に増やすと、63（素直な頼み）は 20/20 と 20/20、73 は 20/20 と 20/20、74 は 19/20 と 12/20（p≈0.02）。
74 の外れ8回はどれも、文で相手が疑っていて種類も `casual_response`。
文では応じているのに種類だけ外れる版1の崩れ（6回あった）とは違い、返事の中身と種類は合っている。

74 で、どの違いが効くかを切り分けた（各20回）。

| 送り方 | 情報 | 雇用 |
|---|---|---|
| 元のまま | 全部 | 20/20 |
| スキーマの外を1文字変える（改行・読点・末尾の改行） | 全部 | 20/20・20/20・19/20 |
| `title` だけ抜いた Python 表記 | `title` 以外 | 18/20 |
| 元を JSON 表記にする（空白あり） | 全部 | 16/20 |
| 元の空白を詰める | 全部 | 15/20 |
| 骨組みの引用符を `'` にする | 型と値 | 15/20 |
| 骨組み（3回） | 型と値 | 14・13・12/20 |
| `title` だけ抜いた JSON 表記 | `title` 以外 | 13/20 |
| 元を空白なしの JSON にする | 全部 | 3/20 |

- スキーマの外を変えても割れない。割れるのはスキーマの書き方を変えたときだけ
- 情報を落とさない書き換えでも骨組みと同じ程度か、それ以上に下がる。元の書き方だけが高い
- 骨組みの書き方を詰めても戻らないと見て、短いスキーマを触らないことにした

実データのスキーマの長さは 1,468 字の次が 2,280 字で、下限はその間の 2,000 字に置いた。
会話進行は 650〜1,134 字で下限の下に入る。
触らなくなるのは 1,758 件（背景絵 743・会話の決着 181・戦闘の要約 122 など）で、失う削減は全体の 6.1%。
スキーマを含むメッセージでの縮み方は 65.9% → 61.9%（10,099,393 → 3,845,116 文字）、圧縮した 2,160 件で2回目に変わる回は 0。
雇用の記録 13 件は、送る文が圧縮なしと一致する（投げ比べるまでもなく同じ頼みになる）。

## 105 を外しても窓に収まるか（2026-10-30）

`105_` は v1.20.0 以降で対応済みとして外す予定で、外しても頼みと出力が窓（`--ctx-size 16384`、`127_` の `--parallel 1` で1件ごとに全部使える）に収まるかを測った。

`output_data/` のローカルの記録 3,918 件（本文にスキーマ入り）を同梱モデルで数えると、圧縮なしの頼みと出力の合計は中央 2,555・p99 7,207・最大 10,287（`master_ai_facilitator`）。
16,384 を超えるものは 0 件。
頼みの長い型（審判・進行）は出力が短く、出力の長い型（街の依頼の生成）は頼みが短いので、合計は1万前後で頭打ちになる。
記録の `messages` は MOD が送る直前に足す分を含まないが、`_apply_chat_template` で測った実際の送信の最長（16,141 字）は同じ型の記録（16,109 字）とほぼ同じ。

続けて `105_` を無効にし、テストワールドをローカル LLM で遊んだ（`204_` 版4 の `TOKENS` 行。126 件）。
会話・自由行動・依頼の生成・依頼の道中と戦闘・1週間の宿泊を通した。

| 型 | 回数 | 最大（頼み＋出力） |
|---|---|---|
| 自由行動の進行 `Structure[AddStatusEffect,ArrestPlayer,DealDamage]` | 9 | 6,724 + 366 = 7,090 |
| 依頼の生成 `QuestStructure` | 1 | 3,744 + 2,376 = 6,120 |
| 依頼の道中 `QuestTurnStructure` | 5 | 4,941 + 227 = 5,168 |
| 会話進行 `Structure[Reply,Retrieve]` | 8 | 4,254 + 232 = 4,486 |
| 審判 | 13 | 4,125 + 218 = 4,343 |

- 窓あふれ（`RAISE chat`）と、窓に合わせた切り詰め（`truncated=True`）は 0 件
- 自由行動の進行は3回続けても伸びない
- 会話進行は1往復で 120〜270 伸びる（3,297 → 4,254。7往復）。16,384 に届くには1回の会話でさらに約 70 往復が要る
- `tokens_evaluated` と `timings.prompt_n` は使い回し（`cache_n`）を除いた分だけ。窓の占め方は「使い回し＋新しく処理した分＋出力」で、版4 の `prompt` はこの和を書く（測った時点のコードは使い回しを足しておらず、表は記録の `cached` を足して計算し直した）
- テストワールドは記録が少なく、長く遊んだ世界の頼みは測っていない

## 105 を 127 に取り込む（2026-10-31）

### 105 が要った理由

窓が足りなくなっていたのは、圧縮が無いからではなかった。
プロキシ（InstantaleLLMProxy）の履歴をたどると、3つの手当てが3日のうちに入っている。

| 日付 | 入れたもの | 何に効くか |
|---|---|---|
| 07-15 | DEDUP（作り直すたびに足されるスキーマの system を畳む）と多重起動の抑止 | 頼みが 37,283 字まで膨らむ |
| 07-16 | COMPACT（スキーマ説明の圧縮）。同じコミットで、共有する llama-server を `--parallel 1` に固定 | 1件あたりの頼みを縮める |
| 07-17 | 調査結果の追記 | 統合 KV の 16,384 を4スロットが共有し、2本が同時に走ると1件あたり約半分になり、`context-exceeded`（HTTP 500）で止まっていた。`--parallel 1` で直列にしたら直った |

ローダの `105_` は 07-28 の最初のコミットで、プロキシの機能をまとめて移植したもの。
「適用後、打ち切りの再発なし」（07-17）は3つを一度に入れた後の結果で、圧縮だけの効き目は切り分けていない。
その後、複製は本体が main_023 で直し、直列化は `127_` の `--parallel 1` が担っている。
圧縮が効くのは、窓を共有したまま2本が同時に走る起動のときだけになった。

### 起動引数で縮めるかを決める

`127_` 版6 に圧縮の部品（`schema_compact.py`）を移し、最後に渡した起動引数で縮めるかを決める（`needs_schema_compact`）。

| 起動 | 縮めるか |
|---|---|
| `--parallel` 無し（127 の SLOTS=0） | 縮める |
| `--parallel 1`（SLOTS=1、既定） | 縮めない |
| `--parallel N` で窓をスロット数倍（SLOTS≥2） | 縮めない |
| `--parallel N` で窓が割られる（設定欄に書いた場合） | 縮める |
| 起動を見ていない（注入がサーバより後） | 走っているサーバの引数で決め、読めなければ縮める |

`105_` は `superseded: 127_llm_response_speed` で伏せた。
`111_` / `119_` の `after` は `127_` を指すように直し、順序ファイルでも `127_` を `111_` より前に置いた（置換は圧縮前の本文を見る、の関係を保つ）。

### 実機（テストワールド・ローカル LLM、`105_` は無効）

| 127 の SLOTS | `llm_speed.log` の判定 | 自由行動の進行の頼み |
|---|---|---|
| 1（既定） | 縮めない: `--parallel 1` で1件ごとの窓 16384 | `[COMPACT]` 無し、6,519 トークン |
| 0 | 縮める: `--parallel` 無し（統合 KV） | 6,682 → 2,147 字に圧縮、4,334 トークン |

`safe hook failed` と `VERIFY FAILED` は出ていない。
`204_` 版4 の読み方の直し（使い回しを足す）もこの起動で効いた（`prompt=6694 cached=6002`）。
