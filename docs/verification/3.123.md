# 3.123 戦闘中に持ち物を開くとゲームごと落ちる（`148_fix_enemy_panel_crash`）: 実機で落ちなくなった

2026-11-04 に見つけて直した。
敵の画像の生成中に戦闘で鞄を開け閉めすると、`ZeroDivisionError` でゲームごと落ちた。

```text
scripts\hud\new_hud.py:2307 in update_enemy_display
ZeroDivisionError: float division by zero
total_height = 0 / enemy_count = 1
```

## 分かったこと

手がかりは、落ちる前の記録の並びだった（`220_` の `枠が動いた`、`out\live_crashes.log` の変数）。

| 順 | 起きること | 確かめ方 |
|---|---|---|
| 1 | 点送りの最中に鞄を開くと、`top_info_layout_battle` が `[384, 456.3]` → `[0, 0]`、不透明度 0 になる | 毎フレーム読むスクリプト。`333_` を切っても同じ |
| 2 | 敵の欄の更新は手の約1秒後に走る | 落ちたときの `dt=1.13`、手の終わりとの時刻の差。走る間隔を直接は測っていない |
| 3 | 畳まれている間に更新が走ると 0 除算で落ちる | `update_enemy_display` を畳まれた瞬間に呼ぶと例外。鞄の開け閉めだけでも3回目のクリックで落ちた |

- 欄に高さだけを与えると更新は最後まで走るので、割る相手は欄の高さと読める
- `333_` を切った回は30回のクリックで落ちなかった。畳まれている間に更新が走らなかっただけで、素のゲームで落ちないとは言えない
- 生成中に落ちやすいのは、点送りが長く続くからと読んでいる。生成中の再現はしていない

## 直し方

最初は、更新の 0 除算を握って飛ばす案だった。
試しの中で、更新を畳まれた間に呼んで途中で失敗させた回の次の手が、`resolve_opponents`（`instantale.py:7261`）の `KeyError` で止まった。
飛ばす形も、敵の絵の一覧を組み直さないので同じ所で止まりうる。

次の形にした。

1. 敵が残っていて欄の高さが 0 なら、その間だけ高さを与えて更新を最後まで走らせ、元の高さへ戻す
2. 欄が戻るのを 0.25 秒ごとに見て、最後の更新をもう一度走らせて描き直す。見張りは1本だけ。敵が居なくなったら描き直さずに終わる
3. 敵の一覧が空のとき（切り上げの直後）は触らない。`334_` が入っていれば、今までどおり `defeat` が 10 秒の間だけ 0 除算を握る

最初は `defeat.py` に置いたが、`defeat.install` を呼ぶのは `334_colosseum_custom` だけで、334 を切ると手当てが入らないので、独立した MOD にした。

## 実機（テストワールド、依頼の戦闘）

| 確かめたこと | 結果 |
|---|---|
| 畳まれた瞬間に `update_enemy_info` を呼ぶ | 例外なし。敵の絵の一覧は2体とも残った（334 あり・なし） |
| ゲーム自身のタイミングで重なった回（`defeat.py` に置いていた版） | 落ちず、0.26 秒後に描き直した |
| 鞄の開け閉め（`148_`・334 なしで32回） | 落ちない。戦闘は手番まで進み、欄は `[384, 456.3]` に戻った。`out\enemy_panel_crash.log` に `updated while folded` と `redrew the enemy panel` が出た |

## 試しの手順の不具合（`tools\drive\relaunch.sh`）

世界を選ぶのがローダの当て直しの間に入ると、MOD の施設の中のセーブは `load_game_new` の `'facilityが見つからない'.name` で落ちた（3回）。
落ちずに読めた回も、主人公の居場所が町の入口に代わり、区画の名前が本来と違っていた。
世界の一覧を開く前と後の2か所で `wait_boot_settled`（2回目以降の boot が complete まで進み、ログの大きさが動かなくなるまで）を待つようにして、本来の施設から始まるようになった。
当て直しの間に手で世界を選んだときも同じことが起きるかは確かめていない。

## オフラインの検査（`tools\tests\test_fix_enemy_panel_crash.py`）

畳まれた間の更新が最後まで走る・高さが 0 に戻る・見張りが増えない・最後の更新で1回だけ描き直す・戦闘が終わったら描き直さない・敵が居ないときは触らない・新しい注入が来たら古い見張りが降りることを確かめた。

## 残っていること

- 敵の画像の生成中に鞄を開け閉めしたときの実機
- 333 を切ったときに鞄の中で胸甲が `(0, 0)` に置かれる件（333 の形のセーブを 333 なしで読んだ状態。原因は調べていない）
