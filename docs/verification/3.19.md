# 3.19 アイテムの値付け（`129_`）: 決着（決済まで確認）

値付けは実機で成立（説明欄・売買画面あわせて367行）。
決済も売り買いを1回ずつ通し、`settled sell ... shown=100` /
`settled buy ... shown=25` の両方が出た。
**`reconcile` は0行 ＝ ゲームの決済はこの MOD が書いた値段をそのまま読んでいる**（[§2.50](2.50.md)）。

値付けの根拠は実セーブとゲームのプロンプト出力から取ってあり推測ではない（GAME.md §2.13.2）。
分類の語彙は生成スキーマとアセットのフォルダ名、元の実額は実セーブ151件、
物価の目安は同じセーブの宿の主の台詞。

実機で見えたこと（注入99回ぶん）。
書きうる経路を全部フックしてあったので、実際に当たるのが分かった:
`shop_player` 221（主経路）/ `window/left` `window/right` 65・56（画面を開いた時点の付け直し）/
`detail` 8 / `shop_owner` 1 / `skip` 17 / **`generated*` と `normalize/*` は0**。

書き換わった額の例（種別倍率を織り込む前・すべて 1.0）:
攻撃力580の mythic の長物が **36G → 107,600G**、防御力450の accessory が 579G → 79,800G。
GAME.md §2.13.2 の「売価はレア度も能力値も見ていない」が遊んでいるセーブでもそのまま出ている。
同じ計算をオフラインで走らせるとこの3件が **1G の差も無く再現する** ＝
ゲームの中で走っている値付けと検査が見ている値付けが同じものである証拠。

`skip` の17件はすべてセーブエディタで足した `value` を持たない品で、元の値段のまま残る（設計どおり）。

**残っている未確認**

| 未確認 | 見方 |
| --- | --- |
| 強化費用への波及 | `get_item_base_price` はわざとフックしていない（`get_*_level_from_price` の定義域を壊さないため。[§2.2](2.2.md) の前例）。鍛冶で強化して費用が MOD なしのときと変わらないこと |
| `generate_*` / `normalize_*` の経路 | 0件のまま。売買画面の経路が拾うので実害は無いが、**新しく作られた品がその場で値付けされているかは不明**。新しい店を初めて開いたときに `generated*` が出るか |

オフライン検証は値付けの水準そのものも見ている
（`RATES` や種別倍率を触って目安から3割以上外れると落ちる）。

## 3.19.1 `405_regional_economy` との競合（直して実機で確認）

地域倍率が**買値にだけ乗っていなかった**。
`out\regional_economy.log` と `out\item_price.log` の突き合わせで、405 が動かした9件が9件とも 129 に戻されていた
（`shop_owner` 8・`normalize/shop` 1。消えたのは全部買価の店の品4種で、売価の5種は無事）。
適用順の問題ではなく、129 が値段を書く時点が地点ごとに `orig` の前後で混在しているため
（TECH.md §3.3.1。相手は外側でも内側でも必ず半分の地点で負ける）。
直しは 129 側の値付け直後の入口 `sys._instantale_item_price_post`（`(名乗り, 関数)` のリスト。405 は `mod.json` の `"shares"` で借りる）。

> **この入口は後に廃した。** 同じ競合が PR#12 で再発したため
> （405 を書き直した版が `"shares"` ごと入口を削除し、`after: 129` へ戻していた）。
> 入口は `sys` の文字列と `mod.json` の宣言でしか見えず、405 の側からは存在が分からない。
> 値段を**書く側をローダ1枚に移し**（`instantale_modloader.prices` の共通フック。TECH.md §5.9）、
> 129 は式を、405 は処理を置くだけにした。以下の記録は入口が在った頃のもの。
仕組みは `405_` の DOC.md。
オフライン検証は、129 が書く6経路すべてで後処理が最後の書き手になること（壊れていたのは `shop_owner` と `normalize` の2つ）と、
入口の名前が2本の mod で一致していること（改名しても例外は出ず黙って乗らなくなるので静的に見る）。

**実機で成立（直した直後）。**
2つの街で売買画面を開き、129 が 405 の値を戻した行と直後に 405 が掛け直した行を1対1で数えた:

| 129 の経路 | 129 が戻した | 405 が掛け直した |
| --- | --- | --- |
| `shop_owner` | 7 | 7 |
| `normalize/shop` | 7 | 7 |
| `normalize/player` | 5 | 5 |

**19 / 19。** 直す前は 9 / 0。
売買画面を開いた時点の 405 自身のフックは `regional overlay: 0 price(s)`（入口で既に掛かっていてマークを見て何もしない。設計どおり）。
`modloader.log` に `post hook ... failed` は無し。`reconcile` も無し。

共通フックへ移った後の 405 は、自分が書いた額を控えず、最終額をいつでも式から組み直す。
控えていた頃は、保存中に売買画面が先に掛け直すと倍率が積み上がり、並行テストで 100 が 168万まで伸びた。
組み直す形にして、その経路ごと無くなった。

## 3.19.2 `item_price.log` の同じ中身の繰り返しを止めた

設定の書き出し（`---- installed ...`）は apply のたびに出ていて、遅れて当て直す boot を含めて約40日で1,120回・約300KB になっていた。
前に書いた中身と同じなら書かないようにした。
値段が読めない品の `skip` は同じ品で何度も出ていた（1,085行のうち品は16通り）。
行は品ごとに1プロセス1回にし、数（`skipped`）は今までどおり毎回数える。
控えは `sys` に置き（1プロセス）、注入のときにログが世代送りされたら（ファイルが入れ替わったら）、設定も `skip` も新しいログに書き直す。
