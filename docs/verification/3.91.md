# 3.91 脱獄の決行を即席の武器・防具で戦う（`336_`）と、ローダの窓口 `equipment` の貸し、取り残された右の欄の畳み直し（窓口 `choices`）: 実機で成立（ロードで場所の画面に戻る回だけ控えを仕込んで確認）

遊び方は `336_` の DOC.md「脱獄」。窓口の作りは TECH.md §3.3.6「貸し」。
記録は `out\crime_overhaul.log`（貸すと返すの行もここ）と `out\modloader.log`（セーブへの書き戻し）。

## 決めた仕様（再検討しない）

- 決行の戦闘は、押収された装備の代わりに即席の武器（研いだ鉄片）と防具（囚人服）で戦う。戦闘が終われば元の装備に戻る（2026-10-08）
- 強さは今の装備の値 × 30%（設定 `JAILBREAK_IMPROVISED_PCT`）。今の装備の値は窓口 `combat` の答え（`333_` が居れば合算を含む）、無ければ本体の `equipments` の1品。素手・防具なしの種類は持たせない
- 即席の品は持ち物にも装備欄にも入れない。本体の `equipments` の2つだけを戦闘のあいだ差し替える（ローダの窓口 `equipment.lend`）
- 処刑場からの脱出（手引きのダンジョン）は対象にしない。手引き役が連れ出す筋で、装備を持ったまま挑む

## 分かったこと

- 本体は審判への頼みの「プレイヤー情報」に `weapon: 名前(説明)` と `wearable: 名前(説明)` を `equipments` から書く。差し替えると、`401_` の部位の文も含めて本物の品の名前は頼みに1つも出なかった
- `333_` は戦闘の1手ごとに装備欄から `equipments` を組み直す（`sync_game`）。貸しの間はここを止めないと、2手目から本物の装備に戻る
- 戦闘の最中もゲームは保存する。貸した品の id がそのままセーブに入ると、持ち物に無い品を指す
- 決行の戦闘の最中に落ちてロードすると、ゲームは戦闘の続きに戻った（GAME.md §2.10「戦闘の最中のセーブ」の「戦闘のボタン」の回）。メモリの決行の控えはロードで消えるので、前の版はこの戦闘の終わりで牢を出た後の始末（本文・手配度・備えの片付け）をしていなかった
- 倒れた戦闘は `BattleEndManager.end_phase` を通らず、`GameOverManager` が作られる。ゲームオーバーの画面（あなたは死んだ…／新たな人生／終了する）の時点で、ゲームはその世界の `savedata.json` を消していた（`backups` だけが残った）。決行の控えは、セーブの無い周回の state にだけ残る形だった
- 決行の一覧（5択）から戦闘に入ると、右の欄（溢れた選択肢の欄）が開いたまま敵の欄に重なった（10-08 の最初の写真にも写っていたが見落としていた）。原因は HUD 自身の `in_battle`（GAME.md §2.2）。`display_button_load(0)`・`update_ui`・`update_button_texts` の素の呼び出し・`app.in_battle` を下ろしての呼び出しでは閉じず、HUD の `in_battle` をその1回だけ下ろした `update_button_texts` で閉じた。戦闘の後に閉じたときの呼び出し元は `new_hud.py:2126` の `update_button_texts`

## 確かめたこと（2026-10-08、ペルディション。牢へは `ImprisonmentStartManager` を直に起こして入った）

- 決行: 本文に「押収された装備は看守の詰所にある。手にあるのは研いだ鉄片と囚人服だけだ。」。`equipments` が研いだ鉄片（攻撃力 295 ＝ 合算 982.5 × 30%）と囚人服（防御力 249 ＝ 831.3 × 30%）、画面上部が `Atk:510(+295)` / `Def:0(+249)`（写真）。持ち物に即席の品は無い
- 1手の後も貸した品のまま（`333_` が組み直さない）。`319_` の被弾の行が `def=249`
- 審判への頼み（`capture_messages` で写した messages）に研いだ鉄片・囚人服が4回ずつ、本物の品の名前は0回
- 戦闘の最中の保存3回とも、セーブの `equipments` は元の `item_462` / `item_463`（`the save keeps the own equipment instead of the loan`）
- 逃げて出る: 「逃げる途中で詰所に押し入り、押収されていた装備を取り戻した。」が「追っ手を振り切り、牢獄の外へ出た。」の次に出て、`equipments`・画面上部（+800）・窓口の答え（982.5 / 831.3）・装備欄の4品が元に戻った
- 戦闘の最中に落とした（ゲームを止めて起動し直した）: 前の版では戦闘の続きに本物の装備で戻った。直した版では、ロードの直後に `back in the break-out battle after a load` で即席の品を持たせ直し、逃げて出ると牢を出た後の始末と装備の返却まで通り、決行の控え（`jail_break`）も消えた。`107_` 版7（見分けをローダへ移した版）は同じロードで `the battle screen came back` を出した
- 勝って出る: 5手で衛兵3体を倒し、「全ての敵を倒した。」の後に牢を出た2行と手配度の行。`escaped ('won')`、装備・画面上部（+800）・窓口の答えが元に戻った
- 倒れてゲームオーバー（`319_` の回避を切り、HP を 1 にして決行）: 看守の一撃（21）でゲームオーバーの画面。直す前の版では決行の控え（`jail_break`）が残った。`GameOverManager` の包みを足した版では `game over; dropped the break-out marks` で控えが消えた。貸しはメモリに残るが、ゲームはこのときセーブを消しているので書き出されない（次のロード・新規開始でローダが捨てる）
- ロードで場所の画面に戻った回: ゲームがどちらに戻すかは選べないので、ギルドの画面で控えだけを書いてから読み直した。`the load did not return to the break-out battle; dropped the mark` で控えが消え、即席の品は持たされなかった
- 右の欄: 窓口 `choices` の畳み直しを入れた版で、決行の一覧（5択）から入った戦闘は `folded the right panel left open over 4 choice(s): closed` となり、敵の欄が重ならずに出た（写真）。右の欄はゲームが閉じたときと同じ位置へ退いていた。`316_` 版4（自前の手当てを外した版）で、町の画面（5択以上）から起きた追手の戦闘も重ならなかった（この回は取り残されず、畳み直しは走っていない）
- 確かめていないもの: ゲーム自身の依頼の戦闘が5択以上の画面から始まる回の畳み直し（窓口は起こした者を見ないので同じ形で働く見込み。届く場面を作れていない）、`336_` の店で盗んで見咎められた衛兵の戦闘
