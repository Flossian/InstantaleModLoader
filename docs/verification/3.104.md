# 3.104 `409_fix_crafted_item_type`（わさの 様の提供）の取り込みとレビュー: 店の消耗品の霧茸に「消費」が出て使えた（10-19）・鍵を足す経路は 134 を外した実機が未

2026-10-19 に、わさの 様から提供を受けた `work\800_fix_crafted_item_type`（版1）を `409_` として取り込み、読んで直した。
提供物の原本は `out\backup\800_fix_crafted_item_type_provided\` に退避した。

## 前提の裏付け

| 主張 | 確かめ方 | 結果 |
| --- | --- | --- |
| 右クリックの「消費」は `healing_item` だけに出る | exe の `scripts.hud.new_hud` の定数 | `healing_item` はあり、`consumable` / `utility` は無い（読めた範囲。分岐の形は読めない） |
| クラフトが飲食物・薬を `consumable` で返すことがある | exe の `item_craft_generator` の定数 | 型に `HealingItem` と `Consumable` の両方がある（どちらを選ぶかは LLM） |
| `consumable` は クラフト以外からも出る | 全セーブ7つを `409_` の判定に通した（書き戻さない） | 直る品は店の品揃え（`areas/…/facilities`）と人物の持ち物が大半。クラフトに限らない |
| `consumable` の品には `回復` と `疲労負荷` が無い | 同上 | 無いのが大半。在るのは `134_` が作り直した品（`スタミナ回復` 等と `疲労負荷: 0`）だけ |

直る品の中には回復と結びつかないものもある（煙玉・化粧粉が `potion`、解毒腺の抽出液が `medicine`）。
細分が飲食物・薬なら一律に回復アイテムへ寄せる形は提供物のまま変えていない。

## レビューで直したこと（版2）

| 件 | 直したこと |
| --- | --- |
| 種別だけ変えると `回復` も `疲労負荷` も無い `healing_item` ができる | どちらも無い品には本体の `get_heal_spec(value)` / `get_heal_physical_integrity_barden(value)` の値を足す。並びは `item_detail` → `回復` → `疲労負荷` → 残り。綴りは表示言語で `134_` と同じ（`recovery` / `fatigue`）。本体が鍵の無い品を読むとどうなるかは測っていない（`134_` の `Silenced` が必ず鍵の在る状態で通しているのと同じ理由） |
| 窓の経路が持ち物を辞書か並びとしか読まない | ローダの `items.inventory_of`（持ち主でも入れ物でも中の辞書を引く）に乗せ替えた。今回の実機ではテオの `inventory` は辞書で、提供物の書き方でも読めた |
| 包みが名前で渡された引数を位置へ直して `orig` へ渡す | 受けた形のまま渡す（`place_crafted_item`・二つ窓・説明欄） |
| 並び順の表に無い | `load_order.json` で `134_` の直後（`134_` が内側。生成の後では `134_` が先に作り直し、`409_` は種別だけ直す） |
| 作者の名乗り・題・DOC.md | `author` を `わさの, R01/Flossian`、NOTICE に追記。題を効果の一文に。DOC.md の番号（`135_` のまま）と、遊ぶ側に要らない根拠の表をこちらへ移した |

検査は `tools\tests\test_fix_crafted_item_type.py`（34項目）。
提供物のコードに差し替えると、鍵を足す項目と窓の2項目（持ち主・入れ物）が落ちる。

## 実機（10-19、テストワールド、クラウド LLM）

ミストルの霧の荷物屋（店主テオ）で、`relaunch.sh` → 売買 → 買う → 持ち物の窓 → 右クリック → 消費 の素の経路。

| 見たこと | 結果 |
| --- | --- |
| 売買の窓を開いたとき、店主の持ち物の `consumable` の霧茸（`134_` が作り直し済み）を直す | `window/left: '霧茸の乾燥品'/food consumable -> healing_item`。鍵は足さない（`疲労負荷: 0` が在る） |
| 買った霧茸の右クリック | 「消費」「捨てる」が出た（写真 `out\drive\409_右クリック.png`） |
| 消費する | 「霧茸の乾燥品を消費した。スタミナが13回復した。」。スタミナ 24 → 37、品は消えた。`134_` の `consumed … kind=stamina planned={'stamina': 13}` |
| 鍵を足すときの本体の関数 | ゲームの中で `409_` の `game_heal_values` を呼んだ。value 3/7/18/50 → (8, 9) / (16, 9) / (56, 11) / (199, 10)。表示言語は ja |

試しの後は控えへ戻した。

## 残り

- 鍵を足した品を、`134_` を外した構成で消費する（`回復` ぶん HP が戻り、`疲労負荷` ぶんスタミナが減る）。鍵の無い `consumable` は今回のミストルに無かった
- クラフトで `consumable` の品ができたときの `generated` / `crafted` の行
