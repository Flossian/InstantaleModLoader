# 2.81 別の世界の NPC を連れてくる。実機7回で決着（`323_`）

5体を持ち込んで、置く・残る・会えるまで通した。
不具合が3つ出て、どれも直っている。
2つは**ローダ側**の穴で、`320_` と手元の MOD も同じ場面で踏んでいた。

## 不具合1: ロード直後は素データの辞書を見分けられない（ローダ `npcs.py`）

`npc_stores` は素データの辞書を「実行時の名簿（`world.characters`）と鍵が重なるか」で
見分けていた。
**ロード直後の名簿はまだ埋まっていない**（`224_` の記録で**1件**）ので、
突き合わせる相手が居ず、何も見つからない。

結果 `save_data_dict['npcs']`（[§2.23](2.23.md) が「★ ここが本体」と書いている辞書）へ
何も書かれず、`generate_character` が `KeyError` で落ちて最後の手段
（`Character` の直組み）に落ちていた。
`savedata.json` は 43人のままで、置いたはずの NPC は残らなかった。

直し方: 中身の形でも見分ける（値が `name` と `ability_scores` を持つ辞書）。
`ability_scores` の6鍵は `generate_character` が要求するので、
「素データである」ことの必要条件そのもの。

## 不具合2: 注入し直しで持ち越しが消える（`323_`）

ロードの2秒後・画面が出る前に**注入し直し**が走っていた
（`out\modloader.log`）。
到着の知らせは「ロードの後・最初に選択肢が組み直されるまで」持ち越すものなので、
閉包に置いていると新しい世代の空のリストが読まれて消える（TECH.md §3.5）。
プロセス（`sys` の属性）へ移した。

## 不具合3: 置いてもプレイヤーが保存しなければ残らない（`323_`）

MOD が触るのは動いているゲームの中の辞書で、ファイルが書かれるのは保存したとき。
予約を果たした瞬間に「済んだ」ことにすると、保存せずに終えた回で予約だけが消費される。

保存されたかを別に控える（`InstantaleApp.save_game` を包んで印を付ける）。
次のロードで「置いた記録があるのに印が無く、その NPC も世界に居ない」なら、
予約を戻して置き直す。印の付いた予約は二度と触らない。
