# 2.75 321_ の実機1回目。編纂・差し替え・下流への波及まで成立（`321_`）

世界A の最初の街（achievements 9件が既にある状態）で、注入直後の4分間。
読んだのは `out\area_chronicle.log` と `output_data\unknown\unknown\`
（この回はゲーム自身の記録も unknown/unknown に入っており、MOD 固有の現象ではない）。

1. 実行時の形:
   `descriptions` は dict。ただし鍵は
   `['area_description', 'facilities', 'overview']` の3枚で、
   world_data.json の2枚（overview / facilities）より1枚多い。
   `area_description` を誰が読むかは未特定。差し替えは dict の写しに
   2鍵だけ上書きする形なので、3枚目はそのまま残る
2. 編纂: 契機は「日数経過」の取りこぼし保険側
   （9件が未織り込みだったので、クリアを踏まなくても立った）。
   `新しい功績 9件のうち直近5件だけを渡す` の絞りが効き、2.5秒で返答。
   囲み付き JSON を読めて `done` 0 → 9。
   overview 73字 → 104字、facilities 87字 → 278字
   （facilities の底は300字なので設計どおりの範囲）
3. 質: 1件目は合格。
   元の文の定型句が両方の文から消え、村の正体（貧しい湿地の村）は保たれ、
   未解決の糸（行方不明の荷）は残った。
   出来事の並べ直しではなく「いまの土地の状態」の記述になっている
4. 下流への波及（キャッシュの有無）:
   編纂を境に、プロンプトの文面が全読み手で切り替わった。
   前: narrator / conversation_starter / conversation_resolver が旧 overview。
   後: vacation_rest_overview_generator / narrator / random_quest_generator
   （新 overview と新 facilities の両方）が新文面。
   キャッシュは無い。差し替えは次の呼び出しから読まれる
5. 街歩きナレーションのマネージャ: `narrator` で確定。
   そのプロンプトに overview が載っている（facilities は載っていない）ので、
   原文の差し替えが自動で波及する。注入先の追加は不要

modloader.log にこの区間の 321_ 由来の ERROR/WARN 無し。クラッシュ無し。
まだ踏んでいない経路（クリア契機・ロード時の当て直し・編纂後の会話）は [§2.76](2.76.md)。
