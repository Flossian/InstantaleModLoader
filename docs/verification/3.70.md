# 3.70 インベントリの装備欄（`333_`）: 主人公・仲間・合算・戦闘への効き方まで実機で成立・残るは満杯のとき

開発中は `912_equipment_slots` の名前で動かした。遊び方と設定は `333_` の DOC.md、
ゲーム側の事実は GAME.md §2.13.3、実機の経緯は VERIFICATION_LOG.md [§2.87](2.87.md)。

## 実機で成立したこと

| 見たこと | 結果 |
|---|---|
| ドラッグ・拒否・置換 | 所持品から部位へ入り、部位と種類が合わない品は戻る（`wrong region` / `not equipment`）。居る部位へ落とすと居た品が所持品へ出る |
| 右クリック | 「装備」で空いている部位へ、両手が埋まっていれば右手と入れ替え。「外す」で所持品の空きへ |
| 最高値の反映 | 手の武器の最高値が `weapon`、全部位の防具の最高値が `wearable`。外すと次の最高値へ繰り下がる |
| 合算（版9〜10） | 画面上部の括弧が合算の値になり、ドラッグのその場で描き変わる。戦闘でも `combine weapon` / `combine wearable` が式どおりで、`319_` の錨も上がった |
| セーブとロード | 装備欄の品は書き出す JSON にだけ合流し、ロード後に控えどおり並ぶ。仲間の装備も元の部位で戻り、仲間の持ち物に二重に並ばない |
| 世界の切り替え | 前の世界の品を辞書から落とし、新しい世界の所持品へ返さない |
| 売買・クラフト・強化の窓、捨てる | 装備欄の品はどの窓にも出ず、捨てた品は控えから落ちる（実機で確認。この経路はログを書かない作り） |
| 1920x1080 | マスは所持品と同じ大きさのまま、余白を詰めて画面の上端・右端に寄せる形で、主人公・仲間とも他の欄に被らない |
| 右側の選択肢 | 窓を開いている間は隠れ、閉じると戻る。会話に入る・ロードなど本体の別の経路で窓が消えたときも戻る |
| 仲間の装備欄（版13） | 受け渡しの窓の右に出て、ドラッグと 402_ の右クリックの「装備」で入る。閉じて開き直しても同じ並び |
| 仲間の戦闘の数（`319_` 版15） | 仲間の手の錨が「max_hp ＋ 2×√(能力 × 武器) × 率」、被弾の防御が「`get_npc_defense` ＋ 防具 × 率」で式どおり |
| 書く役の一本化（版16） | 装備欄から主人公側へ直接引いた品は主人公に 1 つだけ渡り、`equipments` を書くのはこの MOD だけ（402_ は `left to the equipment slots` を残して手を引く）。渡した品は次に開いたとき控えに居ない |
| 審判への部位（版17・`401_` 版8） | 審判への文に主人公の枠と仲間の部位ごとの行（名前(説明)と属性）が載り、`item_id=` だけの行が消えた |
| 自由枠に入る・入らない（版26、10-18） | 胴鎧を自由枠へ引くと入り（`equipped … at (0, 8)`）、拳銃は弾かれて所持品へ戻った（`rejected: back to inventory`）。胴が埋まった状態で買ったマントを右クリックの「装備」で入れると自由枠へ（`popup equip … -> free1`）。64x64 の服の絵も崩れない |
| 自由枠を能力値に数えない（版26、10-18） | 防御 298 の胴鎧を自由枠に置いても Def は +123（装飾のピン）のまま、`wearable` もピン。合算を入れても 123（胴に移すと 298 ＋ 123 × 10% ＝ 310.3）。題の画面から読み直しても、自由枠のマントは残り、数えない |
| 仲間の自由枠（版26、10-18） | `402_` の受け渡しの窓で、リュウの装備欄に自由×2 を含む10部位が並んだ |

## 分かったこと（作りに効いた順）

- 装備欄の辞書は、装備欄のグリッドの持ち物の辞書でもある。本体はドラッグで品を出すとき、そこから抜く。
  装備欄から主人公側へ引いた途中で、窓口 `combat.equipped` が False を返した（引いた辞書は画面の装備欄と同じ物で、
  ドラッグ中の品はどの装備欄の辞書にも居なかった）。402_ は None かどうかしか見ないので動きは変わらず、
  右クリックの文字（ドラッグしていない時に決まる）にも響かない
- 主人公の品を仲間の装備欄へ直接落とすと、装備はされず仲間の持ち物へ渡る。
  置けない（`not this owner's item`）が、
  本体はその落とし先のグリッド（持ち主は仲間）へ `change_inventory` を呼ぶので 402_ の受け渡しが走り、
  この MOD が仲間の持ち物の窓へ戻す。もう一度落とせば装備される。辞書と持ち主の食い違いは無い
- 装備欄の品は持ち物の辞書に居ないので、`equipments` の id から引く読み手は名前を引けない。
  版16 までの `401_` は仲間の装備を `wearable: item_id=…` としか書けていなかった（戦闘の数は装備欄から直に出すので効いていた）。
  窓口 `combat.gear` で身に着けている品を答え、`401_` が部位ごとに書く形にした（版17）
- 仲間の装備欄のグリッドは持ち主が仲間なので、402_ の受け渡しの同期も走る。
  装備欄から主人公側へ引くと、
  402_ が本体の `Item.unequip()` と参照の掃除で `equipments` を外し、その後この MOD が品を仲間の持ち物へ戻していた
  （主人公へ移した品が仲間の持ち物にも残る。試験で再現）。402_ は窓口の答えを見て手を引き、
  この MOD は別の持ち主へ渡った品を戻さない（版16）
- 所持品の窓は本体の別の経路でも閉じられる。
  会話に入る・ロード・タイトルへ戻るで窓が消えるとき
  `toggle_center_inventory_visibility` は通らず、隠した右側の選択肢が隠れたままになった。選択肢が組み直されるたび
  （`refresh_choice_buttons`）とロード・タイトルの後に、窓が開いていなければ戻す（版15）
- 本体は品を固定の単位（65px）で置く。
  マスを縮めて 1080p に収めようとしたら、絵が枠からはみ出した。
  マスは所持品と同じ大きさにしか出来ないので、余白を詰めて画面に収める（版14）
- 本体の unequip は渡された品の種類の枠を無条件に落とす。
  装備欄の胸当てを付けたまま、所持品の別の指輪を
  本体の popup で「外す」と `equipments["wearable"]` ごと消え、画面上部が `Def:0(+0)` になった。
  本体の Manager が MOD 以外の経路で走ったら次のフレームで、また戦闘の1手ごとにも装備欄から組み直す（版12）
- 品の実体を持つ辞書はプロセスに1つで、控え（位置）は世界ごと。
  別の世界をロードすると、前の世界の
  品が「控えに無いのに辞書に残っている品」として新しい世界の所持品へ返された。辞書に世界の鍵を添え、
  鍵が変わったら空にする。セーブへの合流も、書き出すセーブの世界名が辞書の世界と違えば行わない（版8）
- 右側の選択肢は `hud.right_buttons`（入れ物は `right_button_layout`）。
  本体も `right_button_layout.opacity` を 0 に
  しているが、ボタン（枠は各ボタンの `canvas.after` の矩形）はそのまま描かれる。ボタンごとの
  `opacity` なら消える。押せなくするのは入れ物の `disabled`（子の値を変えずに継承で効く）
- 注入し直すと、今の版が包まなくなった対象に古い世代の包みが残る。
  `equip_item` の包みをやめた後、古い包みが空の控えで `weapon -> None` を書いた。`--unload` してから注入し直す
- 品の説明窓（`ItemDetailBox`）は、カーソルの下から品が消えると閉じず残る。装備欄を片付けるときと
  品を移し終えたときに消す
- 装備中の品を持ち物の辞書から抜くなら、その辞書は MOD のモジュールに置いてはいけない。
  注入を剥がして戻すとモジュールが読み直され、品の参照ごと消える（4 品を失いかけた）。
  `sys` の属性に置き、念のため窓を開いたとき同じプロセスに残っている品（持ち主がプレイヤーで、
  どの辞書にも居ない `Item`）を1度だけ拾い直す
- 持ち物へ戻った品の `grid_pos` が装備欄の座標のままだと、本体の `place_existing_item` は確かめずに
  置くので他の品の下に隠れる（`108_` と同じ）。窓を組む前に所持品の範囲で重なりとはみ出しを直す
- **本体は持ち物の辞書を回している最中にセーブを呼ぶ**（戦利品の窓を組む途中で `save_game`）。
  セーブのために生きている辞書へ足すと `dictionary changed size during iteration` で落ちた（戦闘後の「漁る」）。
  合流は書き出す JSON の側で行う（`write_obfuscated_json_file` の `data['player_data']['inventory']`
  へ `Item.to_dict()` を足す。`__main__` へ複製された名前はローダの alias 再束縛が張り替える）
- 合算の値は、最高値の品が変わらないドラッグでは描き変わらなかった。
  本体は `status_texts` が変わったときだけ
  見張りを呼ぶ。装備欄が変わるたびに見張りを直に呼ぶ（版10）

## 決めた仕様（再検討しない）

- 本体へ渡す `equipments` は攻撃・防御ともに最高値の1つだけ。合算は設定で入れる別の機能で、
  「最高値はそのまま、残りは圧縮して足す」の形（版9）。却下した形: 係数の合計を 1.0 にする重み付き平均
  （1品だと今より下がり、空の部位が罰になる）、純加算（`319_` の軽減が 1,200 で上限に張り付き、
  差を出すには `319_` の式を変えることになり、敵の防御の帯まで動く）
- 右手・左手は武器と盾のみ。他の部位は DOC.md の表のとおり
- 装備欄は所持品とは別枠で品を持つ。ドラッグと右クリックの両方で装備できる
- 部位の大きさは所持品と同じマスで、頭・腕・脚・装飾は 2×2、手と胴は 2×4（武器は最大 1×4）。
  配置は DOC.md の図のとおり。グリッドは 6×10。部位の外のマスは見せず、全体を所持品の窓と同じ外枠で囲む
- 部位より小さい品は縦横比を保った整数倍で部位いっぱいに広げて表示し、部位の左上に寄せる。
  占有するマスは品の本来の大きさのまま（受け入れの判定は部位単位なので見た目だけの話）
- 1つの部位に1つ。同じ種類の品を居る部位へ落とせば置換（居た品は所持品の空きへ。空きが無ければ置換しない）。
  右クリックの「装備」は空いている部位が無ければ右手（1つ目の装飾）と入れ替える
- 装備中の品は持ち物の辞書に居ない。合流はセーブの間だけ
- 装備欄の品は本体の窓の `FloatLayout` に置いたまま（移し替えない）。装備欄は窓より下に描く
- 持ち主ごとに scope（辞書・控えの鍵・窓の場面）を持つ。主人公は所持品の窓（場面なし）、仲間は 402_ の
  受け渡しの窓（場面 `party_transfer`）。辞書はどちらも `sys` に置く
- 同行する仲間にも装備欄を付け、数（攻撃・防御）にも効かせる。公式が NPC に武器を参照させない理由は
  「審判の文脈に全員の装備を書くと小規模モデルで壊れる」で、数の側の理由ではない（配信の回答）。
  文脈は `401_` が文字数の予算で抑えている。組み立てはローダの窓口 `combat`（TECH.md §3.3.5）に
  この MOD が人物ごとの値を置き、`319_` と `401_` が聞く形。仲間の `equipments` を書く役はこの MOD の 1 本
- 仲間の錨と防御は率で足す（`319_` の `ALLY_GEAR_PERCENT`、既定 50%）。「大きいほう」は却下
  （仲間の素の値が装備の式より常に大きく一度も効かない）
- 審判への文には主人公の装備欄も含める（本体が渡すのは武器1つと防具1つだけ）

## 合算の検算（版9。式を決めるときの数）

帯は実測の品から（value 12 → 防 59、27 → 攻 116、62 → 防 275、70 → 攻 312、76 → 防 407〜456・攻 401〜480）。
攻撃の倍率は能力値に依らず √(新 ÷ 今)。攻撃 50%・防御 10% のとき:

| 帯 | 場面 | 攻撃 今→新 | 防御 今→新 | 軽減 今→新 |
|---|---|---|---|---|
| 序盤 | 最高＋同格を全部位 | 40→60（×1.22） | 60→96 | 7%→11% |
| 中盤 | 最高＋同格を全部位 | 245→368（×1.22） | 275→440 | 26%→35% |
| 中盤 | 最高＋序盤のゴミを全部位 | 245→256（×1.02） | 275→287 | 26%→26% |
| 終盤 | 最高＋同格を全部位 | 580→870（×1.22） | 500→800 | 38%→50% |
| 終盤 | 現実的な全部位（500＋439・300・300・250・500・200） | | 500→699 | 38%→47% |
| 終盤 | 最高＋序盤のゴミを全部位 | 580→592（×1.01） | 500→512 | 38%→39% |

- 乱数 2 万通り（1〜7 品、値 1〜600、率 5〜50%）で、結果は必ず最高値以上・最高値 × (1 ＋ 率 × 6) 以下。
  1 品外して上がらず、1 品を強くして下がらない
- `319_` の上限 60%（防御 1,200）に届くのは防御の率 23.3% 以上のときだけ
- `319_` の数に落とすと、終盤の上限で与ダメ ×1.22・被ダメ ×0.81。帯 1 段（普通→強 ×1.5）や
  レベル差（×2〜3）より小さい。雑魚 HP 600 が 3 発→2 発、ボスの極 1,350 が 675
- 帯をまたぐゴミは効かない。「ゴミにも一応の価値」は同じ帯の中でだけ出る
