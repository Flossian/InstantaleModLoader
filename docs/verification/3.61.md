# 3.61 ロードすると背景が別の場所になる（ローダの `modfacility`）: 実機2回で成立・再発を止める網を追加

報告は「ロードセーブすると、背景が別の場所になっている」。

セーブにはいま見えている絵のフルパスが焼かれ（`game_variables["location_image"]`）、
ロードはその絵をそのまま出す（GAME.md §2.3）。
`modfacility` はここを2箇所で空にしていた。

| 箇所 | 空にしていた場面 |
| --- | --- |
| `swap_background`（保存の間） | 移した先の絵がまだ無いとき |
| `repair_player_location`（ロードの救済） | 入口へ直すときは常に |

空にすればゲームが描き直す、という前提で書いてあったが、**これは測っていない**。
描き直さないなら、ロードは前の画面の絵のまま始まる（立っている場所とは別の絵になる）。

報告の回のログ（`out\real_estate.log`）では救済が走っている。
セーブの立ち位置が `mod:331_facility_investment:6-1`（道場）で、
その時点ではまだ建て直されていなかったため、入口 172 へ直り、
絵はここで空にされた。入口の絵は世界の側に既に在る。

**直した内容**: 入口へ直すときも、いまの絵と同じ並びで名前だけ入れ替えて据える
（`picture_beside`。保存の側と同じ引き方）。引けないときだけ空。
オフラインは `test_modfacility.py` の「救済」に3項目追加して通っている。

## 実機1回目（道場の中でセーブ）

| # | 見たこと | 結果 |
|---|---|---|
| 1 | タイトルから続きから | 道場の**中のまま**（立ち位置は守られた）。**背景は繋ぎ先の区画のもの** |
| 2 | ゲーム中のロード | 同じ。中のままで、背景は繋ぎ先の区画のもの |

救済は走っていない（どちらのロードもログに行が無く、`inside=mod:331_facility_investment:6-1`）。
**絵はセーブに焼かれた時点で既に区画のものだった。**
そのセーブの中身は、立ち位置 `mod:331_facility_investment:6-1` に対して
絵が `backgrounds\<区画名>\image.png`。

手元の7つのセーブで立ち位置と絵を突き合わせると、素の施設に立っている5つは全て一致していて、
食い違っていたのは MOD の施設の1つだけだった（GAME.md §2.3）。
**ゲームは `mod:` の施設に入っても `location_image` を更新しない**、と読める。

**直した内容（2つめ）**: 中のまま保存するときも、絵をその建物のものに据え直す
（`keep_inside_background`。立ち位置も選択肢も替えず、絵だけ）。
建物の絵がまだ世界に無ければ触らない。
オフラインは `test_modfacility.py` に4項目追加して通っている。

## 実機2回目（同じ道場）: 通った

道場の中でセーブ → タイトルから続きから・ゲーム中のロードのどちらも、
中のままで**背景がその道場のもの**になった。
セーブの絵も `backgrounds\<道場名>\image.png` で立ち位置と揃っている。
ログは `save: the background was the place we came from; saving '<道場名>'`。

**直した内容（3つめ。再発を止める側）**: 経路ごとに直すのをやめ、
書き出しの直前に網を1枚置いた（`keep_saved_background`。TECH.md §5.8）。
焼かれる絵のフォルダ名が立ち位置の施設名と違えば、その場所の絵に差し替えて書く。
どの経路が取りこぼしても、セーブに食い違ったまま残らない。
手元の7セーブで空回しして、正しい5つには触らず、
食い違う2つ（入口と出口の対）も絵が無いので触らないことを確かめた。

**実機で見ること**（網が効いているかは、直る側ではなくログで分かる）:

1. 入口へ移して保存する建物（`keep_inside` を名乗らない層）で、
   入口に立たされたとき背景がその入口のものか
2. 絵がまだ生成されていない場所でセーブしたとき何が出るか
   （空にするしかない唯一の場面。ゲームが描き直すかはここで分かる）
3. `save: the picture was … but the place is …` が出たら、
   その経路がまだ取りこぼしている（網が拾ったという記録なので、出ること自体は不具合ではない）

**別件で見えたこと**（まだ直していない）。
起動直後のロードでは、救済（`World.__init__` の中）が層の建て直しより先に走っている。
報告の回のログは 救済 → 330 が建てる → 331 が建てる の順で、
`331_` は `keep_inside` を名乗っているのに、中に立ったまま保存した位置が失われている。
ゲーム中のロードでは建て直しが先に済んでいて救済は走っていない。
