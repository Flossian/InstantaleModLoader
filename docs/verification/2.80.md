# 2.80 立ち絵の高画質化と顔の検出。版1〜10 の経緯（`131_`）

`131_sharp_portrait` を1日で版10まで回した記録。
踏んだ壊れ方（生成が止まる・差し替えが捨てられる・顔がずれる・やり直しが拒まれる）と、
その根拠になったログ・ファイルの寸法を残す。
小見出しの番号（§2.80.1〜§2.80.5）はこの節の中を指す。
今の作りと残りは VERIFICATION.md §3.43。

## 2.80.1 版1〜版6で踏んだこと

版1: NPC の生成が止まった。
`orig` を呼ばずに、渡された画像の写しを1枚返していた。

```text
out\image_no_pixelate.log  キャラクタ: 素通し 512x1024 RGBA（1回目）
out\live_crashes.log       THREAD CRASH: Thread-88 (generate_images)
  TypeError: cannot unpack non-iterable Image object
    instantale.py:3624                ConversationStartManager.generate_images
    instantale.py:2206                InstantaleApp.generate_and_write_character_detail
    image_generation_creature.py:120  generate_character_image
```

ゲーム側は `a, b = pixel_art_process(...)` の形で受けている。
戻り値の形を1枚と決め打ちしたのが誤り。
生成はバックグラウンドスレッドなのでゲームは落ちず、
画像が書かれないまま `wait_generate_chracter_image` が待ち続けた。

版2: 落ちなくなったが、絵は荒いままだった。
「入力と同じ寸法の画像」だけを差し替える作りにしたところ、
差し替えていたのはゲームが捨てる側だった。

```text
キャラクタ: 差し替え 1枚 入力 512x1024 / 戻り (512x1024、165x330)
減色:      差し替え 1枚 入力 330x660  / 戻り 330x660
キャラクタ: 差し替え 1枚 入力 330x660  / 戻り (330x660、16x32)
```

`pixel_art_process` の戻り値は `(入力そのまま, 縮めた絵)` で、ゲームが使うのは2つ目。
1つ目を差し替えても保存されない。
減色の段も、入力（既に潰れた 330x660）の写しを返していたので、
16色への減色を飛ばしただけで細かさは戻らなかった。

版3は戻って来た画像を全部元の絵から作り直し、
減色の段には1つ手前の元の絵をスレッドごとに控えて渡す。

版4（実機で通った後）: 測った形に畳んだ。
実機8回で形は毎回 `(入力そのまま, 縮めた絵)` だったので、
`big, small = orig(...)` と受けて2つ目を作り直す形にした。
形が違ったときの落とし方は `safe=True` が持っている
（`orig` を呼んだ後にフックが投げると、ローダが `orig` の結果をそのまま返す。
`patch._guard`）。
自前の見分けと警告は、その落とし方を二重に書いていた。
本体は 139 行から 32 行に、設定は4つから1つになった。

版5: 枠ごと通さない。
版3・版4は 165x330 / 330x660 という枠をゲームのまま残し、その中身だけを
作り直していた。上限が 330x660 になるのはそのため。
枠を残す理由は無かった（縮小と減色は絵を荒くするためだけの工程で、
後段はどの寸法でも受ける。§2.80.5）。
版5は2つの工程をどちらも呼ばず、入って来た絵をそのまま返す。
立ち絵は 512x1024 を2倍に伸ばした 1024x2048（2倍の段は包めない位置にある）。
顔が見つからなかった回の縮小だけは、ゲームのものを呼ぶ。
元の工程を呼ばないので、戻り値の形が変われば版1と同じ止まり方をする。
そのときは版4（`orig` を呼んで形を見る）へ戻す。

版6: 2倍も戻す。
版5の立ち絵は 1024x2048 で 5MB だった（§2.80.3）。最近傍の2倍は情報を足さない。
減色の包みで、縮小に入って来た絵（スレッドに控えたもの）を返すようにした。
立ち絵は `no_bg_image.png` と同じ 512x1024 になる。

## 2.80.2 版3が実機で通った（NPC 4体）

`out\sharp_portrait.log`（当時の名前は `image_no_pixelate.log`）。4体とも同じ形で通り、
`out\live_crashes.log` にクラッシュは増えていない。

```text
顔の検出: 入力 512x1024 RGBA / 座標 None（1回目）
顔の検出: 入力 512x1024 RGBA / 座標 None（2回目）
キャラクタ: 2枚 作り直し 元絵 512x1024 / 入力 512x1024 / 戻り (512x1024、165x330)
減色:      1枚 作り直し 元絵 512x1024 / 入力 330x660  / 戻り 330x660
キャラクタ: 2枚 作り直し 元絵 330x660  / 入力 330x660  / 戻り (330x660、16x32)
```

| 見たところ | 結果 |
| --- | --- |
| 控えが渡っている | 減色の `元絵` が毎回 512x1024。立ち絵 330x660 の中身が元の絵から作られている |
| 縮めた側も作り直している | `キャラクタ: 2枚`（1つ目 512x1024 と2つ目 165x330 の両方） |
| 寸法はどこも変わっていない | `pixelated_image_original.png` 165x330 / `reduced_color_image.png` 330x660。素と同じ |
| 生成が止まらない | 4体とも通し。`generate_images` のクラッシュは版1が最後 |
| ファイルの嵩 | `reduced_color_image.png` 172〜267KB（素は 323KB、版2は 538KB）。16色の点描が消えたぶん小さい |

顔が小さくなる回は、この MOD より前で決まっている。
`detect_face_coordinates` は素の 512x1024（`generated_image.png`）に対して走り、
`None` を返すことがある。
走る時刻はこの MOD が最初に触るより 1.3 秒前で、入力はこの MOD が一度も触っていない絵。
顔の失敗はゲーム自身の挙動。
4体のうち3体が `座標 None` で `face_image.png` は 32x64
（見つからなかったときの落とし所。`pixel_art_process` の2つ目 16x32 を2倍にしたもの）、
1体は 165x165（見つかった）。
この記録は版3の `detect_face_coordinates` の包み（何も変えず座標を書くだけ）で採った。

### 確認手順

1. デバッグモードは要らない。注入して、まだ絵の無い NPC と会話する
2. `out\live_crashes.log` に `generate_images` のクラッシュが増えていないことを見る
3. `out\sharp_portrait.log` を読む（各行の意味は `131_` の DOC.md）
4. `worlds\<世界>\characters\<名前>\` の `reduced_color_image.png` と `face_image.png` を開く

版4までのログは形が違う（`キャラクタ: 2枚 作り直し 元絵 ... / 入力 ... / 戻り (...)`）。

## 2.80.3 版5〜版10 の実機

版5（`character_generation_quality` を `highres` に切り替えた状態。1体）:

```text
縮小: 512x1024 をそのまま通す
減色: 1024x2048 をそのまま通す
縮小: 1024x2048 顔の代わりを作る回なのでゲームに任せる
```

| ファイル | 寸法 | 大きさ | 見たところ |
| --- | --- | --- | --- |
| `no_bg_image.png` | 512x1024 | 606,181B | |
| `pixelated_image_original.png` | 512x1024 | 606,181B | `no_bg_image.png` と同じ。素通しが効いている |
| `reduced_color_image.png` | 1024x2048 | 5,071,081B | 立ち絵。ゲームが2倍にしたまま減色を通さずに保存された |
| `face_image.png` | 32x64 | 2,262B | 顔が見つからなかった回。ゲームの落とし所どおり |

- 素通しも旗も成立。生成も止まっていない（`live_crashes.log` に増分なし）
- 2倍に伸ばす段は `character_generation_quality` とは別。
  あの設定が変えるのは SD の段（256x512 → 512x1024 の描き直しをするかどうか）で、
  縮小の後の2倍はゲームのコードに固定されている（§2.80.1 の「包めない位置」）
- 立ち絵が 5MB。最近傍の2倍を PNG にするとこの大きさになる

版6（1体）: `減色: 1024x2048 を控えの 512x1024 に戻す` が出て、
`reduced_color_image.png` が `no_bg_image.png` と同じ 512x1024・758,304B で保存された。
版5で 5MB だったものが 758KB。
ここまで6体すべて `座標 None` 側で、顔が見つかった回の切り出しは未確認だった。

版7（2体。顔が見つかった回）: `顔: ゲームが見つけた (102, 14, 358, 270)` の後、
`face_image.png` は 165x165 だが左上にずれていた（頭巾と髪だけ／白地の右下に顔の端）。
顔の箱は 330/512 の定数で縮められている。
戻り値 `(147, 17, 403, 273)` を 330/512 倍すると `(95, 11, 260, 176)`。
これを 512x1024 の立ち絵に当てると、顔の左上 1/3 しか入らない。
「立ち絵の幅 ÷ 検出した絵の幅」の推定は外れ。

版8（4体）: `顔: (94, 21, 259, 186) を (146, 33, 402, 289) に戻して切り直した` で
`face_image.png` が 256x254 / 256x256、顔の位置に合っている。決着。
ゲームが縮めた箱は検出の戻り値の 330/512 倍そのもので、戻せば元の座標に一致する。
254 は、ゲームが縮めた箱が整数に丸まっていて（一辺 165 と 166 が混ざる）
四隅を戻すと 1〜2px ずれるため。
中心を戻して一辺 256 の正方形に組み直す形に直した（実機未確認だが差は 2px）。

版9（「立ち絵を荒くしない」を切って1体）:
`縮小: 512x1024 ゲームのまま` / `減色: 330x660 ゲームのまま` で、
`pixelated_image_original.png` 165x330 / `reduced_color_image.png` 330x660 /
`face_image.png` 165x165（顔の位置に合っている。切り直しはしていない）。
切った側は素のゲームの経路をそのまま通り、顔の換算も素のまま合う。決着。

版10（やり直しが初めて拾った）:

```text
顔: ゲームの呼び方 {'cascade_path': 'runtime/models/face_recognition/lbpcascade_animeface.xml'}
顔: ゲームは見つけられず、均一化 + haar で拾った (113, 48, 369, 304)（箱 (201, 136, 81, 81)）
```

`face_image.png` 165x165 が顔の位置に合っている。決着。
ゲームはカスケードをフォルダ付きで渡していて（1回目の呼び出しから）、
版7〜9の呼び直しは素のファイル名を渡していたので読めずに `None` になっていた。
ゲームの1回目（anime）が外れた 92ms 後にやり直しが haar で拾い、
ゲームの2回目は呼ばれていない（ログに `ゲームが見つけた` が無い）。

「立ち絵を荒くしない」側でも `顔: ゲームは見つけられず、均一化 + lbp で拾った` →
`顔: (79, 10, 244, 175) を (123, 16, 379, 272) に戻して切り直した` の並びで
`face_image.png` 256x256 が顔の位置。やり直し → 切り直しの繋ぎも決着。
2体とも lbp の側で拾っている（1体は CLAHE、1体は均一化）。

## 2.80.4 顔の検出の精度（手元の 364 体で測った）

`face_image.png` が全身の縮小（幅の2倍が高さ）なら「見つからず」と数えられる。

| 世界 | 体 | 見つからず |
| --- | --- | --- |
| 世界F | 45 | 1（2%） |
| 世界D | 111 | 10（9%） |
| 世界E | 83 | 11（13%） |
| 世界G | 56 | 12（21%） |
| 世界B | 15 | 5（33%） |
| 世界H | 54 | 19（35%） |
| **計** | **364** | **58（16%）** |

実機の6連続の失敗は運が悪かった側で、素の外れ方は 16%。世界（画風）でかなり差がある。

### ゲームの検出の再現（校正）

`generated_image.png` に OpenCV のカスケードを掛け、ゲームの結果と突き合わせた。

| 条件 | ゲームと一致 |
| --- | --- |
| `lbpcascade_animeface` 1.1/3 だけ | 68% |
| `haarcascade_frontalface_alt` 1.1/3 だけ | 同程度 |
| **anime → haar の順（1.1/3）** | **93%** |

ゲームは検出を1体につき2回呼んでいる（§2.80.2 の記録。40ms 間隔）。
anime で外れたら haar、の順と読むのが一致率の根拠。
入力は `generated_image.png`（`no_bg` の α を黒・白・無視にしてもこれを上回らない）。

残る 7% は、ゲームの関数が箱を何かしら絞っているぶんと見ている。
絞り無しの「一番大きい箱」だと、ゲームが外した絵でも靴や鎧の小さな箱を拾う。
MOD の位置の絞り（下記）を掛けると、ゲームが外した絵では素の状態で何も拾わない
（世界B の5体で確認）。

### 前処理で拾い直す

外れた 58 体に、座標系を変えない前処理を掛けて同じ検出（anime → haar、1.1/3）を掛け直した。
位置の絞り（箱の中心が上から 40% 以内・幅が 8〜60%・一番上の箱）を入れた数:

| 前処理 | 拾えた（58 体中） |
| --- | --- |
| 均一化 | 29 |
| CLAHE | 26 |
| ガンマ 0.6 | 29 |
| ぼかし 3x3 | 31 |
| **順に試して** | **42** |

拾えた 42 体の切り抜きを一覧にして目で見た。
顔でないものが 4（暗い鎧・肩章・暗い服・金色の装飾）。残り 38 は顔。
位置の絞りを入れる前は 50 拾えて 13 が顔ではなかった（靴・帯・花・鎧）。
絞りで拾いが 8 減り、誤りが 9 減る。

感度を上げる側（`scaleFactor 1.05` / `minNeighbors 2` / 2倍に拡大）は
拾いは増えるが、既に見つかっている側の箱まで別のものに変わる（一覧の「妥当」が 302 → 277）。
ゲームが見つけた回には触らず、外れた回だけやり直すのはそのため。

## 2.80.5 同じ目的の道具が既に手元で動いていた

`InstantaleHDPortraitScript`（`hd_portrait.ps1`）が、
ゲームが立ち絵を書き終えた後に `reduced_color_image.png` を `no_bg_image.png`（512x1024 か 640x1216）で上書きし、
元のドット絵を `reduced_color_image.orig.png` へ退避する。
手元の立ち絵 363 体のうち 359 体が `.orig.png` 付きの 512x1024 / 640x1216 で、330x660 はこの MOD だけで作った4体。

あちらは枠ごと差し替えるので SD が描いた寸法がそのまま出る（この MOD の上限は 330x660。§2.80.1）。
この MOD の 330x660 はあちらの「適用済み」の判定（大きさと更新時刻の一致）に当たらないので、両方動かせば上書きされる。
この MOD にしか残らない持ち分は `face_image.png` と `pixelated_image_original.png`（PortraitWatcher は顔を切る段に間に合わない）。
立ち絵だけが目的なら PortraitWatcher で足り、顔まで滑らかにしたいならこの MOD を残して立ち絵はあちらに任せる。
