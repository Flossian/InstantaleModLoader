# 3.117 街ごとの依頼の難易度の範囲（`922_town_quest_difficulty`）: 探す経路は実機で成立・初訪問の3件は検査まで

2026-10-31 に作った。
きっかけは、世界の一括生成やエディタで足した9番目より後の街の依頼が、1〜76 の全域から引かれること（GAME.md §2.9）。
開始の隣の村でレベル70の依頼が出る。
街ごとに範囲を決める画面と、道に沿ってなだらかにする計算を持つ MOD を作った。

## 決めた仕様

- すでにある依頼は書き換えない。これから作られる依頼だけを、ゲームが数を引く所で差し替える
- 差し替えるのは2か所（GAME.md §2.9）
  - 初訪問の3件: `write_area_data_to_world_dict` の中の `random.sample(range, k=3)` の最初の1回
  - 探した1件: `generate_random_quest` の中の `random.randint` の最初の1回
- 引いた値はゲームがそのまま LLM への指示と記録へ渡すので、セーブ・指示・`318_` の素の値が同じ数になる。
  作った後で書き直す形は採らない（318 は作った直後の値を素の値として控えるので、包みの順番を取り合う）
- 範囲は世界ごと（`state\town_quest_difficulty\<世界名>.json`。設定画面が書き、本体は読むだけ）。
  同じ世界でキャラクターを作り直しても効く
- 範囲は両端を含み、幅は3以上（初訪問の3件は重ならずに引くため）。上限は設定「範囲の上限」（既定 76、100 まで）
- なだらかにする: 固定した街と、開始の街・開始から最も遠い街を錨にした調和補間（各街の中心＝つながる街の中心の平均）。
  錨を固定した街だけにすると、行き止まりの街が隣と同じ高さに平らになる（10-31 にヴェスティアの道で試算。
  id 0〜8 をゲームの範囲で固定して残りを均すと、行き止まりの id 12・13 が 46・42 になった）
- 範囲は窓口 `quest_bands` に出す（TECH.md §3.3.25）。`133_` 版5は訪ねる前の街の推定をそこから引く

## 測ったこと

10-31、テストワールド（控えを取って試し、後で戻した）。

1回目は `225_` 版9で「クエストを探す」の窓の乱数を録った（id 8 のアビス）。

```text
乱数: randint(67, 76) -> 75 caller=DisplayQuestChoice.generate_random_quest (instantale.py:5957)
頼み文: random_quest_generator difficulties=[75] caller=DisplayQuestChoice.generate_random_quest (instantale.py:5960)
search: 頼み文へ渡す難易度 75 -> 85            （318 の +13）
```

窓の中の乱数は、この `randint` のほかに一時ファイルの名前（`tempfile` の `choices`）と、依頼の土地の BGM の `choice` だけだった。

2回目は 922 を入れ、id 8 に 20〜24 を決めて探した。

```text
探す: 土地 8 randint(67, 76) -> 20〜24 を引いた 24          （out\town_quest_difficulty.log）
search: 頼み文へ渡す難易度 24 -> 37                           （318）
search: 土地 8 依頼 37 難易度 24 -> 37（素 24 + 13）           （318）
```

セーブの依頼37の `difficulty` は 24（ゲームが自分で書いた値）。
生きた一覧は 318 が乗せた 37。
