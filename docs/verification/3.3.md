# 3.3 パーティ関係（`302_` の残り / `303_` / `304_`）

> `303_` と `304_` は同じ場面に手を入れる。
> 既定では `304_`（解散しない）が勝つので、`303_` の手順を踏んでも `303_` の行は出ない。
> `303_` を確かめたいときは先に `304_` のファイル名の頭に `_` を付けて注入し直すこと。

**`302_` の残り**は、土地を跨いで別れた場合（いまの町のギルドへ置く経路）が未実測。
`leave: ... [guild of the current area (left home behind)]` が出るのを見る。

> 決着済み: 「別れる選択肢が出ない」は `original_party` の読み違いだった。
> 「入っていたら断る」で毎回断り、「控えと名簿が食い違えば差し替え中」に変えたら雇用直後に消えた。
> `original_party` は差し替えの控えであって「差し替え中の印」ではなく、雇用にも追随しない。
> 判定には使わず記録だけ残す（守りたかったクエスト中は `current_quest_data` で既に断っている）。
> 意味を確かめていないフィールドで機能を止めない。確かめていないものは「記録」に回す。

`303_` は置く側そのものが未発火。
仲間を連れてクエストに行き、かつ**雇った町とは別の町で**終える必要がある。

1. A の町で NPC を雇う → B の町へ移動 → B のクエストをクリア
2. `party_leave.log` に `quest-end: '<名前>' (<id>) left the party in <B> ... -> '<B のギルド>'`
3. 続けて `leave facility via ...`（第1層）か `'<A のギルド>' -> '<B のギルド>'`（第2層）
   のどちらが出たかで、ゲームが `get_party_leave_facility` を使っているかが確定する
4. 画面に `<名前>は<B のギルド>に留まることになった。` が出て、B のギルドで再雇用できる
5. `nobody moved ... placing them by hand` が出たら第3層まで落ちている ＝
   置き直しの経路が前提と違う。その状況を残すこと

**`304_` は実機で成立済み**（[§2.50](2.50.md)）だが、次の3点は未確認のまま。

- 外した先に NPC がちゃんと居ること（`302_` の「ここで別れる」で
  `is leaving for real` が出て控えが落ちる経路。ここが壊れると NPC が世界から消える）
- ギルドや宿にその NPC が立っていないこと（`not placing ... anywhere` が出ているか）
- `WARN ... is not in __main__` / `WARN no code object resolved` が出ていないこと

`302_` は自前の解散以外の `remove_party_member` 呼び出しも記録する
（`remove_party_member('63') from <関数名> (<ファイル:行>)`）。
死別が起きればその経路も確定する。
