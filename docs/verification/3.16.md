# 3.16 店の品揃えの入れ替え（`312_`）: 前提が成立

前提（主の持ち物を空にすればゲームが初回と同じ経路で作り直す）は実機で成立した（§2.39）。
その後の実績は4店舗・入れ替え6回で `WARN not refilled` は0件。

確認手順は「店で何か売る → 30日以上進める → 同じ店をもう一度開く → `out\shop_restock.log`」。

| ログの行 | 意味 |
| --- | --- |
| `first visit: … (baseline only)` | 1回目。基準の日を控えただけ |
| `not due: … day=X last=Y` | まだ日数が足りない |
| `cleared:` → `restocked:` | 前提が成立。品揃えが入れ替わった |
| `WARN not refilled:` | 前提が外れた。品物は書き戻され、以後この MOD は空にしない。`tier:` が出ているかを見る |
| `tier: owner=… tier=…` | ゲームが渡した段。**1行も出ない**。理由が判明した。品揃えを作っているのは `set_item_from_world_data` ではなく `generate_item_in_shopping` で、`312_` はそちらを見ていない（§2.67 / GAME.md §2.13.1.2）。空にした後の逃げ道が段を要求するので、**逃げ道へ入ると段が引けないまま**になる |

残っている未確認:

| 未確認 | なぜ問題になりうるか |
| --- | --- |
| **入れ替えのたびに品数が減らないか** | 実測である店が 9→5、7→5、5→3。`restocked` 側だけ見ても落ちている。毎回同じ数を並べる保証は無い |
| 品揃えの質が来店ごとに偏らないか | 段はゲームが決めるので、同じ段が使われ続けると進行に対して据え置きになる |
| 主が店以外に持ち物を使っているか | 持ち物を丸ごと空にする。`inventory` を戦闘や会話で読む経路があれば影響する |
| `108_` との併用 | `108_` は降ろしたので、起きるのはデバッグモードのときだけ（§3.8.1） |
