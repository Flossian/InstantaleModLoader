### 無料の宿泊の前払いと引き落としが食い違う

自分の宿屋での無料の滞在は前払い（TECH.md §3.3.4）。
窓口に聞いた部屋の額を先に足し、ゲームが引いて元に戻る。
所持金は毎回最後に元の額へ戻る（`218_` の `gold 4648470 -> 4648470 (moved 0)`）が、引かれた額が窓口の額と合わない回がある。

```text
1ヵ月 1泊目  stay: prepaid 1000 for the room ('luxury_suite')
             WARN stay: the room cost 2000 but we prepaid 1000; corrected 1000
1ヵ月 2泊目  stay: prepaid 1000 for the room ('luxury_suite')   （WARN 無し）
3ヵ月        stay: prepaid 1000 for the room ('luxury_suite')
             WARN stay: the room cost 5000 but we prepaid 1000; corrected 4000
```

値札は `高級個室(1000円)`。
5000 は 1000×3 でも 1000×2 でもない。
`327_inn_quality` に金を触るコードは無く、`315_vacation_custom` は `price:` の行を出していない。
取った先は特定できていない。

次に測ること: よその宿屋で同じ部屋・同じ月数に払って泊まり、ゲーム単独の引き落としが月数でどう動くかを見る。
`settle_room` は区間で他の MOD が金を動かせば巻き込む作りなので、所持金の変化をその場で録る probe が要る。

## 設計の根拠（実セーブ6世界）

語彙はゲームのもの（種類は `facility_type`、等級は `tier`、規模は `area["size"]`）。
施設を数えると `inn` 52・`colosseum` 6・`training_facility` 4 で、`tier` は `basic` / `standard` / `advanced` の3語だけ。
`config` は `{"level_of_detail": 0}` だけで、`owner` は主の id、主の `job` は `facility_type` と同じ語（GAME.md §2.13.1）。

種類ごとの最低の規模は 56 街（村19・町25・都市12）を数えて決めた。

| | 村 | 町 | 都市 |
| --- | --- | --- | --- |
| `inn` | 0〜1 | 1〜2 | 0〜2 |
| `colosseum` | 0 | 0〜1 | 0〜1 |
| `training_facility` | 0 | 0〜1 | 0〜2 |
| `general_store` | 1 | 1〜2 | 1〜2 |
| `specialty_shop` | 0〜1 | 1〜3 | 1〜2 |
| `blacksmith` | 0〜1 | 1〜2 | 1〜2 |

道場と闘技場の最低の規模は「町」（村には無い）。
軒数は種類ごとではなく、その街に建てられる合計（村1・町2・都市3）で、この MOD で建てた分だけ数える。
種類ごとに上限を持ちゲームの施設まで数えた形では、宿屋も雑貨店も1軒ある村に何も建たなかった。

## 実機で成立したもの

| 何 | どこまで |
| --- | --- |
| 窓口と出資 | 村・町・都市の役場に「施設の建設（出資）」が出て、建てられない種類も含めた条件が並ぶ。村では道場と闘技場が並ばない |
| 建物と道 | 入口の下の区画の1つに繋がり、建て直しでも同じ区画。ロードで建ち直る |
| 主人 | 建てるときに生成 AI が建物の名前と主人を作り（`keeper: '<名>'（<category>）was made for …`、版26）、ロードでは聞き直さず帳簿から同じ人が戻る。`会話する` に並び、出資者として接する（好感度40、`conversation_starter` の profile に「出資者で、あなたにとっては雇い主」） |
| 宿屋 | `無料で泊まる` で宿代が戻り、暦はゲームの宿泊1回ぶん。終えた直後に選択肢が戻る。ゲームの `宿泊する` は自分の宿では伏せる（版40） |
| 闘技場 | `試合に出る` から `BattleEndInColosseum` まで通る。既に出た闘士を頼み文に足すと相手の名が変わる（`arena: N earlier fighter(s) told to the generator`、版13） |
| 店3種と道場 | ゲームの売買で品が並んで買え、ロードでも品が残る（版21）。訓練が動いて暦が3年進む |
| 売上 | 日数ぶんの売上が入り、受け取った直後に文言が変わる。溜まりは `HOLD_DAYS`（既定360日）で頭打ち |
| 保存とロード | 建物の中のまま保存して開ける。会話の途中も、会話相手の一覧を出したままも、その続きから再開する |
| 漏れ | `savedata.json` と `world_data.json` に `mod:` の施設と NPC が無い。書き出しの網の `WARN` も出ない |
| 新しい主人公 | 同じ世界で作り直すと建物も主人も道も無く、帳簿は別のファイル（版27） |

### 番号つきの確認（ソースから参照されているもの）

- #7d（ローダ）: MOD の建物の並びを素の施設（操作 → `出る` → `会話する`。GAME.md §2.2）に合わせた。
  MOD の建物にはゲームの `出る` が無いので、自前のボタンが `会話する` の後ろに落ちていた。
  `TAIL_CLASSES` で移動と会話の手前に入れる（TECH.md §5.8）。
  4種類とも狙いどおり。店 `['売買する', '会話する'] -> ['売買する', '売上を受け取る(2,156円)', '出る', '会話する']`、宿 `['宿泊する(3ヵ月)', '会話する'] -> ['無料で泊まる', '売上を受け取る(1,260円)', '出る', '会話する']`、闘技場も同じ形、自宅（`330_`）は `['滞在する', '保管庫をあける', '家から出る']`。
  `無料で泊まる` は伏せた `宿泊する` の場所に出す（`choices` の `replaces`）。
  1回目は2段の塗り直しで既に在る自前のボタンが動かず後ろに残ったので、ローダで伏せた場所へ動かすようにした
- #7e: `無料で泊まる` の長さが設定と合わなかった（版41 で直した）。
  月数に 1 を直接渡していた（`cls(app, 1, quality)`）。
  1 にした根拠の実測は 315 が週単位の回で、素の `3ヵ月` では本体は 3 を渡す。
  週単位なら 315 の関所が 7 日に縮めるので一致し、月単位のときだけ「払えば3ヵ月、無料なら1ヵ月」と食い違った。
  `218_` の `elapse_days(30)` は関所が縮める前の呼び出しで、進んだ日数ではない（最初これを読み違えた）。
  版41 で `durations.inn_stay(app)["months"]` を渡す。
  `months=3` → `init_args=['3', "'luxury_suite'"]` → `elapse_days(90)` → `3ヵ月泊まることにした。` で成立。
  330 の自宅も同じ形だった（[§3.62](3.62.md) #11）
- #10e: 試合の途中のセーブから再開すると `ColosseumMatchStart.execute` を通らない。
  2試合目の申し込みの直後にロード（`forgot 6 building(s)` → `restored 6 entr(y/ies)`）すると、相手の生成も申し込みの操作も無いまま戦闘に入った。
  控えの `snapshot.config` に `current_phase` と `enemy_data`（鍵は `"0"` のような str）が残る

## 作りに効いたこと

- 実行時に足した施設でも、中の選択肢はゲームが `facility_type` から出す（`inn` の `宿泊する` / `会話する`、`colosseum` の `試合に出る` / `観戦する`、店の `売買する`、道場の訓練）。この MOD が足すのは `売上を受け取る` と `無料で泊まる` と出口だけ
- 素データを施設 id で引く経路は、中に立っている間だけ写しを置けば通る（`modfacility` の `plain=True`）。売買の `KeyError`（GAME.md §2.28）と `ColosseumMatchStart.method` は同じ穴で、写しの前は試合のワーカースレッドごと死んだ。写しは保存の前に外れ、書き出しの直前にも網がある。宿屋は写しが要らない
- 画面の判定は足す側それぞれが持たない。部屋選び・会話の最中・会話相手の一覧の3回とも、同じ取りこぼしが別の場所から出た。ローダの `can_add_here` の1か所で決着（TECH.md §5.8）
- 相手が触る値を見に行く形は順序に左右される。「会話の最中は中のまま保存しない」を `in_conversation` の旗で見ていたが、`modnpc` が先に旗を落としていた
- 痕跡を消す手当ては素のゲームができることまで壊す。会話の途中の保存で相手と選択肢を落とし、ロードで会話が戻らなかった。3版追った末に消すのをやめた（いま話している相手だけ掃除から外す）
- 背景は MOD が描かない。ゲームは施設の名前で絵を引き、無ければ生成する。描いた覚えでゲームの描画口を止めていた頃は6件の不具合が出た（TECH.md §5.8）
- 周回の鍵は世界×主人公（`state.playthrough_key`。TECH.md §5.4）。世界名だけでは、作り直した主人公が前の4軒を受け取った。建物の id は周回をまたいで重なるので、`forget` は控えの写しも捨て、新築は写しを使わない
- 名前は鍵の hash で選ぶだけでは重なる（4軒で2人が同じ名）。生成 AI に作らせ、その世界で使っている名前を避ける

## オフラインで確かめたこと

`tools\tests\test_facility_investment.py` 263件。

実機ではローダの世代管理が防いでいる（TECH.md §3.5）。
