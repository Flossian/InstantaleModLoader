## 版5: SDK が外した const を戻す（2026-10-13）

**分かったこと**: Claude で世界を作ると、町の生成（ゲームの型 `Area`）が検証エラーで何度も送り直しになっていた（10-12〜13 に宇宙 SF 19回・ハイファンタジー 11回・現代 0回・西部劇 6回。[§3.95](3.95.md)）。
ゲームのエラーログの全文では、区画の中の場所に `type: "facility"` と書かれ、`tier` / `owner` が無かった。
送った型を読むと、場所（`NonFunctionalLocation`）と区画（`Ward`）の `type` は `{"type": "string", "description": "{const: location}"}` で、値の縛りが無い。
SDK が送る前に `const` を外して説明文へ書き移している（`136_` もローダも `const` に触らない）。
API は自由な文字列として縛るので、頼み文の「ロケーションには[ward, facility, location]の3つの大枠がある」に沿って `facility` と書いた場所が、施設の欄の無い `NonFunctionalLocation` の形で通る。
同じ書き移しは、効果（`instant_damage` など）・品物の種類（`weapon` など）・ボス（`boss`）にもある。
10-08 の依頼の生成の `InstantDamage.type` の検証エラーと、ゲームの会話の `TakeARest.type` の検証エラーも同じ形だった。
`modloader.log` の検証エラーは、`literal_error` で落ちたものがすべて Claude 宛てだった。

**直し**: `claude_grammar.restore_const` が、文字列の欄の説明文の `{const: X}` を値1つの `enum` に戻してから送る（数や真偽の欄は戻さない）。
差し替え先が `off` でも効く。
ゲームが 10-13 に送った町の生成の型では、2か所（`ward` と `location`）が戻り、`{const:` は残らなかった。
オフラインは `tools\tests\test_cloud_model_override.py`。

**実機（2026-10-13、Haiku 5.5・916（現 343）あり）**: 4つの世界を作り、町の生成の検証エラーを数えた。世界は確かめた後に消した。

`minimum` / `maximum` も SDK が説明文へ書き移す縛りで、API は数の範囲を縛らない。

**数の範囲に寄せる（同じ日、版5のうち）**: `claude_bounds.py` が、応答をゲームの型で読む前（文字列の欄を読み戻した後）に型を辿り、
説明文の `{maximum: 5, minimum: 3}` などから範囲を読んで、外の数を端へ寄せる。
整数の `exclusiveMinimum` / `exclusiveMaximum` は1つ内側へ寄せる。`maxItems` を超えた配列は後ろを落とす。
`minItems` に足りない配列は足す中身を作れないので触らない（10-11 にゲームの `Story` の `story_quests` が 5件のところ1件で落ちた例がある）。
選択肢（`anyOf`）は、値1つの `enum` の欄と必須の欄で選択肢が1つに決まるときだけ、その形で辿る。
寄せたときはログに `clamped to the type's range: 2->3` の形で出る。
ゲームが 10-13 に送った型で書き移されていた範囲は、効果の `duration`（2〜5 / 3〜5）・`intensity`（1〜5）、スキルの `max_uses`（1〜10）、`story_quests` の件数（5件ちょうど）。

依頼の生成の頼みを API へ直接15回送り、範囲も検めた: 1回で `duration` が 2（型は 3〜5）、寄せた後は15回とも通った。
上の送り比べの表は、範囲を検めていない（型の形と値の選択肢だけを見た）。
直した版で宇宙 SF の世界をもう1つ作り、町の生成も依頼の生成も検証エラー0回で通った（範囲の外れは出ず、寄せた行も無かった。世界は消した）。

**版8（11-13）: Gemini を足し、GPT-6.1 Terra と Claude Fable 5.2 を一覧に入れた**。
ゲームの exe（10-14 の版）の定数で、ゲームの一覧と Gemini の送り方を確かめた。

SDK 1.52.0 のソース（PyPI の wheel）を読み、モデル名は本文ではなく URL のパス（`models/<モデル>:streamGenerateContent?alt=sse`）に入り、`BaseApiClient.request_streamed`（一括は `request`）へパスと本文の dict が渡ると分かった。
`gemini_side.py` でこの2つを包み、宛先が `generativelanguage.googleapis.com` のときだけパスのモデル名と思考の段階を直す。
思考の段階の幅は Google の Thinking のページの表（11-13）に合わせた。Gemini 4 Carbon・Argon と Gemini 3.8 Flash は low〜high、Gemini 4 Hydrogen は low〜xhigh、Gemini 3.6 Flash と 3.5 Flash-Lite は minimal〜high。受けない段階は近い端へ寄せる。
ゲームが送る思考の指定は、送信モジュールの `_build_config` をゲームの中でモデル名を変えて呼んで確かめた（送信はしない）。
3.5 Flash・3 Flash Preview・3.1 Flash-Lite（ゲームの `reasoning_models`）は `thinking_budget: 0`、3.1 Pro Preview は `thinking_level: LOW`、Gemma 4 の2つは `thinking_level: minimal` と `temperature: 1.0`。
exe の定数からは「ふだんは minimal」と読んでいたが、組み合わせが逆だった（実機の会話で、ゲームが渡す本文を一時の包みで控えて見つけた。3回とも `thinking_budget: 0`）。
