# 3.11 アイテム説明欄が閉じた後も残る（新種・計測中）

スクリーンショットで発見。
所持品を閉じて戦闘に入っているのにアイテム説明の箱が浮いたままだった（間欠）。

分かっていること: 表示・非表示は `opacity` の 0/1 で行われている
（箱が `opacity=0`、子はいずれも `1.0`）。
したがって症状は「1 に上げた誰かが 0 に戻していない」。

`109_` は原因ではない（触るのは `size` / `pos` / `size_hint` / `pos_hint` だけで
`opacity` には一切書き込まない）。

`208_` が `box.bind(opacity=...)` で変化そのものを見張っている（読み取り専用）。

| ログの形 | 意味 |
| --- | --- |
| `-> 1.0` の後に `-> 0` が無いまま所持品を閉じた | 戻す側が呼ばれていない。`from` の対になる関数を探す |
| `-> 0` は出ているのに見えている | 別の箱が残っている（`box=` の id）か、親ごと生きている（`parent=`） |
| 何も出ない | 見張りが掛かる前の箱。`watch_opacity` の掛け方を変える |

**現在地**: 796 遷移（`-> 1` が 398 / `-> 0` が 398）で**再現はしていない**。
ただし `box=` の id は通しで**1つしか出ていない**ので、
「別の箱が残っている」枝は現時点で支持が無い（[§2.49](2.49.md)）。
残る候補は「上げた側の対になる関数が呼ばれていない」か「見張りが掛かる前の箱」。
再現手順の候補は「所持品を開いてアイテムにマウスを乗せたまま戦闘に入る」。
