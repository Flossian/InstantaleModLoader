# 3.106 遊んでいる最中に世界の素データを引く箇所（`242_probe_world_reads`）: 箇所と段を実測・世界側に無い人物の詳細の生成が落ちてセーブが欠けると分かった・訓練場でも詳細の生成が落ちる・闘技場の試合も落ちる・奴隷市場・一括生成・新たな道を探すは落ちない

2026-10-19 に作った計測。
セーブエディタで足した宿屋で売買が `KeyError` で落ちた件（[§3.105](3.105.md)）から、
ゲームが遊んでいる最中にメモリ上の骨格（`app.world_dict`）を引く箇所を洗い出し、要否を決める下調べ。

## 録り方と、拾えないもの

`app` の型を同じ名前の派生クラスに替え、`world_dict` の属性を引いた瞬間に呼び出し元を控える（辞書は替えない）。
暗号化の層（`save_world_json:write_obfuscated_json_file`・`scripts.save_codec:read_obfuscated_json_file`・`read_json_with_obfuscation_fallback`）で、ディスクとの読み書きもファイル名と連鎖ごとに数える。

拾えないもの: 属性を引かずに参照を持ち回して読む経路。関数の中で何度読んでも、その関数の1件に数える。どの段（エリア・施設・NPC）を読んだかは分からない。

## 踏んだ場面

テストワールド（売買・移動・宿泊・会話・依頼の生成・依頼と戦闘と帰還・生成済みの街への移動・起動し直しての読み込み）と、
新しく作った世界「計測ワールド」（世界の生成・ランダム作成の主人公で開始・未生成の村へ徒歩で移動）。
テストワールドは控えへ戻した。

| 箇所 | 場面 | 何をしているか（読める範囲） |
| --- | --- | --- |

| `Facility.__init__`（10940） | 読み込みでエリアを組み立てるとき（`Area.update` → `generate_nodes` → `Node.generate_facilities`） | 施設の組み立て。何を引くかは読めない |
| `InstantaleApp.start_game`（936 代入・読み） | 新しい主人公で始めるとき | ディスクから `world_data.json` を読み、辞書に据える |
| `World.generate_character`（11054・11057） | 始めたとき（18回）・未生成の村に着いたとき（15回） | 人物の組み立て |
| `InstantaleApp.save_game`（1148・1158） | 行動のたびの保存 | 1159 で `world_data.json.temp` を書く（続けて 1352 で `savedata.json.temp`） |
| `ShoppingStartManagerRemake.shopping_start_method_1`（3189） | 売買 | 施設と主を引く。無いと 3194 で `KeyError`（[§3.105](3.105.md)） |

ディスクからの読み込みは、世界の一覧の画面（`WorldChoiceScreen.__init__`。世界ごとに両方のファイル）・読み込み・世界の生成（`save_world_json:generate_new_world`）・主人公の作り始めだけ。
遊んでいる最中にディスクから `world_data.json` を読み直す場面は無かった。

保存は、移動・部屋選び・休養・会話の各段・依頼の各段・戦闘の始めと終わりの、毎回の行動で `world_data.json` を書いた。
書き方は `world_data.json.temp` に書いてから置き換える（名前で絞った初版が1件も拾えなかった原因）。

## 要否の見立て（基準: 世界データは世界と街の生成時だけの基底情報）

| 箇所 | 見立て |
| --- | --- |
| 読み込み・主人公の作り始め・世界の生成・街の生成 | 要る（骨格を据える・骨格を作る） |
| 保存（`world_data.json` を毎回書く） | 書き込みの側。街の生成以外では要らない見込み |
| 売買 | 要らない。施設と主はセーブ側にある |
| `Facility.__init__` | 要らない。引くのは世界の名前（`world_data/name`）だけで、セーブ側にも同じ `world_data` がある |
| `World.generate_character` | 読み込みでは `npcs` の段を引くだけ。街の生成では NPC の段を読み、`experience_level`・`config/difficulty_level`・`config/level_of_detail` を書く（街の生成の一部なので、基準では要る側） |
| `InstantaleApp.generate_npc_detail`（3046・3077） | 要らない。初めて話す人物の詳細を作るとき、世界の名前と概要を読み、NPC の段に詳細を書く。世界側に無い人物では落ちてセーブが欠ける（下） |

## 未決の2つと、詳細の生成を段で測った（10-20、計測ワールド）

`TRACE_PATHS`（既定は切）で、対象の関数が走る間だけ `world_dict` を「引いた段を記録する写し」に替えた（書き込みは元の辞書にも通す）。

| 関数 | 場面 | 引いた段（数字の id は `<id>`） |
| --- | --- | --- |
| `Facility.__init__` | 読み込み・街の到着 | `world_data` → `world_name`（無い）→ `name` |
| `World.generate_character` | 読み込み | `npcs` だけ |
| 〃 | 未生成の街に着いたとき | 上に加えて `world_data/name`、`npcs/<id>` を読み、`npcs/<id>/experience_level`・`npcs/<id>/config/difficulty_level`・`level_of_detail` を書く |
| `InstantaleApp.generate_npc_detail` | 初めて話す人物（詳細度 1） | `world_data/name`・`overview` を読み、`npcs/<id>` の `speech_style`・`image_src`・`ability_scores`・`skills`・`experience_level`・`original_max_hp`・`config/level_of_detail`・`difficulty_level` を書く。続けて世界の辞書を丸ごとたどる（`items`） |

### 世界側に無い人物の詳細の生成は落ち、セーブが欠ける

詳細度 1 の人物を、メモリ上の `world_dict["npcs"]` からだけ外して話しかけた（記録の写しは挟まない素の状態）。

```text
safe hook on __main__:InstantaleApp.generate_npc_detail: the original raised KeyError: '5' at instantale.py:3069
stall guard: Thread-51 (generate_npc_detail_and_ready) died: KeyError: '5'
```

- 会話は始まらず、話す相手の一覧に戻った
- その後のセーブ側の人物は詳細度 2（作成済み）なのに、`speech_style` が空・`skills` が0。メモリ上の人物には話し方が入っている
- 詳細度が 2 なので、ゲームはこの人物の詳細を作り直さない。セーブに欠けたまま残る
- 世界側へ書く 3069 行で落ち、その後でセーブ側へ書くはずの項目が抜けたと読める（順序は測っていない）

素のゲームで世界側に無い人物が詳細度 1 のまま生まれる経路は、まだ見つけていない（ヴェスティアのセーブにしか無い10人は全員詳細度 2）。
セーブエディタで人物を足した場合は、この形になる。

試した世界は控えへ戻した。

その街で操作を1つずつ行い、操作ごとに `out\modloader.log` の `KeyError` と `stall guard … died` を見た。試した世界は控えへ戻した。

世界側に無い人物の詳細の生成は、この試しでは踏んでいない（ミストルの人物は全員作成済み）。上の節の計測ワールドで落ちることは確かめてある。

### 続き: 奴隷市場と一括生成（10-20）

奴隷市場は、セーブエディタでテストワールドのエテルナに足した（施設 308、主 NPC 120「テスター」）。エディタは施設と主を両方の辞書に書いていた。

| 場面 | 結果 |
| --- | --- |
| 奴隷市場に入る・「奴隷を買う」（公式の未実装の枠）。素の状態と、エテルナを `world_dict` から外した状態の両方 | 何も起きない（落ちない） |
| 外した状態で主のテスター（詳細度 1）と話す | 詳細の生成が落ちた（`KeyError: '120'` at 3069）。上の「人物の詳細の生成」と同じ穴 |

一括生成は、計測ワールドで「開始／再開」から4件（街4つ）を流して中断した。失敗0件・落ちない。

- 一括生成は `world_data.json` と `savedata.json` の両方をディスクから読み（`scripts/world_bulk_generation.py:155` / `159`）、書くのは `world_data.json.bulk.tmp`（`atomic_world_write`）だけ。作った街4つと人物35人は世界側にだけ入り、セーブ側の街は詳細度 0 のままだった
- その後に遊ぶと、読み込みのとき（`load_game_new` から `World.generate_character`）に世界側の街と人物がセーブ側へ取り込まれた（ヴェルナは両方で詳細度 1・施設14件・人物46人）。移動先の一覧は「推定」が消えて世界側の難易度を出し、移動は LLM を待たずに着いた
- 一括生成で作られた人物との初めての会話は、詳細の生成が通り、セーブ側に話し方まで入った

世界側への追加がセーブ側へ流れる向きは、ゲームの作りどおりに動いた。漏れは無かった。

試した世界は控えへ戻した（テストワールドは奴隷市場を足した後の控え）。

### 続き: 新たな道を探す（`325_`。10-20、テストワールド）

ミストル（出発地）・ゼニス（委託の行き先）・リヴェール（踏破の行き先）の3つの街の施設と人物を `world_dict` からだけ外した。委託の日数は `m 325_ PAY_DAYS 0` でその場で開くようにした。控えへ戻した。

| 場面 | 結果 |
| --- | --- |
| 「新たな道を探す」→ 候補の一覧 | 落ちない |
| お金を支払い委託する（ゼニス）→ 開通 → 馬車でゼニスへ | 落ちない（「ミストルとゼニスを結ぶ道が開かれた。」） |
| 自ら切り拓く（ゼニス → リヴェール）→ 道中の依頼を戦闘・ボス・帰還まで → 開通してリヴェールへ移動 | 落ちない（「ゼニスとリヴェールを結ぶ道が開かれた。」） |

この間に世界側を引いた箇所（242）は、保存・読み込み・施設の組み立てだけだった。

これで、使える世界にある場面は一通り踏んだ。

試しの途中、強化の窓を売買の窓用の閉じる手順（`tools\drive\trade.py close`）で閉じようとして、`InstanTaleHUD.toggle_twin_inventory_visibility` が `AttributeError: 'InstanTaleHUD' object has no attribute 'twin_inventory_text_left'` を2回出した。送った時刻とミリ秒まで一致するので、試しの手順で起きたもの（素の経路では、強化の窓にこの閉じ方は届かない）。
### 読み込みと会話は、セーブにしか無い施設・人物でも動く

ヴェスティアの日陰亭（施設 228）と主のエデル（NPC 98）はどちらもセーブにしか無いが、読み込み・宿屋に入る・エデルとの会話は落ちなかった（10-19 に画面がエデルとの会話にあった）。落ちたのは売買だけ（[§3.105](3.105.md)）。

## まとめと、残り

世界側に無い施設・人物で落ちるのは、売買・人物の詳細の生成（会話と訓練場の入口）・闘技場の試合の3か所。直しは [§3.107](3.107.md)（`146_fix_save_only_entities`）。
上の各節で踏んだ場面のほかは見ていない。MOD 独自の場面の多く（`402_` の受け渡し・`330_` / `331_` の家と施設・`404_`・`336_` の脱獄と店で盗む）は踏んでいない。
ローダと MOD の読み（`mod:` の行）は別に数えてあり、まだ仕分けていない。
世界側の関係が「同行中」になっていたジーク（ヴェスティアの NPC 68）の出どころは調べない。
