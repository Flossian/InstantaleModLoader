# 3.43 立ち絵の高画質化と顔の検出（`131_`）: 実機で決着・残るは誤検出率・旗・敵の除外の実機

版1〜10 を1日で回した。
経緯と根拠のログは VERIFICATION_LOG.md §2.80。ゲーム側の経路と寸法は GAME.md §2.30。

| 部品 | 立ち絵を荒くしない | 立ち絵を荒くする（既定） |
| --- | --- | --- |
| 縮小・減色の素通し、2倍の戻し | 決着（立ち絵が `no_bg_image.png` と同じ 512x1024・758KB） | 素の経路（330x660） |
| 顔の切り直し | 決着（256x256 で顔の位置） | 触らない（ゲームの縮め方がそのまま合う） |
| 顔の検出のやり直し | 決着（均一化 + lbp で拾い、切り直しへ繋がった） | 決着（均一化 + haar） |

実機で確かめた前提:

- `pixel_art_process` の戻り値は `(入力そのまま, 縮めた絵)` の2つ組で、ゲームが使うのは2つ目
- `detect_face_coordinates` の戻り値は `(左, 上, 右, 下)` で一辺 256。ゲームはこれを 330/512 の**定数**で縮めてから立ち絵から切る（立ち絵の実寸からは求めていない）
- ゲームは検出を anime → haar の順に2回呼び、`cascade_path` は `runtime/models/face_recognition/...` とフォルダ付きで渡す。素のファイル名で呼び直すとゲームの関数はカスケードを読めず `None` を返す
- 手元の 364 体で顔の外れは 58 体（16%）。世界（画風）で 2%〜35% の差がある。前処理と位置の絞りで 42 体を拾い、目で見て 4 体は顔でなかった

## 既存の NPC を一括で直す道具（`tool.py`。後から追加）

設定画面の「設定…」から開く（TECH.md §3.12）。手元の全世界を走査して顔の状態を数え、
顔が見つかっていない個体の検出をやり直して `face_image.png` を切り直す。書く前に `face_image.orig.png` を残す。
検出の中身は MOD 本体と同じ `faces.py`。

- `--dump` で実世界 364 体を走査: 全身の縮小 56 体（MOD で直した2体を除いた数。§3.43 の 58 と一致）
- 切り直しはテスト（`test_sharp_portrait_tool.py`）で手元の1体を借りて通した:
  検出だけなら書かない → 控えを残して 256x256 → 立ち絵からは 165 → 元に戻す
- 顔の箱の端数は**切り捨て**（`(201, 136, 81, 81)` → 左 113。実機の戻り値と一致。丸めだと 114 でずれる）
- **画面は実機で決着**。全世界・全員・背景を抜いた元絵から、で走らせた:
  364 体中 **348 体**を 256x256 で切り直し（控え 348 件）。
  控えの前の状態は顔 308 / 全身の縮小 40 で、**全身の縮小 40 体を全部拾い**、
  残ったのは検出できなかった 16 体（`--dump` の 56 と 40 + 16 で一致）。
  拾った顔を目で見た範囲（2つの世界の3体）は正面の顔で位置も合っている

## 残り

| # | 確かめること | 見方 |
| --- | --- | --- |
| 1 | やり直しの誤検出率の実機値（手元の統計では拾った 42 体中 4 体） | 道具で拾った 40 体の `face_image.png` を目で見る。顔でなければ `箱` の座標を控え、その個体は道具で元に戻す |
| 2 | 旗（`after_reduce`）がスレッドを跨がないこと | 生成は毎回新しいスレッドで、顔が切られた時点で旗を降ろす作りにしてある。`縮小: ... ゲームに任せる` が減色の直後ではなく生成の頭で出たら漏れている |
| 3 | ゲームの2回目の検出の引数（1回目と何が違うか） | 版18 から、1回目（anime）で外れた回はやり直さずにゲームの2回目へ任せる（§3.80）。`顔: ゲームの呼び方` は2回目の引数を記録するので、次に1回目で外れる絵が出たときのログで埋まる |
| 4 | `165x330` をゲームがどう決めているか | 版5以降は通らないので効かない。330/512 の定数の出どころとして残る |
| 5 | 敵・モンスターの除外（版14。後から追加、**実機未確認**） | `generate_enemy_image` / `generate_enemy_image_from_character` の中では4つの包みがゲームのまま。戦闘に入って敵の絵が素のドット絵寄りで出ること、その戦闘の前後で NPC の絵が素通しのままであること（`out\sharp_portrait.log` に敵の生成の行が**出ない**のが正しい） |

## 確認手順

1. デバッグモードは要らない。注入して、まだ絵の無い NPC と会話する
2. `out\live_crashes.log` に `generate_images` のクラッシュが増えていないことを見る
3. `out\sharp_portrait.log` を読む
4. `%LOCALAPPDATA%\Darmabeko\Instantale\worlds\<世界>\characters\<名前>\` の `reduced_color_image.png` と `face_image.png` を開く

| 出た行 | 意味 |
| --- | --- |
| `縮小: 512x1024 をそのまま通す` | `pixel_art_process` を通った。絵を控えた |
| `減色: 1024x2048 を控えの 512x1024 に戻す` | 控えた絵がそのまま立ち絵になる |
| `顔: ゲームが見つけた (...)` | ゲーム自身の検出が通った |
| `顔: ゲームは見つけられず、均一化 + haar で拾った (...)（箱 (x, y, w, h)）` | やり直しが拾った。`箱` はこちらの検出、括弧の前がゲームの関数の戻り値 |
| `顔: (...) を (...) に戻して切り直した` | 切り直した。`face_image.png` は 256x256 |
| `縮小: ... 顔の代わりを作る回なのでゲームに任せる` | ゲームもやり直しも外した回。減色の直後に出るのが正しい |
| `out\live_crashes.log` に `generate_images` | 縮小の戻り値の形が実測と違う。`safe=True` が拾えない形なので MOD を切る |
