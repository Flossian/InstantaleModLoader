# 3.43 立ち絵・敵・背景の高画質化と顔の検出（`131_`）: 実機で決着・残るは誤検出率・旗・敵の絵の縁・版19 の YuNet の実機

版1〜10 を1日で回した。
経緯と根拠のログは VERIFICATION_LOG.md [§2.80](2.80.md)。ゲーム側の経路と寸法は GAME.md §2.30。

| 部品 | 立ち絵を荒くしない | 立ち絵を荒くする（既定） |
| --- | --- | --- |
| 縮小・減色の素通し、2倍の戻し | 決着（立ち絵が `no_bg_image.png` と同じ 512x1024・758KB） | 素の経路（330x660） |
| 顔の切り直し | 決着（256x256 で顔の位置） | 触らない（ゲームの縮め方がそのまま合う） |
| 顔の検出のやり直し | 決着（均一化 + lbp で拾い、切り直しへ繋がった） | 決着（均一化 + haar） |

実機で確かめた前提:

- `pixel_art_process` の戻り値は `(入力そのまま, 縮めた絵)` の2つ組で、ゲームが使うのは2つ目
- `detect_face_coordinates` の戻り値は `(左, 上, 右, 下)` で一辺 256。ゲームはこれを 330/512 の**定数**で縮めてから立ち絵から切る（立ち絵の実寸からは求めていない）
- ゲームは検出を anime → haar の順に2回呼び、`cascade_path` は `runtime/models/face_recognition/...` とフォルダ付きで渡す。素のファイル名で呼び直すとゲームの関数はカスケードを読めず `None` を返す
- 手元の 364 体で顔の外れは 58 体（16%）。世界（画風）で 2%〜35% の差がある。前処理と位置の絞りで 42 体を拾い、目で見て 4 体は顔でなかった

## 既存の NPC を一括で直す道具（`tool.py`。後から追加）

設定画面の「設定…」から開く（TECH.md §3.12）。手元の全世界を走査して顔の状態を数え、
顔が見つかっていない個体の検出をやり直して `face_image.png` を切り直す。書く前に `face_image.orig.png` を残す。
検出の中身は MOD 本体と同じ `faces.py`。

- `--dump` で実世界 364 体を走査: 全身の縮小 56 体（MOD で直した2体を除いた数。§3.43 の 58 と一致）
- 切り直しはテスト（`test_sharp_portrait_tool.py`）で手元の1体を借りて通した:
  検出だけなら書かない → 控えを残して 256x256 → 立ち絵からは 165 → 元に戻す
- 顔の箱の端数は**切り捨て**（`(201, 136, 81, 81)` → 左 113。実機の戻り値と一致。丸めだと 114 でずれる）
- **画面は実機で決着**。全世界・全員・背景を抜いた元絵から、で走らせた:
  364 体中 **348 体**を 256x256 で切り直し（控え 348 件）。
  控えの前の状態は顔 308 / 全身の縮小 40 で、**全身の縮小 40 体を全部拾い**、
  残ったのは検出できなかった 16 体（`--dump` の 56 と 40 + 16 で一致）。
  拾った顔を目で見た範囲（2つの世界の3体）は正面の顔で位置も合っている

## 敵の絵と背景（版19。2026-11-06 に実機）

工程と寸法は GAME.md §2.30。
試したのは `sdcpp_cuda` で、テストワールドのモンスターと、ゲームの関数を外から呼んだ NPC の戦闘用の絵。

| 確かめたこと | 結果 |
| --- | --- |
| 敵の設定が切のとき（版14 の除外。`SHARP_PORTRAIT` は入） | 敵の入口の中では `pixel_art_process` が 96x96 / 128x128 / 200x200 を返し、ゲームの絵のまま |
| 戦闘中に「画像の再生成(txt2img)」で敵を描き直す | `敵: 縮小 1024x1024 をそのまま通す` → `敵: 色調 1024x1024 雑音を 1 に` → `敵: 減色 1024x1024 をそのまま通す` → `敵: 2倍の絵を 1024x1024 に戻した`。ファイルは 1024x1024・955KB |
| 描き直した後の戦闘画面 | 部品は 240x240 のまま。読み込んだ絵は 1024x1024、`min_filter` は `linear`、`mag_filter` は `nearest`。写真で荒さが消えた |
| 既にあるドット絵の敵 | 192x192 を 240x240 に拡大する `mag_filter` は `nearest` のままで、見た目は変わらない |
| NPC の戦闘用の絵 | `敵: 縮小 704x1408 をそのまま通す` → `敵: 2倍の絵を 704x1408 に戻した`。部品に読ませて `min_filter` が `linear` |
| 背景を描き直す | `背景: 縮小 1024x512 をそのまま通す`・`背景: 減色 1024x512 をそのまま通す`。ファイルは 1024x512・605KB・31,645色。落ちなかった |

素通しに要る時間は 1024x1024 で縁 0.24 秒・色調 0.05 秒。

縁は、色調を残して雑音を 1 にした絵で6体を暗い背景と明るい背景の上に並べて比べた。
暗い敵は縁があると輪郭が分かるが、線は細く途切れ、足元の影など背景抜きの取り残しまで囲む。
明るい敵と明るい背景ではほとんど差が無い。
描いた寸法が 512 の敵は線が太めに見える。
縁は既定で切にし、設定で付けられるようにした。

背景は素のゲームが 16色・約 390KB、素通しが 57,953色・737KB（2026-09-09。1024x512、同じ場所の描き直し）。
`apply_dark_fantasy_tone` に `randomize=0` を渡した回は生成スレッドが死に、絵が書かれなかった。

版19 の中で分かったこと:

- NPC の戦闘用の絵は減色を通らないので、最初の形（減色で絵を控える）では 1408x2816 のまま残った。縮小でも控えるようにして 704x1408 に戻った
- 設定の道具の保存は渡した項目でこの MOD の欄を置き換える。道具が `FACE_YUNET` を持っていなかったので、道具から保存すると「切」が既定へ戻っていた。全部の設定を並べるようにした

| --- | --- | --- |
| 1 | 敵の絵に縁を付ける設定（`ENEMY_BORDER`）を入れた回 | 検査は通っている。ゲームのボタンで敵を描き直し、`敵: 色調` の前に縁が通る。写真で縁が付く |
| 2 | 新しい名前の敵が依頼の中で描かれる回 | `敵: 2倍の絵を … に戻した` が出て、戦闘画面に荒くない絵が出る |

## 敵の背景抜き（版19。2026-11-06）

敵の透けは荒くする工程ではなく、その前の背景抜きが原因だった。
手元の3つの世界の 535 体を数えると、減色後の絵の不透明な面積が絵全体の 10% 未満の敵が 83 体（5% 未満は 54 体）、内側に 5% 以上の穴がある敵が 34 体あった。
開発機は `343_` で isnet-anime を選んでいて、抜いた結果は手元の同じモデルの再現と差 0.0 で一致した（起動直後の1〜2回だけ u2net と一致。boot #2 でフックが当たる前と読んでいる。測ってはいない）。

同梱のモデルを同じ絵に掛けて比べた（手元の CPU）。
無作為の 120 体で、濃い本体（透明度 200 以上）の面積を「どちらかのモデルが薄くでも本体と言う範囲」と比べた。
この物差しは合わせたマスクから作るので、合わせる案に有利。

| 方式 | 25% 未満 | 25〜60% | 中央値 |
| --- | --- | --- | --- |
| isnet-anime | 43 体 | 19 体 | 57% |
| u2net | 19 体 | 25 体 | 78% |
| 2つの濃いほう | 3 体 | 18 体 | 85% |
| 濃いほう＋薄い所を濃くする（下限 24・上限 160） | 1 体 | 5 体 | 91% |
| さらに端からつながる暗い地を削る | 2 体 | 5 体 | 86% |

1枚の推論は isnet-anime 0.41 秒、u2net 0.15 秒。
暗い地を削る案は黒い地が消えるが、暗い鎧や服の敵の本体も欠けるので採らなかった。
濃くする案で残る黒い地は、本体の欠けより目立たないと判断した。
黒地を端から抜くだけの案は、背景が黒でない絵で四角く残り、黒い服の中央が欠けた。

`343_` の切り抜きのモデルの設定とフックは、描いた絵の加工にまとめるため `131_` へ移した。
`CUTOUT_MODEL` は `343_` の欄に残っていれば、起動のときに1度だけ `131_` の欄へ移す。
移すのは `131_` の起動の時なので、その前に `343_` の設定を道具から保存すると、`343_` の欄の値は宣言から消えているので書かれず、引き継がれない。

実機（`sdcpp_cuda`、テストワールド。`ENEMY_CUTOUT_MERGE` 入）:

| 確かめたこと | 結果 |
| --- | --- |
| 設定の移し替え | 起動で `343_` の `isnet-anime` が `131_` の欄へ移り、`343_` の欄から消えた |
| 入口の外の背景抜き | `背景抜き: isnet-anime 1024x1024 0.36 秒`。立ち絵の扱いは合わせない |
| 新しい敵（ゴーレム・亀。荒くしない） | `背景抜き: 2つのモデル`（0.58〜1.20 秒）。不透明 65.5%・58.6%、半透明 3.0%・2.1% |
| 新しい敵（ゴーレム。荒くする） | 不透明 56.1%、半透明 5.5%。戦闘画面で輪郭だけにならない |
| 戦闘中に「画像の再生成(txt2img)」 | `背景抜き: 2つのモデル 1024x1024 0.50 秒` から2倍の戻しまで通った |

## YuNet（版19。2026-11-02 に手元で測った。実機は未）

手元の全世界 695 体の `no_bg_image.png` に、ゲームの検出の再現（anime → haar、1.1/3、絞り無し）、
版18 のやり直し（前処理4つ × カスケード2つ、位置で絞る）、YuNet（opencv_zoo の
`face_detection_yunet_2023mar.onnx`、確かさ 0.6 以上、位置の絞りは同じ）を掛けて比べた。
手元の Python（OpenCV 4.14）で、ゲームの中ではない。

| | 体数 |
| --- | --- |
| `face_image.png` が全身の縮小 | 79 |
| 再現で見つかる / やり直しで拾う / 外れる | 598 / 52 / 45 |
| YuNet が拾う | 651（位置の絞りで落ちる体は 0。顔の幅は絵の幅の 8.5〜39%） |
| YuNet が外し、版18 の検出も外す | 7 |

一覧画像で目で見た結果:

- 外れた 45 体: YuNet は 38 体を拾い 37 体が顔（外れの1体は小さく描かれた全身が切り出しに入った）。
  カスケードの工夫（背景を白・灰で塗る、左右反転、±12°・±24° の回転、感度 1.05/2）は 38 体を拾ったが、
  10 体が顔でなく（髪・服・武器・背景）、5 体ほどが顔の一部だった。採らなかった
- 見つかった 650 体で、再現・やり直しの箱と YuNet の箱の中心が食い違ったのは 67 体。
  保存されている `face_image.png` を並べると、約 19 体が服・鎧・飾りを切っていて、15 体は全身の縮小だった。
  残りは再現の箱の選び方がゲームとずれていた体（ゲームは顔を切っていた）。67 体の YuNet の箱はほぼ顔
- YuNet の確かさが 0.75 未満の 41 体は 39 体が顔、2 体は小さく描かれた全身が切り出しに入った
- YuNet が外した 44 体は目の大きいアニメ寄りの顔が中心で、版18 の検出に落とすと 37 体で箱が出て約 28 体が顔

速さは1枚 平均 33ms・最大 55ms、検出器を作るのは 3ms。
ゲームの OpenCV は 4.10.0（`cv2/opencv_videoio_ffmpeg4100_64.dll`）で、`cv2.pyd` の文書文字列に
`FaceDetectorYN.create(framework, bufferModel, bufferConfig, input_size, ...)` がある（バイト列から作る形）。

実機で確かめること:

| # | 確かめること | 見方 |
| --- | --- | --- |

## 確認手順

1. デバッグモードは要らない。注入して、まだ絵の無い NPC と会話する
2. `out\live_crashes.log` に `generate_images` のクラッシュが増えていないことを見る
3. `out\sharp_portrait.log` を読む
4. `%LOCALAPPDATA%\Darmabeko\Instantale\worlds\<世界>\characters\<名前>\` の `reduced_color_image.png` と `face_image.png` を開く

| 出た行 | 意味 |
| --- | --- |
| `縮小: 512x1024 をそのまま通す` | `pixel_art_process` を通った。絵を控えた |
| `減色: 1024x2048 を控えの 512x1024 に戻す` | 控えた絵がそのまま立ち絵になる |
| `顔: YuNet が見つけた (...)（箱 (x, y, w, h)、確かさ 0.xx）` | YuNet が先に見つけた（版19）。ゲームの検出は呼んでいない |
| `顔: YuNet は見つけられず、ゲームの検出に任せる` | YuNet が外した。次の行がゲームの検出の結果 |
| `顔: ゲームが見つけた (...)` | ゲーム自身の検出が通った |
| `顔: ゲームは見つけられず、均一化 + haar で拾った (...)（箱 (x, y, w, h)）` | やり直しが拾った。`箱` はこちらの検出、括弧の前がゲームの関数の戻り値 |
| `顔: (...) を (...) に戻して切り直した` | 切り直した。`face_image.png` は 256x256 |
| `縮小: ... 顔の代わりを作る回なのでゲームに任せる` | ゲームもやり直しも外した回。減色の直後に出るのが正しい |
| `out\live_crashes.log` に `generate_images` | 縮小の戻り値の形が実測と違う。`safe=True` が拾えない形なので MOD を切る |
