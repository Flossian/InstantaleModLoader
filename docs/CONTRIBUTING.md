# CONTRIBUTING: MOD を提供する

作った MOD を同梱に入れてほしいときに読む1枚。

書き方そのものは [TECH.md](TECH.md) にある。
こちらが持つのは、あちらに書いていないこと。
**ライセンス・送るときに揃えるもの・取り込みでこちらが何をするか**の3つ。

道は2つある。どちらを選んでもよい。

| | 同梱に入れる | 自分で配る |
|---|---|---|
| 配る人 | このプロジェクト | あなた |
| 保守 | こちらが引き受ける（下記） | あなた |
| 番号 | こちらが振り直す | 自分で決める |
| 入れ方 | 次のリリースに入る | 受け取った人が GUI の `MOD を追加…` で入れる |

この文書は**同梱に入れる**側の話。
自分で配る場合に守ってほしいのは「[名前がぶつからないようにする](#名前がぶつからないようにする)」だけ。

## ライセンス

提供は MIT で受ける。
このプロジェクトが配っているのと同じライセンスで、別途の取り決めは置かない。

- **著作権はあなたに残る。**
  譲り渡してもらうことはしない。
  お名前は `mod.json` の `"author"` と [NOTICE](../NOTICE) に載る
- **同梱後は MIT で配る。**
  あなたを含む全員が、再配布・改変・商用利用を MIT の条件どおりに行える
- **取り込んだ後の保守はこちらで引き受ける。**
  ゲーム本体の更新への追随、他の MOD との衝突の解消、ローダの API 変更への追随。
  あなたに続ける義務は無い

他のライセンスで配りたい場合は同梱にはできないが、自分で配る道は塞がらない。
その MOD がローダの機能（`instantale_modloader.*`）を使うこと自体は MIT が許している。

他人のコードを含む場合は、そのことを書いて渡すこと。
出どころが確かめられないものは同梱しない。
配った後では取り消せないため、こちらで判断せずに保留する。

## 送る前に揃えるもの

1本の MOD は**フォルダ1つ**。
中身は `mod.json`（名乗り）と入口の `.py` の2つが最低限。

```
my_mod/
    mod.json
    my_mod.py       # apply(ctx) を持つ
    DOC.md          # 遊ぶ側から見た説明。無ければこちらで書く
```

雛形が `runtime/mods/_template/` に在るので、それを複製するのが早い。

| 揃えるもの | 見るところ |
|---|---|
| `mod.json` に `entry` / `api` / `kind` / `name` / `description` / `author` | [TECH.md §3.1](TECH.md#31-最小の形) |
| 入口が `def apply(ctx):` である | [TECH.md §3.1](TECH.md#31-最小の形) |
| **Python 3.10 の構文で書く** | ゲームに埋まっているのが CPython 3.10。3.11 以降の書き方は注入した瞬間に落ちる |
| 書き込み先が `out\`（ログ）と `state\`（永続データ）だけ | [TECH.md §3.11](TECH.md#311-書き込み先out-と-state) |
| 設定を持つなら `"settings"` の宣言とコード側の定数の既定値が一致している | [TECH.md §3.8](TECH.md#38-gui-から変えられる設定ctxconfig) |
| `python tools/check_mods.py` が通る | [TECH.md §2.3](TECH.md#23-静的検査toolscheck_modspyは必ず通す) |

番号は付けなくてよい。
取り込むときにこちらで振る（下記）。
フォルダ名は分かる名前であれば何でもよい。

`apply()` は1つのプロセスで何度も呼ばれる。
これは MOD を書くうえで一番踏みやすい落とし穴なので、
送る前に [TECH.md §3.4〜§3.6](TECH.md#34-まだ現れていない対象を狙う保留と当て直し) を読んでおくこと。

### 名前がぶつからないようにする

MOD どうしが名前を共有すると**静かに壊れる**。
例外は出ず、片方の機能が黙って効かなくなる。
次の4つは MOD ごとに別の文字列にする。

| 何 | 決まり |
|---|---|
| 自前ボタンの印（mark キー） | `mod_` で始めること（`ui.MARK_PREFIX`）。同梱が使用中のものは [TECH.md §5.1.1](TECH.md#511-組み立て) に一覧がある |
| プロセスに置く控え（`sys` の属性） | `__instantale_<自分の名前>_store__` の形にする |
| `state\` のフォルダ名 | 自分の MOD 名にする。他の MOD の控えを読むときは**フォルダを作らないこと**（[TECH.md §3.11](TECH.md#311-書き込み先out-と-state)） |
| ログの名前・LLM の `manager_name` | 自分の MOD 名にする |

わざと共有する場合は `mod.json` で断る。
他の MOD の控えを読む、相手が置いた印を見る、はこのローダの正しい繋がり方
（MOD どうしは import しない）。
その名前が自分のものでないことを書いておけば、取り合いと区別できる:

```json
"shares": ["npc_profiles"]
```

断りが無いまま同じ名前を2本が使うと `tools/check_mods.py` が止める。
決まりは [TECH.md §3.2.3](TECH.md#323-mod-どうしは-import-しないローダの語彙は共有する)。

## 送り方

GitHub の Issue か Pull Request で受ける。

- <https://github.com/Flossian/InstantaleModLoader/issues>

もしくは公式Discord等からDMで送付も可。

フォルダをそのまま zip で固めたものでもよい。
動いている様子（ログ・画面）が付いていると確かめが速い。

一緒に書いてあると助かること。

- 何をする MOD か。1〜2行でよい
- どのゲームの版で動かしたか
- ローカルの LLM とクラウドのどちらで試したか（両方あればその旨）
- 未確認のまま残っていること

動かない状態で送ってもよい。
「ここまでは動いた・ここから先が分からない」でも受ける。
`404_party_talk` は試作を受け取って正式化したもの。

## 取り込みでこちらがやること

送ったあとに起きること。手を動かすのはこちら側。

1. **番号を振る。**
   出どころを表す `4xx` の帯に入れる（提供された計測 MOD は種別どおり `2xx`）。
   帯の意味は [TECH.md §3.2.2](TECH.md#322-同梱-mod-の番号帯)
2. **こちらの環境へ合わせる。**
   他の MOD との適用順（`mod.json` の `after` / `before`）、重なる機能の調整、
   ローダの共通部品への寄せ（[TECH.md §5](TECH.md#5-共通部品)）。
   `runtime\mods\load_order.json` に名前を載せる（載せないと `docs/MODLIST.md` に出ず、
   `tools/build_mods.py --check` が止まる）
3. **オフライン検証を1本書く。**
   `tools/tests/test_*.py`。ゲーム無しで走り、CI が全件を回す
4. **`DOC.md` を用意する。**
   無ければこちらで書く。`docs/MODS.md` はこれを綴じたもの
5. **名乗りを載せる。**
   `mod.json` の `"author"` にお名前、[NOTICE](../NOTICE) に著作者として記載。
   `docs/MODLIST.md` の「提供を受けた MOD」にも出る。
   ここは `tools/check_mods.py` が検算するので、載せ忘れると CI が止まる

2 で手を入れた内容は `docs/MODS.md` のその MOD の説明に残す。
何をどう変えたかが後から読める状態にしてから同梱する。
