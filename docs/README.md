# InstantaleModLoader

Instantale（Epic版）に、ゲームのファイルを書き換えずに MOD を適用する仕組み。
ローダ本体と、その上で動く MOD 一式を同梱している。

| | |
| --- | --- |
| ゲームフォルダ | 読み込みのみ。ゲームの更新や修復の影響を受けず、このフォルダを消せば元に戻る |
| セーブ | MOD 独自の項目は足さない。書き換えるのはゲームが元から持っている値だけ（§2.3） |
| 必要なもの | Instantale（Epic版）と 64bit の Python。管理者権限は要らない |
| 適用の方法 | 起動中のゲームに注入する。ゲームを起動するたびに注入が要る（§2.1） |

この文書はローダと GUI の使い方を扱う。
ほかの内容は次の文書にある。

- [MODLIST.md](MODLIST.md)：同梱 MOD の1行早見表
- [MODS.md](MODS.md)：MOD 一本ずつの説明・設定・困ったとき
- [TECH.md](TECH.md)：ローダの仕組みと MOD の書き方
- [GAME.md](GAME.md)：ゲーム自身の内部構造（MOD を作る人向け）
- [VERIFICATION.md](VERIFICATION.md) / [VERIFICATION_LOG.md](VERIFICATION_LOG.md)：検証の状況と、検証記録の目次（本文は [verification/](verification/) に1節1ファイル）
- [CONTRIBUTING.md](CONTRIBUTING.md)：作った MOD を同梱に入れてほしいとき

## 1. 導入

### 1.1 必要なもの

- Instantale（Epic版）
- 64bit の Python（3.10 以上、3.13 と 3.14 で動作確認済み）

Python は、3.13 の python.org の既定の場所（`C:\Users\<ユーザー名>\AppData\Local\Programs\Python\Python313\`）、
`py` ランチャー、`PATH` の順に探す。
見つからなければその旨を出して止まる。
32bit の Python が見つかったときも、ゲームが 64bit で注入できないため、その旨を出して止まる。

### 1.2 置く場所

置き場所は自由で、ゲームフォルダの中に入れる必要は無い。

GitHub の Release には zip が3つある。
初めて入れるときは full をダウンロードする。

| zip | 中身 |
| --- | --- |
| `InstantaleModLoader-<版>-full.zip` | 全部入り |
| `InstantaleModLoader-<版>-lite.zip` | full から大きいアセット（`128_item_image_variety` の画像と辞書）を除いたもの。更新用 |
| `InstantaleModLoader-<版>-assets-<ハッシュ>.zip` | 大きいアセットだけ |

GUI の更新ボタンは、必要なほうを選んでダウンロードする（§3.6）。
手で更新するときは、lite の中の `InstantaleModLoader-<版>` フォルダの中身を、インストール先のフォルダへ上書きコピーする。
assets の zip 名のハッシュが、手元の `runtime\assets.json` の `digest` と違うとき（ファイルが無いときも）は、assets も同じようにコピーする。

### 1.3 初回の起動

1. `InstantaleModLoader.bat` をダブルクリックする。MOD の一覧ウィンドウが開く
2. `MOD を注入してゲームを起動` を押す
3. 初回だけ `instantale.exe` の場所を聞かれる。Epic がインストールしたフォルダの中の exe を選ぶ
4. ゲームが起動し、準備ができた時点で MOD が注入される

exe の場所は `settings\gui.json` に保存され、次からは聞かれない。
変えたいときは `ファイル` メニューの `ゲームの場所を設定…`。

### 1.4 効いているかの確認

注入が終わると、一覧の `前回` 列に MOD ごとの結果が出る。
適用されなかった行は赤くなり、下に警告が出る。

ゲームの画面では、タイトル画面の右上に `modloader vX.Y.Z` の1行が出る。
出ていなければ注入されていない。
本文欄の右上にも本のアイコンが増える（押すと過去の本文を読み返せる）。

ログで見るなら `out\modloader.log` の末尾。

```text
boot complete: N/N mod(s) applied
```

左右の数が同じなら、すべて適用されている。
違うときは、一覧の `前回` 列で赤い行を探す（§6.2）。

ゲームの起動直後に注入すると、まだ読み込まれていない部分へのフックは、読み込まれた時点で適用される（段階適用）。
一覧の下に「注入は段階適用の途中です」と出ている間は、その読み込みを待っている。
すべて適用されるまで数十秒かかる。

## 2. 動作の仕様

### 2.1 ゲームを起動するたびに入れ直す

MOD はゲームのプロセスの中で動くので、ゲームを閉じると消える。
ゲームを起動し直したら、注入もし直すこと。
ゲームの設定画面で LLM や画像生成の方式を切り替えると、ゲームは自動で再起動する。
このときも MOD は外れる。

`InstantaleModLoader.bat` の起動ボタンから起動すれば注入される。
ただし起動ボタンが注入するのは1回だけで、ゲームが自動で再起動した後は注入し直さない。
Epic のランチャーから起動することが多いときや、遊ぶ途中で LLM などを切り替えるときは、`tools\watch.bat` を起動したままにしておく。
ゲームの起動を監視して自動で注入する。
監視を始めた時点で既に動いているゲームにも注入するが、そのときは `out\` のログをローテーションしない（注入済みのプレイのログを途中で分けないため）。

```powershell
.\tools\watch.bat          # 起動を監視して自動注入。閉じるときは Ctrl-C
.\tools\watch.bat --once   # すでに起動しているゲームに1回だけ注入して終了
```

### 2.2 セキュリティソフトが反応することがある

ローダは動作中のゲームのプロセスにコードを注入する。
`VirtualAllocEx` でメモリを確保し、`CreateRemoteThread` で実行する。
マルウェアが他のプログラムに侵入するときと同じ手法なので、
Windows Defender や各種セキュリティソフトが警告・ブロックすることがある。
誤検知だが、動作が同じなので製品によっては出続ける。

| | |
| --- | --- |
| していること | ゲームのプロセスに Python のコードを注入し、その中で関数を差し替える |
| していないこと | ゲームフォルダへの書き込み、常駐、他のプログラムへの干渉、管理者権限の要求 |
| 通信 | GUI を開いたときに、GitHub へ新しい版があるかを確かめに行く（§3.6）。ゲームの中では、MOD が LLM を呼ぶときにゲームに設定した LLM へゲームと同じ経路で送る。ほかの通信はしない |
| 止めている通信 | ゲーム本体がクラッシュ記録をゲームの作者のサーバへ送る処理。MOD のスタックフレームが混ざった記録を送らないため |
| 判断の材料 | ソースは全て読める。注入の手順は [TECH.md](TECH.md) §1 |

### 2.3 セーブとゲームファイルへの影響

- ゲームフォルダは読むだけで、書き込まない
- セーブに書くのは、ゲームが元から持っている値だけ（パーティの名簿・依頼・エリアのBGMなど）。
  MOD 独自の項目は足さない
- MOD が追加した選択肢ボタンは、押した時点で、ゲームに元からある害のない動作に差し替わる。
  MOD 無しで次回起動しても壊れない。
  ボタンがセーブに残ることはあるが、押しても何も起きない
- NPC の名前だけは書き換えることがある。
  生成された名前が世界に居る誰かと同じに読めるとき（ビクトル / ヴィクトル）に別の名前へ付け直す。
  書き換えは `out\npc_name.log` に記録する
- 既存セーブの BGM の偏りを一括で直すツール（`tools\rebalance_saved_bgm.py`）だけはセーブを書き換える。
  既定は dry-run で、実行時は自動でバックアップを作る

### 2.4 できないこと

- MOD はゲーム起動後に注入されるので、起動時に一度だけ走る処理は変えられない
- LLM の推論中に注入すると、完了まで時間がかかることがある。
  30秒たっても終わらないときは「注入の完了待ち」と出るが、待てば完了する
- `MOD を外す` では完全には元に戻らない。
  起動時に一度だけ走った処理や、MOD がセーブに書いた値は戻らない。
  MOD なしのゲームで確かめたいなら、注入せずに起動し直す

## 3. GUI（MOD 一覧ウィンドウ）

### 3.1 一覧

上にあるものから順に適用される。

| 列 | 意味 |
| --- | --- |
| 左端のチェック | 有効/無効。無効にした MOD は読み込まれない（フォルダは消さない） |
| 順 | 適用順。行をドラッグ、または右クリックの `上へ / 下へ` で入れ替える |
| 設定 | `○` を押すとその MOD の設定が開く。変更済みなら `●` |
| 前回 | 前回の注入でその MOD が適用されたか。適用されなかった行は赤 |

行を選ぶと右側に説明が出る。
`English` にチェックを入れると英語の名前と説明も並ぶ。

一覧が長いときは上の `検索` と `表示` で絞り込む。
`表示` は `すべて / 有効のみ / 無効のみ / 前回失敗 / 設定あり`。
`解除` で戻る。

### 3.2 ボタンとメニュー

| | どこ | 何をするか |
| --- | --- | --- |
| MOD を注入してゲームを起動 | 下・`実行`（F9） | ゲームを起動して注入する。すでに動いていれば起動は飛ばして注入だけする |
| MOD を外す | 下・`実行` | 遊んでいる途中で MOD を外す。ゲームは終了しない（§2.4） |
| 保存 | 下・`ファイル`（Ctrl+S） | 順序と有効/無効を `runtime\mods\load_order.json` に書く。次の注入から効く |
| MOD を追加… | `ファイル`（Ctrl+O） | zip でもフォルダでも選べる。`runtime\mods\` にコピーされ、一覧の末尾に付く |
| 読み直す | `ファイル`（F5） | フォルダを直接変更したあとに、一覧を読み込み直す |
| ゲームの場所を設定… | `ファイル` | `instantale.exe` を選び直す |
| 有効 / 無効・設定… | `MOD`・右クリック（Space / Enter） | 選んでいる行の切り替えと設定 |
| MOD のフォルダを開く | `MOD`・右クリック | 一覧に出ない設定を直接書き換えるときに使う |
| 記録を開く | 右クリック | `state/` にあるその MOD の保存データを開く。消すとその内容が失われる（§5）。保存データが2つ以上ある MOD は開く先を選ぶ。まだ保存データが無い MOD では押せない |
| ログのフォルダを開く | `実行` | `out/` を開く。消してよい |
| MOD の記録のフォルダを開く | `実行` | `state/` を開く。消すとその内容が失われる（§5） |
| デバッグモード | `実行` | 開発者向けの MOD を一覧に出す（§3.4） |
| 注入のたびにログを新しくする | `実行` | 既定 ON（§3.5） |
| 更新 (vX.Y.Z) | 右上 | GitHub に新しい版があるときだけ出る（§3.6） |
| このバージョンの更新内容… | `ヘルプ` | 今の版のリリースノートを出す。一度取得したらキャッシュから読む（§3.6） |
| GitHub を開く | `ヘルプ` | 配布元のページをブラウザで開く |

ウィンドウの大きさと位置は、閉じたときのものが保存される。

並べ替えや有効/無効を保存しないまま、閉じる・`読み直す`・`MOD を追加…` をすると、先に保存するかを聞かれる。
注入の後に一覧が自動で読み直されるときも、保存していない変更は消さない（状態欄に「未保存」と出る）。

### 3.3 設定の変え方

一覧の `設定` 列を押す。
変えた値は `settings\mod_settings.json` に保存され、MOD を新しい版に差し替えても残る。
反映は次の注入から（ゲーム再起動＋再注入）。
どの MOD に何の設定があるかは [MODS.md](MODS.md) に MOD ごとに書いてある。

設定の多い MOD では項目の一覧だけがスクロールし、`OK` と `キャンセル` は下に固定される。

ウィンドウに出ない設定は MOD のコードの先頭にまとめてある。
どのファイルが入口かは、そのフォルダの `mod.json` に書いてある。
コードを書き換えた値は、MOD を新しい版に差し替えると消える。

### 3.4 デバッグモード

既定は OFF。
OFF の間、一覧に出ず読み込まれもしない MOD が2種類ある。

| | |
| --- | --- |
| 計測用の MOD（`2xx`） | 不具合の原因を調べるためのもの。遊ぶだけなら要らない。計測のぶん動作は重くなる |
| 本体が取り込んだ修正 | ゲームの更新で同じ修正が入ったので無効にしたもの。一覧では `〔main_024 で本体が取込〕` と出る |

ON にするのは、不具合の報告でログの採取を頼まれたときか、
修正が取り込まれる前の版のゲームで遊ぶとき。
切り替えは `settings\loader.json` に保存され、次の注入から効く。

### 3.5 ログの世代管理

`out\*.log` と `out\*.jsonl` は注入のたびに新しくなる。
前回の内容は `modloader.log.1` のように `.1` を付けて1世代だけ残り、それより古いものは消える。
ログが数MBまで増えるのを防ぐため、既定は ON。

複数回のプレイをまたいでログを追いたいときは、`実行` メニューのチェックを外す。
更新の前後で挙動を比べるときは、始める前に外しておく。
ローテーションされると比較元のログが消える。

その実行だけ無効にするならコマンドラインで指定する。

```bat
.\tools\watch.bat --no-log-rotate
```

`out\status.json` などログ以外のファイルと、`out\test\` `out\recon\` の中身は対象外。
残す世代数などの設定は [TECH.md](TECH.md) §1.5。

### 3.6 更新機能 (v1.11.0から)

右上に `更新 (vX.Y.Z)` が出ていれば、GitHub に新しい版がある。
押すと新しい版をダウンロードしてこのフォルダへ上書きし、ウィンドウを開き直す。

ダウンロードするのは full か lite のどちらか（§1.2）。
大きいアセット（`128_item_image_variety` の画像と辞書）は、画像を足した版でしか変わらない。
手元のアセットのハッシュ（`runtime\assets.json`）と新しい版のハッシュが同じなら、アセットを除いた lite（数 MB）をダウンロードする。
違うとき・手元にハッシュが無いときは full になる。
手元の画像と辞書のファイルは調べないので、要らないカテゴリの画像を消していても lite のまま（消した画像は戻らない）。
消した画像を戻したいときは、`runtime\assets.json` を消してから更新すると full になる。
どちらをダウンロードするかとサイズは、押した後の確認に出る。

開き直した後、新しい版のリリースノート（GitHub の Release と同じ文）が別のウィンドウに出る。
何版か飛ばして更新したときは、間の版も新しい順に続けて出る。
zip を手で上書きした場合も、次にウィンドウを開いたときに出る。
ネットにつながらず取得できなかったときは、次に開いたときにもう一度取得する。
後から読み直すときは `ヘルプ` メニューの `このバージョンの更新内容…`。
一度取得した文は `out\release_notes.json` にキャッシュするので、読み直しにネットは要らない（消しても次に読むとき取得し直す）。

更新で消えるものは無い。
`settings\`・`state\`・`local\` と手元で足した MOD は配布物に含まれないので、上書きされない。
新しい版で無くなった MOD のフォルダも消さない（手元で作っているものと区別できないため）。
`load_order.json` は新しい版に置き換わるが、無効にしていた MOD は無効のまま、手で足した MOD は末尾に残る。
並び順だけは新しい版の順に戻る（版によって `after` の宣言が変わるため）。

## 4. MOD を止める・外す

| したいこと | やること |
| --- | --- |
| 1つ止める | 一覧のチェックを外して `保存`。`load_order.json` の `"disabled"` に入り、読み込まれなくなる。戻すときはチェックを入れ直す |
| ウィンドウを開かずに止める | フォルダ名の先頭に `_` を付ける |
| 遊んでいる途中で外す | `MOD を外す`。完全には戻らない（§2.4） |
| MOD なしのゲームで確かめる | 注入せずに起動する |
| 完全に消す | このフォルダを消す |

## 5. ファイルの置き場所

| | |
| --- | --- |
| `InstantaleModLoader.bat` | これをダブルクリックする |
| `runtime\instantale_modloader\` | ローダ本体（注入・パッチ管理） |
| `runtime\mods\` | MOD 本体。`load_order.json` が適用順と無効一覧、`_template\` がテンプレート（読み込まれない） |
| `runtime\assets.json` | 入っている大きいアセットのハッシュ。更新ボタンが lite と full のどちらをダウンロードするかをこれで決める。消すと次の更新は full になる |
| `local\` | 配らない MOD の置き場所（無くてよい）。置き方は [TECH.md](TECH.md) §2.6.2 |
| `settings\` | 設定。`mod_settings.json`（MOD の設定）、`gui.json`（ゲームの場所・ウィンドウ・リリースノートを出した版）、`loader.json`（デバッグモード・ログ） |
| `out\` | ログ。ログ各種と `status.json`（前回の注入の結果）、`release_notes.json`（リリースノートのキャッシュ）。消してよい |
| `state\` | MOD の保存データ（進行中の道中、依頼の出所、NPC の人物像、過去の本文）。消すとその内容が失われる |
| `tools\` | GUI・注入・監視のスクリプトと、開発用のツール |
| `docs\` | この文書と、冒頭に挙げた各文書 |

書き込み先を3つに分けているのは、消してよいもの（`out\`）と消してはいけないもの（`settings\`・`state\`）を区別するため。
どれも MOD を新しい版に差し替えても残る。

## 6. うまく動かないとき

### 6.1 MOD が効いていない

まずタイトル画面の右上に `modloader vX.Y.Z` が出ているかを見る。

| 見えていること | 原因とやること |
| --- | --- |
| タイトル画面に `modloader` の行が無い | 注入されていない。`MOD を注入してゲームを起動` を押す。ゲームは起動したままでよい（注入し直しても二重には適用されない） |
| 遊ぶ途中から効かなくなった | LLM や画像生成の方式を切り替えて、ゲームが自動で再起動した（§2.1）。注入し直す |
| 一部の MOD だけ効かない | 一覧の `前回` 列で赤い行を探す（§6.2） |

### 6.2 起動・注入で出るメッセージ

| 出たメッセージ | 意味とやること |
| --- | --- |
| `No 64-bit Python found.`（コンソール） | Python が見つからない。python.org から 64bit 版を入れるか、`InstantaleModLoader.bat` の `PYEXE=` の行を書き換える |
| 「64bit の Python が必要です」 | 32bit の Python が使われた。64bit 版を入れる |
| 何も開かない | tkinter の無い Python が使われている。`tools\watch.bat` はコンソールで動き、同じ手順で Python を探すので、どの Python が使われたかが分かる |
| instantale.exe が複数起動しています | 取り違えを避けるため自動では選ばない。ゲームを1つにする |
| ゲームのプロセスが見つかりません | 60秒探して見つからなかった。Epic 経由の起動が遅いときに出る。ゲームが起動してからもう一度押す |
| 注入の完了待ちです | 失敗ではない。ゲームが処理中で、終わり次第、注入が完了する（§2.4） |
| 注入に失敗しました | 原因は `out\bootstrap.log` |
| 注入は段階適用の途中です | 失敗ではない。数十秒待つ（§1.4） |
| 前回の注入で対象が見つからなかったフック N 件 | ゲームの更新で、MOD がフックする関数が無くなった可能性がある。どの MOD のどの関数かは `out\modloader.log` の `UNRESOLVED` の節 |

一覧の `前回` 列には、MOD ごとの適用の結果が出る。
`適用` 以外は赤い行になり、その MOD だけが適用されていない（ほかの MOD は動く）。

| `前回` 列 | 意味 |
| --- | --- |
| 読込失敗・適用失敗 | MOD のコードで例外が出た。トレースバックは `out\modloader.log` |
| ローダが古い | MOD が新しいローダを前提にしている。§3.6 でローダを更新する |
| mod が古い | 今のローダが対応していない古い MOD。MOD の更新を待つ |
| 入口なし・apply なし | `mod.json` が指す入口のファイルが無いか、そのファイルに `apply()` が無い。MOD を入れ直す |

### 6.3 ゲームが落ちる

| 状況 | 見るファイル |
| --- | --- |
| 遊んでいる途中で落ちる | `out\live_crashes.log`（`001_crash_recorder` が全文を残す） |
| 起動して間もなく落ち、`out\live_crashes.log` に何も増えない | `001_crash_recorder` が動き出す前に落ちている。ゲームフォルダの `crash_log.txt` と `%USERPROFILE%\.kivy\logs\` |

MOD が原因かを切り分けるときは、注入せずに起動する。
同じように落ちるならゲーム側の問題。
落ちなければ、MOD を半分ずつ無効にして絞り込む（§4）。

MOD ごとの症状は [MODS.md](MODS.md) の各 MOD の「困ったとき」。
セキュリティソフトが止めるときは §2.2。

### 6.4 不具合ではないもの

| | |
| --- | --- |
| 「依頼を受ける」を押すと会話が終わる | 依頼の話をするために会話を切り上げている。ボタンにもそう書いてある |
| クエストをクリアしても仲間が離れない | `348_party_departure` の「依頼が終わっても解散しない」の効果。戻し方は [MODS.md](MODS.md) のその項 |
| MOD 無しで起動すると追加ボタンが何もしない | セーブに残ったボタン。押しても害は無い |
| 選択肢を押しても何も起きない | 本文欄が「…」の間は処理中。終わるまで待つ |

### 6.5 報告するとき

送るものは `out\` の中身（`modloader.log`・`bootstrap.log`・`status.json`、落ちたなら `live_crashes.log`）。
起動して間もなく落ちたなら、ゲームフォルダの `crash_log.txt` も足す。
注入せずに起動しても同じことが起きるかも書く。
送り先は [CONTRIBUTING.md](CONTRIBUTING.md) と同じ（GitHub の Issue か、公式 Discord などの DM）。
ログの採取を頼まれたら、デバッグモード（§3.4）を ON にして再現する。
