# InstantaleModLoader

Instantale（Epic版）に、ゲームのファイルを一切書き換えずに MOD を効かせる仕組み。
ローダ本体と、その上で動く MOD 一式が同梱してある。

| | |
| --- | --- |
| ゲームフォルダ | 読込のみ。書き込みはしない。ゲームの更新や修復で壊れず、このフォルダを消せば完全に元通り |
| セーブ | MOD 独自の項目は足さない。書き換えるのはゲーム自身が持っている値だけ |
| 必要なもの | Instantale（Epic版）と 64bit の Python。管理者権限は要らない |
| 効き方 | 起動中のゲームに後から入る。ゲームを起動するたびに入れ直す |

このドキュメントはローダと GUI の使い方を記載した。
何が変わるかは別の文書に記載した。

- [MODLIST.md](MODLIST.md)：同梱 MOD の1行早見表
- [MODS.md](MODS.md)：MOD 一本ずつの説明・設定・困ったとき
- [TECH.md](TECH.md)：ローダの仕組みと MOD の書き方
- [GAME.md](GAME.md)：ゲーム自身の内部構造（MOD を作る人向け）
- [VERIFICATION.md](VERIFICATION.md) / [VERIFICATION_LOG.md](VERIFICATION_LOG.md)：どこまで確かめてあるかと、その記録
- [CONTRIBUTING.md](CONTRIBUTING.md)：作った MOD を同梱に入れてほしいとき

## 1. 導入

### 1.1 必要なもの

- Instantale（Epic版）
- 64bit の Python（3.10 以上、3.13 で動作確認済み）

Python は python.org の既定の場所（`C:\Users\<ユーザー名>\AppData\Local\Programs\Python\PythonXXX\`）、
`py` ランチャー、`PATH` の順に探す。
見つからなければその旨を出して止まる。
32bit しか無いときも同じで、ゲームが 64bit なので注入できないと出て止まる。
「押しても何も起きない」にはならない。

### 1.2 置く場所

どこでも動く。
ゲームフォルダの中に入れる必要は無い。

### 1.3 初回の起動

1. `InstantaleModLoader.bat` をダブルクリックする。MOD の一覧ウィンドウが開く
2. `MOD を注入してゲームを起動` を押す
3. 初回だけ `instantale.exe` の場所を聞かれる。Epic がインストールしたフォルダの中の exe を選ぶ
4. ゲームが立ち上がり、準備が整った時点で MOD が入る

exe の場所は `settings\gui.json` に残り、次からは聞かれない。
変えたいときは `ファイル` メニューの `ゲームの場所を設定…`。

### 1.4 効いているかの確認

一覧の `前回` 列が答え。
注入が終わると、何本入ったか、何が失敗したかがそのまま一覧に出る。
入らなかった行は赤くなり、下に警告が出る。

ゲーム内で分かりやすいのは次の3つ。

- 本文の枠の右上に本のアイコンが増える（押すと流れた本文を読み返せる）
- 宿屋や店に入ると、NPC から話しかけてくることがある
- NPC と会話すると「会話を終了する」の上に「依頼を受ける（話を切り上げる）」がある

ログで見るなら `out\modloader.log` の末尾。

```text
boot complete: N/N mod(s) applied
```

左右の数が揃っていなくても失敗とは限らない。
LLM 関連の MOD は、ゲームが LLM を起動してから入る。
LLM を一度動かしてからもう一度見ると揃う。

## 2. 動作の仕様

### 2.1 ゲームを起動するたびに入れ直す

MOD はゲームのプロセスの中に居るので、ゲームを閉じると一緒に消える。
再起動したら必ず注入し直すこと。
入れ忘れると素のゲームが動き、修正も追加要素も効かないまま遊ぶことになる。

`InstantaleModLoader.bat` の起動ボタンから立ち上げれば必ず入る。
Epic のランチャーから起動する癖があるなら、`tools\watch.bat` を立てっぱなしにしておく。
ゲームの起動を見張って自動で注入する。

```powershell
.\tools\watch.bat          # 起動を監視して自動注入。閉じるときは Ctrl-C
.\tools\watch.bat --once   # すでに起動しているゲームに1回だけ入れて終了
```

### 2.2 セキュリティソフトが反応することがある

ローダは動作中のゲームのプロセスにコードを送り込む。
`VirtualAllocEx` でメモリを確保し、`CreateRemoteThread` で実行する。
これはマルウェアが他のプログラムへ寄生するときの手口と技術的に同一なので、
Windows Defender や各種セキュリティソフトが警告・ブロックすることがある。

害は無いという意味では誤検知。
ただし振る舞いそのものが同じなので、製品によっては今後も出続ける。

| | |
| --- | --- |
| していること | ゲームのプロセスに Python のコードを流し込み、その中で関数を差し替える |
| していないこと | ゲームフォルダへの書き込み、常駐、通信、他のプログラムへの干渉、管理者権限の要求 |
| 判断の材料 | ソースは全て読める。注入の手順そのものは [TECH.md](TECH.md) §1 |

v1.11.0以降、 アプリを開いたときに GitHub へ新しいバージョンがあるかを確かめに行く。
新バージョンがあれば GUI 上から更新ができる。

Mod 導入中は、ゲーム本体がクラッシュ記録を作者のサーバへ送る段を止めている（MOD の枠が混ざった記録を送らないため）。

### 2.3 セーブとゲームファイルへの影響

- ゲームフォルダは読むだけで、一切書き込まない
- セーブに書くのは、ゲーム自身が持っている値だけ（パーティの名簿・依頼・エリアのBGMなど）。
  MOD 独自の項目は足さない
- MOD が追加した選択肢ボタンは、押した瞬間に無害な既存の動作へ差し替わる。
  MOD 無しで次回起動しても壊れない。
  残骸のボタンが残ることはあるが、押しても何も起きないだけ
- NPC の名前だけは2つの場合に書き換える。
  生成された名前が世界に居る誰かと同じに読めるとき（バルガス / ヴァルガス）。
  書き換えは `out\character_name.log` と `out\npc_name.log` に残る
- 既存セーブの BGM を一括で均す道具（`tools\rebalance_saved_bgm.py`）だけはセーブを書き換える。
  既定は dry-run で、実行時は自動でバックアップを作る

### 2.4 できないこと

- MOD はゲーム起動後に入るので、起動時に一度だけ走る処理には手が届かない
- LLM の推論中に注入すると、入るまで時間がかかることがある。
  30秒でタイムアウト表示が出ても、その後ちゃんと入る
- `MOD を外す` で完全に元通りにはならない。
  起動時に一度だけ走った処理や、MOD がセーブに書いた値は戻らない。
  素のゲームで確かめたいなら、注入せずに起動し直す

## 3. GUI（MOD 一覧ウィンドウ）

### 3.1 一覧

上にあるものから順に適用される。

| 列 | 意味 |
| --- | --- |
| 左端のチェック | 有効/無効。無効にした MOD は読み込まれない（フォルダは消さない） |
| 順 | 適用順。行をドラッグ、または右クリックの `上へ / 下へ` で入れ替える |
| 設定 | `○` を押すとその MOD の設定が開く。変更済みなら `●` |
| 前回 | 前回の注入でその MOD が入ったか。入らなかった行は赤 |

行を選ぶと右側に説明が出る。
`English` にチェックを入れると英語の名前と説明も並ぶ。

一覧が長くなったら上の `検索` と `表示` で絞る。
`表示` は `すべて / 有効のみ / 無効のみ / 前回失敗 / 設定あり`。
`解除` で戻る。

### 3.2 ボタンとメニュー

| | どこ | 何をするか |
| --- | --- | --- |
| MOD を注入してゲームを起動 | 下・`実行`（F9） | ゲームを起動して注入する。すでに動いていれば起動は飛ばして注入だけする |
| MOD を外す | 下・`実行` | 遊んでいる途中で MOD を切り離す。ゲームは終了しない（§2.4） |
| 保存 | 下・`ファイル`（Ctrl+S） | 順序と有効/無効を `runtime\mods\load_order.json` に書く。次の注入から効く |
| MOD を追加… | `ファイル`（Ctrl+O） | zip でもフォルダでも選べる。`runtime\mods\` に入って一覧の末尾に付く |
| 再読み込み | `ファイル`（F5） | フォルダを直に触ったあとに一覧を組み直す |
| ゲームの場所を設定… | `ファイル` | `instantale.exe` を選び直す |
| 有効 / 無効・設定… | `MOD`・右クリック（Space / Enter） | 選んでいる行の切り替えと設定 |
| この MOD のフォルダを開く | `MOD`・右クリック | 一覧に出ない設定を直に書き換えるときに使う |
| out/ フォルダを開く | `実行` | ログ。消してよい |
| state/ フォルダを開く | `実行` | MOD の記録。消すと巻き戻る（§5） |
| デバッグモード | `実行` | 開発者向けの MOD を一覧に出す（§3.4） |
| 注入のたびにログを新しくする | `実行` | 既定 ON（§3.5） |
| 更新 (vX.Y.Z) | 右上 | GitHub に新しい版があるときだけ出る（§3.6） |

ウィンドウの大きさと位置は閉じたときのものが残る。

### 3.3 設定の変え方

一覧の `設定` 列を押す。
変えた値は `settings\mod_settings.json` に入り、MOD を新しい版に差し替えても残る。
反映は次の注入から（ゲーム再起動＋再注入）。
どの MOD に何の設定があるかは [MODS.md](MODS.md) が MOD ごとに書いている。

設定の多い MOD では項目の並びだけがスクロールし、`OK` と `キャンセル` は下に据え置き。

ウィンドウに出ない設定は MOD のコードの先頭にまとまっている。
どのファイルが本体かは、そのフォルダの `mod.json` に書いてある。
コードを書き換えた値は、MOD を新しい版に差し替えると消える。

### 3.4 デバッグモード

既定は切。
切っているあいだ、一覧に出ず読み込まれもしない MOD が2種類ある。

| | |
| --- | --- |
| 計測用の MOD（`2xx`） | 原因を測るための道具。遊ぶだけなら要らない。測るぶん動作は重くなる |
| 本体が取り込んだ修正 | ゲームの更新で同じ修正が入ったので降ろしたもの。一覧では `〔main_024 で本体が取込〕` と出る |

入れるのは、不具合の報告でログを採ってほしいと頼まれたときか、
取り込まれる前の版のゲームで遊ぶときくらい。
切り替えは `settings\loader.json` に残り、効くのは次の注入から。

### 3.5 ログの世代管理

`out\*.log` は注入のたびに新しくなる。
前回の内容は `modloader.log.1` のように `.1` を付けて1世代だけ残り、それより古いものは消える。
放っておくとログが数MBまで育つので、既定で ON。

複数回のプレイをまたいで追いたいときは、`実行` メニューのチェックを外す。
更新の前後で挙動を比べる作業では、始める前に必ず切ること。
入れ替えてしまうと比較の土台ごと消える。

その実行だけ切るならコマンドラインで指定する。

```bat
.\tools\watch.bat --no-log-rotate
```

`out\status.json` などログ以外のファイルと、`out\test\` `out\recon\` の中身は対象外。
残す世代数などの細かい設定は [TECH.md](TECH.md) §1.5。

### 3.6 更新機能 (v1.11.0から)

右上に `更新 (vX.Y.Z)` が出ていれば、GitHub に新しいバージョンがある。
押すと full 版をダウンロードしてこのフォルダへ上書きし、ウィンドウを開き直す。

消えるものは無い。
`settings\`・`state\`・`local\` と手元で足した MOD は配布物に入らないので、上書きが触らない。
新しい版で無くなった MOD のフォルダも消さない（手元で作っているものと見分けが付かないため）。

## 4. MOD を止める・外す

| したいこと | やること |
| --- | --- |
| 1つ止める | 一覧のチェックを外して `保存`。`load_order.json` の `"disabled"` に入り、読み込まれなくなる。戻すのはチェックを入れ直すだけ |
| ウィンドウを開かずに止める | フォルダ名の先頭に `_` を付ける |
| 遊んでいる途中で外す | `MOD を外す`。完全には戻らない（§2.4） |
| 素のゲームで確かめる | 注入せずに起動する。ローダは何も残さない |
| 完全に消す | このフォルダを消す。ゲームフォルダには何も無い |

## 5. ファイルの置き場所

| | |
| --- | --- |
| `InstantaleModLoader.bat` | これをダブルクリックする |
| `runtime\instantale_modloader\` | ローダ本体（注入・パッチ管理） |
| `runtime\mods\` | MOD 本体。`load_order.json` が適用順と無効一覧、`_template\` が雛形（読み込まれない） |
| `local\` | 配らない MOD の置き場所（無くてよい）。置き方は [TECH.md](TECH.md) §2.6.2 |
| `settings\` | 自分で決めたこと。`mod_settings.json`（MOD の設定）、`gui.json`（ゲームの場所・ウィンドウ）、`loader.json`（デバッグモード・ログ） |
| `out\` | 記録。ログ各種と `status.json`（前回の注入の結果）。消してよい |
| `state\` | 遊びの続き。MOD が覚えている内容（進行中の道中、依頼の出所、NPC の人物像、流れた本文の控え）。消すとその分だけ巻き戻る |
| `tools\` | GUI・注入・監視のスクリプトと、開発用の道具 |
| `docs\` | この文書と、冒頭に挙げた各文書 |

書き込み先を3つに分けてあるのは、消していいものと消してはいけないものを一目で分けるため。
`settings\` は自分で決めたこと、`out\` は記録、`state\` は遊びの続き。
どれも MOD を新しい版に差し替えても残る。

## 6. うまく動かないとき

### 6.1 まず入れ直す

`MOD を注入してゲームを起動` をもう一度押す。
ゲームは起動したままでよい。
音の不具合や「イベントが出なくなった」は、入れ直しでその場で直ることが多い。
変わらなければ、ゲームを終了してから起動ボタンで立ち上げ直す。

### 6.2 全体に関わる症状

| 症状 | やること |
| --- | --- |
| イベントも追加ボタンも出ない | 入れ直す。タイトル画面右上に`vX.Y.Z`の記載がなかったり、`out\modloader.log` に `boot complete:` が無ければ入っていない |
| ウィンドウが開かない | Python が見つかっていないか、tkinter の無い Python を掴んでいる。`tools\watch.bat` はコンソールで動くので、同じ探し方で何を掴んだかが読める |
| 選択肢を押しても何も起きない | 画面が「…」の間は処理中。終わるまで待つ |
| ゲームが落ちる・様子がおかしい | 注入せずに起動すれば完全に素のゲームとして動く。記録は `out\live_crashes.log` |
| セキュリティソフトが止める | §2.2。除外に入れるか、諦めるかの判断材料はそこにある |

MOD ごとの症状は [MODS.md](MODS.md) の各 MOD の「困ったとき」。

### 6.3 不具合ではないもの

| | |
| --- | --- |
| 「依頼を受ける」を押すと会話が終わる | 依頼の話をするために会話を切り上げている。ボタンにもそう書いてある |
| クエストをクリアしても仲間が離れない | `304_quest_end_keep_party` の効果。戻し方は [MODS.md](MODS.md) のその項 |
| MOD 無しで起動すると追加ボタンが何もしない | セーブに残った残骸。押しても害は無い |
| `boot complete` の数が揃わない | LLM 関連の MOD は LLM の起動後に入る（§1.4） |

### 6.4 報告するとき

`out\` の中身と、落ちたなら `out\live_crashes.log` があれば足りる。
ログを採ってほしいと頼まれたらデバッグモード（§3.4）を入れて再現する。
