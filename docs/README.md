# InstantaleModLoader

Instantale（Epic版）にゲームのファイルを一切書き換えずに MOD を効かせる仕組み。
ローダ本体と、その上で動く MOD 一式が入っている。

- ゲームフォルダには何も書き込まない。Epic のアップデートや修復（repair）をしても
  壊れないし、MOD 側を消すだけで完全に元通りになる
- 管理者権限は不要。追加のインストールも不要（Python だけ）
- セーブは壊さない。MOD が書き換えるのはゲームが自分で保存する値だけ

このドキュメントは前半がローダと GUI の使い方、後半が同梱 MOD の一覧。
何がどこまで直るか・何が増えるかを知りたい場合は
[同梱している MOD](#第2部-同梱している-mod) へ。

技術的な中身は別のドキュメントにある。

- [TECH.md](TECH.md)：ローダの仕組みと MOD の書き方
- [GAME.md](GAME.md)：実測でわかったゲーム自身の構造
- [VERIFICATION.md](VERIFICATION.md)：検証の状況

---

# 第1部 ローダと GUI

## 仕組み

ゲームは書き換えない。起動しているゲームのプロセスに、あとから MOD を差し込む。

1. ゲームが立ち上がり、準備が整うのを待つ
2. ローダがゲームのプロセスへ入り込み、`runtime\mods\` の MOD を上から順に読み込む
3. 各 MOD がゲーム内部の関数を差し替える（元の関数は保持されるので、外すこともできる）

ゲームフォルダは読むだけで、書き込みは一切しない。MOD はゲームのプロセスと一緒に消える。

> ## ゲームを起動するたびに入れ直しが必要
>
> ゲームを再起動したら必ず注入し直すこと。忘れると素のゲームが動き、修正も追加要素も
> 何も効かないまま遊ぶことになる。
>
> `InstantaleModLoader.bat` の起動ボタンから立ち上げれば必ず入る。ゲームを別の
> 場所から起動する癖があるなら、`tools\watch.bat` を立てっぱなしにしておくと確実。

---

## 導入する前に

以下は動作の不具合ではなく、この方式を選んだ以上は避けられない性質。

### セキュリティソフトが反応することがある

上の「仕組み」の2で、ローダは動作中のゲームのプロセスにコードを送り込む。手順は
`VirtualAllocEx` でプロセスにメモリを確保し、`CreateRemoteThread` でそこを実行する。
これはマルウェアが他のプログラムへ寄生するときの手口と技術的に同一。

そのため Windows Defender や各種セキュリティソフトが、このツールを疑わしいものとして
警告・ブロックすることがある。害が無いという意味では誤検知。ただし振る舞いそのものが
同じで出る警告なので、製品によっては今後も出続ける。

| | |
|---|---|
| 何をしているか | ゲームのプロセスに Python のコードを流し込み、その中で関数を差し替える |
| 何をしていないか | ゲームフォルダへの書き込み、常駐、通信、他のプログラムへの干渉、管理者権限の要求 |
| 判断の材料 | ソースは全て読める（[TECH.md](TECH.md) §1 に注入の手順そのものが書いてある）。信用できないなら動かさないこと |

## 導入

### 必要なもの

- Instantale（Epic版）
- 64bit の Python（3.13 で動作確認済み）。ゲームが 64bit なので、32bit 版からは
  注入できない

Python はどこに入れてあってもよい。場所は自動で探す。
`C:\Users\<ユーザー名>\AppData\Local\Programs\Python\Python313\`（python.org の既定の
インストール先）にあれば一番速く、無ければ `py` ランチャー → `PATH` の順に探す。
見つからなければその旨を表示して止まる。

> 32bit の Python しか見つからなかった場合も、その旨を出して止まる。
> 「起動ボタンを押しても何も起きない」にはならない。

このフォルダをどこに置いても構わない（既定は `Desktop\InstantaleMods\InstantaleModLoader`）。
ゲームフォルダの中に入れる必要はない。

### 使い方

`InstantaleModLoader.bat` をダブルクリックする。MOD の一覧が出るので、
「Mod を注入してゲームを起動」を押せばゲームが立ち上がり、準備が整った時点で
MOD が入る。

## GUI（MOD 一覧ウィンドウ）

一覧でできること:

| | |
|---|---|
| 並べ替え | 行をドラッグ（または `▲上へ / ▼下へ`）。上にあるものから順に適用される |
| 有効/無効 | 左端のチェックを押す。無効にした MOD は読み込まれない（フォルダは消さない） |
| 設定 | `設定` 列の `○` を押す（変更済みなら `●`）。MOD ごとの設定を変えられる |
| 保存 | `保存` を押すと `runtime\mods\load_order.json` に書かれる。次の注入から効く |
| MOD を追加 | zip でもフォルダでも選べる。`runtime\mods\` に入って一覧の末尾に付く |
| この MOD を開く | 選んでいる MOD のフォルダをエクスプローラで開く。一覧に出ない設定を直に書き換えるときに使う |
| 前回 | 前回の注入でその MOD が入ったか。失敗したものは赤くなる |
| MOD を外す | 遊んでいる途中で MOD を切り離す。ゲームは終了しない |

ウィンドウの大きさと位置は閉じたときのものが残り、次に開くと同じ場所に出る
（`settings\gui.json`）。

`前回` の列と、その下に出る警告が「本当に入ったか」の答え。ゲームを起動して注入すると、
何本入ったか・何が失敗したかがそのまま一覧に出る（ログを開かなくてよい）。

### コンソールから使う

ウィンドウを使わず済ませることもできる。`tools\watch.bat` を立てておくと、
ゲームの起動を見張って自動で注入する:

```powershell
.\tools\watch.bat          # 起動を監視して自動注入。閉じるときは Ctrl-C
.\tools\watch.bat --once   # すでに起動しているゲームに1回だけ入れて終了
```

### 効いているかの確認

`out\modloader.log` の末尾に、こう出ていれば入っている:

```
boot complete: 32/32 mod(s) applied
```

数が足りなくても失敗とは限らない。AI関連の MOD は最初の会話まで待ってから入る
（ゲームがその部分を後から読み込むため）。会話を1回してからもう一度ログを見ると揃う。

ゲーム内で分かりやすいのは:

- 宿屋や店に入ったときに NPC から話しかけてくることがある
- NPC と会話すると「会話を終了する」の上に「依頼を受ける（話を切り上げる）」がある
- ギルドの「クエスト掲示板」に「軽い頼まれごとを探す」がある

## 設定の変え方

一覧の `設定` 列を押す。よく触る設定はウィンドウから変えられる。変えた値は
`settings\mod_settings.json` に入り、MOD を新しい版に差し替えても残る。
次に注入するときから反映される（ゲーム再起動＋再注入）。

どの MOD にどんな設定があるかは、後半の[同梱している MOD](#第2部-同梱している-mod) に
MOD ごとに書いてある。

それ以外の設定はコードに入っている。MOD のフォルダにある `.py` を開くと、先頭に
設定がまとまっている（どのファイルが本体かは同じフォルダの `mod.json` に書いてある）。

> コードを書き換えた場合、その値は MOD を新しい版に差し替えると消える。
> ウィンドウから変えた設定（`settings\mod_settings.json`）は残る。

### MOD を止める・外す

MOD を1つ止めたいときは、`InstantaleModLoader.bat` の一覧でチェックを外して保存する。
無効にしたものは `load_order.json` の `"disabled"` に記録され、読み込まれなくなる
（フォルダはそのまま残るので、戻すのはチェックを入れ直すだけ）。
ウィンドウを開かずに止めたいなら、フォルダ名の先頭に `_` を付けてもよい（同じく
読み込まれなくなる）。

遊んでいる途中で MOD を外したいときは `MOD を外す` を押す。ゲームは終了しない。
ただし完全に元通りにはならない（起動時に一度だけ走った処理や、MOD がセーブに書いた値は
戻らない）。素のゲームで確かめたいなら、注入せずに起動し直すのが確実。

## ログの世代管理

`out\*.log` は注入のたび（＝ゲームを起動するたび）に新しくなる。前回の内容は
`modloader.log.1` のように `.1` を付けて1世代だけ残り、それより古いものは消える。
放っておくとログが数MBまで育って読めなくなるため、既定で ON。

複数回のプレイをまたいで追いたいときは OFF にできる:

```
.\tools\watch.bat --no-log-rotate       # この実行だけ追記のまま
```

常時 OFF にしたい場合は `tools\logrotate.py` の先頭:

| 設定 | 意味 |
|---|---|
| `ROTATE_LOGS` | `False` にすると入れ替えず、常に追記していく |
| `KEEP_GENERATIONS` | 残す古い世代の数（既定 1）。`0` にすると退避せず消す |

環境変数 `INSTANTALE_LOG_ROTATE=0` でも OFF にできる（優先順位は
コマンドライン → 環境変数 → `tools\logrotate.py` の既定値）。

`out\` の中でも `quest_clients.json` などログ以外のファイルと、
`out\test\` `out\recon\` の中身は対象外。

## セーブとゲームファイルへの影響

- ゲームフォルダは読むだけで、一切書き込まない
- セーブに書くのは、ゲーム自身が持っている値だけ（パーティの名簿・依頼・エリアのBGM）。
  MOD 独自の項目をセーブに足すことはしない
- ファイル名に使えない文字を含む NPC の名前だけは書き換える（`"` → `”` のように全角へ）。
  そうしないとそのNPCの画像が永久に作られないため。書き換えた名前は
  `out\character_name.log` に残る
- MOD が追加した選択肢ボタンは、押した瞬間に無害な既存の動作へ差し替わる。だから
  MOD を入れずに次回起動しても壊れない
- 既存セーブの BGM を一括で均す道具（`tools\rebalance_saved_bgm.py`）だけはセーブを
  書き換えるが、既定は dry-run（変更しない）で、実行時は自動でバックアップを作る

---

## 制限

- MOD はゲーム起動後に入るので、起動時に一度だけ走る処理には手が届かない
- AIが推論している最中に注入すると入るのが遅れることがある（30秒でタイムアウト表示が
  出るが、その後ちゃんと入る）
- 追加した選択肢ボタンがセーブに残骸として残ることがある。無害だが、MOD 無しで押すと
  何も起きない

---

## うまく動かないとき

### まずこれを試す

`InstantaleModLoader.bat` の「Mod を注入してゲームを起動」をもう一度押す
（ゲームは起動したままでよい。動いているゲームを見つけたら起動は飛ばして注入だけする）。
MOD の入れ直しで、音の不具合や「イベントが出なくなった」はその場で直ることが多い。

それでも変わらなければ、ゲームを終了してから、もう一度起動ボタンで立ち上げ直す。

### 全体に関わる症状

| 症状 | やること |
|---|---|
| イベントも追加ボタンも出ない | 入れ直す（上）。`out\modloader.log` に `boot complete:` が無ければ入っていない |
| 選択肢を押しても何も起きない | 画面が「…」の間は処理中。終わるまで待つ |
| ゲームが落ちる・様子がおかしい | 注入せずにゲームを起動すれば完全に素のゲームとして動く。記録は `out\live_crashes.log` |

MOD ごとの症状は、後半の各 MOD の「困ったとき」に書いてある。

### 不具合ではないもの

| | |
|---|---|
| 「依頼を受ける」を押すと会話が終わる | 依頼の話をするために会話を切り上げている（ボタンにもそう書いてある） |
| クエストをクリアしても仲間が離れない | `304_quest_end_keep_party/` の効果。戻し方はその MOD の項を参照 |
| 追加されたボタンが MOD 無しだと何も起きない | セーブに残ったボタンの残骸。押しても害は無い |

## ファイルの置き場所

| | |
|---|---|
| `InstantaleModLoader.bat` | これをダブルクリックする。MOD の一覧と起動ボタン |
| `runtime\instantale_modloader\` | ローダ本体（注入・パッチ管理） |
| `runtime\mods\` | MOD 本体。一覧に無い設定はここを開いて書き換える |
| `runtime\mods\load_order.json` | 適用順と無効一覧。一覧の `保存` が書き込む先 |
| `runtime\mods\_template\` | 新しい MOD を作るときの雛形（読み込まれない） |
| `settings\` | 変えたものの置き場所。`mod_settings.json`（MOD の設定）と `gui.json`（ゲームの場所・ウィンドウの大きさと位置）。MOD を差し替えても残る（無くてよい） |
| `out\` | ログ各種。何が起きたかは全部ここに残る（`.1` は前回のプレイ） |
| `out\status.json` | 前回の注入の結果。一覧の `前回` の列はこれを読んでいる |
| `tools\` | 中身。GUI・注入・監視のスクリプトと、検証用の道具 |
| `tools\watch.bat` | GUI を使わない自動注入（コンソール） |
| `tools\logrotate.py` | ログの世代管理（ON/OFF と残す世代数） |
| `docs\TECH.md` | MOD を作る人向けのリファレンス（ローダの仕組みと書き方） |
| `docs\GAME.md` | Instantale 自身の内部リファレンス（実測でわかったゲームの構造） |
| `docs\VERIFICATION.md` | 何がどこまで確認済みか・次に何を確かめるか |

# 第2部 同梱している MOD

フォルダ名の先頭の番号が種類と適用順を表す。

| 番号帯 | 種類 | 中身 |
|---|---|---|
| `000`-`0xx` | 調査・記録 | ゲームは変えない。構造の書き出しとクラッシュ記録 |
| `100`-`1xx` | 修正 | ゲームのバグ・不便の修正 |
| `200`-`2xx` | 計測 | ゲームは変えない。原因を測るための道具 |
| `300`-`3xx` | 追加 | ゲームに無かった遊びの追加 |

各項の「設定」は GUI の `設定` 列から変えられるもの。

## 調査・記録（0xx）

### `000_recon`: モジュール調査

ゲームの内部構造を走査し、パッチ対象の一覧を `out\recon\` に書き出す。ゲームは変更しない。
MOD を作るときの下調べ用。

### `001_crash_recorder`: クラッシュ記録

クラッシュ時のトレースバックとフレーム変数を、省略なしで `out\live_crashes.log` に残す。
不具合を報告するときはこのファイルを見る。

---

## 修正（1xx）

### `100_fix_kivy_shutdown`: 終了時のクラッシュ

ゲームを閉じるときに落ちる件（記録されていたクラッシュの最多ケース）を抑え、
その裏に隠れていた本来の例外を表に出す。

### `101_fix_npc_employ_price`: NPC 雇用時のクラッシュ

特定の NPC を雇おうとすると落ちる `KeyError: 80` を、ゲーム自身のクランプ関数を
通して防ぐ。

### `102_fix_prompt_dedup`: AIへ送る文章の重複除去

ゲームが AI へ送る文章の中で重複した同一ブロックを畳み、プロンプトの肥大を抑える。
`103` `105` と合わせて実測で約73%削減。長時間プレイでの応答の遅さ・崩れが軽くなる。

### `103_fix_eventlog_trim`: イベントログの刈り込み

【今回のイベント内ログ】を直近3ターンぶんに刈り込み、プロンプトの肥大を抑える。

### `104_balance_area_bgm`: エリアBGMの偏りを均す

新しく生成されるエリアの曲が一部に偏るのを均す。使われていなかった曲が出るようになる。

| 設定 | 意味 |
|---|---|
| 曲が無いエリアにも割り当てる | 既定 ON |

既存セーブの BGM をまとめて均したいときは `tools\rebalance_saved_bgm.py`
（既定は dry-run、実行時は自動バックアップ）。

### `105_fix_schema_compact`: スキーマ説明の圧縮

プロンプトに埋め込まれたスキーマ説明文を、簡潔な一覧表記に置き換える。

### `106_fix_battle_bgm_restore`: 戦闘後もBGMが戻らない

会話から戦闘に入ると戦闘BGMが鳴り続ける件を修正。重なって溜まった「迷子の曲」も
注入時に掃除する。

| 設定 | 意味 |
|---|---|
| 戦闘後に曲を戻すまでの待ち（秒） | 既定 2.5 |

**困ったとき**

| 症状 | やること |
|---|---|
| 音が重なる・戦闘後も戦闘BGMが鳴り続ける・タイトルに戻っても曲が止まらない | 入れ直す。溜まっていた分ごと直る。MOD を入れていない場合はゲームの再起動しかない |

### `107_fix_battle_flag_stuck`: ロードすると戦闘BGMで始まる

会話からの戦闘で「戦闘中」の印が下ろされず、セーブに焼かれるのを修正。
一度戦闘すると施設でNPCから話しかけられなくなるのも同じ原因だった。

**困ったとき**

| 症状 | やること |
|---|---|
| ロードすると戦闘BGMで始まる | 入れ直す。読み込んだ時点で直る |
| 一度戦闘したらNPCから話しかけられなくなった | 同上（同じ原因） |

### `108_fix_shop_inventory_overflow`: 売買画面を開くと落ちる

店で売り買いしようとした瞬間に落ちる `IndexError` を修正。持ち物の置き場所が
はみ出したときは、ゲーム自身の「空いている場所に置く」処理に流す。

**困ったとき**

| 症状 | やること |
|---|---|
| 店で売り買いしようとすると落ちる | 入れ直す。落ちなくなる代わりに、はみ出した持ち物が別のマスに置かれることがある |

### `109_fix_item_detail_autosize`: アイテムの説明が途中で切れる

説明欄が固定サイズで、長い説明・長い名前が読めなかったのを修正。
入り切らないときだけ枠が広がる（普通の長さのアイテムは見た目が変わらない）。

| 設定 | 意味 |
|---|---|
| 説明欄を広げてよい上限 | 元の幅の何倍まで（既定 3.0） |

**困ったとき**

| 症状 | やること |
|---|---|
| アイテムの説明が途中で切れる | 入れ直す。枠が伸びるようになる。それでも入り切らないほど長い説明は画面の高さで頭打ち |

### `110_fix_character_name_path`: 特定のNPCの画像が生成されない

名前に `"` などファイル名に使えない文字が混じると、立ち絵などが無言で作られないままだった。
これを修正し、名前を全角に置き換えて通す（表示はほぼ変わらない）。既に世界に居る NPC も直す。
書き換えた名前は `out\character_name.log` に残る。

**困ったとき**

| 症状 | やること |
|---|---|
| 特定のNPCだけ立ち絵や画像が出ない | 入れ直す。名前が原因なら直り、次に画像を作る場面（会話・戦闘）で生成される |

### `111_llm_prompt_replace`: AIへの指示文を置換ルールで書き換える

ゲームが AI へ送る文章を置換ルールで書き換える。ゲーム側の誤字・崩れた改行の修正と、
NPC の言動の調整を入れたルールが同梱されていて、そのまま効く。

自分で書き換えるときは `runtime\mods\111_llm_prompt_replace\` の
`llm_replacements.default.txt` を同じフォルダに `llm_replacements.txt` としてコピー
してから編む（そちらが優先され、MOD を新しい版にしても消えない）。
書き方は「置換前=>置換後=>確率」で1行1ルール。保存すると次の応答から効く
（ゲーム再起動は不要）。`InstantaleLlmProxy` のルールファイルは書式が同じなので、
`llm_replacements.txt` として置けばそのまま動く。

| 設定 | 意味 |
|---|---|
| 置換したことを記録する | 既定 ON。`out\prompt_bloat.log` の `[REPLACE]` |
| ルールの読込を記録する | 既定 ON。`out\prompt_bloat.log` の `[RULES]`（書式の誤りは切っても必ず残る） |

### `112_ui_text_spacing`: 本文の行間が広すぎる

AIの応答やシステムメッセージの行間を詰め、段落の間に入る空行を減らす。
画面に出る見た目だけを変えるので、会話履歴やセーブの中身は元のまま。

| 設定 | 意味 |
|---|---|
| 行間 | ゲームの元の値に対する倍率（既定 0.8）。`1.0` でゲームのまま、空欄なら行間に触らない |
| 段落の間に残す空行の数 | 既定 0（空行なし）。`1` でゲームのまま、空欄なら本文の改行に触らない |

元の行間の値は `out\text_spacing.log` に出る（実測では `1.8` ＝ Kivy の既定 1.0 の
1.8 倍。既定の 0.8 倍で `1.44` になる）。詰めすぎ・緩すぎと感じたら 0.7〜0.9 で調整する。

### `113_ui_text_expand`: 本文の表示域が狭い

画面の隅に小さなボタンが1つ増える。押すと本文（情景描写・AIの応答）の枠が広がって
まとめて読めるようになり、**もう一度押すと元の寸法に戻る**。広げるのは枠だけで、
本文・会話履歴・セーブには触らない。広げたままでも遊べる（選択肢は今までどおり使える）。

| 設定 | 意味 |
|---|---|
| 広げたときの幅 | 元の枠の何倍か（既定 1.0 ＝ 幅には一切触らない）。上げると右へ広がる |
| 広げたときの高さ | 元の枠の何倍か（既定 2.5）。**下端は動かず上へ伸びる**ので、入力欄や状態表示はずれない |
| ボタンの置き場所 | キャラの欄（画面右下の立ち絵と HP）の上（既定）／枠の右上（本文の枠の内側。枠が伸びると一緒に上がる）／右上／左上／右下／左下 |
| ボタンの大きさ | px（既定 32）。アイコンは正方形、文字なら幅はこの2倍 |
| ボタンの絵柄 | 二重山形（既定）／山形／矢印／伸縮／枠／文字。背景なしの白い線で描き、押すと上下が入れ替わる |
| アイコンの線の太さ・濃さ | 既定 2.0px / 0.85。背景に溶けて見にくいときに上げる |
| ボタンの文字 | 絵柄に「文字」を選んだときだけ使う（広げる前「拡張」／広げた後「戻す」）|
| 最初から広げておく | 既定 OFF |

倍率をいくつにしても窓の外へははみ出さない（窓の 98% で頭打ち）。元の枠の寸法と、
実際に広げた寸法は `out\text_expand.log` に出る。ボタンが他の表示に隠れて押せない
ときは、置き場所を変えるか高さを小さくする。

ウィンドウの大きさを変えても、ボタンの位置と枠の広がりは追従する（広げたままでも
一度たたんで、新しい寸法で広げ直す）。

本文の枠と一緒に、その枠線・背景も広がる（同じ場所に重なっているものをまとめて
扱う）。もし本文だけが広がって枠線が元のままなら、`out\text_expand.log` の
`frame neighbours:` の行を見ると、枠のまわりに何が置かれているかが分かる。

### `114_ui_input_focus`: 自由入力のたびにフォーカスが外れる

自由入力を送るたびに入力欄からフォーカスが外れ、次の一言を打つのに毎回クリックし
直していたのを、**送ったあともそのまま打てる**ようにする。Enter で送っても、
送信ボタンを押しても戻る。入力欄の中身や送信の仕組みには触らない。

AIの応答を待つ間はゲームが入力を塞ぐので、その間は戻さず、**応答が返った瞬間に
戻る**。別の窓が開いているとき・他の入力欄に打っているときも横取りしない。

| 設定 | 意味 |
|---|---|
| フォーカスが外れたら戻す | 既定 ON。送信でも、画面のどこかを触ったときでも入力欄に戻る。OFF にすると次の項目だけが効く |
| 応答待ちが明けたら戻す | 既定 ON。応答が返って入力が解けた瞬間に戻す |
| 戻すまでの待ち（秒） | 既定 0.05。戻ってもすぐまた外れるようなら 0.1〜0.2 に上げる |

フォーカスが常に入力欄にあるので、キーボードで他の操作をしている場合はそちらが
効きにくくなる。そのときは「フォーカスが外れたら戻す」を OFF にすると、送信の後
だけ戻る形になる。どの入力欄を掴んでいるかは `out\input_focus.log` に出る。

### `115_ui_item_list_fit`: アイテム一覧が画面の上へはみ出す

入力欄の左下のアイコンから開くアイテム（スキル）の一覧は、入力欄を下端にして上へ
積まれる。持ち物が増えると**画面の上端を突き抜け、先頭の数件が画面の外に出て
押せなくなる**。何件で溢れるかは画面の解像度で変わるので、そのときの窓の高さに
合わせて収める。

収め方は**列を増やすこと**だけ。一覧が1列で入り切らなくなったら 2列・3列…と
折り返す。**位置も行の大きさも文字の大きさも変えない**ので、見え方は今までのまま
高さだけが減る。行は1件も隠さない。

| 設定 | 意味 |
|---|---|
| 一覧が画面の高さに占めてよい割合 | 既定 0.9。小さくすると早く2列目へ折り返す |
| 列数の上限 | 既定 4。1 にすると列を増やさない（＝この MOD は何もしない） |
| 列数を固定する（0 で自動） | 既定 0 ＝ 件数と画面の高さから自動。2 にすると、収まっていても常に2列 |

一覧が1列で収まっているときは何も触らない。上限の列数でもまだはみ出す件数のときは
`out\item_list.log` にその旨が出るので、「列数の上限」を上げる。見つけた一覧の構成
（型・親・行数・矩形）も同じログに出る。

### `307_area_move_dungeon`: 危険な道を行く

土地を移るとき、徒歩・馬車に並んで **「危険な道を行く」** が出る。選ぶと、その2つの
土地を繋ぐ**道中を舞台にしたクエスト**がその場で作られ、いつもの受注画面が開く。
踏破すれば目的地に着き、放棄すれば出発地に留まる（移動そのものが失敗する）。

道の難易度は**移動元と移動先の間から抽選**される。安全な村から危険な土地へ向かえば
その中間、隣の同じような町へ行くだけなら軽い道になる。

**危険だが早い。** 道中と最後の移動を合わせて **14日**（馬車と同じ）を超えない。
徒歩の3ヵ月を待たずに済み、馬車の 1000G も要らない代わりに、道中で戦うことになる。

踏破して「帰還する」を押し、報酬を受け取った直後にそのまま目的地へ移動する
（元の街を歩き直す必要はない）。道中のクエストの生成には数分かかることがある。

**体力が3分の1を切っていると行けない。**「この道を行くには、今は体力が無い。」と
出て、ダンジョンは作られない（宿で休むこと）。

依頼の説明の末尾には、AIが書いた文に続けて次の1行が足される。掲示板に残った道を
後から見ても、それが移動の依頼だと分かる。

```
※このクエストをクリアすると「澱みの宿場町」に移動します。
```

移動の紐付けが切れたとき（別の依頼を受けた・普通に移動した・道を選び直した・放棄した）
は、この一文も消えてただの依頼に戻る。AIが書いた本文はそのまま残る。

| 設定 | 意味 |
|---|---|
| 道の難易度の決め方 | 既定「移動元と移動先の間から抽選」。「移動先に合わせる」「高いほう」も選べる |
| 難易度に足す下駄 | 既定 0。道中を素の依頼より重くしたいときに足す |
| 道にかける日数の上限 | 既定 14（馬車と同じ）。道中のクエストと最後の移動の合計。0 なら日数が進まない、365 なら実質上限なし |
| 踏破した後の移動手段 | 既定「徒歩」（所持金が要らない。日数は上の上限で切り詰める）。「馬車」にすると 1000G がかかる |
| 体力がこの割合を切ったら断る | 既定 33（＝3分の1）。下回っていると「この道を行くには、今は体力が無い。」と出て道を行けない。0 にすると体力を見ない |
| 依頼概要に移動先を明記する | 既定 ON。依頼の説明の末尾に「※このクエストをクリアすると「〜」に移動します。」が付く |
| 「長旅だ…」を出さない | 既定 ON。踏破した後の移動で「徒歩で目指す。長旅だ...」が出るのを伏せる（普通の徒歩・馬車の移動はそのまま） |
| 出発時に道の危険度を出す | 既定 ON。「危険度: 6 ／ かかる日数: 最大14日」と出る |

**困ったとき**

| 症状 | やること |
|---|---|
| 踏破したのに目的地に着かない | 「帰還する」を押して報酬が出た直後に移動する。動かないときは `out\road_travel.log` に `cleared:` の行があるか見る（無ければ、その道のクエストとして認識されていない） |
| 道を選んだ直後に MOD を入れ直した | 入れ直しをまたいでも道は続く（控えは `out\road_travel.json`）。道中のクエストを進めていれば、次に画面が切り替わったときに拾い直す（`armed: the game is running quest ...`） |
| 受注をやめた道の依頼が掲示板に残る | 生成された時点で世界に登録されるので残る。依頼の説明に移動先が書いてあるので、後から受ければ踏破で移動する。ただし**その場を離れる（別の依頼を受ける・普通に移動する・道を選び直す）と移動の紐付けは切れ**、説明の一文も消えてただの依頼になる |
| ゲームを再起動したら着けなくなった | 道中の控えは `out\road_travel.json` に残るので、消していなければ続きから着ける |
| 日数が上限を超えて進んでいる | `out\road_travel.log` に `days:` の行が出ているか見る。1行も出ていなければ、このビルドの日数送りが `elapse_days` を通っていない（`WARN arrived: elapse_days was never seen` が出る）。その場合は「踏破した後の移動手段」を馬車にすると 14 日で着く |

### `308_battle_damage_display`: 戦闘のダメージ表示

戦闘の地の文の後ろに、その1手で**実際に動いた HP** が出る。自分や味方が敵に与えた
ぶんも、敵が自分や味方に与えたぶんも、同じように数字で出る。

```
テストプレイヤーは剣を振り抜き、斥候の脇腹を裂いた。
ゴブリンの斥候 に 23 のダメージ（残り HP 11/34）
テストプレイヤー は 8 のダメージを受けた（残り HP 52/60）
```

とどめの一撃は残り HP の代わりに撃破と出る。

```
ゴブリンの斥候 に 11 のダメージ（撃破）
```

行の頭に記号を付けたいときは設定から選べる（既定は付けない）。

```
● ゴブリンの斥候 に 23 のダメージ（残り HP 11/34）
```

毒などの継続ダメージや回復も同じ仕組みで出る（HP が動いたぶんを測っているので、
どういう理由で動いたかは問わない）。ゲームの側は何も変えない。読むのは HP だけで、
書くのは画面のこの数行だけ。

| 設定 | 意味 |
|---|---|
| 行の頭に付ける記号 | 既定「なし」。`- * > ・ → ※ ● ◆ ■ ★` から選べる（選ぶと記号と半角空白が各行の頭に付く）。機種依存文字は候補に入れていないので、どれを選んでも文字化けしない |
| 敵に与えたダメージを出す | 既定 ON |
| 自分や味方が受けたダメージを出す | 既定 ON |
| 回復も出す | 既定 ON。HP が増えたときも1行出る |
| 残りの HP を添える | 既定 ON。「（残り HP 11/34）」の部分 |
| 身体の負傷の増減も出す | 既定 OFF。HP とは別の数字なので普段は邪魔になりやすい |
| この値未満の増減は出さない | 既定 1。0 にすると 0 ダメージの行まで出る |

**困ったとき**

| 症状 | やること |
|---|---|
| 戦闘しても数字が出ない | `out\battle_damage.log` を見る。`battle start:` の行すら無ければ、このビルドでは戦闘の入口が違う。行はあるのに数字が出ないなら、HP の持ち方が違うので**このログを添えて報告してほしい**（未確認の項目。`docs\VERIFICATION.md` §3.14） |
| 残りの HP が「11/34」でなく「11」と出る | このビルドで最大 HP の項目名が違う。ダメージの数字自体は正しい |
| 数字が地の文より先に出る | 出す位置がこのビルドと合っていない。同じくログを添えて報告してほしい |

### `309_office_pardon`: 役場で手配を解く

その土地で手配されている（手配度が 0 未満）と、役場の選択肢に
**「罰金を納めて手配を解く」** が出る。押すと金額を出して確認し、払えば
手配度が平常値（10）に戻る。

```
[役場]  労働の募集をみる / 市民権の発行 / 罰金を納めて手配を解く(10,000G) / 出る / 会話する
                                              ↓
                        10,000ゴールドを納める / やめておく
                                              ↓
                        所持金 -10,000 ／ この土地での手配は取り消された
```

**扱うのは今いるエリアの手配だけ。** 手配は土地ごとに別々に付くので、よその土地の
分はその土地の役場で払うことになる。

罰金は **手配度1あたり 1000ゴールド**（既定）。手配度が3なら 3,000ゴールド。
所持金が足りなければ何も起きない（金も手配度も動かない）。

| 設定 | 意味 |
|---|---|
| 手配度1あたりの罰金 | 既定 1000。0 にすると無料で解ける |
| 手配とみなす手配度 | 既定 0（手配度が 0 未満なら犯罪者）。罰金はこの値との差で決まる |
| 罰金を納めた後の手配度 | 既定 10（素の平常値）。今の値より低い値を入れても下がらない |
| 役場に入ったら手配を知らせる | 既定 ON。手配されているときだけ1行出る |

**困ったとき**

| 症状 | やること |
|---|---|
| 役場に入っても選択肢が出ない | その土地では手配されていない（手配度が 0 以上）ときは出ない。手配されているはずなのに出ないときは `out\office_pardon.log` を見る。`offer:` の行が1つも無ければ、このビルドでは手配度の持ち方が違うので**このログを添えて報告してほしい** |
| 会話中に出ない | 会話・戦闘・買い物の最中は出さない。会話を終えれば出る |
| 払ったのに次に遊んだら戻っている | ゲームがセーブする前に終了している。罰金も一緒に戻っているので損はしない（この MOD からはセーブを書かない） |
| よその土地の手配が消えない | 仕様。手配は土地ごとで、その土地の役場でしか解けない |

### `1308_companion_travel`: NPCを連れて歩ける

会話中に「同行を持ちかける」が出る。**雇用（パーティ）とは別物**で、金も契約も
要らない代わりに、応じるかどうかは**それまでの会話しだい**。初対面ではまず断られる。
連れて行けるのは施設の移動と土地の移動で、土地を跨ぐときは本人に**続ける気があるか**
を訊く。断られたら「置いて行く」か「旅をやめる」かを選ぶ。

| 設定 | 意味 |
|---|---|
| 土地を跨ぐときも連れて行く | 既定 ON。OFF にすると同行者はその土地に残る |
| 土地を跨ぐ前に同行の継続を訊く | 既定 ON。OFF にすると無条件に付いて来る（**同行者の数だけ待ち時間が伸びる**ので、重いと感じたらここ） |
| 同行を解くのにも相手の承諾を要る事にする | 既定 OFF。ON にすると断られることがある |
| 同行者の上限 | 既定 3 |
| 土地移動の後に同行者の名前を出す | 既定 ON |

**制限**

- 連れて歩いている NPC は**戦闘にもクエストにも同行しない**（画面のパーティ欄にも出ない）。
  一緒に戦ってほしいならゲーム本来の雇用を使うこと
- 店主や宿の主人を連れ出すと、その施設に主が居なくなる。人数の上限以外に止める仕掛けは
  入れていない
- 馬車の運賃は同行者の分を取らない（ゲームの計算に手を入れないため）

同行者の一覧は**セーブではなく `out\companions.json`** に入る（世界ごとに分けてある）。
世界の名前で分けているので、外部のデータ改変ツールで世界名を書き換えると同行状態が
行方不明になる（NPC はその場に残る）。そうなったときは `out\companion.log` に
`no companions for world ...` が出る。
